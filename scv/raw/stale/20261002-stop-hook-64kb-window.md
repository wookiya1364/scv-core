# 다음 계획 후보 — 종료 훅은 끝 메시지의 앞 64KB 만 본다

출처: 계획 20261002-wookiya1364-stop-gates-each-once 구현 중 속도 검사(T35.12)를 처음 돌렸을 때 발견
(대화 scv/conversations/20261002-090454-install-check-0-64-1.md). 그 계획의 범위(판정 기준 · 입력은 그대로) 밖이라 여기 남긴다.

## 확인한 것

- 종료 훅(`core/template/hooks/on-stop.sh`)은 호스트가 준 끝 메시지를 `head -c 65536` 으로 앞 64KB 만 잘라 원칙 검사 · 선택지
  검사에 넘긴다(0.64.0 부터).
- 선택지 검사는 답의 **끝**(마지막 두 문단)을 본다. 그래서 64KB 를 넘는 답의 끝에 있는 질문은 판정에 들어가지 않는다 — 105KB
  답 끝의 "릴리스할까요?" 를 묻지 않음으로 봤다(실측, 0.64.1 과 고친 코드 모두).
- 원칙 검사는 문제 표를 답 **어디서나** 찾는다 — 앞 64KB 만 보면 뒤쪽 표를 놓친다(코드로 본 추정, 재현 안 함).

## 고칠 방향(정할 것)

- 검사마다 필요한 쪽을 준다: 선택지 검사는 끝 64KB, 원칙 검사는 앞뒤 또는 전체(바이트 상한 안에서).
- 지킬 것: 맥 기본 bash 3.2 속도(10만 바이트 답 지금 1.2초), 판정 기준 자체는 그대로.
- 확인 방법: 64KB 를 넘는 답 끝 질문 · 뒤쪽 문제 표 픽스처를 검사로 잠근다.
