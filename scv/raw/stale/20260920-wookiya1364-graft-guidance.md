# Graft 안내 — 계획·코드생성 때 먼저 알리고, 설치까지 안내한다

작업 중(20260920-wookiya1364-rule-constitution 구현) 사용자가 남긴 요구. 원문:

> graft는 강제는 아닌데, 계획 및 코드생성때는 먼저 안내를 해줘야해. 있으면 더 자세하고 품질 향상가능하다고.
> 그래서 설치까지 할 수 있도록 안내를 해줘. 그리고 이거 지금 개발은 로컬맥에서 하는데, 리눅스에서도 같이
> 병행하거든. 그러니 맥과 리눅스에서 모두 가능하도록 해야해. 어느한쪽만 되게하면 안돼.

## 지금 상태 (2026-09-20 확인)

- Graft 는 선택 제공자다 (결정 2026-09-17 "있으면 덧붙이고, 없으면 조용히 생략"). 프로토콜은 "absent 는 아무것도
  바꾸지 않는다" 고 적고, `install-deps --print` 가 한 줄짜리 설치 명령을 보여 준다. **먼저 알려 주는 단계는 없다.**
- 이 기계에는 graft 가 없다 (PATH 에 없음, graft/ 폴더 없음). promote·work 헬퍼는 `GRAFT_STATUS: absent` 만 찍는다.
- 결정 기록에 "Graft 는 bash 미지원" — 이 저장소(bash)에서는 설치해도 코드 그래프가 안 만들어진다. 안내 문구가
  이 사실을 함께 말해야 한다(안내만 받고 설치했는데 빈 결과가 나오면 신뢰를 잃는다).

## 요구를 SCV 규칙에 맞게 놓으면

- 4조(같은 요구는 한 곳에만): 안내 문구는 **한 곳**에서 나와야 한다. 후보: `scripts/lib/graft.sh` 의 status 함수가
  `GRAFT_STATUS: absent` 뒤에 `GRAFT_NOTICE:` 한 줄(무엇이 좋아지는지 + 설치 명령 + 언어 지원 여부)을 붙이고,
  promote·codegen·work 프로토콜은 "그 줄을 그대로 전달하라" 만 적는다. 프로토콜마다 문구를 복제하지 않는다.
- 6조(순수함수): 문구 생성은 상태 문자열 → 문구 문자열의 순수 함수로, 검사는 고정 입력·고정 출력.
- 맥·리눅스 동일: 셸 스크립트만, 외부 도구 의존 없음. 설치 명령은 npm 기반이라 둘 다 같다.
- 강제 아님: 안내는 한 줄, 묻지 않고 막지 않는다. 사용자가 설치하면 다음 액션부터 `ready`.

## 수용 기준 후보

1. graft 가 없을 때 promote·codegen·work 의 첫 출력에 안내 한 줄이 있다 (있으면 무엇이 좋아지는지 · 설치 명령 · 이 저장소 언어 지원 여부).
2. 그 문구가 정의된 자리는 저장소에 한 곳이다 (rule-constitution 검사 (b) 가 중복을 잡는다).
3. graft 가 있으면 안내가 나오지 않는다.
4. 맥(BSD 도구)과 리눅스(GNU·mawk)에서 같은 출력 — 픽스처 검사.
