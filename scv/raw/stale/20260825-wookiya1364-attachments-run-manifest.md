# PR 증적 첨부가 빈손으로 나간다 — 이름 매칭의 한계

2026-08-25, ai_tm_center FE 실사용 보고.

슬러그 `20260824-wookiya1364-readiness-inspection-refine` 로 e2e 8건을 green 으로
만들고 PR 을 만들었는데 증적(영상/스크린샷)이 하나도 안 붙었다.

원인 사슬 (코드로 확인):

1. Playwright 는 결과 폴더 이름을 길이 제한으로 자른다 —
   `test-results/20260824-wookiya1364-readi-07a27-…` 처럼 슬러그가 중간에서 잘림.
2. `attachment_scope_filter` 는 경로에 **슬러그 전체**가 부분문자열로 있어야
   통과시킨다 (`*"$slug"*`). 잘린 이름에는 전체가 없다 → 0건.
3. pr-helper 의 재실행 경로가 돌아도 결과 폴더 이름은 똑같이 잘린다 → 여전히 0건.
4. `collect-artifacts.sh`(report 경로)는 0건일 때 **무경고** — 조용히 빈손.
5. 사후 보정하려고 pr-helper 를 다시 돌리면 **PR 을 또 만들려 한다** (기존 열린
   PR 탐지 없음).

교훈: 파일 "이름"으로 소속을 알아맞히는 구조 자체가 취약하다. 테스트를 돌린
그 순간에는 "이 실행이 이 계획의 것"임을 확실히 안다 — 그때 기록해 두면 이름이
어떻게 저장되든 상관없다.

원하는 것 (사용자 확인, 2026-08-25):

- 접두사 줄여가며 재시도 같은 증상 대응 말고 근본 해결.
- SCV 가 테스트를 돌릴 때 그 실행이 만든 파일 목록을 계획 이름과 함께 기록
  (run manifest), 첨부는 그 기록을 우선 사용.
- 기록이 없으면 지금의 이름 매칭으로 폴백, 그래도 0건이면 침묵하지 말 것.
- 같은 브랜치에 열린 PR 이 있으면 새로 만들지 말고 갱신할 것.
