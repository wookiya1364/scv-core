# 데크 재설계 — 측정 기록과 결정

2026-08-13. 대표님이 `/scv:deck` 산출물을 "디자인이 심각하게 구려서 쓰고 싶은 엄두가
안 난다", "아키텍처 그려놓은 게 배경색이 화살표·글자색과 비슷해서 보이지도 않는다"
고 지적했다. 세 차례 조사(85 + 52 에이전트)로 원인을 찾고 이식 사양을 확정했다.

## 확인 1 — 제일 큰 원인은 색이 아니라 크기다

다이어그램이 자연 크기의 절반으로 찌그러져 있다.

```
viewBox 자연 폭   1437px
본문 칸           694px   (840px 칼럼 - 패딩, 사이드 패널 열렸을 때)
배율              0.483
16px 글자         →  7.7px 로 보임
```

7.7px 다. 색을 아무리 고쳐도 이건 안 고쳐진다.

## 확인 2 — 색은 프롬프트에 박혀 있다

`core/protocols/promote.md` 가 모델에게 **모든 mermaid 펜스 안에 다크 팔레트 한
줄을 붙여넣으라고 지시**한다. 그 `%%{init:...}%%` 가 렌더러의 `theme:"default"` 를
이긴다. 그리고 헤드리스 크롬이 그 색으로 SVG 를 구워서 고정한다.

팔레트가 코드가 아니라 **작성 지시문** 안에 있어서, 코드를 고쳐도 안 바뀌고 이미
만들어진 문서는 영원히 그대로다.

## 확인 3 — 그래서 양쪽 테마 다 깨졌다

페이지는 `:root`(다크) + `html[data-theme="light"]` 로 실시간 전환되는데, 다이어그램만
빌드 때 구워져 고정이다. 어느 한쪽은 반드시 어긋난다.

```
라이트 페이지 #ffffff  :  화살표 #e7e9f0  1.21:1  안 보임
                         테두리 #9096a8  2.95:1  미달
다크 페이지  #0d0e13  :  박스   #171922  1.10:1  페이지에 묻힘
                         검은글자 #000000 1.09:1  안 보임
```

다크 팔레트가 페이지 다크(`#0d0e13`)가 아니라 다른 다크(`#171922`)를 기준으로
잡혀 있었다.

## 확인 5 — 대표님 md2pdf 가 안 깨지는 이유

`~/.claude/tools/md2pdf/` 를 헤드리스로 렌더해 실측: 화살표 12.63:1, 테두리 3.76:1,
글자 10.83:1 로 전부 통과. 팔레트가 좋아서가 아니라 **구조** 때문이다.

- 테마가 하나뿐이라 어긋날 수가 없다
- mermaid 테마를 작성자가 아니라 **렌더러**가 정한다
- SVG 를 얼려두지 않고 **볼 때** 그린다

## 결정 — 대표님이 정한 것

| 항목 | 결정 |
|---|---|
| 테마 | **다크 전용**. 대표님 deck 스킬이 "dark 테마" 로 못 박고 있다 |
| 토큰 | 대표님 `DesignSystem/src/index.css` 의 shadcn oklch `.dark` 세트 |
| 브랜드 | **장미색 유지**. 공개 제품이어도 괜찮다고 확인받음 |
| 레이아웃 | 대표님 `SlideDeck.tsx` 크롬과 동일하게 |
| 인쇄 | 화면은 다크 전용, **종이만 라이트** (`@media print` 단일 블록) |

인쇄를 남기는 이유: 대표님이 거부한 것은 "독자가 고를 수 있는 두 번째 팔레트"
(토글 버튼·저장되는 선택·깜빡임 방지 스크립트)다. `@media print` 는 화면에서 도달할
수 없고, 버튼도 저장도 없고, 화면으로 새지 않는다. 그리고 SCV 데크는 PR 옆
`scv/archive/` 에 놓이는 물건이라 리뷰어가 인쇄한다.

## 장미색은 두 개가 필요하다

원본 `oklch(.455 .188 13.697)` = `#a50036` 은 칠하는 색으로는 좋은데 **글자로는
안 된다**. 그런데 대표님 `Kicker` 가 `text-primary` 로 글자에 쓰고 있다.

같은 색상(hue 13.7)에서 밝기만 올려 글자용을 따로 뽑았다. 여섯 역할 전수 검증:

```
글자 (kicker·링크)   #fc7184 on #0a0a0a   7.39:1  ✓
카드 위 글자         #fc7184 on #171717   6.69:1  ✓
칠하기 + 흰 글자     #fafafa on #a50036   7.58:1  ✓
밝은 판 + 검은 글자  #0a0a0a on #fc7184   7.39:1  ✓
불릿 점 70%          #fc7184@70%          4.04:1  ✓
활성 알약(어두운 판) #a50036 on #0a0a0a   2.50:1  ✗
```

마지막 하나 때문에 활성 알약은 **밝은 장미 바탕 + 검은 글자**로 간다. 어두운 장미로
칠하면 배경과 2.50:1 이라 어느 게 켜졌는지 안 보인다.

## 이식 — 되는 것

뼈대가 이미 거의 같다. SCV 데크에 패널 토글(`S` 힌트), `border-left` 사이드 패널,
`cursor:col-resize` 드래그 핸들, 패널 헤더가 이미 있다. 대표님 `SlideDeck.tsx:96-160`
과 같은 조각이다.

- 크롬 높이 268px → 110px (헤더 51 + 푸터 59). 1152px 화면에서 내용 영역 526 → 790px
- 목차가 격자에서 헤더 안 한 줄 가로 스크롤로
- 하단에 진행 점 + `N/M` + 이전/다음
- 파란 기 도는 회색 전부 무채색으로 (`#171922` → `#0a0a0a`/`#171717`/`#262626`).
  두 덱이 다른 시스템처럼 보이던 가장 큰 이유
- 콜아웃·표·불릿·`ScreenFrame` 브라우저 창을 프리미티브 모양으로

**뜻밖의 발견**: 대표님 `SlideDeck.tsx:98` 이 `flex-wrap` 과 `overflow-x-auto` 를 같이
걸어서 `flex-wrap` 이 이긴다. SCV 라벨 19 개를 먹이면 대표님 헤더도 3 줄로 늘어난다.
SCV 는 `nowrap` 으로 가므로 베끼는 쪽이 원본보다 낫다.

## 이식 — 안 되는 것

**폰트.** Inter 에 한글이 없다. 실제 산출물에 한글 389 자가 있어서 Inter 만 넣으면
한 문장 안에서 글꼴이 갈린다. 한글까지 넣으면 121KB 파일이 3~7 배로 붓는데, 이
파일은 promote 때마다 커밋된다. 시스템 글꼴로 간다 — 줄바꿈 위치가 몇 % 다르다.

**`ScreenSlide` 의 주석 칸.** 프롭 9 개(`intent`·`callFlow`·`data`·`rules`·`notScope`
·`frDone`·`stories`·`roles`·`frameLabel`)를 사람이 써넣어야 나온다. SCV 의
` ```screen ` 펜스에는 그림밖에 없다. 창틀은 가져오되 주석 칸은 못 만든다. 산문에서
지어내면 `promote.md:811` 위반이다.

**`Flow`·`TransitionList`·`SchemaTable`·`StatusLegend`.** 마크다운에 그 데이터가
없다. 아카이브 전체에 표가 3 개고 전부 2 열이다. `SchemaTable` 은 PK/FK/IDX/NN/UQ
가 필요한데 SCV 문서 종류 중 DB 스키마를 만드는 게 없다. 다이어그램은 계속 mermaid
가 맡는다.

## 다이어그램 해법 — SVG 에서 색을 벗겨낸다

구운 SVG 를 **다시 칠할 수 있게** 만든다. `static-mermaid.mjs` 에 정규화 단계를 넣어:

1. SVG 자체 `<style>` 의 `#mermaid-<타임스탬프>` 를 `.scv-mmd` 로 바꾸고 `!important`
   제거 → 특이도 (1,1,0) → (0,1,0) 이라 일반 규칙이 이길 수 있다
2. SVG 안 모든 인라인 `style=` 에서 `fill`/`stroke`/`color`/`background` 선언 제거 →
   `classDef` 가 박아넣는 `style="fill:#FFE082 !important"` 는 이것 말고는 못 이긴다
3. 타임스탬프 id 를 `scv-mmd-1` 로 고정 → `url(#...)` 참조 일관성 + 재빌드해도
   바이트 동일 (지금은 빌드마다 id 가 달라 git diff 가 출렁인다)
4. `width="100%"` + `max-width` 를 viewBox 실제 크기로 → 배율 0.483 → 1.000

실제 산출물로 시험해서 양쪽 테마가 제대로 뒤집히는 것을 확인했다. `classDef new`
노드도 테마를 따른다 — 전에는 CSS 로 못 이기던 것이다.

**대가**: 인라인 색 제거는 작성자가 손으로 칠한 `style A fill:#f9f` 도 지운다.
의도한 것이지만 동작 변경이므로 `deck.md` 에 적어야 한다. 색만으로 정보를 나르던
다이어그램은 정보를 잃는다.
