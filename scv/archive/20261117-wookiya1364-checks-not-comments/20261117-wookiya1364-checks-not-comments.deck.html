# 글 대신 검사 — 발표에서 뽑은 것 + 사용자 지적 두 가지

## Summary

Lauren Tan 발표의 핵심("에이전트를 고칠 일이 생기면 글이 아니라 검사로 남긴다 · 주석의 약속은 강제력이 없다 · 사람은 코드 대신 검증 결과물을 본다")을 SCV 에 넣는다. 매 턴 글 중 검사가 이미 막는 줄을 덜고, 고쳐 준 턴을 검사로 남기자고 제안하고, 새 임시방편 주석을 알린다. 사용자 지적에 따라 대시보드는 단계 노드를 누르면 끝난 단계의 실제 증거와 진행 중 단계의 실제 진행을 보이게 하고(증거 없는 '끝'은 거절), 순수 함수 사전 재사용은 계획 끝 검사가 실제로 막는 규칙으로 만든다.

## Goals / Non-Goals

- **Goals**
  - 1단계: 매 턴 글 중 결정적 검사가 이미 막는 규칙의 줄을 덜어 매 턴 글을 지금보다 작게 함.
  - 2단계: 고쳐 달라는 턴 뒤에 "이 정정을 검사로 남길까요?"를 선택 창으로 제안함.
  - 3단계: 계획 끝 검사가 이번 변경이 새로 넣은 임시방편 주석(TODO · FIXME · HACK · 임시 · 나중에 · workaround 등)을 파일:줄로 알림.
  - 4단계: 대시보드 단계 노드를 누르면 — 끝난 단계는 증거(화면 파일 · 결과 파일 · 명령 출력)를, 진행 중 단계는 에이전트가 알려 준 로그 파일의 최근 줄 · 진행률과 주소 여는 버튼을 보임. 단계 보고 도구는 증거 없는 '끝'을 거절함. 지금의 "지금 하는 일" 칸은 이것으로 바꿈.
  - 5단계: 계획 끝 검사가 순수 함수 사전 중복 검사를 자동으로 돌려 중복이면 막음 — 재사용하거나 다른 이유를 적어야 통과. TS/JS · 파이썬 · 러스트 함수도 서로의 예시 입력으로 실제로 돌려 비교함(지금은 셸만 실제로 돌림).
- **Non-Goals**
  - 주석 전면 금지 · 기존 주석 일괄 삭제.
  - 형식 검증(TLA+ · Lean) · 출시 때 자동 퍼즈.
  - 사용자 프로젝트 코드에 검사를 SCV 가 스스로 써 넣는 일 (제안 → 사용자 선택 → 그 턴의 일로만).
  - 대시보드가 진행 주소(웹 페이지)를 읽거나 퍼 오는 일 — 여는 버튼만.
  - 표식 없는 새 함수 막기 — 이미 가드 규칙(0.81.0+)이 쓰기 때 거절함.
  - Go 함수 실제 실행 — Go 는 지금처럼 예시 글 비교만.
  - 토큰 비율(확인 대 만들기) 측정.

## Approach Overview

1. 매 턴 글의 규칙 줄마다 "그 규칙을 막는 검사가 있는가"를 대조한 표를 만들고, 검사가 실패 사례를 실제로 막는 줄만 덜어 낸다. 덜어 낸 줄의 규칙은 검사의 거절 문구가 대신 알린다.
2. 이미 있는 정정 판정(`scv_show_real_is_correction`)을 매 턴 훅에서 써서, 직전 사람 턴이 정정이면 선택 창으로 "검사로 남기기 / 넘어가기"를 물으라는 안내 한 줄을 싣는다. 크기는 1단계에서 비운 자리 안.
3. 계획 끝 검사(`pure-bench.sh plan-end` 옆)에 이번 변경의 추가 줄만 보는 주석 알림을 붙인다. 표식 주석과 원래 있던 주석은 알리지 않는다. 막지 않고 알린다.
4. 단계 보고 도구(`scv_step`)에 두 칸을 더한다: `doing` 의 진행 출처(로그 파일 경로 · 주소), `done` 의 증거(파일 경로 목록 또는 명령 출력 발췌). 증거 판정은 순수 함수 하나 — 파일이 있고 단계 시작 시각 뒤에 바뀌었는가, 출력 발췌는 비어 있지 않은가. 실패하면 거절하고 이유를 돌려준다. 패널은 단계 노드를 누르면 상세를 펼친다: 끝 = 증거 목록(이미지는 그림으로, 글은 앞부분), 진행 중 = 로그 최근 줄 · 진행률(지금 뒤 작업 진행률 읽기 재사용) · 주소 버튼. "지금 하는 일" 카드는 이 상세로 대체한다.
5. 지금 사전 중복 검사(`pure-catalog.sh check`)는 문서에만 적혀 있고 어디서도 자동으로 불리지 않는다(확인). 계획 끝 검사가 사전을 다시 만들고 중복 검사를 돌려, 중복이면 막는다. 셸 아닌 함수는 지금 예시 글끼리만 견주므로, TS/JS(node) · 파이썬(python3) · 러스트(rustc) 함수를 서로의 예시 입력으로 실제로 돌려 출력이 같으면 중복으로 본다. 돌릴 도구가 없으면 '돌려 보지 못함: <언어>'로 알린다. 다르다고 보면 기존 중복 예외 파일에 이유를 적는다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readTurnText,        // (훅 · 도움말 본문) → 매 턴 글 줄 목록          [입구]
  matchRuleToCheck,    // 줄 목록 → 줄마다 막는 검사 이름 또는 없음
  dropCoveredLines,    // 대조 결과 → 덜어 낼 줄 목록
  detectCorrection,    // 직전 사람 턴 글 → 정정 여부
  correctionNotice,    // 정정 여부 → 안내 줄 또는 빈 값
  addedCommentLines,   // 변경 diff → 추가된 주석 줄(파일:줄:글)
  flagWorkaround,      // 추가된 주석 줄 → 임시방편 표시 목록 (표식 주석 제외)
  judgeEvidence,       // (증거 목록 · 파일 정보 · 단계 시작 시각) → 받음 또는 거절 이유
  stepDetail,          // (단계 상태 · 증거 · 진행 출처 · 로그 끝 글) → 상세 칸 내용
  crossInputs,         // (함수 짝 · 각자의 예시) → 서로의 입력으로 돌릴 실행 목록
  sameBehavior,        // (두 함수의 예시 입력별 출력) → 같음 또는 다름
)
```

## Guardrails

- 순수 함수 표식 주석(`@pure` · `@deterministic` · `@effect`)과 사전 모양을 바꾸지 않는다.
- 검사가 실패 사례를 실제로 막는다는 시험이 없는 줄은 덜지 않는다.
- 매 턴 글 상한 10,800 B 와 codex 사본 크기 검사를 넘지 않는다.
- 정정 제안은 선택 창 질문 안내뿐 — 검사 파일을 스스로 만들지 않는다.
- 주석 알림은 막지 않는다 (경고만). 사전 중복은 막는다.
- 대시보드는 프로젝트 파일을 읽기만 하고, 진행 주소는 열기만 한다.
- 증거 파일은 프로젝트 안 경로만 받는다 (밖 경로는 거절).
- 사전 중복 검사는 사전 전체를 보되, 이미 예외 파일에 이유가 적힌 짝은 막지 않는다.
- 남의 코드를 실제로 돌리는 것은 사전에 순수로 표식된 함수의 예시 입력뿐 — 그 밖의 코드는 돌리지 않는다.
- 맥(BSD)과 리눅스(GNU) 도구 차이를 둘 다 시험한다.

## Exit criteria

- All TESTS.md scenarios pass
- 매 턴 글 크기가 지금 값보다 작고, 덜어 낸 줄마다 그 규칙의 실패 사례를 검사가 막음
- 정정 사례 · 비정정 사례 · 첫 턴에서 안내가 각각 뜸 · 안 뜸 · 안 뜸
- 새 임시방편 주석만 파일:줄로 알리고, 표식 · 원래 주석은 알리지 않음
- 증거 없는 · 옛 파일 · 프로젝트 밖 증거의 '끝'이 거절되고, 받은 증거가 노드 상세에 보임
- 진행 중 노드 상세에 로그 최근 줄 · 진행률 · 주소 버튼이 보이고, "지금 하는 일" 카드는 사라짐
- 사전 함수와 같은 일을 하는 순수 함수가 계획 끝 검사에서 막힘 — 셸 · TS/JS · 파이썬 · 러스트 모두 실제로 돌려서
- 대시보드 기존 시험은 바뀐 화면에 맞춰 고친 것 말고는 그대로 통과

## Suggested path

1. 매 턴 글 줄과 검사 대조 표를 만들고, 막히는 줄을 덜어 냄 — `readTurnText`, `matchRuleToCheck`, `dropCoveredLines`
2. 정정 턴 뒤 검사로 남기기 제안 안내를 훅에 붙임 — `detectCorrection`, `correctionNotice`
3. 계획 끝 검사에 새 임시방편 주석 알림을 붙임 — `addedCommentLines`, `flagWorkaround`
4. 단계 보고 도구에 증거 · 진행 출처를 더하고, 대시보드 노드 상세로 "지금 하는 일" 칸을 바꿈 — `judgeEvidence`, `stepDetail`
5. 계획 끝 검사가 사전 중복 검사를 자동으로 돌리고, TS/JS · 파이썬 · 러스트도 실제로 돌려 비교함 — `crossInputs`, `sameBehavior`
6. 관련 시험 · 순수 사전 검사를 맥 · 리눅스에서 돌리고 결과를 기록함 — 시험 실행과 기록

## Risks / Open Questions

- 덜어 낸 줄이 모델 행동을 바꿀 수 있음 — 검사 거절 문구가 대신 알리지만, 거절 전 한 번 틀릴 수 있음 (긴 실제 세션에서 확인 필요).
- 정정 판정의 오탐 — 정정이 아닌 턴에 제안이 뜨면 귀찮음. 이번에 다시 잼.
- 임시방편 낱말 목록이 언어마다 다름 — 한국어 · 영어 · 일본어 우선.
- 증거 거절이 일을 막을 수 있음 — 화면이 없는 단계(문서 · 설정)는 바뀐 파일이나 시험 출력이 증거. 거절 이유에 무엇을 내면 되는지 적음.
- 대시보드는 외부 모드라 SCV 래퍼가 단계 보고 도구를 부르는 쪽(프로토콜 글)도 함께 바꿔야 함 — 래퍼 동기화가 멈출 수 있음 (새 칸은 세 곳에 한 번에).
- 러스트는 함수 하나를 돌리려면 작은 실행 파일을 컴파일해야 해 느림 — 짝 수가 많으면 시간이 늘어남. 잰 시간을 기록하고, 사전에 러스트 함수가 있을 때만 돎.
- 사전이 지금 러스트 함수를 읽는지 미확인 — 읽지 않으면 사전 만들기부터 러스트를 넣어야 함.
- 앞 턴의 "표식 없는 새 함수는 검사 밖" 판단은 틀렸음 — 가드 규칙 D 가 이미 막음(정정).
- 릴리스가 코어 · 래퍼 둘 · 대시보드에 걸침 — 한 계획이라 함께 묶임 (사용자 선택).

# Test Plan — 글 대신 검사

## Overview

다섯 가지가 실제로 도는지 확인한다: 매 턴 글이 줄었는데 규칙은 검사가 계속 막는지, 정정 턴에만 제안이 뜨는지, 새 임시방편 주석만 알리는지, 대시보드가 증거 없는 '끝'을 거절하고 노드 상세에 증거 · 실제 진행을 보이는지, 사전과 같은 일을 하는 순수 함수가 언어마다 실제로 돌려져 막히는지. 코어 부분은 새 시험 파일 `core/tests/test-checks-not-comments.sh`, 대시보드 부분은 모드 시험으로 잰다.

## Test scenarios

### T1. 매 턴 글이 줄어듦

- **Setup**: 계획 시작 전 매 턴 글 크기를 `test-instruction-diet.sh` 방식으로 재어 기준값으로 적음.
- **Run**: 1단계 뒤 같은 방식으로 다시 잼.
- **Expected**: 새 값 < 기준값, 새 값 ≤ 10,800 B, codex 사본도 상한 안.
- **Pass criterion**: 크기 비교 두 개가 모두 참이고 `test-instruction-diet.sh` · `test-help-budget.sh` 종료 코드 0.

### T2. 덜어 낸 줄의 규칙을 검사가 여전히 막음

- **Setup**: 덜어 낸 줄마다 그 규칙을 어기는 사례 하나씩(예: 영어 최종 답, 불릿 없는 긴 문단, 등록 없는 쓰기).
- **Run**: 각 사례를 해당 검사에 넣음.
- **Expected**: 사례마다 검사가 거절하고, 거절 문구에 고칠 방법이 적혀 있음.
- **Pass criterion**: 덜어 낸 줄 수 = 거절된 사례 수, 거절 문구가 빈 사례 0.

### T3. 대조 표에 검사가 없는 줄은 남음

- **Setup**: 검사가 없는 규칙 줄이 든 매 턴 글.
- **Run**: `matchRuleToCheck` → `dropCoveredLines`.
- **Expected**: 그 줄은 덜어 낼 목록에 없음.
- **Pass criterion**: 덜어 낼 목록에 검사 없는 줄 0개.

### T4. 정정 턴 뒤에 제안 안내가 뜸

- **Setup**: 같은 세션의 둘째 사람 턴이 "아니, 그게 아니라 … 로 고쳐" 같은 정정.
- **Run**: 매 턴 훅을 그 턴으로 돌림.
- **Expected**: 출력에 "검사로 남기기"를 선택 창으로 물으라는 안내 한 줄.
- **Pass criterion**: 안내 줄 1개.

### T5. 정정이 아닌 턴 · 세션 첫 턴엔 안내가 없음

- **Setup**: (a) 새 기능 요청 턴 (b) 세션 첫 턴인 정정 문장.
- **Run**: 매 턴 훅을 각각 돌림.
- **Expected**: 두 경우 모두 안내 없음.
- **Pass criterion**: 안내 줄 0개 · 0개.

### T6. 고르기 전엔 파일이 생기지 않음

- **Setup**: T4 상태.
- **Run**: 훅을 돌린 뒤 저장소 파일 목록 비교.
- **Expected**: 새 파일 · 바뀐 파일 없음 (기록 파일 제외).
- **Pass criterion**: `git status --short` 전후 같음 (scv/journal · scv/conversations 제외).

- **Setup**: 임시 저장소에 원래 주석 `// TODO: old` 가 있는 파일, 그 위에 변경으로 `// TODO: 나중에 제거` · `# workaround — 큰 변경이라 미룸` · `// 일반 설명` 을 추가.

- **Expected**: 새로 넣은 두 줄만 파일:줄로 알림, 원래 TODO 와 일반 설명은 없음.
- **Pass criterion**: 알림 2줄, 줄 번호가 실제 추가 줄과 같음.

### T8. 순수 함수 표식 주석은 알리지 않음

- **Run**: 주석 알림.
- **Expected**: 알림 없음.
- **Pass criterion**: 알림 0줄, `check-purity.sh` · 사전 모양 시험 종료 코드 0.

### T9. 주석 알림은 막지 않음

- **Setup**: T7 상태.
- **Run**: 계획 끝 검사 전체.
- **Expected**: 알림은 나오지만 종료 코드는 알림이 없을 때와 같음.
- **Pass criterion**: 두 실행의 종료 코드가 같은 숫자(0 = 0).

### T10. 맥 · 리눅스 같은 결과

- **Setup**: T7 · T8 · T19 사례.
- **Run**: 맥(BSD 도구)과 리눅스(GNU 도구, CI 또는 컨테이너)에서 각각.
- **Expected**: 알림 · 막힘 줄이 글자까지 같음.
- **Pass criterion**: 두 출력의 `diff` 종료 코드 0.

# 글 대신 검사 — 발표에서 뽑은 것 + 사용자 지적 두 가지

## Summary

Lauren Tan 발표의 핵심("에이전트를 고칠 일이 생기면 글이 아니라 검사로 남긴다 · 주석의 약속은 강제력이 없다 · 사람은 코드 대신 검증 결과물을 본다")을 SCV 에 넣는다. 매 턴 글 중 검사가 이미 막는 줄을 덜고, 고쳐 준 턴을 검사로 남기자고 제안하고, 새 임시방편 주석을 알린다. 사용자 지적에 따라 대시보드는 단계 노드를 누르면 끝난 단계의 실제 증거와 진행 중 단계의 실제 진행을 보이게 하고(증거 없는 '끝'은 거절), 순수 함수 사전 재사용은 계획 끝 검사가 실제로 막는 규칙으로 만든다.

## Goals / Non-Goals

- **Goals**
  - 1단계: 매 턴 글 중 결정적 검사가 이미 막는 규칙의 줄을 덜어 매 턴 글을 지금보다 작게 함.
  - 2단계: 고쳐 달라는 턴 뒤에 "이 정정을 검사로 남길까요?"를 선택 창으로 제안함.
  - 3단계: 계획 끝 검사가 이번 변경이 새로 넣은 임시방편 주석(TODO · FIXME · HACK · 임시 · 나중에 · workaround 등)을 파일:줄로 알림.
  - 4단계: 대시보드 단계 노드를 누르면 — 끝난 단계는 증거(화면 파일 · 결과 파일 · 명령 출력)를, 진행 중 단계는 에이전트가 알려 준 로그 파일의 최근 줄 · 진행률과 주소 여는 버튼을 보임. 단계 보고 도구는 증거 없는 '끝'을 거절함. 지금의 "지금 하는 일" 칸은 이것으로 바꿈.
  - 5단계: 계획 끝 검사가 순수 함수 사전 중복 검사를 자동으로 돌려 중복이면 막음 — 재사용하거나 다른 이유를 적어야 통과. TS/JS · 파이썬 · 러스트 함수도 서로의 예시 입력으로 실제로 돌려 비교함(지금은 셸만 실제로 돌림).
- **Non-Goals**
  - 주석 전면 금지 · 기존 주석 일괄 삭제.
  - 형식 검증(TLA+ · Lean) · 출시 때 자동 퍼즈.
  - 사용자 프로젝트 코드에 검사를 SCV 가 스스로 써 넣는 일 (제안 → 사용자 선택 → 그 턴의 일로만).
  - 대시보드가 진행 주소(웹 페이지)를 읽거나 퍼 오는 일 — 여는 버튼만.
  - 표식 없는 새 함수 막기 — 이미 가드 규칙(0.81.0+)이 쓰기 때 거절함.
  - Go 함수 실제 실행 — Go 는 지금처럼 예시 글 비교만.
  - 토큰 비율(확인 대 만들기) 측정.

## Approach Overview

1. 매 턴 글의 규칙 줄마다 "그 규칙을 막는 검사가 있는가"를 대조한 표를 만들고, 검사가 실패 사례를 실제로 막는 줄만 덜어 낸다. 덜어 낸 줄의 규칙은 검사의 거절 문구가 대신 알린다.
2. 이미 있는 정정 판정(`scv_show_real_is_correction`)을 매 턴 훅에서 써서, 직전 사람 턴이 정정이면 선택 창으로 "검사로 남기기 / 넘어가기"를 물으라는 안내 한 줄을 싣는다. 크기는 1단계에서 비운 자리 안.
3. 계획 끝 검사(`pure-bench.sh plan-end` 옆)에 이번 변경의 추가 줄만 보는 주석 알림을 붙인다. 표식 주석과 원래 있던 주석은 알리지 않는다. 막지 않고 알린다.
4. 단계 보고 도구(`scv_step`)에 두 칸을 더한다: `doing` 의 진행 출처(로그 파일 경로 · 주소), `done` 의 증거(파일 경로 목록 또는 명령 출력 발췌). 증거 판정은 순수 함수 하나 — 파일이 있고 단계 시작 시각 뒤에 바뀌었는가, 출력 발췌는 비어 있지 않은가. 실패하면 거절하고 이유를 돌려준다. 패널은 단계 노드를 누르면 상세를 펼친다: 끝 = 증거 목록(이미지는 그림으로, 글은 앞부분), 진행 중 = 로그 최근 줄 · 진행률(지금 뒤 작업 진행률 읽기 재사용) · 주소 버튼. "지금 하는 일" 카드는 이 상세로 대체한다.
5. 지금 사전 중복 검사(`pure-catalog.sh check`)는 문서에만 적혀 있고 어디서도 자동으로 불리지 않는다(확인). 계획 끝 검사가 사전을 다시 만들고 중복 검사를 돌려, 중복이면 막는다. 셸 아닌 함수는 지금 예시 글끼리만 견주므로, TS/JS(node) · 파이썬(python3) · 러스트(rustc) 함수를 서로의 예시 입력으로 실제로 돌려 출력이 같으면 중복으로 본다. 돌릴 도구가 없으면 '돌려 보지 못함: <언어>'로 알린다. 다르다고 보면 기존 중복 예외 파일에 이유를 적는다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

## Guardrails

- 순수 함수 표식 주석(`@pure` · `@deterministic` · `@effect`)과 사전 모양을 바꾸지 않는다.
- 검사가 실패 사례를 실제로 막는다는 시험이 없는 줄은 덜지 않는다.
- 매 턴 글 상한 10,800 B 와 codex 사본 크기 검사를 넘지 않는다.
- 정정 제안은 선택 창 질문 안내뿐 — 검사 파일을 스스로 만들지 않는다.
- 주석 알림은 막지 않는다 (경고만). 사전 중복은 막는다.
- 대시보드는 프로젝트 파일을 읽기만 하고, 진행 주소는 열기만 한다.
- 증거 파일은 프로젝트 안 경로만 받는다 (밖 경로는 거절).
- 사전 중복 검사는 사전 전체를 보되, 이미 예외 파일에 이유가 적힌 짝은 막지 않는다.

## Risks / Open Questions

- 덜어 낸 줄이 모델 행동을 바꿀 수 있음 — 검사 거절 문구가 대신 알리지만, 거절 전 한 번 틀릴 수 있음 (긴 실제 세션에서 확인 필요).
- 정정 판정의 오탐 — 정정이 아닌 턴에 제안이 뜨면 귀찮음. 이번에 다시 잼.
- 임시방편 낱말 목록이 언어마다 다름 — 한국어 · 영어 · 일본어 우선.
- 증거 거절이 일을 막을 수 있음 — 화면이 없는 단계(문서 · 설정)는 바뀐 파일이나 시험 출력이 증거. 거절 이유에 무엇을 내면 되는지 적음.
- 대시보드는 외부 모드라 SCV 래퍼가 단계 보고 도구를 부르는 쪽(프로토콜 글)도 함께 바꿔야 함 — 래퍼 동기화가 멈출 수 있음 (새 칸은 세 곳에 한 번에).
- 러스트는 함수 하나를 돌리려면 작은 실행 파일을 컴파일해야 해 느림 — 짝 수가 많으면 시간이 늘어남. 잰 시간을 기록하고, 사전에 러스트 함수가 있을 때만 돎.
- 사전이 지금 러스트 함수를 읽는지 미확인 — 읽지 않으면 사전 만들기부터 러스트를 넣어야 함.
- 앞 턴의 "표식 없는 새 함수는 검사 밖" 판단은 틀렸음 — 가드 규칙 D 가 이미 막음(정정).
- 릴리스가 코어 · 래퍼 둘 · 대시보드에 걸침 — 한 계획이라 함께 묶임 (사용자 선택).

## Test scenarios

### T1. 매 턴 글이 줄어듦

- **Setup**: 계획 시작 전 매 턴 글 크기를 `test-instruction-diet.sh` 방식으로 재어 기준값으로 적음.

- **Pass criterion**: 크기 비교 두 개가 모두 참이고 `test-instruction-diet.sh` · `test-help-budget.sh` 종료 코드 0.

### T2. 덜어 낸 줄의 규칙을 검사가 여전히 막음

- **Setup**: 덜어 낸 줄마다 그 규칙을 어기는 사례 하나씩(예: 영어 최종 답, 불릿 없는 긴 문단, 등록 없는 쓰기).
- **Run**: 각 사례를 해당 검사에 넣음.
- **Expected**: 사례마다 검사가 거절하고, 거절 문구에 고칠 방법이 적혀 있음.
- **Pass criterion**: 덜어 낸 줄 수 = 거절된 사례 수, 거절 문구가 빈 사례 0.

### T3. 대조 표에 검사가 없는 줄은 남음

- **Setup**: 검사가 없는 규칙 줄이 든 매 턴 글.
- **Run**: `matchRuleToCheck` → `dropCoveredLines`.
- **Expected**: 그 줄은 덜어 낼 목록에 없음.
- **Pass criterion**: 덜어 낼 목록에 검사 없는 줄 0개.

- **Setup**: 같은 세션의 둘째 사람 턴이 "아니, 그게 아니라 … 로 고쳐" 같은 정정.
- **Run**: 매 턴 훅을 그 턴으로 돌림.
- **Expected**: 출력에 "검사로 남기기"를 선택 창으로 물으라는 안내 한 줄.

- **Expected**: 두 경우 모두 안내 없음.

- **Expected**: 거절, 답에 "증거(파일 경로 또는 명령 출력)를 함께 보내라"는 이유. 노드 상태는 진행 중 그대로.
- **Pass criterion**: 거절 1건, 상태 변화 0.

### T12. 단계 시작 전에 생긴 파일은 증거로 안 받음

- **Setup**: 단계 시작 시각보다 바뀐 시각이 앞선 파일 하나, 뒤인 파일 하나.
- **Run**: 앞선 파일로 `done` → 뒤인 파일로 `done`.
- **Expected**: 첫째 거절(이유: 단계 시작 전 파일), 둘째 받음.
- **Pass criterion**: 거절 1 · 받음 1.

### T13. 프로젝트 밖 · 없는 파일은 거절

- **Setup**: 프로젝트 밖 경로, 없는 경로.
- **Run**: 각각으로 `done`.
- **Expected**: 둘 다 거절, 이유가 각각 "프로젝트 밖" · "파일 없음".
- **Pass criterion**: 거절 2건, 이유 글이 서로 다름.

### T14. 명령 출력 발췌도 증거로 받음

- **Setup**: 화면이 없는 단계, 시험 출력 발췌 글.
- **Run**: 발췌 글로 `done` → 빈 글로 `done`.
- **Expected**: 첫째 받음, 둘째 거절.
- **Pass criterion**: 받음 1 · 거절 1.

### T15. 끝난 노드를 누르면 증거가 보임

- **Setup**: 이미지 파일 하나 · 글 파일 하나 · 출력 발췌를 증거로 받은 끝난 단계.
- **Run**: 모드 시험에서 그 노드를 누름.

### T16. 진행 중 노드를 누르면 실제 진행이 보임

- **Run**: 그 노드를 누름.
- **Expected**: 로그 최근 줄, 진행률 막대(찾은 경우), 주소 여는 버튼.
- **Pass criterion**: 세 가지가 모두 나오고, 주소로 나가는 읽기 요청 0건.

### T17. "지금 하는 일" 카드가 사라짐

- **Run**: 패널을 그림.

### T18. 계획 끝 검사가 사전 중복 검사를 자동으로 돌림
