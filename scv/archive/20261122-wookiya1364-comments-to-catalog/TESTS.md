# Test Plan — 코드 주석을 없애고 순수 함수 사전에만

## Overview

사전이 원본으로 바뀌어도 사전 검사 · 순수 검사 · 선언 안전장치가 같은 판단을 하는지, 주석 넣는 편집이 막히는지, 옮기기가 잃는 것 없이 주석을 사전으로 옮기고 코드 뜻을 바꾸지 않는지, 설정을 끈 프로젝트는 그대로인지, 실제 실사용 프로젝트에서 빌드 · 시험이 통과하는지 본다.

## Test scenarios

### T1. 사전이 원본 — 코드에 주석이 없어도 사전 검사가 통과
- **Setup**: 주석 없는 함수 셋(sh · ts · rs) + 그 함수들의 사전 항목.
- **Run**: 사전 검사(예시 실행 · 중복 · 낡음).
- **Pass criterion**: 통과. 사전에 있는데 코드에 없는 함수 · 이름이 바뀐 함수는 '낡음'으로 잡힘.

### T2. 순수 검사가 사전의 표시로 함수를 찾음
- **Run**: 사전에 '순수'로 적힌 함수 본문에 파일 쓰기를 넣음.
- **Pass criterion**: 순수 검사가 그 함수를 위반으로 잡음(주석 없이).

### T3. 함수 선언 안전장치
- **Run**: 사전에 없는 새 함수를 넣는 편집 · 사전에 적은 뒤 같은 편집.
- **Pass criterion**: 앞은 거절, 뒤는 허용.

### T4. 주석 막기
- **Run**: 설정을 켠 프로젝트에서 sh · ts · py · rs 파일에 주석 줄을 넣는 편집, 문자열 안 `#` · `//` 를 넣는 편집.
- **Pass criterion**: 주석 줄은 거절(줄 번호와 사전에 적으라는 안내), 문자열 안은 허용. 계획 끝 검사도 남은 주석을 잡음.

### T5. 옮기기 — 잃는 것 없이, 코드 뜻 그대로
- **Run**: 표식 주석 · 설명 주석 · 도구 표시 줄이 섞인 파일(sh · ts/js · py · rs)을 옮기기.
- **Pass criterion**: 코드 주석 0줄, 표식은 사전 항목으로, 설명 · 도구 표시는 그 함수 · 파일 항목의 메모로. 옮기기 전 사전 항목 수 ≤ 뒤. 주석을 뺀 코드가 옮기기 전과 같은 동작(시험 통과 · 같은 출력).

### T6. 기존 프로젝트 자동 옮기기
- **Run**: 주석이 있는 프로젝트에서 설정을 켜고 다음 액션을 부름 · 한 번 더 부름.
- **Pass criterion**: 첫 번에 옮기기가 한 번 돌고 옮긴 수 · 지운 수를 보고, 둘째에는 아무것도 안 함. 커밋은 하지 않음.

### T7. 설정을 끄면 지금과 같다
- **Run**: 설정 없음 · 끔.
- **Pass criterion**: 사전 생성 · 검사 · 선언 거절 · 매 턴 글이 지금과 같음(바이트 비교).

### T8. 실사용 프로젝트에 적용
- **Run**: 실사용 프로젝트 사본에서 옮기기 → 빌드 · 시험.
- **Pass criterion**: 코드 주석 0줄, 사전 함수 항목 수 ≥ 옮기기 전 표식 수(Rust 포함), 빌드 · 시험 통과. 도구 표시 줄 삭제로 깨진 것은 목록과 함께 보고.

### T9. /scv:catalog-source 명령
- **Run**: 인자 없이(뒤집기) · off · on · 잘못된 인자.
- **Pass criterion**: 켜면 그 자리에서 옮김(주석 0줄) · 끄면 주석 넣는 편집 허용(사전 원본 표시는 그대로) · 다시 켜면 '이미 옮김'에 막기 돌아옴 · 잘못된 인자는 exit 2. (시험 파일에서는 T8)

## How to run

```bash
bash core/tests/test-comments-to-catalog.sh
```

## Pass criteria

- T1–T8 통과(맥 · 리눅스 · 코덱스 사본), 전체 실행 통과, 실사용 프로젝트 적용 수치(주석 수 전후 · 사전 항목 수 전후 · 빌드 · 시험)가 마무리 보고에.
