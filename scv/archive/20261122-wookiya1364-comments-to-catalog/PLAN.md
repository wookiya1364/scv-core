# 코드 주석을 없애고 순수 함수 사전에만 — 사전이 원본 · 주석 막기 · 자동 옮기기

## Summary

SCV 를 쓰는 프로젝트(예: 실사용 프로젝트)의 코드에는 함수 위 표식 주석(`@pure` 역할 · 종류 · 예)과 설명 주석이 섞여 있고, 사용자는 코드 안 주석이 오해를 부른다고 본다(2026-11-22). 지금 순수 함수 사전(`scv/core/catalog/pure`)은 코드 주석에서 만들어지는 생성물이라 주석을 지우면 사전도 빈다. 이 계획은 사전을 원본으로 뒤집고, 코드에서는 모든 주석(함수 설명 · 그 밖의 설명 · 도구 표시 줄)을 없애 그 내용을 사전에만 최신으로 두며, 앞으로 코드에 주석이 생기지 못하게 막는다. 이미 있는 프로젝트의 코드 주석도 SCV 가 자동으로 사전으로 옮긴다.

## Goals / Non-Goals

- **Goals**
  - 사전이 원본: 함수마다 '파일 · 이름'으로 코드와 이어지고, 역할 · 종류 · 예 · 순수/부수효과 표시(부수효과는 이유)가 사전에만 있다.
  - 순수 검사 · 사전 검사(예시 실행 · 중복 · 낡음) · 함수 선언 안전장치가 코드 주석 대신 사전을 읽는다.
  - 주석 막기: 설정을 켠 프로젝트에서 코드에 주석을 넣는 편집은 쓰기 전에 거절되고, 계획 끝 검사도 남은 주석을 잡는다.
  - 그 밖의 설명 주석과 도구 표시 줄(`#!` · `eslint-disable` · `shellcheck` 등)도 코드에서 지우고, 그 내용은 사전의 그 파일 · 함수 항목에 최신으로 옮겨 적는다.
  - 자동 옮기기: 이미 있는 프로젝트는 설정을 켜거나 SCV 를 올린 뒤 다음 액션 때 프로젝트 전체 코드 주석을 사전으로 옮기고 지운다(옮긴 수 · 지운 수 보고, 커밋은 사람이).
  - 규약 · 계획 틀 · 매 턴 안내 · 대시보드 문구가 '함수 위 주석' 대신 '사전에 적는다'를 말한다.
  - 실사용 프로젝트에 적용해 빌드 · 시험이 그대로 통과하는지 본다.
- **Non-Goals**
  - SCV 코어 · 두 래퍼 자기 코드의 주석 정리.
  - 문서 파일(md 등) · 설정 파일의 주석.
  - (2026-11-22 사용자 요청으로 바뀜 — 기본값을 on 으로 함. 10단계)

## Approach Overview

사전 파일에 함수 항목마다 '위치: 파일 · 이름'이 이미 있으니, 그것을 열쇠로 삼아 사전을 원본으로 만든다. 순수 검사는 사전의 표시로 함수를 찾아 그 본문을 검사하고, 선언 안전장치는 '새 함수가 사전에 있는가'로 바꾼다. 주석 막기는 언어별 주석 모양(`#` · `//` · `/* */` · `///` · `"""` 등)을 가려 편집이 새로 넣는 주석 줄을 거절하고, 문자열 · 정규식 안의 같은 글자는 주석으로 보지 않는다. 옮기기 도구는 표식 주석을 사전 항목으로, 그 밖의 주석은 그 함수(또는 파일) 항목의 '메모'로 옮긴 뒤 코드에서 지운다. 도구 표시 줄을 지울 때 깨지는 것(스크립트 실행 · 검사 설정)은 실사용 프로젝트 적용에서 재서 정한다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readSources,     // 프로젝트 코드 · 사전 파일 → 파일 글 · 사전 항목 (입구)
  findComments,    // 파일 글 · 언어 → 주석 조각 목록(줄 · 종류: 표식 · 설명 · 도구 표시)
  toCatalogEntries,// 주석 조각 · 함수 위치 → 사전 항목(역할 · 종류 · 예 · 표시 · 메모)
  mergeCatalog,    // 지금 사전 · 새 항목 → 합친 사전(잃는 항목 없음)
  stripComments,   // 파일 글 · 주석 조각 → 주석 없는 파일 글
  commentGate,     // 편집 전 글 · 편집 뒤 글 · 언어 → 허용 | 거절(새 주석 줄)
  writeResults,    // 사전 · 파일 → 파일 쓰기 · 보고 (출구)
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `readSources` | 코드 파일과 사전 파일을 읽음 | 경로들 → 글 | 부수효과 (입구) |
| 2 | `findComments` | 언어별 주석 모양으로 주석 조각을 찾음(문자열 안은 뺌) | 글 · 언어 → 조각 목록 | 순수 |
| 3 | `toCatalogEntries` | 조각을 사전 항목으로 바꿈 | 조각 · 위치 → 항목 | 순수 |
| 4 | `mergeCatalog` | 지금 사전과 합침 — 같은 함수는 최신으로, 잃는 것 없음 | 사전 · 항목 → 사전 | 순수 |
| 5 | `stripComments` | 코드에서 주석을 지움 | 글 · 조각 → 글 | 순수 |
| 6 | `commentGate` | 편집이 새 주석을 넣는지 가름 | 전 · 후 · 언어 → 판정 | 순수 |
| 7 | `writeResults` | 사전 · 코드 파일을 쓰고 보고 | 결과 → 파일 · 보고 | 부수효과 (출구) |

- 부수효과 위치: 1 · 7(그리고 쓰기 전 안전장치의 거절 출력).
- 재사용: 사전 만들기 · 검사(`pure-catalog.sh`), 순수 검사(`check-purity.sh`), 함수 선언 안전장치(0.81.0+), 자동 갱신 자리(`scv_autosync`).

## Guardrails

- 설정에 off 를 적은 프로젝트는 출력 · 검사 · 거절이 지금과 같다(기본은 on — 키가 없으면 켬).
- 옮기기 전 사전의 함수 설명 수보다 옮긴 뒤 수가 적으면 쓰지 않고 멈춘다(잃는 항목 0).
- 문자열 · 정규식 · 여기 문서 안의 `#` · `//` 는 주석으로 보지 않는다 — 코드 뜻이 바뀌면 안 된다.
- 자동 옮기기는 사람 커밋 전 상태로 둔다(SCV 가 커밋하지 않음) · 옮긴 파일 목록을 보고한다.
- SCV 코어 · 두 래퍼 자기 코드, 문서 · 설정 파일은 건드리지 않는다.
- 코어 글에 호스트 · 도구 이름을 쓰지 않는다. 공개 저장소에 다른 프로젝트 이름을 넣지 않는다.

## Exit criteria

- TESTS.md 시나리오 통과(맥 · 리눅스 · 코덱스 사본), 전체 실행 통과.
- 실사용 프로젝트에 적용: 코드 주석 0줄, 사전 함수 항목 수 ≥ 옮기기 전 표식 수, 실사용 프로젝트 빌드 · 시험 통과.
- 설정을 켠 프로젝트에서 주석을 넣는 편집이 거절됨(실제 훅으로).

## Suggested path

1. 사전을 원본으로 — 함수와 '파일 · 이름'으로 연결, 낡음 검사를 '사전 항목이 코드에 있는가'로 뒤집음 — `readSources`, `mergeCatalog`
2. 순수 검사 · 사전 검사 · 함수 선언 안전장치가 사전의 표시를 읽음 — `readSources`
3. 주석 막기 — 주석 넣는 편집 거절 + 계획 끝 검사, 설정 하나로 켬 — `commentGate`
4. 옮기기 도구 — 코드 주석을 사전으로 옮기고 지움(sh · ts/js · py · rs) — `findComments`, `toCatalogEntries`, `stripComments`, `writeResults`
5. 기존 프로젝트 자동 옮기기 — 설정을 켜거나 SCV 를 올린 뒤 다음 액션 때 프로젝트 전체 코드 주석을 사전으로 옮기고 지우고 보고 — `writeResults`
6. 규약 · 계획 틀 · 매 턴 안내 · 대시보드 문구를 '사전에 적는다'로 — 함수 위 주석을 말하는 글을 바꿈
7. 실사용 프로젝트에 적용 — 옮기기 뒤 빌드 · 시험 통과, 도구 표시 줄 삭제 영향을 재서 정함 — 실제 프로젝트로 확인
8. 시험 · 전체 실행(맥 · 리눅스 · 코덱스 사본) — 시험으로 확인
9. /scv:catalog-source 명령 — on/off(없으면 뒤집기), 켜면 바로 옮기기, 끄면 주석 막기만 풂(사전은 원본 그대로) — `commentGate`
10. 기본값 on — 설정 파일에 키가 없으면(새로 설치 · 업데이트) 켬, 적힌 off 는 그대로 — `commentGate`

## Risks / Open Questions

- 도구 표시 줄(`#!` 등)을 지우면 스크립트를 직접 실행할 수 없게 되거나 검사 도구 설정이 사라질 수 있음 — 7단계에서 실제로 재서, 깨지면 사용자에게 선택으로 물음(해로운 변경이면 넣지 않음).
- 지금 사전이 Rust 함수 일부를 못 담음(실사용 프로젝트의 `start_battle` · `grade_affixes` 없음, 확인 2026-11-22) — 1 · 4단계에서 언어별 함수 찾기를 맞춤.
- 주석과 문자열을 가르는 일은 언어마다 다름 — 틀리면 코드가 바뀜. 옮긴 뒤 빌드 · 시험으로 막음.
- 대시보드는 다른 저장소(scv-mods) — 문구 · 표시가 사전 원본을 따라가는지 6단계에서 같이 봄.
