## 1. 문제

- 상황: SCV 를 쓰는 실사용 프로젝트 코드에 함수 표식 주석과 설명 주석이 섞여 있고, 사용자는 코드 안 주석이 자꾸 오해를 부른다고 봄(2026-11-22). 예: 실사용 프로젝트의 전투 코드 파일 하나가 3,191줄 중 306줄이 주석.
- 기대: 코드에는 주석이 하나도 없고, 함수 설명은 순수 함수 사전에만 최신으로 있음.
- 실제: 사전은 코드 주석에서 만들어지는 생성물이라 주석을 지우면 사전이 빔. 새 함수에 표식 주석이 없으면 쓰기가 거절됨(0.81.0+). 사전에 Rust 함수 일부가 없음(start_battle · grade_affixes, 확인).
- 재현 조건: 주석을 지운 뒤 사전 다시 만들기 — 항목이 사라짐.

## 6. 해결과 검증

- 해결책과 고른 이유: 설정 하나(SCV_CATALOG_SOURCE=on)로 켜는 '사전이 원본' 모드. 언어별 주석 읽기 도구(code-comments.py — 문자열 · 정규식 · 원시 문자열 · 여기 문서 제외)가 주석을 찾고 지우며, 옮기기(comments-migrate.sh)가 표식 → 사전 항목, @effect → effects.md, 나머지 → notes.md 로 옮기고 SOURCE 표시를 남김. 그 뒤 사전 검사 · 선언 검사 · 쓰기 전 안전장치가 사전을 봄. 첫 줄 #! 는 실행기 지정이라 남김(사용자 결정, 지우면 직접 실행이 깨짐). 기존 사전 렌더 형식을 그대로 되읽어 예시 실행 · 중복 검사를 다시 씀.
- 고치기 전후 값: 실사용 프로젝트 사본 — 코드 주석 13,780줄 → 0(파일 519개), 사전 순수 항목 297 → 1,523(+부수효과 1,255 · 메모 5,850, 러스트 함수 새로 들어감), 타입 오류 옮기기 전과 같음(줄 번호만), cargo test 30 → 30 통과, 단위 시험 141 → 140(그 프로젝트 자기 시험 하나가 함수 위 @pure 주석을 요구 — 사전 확인으로 바꿔야 함).
- 부작용과 회귀 시험: 설정을 끈 프로젝트는 옮기지 않고 주석 넣는 편집도 막지 않음(T7). test-comments-to-catalog T1–T7. 사전이 1,500개 규모가 되면 사전 검사의 예시 실제 실행이 25분을 넘김(기존 기능의 규모 문제 — 따로 고칠 일). JS 템플릿 문자열 ${ } 안 주석은 지우지 못함(한계).

## 7. 배운 것

- 다음에 같은 문제를 만나면 진단하는 법: 사본에서 옮기기 전 시험 → 옮기기 → 같은 시험을 돌려 차이만 봄. 프로젝트 자기 시험이 주석을 요구하는지부터 찾음.
- 다른 곳에도 쓸 수 있는 것: 생성물이던 문서를 원본으로 뒤집을 때는 렌더 형식을 그대로 되읽는 함수 하나로 기존 검사를 모두 살릴 수 있음. 주석처럼 생긴 실행기 지정(#!)은 지우기 전에 직접 실행으로 재 봐야 함.
