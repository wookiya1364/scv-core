# 턴 끝 계획 검사는 이 세션이 고친 파일만 셈

## Summary

0.87.2 의 턴 끝 검사는 '건드린 폴더'에서 턴 시작 뒤 바뀐 파일을 누가 바꿨든 모두 센다. 읽기 도구의 경로 · 셸의 폴더 이동도 '건드림'으로 친다.
2026-11-09 실측: 이 세션은 slay 폴더를 읽기만 했는데, 같은 때 slay 세션이 고친 `scripts/balance-bot/stage-sim.mts` 때문에 두 번 막혔다.
이 세션이 쓴 파일만 세도록 고친다 — 읽기만 한 폴더는 세지 않고, 편집 도구는 적힌 파일만, 셸 명령은 명령 앞뒤 모습을 비교해 바뀐 파일만 이 세션 몫으로 친다.

## Goals / Non-Goals

- **Goals**
  - 읽기 도구(파일 이름만 있고 쓸 내용이 없는 도구)는 폴더도 파일도 세지 않음
  - 편집 도구는 적힌 파일 하나만 이 세션 몫('내 파일')으로 셈
  - 셸 명령은 명령 앞 모습과 그다음 도구 앞(또는 턴 끝) 모습을 비교해 바뀐 파일만 '내 파일'로 셈 — 도구 뒤 훅이 없는 호스트도 같은 방식
  - 턴 끝 판정은 '바뀐 파일 ∩ 내 파일'만 셈
- **Non-Goals**
  - 래퍼 릴리스 (core 만 고친다)
  - 셸 명령이 도는 그 몇 초 사이 다른 세션이 같은 폴더를 고친 경우의 완전한 분리

## Approach Overview

- 도구 앞 훅(guard)이 도구 입력 모양으로 종류를 정한다: 명령 글이 있으면 셸, 파일 경로와 쓸 내용(content · old_string · new_string · edits · new_source)이 있으면 쓰기, 그 밖은 읽기.
- turn-check.sh `touch` 가 `--kind write|shell|read` 를 받는다. 어떤 종류든 먼저 '정산'(앞 셸 명령의 비교)을 한다.
- 쓰기: 그 파일의 절대 경로를 상태 폴더 `mine` 에 적고 저장소를 시작 사진에 넣는다.
- 셸: 이 프로젝트와 명령의 cd · -C 대상 저장소를 시작 사진에 넣고, 지금 모습을 '대기 사진'(pend.*)으로 찍는다.
- 정산: 대기 사진과 지금 모습을 비교해 바뀐 파일(HEAD 가 움직였으면 그 사이 커밋 파일도)을 `mine` 에 적고 대기 사진을 지운다.
- `end` 는 먼저 정산하고, 저장소별 바뀐 파일 중 `mine` 에 있는 것만 센다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  scv_tc_tool_kind,   // 도구 입력의 칸 이름들 → write | shell | read
  scv_tc_abs_paths,   // 저장소 + 상대 경로들 → 절대 경로들
  scv_tc_mine_only,   // 절대 경로들 + 내 파일 목록 → 내 파일인 것만
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `scv_tc_tool_kind` | 도구 입력에 어떤 칸이 있는지로 쓰기 · 셸 · 읽기를 가름 | 명령 유무 · 경로 유무 · 내용 유무 → write/shell/read | 순수 |
| 2 | `scv_tc_abs_paths` | 저장소 맨 위와 상대 경로를 이어 절대 경로로 바꿈 | 저장소 · 경로 줄들 → 절대 경로 줄들 | 순수 |
| 3 | `scv_tc_mine_only` | 바뀐 파일 중 내 파일 목록에 있는 것만 남김 | 경로 줄들 · 내 파일 줄들 → 남은 줄들 | 순수 |
| 4 | `settle` | 대기 사진과 지금 모습을 비교해 내 파일에 더함 | 상태 폴더 → (mine 파일에 씀) | 부수효과 (파일 읽기 · 쓰기) |

- 부수효과 위치: 사진 찍기(snap_root) · 정산(settle) · 상태 파일 쓰기는 turn-check.sh 어댑터, 도구 입력 읽기는 guard 훅.
- 재사용: `scv_tc_diff` · `scv_tc_filter` · `snap_root` · `take_snap` · `root_of` 그대로.

## Guardrails

- guard 훅의 다른 규칙(계획 파일 손으로 만들기 금지 · 영수증 없는 바깥 쓰기 금지 · help 표시 · 영수증 기록)은 건드리지 않는다.
- 판정 함수 `scv_tc_judge` 의 규칙은 바꾸지 않는다 — 들어가는 '바뀐 파일 수'만 달라진다.
- core 에 호스트 이름(도구 이름 · 설정 폴더 이름)을 쓰지 않는다 — 도구 종류는 입력 칸 모양으로만 정한다.
- 어떤 실패도 세션을 막지 않는다 — 판단할 수 없으면 지금처럼 통과.

## Exit criteria

- All TESTS.md scenarios pass
- 전체 core 시험 통과 (bash 5 · bash 3.2)
- slay 같은 상황(남의 세션이 같은 폴더를 고침)을 재현한 시험에서 이 세션이 막히지 않음

## Suggested path

1. 순수 함수 세 개를 lib 에 더함 — `scv_tc_tool_kind`, `scv_tc_abs_paths`, `scv_tc_mine_only`
2. turn-check.sh 에 `--kind` · 대기 사진 · 정산을 넣고 end 가 내 파일만 세게 함 — `settle`
3. guard 훅이 도구 종류를 정해 touch 에 넘김 — `scv_tc_tool_kind`
4. 시험: 남이 고친 파일 · 편집 도구 · 셸 · 읽기만 · 커밋 사례를 더하고 기존 시험을 새 방식에 맞춤 — 시험 시나리오를 더하고 전체 시험을 돌림
5. 순수 함수 목록 · 변경 기록 · 버전 · 템플릿 지문을 맞춤 — 릴리스에 필요한 기록을 맞춤

## Risks / Open Questions

- 셸 명령의 비교 구간은 '명령 앞 ~ 다음 도구 앞'이라, 그 사이(모델이 생각하는 시간 포함) 다른 세션이 같은 폴더에서 고친 파일은 내 몫으로 섞일 수 있다. 도구 뒤 훅을 쓰면 줄일 수 있지만 래퍼 변경이라 이번 범위 밖.
- 셸 명령마다 사진을 한 번 더 찍는다 — 바뀐 파일이 많은 저장소에서 느려지는지 시험의 시간 상한으로 본다.
