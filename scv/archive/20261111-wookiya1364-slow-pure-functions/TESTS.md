# Test Plan — 느린 순수함수 고치기

## Overview

고친 함수 17개가 고치기 전과 같은 답을 내는지, 그리고 정말 빨라졌는지를 본다.
답은 옛 본문을 그대로 옮긴 견줄 판(`core/tests/fixtures/slow-pure/reference.sh`)과 맞대고, 시간은 재는 명령(`pure-bench.sh`)으로 잰다.

## Test scenarios

### T1. 함수 머리의 예시에서 두 판의 답이 같다

- **Setup**: 17개 함수 바로 위 주석의 예시 인자를 읽는다
- **Run**: 예시 인자를 옛 본문(`ref_<이름>`)과 고친 본문에 넣는다
- **Expected**: 출력(끝의 줄바꿈까지)과 끝 코드가 같다
- **Pass criterion**: 17개 함수의 모든 예시에서 다름 0건

### T2. 큰 입력에서 두 판의 답이 같다

- **Setup**: 첫 예시를 25번 · 100번 되풀이한 인자(재는 명령과 같은 방법)
- **Run**: 두 판에 넣는다. 옛 본문이 너무 오래 걸리는 셋은 작은 배수로 본다 — 뒤쪽 충돌 검사 25 · 50번, 앞쪽 충돌 검사 8 · 16번, 언어 검사 25 · 50번
- **Expected**: 출력과 끝 코드가 같다
- **Pass criterion**: 다름 0건

### T3. 모서리 입력에서 두 판의 답이 같다

- **Setup**: 빈 글, 한 글자, 공백만, 한글 · 일본어 · 그림 글자가 섞인 글, 줄 끝이 없는 글, 짝이 안 맞는 따옴표 · 괄호, 같은 줄이 되풀이되는 목록, 깨진 바이트가 든 낱말. 고친 방법이 기대는 경계도 넣는다: 40바이트 토막 경계, 4000바이트 자르는 자리, 머리 토막(64자 · 32자)을 넘겨야 답이 정해지는 줄, 블록을 지운 자리에서 새 블록 머리가 생기는 글
- **Run**: 함수마다 그 함수에 뜻이 있는 모서리 입력을 두 판에 넣는다. 따옴표 속 비우기는 따옴표 · 괄호 · 글자로 만든 길이 5까지의 글 전부(2,168개)를 넣는다
- **Expected**: 출력과 끝 코드가 같다
- **Pass criterion**: 다름 0건. 그물이 성긴지 보려고 일부러 두 군데를 틀리게 고친 판(머리 토막을 늘리지 않음 · 4000바이트 경계를 한 토막 넘김)을 넣었을 때는 실패해야 한다(2026-11-11 에 손으로 확인)

### T4. 충돌 검사 둘은 큰 입력을 5초 안에 끝낸다

- **Setup**: 예시를 100번 되풀이한 입력 (고치기 전: 뒤쪽 23초, 앞쪽 60초 넘김)
- **Run**: 고친 두 함수를 한 번씩 돌린다
- **Expected**: 각각 5초 안에 끝나고 겹침 줄이 나온다
- **Pass criterion**: 걸린 시간 5초 미만 (붐비는 컴퓨터를 생각해 넉넉히 잡은 값 — 고친 뒤 실제 값은 0.2초 안팎)

### T5. 낱말 세기는 프로그램을 낱말 수만큼 부르지 않는다

- **Setup**: 줄에 없는 대문자 낱말 51개 · 201개와 맞는 낱말 하나. 글자 바꾸는 프로그램 앞에 횟수를 세는 가짜를 둔다
- **Run**: 낱말 세기를 한 번씩 돌린다
- **Expected**: 띄운 횟수가 두 입력에서 같고 2번 이하다 (고치기 전: 51번 · 201번). 센 값은 1 그대로다
- **Pass criterion**: 띄운 횟수 같음 · 2 이하 · 센 값 1

### T6. 순수 검사와 사전 검사

- **Setup**: 고친 뒤의 저장소
- **Run**: `bash core/scripts/check-purity.sh`, `bash core/scripts/pure-catalog.sh check` (전체 시험의 `test-purity` · `test-pure-catalog` 도 같은 것을 본다)
- **Expected**: 선언과 다른 함수 0개, 사전과 코드가 같음, 예시가 모두 맞음
- **Pass criterion**: 두 명령 모두 끝 코드 0

### T7. 한도 안으로 들어온 함수는 배수 기준 목록에 없다

- **Setup**: 두 셸에서 363개 전체를 다시 재서 고쳐 쓴 기준 목록(`scale-baseline.bash3` · `scale-baseline.bash5`). 고치기 전에는 15개 · 11개였다
- **Run**: 이 계획으로 한도(입력 4배에 8배) 안에 들어온 12개 이름이 두 목록에 있는지 본다
- **Expected**: 하나도 없다. 목록은 4개 · 4개다(남은 넷은 이유와 함께 계획에 적었다)
- **Pass criterion**: 12개 이름 가운데 목록에 있는 것 0개. 다시 들어오면 시험이 실패한다

## How to run

```bash
bash core/tests/test-slow-pure-functions.sh
```

## Pass criteria

- 위 명령이 옛 셸(bash 3.2)과 새 셸(bash 5)에서 끝 코드 0
- 전체 시험이 두 셸에서 통과
- 17개의 앞뒤 시간 표가 계획 폴더에 있다
