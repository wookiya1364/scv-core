# Test Plan — 결정 색인과 recap

## Overview

확인하는 것: 결정이 쌓이면서 **판단 없이** 색인되는지, 로그 전체를 안 읽고 하나만
꺼내지는지, recap 이 아무것도 안 쓰고 짧은지, 0.32.0 의 색인과 이름이 계속 읽히는지.

판정은 전부 문자열 비교다. 순수성은 `check-purity.sh` 가 본다.

## Test scenarios

### T1–T8. 색인 순수부와 저널 읽기  ✅
0.32.0 에서 옮겨온 그대로. 이름만 `record_*` 로 바뀌었다.
표시 정규화 18가지 전수, 레코드 만들기, 최신이 이기는 조회, 걸러내기, 순수성,
저널을 훑지 않는 읽기, 편집 감지, 없어도 안 죽음.

### T9. 결정이 스스로 색인된다  ✅
- **Setup**: 새 프로젝트에 결정 하나를 쌓는다.
- **Expected**:
  - 결정이 로그에 쌓인다
  - **쌓으면서 자동으로 색인된다** — 부르는 쪽이 색인을 의식하지 않는다
  - 색인이 `scv/INDEX.tsv` 한 곳에
  - 알 수 없는 판정은 **거부**한다 (형식이 흔들리면 나중에 로그를 못 읽는다)
  - 근거 없이는 **안 받는다**
  - 이름으로 그 결정만 읽힌다
  - **읽은 양이 로그의 절반 미만** (실측 195B / 1916B)
- **왜 중요한가**: 이것이 "판단을 검증에서 뺀다" 의 실제 모습이다. 세 지점은
  이미 자동이므로, 색인도 자동이다.

### T10. recap 은 조립만 한다  ✅
- **Expected**:
  - **파일을 하나도 만들거나 지우지 않는다** (전후 파일 목록 해시 동일)
  - 최근 결정이 보인다
  - 펼치는 방법을 알려 준다
  - **40줄 이하** — 길면 안 읽고, 안 읽으면 없느니만 못하다
- **왜 첫 항목이 중요한가**: "지금 내용 저장하고 할 일 리스트 만드는" 손일을
  없애는 것이 목적이다. recap 이 무언가를 쓰기 시작하면 그 손일이 이름만 바뀐 채
  돌아온다.

### T11. 0.32.0 호환  ✅ (수동 확인)
- 옛 색인 자리(`scv/journal/INDEX.tsv`)도 읽는다.
- 함수 예전 이름(`journal_index_*`)이 얇은 별칭으로 남아 있다.
- **결과**: 확인 완료. 자동 회귀는 아직 없다.
