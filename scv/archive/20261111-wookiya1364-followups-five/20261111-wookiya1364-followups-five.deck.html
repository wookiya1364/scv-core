# 남은 일 다섯 마무리 — 저널 거절 · 안 물은 턴 · 맥 속도 시험 · 코덱스 확인과 권장 표

## Summary

2026-11-11 새벽 릴리스(코어 0.89.1) 뒤에 남은 다섯 가지를 순서대로 끝낸다.
기록 폴더를 연결한 프로젝트에서 2주째 안 쌓이던 저널을 살리고, effort 요청이 모델이 안 물어도 '물었다'로 끝나던 것을 고치고, 맥 검사에서 흔들리는 속도 시험 둘을 CPU 시간으로 재게 한다.
이어서 코덱스 래퍼가 새 코어로 실제 세션에서 도는지 보고, 읽을 수 있으면 코덱스에도 권장 effort 표를 넣는다.

## Goals / Non-Goals

- **Goals**
  - 저널 폴더 뿌리가 다른 저장소로 연결돼 있어도 저널 기록 명령이 쓴다.
  - effort 요청 줄이 실린 턴의 답에 질문이 없으면 '물었다'고 적지 않고 다음 턴에 다시 싣는다(모두 세 번까지).
  - 속도 시험 둘이 벽시계가 아니라 CPU 시간으로 판정한다 — 먼저 재서 덜 흔들릴 때만.
  - 코덱스 래퍼 0.89.1-codex.1 이 실제 코덱스 세션에서 도는 것을 기록으로 확인한다.
  - 코덱스 세션 기록에서 effort 를 읽을 수 있고 공식 가이드에 권장 문장이 있으면, 코덱스 래퍼에 권장 표를 넣는다.
- **Non-Goals**
  - 순수함수 성능 재기(사용자와 따로 이야기한 뒤 계획)
  - PR 열기와 릴리스(사용자가 따로 말할 때)
  - effort 요청을 턴 끝에서 막는 검사로 만드는 일
  - 저널의 내용 · 가림 규칙

## Approach Overview

단계 다섯은 서로 기대지 않는다(6만 8의 결과를 쓴다). 단계가 끝날 때마다 커밋한다.

1. **저널(3)** — `journal-append.sh` 는 저널 폴더가 연결이면 통째로 거절한다. 뿌리의 연결은 따라가고, 쓰려는 파일이 연결이면 거절하게 바꾼다. 훅이 저널을 쓰는 다른 길이 같은 이유로 막혀 있는지도 본다.
2. **안 물은 턴(4)** — 지금은 줄을 실을 때 조건을 '물었다'로 적는다. 실을 때는 '실었다(몇 번째)'로만 적고, 턴 끝(종료 판정)에서 그 턴의 답에 질문이 있었으면 '물었다'로 올린다. 다음 턴의 판정은 '실었다'가 3번 미만이면 다시 싣는다. 질문이 있었는지는 순수 함수가 가린다: 선택 창 도구 호출의 질문 글에 effort 가 있거나, 답 글에 effort 와 권장 값 낱말이 함께 있다.
3. **속도 시험(7)** — 먼저 잰다: CPU 를 일부러 붐비게 한 상태에서 같은 시험의 벽시계 값과 CPU 시간 값을 여러 번. CPU 시간이 덜 흔들리면 두 시험의 판정을 CPU 시간으로 바꾼다(재는 함수 하나를 두 시험이 같이 쓴다). 덜 흔들리지 않으면 바꾸지 않고 측정값을 보고한다.
4. **코덱스 확인(8)** — 설치된 코덱스 플러그인을 0.89.1-codex.1 로 올리고, 임시 프로젝트에서 짧은 세션을 돌려 세션 기록으로 확인한다.
5. **코덱스 표(6)** — 8에서 얻은 세션 기록에 effort 가 남는지, 가이드 사본에 권장 문장이 있는지 본다. 둘 다 있으면 표 · 검사 · 프로필 키 · 시험을 넣고, 아니면 넣지 않는다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  journal_root_ok,          // 저널 폴더 · 쓸 파일 → 통과 또는 거절            (부수효과: 연결 검사)
)
flow(
  scv_mp_effort_asked_in,   // 그 턴의 답 글 · 선택 창 질문 글 · 권장 값 → 1|0
  scv_mp_effort_state_next, // 지금 상태 줄 · 조건 · 사건(shown|asked) → 다음 상태 줄
  scv_mp_effort_verdict,    // 스위치 · 지금 값 · 권장 줄 · 상태 → ask|same|asked|unknown|off
)
flow(
  cpu_secs,                 // 명령 → 그 명령과 자식들이 쓴 CPU 초             (부수효과: 실행)
  speed_ok,                 // 켬 · 끔 CPU 초 → 통과|실패
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `journal_root_ok` | 저널 뿌리의 연결은 따라가고 쓸 파일의 연결은 거절한다 | 저널 폴더 · 파일 → 통과 또는 거절 | 부수효과 (입구) |
| 2 | `scv_mp_effort_asked_in` | 그 턴의 답에 effort 질문이 있었는지 가린다 | 답 글 · 질문 글 · 권장 값 → 1 또는 0 | 순수 |
| 3 | `scv_mp_effort_state_next` | 조건의 상태를 '실었다 n번' 또는 '물었다'로 옮긴다 | 상태 줄들 · 조건 · 사건 → 상태 줄들 | 순수 |
| 4 | `scv_mp_effort_verdict` | 물을지 정한다 — 세 번 실었으면 멈춘다 | 스위치 · 값 · 권장 줄 · 상태 → 판정 | 순수 |
| 5 | `cpu_secs` | 명령이 쓴 CPU 시간을 잰다 | 명령 → 초 | 부수효과 (입구) |
| 6 | `speed_ok` | 켬과 끔의 CPU 시간으로 통과를 정한다 | 켬 초 · 끔 초 → 통과 또는 실패 | 순수 |

- 부수효과 위치: 1(파일 시스템) · 5(명령 실행). 상태 파일 읽기 · 쓰기는 지금처럼 어댑터(`model-prompting.sh`)가 한다.
- 재사용: `scv_mp_effort_row` · `scv_mp_effort_block` · 종료 판정(`stop`)이 이미 읽는 답 글과 선택 창 기록.

## Guardrails

- 저널: 뿌리 말고는 어떤 연결도 따라가지 않는다. 가림(redaction)은 지금처럼 쓰기 전에 돈다.
- effort: 다시 싣는 것은 모두 세 번까지. 턴 끝에서 막지 않는다. 사람이 없는 실행에서는 지금처럼 싣지도 적지도 않는다.
- 속도 시험: 한도 숫자를 느슨하게 하지 않는다. CPU 시간이 덜 흔들린다는 측정 없이 바꾸지 않는다.
- 코덱스: 값이나 근거 문장을 지어내지 않는다 — 가이드 사본에 글자 그대로 있는 문장만. 못 읽으면 넣지 않는다.
- 맥(BSD) · 리눅스(GNU), bash 3.2 에서 돈다.

## Exit criteria

- TESTS.md 의 시나리오 16개 가운데 코덱스가 필요한 넷(T12 ~ T15)을 뺀 12개 통과 — 넷은 하지 않았다(위 "하지 않은 것")
- 이 저장소에서 저널 기록 명령이 실제로 한 줄을 쓴다(2주 만에 새 저널 파일)
- 단계마다 커밋이 하나씩 있다

### 하지 않은 것 (2026-11-12, 사용자가 선택 창에서 "빼고 계획을 끝냄"을 고름)

- 코덱스가 필요한 단계 둘(4 · 5)은 하지 않았다. 코덱스 계정이 없어 코덱스에서 세션을 돌릴 수 없다.
- 그래서 확인하지 못한 것: 코덱스의 실제 세션에 매 턴 안내가 실리는지, 그 모델의 가이드 · 등록 · 인용이 기록에 남는지, 코덱스 기록에서 effort 를 읽을 수 있는지(TESTS.md T12 ~ T15).
- 코덱스 래퍼의 권장 표(`EFFORT.tsv`)는 넣지 않았다. 코덱스에서는 권장 effort 요청이 지금처럼 나오지 않는다.
- 계정이 생기면 새 계획으로 다시 한다 — 할 일은 T12 ~ T15 그대로다. 2026-11-11 에 설치본을 0.89.1-codex.1 로 올리는 데까지는 했다(변경 이력의 "4단계 막힘").
- 6단계의 전체 시험은 이 가지만으로 돌리지 않고, 가지 여섯을 하나로 합친 뒤 한 번 돌렸다(2026-11-12 사용자 결정: 전체 시험은 올리기 전에 한 번).

1. 저널 뿌리의 연결을 따라가게 고치고 훅 쪽의 같은 막힘을 확인 · 커밋 — `journal_root_ok`

## Risks / Open Questions

- "답에 질문이 있었다"는 글자로 가린다. 모델이 다른 말로 물으면 못 알아봐 한 번 더 실릴 수 있다 — 세 번에서 멈추므로 끝없이 반복되지는 않는다.
- CPU 시간도 붐비는 기계에서 조금은 늘 수 있다(캐시 · 문맥 전환). 측정으로 정한다.
- 코덱스가 세션 기록에 effort 를 안 남기면 5단계는 "넣지 않음"으로 끝난다.

# Test Plan — 남은 일 다섯 마무리

## Overview

단계 다섯이 각각 고친 것과, 그러면서 지켜야 할 것(연결 거절 · 한 번만 묻기 · 진짜 느려짐 잡기)을 본다.
T1–T9 · T16 은 임시 폴더의 자동 시험, T10 · T11 은 측정, T12–T15 는 실제 코덱스 세션과 래퍼 검사다.

## Test scenarios

### T1. 저널 뿌리가 연결 — 쓴다

- **Setup**: 임시 저장소의 `scv/journal` 이 다른 폴더를 가리키는 연결.
- **Run**: `journal-append.sh --speaker user "한 줄"`.
- **Expected**: 연결이 가리키는 폴더에 오늘 날짜 저널 파일이 생기고 그 줄이 있다.
- **Pass criterion**: 종료 코드 0, 파일에 `한 줄` 1번. (고치기 전에는 종료 코드 1)

### T2. 저널 파일 자체가 연결 — 거절

- **Setup**: 오늘 날짜 저널 파일이 밖의 파일을 가리키는 연결.
- **Run**: `journal-append.sh --speaker user "x"`.
- **Expected**: 거절, 밖의 파일은 안 바뀜.
- **Pass criterion**: 종료 코드 1, 밖의 파일 크기 그대로.

### T3. 보통 저널 폴더 — 그대로

- **Setup**: 연결 없는 임시 저장소.
- **Run**: 저널 관련 기존 시험.
- **Expected**: 고치기 전과 같은 통과 수.
- **Pass criterion**: 종료 코드 0.

### T4. 가림은 그대로

- **Setup**: 연결된 저널 뿌리.
- **Run**: `journal-append.sh --speaker user "token=abc123"`.
- **Expected**: 파일에는 `[REDACTED]` 로 적힌다.
- **Pass criterion**: 파일에 `abc123` 0번.

### T5. 물은 턴 — 다시 싣지 않는다

- **Setup**: effort 가 권장과 다른 세션. 첫 턴에 줄이 실리고, 그 턴의 답에 effort 질문이 있다.
- **Run**: 턴 끝 판정 → 다음 턴의 매 턴 안내.
- **Expected**: 다음 턴에 줄이 없다.
- **Pass criterion**: 요청 줄 수 1 · 0.

### T6. 안 물은 턴 — 다음 턴에 다시 싣는다

- **Setup**: 같은 조건. 줄이 실린 턴의 답에 effort 질문이 없다.
- **Run**: 턴 끝 판정 → 다음 턴의 매 턴 안내.
- **Expected**: 다음 턴에 줄이 다시 실린다.
- **Pass criterion**: 요청 줄 수 1 · 1.

### T7. 세 번에서 멈춘다

- **Setup**: 답에 질문이 계속 없다.

# 남은 일 다섯 마무리 — 저널 거절 · 안 물은 턴 · 맥 속도 시험 · 코덱스 확인과 권장 표

## Summary

2026-11-11 새벽 릴리스(코어 0.89.1) 뒤에 남은 다섯 가지를 순서대로 끝낸다.
기록 폴더를 연결한 프로젝트에서 2주째 안 쌓이던 저널을 살리고, effort 요청이 모델이 안 물어도 '물었다'로 끝나던 것을 고치고, 맥 검사에서 흔들리는 속도 시험 둘을 CPU 시간으로 재게 한다.
이어서 코덱스 래퍼가 새 코어로 실제 세션에서 도는지 보고, 읽을 수 있으면 코덱스에도 권장 effort 표를 넣는다.

## Goals / Non-Goals

- **Goals**
  - 저널 폴더 뿌리가 다른 저장소로 연결돼 있어도 저널 기록 명령이 쓴다.
  - effort 요청 줄이 실린 턴의 답에 질문이 없으면 '물었다'고 적지 않고 다음 턴에 다시 싣는다(모두 세 번까지).
  - 속도 시험 둘이 벽시계가 아니라 CPU 시간으로 판정한다 — 먼저 재서 덜 흔들릴 때만.
  - 코덱스 래퍼 0.89.1-codex.1 이 실제 코덱스 세션에서 도는 것을 기록으로 확인한다.
  - 코덱스 세션 기록에서 effort 를 읽을 수 있고 공식 가이드에 권장 문장이 있으면, 코덱스 래퍼에 권장 표를 넣는다.
- **Non-Goals**
  - 순수함수 성능 재기(사용자와 따로 이야기한 뒤 계획)
  - PR 열기와 릴리스(사용자가 따로 말할 때)
  - effort 요청을 턴 끝에서 막는 검사로 만드는 일
  - 저널의 내용 · 가림 규칙

## Approach Overview

단계 다섯은 서로 기대지 않는다(6만 8의 결과를 쓴다). 단계가 끝날 때마다 커밋한다.

1. **저널(3)** — `journal-append.sh` 는 저널 폴더가 연결이면 통째로 거절한다. 뿌리의 연결은 따라가고, 쓰려는 파일이 연결이면 거절하게 바꾼다. 훅이 저널을 쓰는 다른 길이 같은 이유로 막혀 있는지도 본다.
2. **안 물은 턴(4)** — 지금은 줄을 실을 때 조건을 '물었다'로 적는다. 실을 때는 '실었다(몇 번째)'로만 적고, 턴 끝(종료 판정)에서 그 턴의 답에 질문이 있었으면 '물었다'로 올린다. 다음 턴의 판정은 '실었다'가 3번 미만이면 다시 싣는다. 질문이 있었는지는 순수 함수가 가린다: 선택 창 도구 호출의 질문 글에 effort 가 있거나, 답 글에 effort 와 권장 값 낱말이 함께 있다.
3. **속도 시험(7)** — 먼저 잰다: CPU 를 일부러 붐비게 한 상태에서 같은 시험의 벽시계 값과 CPU 시간 값을 여러 번. CPU 시간이 덜 흔들리면 두 시험의 판정을 CPU 시간으로 바꾼다(재는 함수 하나를 두 시험이 같이 쓴다). 덜 흔들리지 않으면 바꾸지 않고 측정값을 보고한다.
4. **코덱스 확인(8)** — 설치된 코덱스 플러그인을 0.89.1-codex.1 로 올리고, 임시 프로젝트에서 짧은 세션을 돌려 세션 기록으로 확인한다.
5. **코덱스 표(6)** — 8에서 얻은 세션 기록에 effort 가 남는지, 가이드 사본에 권장 문장이 있는지 본다. 둘 다 있으면 표 · 검사 · 프로필 키 · 시험을 넣고, 아니면 넣지 않는다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

- 코덱스가 필요한 단계 둘(4 · 5)은 하지 않았다. 코덱스 계정이 없어 코덱스에서 세션을 돌릴 수 없다.
- 그래서 확인하지 못한 것: 코덱스의 실제 세션에 매 턴 안내가 실리는지, 그 모델의 가이드 · 등록 · 인용이 기록에 남는지, 코덱스 기록에서 effort 를 읽을 수 있는지(TESTS.md T12 ~ T15).
- 코덱스 래퍼의 권장 표(`EFFORT.tsv`)는 넣지 않았다. 코덱스에서는 권장 effort 요청이 지금처럼 나오지 않는다.
- 계정이 생기면 새 계획으로 다시 한다 — 할 일은 T12 ~ T15 그대로다. 2026-11-11 에 설치본을 0.89.1-codex.1 로 올리는 데까지는 했다(변경 이력의 "4단계 막힘").
- 6단계의 전체 시험은 이 가지만으로 돌리지 않고, 가지 여섯을 하나로 합친 뒤 한 번 돌렸다(2026-11-12 사용자 결정: 전체 시험은 올리기 전에 한 번).

## Suggested path

1. 저널 뿌리의 연결을 따라가게 고치고 훅 쪽의 같은 막힘을 확인 · 커밋 — `journal_root_ok`
2. 줄을 실은 것과 물은 것을 나눠 적고, 턴 끝에서 물었는지 보고, 세 번까지 다시 싣게 고침 · 커밋 — `scv_mp_effort_asked_in`, `scv_mp_effort_state_next`, `scv_mp_effort_verdict`
3. 붐비는 조건에서 벽시계와 CPU 시간의 흔들림을 재고, 덜 흔들리면 속도 시험 둘을 CPU 시간으로 바꿈 · 커밋 — `cpu_secs`, `speed_ok`
4. [!] 코덱스 설치본을 올려 임시 프로젝트에서 실제 세션을 돌리고 기록으로 확인 — 하지 않음: 코덱스 계정이 없다(2026-11-12 사용자 결정)
5. [!] 코덱스 기록에서 effort 를 읽을 수 있고 가이드에 권장 문장이 있으면 코덱스 래퍼에 표를 넣음 — 하지 않음: 4단계 없이는 기록을 볼 수 없다(2026-11-12 사용자 결정)
6. 전체 시험을 bash 3.2 · bash 5 로 돌리고 문서 · 변경 기록을 맞춤 · 커밋 — 새로 실패한 것이 없는지 본다

# Test Plan — 남은 일 다섯 마무리

## Overview

단계 다섯이 각각 고친 것과, 그러면서 지켜야 할 것(연결 거절 · 한 번만 묻기 · 진짜 느려짐 잡기)을 본다.
T1–T9 · T16 은 임시 폴더의 자동 시험, T10 · T11 은 측정, T12–T15 는 실제 코덱스 세션과 래퍼 검사다.

## Test scenarios

### T1. 저널 뿌리가 연결 — 쓴다

- **Setup**: 임시 저장소의 `scv/journal` 이 다른 폴더를 가리키는 연결.
- **Run**: `journal-append.sh --speaker user "한 줄"`.
- **Expected**: 연결이 가리키는 폴더에 오늘 날짜 저널 파일이 생기고 그 줄이 있다.
- **Pass criterion**: 종료 코드 0, 파일에 `한 줄` 1번. (고치기 전에는 종료 코드 1)

### T2. 저널 파일 자체가 연결 — 거절

- **Setup**: 오늘 날짜 저널 파일이 밖의 파일을 가리키는 연결.
- **Run**: `journal-append.sh --speaker user "x"`.
- **Expected**: 거절, 밖의 파일은 안 바뀜.
- **Pass criterion**: 종료 코드 1, 밖의 파일 크기 그대로.

### T3. 보통 저널 폴더 — 그대로

- **Setup**: 연결 없는 임시 저장소.
- **Run**: 저널 관련 기존 시험.
- **Expected**: 고치기 전과 같은 통과 수.
- **Pass criterion**: 종료 코드 0.

### T4. 가림은 그대로

- **Setup**: 연결된 저널 뿌리.
- **Run**: `journal-append.sh --speaker user "token=abc123"`.
- **Expected**: 파일에는 `[REDACTED]` 로 적힌다.
- **Pass criterion**: 파일에 `abc123` 0번.

### T5. 물은 턴 — 다시 싣지 않는다

- **Setup**: effort 가 권장과 다른 세션. 첫 턴에 줄이 실리고, 그 턴의 답에 effort 질문이 있다.
- **Run**: 턴 끝 판정 → 다음 턴의 매 턴 안내.
- **Expected**: 다음 턴에 줄이 없다.
- **Pass criterion**: 요청 줄 수 1 · 0.

### T6. 안 물은 턴 — 다음 턴에 다시 싣는다

- **Setup**: 같은 조건. 줄이 실린 턴의 답에 effort 질문이 없다.
- **Run**: 턴 끝 판정 → 다음 턴의 매 턴 안내.
- **Expected**: 다음 턴에 줄이 다시 실린다.
- **Pass criterion**: 요청 줄 수 1 · 1.

### T7. 세 번에서 멈춘다

- **Setup**: 답에 질문이 계속 없다.
- **Run**: 턴 다섯 번.
- **Expected**: 줄이 세 번 실리고 그 뒤 두 번은 없다.
- **Pass criterion**: 요청 줄 수 1 · 1 · 1 · 0 · 0.
