# 자동 비우기 기준을 프로젝트 설정에 저장하고 칸의 글을 세 줄로 줄인다

## Summary

SCV 창의 자동 비우기 칸에서 기준(%)을 바꿔도, 대화가 비워진 뒤에는 50% 로 돌아와 계속 다시 바꿔야 한다(사용자가 2026-11-26 에 사진으로 알림). 기준은 지금 이 컴퓨터 전체에 한 칸으로만 기억된다 — 프로젝트와 세션이 모두 그 한 칸을 같이 쓴다.

이 계획은 기준(%)과 끄기/켜기를 프로젝트의 `scv/scv_settings.json` 에 저장하고, 화면을 새로 읽을 때마다 그 파일에서 읽는다. 값이 없으면 켜짐 · 50% 다. 함께, 칸의 글을 사용자가 고른 세 줄 모양으로 줄인다.

## Goals / Non-Goals

- **Goals**
  - 기준(%)을 바꾸면 대화가 비워진 뒤에도, 새 세션에서도 그 값이 남는다
  - 끄기/켜기도 같은 파일에 프로젝트마다 따로 남는다
  - 칸의 글이 세 줄이다 — `자동 비우기 50% 넘으면 [끄기]` · `◀ 막대 ▶` · `마지막 비우기 50% → 3% · 1초 걸림`
- **Non-Goals**
  - 비우는 방식 · 막대 모양 · 5% 단계를 바꾸는 것
  - 설정 파일이 없는 폴더에 `scv/` 를 새로 만드는 것
  - 거울에서 누를 때 작업 세션에 남는 메시지 글(`거울에서: 비우기 기준 → 65%`)을 바꾸는 것
  - 컴퓨터 보관 칸에 남아 있는 옛 값을 프로젝트 설정으로 옮기는 것(값이 없으면 50% — 사용자 요청)

## Approach Overview

설정 파일은 대시보드가 화면을 새로 읽을 때마다 이미 읽는다(묻기 방식이 그 글에서 나온다). 같은 글에서 기준과 켜짐을 읽는 순수 함수를 하나 더한다. 새로 읽은 뒤 그 값이 지금 화면의 값과 다르면 화면의 값을 맞춘다. 대화가 비워진 뒤에도 같은 길로 읽으므로 값이 남는다.

누를 때는 SCV 의 설정 쓰기 명령(`settings-set.sh`)으로 바뀐 값 하나만 쓴다. 묻기 방식 단추가 쓰는 길과 같다. 빠르게 여러 번 눌러도 쓰기는 차례로 돌고, 마지막에 누른 값이 파일에 남는다. 쓰는 동안에는 파일에서 읽은 옛 값으로 화면을 되돌리지 않는다.

설정 파일이 없는 폴더(SCV 프로젝트가 아닌 곳)와 설정 쓰기 명령을 찾지 못한 곳은 지금처럼 컴퓨터 보관 칸에 쓴다. 설정 파일은 있는데 쓰기가 실패하면 칸에 한 줄로 알린다.

화면 글은 다른 줄(`컨텍스트`, `사용 한도`)과 같은 모양으로 맞춘다 — 굵은 이름 + 흐린 값. 비운 결과 줄은 `마지막 비우기` 라는 이름을 달고 `걸림` 을 붙여 숫자의 뜻이 보이게 한다.

키 이름: `SCV_CLEAR_PERCENT`(10 ~ 95 의 숫자), `SCV_CLEAR_AUTO`(`on` | `off`).

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  lightFromSettings,  // 설정 글 → 켜짐 · 기준 (값 없으면 켜짐 · 50%, 파일 없으면 없음)
  moveLight,          // 켜짐 · 기준 + 옮길 값 → 새 켜짐 · 기준 (이미 있음)
  lightSaveArgv,      // 바뀐 값 → 설정 파일에 쓸 명령
  설정 파일 쓰기,      // 명령 → 파일 (부수효과)
  lightLabel,         // 켜짐 · 기준 → '50% 넘으면' | '꺼짐'
  lightNote,          // 비운 결과 → '마지막 비우기 50% → 3% · 1초 걸림' (글만 바뀜)
  lightSaidParts,     // 그 글 → 굵은 이름 + 값
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | lightFromSettings | 설정 글에서 기준과 켜짐을 읽는다 | 설정 글 → 켜짐 · 기준, 또는 없음 | 순수 |
| 2 | moveLight | 기준을 5% 단위로 옮긴다 | 켜짐 · 기준, 옮길 값 → 새 켜짐 · 기준 | 순수 |
| 3 | lightSaveArgv | 바뀐 값 하나를 쓸 명령을 만든다 | 명령 자리, 전 값, 새 값 → 명령 목록 | 순수 |
| 4 | 설정 파일 쓰기 | 명령을 차례로 돌려 파일에 쓴다 | 명령 목록 → 성공 여부 | 부수효과 (출구) |

## Guardrails

- 비우는 방식 · 막대 모양 · 5% 단계 · 10% ~ 95% 범위는 바꾸지 않는다
- 설정 파일의 다른 키는 건드리지 않는다 — 쓰기는 SCV 의 설정 쓰기 명령으로만 한다(파일을 직접 고쳐 쓰지 않는다)
- 설정 파일이 없는 폴더에 `scv/` 를 만들지 않는다
- 거울 세션은 파일을 쓰지 않는다 — 지금처럼 작업 세션에 요청을 보낸다
- 쓰는 중에 화면의 값이 옛 값으로 튀지 않는다

## Exit criteria

- All TESTS.md scenarios pass
- 모드 시험 전부 통과, 타입 오류 수가 전과 같다(10개)
- 실제 설정 쓰기 명령을 임시 프로젝트에 돌려, 쓰인 파일과 그 파일에서 읽은 값을 보고에 그대로 남긴다
- 실제 앱에서 비운 뒤에도 값이 남는지는 릴리스 뒤 사용자가 직접 본다(이 계획 안에서는 확인하지 못한다)

## Suggested path

1. 설정 글에서 기준과 켜짐을 읽는 함수를 만든다 — `lightFromSettings`
2. 화면을 새로 읽을 때 그 값으로 맞춘다 — `lightFromSettings`
3. 누를 때 바뀐 값을 설정 파일에 차례로 쓴다 — `moveLight`, `lightSaveArgv`, `설정 파일 쓰기`
4. 칸의 글을 세 줄 모양으로 바꾼다 — `lightLabel`, `lightNote`, `lightSaidParts`
5. 모드 시험을 고치고 더해 돌린다 — 시험 통과와 타입 오류 수를 확인한다
6. 실제 설정 쓰기 명령을 임시 프로젝트에 돌려 본다 — 쓰인 파일과 읽은 값을 확인한다

## Risks / Open Questions

- 왜 지금 50% 로 돌아오는지는 끝까지 확인하지 못했다. 확인한 것: 기준은 컴퓨터 전체에 한 칸으로 기억되고(2026-11-26 13:34 에 그 칸의 값은 15%), 사진의 세션은 50% 를 보였다. 추정: 여러 세션이 한 칸을 같이 써서 서로의 값을 덮는다. 이 계획은 그 칸을 쓰지 않고 프로젝트 파일에서 매번 읽으므로 원인이 무엇이든 값이 남는다.
- 설정 파일은 git 에 올라가는 파일이다. 기준을 바꾸면 그 프로젝트에 바뀐 파일로 잡힌다(사용자가 고른 저장 자리).
- 한 번 누를 때마다 설정 쓰기 명령이 한 번 돈다. 이 맥에서 5번 측정해 55 ~ 69 ms 였다(6단계).
