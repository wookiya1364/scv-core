# Test Plan — 자동 비우기 기준을 프로젝트 설정에 저장하고 칸의 글을 세 줄로 줄인다

## Overview

기준(%)과 끄기/켜기가 프로젝트 설정 파일에서 읽히고 거기에 쓰이는지, 값이 없을 때 켜짐 · 50% 인지, 설정 파일이 없는 폴더가 지금처럼 도는지, 칸의 글이 고른 세 줄 모양인지 확인한다. 시험은 scv-mods 의 대시보드 모드 시험에 더한다.

## Test scenarios

### T1. 설정 글에 값이 있으면 그 값을 읽는다

- **Setup**: 설정 글 `{"SCV_CLEAR_PERCENT":"65","SCV_CLEAR_AUTO":"off"}`
- **Run**: `lightFromSettings(설정 글)`
- **Expected**: 꺼짐 · 65%
- **Pass criterion**: `{ isOn: false, percent: 65 }`

### T2. 값이 없거나 틀리면 켜짐 · 50% 다

- **Setup**: 설정 글 `{"SCV_LANG":"korean"}`, 그리고 `{"SCV_CLEAR_PERCENT":"300"}` · `{"SCV_CLEAR_PERCENT":"abc"}`
- **Run**: `lightFromSettings(설정 글)`
- **Expected**: 셋 다 켜짐 · 50%
- **Pass criterion**: `{ isOn: true, percent: 50 }`

### T3. 설정 파일이 없으면 없음을 돌려준다

- **Setup**: 설정 글이 없음(null · undefined), 그리고 JSON 이 아닌 글
- **Run**: `lightFromSettings(설정 글)`
- **Expected**: 없음 — 컴퓨터 보관 칸의 값을 쓰라는 뜻
- **Pass criterion**: `null`

### T4. ▶ 를 누르면 설정 파일에 새 기준을 쓴다

- **Setup**: 설정 파일이 있는 프로젝트, 기준 50%
- **Run**: 칸의 ▶ 단추를 누른다
- **Expected**: 설정 쓰기 명령이 `SCV_CLEAR_PERCENT=55` 로 한 번 돈다. 컴퓨터 보관 칸에는 쓰지 않는다. 칸은 `55% 넘으면` 을 보인다
- **Pass criterion**: 돈 명령의 인자가 `settings-set.sh` · `SCV_CLEAR_PERCENT=55`, 보관 칸 쓰기 0번

### T5. 끄기를 누르면 설정 파일에 꺼짐을 쓴다

- **Setup**: 설정 파일이 있는 프로젝트, 켜짐
- **Run**: 칸의 끄기 단추를 누른다
- **Expected**: 설정 쓰기 명령이 `SCV_CLEAR_AUTO=off` 로 돈다. 칸은 `자동 비우기` · `꺼짐` · `켜기` 단추를 보이고 막대는 없다
- **Pass criterion**: 돈 명령의 인자, 그린 글

### T6. 화면을 새로 읽으면 설정 파일의 값이 보인다 — 비운 뒤에도 남는다

- **Setup**: 설정 파일에 `SCV_CLEAR_PERCENT` 70, 컴퓨터 보관 칸에는 50
- **Run**: 세션을 시작한다(비운 뒤 다시 시작하는 것과 같은 길)
- **Expected**: 칸이 `70% 넘으면` 을 보인다
- **Pass criterion**: 그린 글에 `70% 넘으면`, `50% 넘으면` 없음

### T7. 값이 없는 프로젝트는 보관 칸의 값이 아니라 50% 다

- **Setup**: 설정 파일은 있고 두 키는 없음, 컴퓨터 보관 칸에는 15
- **Run**: 세션을 시작한다
- **Expected**: 칸이 `50% 넘으면` 을 보인다
- **Pass criterion**: 그린 글에 `50% 넘으면`

### T8. 설정 파일이 없는 폴더는 지금처럼 컴퓨터 보관 칸을 쓴다

- **Setup**: 설정 파일이 없는 폴더, 컴퓨터 보관 칸에 60
- **Run**: 세션을 시작하고 ▶ 를 누른다
- **Expected**: 칸이 `60% 넘으면` → `65% 넘으면`. 설정 쓰기 명령은 돌지 않고 보관 칸에 65 가 쓰인다
- **Pass criterion**: 설정 쓰기 명령 0번, 보관 칸의 값 65

### T9. 연달아 눌러도 마지막 값이 파일에 남는다

- **Setup**: 설정 파일이 있는 프로젝트, 기준 50%
- **Run**: ▶ 를 기다리지 않고 세 번 누른다
- **Expected**: 칸은 65% 를 보이고, 마지막으로 돈 설정 쓰기 명령의 값이 65 다. 쓰는 중에 화면을 새로 읽어도 칸이 옛 값으로 돌아가지 않는다
- **Pass criterion**: 마지막 명령 `SCV_CLEAR_PERCENT=65`, 그린 글 `65% 넘으면`

### T10. 설정 쓰기가 실패하면 알리고, 다시 읽으면 파일의 값으로 돌아간다

- **Setup**: 설정 파일이 있는 프로젝트, 설정 쓰기 명령이 실패함(종료 1)
- **Run**: ▶ 를 누른 뒤 화면을 새로 읽는다
- **Expected**: 칸에 `설정 파일에 저장하지 못함 — 다시 눌러 주세요` 가 보인다. 파일도 보관 칸도 바뀌지 않고, 새로 읽은 뒤 칸은 파일의 값(50%)을 보인다
- **Pass criterion**: 그린 글, 파일 · 보관 칸 쓰기 0번
- (2026-11-26 구현하며 고침: 처음에는 실패하면 보관 칸에 쓰기로 적었으나, 파일이 있는 프로젝트는 파일이 기준이라 보관 칸의 값은 읽히지 않는다 — 저장되지 않은 값을 저장된 것처럼 보이지 않게 함)

### T11. 칸의 글이 세 줄 모양이다

- **Setup**: 켜짐 · 50%, 컨텍스트 62%, 방금 비움(62% → 3%, 1.2초)
- **Run**: 창을 그린다
- **Expected**: `자동 비우기` · `50% 넘으면` · `끄기`, 막대 줄에는 ◀ ▶ 와 막대만, `마지막 비우기` · `62% → 3% · 1초 걸림`. 옛 글(`컨텍스트가 50% 를 넘으면 자동으로 비우기`, 막대 옆 `비우기 기준 50%`, `비움 62%`)은 없다
- **Pass criterion**: 새 글 셋이 있고 옛 글 셋이 없다

### T12. 비운 결과 줄의 글

- **Setup**: 비운 결과 넷 — 비움(62 → 3, 1.2초), 비움(뒤 값 모름), 기록으로 바꿈, 하지 못함
- **Run**: `lightNote(결과)` 와 `lightSaidParts(글)`
- **Expected**: `마지막 비우기 62% → 3% · 1초 걸림` / `마지막 비우기 62% 일 때 · 1초 걸림` / `마지막 줄이기 62% → 8% · 1초 걸림 · 기록으로 바꿈` / 하지 못함은 지금 글 그대로. 나눈 이름은 `마지막 비우기` · `마지막 줄이기`, 그 밖의 글은 이름 없이 값만
- **Pass criterion**: 글자열 일치

### T13. 거울 화면에서 누르면 작업 세션이 설정 파일에 쓴다

- **Setup**: 거울 세션과 작업 세션(설정 파일 있음)
- **Run**: 거울의 ▶ 를 누른다 → 작업 세션이 그 요청을 받는다
- **Expected**: 거울 세션은 설정 쓰기 명령을 돌리지 않는다. 작업 세션이 `SCV_CLEAR_PERCENT` 를 쓴다
- **Pass criterion**: 거울 쪽 명령 0번, 작업 쪽 명령 1번

### T14. 실제 설정 쓰기 명령으로 쓰고 읽는다 (손으로 한 번)

- **Setup**: 임시 폴더에 `scv/scv_settings.json` (`{"SCV_LANG":"korean"}`)
- **Run**: `lightSaveArgv` 가 만든 명령을 실제로 돌린 뒤, 파일을 `lightFromSettings` 로 읽는다. 걸린 시간을 측정한다
- **Expected**: 파일에 `SCV_CLEAR_PERCENT` 65 가 있고 `SCV_LANG` 은 그대로다. 읽은 값은 켜짐 · 65%
- **Pass criterion**: 파일 내용과 읽은 값을 보고에 남긴다

## How to run

scv-mods 저장소에서:

```bash
claude plugin test marketplace/mods/scv-dashboard
```

## Pass criteria

- T1 ~ T13 이 모드 시험으로 통과한다
- T14 의 출력이 보고에 남는다
- 모드 시험 전부 통과, 타입 오류 수가 전과 같다
