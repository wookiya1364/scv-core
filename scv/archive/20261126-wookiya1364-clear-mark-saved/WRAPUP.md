# 마무리 보고 — 자동 비우기 기준을 프로젝트 설정에 저장하고 칸의 글을 세 줄로 줄인다

<!-- 계획을 세울 때 아는 만큼(적어도 1번) 채우고, 일이 끝난 뒤 모든 칸을 채운다.
     고장을 고치는 계획이 아니면 2 ~ 5번은 묶음마다 "해당 없음 — 이유" 한 줄로 건너뛴다.
     1 · 6 · 7번은 모든 계획이 채운다. 빈 칸이 있으면 보관되지 않는다. -->

## 1. 문제

- 상황: SCV 창의 자동 비우기 칸에서 기준(%)을 바꿔 쓰는 중이다. 칸의 글은 `컨텍스트가 50% 를 넘으면 자동으로 비우기 — 기록으로 이어 감` · `비우기 기준 50%` · `비움 50% · 1초` 다.
- 기대: 바꾼 기준이 대화가 비워진 뒤에도 남는다. 칸의 글은 한눈에 뜻이 보인다.
- 실제: 대화가 비워지면 기준이 50% 로 돌아와 계속 다시 바꿔야 한다. 칸의 글은 길고, 같은 말이 겹치고(`50%` 가 세 번), `비움 50% · 1초` 가 무슨 뜻인지 알기 어렵다(사용자가 2026-11-26 에 사진으로 알림).
- 재현 조건: 사용자의 실제 앱에서 본 것이다. 이 계획 안에서 다시 일으켜 보지는 못했다.

## 2. 관찰

- 관찰한 사실과 측정값: 기준은 컴퓨터 전체에 한 칸(`scv-dashboard:light`)으로 기억된다 — 프로젝트 · 세션 구분이 없다. 2026-11-26 13:34 에 그 칸의 값은 켜짐 · 15% 였고, 같은 무렵 사진의 다른 세션은 50% 를 보였다. 세션은 시작할 때와 거울을 끌 때만 그 칸을 읽는다.
- 정상일 때와 차이: 한 세션만 쓰면 바꾼 값이 그 칸에 남고 다음 세션이 읽는다. 여러 세션이 같이 쓰면 칸의 값과 화면의 값이 서로 다를 수 있다.

## 3. 가설

- H1: 여러 세션이 컴퓨터의 한 칸을 같이 써서, 한 세션이 바꾼 값을 다른 세션이 덮거나 읽지 못한다.

## 4. 실험

- 방법과 같게 둔 것: 원인을 가르는 실험은 하지 않았다 — 사용자의 앱에서 여러 세션이 한 칸을 같이 쓰던 상태를 다시 만들 수 없었다. 대신 값이 어디에 기억되는지를 코드(읽는 자리 둘 · 쓰는 자리 하나)와 컴퓨터의 보관 파일로 확인했다.
- 결과와 가설별 판정: H1 은 판정하지 못했다(확인 못 함). 확인한 것은 보관 칸이 컴퓨터 전체에 하나뿐이고, 그 칸의 값(15%)과 사진 속 세션의 값(50%)이 같은 무렵에 서로 달랐다는 사실까지다.

## 5. 원인

- 직접 원인과 일어난 길: 50% 로 돌아오는 직접 원인은 확인하지 못했다. 확인한 길은 여기까지다 — 기준은 프로젝트 · 세션 구분이 없는 한 칸에 쓰이고, 세션은 시작할 때와 거울을 끌 때만 그 칸을 읽는다.
- 근본 원인: 기준이 누구의 것인지(프로젝트의 것인지 컴퓨터의 것인지) 정하지 않고 컴퓨터 한 칸에 두었다. 프로젝트마다 다르게 쓰는 값인데 프로젝트가 가진 파일에 없었다.

## 6. 해결과 검증

- 해결책과 고른 이유: 기준(%)과 끄기/켜기를 프로젝트의 `scv/scv_settings.json` 두 키(`SCV_CLEAR_PERCENT` · `SCV_CLEAR_AUTO`)에 저장하고, 화면을 새로 읽을 때마다 그 파일에서 읽는다. 사용자가 제안한 자리이고, 파일은 매번 다시 읽히므로 직접 원인이 무엇이든 값이 남는다. 칸의 글은 사용자가 고른 세 줄 모양으로 바꿨다.
- 고치기 전후 값: 모드 시험 256개 → 265개 통과(새 시험 9개, 옛 시험 16개는 새 글 · 새 저장 자리에 맞게 고침). 타입 오류 10개 → 10개. 칸의 글 — `컨텍스트가 50% 를 넘으면 자동으로 비우기 — 기록으로 이어 감` → `자동 비우기` `50% 넘으면`, 막대 옆 `비우기 기준 50%` → 없음, `비움 50% · 1초` → `마지막 비우기` `50% → 3% · 1초 걸림`. 실제 설정 쓰기 명령은 임시 프로젝트에서 5번 모두 성공했고 한 번에 55 ~ 69 ms 였다.
- 부작용과 회귀 시험: 설정 파일은 git 에 올라가는 파일이라 기준을 바꾸면 그 프로젝트에 바뀐 파일로 잡힌다. 설정 파일이 있는 프로젝트는 컴퓨터 보관 칸의 옛 값을 더는 읽지 않아, 값을 다시 정하기 전에는 50% 다. 회귀 시험은 mark T1 ~ T13(읽기 · 쓰기 · 시작할 때 · 값 없음 · 파일 없음 · 연달아 누르기 · 쓰기 실패 · 결과 줄 · 거울)과 고친 light T5 · T7, clear T9, mirror-act T1 · T7 이다.

## 7. 배운 것

- 다음에 같은 문제를 만나면 진단하는 법: "바꾼 값이 돌아온다"면 먼저 그 값이 어디에 기억되는지(컴퓨터 한 칸인지 · 프로젝트 파일인지 · 세션 안인지)와 언제 다시 읽히는지를 본다. 컴퓨터의 보관 파일(`~/.claude/plugins/store/` 아래 모드 파일)을 열면 지금 값이 보인다.
- 다른 곳에도 쓸 수 있는 것: 프로젝트마다 다른 값은 프로젝트의 설정 파일에 두고 SCV 의 설정 쓰기 명령으로 쓴다(묻기 방식 단추와 같은 길). 단추가 파일을 쓸 때는 쓰기를 차례로 돌리고, 쓰는 동안에는 파일에서 읽은 옛 값으로 화면을 되돌리지 않는다.
