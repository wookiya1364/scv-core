# 맞는 기어가 있어도 반복을 알린다 — 새 기어 질문이 가려지지 않고, 일이 아닌 반복은 한 번만 알린다

## Summary

기어 반복 알림(0.104.0)이 실제 프로젝트에서 한 번도 "기어로 만들까요?" 질문으로 이어지지 않았다(사용자가 2026-11-26 에 알림). 그 프로젝트의 세션 기록과 쌓인 요청 54개로 확인한 까닭은 둘이다. 되풀이한 일("친구 서버에 배포", 4번)은 그때마다 낱말이 겹치는 기어(서버 띄우기)가 있어 그 기어 알림만 나갔다 — 기어가 맞으면 반복 검사를 아예 하지 않는다. 반복 알림 5번은 모두 진행을 묻는 말("어디까지했어")에 나갔고, 모델은 다섯 번 모두 말없이 넘어갔다.

이 계획은 기어가 맞아도 지난 요청을 함께 보고 같은 줄에 알린다. 일을 시키는 글이 아닌 반복은 모델이 "만들지 않음"으로 적어 다시 알리지 않게 한다. 알림을 받고도 묻지 않았으면 그 이유를 답 끝에 한 줄로 알리게 한다.

## Goals / Non-Goals

- **Goals**
  - 낱말이 겹치는 기어가 있어도, 비슷한 요청이 전에 있었으면 같은 줄에 함께 알린다
  - 일을 시키는 글이 아닌 반복(진행 · 상태를 묻는 말)은 한 번 알린 뒤 다시 알리지 않는다
  - 반복 알림을 받고도 기어 질문을 하지 않았으면 답 끝에 이유가 한 줄로 보인다
- **Non-Goals**
  - 판정 점수 · 최소 길이 · 보는 범위를 바꾸는 것
  - 말이 전혀 다른데 뜻이 같은 요청을 잡는 것(앞 계획의 Non-Goal 그대로)
  - 묻지 않고 기어를 만드는 것
  - 특정 프로젝트의 기어를 대신 만들어 주는 것

## Approach Overview

판정 명령(`gear.sh detect`)은 기어 사전을 먼저 보고, 맞는 기어가 없을 때만 지난 요청을 본다. 이 조건을 없애 둘을 늘 함께 본다. 알림 줄을 만드는 함수는 이미 둘을 인자로 받으므로, 둘 다 있을 때의 한 줄을 더한다: 기어를 먼저 알리고, "그 기어가 하는 일과 다르면"이라는 말 뒤에 반복을 잇는다. 같은 일이면 그 기어로 하면 되고 뒤는 읽지 않아도 된다.

반복을 알리는 글의 꼬리를 고친다. 지금은 "다른 일이면 묻지 말고 이 줄을 무시한다"로 끝나 모델이 말없이 넘어간다. 세 갈래로 나눈다 — 같은 일의 반복이면 일을 마친 뒤 선택 도구로 묻는다 · 일을 시키는 글이 아니면 묻지 않고 "만들지 않음"으로 적는다(이미 있는 `gear.sh decline`) · 그 밖에 묻지 않았으면 이유를 답 끝에 한 줄로 알린다.

"만들지 않음"으로 적을 수 있게, 반복이 실린 알림이면 기어가 함께 맞았더라도 방금 알린 요청을 기록해 둔다(지금은 기어가 맞으면 그 기록을 지운다).

알림 글은 겹칠 때만 실리므로 겹치지 않는 턴의 글은 늘지 않는다. 매 턴 훅 파일은 바꾸지 않는다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  scv_gear_request_keep,     // 요청 글 → 쌓을지 (그대로)
  scv_gear_request_line,     // 가린 요청 글 → 기록 한 줄 (그대로)
  scv_gear_match_index,      // 요청 + 기어 사전 → 맞는 기어 (그대로)
  scv_gear_match_requests,   // 요청 + 지난 요청 → 반복 수와 대표 글 (그대로 — 이제 기어가 맞아도 부른다)
  scv_gear_notice_line,      // 기어 + 반복 → 알림 한 줄 (둘 다 있을 때의 줄과 꼬리를 고침)
  기록 쓰기,                  // 알림 · 기록 한 줄 · 방금 알린 요청 (부수효과)
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | scv_gear_request_keep | 쌓을 요청인지 가른다 | 요청 글, 턴 종류 → 1 또는 0 | 순수 |
| 2 | scv_gear_request_line | 기록에 쌓을 한 줄을 만든다 | 가린 요청 글, 날짜 → 한 줄 | 순수 |
| 3 | scv_gear_match_index | 사전에서 맞는 기어를 고른다 | 요청, 사전 글 → 기어 이름과 하는 일 | 순수 |
| 4 | scv_gear_match_requests | 지난 요청에서 반복을 센다 | 요청, 지난 줄들, 기준, 거절 줄들 → 수와 대표 글 | 순수 |
| 5 | scv_gear_notice_line | 알림 한 줄을 만든다 | 기어, 반복, 명령 경로 → 한 줄 | 순수 |
| 6 | 기록 쓰기 | 알림을 내고 기록을 쓴다 | 한 줄들 → 파일 | 부수효과 (출구) |

- 부수효과 위치: 6단계와 입구(요청 · 사전 · 기록 읽기) — 모두 `gear.sh detect` 안, 지금과 같은 자리
- 재사용: 1 ~ 4단계는 그대로 쓴다. `gear.sh decline` 도 그대로 쓴다

## Guardrails

- 알림은 한 턴에 한 줄이다 — 둘 다 있으면 한 줄 안에 잇는다
- 겹치는 것이 없는 턴에는 한 글자도 더 싣지 않는다. 매 턴 훅 파일은 바꾸지 않는다
- 기어만 맞고 반복이 없는 턴의 알림 글은 지금과 글자까지 같다
- 판정 점수 · 최소 길이 · 보는 범위는 바꾸지 않는다
- 묻지 않고 기어를 만들지 않는다
- 매 턴 시간 시험(켠 훅이 끈 훅의 1.5배 이내)이 그대로 통과한다
- core 글에 특정 호스트 이름을 쓰지 않는다. 맥과 리눅스에서 같은 결과

## Exit criteria

- All TESTS.md scenarios pass
- 실제 요청 85개(두 프로젝트의 요청 기록)를 시간순으로 다시 흘린 전후 값을 보고에 남긴다 — 기어가 맞은 턴 가운데 반복이 함께 실리는 턴 수, 반복 알림 수
- 순수 함수 사전 검사 통과
- 관련 시험이 맥 기본 셸과 새 셸에서 통과한다
- 실제 세션에서 모델이 그 알림대로 하는지는 릴리스 뒤에 본다(이 계획 안에서는 화면 없는 실행 한 번으로만 본다)

## Suggested path

1. 판정 명령이 기어가 맞아도 지난 요청을 함께 보고, 반복이 실린 알림이면 방금 알린 요청을 적어 둔다 — `scv_gear_match_index`, `scv_gear_match_requests`, `기록 쓰기`
2. 알림 줄에 둘 다 있을 때의 한 줄과 반복 꼬리의 세 갈래를 넣는다 — `scv_gear_notice_line`
3. 기어 설명 문서의 반복 알림 대목을 맞춘다 — 모델이 읽는 설명을 알림 글과 같게 한다
4. 시험을 고치고 더해 돌리고, 순수 함수 사전을 다시 만든다 — 시험 통과와 사전 검사를 확인한다
5. 실제 요청 85개를 전후로 다시 흘려 측정한다 — 전후 알림 수를 확인한다
6. 고친 본체로 화면 없는 실행을 한 번 돌린다 — 모델이 알림을 받고 무엇을 하는지 확인한다

## Risks / Open Questions

- 일을 시키는 글인지 아닌지는 모델이 가른다. 일인데 "만들지 않음"으로 적으면 그 요청은 다시 알리지 않는다. 적을 때마다 답 끝에 한 줄로 알리게 해 사용자가 바로잡을 수 있게 한다.
- 기어를 제 용도로 되풀이해 쓰는 턴에도 반복이 함께 실린다(글이 길어진다). 같은 일이면 그 기어로 하고 뒤는 읽지 않아도 되게 적는다.
- 모델이 고친 글대로 하는지는 화면 없는 실행 한 번으로만 본다. 실제 긴 세션에서의 비율은 릴리스 뒤에 보아야 안다.
