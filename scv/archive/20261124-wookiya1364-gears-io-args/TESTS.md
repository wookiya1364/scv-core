# Test Plan — 기어의 입력 · 출력 표시와 이름 붙은 인자 + 글 대신 그림으로 보여 주기

## Overview

기어 파일에 적은 값의 종류 이름(`in` · `out`)과 예시(`예`)가 보이고 검사되는지, 이름 붙은 인자로 같은 기어를 값만 바꿔 다시 쓸 수 있는지 본다. 인자가 안전 장치(밖으로 나가는 확인)와 순수함(같은 입력 + 같은 인자 = 같은 출력)을 깨지 않는지도 함께 본다.

모든 시나리오는 임시 폴더에 만든 시험용 프로젝트에서 돈다. 시험용 프로젝트에는 인자를 받는 순수 톱니 `head-n`(받은 줄 중 앞 `count` 줄만 낸다, 기본값 3), 인자 없는 순수 톱니 `upper`, 실행되면 표식 파일을 남기는 `outward` 톱니 `send`(인자 `target` 을 받는다), 그리고 이 톱니들로 만든 기어들이 있다. 앞 계획의 시험 T1–T25 는 같은 파일에 그대로 남는다.

둘째 부분(글 대신 그림)은 T44–T51 이다. 규칙 글이 매 턴에 실리는지, 직전 답 검사가 "긴 순서 글인데 그림이 없음"만 잡고 짧은 답은 건드리지 않는지, 호스트 프로필의 새 칸이 세 곳에 다 들어갔는지 본다.

## Test scenarios

### T26. 같은 기어, 다른 인자 — 출력이 인자를 따른다

- **Setup**: flow 가 `head-n | upper` 인 기어. 입력은 소문자 6줄.
- **Run**: 같은 입력으로 `count=2` 를 주어 한 번, `count=5` 를 주어 한 번 돌린다.
- **Expected**: 첫 실행은 대문자 2줄, 둘째 실행은 대문자 5줄을 낸다.
- **Pass criterion**: 두 실행 모두 종료 코드 0, 출력 줄 수 2 · 5, 내용이 입력의 앞 줄들을 대문자로 바꾼 것과 같음.

### T27. 인자를 주지 않으면 사전의 기본값이 쓰인다

- **Setup**: T26 의 기어와 입력.
- **Run**: 인자 없이 돌린다.
- **Expected**: 사전에 적은 기본값 3 이 쓰여 3줄이 나온다.
- **Pass criterion**: 종료 코드 0, 출력 줄 수 3.

### T28. 기어 파일의 `arg:` 줄이 기본값을 덮고, 실행 때 준 값이 그것을 덮는다

- **Setup**: T26 과 같은 흐름에 `arg: count=4` 줄이 있는 기어.
- **Run**: (a) 인자 없이 돌린다. (b) `count=1` 을 주어 돌린다.
- **Expected**: (a) 4줄. (b) 1줄.
- **Pass criterion**: 둘 다 종료 코드 0, 출력 줄 수 4 · 1.

### T29. 안에 든 기어의 인자 — 바깥 기어가 안쪽을 이긴다

- **Setup**: 안쪽 기어(`arg: count=4`)를 flow 에 넣은 바깥 기어(`arg: count=2`), 그리고 `arg:` 줄이 없는 또 다른 바깥 기어.
- **Run**: 두 바깥 기어를 인자 없이 돌린다.
- **Expected**: `arg:` 줄이 있는 바깥 기어는 2줄, 없는 바깥 기어는 안쪽 기어의 값대로 4줄.
- **Pass criterion**: 둘 다 종료 코드 0, 출력 줄 수 2 · 4.

### T30. 선언하지 않은 인자는 거부한다

- **Setup**: T26 의 기어.
- **Run**: (a) `nope=1` 을 주어 돌린다. (b) 이름 모양이 틀린 `Count=1`, `=1`, `count` (등호 없음)를 각각 주어 돌린다.
- **Expected**: 어느 톱니도 돌지 않고 거부된다. (a) 의 오류 글에 모르는 이름 `nope` 과 쓸 수 있는 이름 `count` 가 나온다.
- **Pass criterion**: 모두 종료 코드 2, 표준 출력 비어 있음, (a) 의 오류 글에 `nope` 과 `count` 가 모두 있음.

### T31. 선언하지 않은 값은 톱니 안으로 들어가지 않는다

- **Setup**: 톱니 `upper` 는 인자를 선언하지 않았다. `head-n | upper` 흐름에서 `count=2` 를 준다. 시험용 톱니 하나는 자기가 선언하지 않은 `count` 를 읽으려 한다.
- **Run**: 그 흐름을 `count=2` 로 돌린다.
- **Expected**: `count` 를 선언한 `head-n` 만 그 값을 받는다. 선언하지 않은 톱니가 읽은 값은 비어 있다.
- **Pass criterion**: 종료 코드 0, 선언하지 않은 톱니가 남긴 값이 빈 글.

### T32. 판단 단계에서 멈췄다 이어 가도 인자가 그대로다

- **Setup**: flow 가 `upper | @ | head-n` 인 기어.
- **Run**: `count=2` 로 돌려 판단 단계에서 멈춘 뒤, 이어가기 표와 함께 5줄을 돌려준다. 이어가기 명령에 `count=4` 를 붙여서도 한 번 시도한다.
- **Expected**: 이어 간 뒤 2줄이 나온다. 이어가기에 인자를 붙인 시도는 거부된다.
- **Pass criterion**: 첫 실행 종료 코드 10, 이어가기 종료 코드 0 + 출력 줄 수 2, 인자를 붙인 이어가기는 종료 코드 2.

### T33. 인자로는 밖으로 나가는 확인을 건너뛸 수 없고, 확인 글에 인자 값이 보인다

- **Setup**: `outward` 톱니 `send` 가 마지막인 기어.
- **Run**: (a) `target=stage` 를 주어 돌린다. (b) 확인 없이 이어가기를 시도한다. (c) "실행"으로 답한 것으로 적고 이어 간다.
- **Expected**: (a) `send` 앞에서 멈추고, 내놓은 글에 `target=stage` 가 보인다. (b) 다시 멈춘다. (c) `send` 가 `stage` 를 받아 돈다.
- **Pass criterion**: (a)(b) 종료 코드 11 + 표식 파일 없음 + (a) 출력에 `target=stage`, (c) 종료 코드 0 + 표식 파일의 내용이 `stage`.

### T34. 인자가 든 예시로 순수 톱니를 검사한다

- **Setup**: `head-n` 의 사전에 예시 둘 — `- 예: 'a\nb\nc\nd' → 'a\nb\nc'`(인자 없음, 기본값 3) 과 `- 예: count=1 'a\nb' → 'a'`. 또 하나의 톱니에는 일부러 틀린 예시 `- 예: count=2 'a\nb\nc' → 'a'` 를 둔다.
- **Run**: 검사를 돌린다. 틀린 예시를 고친 뒤 다시 돌린다.
- **Expected**: 첫 검사는 틀린 예시가 든 톱니의 이름과 그 예시를 짚어 실패한다. `head-n` 은 문제 줄이 없다. 고친 뒤에는 통과한다.
- **Pass criterion**: 첫 검사 종료 코드 1 + 출력에 그 톱니 이름, `head-n` 의 문제 줄 0건, 둘째 검사 종료 코드 0.

### T35. 같은 입력 + 같은 인자면 출력이 바이트까지 같다

- **Setup**: T26 의 기어와 입력.
- **Run**: `count=2` 로 두 번 돌려 결과를 각각 파일로 받는다.
- **Expected**: 두 파일이 같다.
- **Pass criterion**: 두 실행 종료 코드 0, `cmp` 종료 코드 0.

### T36. 기어 파일의 `in` · `out` 이 목록에 나온다

- **Setup**: 맨 위에 `in: lines — 글 줄들`, `out: lines — 대문자 줄들` 이 있는 기어(`head-n | upper`).
- **Run**: 목록을 낸다.
- **Expected**: 그 기어의 줄에 `lines → lines` 와 인자 `count=3` 이 나온다.
- **Pass criterion**: 종료 코드 0, 기어 줄에 `lines → lines` 와 `count=3` 이 모두 있음.

### T37. 기어의 `in` · `out` 이 첫 · 끝 톱니와 다르면 검사가 잡는다

- **Setup**: 첫 톱니가 받는 값이 `lines` 인데 `in: number` 라고 적은 기어, 끝 톱니가 돌려주는 값이 `lines` 인데 `out: number` 라고 적은 기어.
- **Run**: 검사를 돌린다.
- **Expected**: 두 기어의 이름과, 어느 쪽(`in` · `out`)이 어떤 이름과 다른지가 오류 줄로 나온다.
- **Pass criterion**: 종료 코드 1, 오류 줄 2건 — 각각 기어 이름 · 적은 이름 · 톱니의 이름이 들어 있음.

### T38. 순수 톱니로만 된 기어의 예시는 실제로 돌려 맞춰 본다

- **Setup**: `head-n | upper` 기어에 맞는 예시 `예: count=2 'a\nb\nc' → 'A\nB'` 를 둔다. 같은 흐름의 다른 기어에는 틀린 예시 `예: 'a\nb' → 'a\nb'` 를 둔다.
- **Run**: 검사를 돌린다.
- **Expected**: 맞는 예시의 기어는 문제 줄이 없고, 틀린 예시의 기어는 이름과 예시를 짚어 실패한다.
- **Pass criterion**: 종료 코드 1, 틀린 기어의 이름이 든 문제 줄 1건, 맞는 기어의 문제 줄 0건.

### T39. 판단 단계가 든 기어의 예시는 보기용 — 돌리지 않는다

- **Setup**: flow 가 `upper | @ | head-n` 인 기어에 예시 한 줄. 판단 단계가 없지만 `effect` 톱니가 든 기어에도 예시 한 줄(그 톱니는 실행되면 표식 파일을 남긴다).
- **Run**: 검사를 돌린다.
- **Expected**: 두 예시 모두 돌지 않고 "보기용"으로 세어진다. 표식 파일이 생기지 않는다.
- **Pass criterion**: 종료 코드 0, 출력에 보기용 예시 2개라는 줄, 표식 파일 없음.

### T40. 0.100.0 모양의 기어와 톱니 사전은 그대로 돈다

- **Setup**: `in` · `out` · `예` · `arg` 줄이 없는 기어 파일과 `- 인자:` 줄이 없는 톱니 사전(앞 계획의 시험용 프로젝트 그대로).
- **Run**: 기어를 돌리고, 검사를 돌린다.
- **Expected**: 실행 결과가 앞 계획의 기대값과 같다. 검사는 통과하고, 빠진 줄은 알림으로만 나온다.
- **Pass criterion**: 실행 종료 코드 0 + 기대 출력과 같음, 검사 종료 코드 0, 알림 줄에 그 기어 이름.

### T41. 기어를 만들 때 `in` · `out` 을 첫 · 끝 톱니에서 채운다

- **Setup**: 값 이름이 적힌 톱니 둘.
- **Run**: 만들기 명령으로 `--flow "head-n | upper"` 기어를 `--in` · `--out` 없이 만든다. `--arg count=2` 와 `--example` 을 준 기어도 하나 만든다.
- **Expected**: 만든 기어 파일 맨 위에 첫 톱니의 받는 값 · 끝 톱니의 돌려주는 값이 `in` · `out` 줄로 들어 있다. 둘째 기어에는 `arg: count=2` 와 `예:` 줄이 있다. 만든 직후 검사가 통과한다.
- **Pass criterion**: 만들기 종료 코드 0, 파일에 그 줄들이 있음, 검사 종료 코드 0.

### T42. 뜻이 이미 있는 이름 · 틀린 모양의 인자 이름은 만들 때와 검사에서 거부한다

- **Setup**: 없음.
- **Run**: (a) 만들기 명령에 `--arg http_proxy=x`, `--arg Count=1`, `--arg 1st=1` 을 각각 준다. (b) 톱니 사전에 `- 인자: no_proxy=x` 를 손으로 적고 검사를 돌린다.
- **Expected**: (a) 세 번 모두 거부되고 파일이 생기지 않는다. (b) 검사가 그 톱니와 이름을 짚어 실패한다.
- **Pass criterion**: (a) 모두 종료 코드 2 + 톱니 파일 없음, (b) 종료 코드 1 + 출력에 `no_proxy`.

### T43. 판단 단계에서 넘기는 글에 맨 위 줄이 실리지 않는다

- **Setup**: `in` · `out` · `예` · `arg` 줄이 모두 있는, 판단 단계가 든 기어.
- **Run**: 돌려서 판단 단계에서 멈춘다.
- **Expected**: 내놓은 글에 그 기어의 글과 앞 단계 결과만 있다.
- **Pass criterion**: 종료 코드 10, 출력에 `flow:` · `in:` · `out:` · `예:` · `arg:` 로 시작하는 줄 0건.

### T44. 매 턴 글에 그림 구절이 실리고 한도 안에 있다

- **Setup**: 쉬운 말 설정이 켜진 프로젝트(기본)와 꺼진 프로젝트.
- **Run**: 매 턴 훅을 돌려 실리는 글을 받는다. 매 턴 글 크기 시험을 돌린다.
- **Expected**: 켜진 프로젝트의 글에 그림 구절(흐름 · 구조 · 수치 비교는 그림 먼저)이 한 번 있다. 꺼진 프로젝트의 글에는 없다. 전체 크기는 한도 안이다.
- **Pass criterion**: 구절 1건 · 0건, `bash core/tests/test-instruction-diet.sh` 종료 코드 0(11,000 바이트 이하).

### T45. 그림 도구가 있는 호스트와 없는 호스트에 맞는 글이 실린다

- **Setup**: 프로필에 `SCV_DRAW_TOOL` 을 채운 호스트와 비운 호스트.
- **Run**: 두 호스트에서 매 턴 훅을 돌린다.
- **Expected**: 채운 호스트의 글은 그 도구로 그리라고 하고, 비운 호스트의 글은 화살표 한 줄 · 표로 보여 주라고 한다. core 의 글에는 특정 도구 이름이 박혀 있지 않다.
- **Pass criterion**: 두 글에 각각 맞는 구절 1건, `bash tests/test-host-neutral.sh` 종료 코드 0.

### T46. 긴 순서 글인데 그림이 없으면 잡는다

- **Setup**: 번호 순서가 5줄 이어지는 답 글, 화살표가 든 줄이 4줄 흩어진 답 글. 그 턴에 그림 도구 호출은 0번.
- **Run**: 직전 답 검사를 두 글에 돌린다.
- **Expected**: 두 글 모두 그림이 있어야 했다고 나온다.
- **Pass criterion**: 두 번 모두 출력에 `picture=1`.

### T47. 그림 도구를 썼으면 잡지 않는다

- **Setup**: T46 의 글, 그 턴에 그림 도구 호출 1번.
- **Run**: 직전 답 검사를 돌린다.
- **Expected**: 그림 종류의 어긋남이 없다.
- **Pass criterion**: 출력에 `picture=` 0건.

### T48. 화살표 한 줄이나 표가 있으면 잡지 않는다

- **Setup**: 번호 순서 5줄 + 화살표가 둘 이상인 한 줄(`A → B → C`)이 있는 답 글, 번호 순서 5줄 + 표가 있는 답 글. 그림 도구 호출은 0번.
- **Run**: 직전 답 검사를 돌린다.
- **Expected**: 두 글 모두 어긋남이 없다.
- **Pass criterion**: 두 번 모두 `picture=` 0건.

### T49. 짧은 답은 건드리지 않는다

- **Setup**: 한 줄 답, 받았다는 답, 불릿 3개짜리 답, 번호 순서 3줄짜리 답.
- **Run**: 직전 답 검사를 네 글에 돌린다.
- **Expected**: 어느 것도 그림 종류의 어긋남이 없다.
- **Pass criterion**: 네 번 모두 `picture=` 0건.

### T50. 다음 턴에 알림 한 줄이 실리고, 끄면 실리지 않는다

- **Setup**: T46 의 답으로 턴을 끝낸 세션. 설정 `SCV_PICTURE_NOTICE` 를 켠 경우(기본 — 2026-11-24 사용자 결정)와 끈 경우.
- **Run**: 다음 턴의 매 턴 훅을 돌린다. 어긋남이 없는 답으로 끝낸 세션에서도 돌린다.
- **Expected**: 켠 경우 알림이 한 줄 실리고 그 턴은 막히지 않는다. 끈 경우와 어긋남이 없는 경우에는 실리지 않는다.
- **Pass criterion**: 알림 줄 1건 · 0건 · 0건, 훅 종료 코드는 모두 0.

### T51. 호스트 프로필의 새 칸이 읽기 · 검증 · 내려쓰기 세 곳에 있다

- **Setup**: `SCV_DRAW_TOOL` 이 든 프로필 파일, 그 칸에 줄바꿈이 든(모양이 틀린) 프로필 파일.
- **Run**: 프로필 읽기 · 프로필 검증 · 래퍼로 내려쓰기를 각각 돌린다.
- **Expected**: 맞는 프로필은 세 곳 모두 그 값을 다루고, 틀린 프로필은 검증이 거부한다.
- **Pass criterion**: 읽은 값이 준 값과 같음, 검증 종료 코드 0 · 0 이 아닌 값, 내려쓴 파일에 그 칸이 있음.
