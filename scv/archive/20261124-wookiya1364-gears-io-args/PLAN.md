# 기어의 입력 · 출력을 종류 이름 + 예시로 보이고, 이름 붙은 인자로 같은 기어를 다르게 쓰기 + 글 대신 그림으로 보여 주기

## Summary

0.100.0 의 기어 파일은 맨 위에 흐름(`flow:`) · 하는 일 · 낱말만 있다. 합성 순서는 보이지만 그 기어가 무엇을 받아 무엇을 돌려주는지는 파일에도 목록에도 없다(색인 파일에만 계산돼 있다). 넣을 수 있는 입력도 표준 입력 하나뿐이라, "최근 12개" 같은 조절 값이 톱니 안에 박혀 있고 30개로 바꾸려면 톱니를 새로 써야 한다.

이 계획은 두 가지를 더한다. 기어 파일에 값의 종류 이름(`in:` · `out:`)과 실제 입력 예 → 출력 예(`예:`)를 적게 하고 검사가 맞춰 본다. 그리고 톱니와 기어가 이름 붙은 인자를 받게 해서, 같은 기어를 값만 바꿔 다시 쓸 수 있게 한다.

이 계획에는 둘째 부분이 얹혀 있다(2026-11-24 사용자 요청 — 같이 진행). 흐름도와 차트로 본 계획 요약이 글보다 훨씬 빨리 이해된다는 것을 사용자가 확인했다. 지금 SCV 의 글쓰기 규칙(`core/contracts/writing.md`)에는 그림에 대한 말이 없다. 둘째 부분은 흐름 · 구조 · 수치 비교를 설명할 때 그림을 먼저 쓰게 하는 규칙과, 지켜지지 않았을 때 다음 턴에 알리는 검사를 더한다.

## Goals / Non-Goals

- **Goals**
  - 기어 파일 맨 위에 `in:` · `out:` · `예:` 줄을 둔다. `in` · `out` 은 값의 종류 이름(뒤에 ` — ` 와 한 줄 설명을 붙일 수 있다), `예` 는 실제 입력 표기 → 출력 표기다. 종류 이름은 고정된 값이 아니고, 예시는 "이 입력이면 이 출력"의 한 가지 경우다.
  - 검사가 기어의 `in` 을 첫 톱니가 받는 값의 이름과, `out` 을 끝 톱니가 돌려주는 값의 이름과 맞춰 본다. 다르면 오류 줄을 낸다.
  - 기어의 예시: 펼친 흐름이 순수 톱니로만 된 기어는 검사가 실제로 돌려 맞춰 본다. 판단 단계(`@`)나 순수하지 않은 톱니가 든 기어의 예시는 보기용으로 두고 돌리지 않는다.
  - 목록에 기어의 "받는 값 → 돌려주는 값"과 인자가 나온다.
  - 이름 붙은 인자: 톱니 사전에 `- 인자: 이름=기본값 — 설명` 줄, 기어 파일에 `arg: 이름=값` 줄, 실행할 때 `gear.sh run <기어> 이름=값 …`. 뒤가 앞을 이긴다(사전의 기본값 → 기어 파일 → 실행 때 준 값).
  - 톱니는 선언한 인자를 같은 이름의 환경 변수로 받는다.
  - 예시 줄 앞에 인자를 적을 수 있다(`- 예: count=2 <입력 표기> → <출력 표기>`). 예시 검사는 그 인자로 돈다.
  - 기어 안내 글(`core/protocols/gear.md`)에 두 규칙을 더한다: 읽는 톱니는 다시 쓸 기어 밖(또는 그 기어를 감싸는 기어)에 둔다. 요청이 숫자 · 범위 · 이름만 다르면 톱니를 새로 쓰지 않고 인자를 준다.
  - (둘째 부분) 글쓰기 규칙에 한 줄을 더한다: 흐름 · 구조 · 수치 비교를 설명할 때는 그림을 먼저 보여 준다 — 순서나 갈래는 흐름도, 무엇 안에 무엇이 있는지는 구성 그림, 전후나 여러 항목의 숫자는 차트. 짧은 답 · 한 줄 답은 글 그대로다.
  - (둘째 부분) 그림은 작게(한 장에 한 가지), 둘레의 글은 짧게, 그림에 있는 내용을 글로 다시 적지 않는다.
  - (둘째 부분) 이 세션에 그림 도구가 있으면 그 도구로 그리고, 없으면(터미널 · 그림 도구가 없는 호스트) 화살표 한 줄(`A → B → C`)과 짧은 표로 대신한다.
  - (둘째 부분) 그림 도구의 이름은 호스트 프로필의 새 칸(`SCV_DRAW_TOOL`)이 준다. core 글에는 특정 도구 이름을 적지 않는다.
  - (둘째 부분) 직전 답이 "긴 순서 글"(번호 순서가 4줄 이상 이어지거나, 화살표가 든 줄이 3줄 이상 흩어진 글)인데 그림도 화살표 한 줄도 표도 없었으면, 다음 턴에 알림 한 줄을 싣는다. 지금 있는 "직전 답 모양" 알림에 한 종류로 더한다.
  - (둘째 부분) 알림은 실제 세션 기록으로 틀린 알림이 얼마나 나오는지 잰 뒤에 켠다. 재기 전의 기본값은 꺼짐이다(설정 `SCV_PICTURE_NOTICE`). 잰 뒤(2026-11-24: 808턴 · 알림 11 · 맞음 8 · 틀림 3) 사용자가 기본값을 켜기로 정했다 — 끄기는 `SCV_PICTURE_NOTICE=off`.
- **Non-Goals**
  - (둘째 부분) SCV 가 스스로 그림을 그리는 것 — 그리는 것은 모델과 호스트의 그림 도구다.
  - (둘째 부분) 파일로 쓰는 문서(계획 · 시험 문서)에 그림을 강제하는 것 — 이 규칙은 사용자에게 보이는 답에만 적용된다.
  - (둘째 부분) 그림의 내용이 맞는지 검사하는 것.
  - 기어를 돌릴 때마다 실제로 받은 값 · 낸 값을 화면에 보여 주는 것.
  - 판단 단계가 든 기어의 예시를 자동으로 맞춰 보는 것(모델이 쓰는 글은 매번 다르다).
  - 인자 값의 종류 검사(숫자인지, 범위 안인지).
  - 반복 알아채기(`20261124-wookiya1364-gears-detect` 계획의 일).
  - 새 명령 — 명령 개수는 23 그대로다.

## Approach Overview

톱니 사전(`TEETH.md`)의 톱니 항목에 `- 인자:` 줄을 읽는 순수 함수를 더하고, 사전 한 줄(색인)에 인자 칸을 하나 더 둔다. 실행기는 실행할 때 받은 `이름=값` 낱말을 나누고, 펼친 흐름의 단계마다 "사전의 기본값 ← 그 단계를 펼쳐 넣은 기어들의 `arg:` 줄(바깥 기어가 안쪽을 이긴다) ← 실행 때 준 값" 순으로 합친다. 어느 톱니도 선언하지 않은 이름이 오면 돌리기 전에 거부한다. 합친 값은 실행 상태 폴더에 적어 두어, 판단 단계나 확인에서 멈췄다가 이어 갈 때도 같은 값이 쓰인다. 이어가기 명령은 인자를 새로 받지 않는다.

톱니를 돌릴 때는 그 톱니가 선언한 인자만 환경 변수로 넘긴다. 밖으로 나가는 톱니의 확인 글에는 그 톱니로 들어갈 인자 값이 함께 나온다.

기어 파일의 맨 위 줄 읽기는 지금 영어 소문자 열쇠만 받는다(`core/scripts/lib/gear.sh:168`). `예:` 줄을 받게 넓히고(`example:` 도 같은 뜻으로 읽는다), 같은 열쇠가 여러 줄일 때(`예` · `arg`) 모두 꺼내는 함수를 더한다. 기어의 `in` · `out` 을 첫 · 끝 톱니와 맞춰 보는 검사는 지금 있는 이음매 검사(`scv_gear_flow_check`) 옆에 순수 함수로 더한다.

기어를 만드는 명령은 `in` · `out` 을 주지 않으면 첫 · 끝 톱니에서 채운다. 0.100.0 모양의 기어 파일과 톱니 사전(새 줄이 없는 것)은 고치지 않아도 그대로 돈다 — 검사는 빠진 줄을 알림으로만 낸다. 색인 파일은 칸이 하나 늘어서, 옛 프로젝트는 색인 다시 만들기를 한 번 해야 검사의 "색인이 어긋남" 줄이 사라진다(실행은 색인 파일을 읽지 않아 그대로 된다 — `core/scripts/gear.sh:99`).

**둘째 부분(글 대신 그림).** 규칙은 글쓰기 규칙 문서에 10조로 적고(1–9조가 이미 있다), 매 턴 훅이 싣는 답 모양 글(`core/template/hooks/on-user-prompt.sh:86` 의 묶음)에 한 구절을 더한다. 매 턴 글의 크기 한도(11,000 바이트 — `core/tests/test-instruction-diet.sh:48`)를 넘지 않게 짧게 쓴다. 호스트 프로필의 새 칸은 읽기 · 검증 · 내려쓰기 세 곳을 한 PR 에서 같이 넣는다(빠지면 래퍼 맞춤이 멈춘다). 직전 답 검사는 지금 있는 답 모양 검사(`core/scripts/lib/help-state.sh:471` 부근 — 어긋난 종류를 `이름=개수` 줄로 낸다)에 `picture=1` 한 종류를 더하고, 그 턴에 그림 도구가 불렸는지는 단계 도구를 세는 것과 같은 방식(`core/scripts/turn-check.sh:440`)으로 턴 중에 적어 둔다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  scv_gear_args_parse,     // 톱니 사전 글 + 이름 → 인자 줄들(이름 · 기본값 · 설명)
  scv_gear_args_split,     // 실행 때 받은 낱말들 → 이름 · 값 줄들 | 오류
  scv_gear_args_unknown,   // 준 이름들 + 선언된 이름들 → 모르는 이름들
  scv_gear_args_merge,     // 기본값 줄들 + 덮는 줄들 → 합친 줄들
  scv_gear_sig_check,      // 기어의 in · out + 첫 · 끝 톱니의 값 이름 → 통과 | 오류 줄
  scv_gear_example_mode,   // 펼친 흐름 + 사전 → 돌려 맞춤 | 보기용
)
```

|---|---|---|---|---|

| 3 | `scv_gear_args_split` | 실행할 때 받은 `이름=값` 낱말들을 이름과 값으로 나눈다 | 낱말들 → 이름 · 값 줄들 또는 오류 | 순수 |
| 4 | `scv_gear_args_unknown` | 어느 톱니도 선언하지 않은 이름을 찾는다 | 준 이름들 + 선언된 이름들 → 모르는 이름들 | 순수 |

| 9 | `scv_gear_example_mode` | 기어의 예시를 돌려 맞출지 보기용으로 둘지 정한다 | 펼친 흐름 + 사전 → 돌려 맞춤 · 보기용 | 순수 |

| 11 | `scv_gear_confirm_text` | 밖으로 나가는 톱니 앞에서 낼 글에 인자 값을 더한다(있던 함수를 넓힌다) | 표 · 단계 · 돌릴 글 · 인자 줄들 → 확인 글 | 순수 |

| 15 | `drive` | 받은 인자를 실행 상태에 적고, 단계마다 인자를 넘겨 돌린다(있던 함수를 넓힌다) | 실행 폴더 + 단계 번호 → 결과 또는 멈춤 | 부수효과 (입구/출구) |
| 16 | `scv_hs_seq_prose` | 답 글이 "긴 순서 글"인지 가린다 — 번호 순서 4줄 이상, 또는 화살표가 든 줄 3줄 이상 | 답 글 → 예 · 아니오 | 순수 |
| 17 | `scv_hs_picture_shown` | 그 답에 그림을 대신하는 것이 있는지 가린다 — 화살표가 둘 이상인 한 줄, 또는 표 | 답 글 → 예 · 아니오 | 순수 |

| 19 | `_scv_turn_tool_count` | 그 턴에 그림 도구가 불린 횟수를 대화 기록에서 센다(턴 경계를 못 찾으면 모름) | 대화 기록 + 도구 이름 → 횟수 | 부수효과 (입구) |

- 부수효과 위치: 파일 읽기 · 톱니 실행 · 실행 상태 읽고 쓰기는 `flat_walk` · `tooth_run` · `lint_gears` · `drive` 와 실행 명령에만 있다. 1–11 은 받은 글만 본다.
- 둘째 부분의 부수효과 위치: 그림 도구 호출을 적는 것은 도구 호출 훅(지금 단계 도구를 적는 자리), 읽는 것은 `_scv_turn_tool_count` 뿐이다. 16–18 은 받은 글과 수만 본다.
- 재사용: 예시 나누기(`scv_gear_example_split`) · 표기 풀기(`scv_gear_lit_decode`) · 이음매 검사(`scv_gear_flow_check`) · 예시 돌리기(`run_example`) · 톱니를 돌려도 되는지 가리기(`tooth_block`)는 그대로 쓴다.

### 합성 설계 체크리스트 (Composition checklist)

## Guardrails

- 순수 톱니는 같은 입력 + 같은 인자면 같은 출력을 낸다. 인자가 있는 순수 톱니도 예시가 하나 이상 있어야 하고, 예시 검사는 그 예시의 인자로 돈다.
- 인자로는 밖으로 나가는 톱니의 확인을 건너뛸 수 없다. 인자는 표시(`pure` · `effect` · `outward`)도 확인 절차도 바꾸지 못하고, 확인 글에 그 톱니로 들어갈 인자 값이 보인다.
- 선언하지 않은 인자는 톱니에 닿지 않는다. 어느 톱니도 선언하지 않은 이름을 실행 때 · 기어 파일 · 예시에서 주면 거부한다(실행은 종료 코드 2, 검사는 오류 줄).
- 인자 이름은 영어 소문자 · 숫자 · 밑줄(첫 글자는 소문자)만. 이미 뜻이 있는 환경 변수 이름(`_proxy` 로 끝나는 이름 등)은 만들 때와 검사에서 거부한다.
- 인자 값은 한 줄 글이다. 실행기는 값을 셸 글로 풀지 않는다(`eval` 없음) — 값은 환경 변수로만 건너간다.
- 예시의 글 표기는 지금처럼 실행하지 않고 푼다.
- 0.100.0 모양의 기어 파일 · 톱니 사전은 고치지 않아도 그대로 돈다. 빠진 `in` · `out` · `예` 줄은 알림이고 실패가 아니다.
- 판단 단계에서 모델에게 넘기는 글은 지금과 같다 — 그 기어의 글과 앞 단계 결과만. 맨 위 줄(`flow` · `in` · `out` · `예` · `arg`)은 싣지 않는다.
- 호스트의 스킬 폴더에 아무것도 쓰지 않는다. 첫째 부분(기어)은 매 턴 훅을 건드리지 않는다.
- (둘째 부분) 매 턴 글은 한도(11,000 바이트) 안에 있고, codex 사본에서도 그렇다. 더한 구절의 크기를 전후로 재서 적는다.
- (둘째 부분) 짧은 답 · 한 줄 답 · 받았다는 답에는 그림 알림이 뜨지 않는다.
- (둘째 부분) 알림은 알림일 뿐 턴을 막지 않는다.
- (둘째 부분) 호스트 프로필의 새 칸은 읽기 · 검증 · 내려쓰기 세 곳에 한 PR 로 넣는다. 칸이 빈 호스트(그림 도구 없음)에서는 화살표 한 줄 · 표 쪽 규칙이 실린다.
- (둘째 부분) 규칙 글이 실리는 방식은 "규칙은 세션에 한 번, 그 뒤는 한 줄" 구조를 그대로 따른다.
- 두 래퍼의 명령 설명 글은 건드리지 않는다(한쪽 래퍼의 설명 글 합계가 한도까지 1 남았다).
- core 글에 특정 호스트 이름을 쓰지 않는다(`tests/test-host-neutral.sh`).
- 맥(BSD 도구 · bash 3.2)과 리눅스(GNU 도구)에서 같은 결과.

## Risks / Open Questions

- (정함 2026-11-24: 바꾸지 않음) 순수 톱니의 환경은 지금 그대로 둔다 — 흐름의 톱니들이 선언한 이름만 환경에서 지우고 그 톱니의 것만 넣는다. 환경을 통째로 비우면 옛 톱니의 출력이 달라질 수 있는데, 달라졌다는 사례가 아직 없어 잴 것이 없다. 아래는 정하기 전의 메모다.
- 순수 톱니를 "정해진 환경(PATH · 언어 설정 · 선언한 인자만)"에서 돌릴지는 구현 중에 정한다. 그렇게 하면 선언하지 않은 환경 변수가 결과를 바꿀 수 없어 "같은 입력 + 같은 인자 = 같은 출력"이 더 단단해지고 맥과 리눅스의 정렬 순서 차이도 줄어든다. 다만 0.100.0 에서 만든 순수 톱니의 출력이 달라질 수 있으니, 바꾸기 전후의 예시 검사 결과를 재서 달라지면 사용자에게 묻는다.
- 같은 흐름 안의 두 톱니가 같은 이름의 인자를 선언하면 같은 값이 둘 다에 들어간다(한 이름 = 한 뜻). 기본값이 서로 다르면 검사가 알림을 낸다. 실제로 헷갈리는 경우가 나오면 이름을 나누라는 안내로 충분한지 본다.
- 색인 파일의 칸이 하나 늘어난다. 색인을 직접 읽는 곳(반복 알아채기 계획이 읽을 예정)이 칸 수에 기대지 않게 맞춘다.
- 기어 파일 맨 위 줄의 열쇠가 영어(`flow` · `in` · `out` · `arg`)와 한국어(`예`)로 섞인다. `example:` 도 같은 뜻으로 읽어 영어 프로젝트에서 쓸 수 있게 한다.
- (둘째 부분) "긴 순서 글"을 가리는 기준(번호 순서 4줄 · 화살표 줄 3줄)은 시작값이다. 실제 세션 기록으로 재서 틀린 알림이 많으면 기준을 고치고, 고친 값과 까닭을 적는다.
- (둘째 부분) 그림 도구가 있는지는 세션마다 다르다(같은 호스트라도 터미널에는 없다). 프로필의 칸은 "있을 수 있는 도구의 이름"만 주고, 규칙 글은 "이 세션에 그 도구가 있으면"으로 적는다.
- (둘째 부분) 래퍼 쪽 일: 그림 도구가 있는 래퍼는 프로필에 새 칸을 채워야 한다 — core 릴리스 뒤 래퍼 맞춤 때 같이 넣는다. 그림 도구가 없는 래퍼는 비워 둔다.
- (둘째 부분) 한 계획에 서로 다른 두 주제(기어 · 답 모양)가 들어 있다 — 사용자가 같이 진행하기로 정했다. 구현과 시험은 부분별로 나눠 진행하고, 한쪽이 막히면 다른 쪽은 계속한다.
- codex 래퍼에는 선택 답을 적는 훅이 없어 밖으로 나가는 톱니를 확인할 길이 아직 없다 — 이 계획은 그 상태를 바꾸지 않는다.
