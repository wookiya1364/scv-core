# Test Plan — 비우기로 줄인다

## Overview

대화가 길어졌을 때 요약 대신 비우고, 새 대화가 기록의 끝부분과 뒤에서 도는 일 목록으로 시작하는지 본다. 본체 쪽(끝부분 자르기 · 이어 하기 훅)은 셸 시험으로, 대시보드 쪽(비우기 돌리기 · 넘어가기 · 첫 글 · 창 글자)은 모드 시험으로, 마지막은 실제 앱의 화면으로 확인한다.

## Test scenarios

### T1. 긴 기록은 끝부분만 남고 턴 머리에서 시작한다

- **Setup**: 턴 머리 줄(`## Turn N`)이 여러 개인 30,000자 기록 글.
- **Run**: `scv_resume_tail` 에 글과 12,000 을 준다.
- **Expected**: 돌려준 글이 12,000자 이하이고 첫 줄이 턴 머리 줄이며, 원래 글의 끝과 같은 줄로 끝난다.
- **Pass criterion**: 길이 ≤ 12,000 · 첫 줄이 `## ` 로 시작 · 마지막 줄 일치.

### T2. 짧은 기록은 그대로다

- **Setup**: 3,000자 기록 글.
- **Run**: `scv_resume_tail` 에 글과 12,000 을 준다.
- **Expected**: 받은 글과 같은 글.
- **Pass criterion**: 입력과 출력이 같다.

### T3. 잘린 자리에 턴 머리가 없으면 끝에서 글자 수만큼 남긴다

- **Setup**: 턴 머리 줄이 없는 30,000자 글.
- **Run**: `scv_resume_tail` 에 글과 12,000 을 준다.
- **Expected**: 끝 12,000자 이하의 글 — 빈 글이 아니다.
- **Pass criterion**: 길이가 0 보다 크고 12,000 이하.

### T4. 비운 뒤에는 훅이 끝부분과 전체 기록의 자리를 찍는다

- **Setup**: 임시 프로젝트에 30,000자 진행 중 대화 기록.
- **Run**: 이어 하기 훅에 `{"source":"clear"}` 를 준다.
- **Expected**: 출력에 기록의 끝부분과 전체 기록 파일의 자리 한 줄이 있고, 기록의 첫 턴 글은 없다.
- **Pass criterion**: 출력의 기록 부분 ≤ 12,000자 · 자리 줄 있음 · 첫 턴의 표식 글 없음 · 종료 코드 0.

### T5. 요약 · 재개 뒤에는 지금처럼 전체를 찍는다

- **Setup**: T4 와 같은 프로젝트.
- **Run**: 훅에 `{"source":"compact"}` 와 `{"source":"resume"}` 를 차례로 준다.
- **Expected**: 두 번 다 기록 전체가 찍힌다.
- **Pass criterion**: 출력에 첫 턴의 표식 글과 마지막 턴의 표식 글이 모두 있다.

### T6. 턴 끝에 기준을 넘으면 비우기를 돌리고, 거절되면 지금의 길로 넘어간다

- **Setup**: 모드 시험 틀에서 컨텍스트 62% · 기준 50% · 턴 끝 · 기록 있음.
- **Run**: (가) 비우기 명령이 받아들여지는 경우 (나) 비우기 명령이 거절되는 경우.
- **Expected**: (가) 비우기 명령이 한 번 돌고 요약 명령은 돌지 않는다. (나) 요약 명령이 한 번 돌고 대화가 기록으로 바뀐다. 창의 결과 줄이 (가) 비웠다고 (나) 넘어갔다고 적는다.
- **Pass criterion**: 돈 명령의 이름과 횟수 · 결과 줄의 글이 기대와 같다.

### T7. 턴이 도는 중 · 기준 아래 · 꺼짐 · 기록 없음이면 비우지 않는다

- **Setup**: 네 경우 각각.
- **Run**: 턴 끝 처리.
- **Expected**: 비우기 명령이 돌지 않는다. 기록 없음은 지금처럼 엔진 요약으로 간다.
- **Pass criterion**: 비우기 명령 0번.

### T8. 비운 뒤 첫 글에 뒤에서 도는 일 목록이 실린다

- **Setup**: 턴이 남기고 간 일 둘(명령 하나 · 감시 하나)이 있는 상태에서 비움.
- **Run**: 비운 뒤의 세션 시작.
- **Expected**: 첫 글에 두 일이 한 줄씩 있다. 남은 일이 없으면 그 묶음이 없다.
- **Pass criterion**: 줄 수와 각 줄의 이름이 남은 일과 같다.

### T9. 창의 글자가 비우기로 보인다

- **Setup**: 컨텍스트 칸.
- **Run**: 창을 그린다.
- **Expected**: 스위치 줄과 기준 표시의 글이 "요약"이 아니라 "비우기"이고, 한 뒤의 결과 한 줄(앞 % → 뒤 % · 걸린 시간)이 보인다.
- **Pass criterion**: 그린 글에 "비우기"가 있고 스위치 줄에 "요약"이 없다.

### T10. 실제 앱에서 비우기가 돈다

- **Setup**: 실제 앱의 시험용 세션(PR 감시와 뒤에서 도는 명령 하나가 걸린 상태).
- **Run**: 기준을 낮춰 턴 끝에 비우기가 돌게 한다.
- **Expected**: 대화가 비워지고 첫 글에 기록의 끝부분과 뒤에서 도는 일 목록이 실린다. 뒤에서 돌던 명령의 알림이 온다. PR 감시와 이어진 세션이 남는지 본 대로 적는다.
- **Pass criterion**: 비운 뒤 화면의 사진 · 첫 글의 사진을 남기고, 남지 않은 것이 있으면 그대로 보고한다.

### T11. 큰 색인에서도 거르기가 제한 시간 안에 끝난다 (6단계, 2026-11-25 추가)

- **Setup**: 색인 300줄(키 260가지, 40개는 두 번 나온다). 실제 프로젝트의 색인 282줄.
- **Run**: `record_index_filter <색인> decision`. 실제 프로젝트에서는 세션 시작 훅을 비우기 입력으로 돌린다.
- **Expected**: 키마다 최신 한 줄씩 260줄이 색인의 순서대로 나온다. 줄이 통째로 같은 레코드 둘은 하나가 된다. 고치기 전 함수와 같은 입력에서 같은 결과다.
- **Pass criterion**: 결과 줄 수 260 · 최신 40줄 · 첫 줄의 키가 맞음. 실제 프로젝트의 훅이 제한 30초 안에 끝남(고치기 전 274초에 멈춤 → 고친 뒤 0.4초).

### T12. 비운 뒤에는 요약 묶음을 싣지 않는다 (7단계, 2026-11-25 추가)

- **Setup**: 진행 중인 계획과 긴 대화 기록이 있는 프로젝트.
- **Run**: 세션 시작 훅을 `source` 가 `clear` · `compact` · `resume` 인 입력으로 돌린다.
- **Expected**: 비운 뒤에는 요약 묶음(진행 중 계획 · 최근 결정)이 없고, 그 묶음을 부를 명령 한 줄이 있다. 요약 · 재개 뒤에는 전과 같이 묶음이 실린다.
- **Pass criterion**: 비운 뒤 출력에 묶음 머리 0번 · 안내 줄 1번. 요약 · 재개 뒤 출력에 묶음 머리가 있고 안내 줄 0번.

### T13. 비운 뒤, 진행 중 표시의 대화가 없으면 가장 최근에 손댄 기록을 싣는다 (7단계, 2026-11-25 추가)

- **Setup**: 표시가 `promoted` 인 긴 대화 기록 하나만 있는 프로젝트(일하던 대화가 계획으로 넘어간 뒤).
- **Run**: 세션 시작 훅을 `clear` · `compact` · `resume` 입력으로 돌린다. 기록의 손댄 시각을 3일보다 오래 전으로 바꿔 다시 돌린다.
- **Expected**: 비운 뒤에는 그 기록의 끝부분과 자리 줄이 실린다. 요약 · 재개 뒤에는 전과 같이 싣지 않는다. 3일 넘게 손대지 않은 기록은 비운 뒤에도 싣지 않는다.
- **Pass criterion**: 비운 뒤 출력에 마지막 턴의 표식 글 있음 · 첫 턴의 표식 글 없음 · 자리 줄 1번. 나머지 경우에는 표식 글 없음.

### T14. 뒤에서 도는 일 목록에 하위 작업이 실리고 끝난 일은 빠진다 (8단계, 2026-11-25 추가)

- **Setup**: 끝난 터미널 탭 명령 · 끝난 명령 · 돌고 있는 하위 작업이 있는 상태에서 비움(2026-11-25 실제 세션에서 본 모습).
- **Run**: 비운 뒤의 세션 시작.
- **Expected**: 첫 글의 목록에 돌고 있는 하위 작업이 있고, 끝난 일은 없다.
- **Pass criterion**: 모드 시험에서 목록의 줄이 돌고 있는 일과 같다. 모드가 끝남을 알 수 없는 종류가 있으면 그 종류를 적는다.

### T15. 비운 직후 마지막 대화 셋이 대화창에 보인다 — 자기 명령의 출력 줄에 (9단계, 2026-11-25 추가 · 같은 날 방법 바꿈)

- **Setup**: 주 대화에서 턴 넷(마지막 턴은 일이 끝났다는 알림으로 시작, 셋째 답은 4,000자)을 한 뒤 기준을 넘김.
- **Run**: 턴 끝에 모드가 비우기를 돌린다.
- **Expected**: 비운 뒤 대시보드가 자기 명령(`/scv-last-talk`)을 한 번 돌리고, 그 출력 줄이 머리 하나와 대화 셋(오래된 것부터, 답은 자르지 않음)으로 그려진다. 가장 오래된 넷째 전 대화는 없다. 알림 글(system 줄)은 넣지 않는다 — 데스크톱 앱이 그리지 않는다. 그 명령의 줄이 저장될 때 글은 표시용 한 줄로 바뀌어, 모델은 그 한 줄만 읽는다. 모델이 받는 첫 글에는 직전 대화가 없고, 턴은 시작되지 않는다. 보일 대화가 없을 때 그 명령의 줄은 없다는 한 줄로 그려진다.
- **Pass criterion**: 모드 시험 clear T15(순수부) · T16 · T19(저장되는 글) · T20(보일 것이 없을 때) 통과. 실제 앱에서 비운 직후 대화창에 그 글이 읽히는 모양으로 보이는 것을 사용자가 본다. (2026-11-25 실제 앱: 같은 방법의 시험 모드로 출력 줄이 여러 줄 그대로 보이고 저장되는 글이 바뀌는 것을 봄. 대시보드 자체의 자동 비우기에서는 아직 못 봄.)

### T16. 비우지 못했거나 사람이 직접 비웠으면 앞 대화를 보이지 않는다 (9단계, 2026-11-25 추가)

- **Setup**: (가) 비우기 명령이 거절되는 상태. (나) 사람이 직접 비운 뒤 턴 하나.
- **Run**: 기준을 넘긴 턴의 끝.
- **Expected**: (가) 직전 대화를 보이지 않는다(자기 명령을 돌리지 않는다). (나) 사람이 비운 뒤의 대화만 보인다.
- **Pass criterion**: 모드 시험 clear T17 · T18 통과.

## How to run

```bash
bash core/tests/test-resume-tail.sh
bash core/tests/test-record-index.sh
bash core/tests/test-session-resume.sh
```

대시보드 쪽(T6–T9 · T14)은 scv-mods 저장소에서 `claude plugin test marketplace/mods/scv-dashboard` 로 돌린다.

## Pass criteria

- T1–T5 · T11–T13 이 맥 기본 셸과 새 셸에서 통과.
- T6–T9 · T14 가 모드 시험에서 통과.
- T10 의 사진을 사용자에게 보였다.
