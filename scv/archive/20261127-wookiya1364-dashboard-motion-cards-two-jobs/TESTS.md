# Test Plan — SCV 창이 움직이고, 내 차례를 카드로 알리고, 두 일을 동시에 보인다

## Overview

세 가지를 확인한다. (1) 단계 흐름의 움직임이 뜻대로만 들어가고(일하는 중 · 단계 끝남 · 내 차례의 멈춤), 끄면 지금과 같은 그림인지. (2) 열린 질문이 창 맨 위의 카드로 뜨고 단추나 직접 쓴 글로 답이 되는지, 요구 확인의 세 줄과 결과 확인의 증거가 카드에 보이는지. (3) SCV 본체가 두 일을 가르고 합치며 결과가 달라진 것을 잡는지, 창이 그 모습을 나란히 그리는지.

실제 앱에서만 알 수 있는 것 셋(T1 ~ T3)과 마지막 녹화(T33)는 손으로 한 번 하고 기록으로 남긴다. 나머지 대시보드 시험은 대시보드 저장소(scv-mods)의 모드 시험 파일에 `motion T번호` · `card T번호` · `lanes T번호` 이름으로, 본체 시험은 `core/tests/test-plan-link.sh` 에 넣는다. 예로 쓰는 값은 일반적인 것으로 든다(보스 체력 1,000 · 한 대 100 → 10대).

## Test scenarios

### T1. 실제 창에서 움직이는 그림이 돈다 (손으로 한 번 · 기록)

- **Setup**: 이 세션에만 있는 시험용 모드로, 번지는 고리의 움직임이 든 그림 한 장(그림 부품 · `isInteractive`)과 1초마다 바뀌는 숫자 한 줄을 실제 SCV 창 자리에 띄운다
- **Run**: 창을 10초 동안 이어 찍는다(1초에 5장 이상). 같은 화면을 원격(거울) 세션에서도 한 번 찍는다
- **Expected**: 고리가 커졌다 사라지기를 되풀이한다. 숫자가 바뀌어 창이 다시 그려질 때 움직임이 이어지는지, 처음부터 다시 시작하는지를 본 대로 적는다
- **Pass criterion**: 이어 찍은 사진에서 고리의 크기가 다른 장이 3장 이상이다. 다시 그려질 때의 동작과 원격 화면의 모습이 보고에 적혀 있다. 고리가 한 번도 움직이지 않으면 실패 — 4 ~ 6단계 전에 멈추고 사용자에게 묻는다

### T2. 창의 단추로 열린 질문에 답이 된다 (손으로 한 번 · 기록)

- **Setup**: 시험용 모드가 질문 도구 호출을 듣고 그 질문의 보기를 창에 단추로 띄운다. Claude 가 보기 둘인 질문 하나를 연다
- **Run**: 창의 단추를 누른다. 대화창의 선택 창은 건드리지 않는다
- **Expected**: 질문 도구가 누른 보기의 글을 답으로 돌려받고, 대화창의 선택 창이 닫힌다
- **Pass criterion**: 도구 결과에 누른 보기의 글이 그대로 있고, 선택 창이 화면에 남지 않는다. 답은 전해지는데 선택 창이 남거나 답이 전해지지 않으면 실패 — 7 ~ 9단계 전에 멈추고 사용자에게 묻는다 (2026-11-27 결과: 통과 — 누름은 8초 뒤 자동으로 했다. 손으로 누르는 것과, 답이 아닌 단추를 눌렀을 때 질문이 닫히지 않는지는 T33 에서 함께 본다)

### T3. 따로 만든 폴더에서 적은 진행이 원래 창에 보인다 (손으로 한 번 · 기록)

- **Setup**: 시험용 저장소에 진행 중인 계획 하나. `git worktree add` 로 폴더를 따로 만든다
- **Run**: 따로 만든 폴더에서, 계획 폴더의 자리를 원래 폴더로 가리키게 하고 `plan-link.sh progress` 로 진행 한 줄을 적는다. 뒤에서 도는 에이전트가 그 폴더에서 같은 일을 하게도 한 번 해 본다
- **Expected**: 원래 폴더의 계획 파일에 그 줄이 생기고, 원래 창의 단계 흐름이 그 단계를 진행 중으로 그린다
- **Pass criterion**: 창을 찍은 사진에 그 단계가 진행 중으로 보인다. 안 보이면 실패 — 13 ~ 14단계 전에 멈추고 사용자에게 묻는다. 어느 일을 따로 만든 폴더로 보낼지(하던 일 / 새로 온 일)가 이 결과와 함께 적혀 있다 (2026-11-28 결과: 통과 — 예시 계획 둘을 실제 가르기 명령으로 가르고 따로 만든 폴더에서 진행을 적자, 실제 창의 단계 흐름과 두 칸에 그 단계가 진행 중으로 보였다. 증거 step-3-real-pane-two-jobs.png. 따로 만든 폴더로 가는 쪽은 하던 일)

### T4. 일하는 중인 단계의 그림에만 번지는 고리가 든다

- **Setup**: 상태 다섯(완료 · 진행 중 · 막힘 · 대기 · 사용자 차례), 움직임 켬
- **Run**: `nodeMotionSvg` 에 상태마다 넣는다
- **Expected**: 진행 중만 되풀이되는 움직임(고리가 커지며 옅어짐)을 담는다. 나머지 넷에는 되풀이되는 움직임이 없다
- **Pass criterion**: 진행 중의 그림 글에 되풀이되는 움직임(`infinite`)이 있고, 나머지 넷의 글에는 움직임(`animation`)이 0개다 (2026-11-27 고침: 1단계 시험에서 SMIL 로 위치를 옮기는 움직임이 실제 창에 그려지지 않아, 움직임을 모두 CSS 로 그린다) (2026-11-28 고침: 움직이는 그림의 선은 실선이다 — 끝나지 않은 단계 뒤는 회색 실선. 단계 밑에 달린 묶음 옆으로 늘어나는 선과 한 줄로 보이게 하려는 것. 멈춘 그림은 그대로다)

### T5. 방금 끝난 단계를 고른다

- **Setup**: 단계 신호 넷 — 2단계가 3초 전에 끝남 / 2단계가 60초 전에 끝남 / 끝난 단계 없음 / 두 단계가 5초 안에 잇달아 끝남
- **Run**: `justDoneOf` 에 신호와 지금 시각을 넣는다
- **Expected**: 정한 시간(처음 값 5초) 안에 끝난 단계 중 가장 나중 것, 없으면 없음
- **Pass criterion**: 차례로 2 · 없음 · 없음 · 나중에 끝난 단계의 번호

### T6. 방금 끝난 단계에만 내려가는 빛이 한 번 든다

- **Setup**: 완료 상태의 단계 셋 — 방금 끝났고 다음 단계가 있음 / 방금 끝났지만 마지막 단계임 / 끝난 지 오래됨
- **Run**: `nodeMotionSvg`
- **Expected**: 첫째의 그림에만, 선을 따라 내려가는 초록 점의 움직임이 한 번 든다
- **Pass criterion**: 첫째의 그림 글에만 한 번 돌고 멈추는 움직임(`forwards` 가 있고 `infinite` 는 0개)이 있다. 둘째 · 셋째의 글에는 움직임(`animation`)이 0개다 (2026-11-27 고침: CSS 로 그린다)

### T7. 내 차례에는 아무것도 움직이지 않는다

- **Setup**: 턴 상태 셋(일하는 중 · 뒤에서 도는 일 있음 · 사용자 차례), 스위치 켬, 방금 끝난 단계가 하나 있음
- **Run**: `motionOf` 로 움직일지를 정하고 단계 그림들을 만든다
- **Expected**: 사용자 차례에는 모든 그림에 움직임이 없다(방금 끝난 단계의 빛도 없다). 앞의 두 상태에서는 진행 중인 단계가 움직인다
- **Pass criterion**: 사용자 차례의 그림 글 전부에 움직임 요소 0개, 앞의 두 상태에서는 1개 이상

### T8. 움직임을 끄면 지금과 같은 그림이다

- **Setup**: 스위치 끔. 상태 다섯 × 다음 단계 있음 / 없음
- **Run**: 창이 단계 그림을 만든다
- **Expected**: 그림 글이 지금의 `nodeIconSvg` 가 만드는 글과 같고, 그림 부품에 `isInteractive` 가 없다
- **Pass criterion**: 열 가지 경우 중 글이 다른 것 0개, `isInteractive` 가 붙은 그림 0개

### T9. 스위치는 창에서 누르고, 값이 남는다

- **Setup**: 창의 움직임 스위치(처음 값은 켬)
- **Run**: 끄고, 세션을 새로 시작한 것처럼 창을 다시 연다
- **Expected**: 끈 값이 남아 있고 그림이 멈춘 그림이다
- **Pass criterion**: 다시 읽은 값이 끔, 그림 글에 움직임 요소 0개

### T10. 그림은 크기 한도 안이고, 그리는 시간이 늘지 않는다

- **Setup**: 단계 30개인 계획(진행 중 1 · 방금 끝남 1)
- **Run**: 단계 그림을 모두 만들고, 창을 서른 번 그려 가운데 값을 측정한다(움직임 켬 / 끔)
- **Expected**: 그림 한 장이 131,072자 안이고, 켠 창을 그리는 시간이 끈 창의 1.5배 안이다
- **Pass criterion**: 가장 긴 그림의 글자 수가 131,072 미만, 시간 비가 1.5 이하 — 측정값이 출력에 있다

### T11. 열린 질문이 창 맨 위의 카드로 뜬다

- **Setup**: 모드 시험 환경에서 질문 도구 호출 하나가 열린다(질문 1개 · 보기 3개 · 하나만 고르기)
- **Run**: 창을 그린다
- **Expected**: 창의 맨 위에 보라 테두리 카드 — '내 차례' 표시, 질문 글, 보기 3개의 단추(보기 글 그대로), 직접 쓰는 칸
- **Pass criterion**: 그려진 나무의 첫 카드가 그 카드이고 단추가 3개이며, 단추의 글이 보기 글과 같다

### T12. 카드의 단추를 누르면 그 질문의 답이 된다

- **Setup**: T11 의 상태
- **Run**: 둘째 단추를 누른다
- **Expected**: 질문 도구가 둘째 보기의 글을 답으로 돌려받고, 카드가 사라진다
- **Pass criterion**: 도구 결과의 답이 둘째 보기의 글과 글자까지 같고, 다시 그린 창의 카드 0개

### T13. 대화창에서 답해도 카드가 사라진다

- **Setup**: T11 의 상태
- **Run**: 창을 누르지 않고, 질문 도구가 대화창의 답으로 끝난다
- **Expected**: 카드가 사라지고, 창은 답을 따로 보내지 않는다
- **Pass criterion**: 다시 그린 창에 카드 0개, 창이 보낸 답 0개

### T14. 직접 쓴 글이 답이 된다

- **Setup**: T11 의 상태, 입력 칸이 있는 화면
- **Run**: 직접 쓰는 칸에 글을 적어 보낸다. 빈 채로도 한 번 보낸다
- **Expected**: 적은 글이 그대로 답이 된다. 빈 글은 보내지 않고 칸 아래에 알린다
- **Pass criterion**: 도구 결과의 답이 적은 글과 같다. 빈 글일 때 보낸 답 0개 (2026-11-27 고침: 시험 틀에서는 질문이 열려 있는 동안 답이 아닌 누름 · 보내기가 그 호출을 끊어, 빈 글을 보낸 뒤의 알림 줄을 읽을 수 없다 — 빈 글이 답이 되지 않는 것은 `answerOf` 로, 알림 줄은 실제 창에서 손으로 본다)

### T15. 단추로 답할 수 없는 질문은 내용만 보인다

- **Setup**: 세 경우 — 질문이 2개인 호출 / 여러 개를 고르는 질문 / 입력 칸이 없는 화면
- **Run**: 창을 그린다
- **Expected**: 앞의 둘은 카드에 질문 글과 '대화창에서 답하세요' 한 줄만 있고 단추가 없다. 입력 칸이 없는 화면은 단추는 있고 직접 쓰는 칸이 없다
- **Pass criterion**: 앞의 둘은 단추 0개, 셋째는 입력 칸 0개

### T16. 요구를 확인받는 카드에 이해한 것 세 줄이 보인다

- **Setup**: 두 경우 — Claude 가 질문 직전에 카드 도구로 세 줄(목표 · 안 하는 것 · 확인 방법)을 보냄 / 보내지 않음
- **Run**: 질문이 열리고 창을 그린다. 질문이 끝난 뒤 다른 질문을 하나 더 연다
- **Expected**: 보냈으면 카드에 세 줄이 이름표와 함께 보이고, 보내지 않았으면 질문과 보기만 보인다. 다음 질문의 카드에는 앞 질문의 세 줄이 없다
- **Pass criterion**: 카드의 줄이 보낸 세 줄과 같다 / 0줄. 다음 카드의 줄 0줄

### T17. 결과를 확인받는 카드에 증거가 보인다

- **Setup**: Claude 가 질문 직전에 카드 도구로 파일 셋(그림 1 · 영상 1 · 소스 파일 1)을 보낸다
- **Run**: 질문이 열리고 창을 그린다
- **Expected**: 그림은 카드에 그려지고(크게 보기 단추가 있다), 영상은 여는 단추로 보인다. 소스 파일은 받지 않고 그 까닭을 도구의 답으로 알린다(지금의 증거 규칙과 같다)
- **Pass criterion**: 카드에 그림 1개 · 여는 단추 1개, 도구의 답에 받지 않은 파일의 이름 1개

### T18. 카드 도구의 안내는 계획이 진행 중일 때만 실린다

- **Setup**: 진행 중인 계획이 있는 프로젝트 / 없는 프로젝트
- **Run**: Claude 가 읽는 안내 글을 만든다
- **Expected**: 진행 중인 계획이 있을 때만 카드 도구의 안내가 실린다. 더해진 글의 크기가 출력에 남는다
- **Pass criterion**: 계획이 없는 프로젝트의 안내에 카드 도구의 이름이 0번 나온다. 출력에 `더해진 글 N바이트` 줄이 1개 있다

### T19. 거울 세션의 창에는 카드가 보이되 단추가 없다

- **Setup**: 작업 세션에 질문이 열려 있고, 거울 세션이 그 창을 비춘다
- **Run**: 거울 세션의 창을 그린다
- **Expected**: 카드의 질문 글과 세 줄 · 증거의 이름은 보이고, 단추와 입력 칸은 없다
- **Pass criterion**: 거울 창의 카드에 단추 0개 · 입력 칸 0개

### T20. 두 일을 가른다 — 겹치지 않는 두 일

- **Setup**: 시험용 저장소 — 진행 중인 계획 A(확인 명령이 `보스: 10` 을 찍는다)와 새 계획 B. 두 계획이 고칠 파일이 다르다. 원래 폴더에 커밋하지 않은 변경이 하나 있다
- **Run**: 가르는 명령을 돌린다(이름은 제안: `plan-link.sh split <A> --with <B> --at <단계>`)
- **Expected**: 따로 만든 폴더 1개와 가지 1개가 생긴다. 그 폴더에 커밋하지 않았던 변경이 들어 있다. 원래 폴더의 파일과 깃 상태는 가르기 전과 같다. A 의 확인 결과가 계획 폴더에 파일로 남는다. 두 계획의 머리말에 서로와 가른 단계 · 시각이 적히고 변경 이력에 '가름' 항목이 생긴다
- **Pass criterion**: `git worktree list` 가 2줄, 가르기 전후의 `git status --porcelain` 이 같다, 결과 파일에 `보스: 10` 이 있다, 종료 코드 0

### T21. 같은 파일을 고치는 두 일은 가르지 않는다

- **Setup**: 두 경우 — A 의 남은 단계와 B 가 같은 파일을 고친다 / B 가 고칠 파일을 알 수 없다(목록이 비어 있다)
- **Run**: 같은 명령
- **Expected**: 아무것도 만들지 않고, 겹친 파일(또는 파일을 알 수 없다는 것)을 한 줄씩 말한다
- **Pass criterion**: 종료 코드 3, `git worktree list` 1줄, 두 계획 파일이 바뀌지 않았다
