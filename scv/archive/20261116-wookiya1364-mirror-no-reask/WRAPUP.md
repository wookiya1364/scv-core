# 마무리 보고 — 대시보드 거울 — 보는 쪽이 스스로 다시 묻지 않게 (작업 세션에 쌓이는 "메시지 받음" 줄 없애기)

## 1. 문제

- 상황: 2026-11-16, 사용자가 휴대폰으로 작업 세션을 보다가 대화 끝에 "SCV mirror session 세션에서 메시지 받음" 줄이 뜨는 화면을 보내고, 아예 안 나오게 할 수 있는지 물었다.
- 기대: 거울(다른 기기에서 SCV 칸을 보는 세션)을 켜 두어도 작업 세션의 대화에 그 줄이 쌓이지 않는다.
- 실제: 작업 세션이 쉬는 동안 보는 세션이 10분마다 다시 묻고, 그때마다 작업 세션의 대화에 줄이 하나 생긴다.
- 재현 조건: 보는 세션에서 거울을 켜고, 작업 세션이 아무것도 보내지 않는 채 11분이 지나면 보는 세션이 묻는 글을 한 번 더 보낸다.

## 2. 관찰

- 관찰한 사실과 측정값: 보는 세션의 3초 갱신이 마지막으로 받은 때 · 물은 때 가운데 늦은 쪽에서 10분이 지나면 다시 묻는다(`hooks/register.tsx` 의 `refresh`). 작업 세션은 상태가 바뀌었을 때만 보낸다. 가로챈 글도 앱은 줄로 그린다(대시보드 코드의 메모, 사용자 화면). 앱의 기능 설명서에 조용히 보내는 선택지는 없다.
- 정상일 때와 차이: 작업 세션이 일하는 동안에는 상태가 자주 바뀌어 보는 세션이 계속 받으므로 다시 묻지 않는다 — 줄은 작업 세션이 쉴 때만 쌓인다.

## 3. 가설

- H1: 작업 세션에 쌓이는 줄은 보는 세션이 10분마다 다시 묻는 글 때문이다. 그 다시 묻기를 없애면 줄은 거울을 켤 때의 한 번으로 준다.

## 4. 실험

- 방법과 같게 둔 것: 보는 세션에서 거울을 켠 뒤 작업 세션이 아무것도 보내지 않는 채 시계를 9분 · 2분 · 60분 앞으로 돌리며 보낸 글의 수를 세는 시험을, 순수 함수만 넣고 갱신 코드는 고치지 않은 상태에 먼저 돌렸다. 같은 시험을 고친 뒤에 다시 돌렸다.
- 결과와 가설별 판정: H1 은 시험 틀에서 맞음 — 고치기 전에는 11분 뒤 보낸 글이 2건(`Expected: length 1 / Received: length 2`), 고친 뒤에는 71분이 지나도 1건. 다만 사용자 화면의 줄이 정말 이 글 때문이었는지는 실제 앱에서 줄이 더 쌓이지 않는 것을 봐야 확정된다.

## 5. 원인

- 직접 원인과 일어난 길: 보는 세션의 3초 갱신이 10분 넘게 조용하면 작업 세션에 다시 물었다. 작업 세션은 쉬는 동안 보낼 것이 없어 답하지 않으니 10분마다 다시 묻게 되고, 앱은 그 글마다 작업 세션의 대화에 "…세션에서 메시지 받음" 줄을 그렸다.
- 근본 원인: "소식이 없으면 끊긴 것일 수 있다"를 자동으로 고치려고 넣은 다시 묻기가, "쉬는 세션은 원래 소식이 없다"는 흔한 경우와 구별되지 않았다. 그리고 가로챈 글도 앱이 줄로 그린다는 것을 보는 세션 쪽에서만 줄였고(0.2.x 의 10초 간격) 작업 세션 쪽 줄은 세지 않았다.

## 6. 해결과 검증

- 해결책과 고른 이유: 스스로 다시 묻기를 없앴다. 남은 자동 묻기는 상태를 못 받은 동안 주소가 달라졌을 때의 한 번뿐이고(`isMirrorAskDue`), 그 밖에는 사람이 거울 줄의 "다시 요청" 버튼을 누른다. 10분 넘게 조용하면 거울 줄이 그 사실을 말한다(`mirrorLineText`). 거울을 끄는 것보다 나은 이유: 다른 기기에서 칸을 계속 볼 수 있다. 간격만 늘리는 것보다 나은 이유: 줄이 0에 가까워진다.
- 고치기 전후 값: 한 시간 조용한 동안 보는 세션이 보낸 글 — 전에는 11분 뒤 2건(시험으로 봄 — 10분마다 한 건씩 늘어나는 구조), 후에는 71분 동안 1건(시험으로 봄). 대시보드 시험 — 143개 → 146개 통과. 타입 오류 9 → 9. 릴리스: scv-dashboard 0.2.26 → 0.2.27(2026-11-16 12:41 KST), 이 컴퓨터의 설치본도 0.2.27.
- 부작용과 회귀 시험: 작업 세션이 보는 세션을 잊으면(작업 세션을 새로 열었을 때) 거울이 조용히 멈추고, 사람이 "다시 요청"을 눌러야 이어진다 — 쉬는 중과 끊긴 것은 화면만으로 구별되지 않는다. 기대값을 바꾼 기존 시험은 `mirror-two-way T5` 한 개(10분 뒤 다시 요청 → 다시 요청하지 않음). 원격 주소가 늦게 적힌 경우의 시험(`mirror-late-address T1`)은 그대로 통과. 확인 못 한 것: 실제 앱에서 줄이 더 쌓이지 않는지(두 세션 모두 새 버전으로 다시 열어야 한다).

## 7. 배운 것

- 다음에 같은 문제를 만나면 진단하는 법: 대화에 "…세션에서 메시지 받음" 줄이 쌓이면, 그 세션으로 글을 보내는 쪽을 찾는다 — 대시보드에서는 보는 세션의 묻는 글 · 누름, 작업 세션의 상태 보내기 셋뿐이다. 시험 틀에서 시계를 돌리며 보낸 글의 수를 세면 어느 것이 몇 번 나가는지 바로 보인다.
- 다른 곳에도 쓸 수 있는 것: 가로챈 글도 받는 쪽 화면에는 흔적이 남는다 — 세션 사이에 글을 보내는 기능은 "보낸 횟수"가 곧 사용자가 보는 줄 수다. 자동으로 다시 시도하는 것은 "원래 조용한 경우"와 구별되지 않으면 사람의 버튼으로 바꾼다.
