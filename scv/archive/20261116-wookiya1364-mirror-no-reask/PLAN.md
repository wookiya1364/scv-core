# 대시보드 거울 — 보는 쪽이 스스로 다시 묻지 않게 (작업 세션에 쌓이는 "메시지 받음" 줄 없애기)

## Summary

휴대폰으로 작업 세션을 보면 대화에 "SCV mirror session 세션에서 메시지 받음" 줄이 쌓인다(2026-11-16, 사용자 화면).
그 줄은 클로드 앱이 그린다 — 다른 세션에서 글이 올 때마다 한 줄씩이고, 대시보드가 그 글을 가로채도 줄은 생긴다. 대시보드가
할 수 있는 일은 그 글을 덜 보내는 것뿐이다. 지금은 보는 세션(거울)이 10분 동안 아무것도 못 받으면 작업 세션에 다시 묻는데,
작업 세션이 쉬는 동안에는 보낼 것이 없으니 10분마다 다시 묻게 되고, 그때마다 작업 세션에 줄이 하나 생긴다.
스스로 다시 묻는 것을 없애고, 사람이 누르는 "다시 요청" 버튼으로 바꾼다.

확인한 사실(2026-11-16, 코드와 앱의 기능 설명서):

- 보는 세션의 3초 갱신이 `마지막으로 받은 때 · 마지막으로 물은 때` 가운데 늦은 쪽에서 10분이 지나면 다시 묻는다(`hooks/register.tsx` 의 `refresh`, `MIRROR_ASK_MS`).
- 작업 세션은 상태가 바뀌었을 때만 보낸다(`isMirrorDue`). 쉬는 세션은 바뀌는 것이 없어 보내지 않는다.
- 가로챈 글(`{ consumed }`)은 대화 기록에 쓰이지 않고 모델에게 가지 않는다고 설명서에 적혀 있다. 그래도 앱은 줄을 그린다 —
  대시보드 코드의 메모("each send is a row in the viewer's app … consumed or not")와 사용자 화면이 그렇다. 조용히 보내는 선택지는 설명서에 없다.

사용자 결정(2026-11-16, 선택 창): "다시 묻기 없애기" — 줄은 거울을 켤 때 한 번만, 끊긴 것을 알 수 있게 마지막으로 받은 시각과 "다시 요청" 버튼. 시험이 통과하면 릴리스.

## Goals / Non-Goals

- **Goals**
  - 보는 세션이 소식이 없어도 스스로 다시 묻지 않는다 — 작업 세션에 생기는 줄은 거울을 켤 때의 한 번뿐이다.
  - 거울 칸에 "다시 요청" 버튼이 있고, 누르면 한 번 다시 묻는다.
  - 10분 넘게 받지 못했으면 거울 줄이 그 사실을 말한다(쉬는 중이거나 끊긴 것일 수 있다고).
- **Non-Goals**
  - 앱이 그리는 줄 자체를 숨기기 — 대시보드가 할 수 없다.
  - 보는 세션 쪽에 쌓이는 줄 줄이기(작업 세션이 상태를 보낼 때마다 보는 세션에 생기는 줄) — 이번 요청은 작업 세션의 줄이다.
  - 거울을 켜고 끄는 방법 바꾸기.
  - 코덱스.

## Approach Overview

보는 세션의 갱신에서 "10분 넘게 조용하면 다시 묻기"를 뺀다. 남는 자동 묻기는 하나뿐이다 — 상태를 아직 한 번도 못 받았고, 이 세션의
주소가 처음 물을 때와 달라졌을 때(원격 주소가 늦게 적힌 경우). 언제 스스로 묻는지는 순수 함수 하나가 정한다.
거울 줄의 글도 순수 함수가 만든다: 누구의 거울인지, 마지막으로 받은 지 얼마인지, 10분이 넘었으면 그 사실. 거울 줄 옆에 "다시 요청"
버튼을 두고, 누르면 지금의 묻기 함수를 한 번 부른다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
// 3초마다 (보는 세션)
flow(
  readMirror,        // (없음) → 거울 상태 · 이 세션의 주소        (부수효과: 상태 읽기)
  isMirrorAskDue,    // (거울 상태, 이 세션의 주소) → 스스로 다시 물을지
  askMirror,         // 작업 세션 주소 → 보냄 결과                 (부수효과: 다른 세션에 글 보내기)
)

// 그릴 때
flow(
  mirrorLineText,    // (누구의 거울, 마지막으로 받은 때, 지금, 걸린 시간 글 함수) → 거울 줄의 글
  drawMirrorLine,    // 글 → 거울 줄과 "다시 요청" 버튼            (부수효과: 그리기 · 누르면 askMirror)
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `readMirror` | 거울 상태와 이 세션의 주소를 읽음 | (없음) → 거울 상태 · 주소 | 부수효과 (입구) |
| 2 | `isMirrorAskDue` | 스스로 다시 물을 때인지 정함 — 상태를 못 받았고 주소가 달라졌을 때만 | (거울 상태, 주소) → 참 · 거짓 | 순수 |
| 3 | `askMirror` | (기존) 작업 세션에 상태를 보내 달라고 물음 | 작업 세션 주소 → 보냄 결과 | 부수효과 (출구) |
| 4 | `mirrorLineText` | 거울 줄의 글을 만듦 — 10분 넘게 조용하면 그 사실을 붙임 | (이름, 받은 때, 지금, 시간 글 함수) → 글 | 순수 |
| 5 | `drawMirrorLine` | 거울 줄과 "다시 요청" 버튼을 그림 | 글 → 화면 조각 | 부수효과 (출구) |

- 부수효과 위치: 1(읽기), 3 · 5(보내기 · 그리기) — 양 끝. 2 · 4 는 `hooks/model.ts` 에 둔다.
- 재사용: `askMirror`(그대로), `hostLabel`, `formatDuration`.

## Guardrails

- 보는 세션이 스스로 보내는 글은 둘뿐이다: 거울을 켤 때의 한 번, 그리고 상태를 못 받은 동안 주소가 달라졌을 때의 한 번.
- 작업 세션 쪽의 보내기 규칙(바뀌었을 때만, 10초 간격, 세 번 실패하면 놓음)은 건드리지 않는다.
- "다시 요청"은 사람이 누를 때만 보낸다 — 눌렀을 때 보냈는지 못 보냈는지를 알린다.
- 순수 단계는 `hooks/model.ts`, 부수효과는 `hooks/register.tsx`.

## Exit criteria

- TESTS.md 의 시나리오가 모두 통과한다.
- 보는 세션이 한 시간 동안 조용해도 보낸 글이 거울을 켤 때의 1건뿐인 것을 시험으로 봤다(고치기 전에는 실패).
- 기존 대시보드 시험이 통과한다 — "10분이 지나면 다시 요청한다"를 보던 시험 한 개는 새 동작으로 바꾸고 그 이름을 마무리 보고에 적는다.

## Suggested path

1. 시험을 먼저 쓰고 실패를 본다 — 한 시간 조용해도 다시 묻지 않는 것, 버튼, 조용함 표시
2. 스스로 묻는 때를 좁힌다 — `isMirrorAskDue`, `readMirror`, `askMirror`
3. 거울 줄에 조용함 표시와 "다시 요청" 버튼을 둔다 — `mirrorLineText`, `drawMirrorLine`
4. 대시보드 시험 전부를 돌린다 — 밀어 올리기 전 확인

## Risks / Open Questions

- **끊긴 것을 사람이 알아채야 한다**: 작업 세션이 보는 세션을 잊으면(세션을 새로 열었을 때) 거울이 조용히 멈춘다. 거울 줄이 "10분 넘게 소식 없음"을
  말하고 버튼이 있으니, 사람이 누르면 다시 이어진다. 쉬는 중과 끊긴 것은 화면만으로는 구별되지 않는다.
- **줄이 정말 묻는 글 때문인지**: 코드와 설명서로 본 것이고, 사용자 화면의 줄 수를 세어 맞춰 보지는 않았다. 릴리스 뒤 줄이 여전히 쌓이면 다른 원인(거울 칸의 누름, 다른 세션의 글)을 본다.
