# 선택 기록 — 그 턴이 다룬 계획에만 적고, 글은 글자 경계에서 자르기

## Summary

선택 창 답을 계획의 변경 이력에 적는 장치(0.87.0)에 결함이 둘 있다. 2026-11-24, 새 아이디어(기어)를 이야기하는 동안의 선택 답 12건이 관계없는 진행 중 계획에 적혔고, 적힌 글은 한글 글자 중간에서 잘려 깨진 바이트가 남았다(같은 일이 2026-11-22 에도 한 번 있었다).

원인은 둘 다 확인했다. (1) 답이 오면 "진행 중인 계획 가운데 가장 최근에 고친 것"에 무조건 적는다 — 질문이 그 계획 이야기인지 보지 않는다. (2) 글을 120자에서 자르는데, 훅이 도는 환경에 언어 설정이 없으면 셸이 글자를 바이트로 세어 한글(3바이트)의 중간에서 자른다.

고치는 방향은 사용자가 골랐다: 답은 그 턴이 실제로 다룬 계획에만 적는다. 다룬 계획이 아직 없으면 들고 있다가 턴이 끝날 때 다룬 계획에 적고, 끝까지 없으면 기록 폴더의 턴 기록에 한 줄로 남긴다. 글은 글자 경계에서 자른다.

## Goals / Non-Goals

- **Goals**
  - 선택 답은 이번 턴이 다룬 계획에만 적힌다.
  - 다룬 계획이 없는 동안의 답은 턴 상태에 들고 있다가, 같은 턴에 다룬 계획이 생기면 순서대로 거기에 적는다.
  - 턴이 끝날 때까지 다룬 계획이 없으면 턴 기록에 한 줄씩 남긴다.
  - 질문 · 답 글은 언어 설정과 상관없이 글자 경계에서 잘린다.
- **Non-Goals**
  - 지난 기록 옮기기 — 2026-11-24 의 12건은 이미 손으로 옮겼다.
  - 대시보드가 선택 기록을 보여 주는 방식 바꾸기.
  - 질문 글의 뜻을 읽어 계획을 고르는 일 — 턴이 실제로 한 일만 본다.

## Approach Overview

- "다룬 계획"은 이번 턴이 시작된 뒤에 문서가 고쳐진 계획이다. 진행 기록을 남긴 계획과 이번 턴에 새로 만든 계획이 여기에 든다. 셋 중 하나면 다룬 것이다: 턴 시작 때 없었다, 글 길이가 달라졌다, 턴 시작 표시 파일보다 새것이다. 턴이 시작될 때 계획마다 글 길이를 적어 둔다(구현하며 바꿈 — 파일 시각만 보면 옛 셸이 초 단위로만 견줘서 같은 초의 수정을 놓친다). 보관된 계획의 문서에는 적지 않는다 — 보관한 뒤의 답은 턴 기록으로 간다.
- 여럿이면 가장 최근에 고친 것 하나에 적는다. 한 번 적으면 그 계획이 가장 최근이 되므로, 같은 턴의 다음 답도 같은 계획으로 간다.
- 다룬 계획이 없으면 답을 턴 상태 폴더에 한 줄씩 들고 있는다. 다음 선택 답이 올 때와 턴이 끝날 때 다시 본다.
- 턴이 끝날 때까지 다룬 계획이 없으면, 들고 있던 답을 턴 기록(`.turn-plan.log`)에 한 줄씩 남기고 비운다. 턴 끝 처리가 못 돈 채 다음 턴이 시작되면, 시작할 때 같은 식으로 내려놓는다 — 앞 턴의 답이 다음 턴의 계획에 섞이지 않게.
- 글자 경계 자르기는 언어 설정에 기대지 않는다. 바이트를 보고 글자의 첫 바이트를 세어 자른다 — 설정이 있든 없든, 맥이든 리눅스든 같은 글이 나온다.
- 선택 답이 없는 턴에는 하는 일이 늘지 않는다 — 들고 있는 파일이 있을 때만 내려놓기가 돈다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  scv_tc_cut_chars,      // 글 + 글자 수 → 글자 경계에서 자른 글
  scv_tc_choice_entry,   // 날짜 · 시각 · 질문 · 답 → 이력 항목
  scv_tc_choice_target,  // 이번 턴에 다룬 계획 이름들 → 적을 계획 하나 | 빈 값
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `scv_tc_cut_chars` | 글을 글자 수로 자른다 — 글자 중간에서 자르지 않고, 잘렸으면 끝에 … 를 붙인다 | 글 + 글자 수 → 자른 글 | 순수 |
| 2 | `scv_tc_choice_entry` | 선택 답 하나를 이력 항목으로 만든다(이미 있는 함수 — 자르기를 1번으로 바꾼다) | 날짜 · 시각 · 질문 · 답 → 이력 항목 | 순수 |
| 3 | `scv_tc_choice_target` | 다룬 계획들 가운데 적을 계획 하나를 고른다 — 없으면 빈 값 | 다룬 계획 이름들(최근 순) → 계획 이름 또는 빈 값 | 순수 |
| 4 | `scv_tc_choice_log_line` | 계획에 못 적은 답을 턴 기록 한 줄로 만든다 | 시각 · 이력 항목 · 요청 꼬리 → 한 줄 | 순수 |
| 5 | `scv_tc_plan_handled` | 계획 하나가 이번 턴에 다뤄졌는지 가린다 — 시작 때 없었거나 · 길이가 달라졌거나 · 더 새것 | 시작 때 길이 목록 + 이름 + 지금 길이 + 새것 여부 → 예 · 아니오 | 순수 |
| 6 | `plan_sizes` | 턴이 시작될 때 계획마다 글 길이를 읽어 적어 둔다 | 계획 폴더 → 이름과 길이 줄들 | 부수효과 (입구) |
| 7 | `handled_plans` | 이번 턴이 다룬 계획을 최근에 고친 순으로 찾는다 | 턴 시작 표시 + 길이 목록 + 계획 폴더 → 계획 이름들 | 부수효과 (입구) |
| 8 | `choice_flush` | 들고 있던 답을 다룬 계획에 적거나, 턴이 끝났으면 턴 기록에 내려놓는다 | 들고 있는 답 + 적을 곳 → 쓰기 | 부수효과 (출구) |

- 부수효과 위치: 파일 읽기는 `plan_sizes` · `handled_plans`, 쓰기는 `choice_flush` 와 선택 명령의 쓰기뿐이다. 1–5 는 받은 글만 본다.
- 재사용: 이력에 항목을 끼워 넣는 일은 이미 있는 `scv_plan_history_add`, 요청 꼬리는 `scv_tc_req_tag`, 턴 시작 표시보다 새것인지 보는 방법은 `plan_texts` 의 것을 쓴다.

## Guardrails

- 재현 시험이 먼저 실패해야 한다 — 다른 계획에 적히는 것, 글자가 깨지는 것 각각.
- 이번 턴이 다루지 않은 계획의 문서를 선택 답 때문에 쓰지 않는다.
- 답을 버리지 않는다 — 계획에 못 적으면 턴 기록에 남긴다.
- 선택 답이 없는 턴의 턴 끝 처리 시간을 늘리지 않는다(기존 빠른 끝 시험 그대로 통과).
- 턴 기록에 남기는 글도 비밀 가림을 거친 요청 꼬리만 붙인다 — 새 원문을 싣지 않는다.
- 훅 글을 바꾸면 템플릿 지문(`core/TEMPLATE_DIGEST`)을 다시 만든다.
- core 글에 특정 호스트 이름을 쓰지 않는다. 맥(bash 3.2)과 리눅스에서 같은 결과.

- 순수 함수 사전 검사 통과, 끝날 때 측정값 기록.
- 맥과 리눅스 두 곳에서 관련 시험 통과.

## Suggested path

1. 재현 시험 둘을 쓰고 실패를 본다 — 고치기 전에 두 결함이 시험으로 잡히는 것을 본다
2. 글자 경계에서 자르기 — `scv_tc_cut_chars`, `scv_tc_choice_entry`
3. 다룬 계획 찾기와 적을 곳 고르기 — `handled_plans`, `scv_tc_choice_target`, `scv_tc_plan_handled`, `plan_sizes`
4. 들고 있기와 내려놓기(다음 답 · 턴 끝 · 다음 턴 시작) — `choice_flush`, `scv_tc_choice_log_line`
5. 훅의 설명 글과 템플릿 지문, 기존 시험 T12 를 새 규칙에 맞춘다 — 문서와 시험이 새 동작을 말하게 한다
6. 설치본에 얹어 실제 선택 창 답이 맞는 계획에 가는 것을 보여 주고 확인받는다 — 실제로 도는 것을 보여 준다
7. 순수 함수 사전 · 측정 · 관련 시험을 맥과 리눅스에서 — 두 환경에서 같은 결과인지 본다

## Risks / Open Questions

- 글 길이와 파일 시각 둘 다로 "다룬 계획"을 가린다 — 길이가 그대로이고 턴 시작과 같은 초에 고쳐진 문서만 옛 셸에서 놓칠 수 있다(추정). 진행 기록은 줄을 더하므로 길이가 항상 달라진다.
- 턴이 옛 판으로 시작된 경우(길이 목록 없음)에는 파일 시각으로만 가린다.
- 턴 도중에 세션이 죽으면 들고 있던 답은 다음 턴이 시작될 때 턴 기록으로 내려간다 — 계획에는 안 남는다.
- 한 턴에 계획 둘을 다루면 답은 가장 최근에 고친 쪽 하나에만 적힌다.
