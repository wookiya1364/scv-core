# Test Plan — 선택 기록: 그 턴이 다룬 계획에만, 글자 경계에서 자르기

## Overview

선택 창 답이 이번 턴이 다룬 계획에만 적히는지, 다룬 계획이 없을 때 답이 사라지지 않고 들려 있다가 맞는 곳에 내려가는지, 그리고 적는 글이 언어 설정과 상관없이 글자 경계에서 잘리는지를 본다.

모든 시나리오는 임시 폴더의 시험용 프로젝트에서 턴 검사 스크립트를 직접 불러 본다. 시험용 프로젝트에는 진행 중 계획 `p1` 이 있다.

## Test scenarios

### T1. 다루지 않은 진행 중 계획에는 적지 않는다 (재현)

- **Setup**: 진행 중 계획 `p1`. 새 턴을 시작하고 `p1` 은 건드리지 않는다. `p1` 문서의 고친 시각은 턴 시작보다 앞이다.
- **Run**: 선택 답 하나를 보낸다.
- **Expected**: `p1` 의 문서가 바이트까지 그대로다. 답은 턴 상태에 들려 있다.
- **Pass criterion**: 문서의 전후 비교가 같음, 들고 있는 답 1줄. (고치기 전에는 `p1` 에 적혀 실패한다)

### T2. 이번 턴에 다룬 계획에는 바로 적는다

- **Setup**: 새 턴을 시작한 뒤 `p1` 에 진행 기록을 남긴다.
- **Run**: 선택 답 둘을 차례로 보낸다.
- **Expected**: `p1` 의 변경 이력에 두 답이 보낸 순서대로 있다.
- **Pass criterion**: 선택 줄 2개, 첫 줄이 첫 답.

### T3. 들고 있던 답은 같은 턴에 다룬 계획이 생기면 그 계획에 간다

- **Setup**: 새 턴. 다룬 계획 없이 선택 답 둘을 보낸다. 그 뒤 같은 턴에 새 계획 `p2`(상태 planned)를 만든다.
- **Run**: (a) 선택 답을 하나 더 보낸다. (b) 다른 실행에서는 답을 더 보내지 않고 턴을 끝낸다.
- **Expected**: (a) `p2` 에 세 답이 순서대로 있다. (b) `p2` 에 두 답이 순서대로 있다. 두 경우 모두 `p1` 은 그대로이고 들고 있는 답은 0줄이다.
- **Pass criterion**: `p2` 의 선택 줄 수 3 / 2, 순서 맞음, `p1` 전후 같음.

### T4. 끝까지 다룬 계획이 없으면 턴 기록에 남는다

- **Setup**: 새 턴. 다룬 계획 없이 선택 답 둘.
- **Run**: 턴을 끝낸다.
- **Expected**: 어느 계획 문서도 바뀌지 않는다. 턴 기록에 질문과 답이 든 줄이 둘 있다. 들고 있는 답은 0줄.
- **Pass criterion**: 계획 문서 전후 같음, 턴 기록의 선택 줄 2개.

### T5. 앞 턴의 답은 다음 턴의 계획에 섞이지 않는다

- **Setup**: 새 턴. 다룬 계획 없이 선택 답 하나. 턴 끝 처리를 돌리지 않고(죽은 턴) 다음 턴을 새로 시작한다.
- **Run**: 다음 턴에서 `p1` 에 진행 기록을 남기고 선택 답 하나를 보낸다.
- **Expected**: `p1` 에는 다음 턴의 답만 있다. 앞 턴의 답은 턴 기록에 있다.
- **Pass criterion**: `p1` 선택 줄 1개(다음 턴의 답), 턴 기록에 앞 턴 답 1줄.

### T6. 여러 계획을 다뤘으면 가장 최근에 고친 하나에 적는다

- **Setup**: 새 턴에서 `p1`, 그다음 `p2` 순서로 문서를 고친다(시각을 직접 정해 준다).
- **Run**: 선택 답 둘.
- **Expected**: 두 답 모두 `p2` 에 있고 `p1` 에는 없다.
- **Pass criterion**: `p2` 선택 줄 2개, `p1` 선택 줄 0개.

### T7. 글자 경계에서 자른다 — 언어 설정이 없어도 (재현)

- **Setup**: 한글 130자로 된 질문과 한글 130자로 된 답.
- **Run**: 언어 설정이 없는 환경(`LC_ALL=C`)과 UTF-8 환경에서 이력 항목을 만든다.
- **Expected**: 두 환경 모두 질문과 답이 "한글 120자 + …" 이고, 기대한 글과 바이트까지 같다.
- **Pass criterion**: 두 환경의 출력이 기대 글과 같음. (고치기 전에는 `LC_ALL=C` 에서 글자가 반으로 잘려 실패한다)

### T8. 자르기의 경계 값

- **Setup**: (a) 딱 120자인 글, (b) 119자인 글, (c) 영문 · 한글 · 4바이트 글자(그림 글자)가 섞인 121자, (d) 줄바꿈이 든 글, (e) 빈 글.
- **Run**: 이력 항목을 만든다(두 환경).
- **Expected**: (a)(b) 는 그대로이고 … 가 없다. (c) 는 120자 + … 이고 마지막 글자가 온전하다. (d) 는 줄바꿈이 빈칸으로 바뀐다. (e) 는 빈 글 그대로다.
- **Pass criterion**: 다섯 경우 모두 기대 글과 같음, 두 환경 결과 같음.

### T9. 턴이 시작되지 않았으면 턴 기록에 남긴다

- **Setup**: 턴 상태가 없는 프로젝트(턴 시작 표시 없음), 진행 중 계획 `p1`.
- **Run**: 선택 답 하나.
- **Expected**: `p1` 문서는 그대로이고 턴 기록에 한 줄이 남는다.
- **Pass criterion**: 문서 전후 같음, 턴 기록 선택 줄 1개.

### T10. 속도와 기존 동작

- **Setup**: 새 턴에서 `p1` 을 다룬 상태.
- **Run**: 선택 답 17개를 연달아 보내고, 훅 입력(JSON) 하나를 훅으로 보낸다. 선택 답이 없는 턴의 턴 끝 처리 시간도 기존 시험으로 잰다.
- **Expected**: 18줄이 순서대로 적히고 17개에 2초 안. 빠른 끝 시험이 그대로 통과한다.
- **Pass criterion**: 줄 수 18, 시간 < 2000ms, `core/tests/test-turn-check-fast-end.sh` 통과.

### T11. 맥과 리눅스, 문서와 지문

- **Setup**: 맥(bash 3.2 · BSD 도구)과 리눅스(GNU 도구).
- **Run**: 이 시험들, 호스트 이름 시험, 순수 함수 사전 검사, 템플릿 지문 검사.
- **Expected**: 두 곳 모두 통과.
- **Pass criterion**: 종료 코드 0.

### T12. 실제 선택 창으로 확인

- **Setup**: 바뀐 파일을 이 세션의 설치본에 얹는다. 진행 중이지만 이 턴이 다루지 않은 계획이 하나 있다.
- **Run**: 이 계획을 다루는 턴에서 실제 선택 창에 답한다.
- **Expected**: 다루지 않은 계획의 문서는 바뀌지 않고, 이 계획의 변경 이력에 그 답이 깨진 글자 없이 적힌다.
- **Pass criterion**: 두 문서의 실제 상태를 사용자에게 보여 주고 확인받았다는 기록이 변경 이력에 있다.

## How to run

```bash
bash core/tests/test-turn-plan-check.sh
```

## Pass criteria

- T1–T11 이 맥과 리눅스에서 통과한다.
- T12 의 사용자 확인이 변경 이력에 있다.
