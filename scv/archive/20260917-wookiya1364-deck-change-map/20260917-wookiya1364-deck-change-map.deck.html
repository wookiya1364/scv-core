# 계획서가 바뀔 함수를 먼저 말하고, 문서가 그것을 그림으로 보여준다

## Summary

계획서를 읽는 사람이 "이번에 어떤 함수가 새로 생기고, 어떤 게 바뀌고, 무엇이 사라지는지" 를
표가 아니라 그림으로 한눈에 보게 한다. 화면 설계의 각 컴포넌트에는 그것을 움직이는 함수가
붙어 있어서, 화면을 보면 동작이 예측된다. Graft 가 설치돼 있으면 그 선언을 실제 코드와
대조해 어긋난 곳을 표시한다.

## Goals / Non-Goals

- **Goals**
  - 파이프라인 단계마다 상태를 선언한다 — 추가 · 변경 · 삭제 · 재사용.
  - 그 파이프라인을 머메이드 그림으로 그리고, 상태를 색으로 구분한다.
  - 화면 설계의 번호 붙은 컴포넌트가 어떤 함수로 동작하는지, 그 함수가 새 것인지까지 보여준다.
  - Graft 가 있으면 선언과 실제 코드를 대조해 어긋난 곳을 표시하고, 관련 호출 후보를 덧붙인다.
  - Graft 가 없으면 설치 명령을 그 자리에서 알려주고, 선언만으로 전부 그린다.

- **Non-Goals**
  - Graft 를 자동으로 설치하지 않는다. 권하고, 실행은 사람이 한다.
  - 계획 폴더 없이 아무 마크다운으로 만든 문서에는 이 기능을 붙이지 않는다.
  - 파이프라인 절을 대신 써주지 않는다. 사람이 선언하고, 도구는 대조하고 그린다.
  - 삭제될 함수를 추측하지 않는다. 계획서에 없으면 그 칸은 비운다.

## Approach Overview

세 역할을 나눈다.

- **계획서가 선언한다.** 파이프라인 표에 상태 칸을 더한다. 이것이 의도이고, 사람이 쓴다.
- **Graft 가 대조한다.** 선언한 함수가 코드에 이미 있는지, 누가 부르는지를 확인한다. 선택 사항이다.
- **문서가 그린다.** 선언과 대조 결과를 합쳐 파이프라인 그림 한 장과 변경 표 하나를 만든다.

대조는 판정이 아니라 표시다. Graft 가 "이미 있다" 고 해도 계획서의 선언을 고치지 않는다.
어긋났다는 사실만 드러내고, 판단은 읽는 사람이 한다.

화면 설계에는 이미 컴포넌트를 파이프라인 단계에 잇는 자리가 있다. 거기에 상태를 얹으면
화면과 함수와 변경이 하나의 사슬로 읽힌다.

  reconcileWithEvidence,  // 선언된 단계들 + 코드 근거 → 대조된 단계들
  buildPipelineDiagram,   // 대조된 단계들 → 머메이드 글
  buildChangeTable,       // 대조된 단계들 → 표 행들

## Guardrails

- Graft 가 없거나, 느리거나, 예상과 다른 모양을 돌려줘도 문서 생성은 끝까지 간다. 실패는 빈 값으로 흡수한다.
- Graft 어댑터의 기존 원칙을 그대로 지킨다 — 설치·초기화·빌드·훅·MCP 를 부르지 않는다. 사용자의 그래프 상태를 바꾸지 않는다.
- 계획 폴더가 아닌 문서에는 이 절을 아예 만들지 않는다. 빈 표를 내보내지 않는다.
- 계획서에 삭제가 적혀 있지 않으면 삭제 칸은 비운다. 코드에서 추측해 채우지 않는다.
- 머메이드 정적화(오프라인 SVG 심기)를 건드리지 않는다. 새 그림도 같은 경로로 정적화된다.
- 파이프라인 절이 없는 옛 계획서는 지금처럼 경고만 뜨고 문서는 만들어진다.

## Exit criteria

- TESTS.md 의 모든 항목이 통과한다.
- Graft 가 설치된 자바스크립트 계열 저장소에서 한 번 실제로 돌려, 대조 표시가 실제 코드와 맞는 것을 확인한다.
- 이 저장소에서는 견본 응답으로 검사가 통과한다 (Graft 가 셸 스크립트를 지원하지 않는다).
- 전체 계약 검사가 통과한다.
- 부하를 건 상태에서도 시간 예산을 쓰는 검사들이 통과한다 (흔들림 제거).

## Suggested path

1. 파이프라인 절 파서를 쓴다 — 표에서 단계 이름·입출력·순수여부·상태를 읽어낸다.
2. 상태 칸이 없는 옛 서식도 읽히게 한다. 상태가 없으면 "미지정" 으로 둔다.
3. 대조 함수를 쓴다 — 선언과 근거를 받아 일치·불일치·근거없음 셋 중 하나를 붙인다.
4. 파이프라인 그림 생성기를 쓴다. 상태별 색과 모양을 정하고, 삭제는 점선으로 둔다.
5. 화면 설계의 단계 태그에 상태를 얹는다.
6. 문서 생성 경로에 Graft 를 선택 입구로 붙인다. 없으면 설치 명령 한 줄을 안내한다.
7. 견본 응답으로 검사를 채운다.

# Test Plan — 계획서가 바뀔 함수를 먼저 말하고, 문서가 그것을 그림으로 보여준다

## Overview

두 가지를 확인한다. 첫째, 선언한 상태가 그림과 표로 정확히 나오는가. 둘째, Graft 가 없거나
이상하게 굴어도 문서 생성이 끝까지 가는가. 순수한 단계는 문자열만 넣고 문자열만 확인하고,
Graft 는 견본 응답으로 세운다.

## Test scenarios

### T1. 파이프라인 표에서 단계와 상태를 읽어낸다

- **Setup**: 상태 칸이 있는 파이프라인 표를 담은 계획서 견본을 만든다. 단계 넷을 각각 추가·변경·삭제·재사용으로 적는다.
- **Run**: 파서를 그 본문에 대고 돌린다.
- **Expected**: 단계 넷이 순서대로 나오고, 각 단계의 이름·받는 값·돌려주는 값·순수여부·상태가 적은 그대로 나온다.
- **Pass criterion**: 네 단계 모두 다섯 항목이 일치한다.

### T2. 상태 칸이 없는 옛 계획서도 읽힌다

- **Setup**: 상태 칸이 없는 기존 서식의 파이프라인 표를 담은 견본을 만든다.
- **Run**: 같은 파서를 돌린다.
- **Expected**: 단계는 전부 읽히고, 상태는 "미지정" 으로 채워진다. 오류가 나지 않는다.
- **Pass criterion**: 단계 개수가 맞고, 모든 상태가 미지정이다.

### T3. 파이프라인 절이 아예 없어도 문서가 만들어진다

- **Setup**: 파이프라인 절이 없는 계획 폴더를 만든다.
- **Run**: 문서를 만든다.
- **Expected**: 지금과 같은 경고가 뜨고, 문서 파일은 정상으로 만들어진다. 변경 표와 파이프라인 그림 절은 나타나지 않는다.
- **Pass criterion**: 종료 코드가 0 이고, 결과 파일이 존재하며, 빈 표가 들어 있지 않다.

### T4. 상태가 그림에 색으로 구분된다

- **Setup**: T1 의 견본을 쓴다.
- **Run**: 그림 생성기를 돌린다.
- **Expected**: 머메이드 글이 나오고, 추가·변경·삭제가 서로 다른 클래스로 표시된다. 삭제 단계로 가는 선은 점선이다. 재사용 단계에는 아무 클래스도 붙지 않는다.
- **Pass criterion**: 세 클래스 정의가 모두 있고, 각 단계가 자기 상태의 클래스를 달고 있다.

### T5. 만들어진 그림이 실제로 SVG 로 그려진다

- **Setup**: T4 가 만든 머메이드 글을 문서에 넣는다.
- **Run**: 문서를 만들고 정적화 단계를 돌린다.
- **Expected**: 인라인 SVG 가 심기고, 외부 로더가 제거된다.
- **Pass criterion**: 결과 파일에 SVG 가 있고 로더 표시가 없다.

### T6. Graft 가 없으면 선언만으로 전부 그려지고, 설치 명령이 안내된다

- **Setup**: Graft 실행 파일이 없는 상태로 둔다.
- **Run**: 계획 폴더로 문서를 만든다.
- **Expected**: 파이프라인 그림과 변경 표가 선언한 대로 나온다. 대조 표시만 빠진다. 터미널 출력에 설치 명령 한 줄이 나온다.
- **Pass criterion**: 종료 코드가 0 이고, 그림과 표가 있고, 대조 열이 전부 "근거없음" 이며, 출력에 설치 명령이 들어 있다.

### T7. Graft 응답이 깨졌거나 느려도 문서 생성이 끝까지 간다

- **Setup**: 깨진 응답을 돌려주는 가짜 Graft 와, 시간 제한을 넘기는 가짜 Graft 를 각각 세운다.
- **Run**: 두 경우 모두 문서를 만든다.
- **Expected**: 두 경우 모두 T6 과 같은 결과가 나온다. 예외로 끝나지 않는다.
- **Pass criterion**: 두 경우 모두 종료 코드가 0 이고 결과 파일이 만들어진다.

### T8. 선언과 코드가 어긋나면 표시된다

- **Setup**: "추가" 라고 선언한 단계가 코드에 이미 있다고 답하는 견본 응답을 세운다.
- **Run**: 대조 함수를 돌린다.
- **Expected**: 그 단계에 어긋남 표시가 붙는다. 계획서의 선언 자체는 바뀌지 않는다.
- **Pass criterion**: 대조 결과가 불일치이고, 원래 상태 값이 "추가" 그대로다.

### T9. 삭제가 적혀 있지 않으면 칸을 비운다

- **Setup**: 삭제 단계가 하나도 없는 계획서 견본을 쓴다.
- **Run**: 변경 표 생성기를 돌린다.
- **Expected**: 삭제 행이 하나도 없다. "삭제 없음" 같은 문구를 지어내지 않는다.
- **Pass criterion**: 표에 삭제 상태의 행이 0 개다.

### T10. 화면의 컴포넌트가 어떤 함수로 동작하는지, 그 함수가 새 것인지 보인다

- **Setup**: 번호 붙은 컴포넌트가 파이프라인 단계를 가리키는 화면 설계 견본을 만든다. 그 단계는 "추가" 로 선언한다.
- **Run**: 문서를 만든다.
- **Expected**: 컴포넌트 옆에 단계 이름 태그가 그려지고, 그 태그에 추가 상태가 함께 표시된다.
- **Pass criterion**: 결과 파일에서 해당 컴포넌트 항목이 단계 이름과 상태를 모두 담고 있다.

### T11. 계획 폴더가 아닌 문서에는 붙지 않는다

- **Setup**: 파이프라인 표처럼 생긴 표를 담은 평범한 마크다운 파일 하나를 만든다.
- **Run**: 그 파일 하나로 문서를 만든다.
- **Expected**: 변경 표와 파이프라인 그림이 나타나지 않는다. 문서는 정상으로 만들어진다.
- **Pass criterion**: 종료 코드가 0 이고, 결과 파일에 변경 표 절이 없다.

### T12. 순수한 단계는 파일을 만지지 않는다

- **Setup**: 순수성 검사가 보는 표시를 각 순수 단계에 붙인다.
- **Run**: 기존 순수성 검사를 돌린다.
- **Expected**: 2·3·5·6·7 번 단계가 순수로 통과한다.
- **Pass criterion**: 순수성 검사가 통과한다.

### T13. 기존 문서 기능이 그대로다

- **Setup**: 없음.
- **Run**: 기존 문서 검사 네 가지와 전체 계약 검사를 돌린다.
- **Expected**: 전부 통과한다.

# 계획서가 바뀔 함수를 먼저 말하고, 문서가 그것을 그림으로 보여준다

## Summary

계획서를 읽는 사람이 "이번에 어떤 함수가 새로 생기고, 어떤 게 바뀌고, 무엇이 사라지는지" 를
표가 아니라 그림으로 한눈에 보게 한다. 화면 설계의 각 컴포넌트에는 그것을 움직이는 함수가
붙어 있어서, 화면을 보면 동작이 예측된다. Graft 가 설치돼 있으면 그 선언을 실제 코드와
대조해 어긋난 곳을 표시한다.

## Goals / Non-Goals

- **Goals**
  - 파이프라인 단계마다 상태를 선언한다 — 추가 · 변경 · 삭제 · 재사용.
  - 그 파이프라인을 머메이드 그림으로 그리고, 상태를 색으로 구분한다.
  - 화면 설계의 번호 붙은 컴포넌트가 어떤 함수로 동작하는지, 그 함수가 새 것인지까지 보여준다.
  - Graft 가 있으면 선언과 실제 코드를 대조해 어긋난 곳을 표시하고, 관련 호출 후보를 덧붙인다.
  - Graft 가 없으면 설치 명령을 그 자리에서 알려주고, 선언만으로 전부 그린다.

- **Non-Goals**
  - Graft 를 자동으로 설치하지 않는다. 권하고, 실행은 사람이 한다.
  - 계획 폴더 없이 아무 마크다운으로 만든 문서에는 이 기능을 붙이지 않는다.
  - 파이프라인 절을 대신 써주지 않는다. 사람이 선언하고, 도구는 대조하고 그린다.
  - 삭제될 함수를 추측하지 않는다. 계획서에 없으면 그 칸은 비운다.

## Approach Overview

세 역할을 나눈다.

- **계획서가 선언한다.** 파이프라인 표에 상태 칸을 더한다. 이것이 의도이고, 사람이 쓴다.
- **Graft 가 대조한다.** 선언한 함수가 코드에 이미 있는지, 누가 부르는지를 확인한다. 선택 사항이다.
- **문서가 그린다.** 선언과 대조 결과를 합쳐 파이프라인 그림 한 장과 변경 표 하나를 만든다.

대조는 판정이 아니라 표시다. Graft 가 "이미 있다" 고 해도 계획서의 선언을 고치지 않는다.
어긋났다는 사실만 드러내고, 판단은 읽는 사람이 한다.

화면 설계에는 이미 컴포넌트를 파이프라인 단계에 잇는 자리가 있다. 거기에 상태를 얹으면
화면과 함수와 변경이 하나의 사슬로 읽힌다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

  parseScreenSteps,       // 화면 설계 본문 → 번호-단계 연결
  reconcileWithEvidence,  // 선언된 단계들 + 코드 근거 → 대조된 단계들
  buildPipelineDiagram,   // 대조된 단계들 → 머메이드 글
  buildChangeTable,       // 대조된 단계들 → 표 행들
)
```

## 성공지표 (Metrics)

| 지표 | 지금 | 목표 |
|---|---|---|
| 계획서를 읽고 "무엇이 새로 생기는지" 를 찾는 데 필요한 절 | 본문을 읽어야 안다 (표 없음) | 그림 한 장 + 표 한 개 |
| 파이프라인 단계 중 상태가 적힌 비율 | 0% (상태 칸이 없다) | 새로 쓰는 계획서 100% |
| 화면 컴포넌트 중 동작 함수가 연결된 비율 | 단계 이름만, 상태 없음 | 이름 + 상태 둘 다 |
| Graft 가 없을 때 문서 생성 실패율 | 해당 없음 (기능 없음) | 0% |

## 예외처리 (Edge cases)

| 상황 | 어떻게 되는가 |
|---|---|
| 파이프라인 절이 아예 없다 | 지금처럼 경고만 뜨고 문서는 만들어진다. 변경 지도 절이 나타나지 않는다. |
| 상태 칸이 없는 옛 서식이다 | 단계는 다 읽히고 상태는 미지정이 된다. |
| 표의 칸 수가 서식과 다르다 | 그 행만 건너뛰고 나머지는 읽는다. 건너뛴 행 수를 한 줄로 알린다. |
| 단계 이름이 비어 있다 | 그 행을 버린다. 번호 없는 그림 조각을 만들지 않는다. |
| Graft 가 없다 | 대조 열이 전부 근거없음. 설치 명령 한 줄 안내. |
| Graft 가 시간 제한을 넘긴다 | 빈 값으로 흡수하고 계속 간다. 기존 어댑터의 시간 제한을 그대로 쓴다. |
| Graft 응답이 깨진 JSON 이다 | 빈 값으로 흡수한다. |
| Graft 가 모르는 모양을 돌려준다 | 기존 어댑터처럼 물음표 요약으로 떨어지고, 대조는 근거없음이 된다. |
| 단계가 아주 많다 | 그림이 넘치지 않도록 상위 몇 개만 그리고, 나머지는 표에만 남긴다. 몇 개까지인지는 실물을 보고 정한다. |
| 삭제가 적혀 있지 않다 | 삭제 행을 만들지 않는다. 문구를 지어내지 않는다. |
| 계획 폴더가 아닌 문서다 | 변경 지도 절 자체를 만들지 않는다. |

## Guardrails

- Graft 가 없거나, 느리거나, 예상과 다른 모양을 돌려줘도 문서 생성은 끝까지 간다. 실패는 빈 값으로 흡수한다.
- Graft 어댑터의 기존 원칙을 그대로 지킨다 — 설치·초기화·빌드·훅·MCP 를 부르지 않는다. 사용자의 그래프 상태를 바꾸지 않는다.
- 계획 폴더가 아닌 문서에는 이 절을 아예 만들지 않는다. 빈 표를 내보내지 않는다.
- 계획서에 삭제가 적혀 있지 않으면 삭제 칸은 비운다. 코드에서 추측해 채우지 않는다.
- 머메이드 정적화(오프라인 SVG 심기)를 건드리지 않는다. 새 그림도 같은 경로로 정적화된다.
- 파이프라인 절이 없는 옛 계획서는 지금처럼 경고만 뜨고 문서는 만들어진다.

## Exit criteria

- TESTS.md 의 모든 항목이 통과한다.
- Graft 가 설치된 자바스크립트 계열 저장소에서 한 번 실제로 돌려, 대조 표시가 실제 코드와 맞는 것을 확인한다.
- 이 저장소에서는 견본 응답으로 검사가 통과한다 (Graft 가 셸 스크립트를 지원하지 않는다).
- 전체 계약 검사가 통과한다.
- 부하를 건 상태에서도 시간 예산을 쓰는 검사들이 통과한다 (흔들림 제거).

## Suggested path

1. 파이프라인 절 파서를 쓴다 — 표에서 단계 이름·입출력·순수여부·상태를 읽어낸다.
2. 상태 칸이 없는 옛 서식도 읽히게 한다. 상태가 없으면 "미지정" 으로 둔다.
3. 대조 함수를 쓴다 — 선언과 근거를 받아 일치·불일치·근거없음 셋 중 하나를 붙인다.
4. 파이프라인 그림 생성기를 쓴다. 상태별 색과 모양을 정하고, 삭제는 점선으로 둔다.
5. 화면 설계의 단계 태그에 상태를 얹는다.
6. 문서 생성 경로에 Graft 를 선택 입구로 붙인다. 없으면 설치 명령 한 줄을 안내한다.
7. 견본 응답으로 검사를 채운다.

# Test Plan — 계획서가 바뀔 함수를 먼저 말하고, 문서가 그것을 그림으로 보여준다

## Overview

두 가지를 확인한다. 첫째, 선언한 상태가 그림과 표로 정확히 나오는가. 둘째, Graft 가 없거나
이상하게 굴어도 문서 생성이 끝까지 가는가. 순수한 단계는 문자열만 넣고 문자열만 확인하고,
Graft 는 견본 응답으로 세운다.

## Test scenarios

### T1. 파이프라인 표에서 단계와 상태를 읽어낸다

- **Setup**: 상태 칸이 있는 파이프라인 표를 담은 계획서 견본을 만든다. 단계 넷을 각각 추가·변경·삭제·재사용으로 적는다.
- **Run**: 파서를 그 본문에 대고 돌린다.
- **Expected**: 단계 넷이 순서대로 나오고, 각 단계의 이름·받는 값·돌려주는 값·순수여부·상태가 적은 그대로 나온다.
- **Pass criterion**: 네 단계 모두 다섯 항목이 일치한다.

### T2. 상태 칸이 없는 옛 계획서도 읽힌다

- **Setup**: 상태 칸이 없는 기존 서식의 파이프라인 표를 담은 견본을 만든다.
- **Run**: 같은 파서를 돌린다.
- **Expected**: 단계는 전부 읽히고, 상태는 "미지정" 으로 채워진다. 오류가 나지 않는다.
- **Pass criterion**: 단계 개수가 맞고, 모든 상태가 미지정이다.

### T3. 파이프라인 절이 아예 없어도 문서가 만들어진다

- **Setup**: 파이프라인 절이 없는 계획 폴더를 만든다.
- **Run**: 문서를 만든다.
- **Expected**: 지금과 같은 경고가 뜨고, 문서 파일은 정상으로 만들어진다. 변경 표와 파이프라인 그림 절은 나타나지 않는다.
- **Pass criterion**: 종료 코드가 0 이고, 결과 파일이 존재하며, 빈 표가 들어 있지 않다.

### T4. 상태가 그림에 색으로 구분된다

- **Setup**: T1 의 견본을 쓴다.
- **Run**: 그림 생성기를 돌린다.
- **Expected**: 머메이드 글이 나오고, 추가·변경·삭제가 서로 다른 클래스로 표시된다. 삭제 단계로 가는 선은 점선이다. 재사용 단계에는 아무 클래스도 붙지 않는다.
- **Pass criterion**: 세 클래스 정의가 모두 있고, 각 단계가 자기 상태의 클래스를 달고 있다.

### T5. 만들어진 그림이 실제로 SVG 로 그려진다

- **Setup**: T4 가 만든 머메이드 글을 문서에 넣는다.
- **Run**: 문서를 만들고 정적화 단계를 돌린다.
- **Expected**: 인라인 SVG 가 심기고, 외부 로더가 제거된다.
- **Pass criterion**: 결과 파일에 SVG 가 있고 로더 표시가 없다.

### T6. Graft 가 없으면 선언만으로 전부 그려지고, 설치 명령이 안내된다

- **Setup**: Graft 실행 파일이 없는 상태로 둔다.
- **Run**: 계획 폴더로 문서를 만든다.
- **Expected**: 파이프라인 그림과 변경 표가 선언한 대로 나온다. 대조 표시만 빠진다. 터미널 출력에 설치 명령 한 줄이 나온다.
- **Pass criterion**: 종료 코드가 0 이고, 그림과 표가 있고, 대조 열이 전부 "근거없음" 이며, 출력에 설치 명령이 들어 있다.

### T7. Graft 응답이 깨졌거나 느려도 문서 생성이 끝까지 간다

- **Setup**: 깨진 응답을 돌려주는 가짜 Graft 와, 시간 제한을 넘기는 가짜 Graft 를 각각 세운다.
- **Run**: 두 경우 모두 문서를 만든다.
- **Expected**: 두 경우 모두 T6 과 같은 결과가 나온다. 예외로 끝나지 않는다.
- **Pass criterion**: 두 경우 모두 종료 코드가 0 이고 결과 파일이 만들어진다.

### T8. 선언과 코드가 어긋나면 표시된다

- **Setup**: "추가" 라고 선언한 단계가 코드에 이미 있다고 답하는 견본 응답을 세운다.
- **Run**: 대조 함수를 돌린다.
- **Expected**: 그 단계에 어긋남 표시가 붙는다. 계획서의 선언 자체는 바뀌지 않는다.
- **Pass criterion**: 대조 결과가 불일치이고, 원래 상태 값이 "추가" 그대로다.

### T9. 삭제가 적혀 있지 않으면 칸을 비운다

- **Setup**: 삭제 단계가 하나도 없는 계획서 견본을 쓴다.
- **Run**: 변경 표 생성기를 돌린다.
- **Expected**: 삭제 행이 하나도 없다. "삭제 없음" 같은 문구를 지어내지 않는다.
- **Pass criterion**: 표에 삭제 상태의 행이 0 개다.

### T10. 화면의 컴포넌트가 어떤 함수로 동작하는지, 그 함수가 새 것인지 보인다

- **Setup**: 번호 붙은 컴포넌트가 파이프라인 단계를 가리키는 화면 설계 견본을 만든다. 그 단계는 "추가" 로 선언한다.
- **Run**: 문서를 만든다.
- **Expected**: 컴포넌트 옆에 단계 이름 태그가 그려지고, 그 태그에 추가 상태가 함께 표시된다.
- **Pass criterion**: 결과 파일에서 해당 컴포넌트 항목이 단계 이름과 상태를 모두 담고 있다.

### T11. 계획 폴더가 아닌 문서에는 붙지 않는다

- **Setup**: 파이프라인 표처럼 생긴 표를 담은 평범한 마크다운 파일 하나를 만든다.
- **Run**: 그 파일 하나로 문서를 만든다.
- **Expected**: 변경 표와 파이프라인 그림이 나타나지 않는다. 문서는 정상으로 만들어진다.
- **Pass criterion**: 종료 코드가 0 이고, 결과 파일에 변경 표 절이 없다.

### T12. 순수한 단계는 파일을 만지지 않는다

- **Setup**: 순수성 검사가 보는 표시를 각 순수 단계에 붙인다.
- **Run**: 기존 순수성 검사를 돌린다.
- **Expected**: 2·3·5·6·7 번 단계가 순수로 통과한다.
- **Pass criterion**: 순수성 검사가 통과한다.

### T13. 기존 문서 기능이 그대로다

- **Setup**: 없음.
- **Run**: 기존 문서 검사 네 가지와 전체 계약 검사를 돌린다.
- **Expected**: 전부 통과한다.
- **Pass criterion**: 실패 0 건.

### T14. 시간 예산이 부하에 맞춰 늘어난다

- **Setup**: 없음.
- **Run**: 시간 예산 검사를 돌린다.
- **Expected**: 기준보다 빠른 셸에서는 예산이 그대로, 굼뜬 셸에서는 늘어나되 상한을 넘지 않는다. 같은 실행 안에서 답이 흔들리지 않는다.
- **Pass criterion**: 18건 전부 통과.

### T15. 부하를 걸어도 검사들이 통과한다

- **Setup**: 바쁜 프로세스를 여럿 띄운다.
- **Run**: 시간 예산을 쓰는 검사 셋과 이 계획의 검사를 돌린다.
- **Expected**: 전부 통과한다. 고치기 전이라면 무너졌을 조건이다.
- **Pass criterion**: 실패 0건.
