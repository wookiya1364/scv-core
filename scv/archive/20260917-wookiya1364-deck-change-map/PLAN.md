# 계획서가 바뀔 함수를 먼저 말하고, 문서가 그것을 그림으로 보여준다

## Summary

계획서를 읽는 사람이 "이번에 어떤 함수가 새로 생기고, 어떤 게 바뀌고, 무엇이 사라지는지" 를
표가 아니라 그림으로 한눈에 보게 한다. 화면 설계의 각 컴포넌트에는 그것을 움직이는 함수가
붙어 있어서, 화면을 보면 동작이 예측된다. Graft 가 설치돼 있으면 그 선언을 실제 코드와
대조해 어긋난 곳을 표시한다.

## Goals / Non-Goals

- **Goals**
  - 파이프라인 단계마다 상태를 선언한다 — 추가 · 변경 · 삭제 · 재사용.
  - 그 파이프라인을 머메이드 그림으로 그리고, 상태를 색으로 구분한다.
  - 화면 설계의 번호 붙은 컴포넌트가 어떤 함수로 동작하는지, 그 함수가 새 것인지까지 보여준다.
  - Graft 가 있으면 선언과 실제 코드를 대조해 어긋난 곳을 표시하고, 관련 호출 후보를 덧붙인다.
  - Graft 가 없으면 설치 명령을 그 자리에서 알려주고, 선언만으로 전부 그린다.

- **Non-Goals**
  - Graft 를 자동으로 설치하지 않는다. 권하고, 실행은 사람이 한다.
  - 계획 폴더 없이 아무 마크다운으로 만든 문서에는 이 기능을 붙이지 않는다.
  - 파이프라인 절을 대신 써주지 않는다. 사람이 선언하고, 도구는 대조하고 그린다.
  - 삭제될 함수를 추측하지 않는다. 계획서에 없으면 그 칸은 비운다.

## Approach Overview

세 역할을 나눈다.

- **계획서가 선언한다.** 파이프라인 표에 상태 칸을 더한다. 이것이 의도이고, 사람이 쓴다.
- **Graft 가 대조한다.** 선언한 함수가 코드에 이미 있는지, 누가 부르는지를 확인한다. 선택 사항이다.
- **문서가 그린다.** 선언과 대조 결과를 합쳐 파이프라인 그림 한 장과 변경 표 하나를 만든다.

대조는 판정이 아니라 표시다. Graft 가 "이미 있다" 고 해도 계획서의 선언을 고치지 않는다.
어긋났다는 사실만 드러내고, 판단은 읽는 사람이 한다.

화면 설계에는 이미 컴포넌트를 파이프라인 단계에 잇는 자리가 있다. 거기에 상태를 얹으면
화면과 함수와 변경이 하나의 사슬로 읽힌다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  parsePipelineSection,   // 계획서 본문 → 선언된 단계들
  parseScreenSteps,       // 화면 설계 본문 → 번호-단계 연결
  reconcileWithEvidence,  // 선언된 단계들 + 코드 근거 → 대조된 단계들
  buildPipelineDiagram,   // 대조된 단계들 → 머메이드 글
  buildChangeTable,       // 대조된 단계들 → 표 행들
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 | 상태 |
|---|---|---|---|---|
| 1 | `readPlanDocs` | 폴더 경로 → 계획서·화면설계 본문 | 부수효과 (입구) | 재사용 |
| 2 | `parsePipelineSection` | 계획서 본문 → 선언된 단계 목록 | 순수 | 추가 |
| 3 | `parseScreenSteps` | 화면설계 본문 → 번호-단계 연결 목록 | 순수 | 추가 |
| 4 | `collectEvidence` | 단계 이름들 → 코드 근거 (없으면 빈 값) | 부수효과 (입구, Graft) | 추가 |
| 5 | `reconcileWithEvidence` | 선언 + 근거 → 대조된 단계 목록 | 순수 | 추가 |
| 6 | `buildPipelineDiagram` | 대조된 단계 목록 → 머메이드 글 | 순수 | 추가 |
| 7 | `buildChangeTable` | 대조된 단계 목록 → 표 행 목록 | 순수 | 추가 |
| 8 | `renderDeck` | 그림 + 표 → 문서 | 부수효과 (출구) | 변경 |
| 9 | `scv_calibrate_ms` | 없음 → 이 셸의 굼뜬 정도(ms) | 부수효과 (입구, 시각) | 추가 |
| 10 | `scv_budget_ms` | 예산 ms → 이 기계에 맞춘 예산 ms | 순수 | 추가 |

- 부수효과 위치: 1번(파일 읽기), 4번(Graft 실행), 8번(문서 쓰기). 2·3·5·6·7 은 문자열만 받아 문자열만 낸다.
- 재사용: 1번과 8번은 이미 있는 문서 생성 경로를 그대로 쓴다. 4번은 이미 있는 Graft 어댑터를 부른다.
- 4번이 빈 값을 돌려줘도 5번부터는 그대로 돈다 — 대조 표시만 빠진다.

## 성공지표 (Metrics)

| 지표 | 지금 | 목표 |
|---|---|---|
| 계획서를 읽고 "무엇이 새로 생기는지" 를 찾는 데 필요한 절 | 본문을 읽어야 안다 (표 없음) | 그림 한 장 + 표 한 개 |
| 파이프라인 단계 중 상태가 적힌 비율 | 0% (상태 칸이 없다) | 새로 쓰는 계획서 100% |
| 화면 컴포넌트 중 동작 함수가 연결된 비율 | 단계 이름만, 상태 없음 | 이름 + 상태 둘 다 |
| Graft 가 없을 때 문서 생성 실패율 | 해당 없음 (기능 없음) | 0% |

## 예외처리 (Edge cases)

| 상황 | 어떻게 되는가 |
|---|---|
| 파이프라인 절이 아예 없다 | 지금처럼 경고만 뜨고 문서는 만들어진다. 변경 지도 절이 나타나지 않는다. |
| 상태 칸이 없는 옛 서식이다 | 단계는 다 읽히고 상태는 미지정이 된다. |
| 표의 칸 수가 서식과 다르다 | 그 행만 건너뛰고 나머지는 읽는다. 건너뛴 행 수를 한 줄로 알린다. |
| 단계 이름이 비어 있다 | 그 행을 버린다. 번호 없는 그림 조각을 만들지 않는다. |
| Graft 가 없다 | 대조 열이 전부 근거없음. 설치 명령 한 줄 안내. |
| Graft 가 시간 제한을 넘긴다 | 빈 값으로 흡수하고 계속 간다. 기존 어댑터의 시간 제한을 그대로 쓴다. |
| Graft 응답이 깨진 JSON 이다 | 빈 값으로 흡수한다. |
| Graft 가 모르는 모양을 돌려준다 | 기존 어댑터처럼 물음표 요약으로 떨어지고, 대조는 근거없음이 된다. |
| 단계가 아주 많다 | 그림이 넘치지 않도록 상위 몇 개만 그리고, 나머지는 표에만 남긴다. 몇 개까지인지는 실물을 보고 정한다. |
| 삭제가 적혀 있지 않다 | 삭제 행을 만들지 않는다. 문구를 지어내지 않는다. |
| 계획 폴더가 아닌 문서다 | 변경 지도 절 자체를 만들지 않는다. |

## Guardrails

- Graft 가 없거나, 느리거나, 예상과 다른 모양을 돌려줘도 문서 생성은 끝까지 간다. 실패는 빈 값으로 흡수한다.
- Graft 어댑터의 기존 원칙을 그대로 지킨다 — 설치·초기화·빌드·훅·MCP 를 부르지 않는다. 사용자의 그래프 상태를 바꾸지 않는다.
- 계획 폴더가 아닌 문서에는 이 절을 아예 만들지 않는다. 빈 표를 내보내지 않는다.
- 계획서에 삭제가 적혀 있지 않으면 삭제 칸은 비운다. 코드에서 추측해 채우지 않는다.
- 머메이드 정적화(오프라인 SVG 심기)를 건드리지 않는다. 새 그림도 같은 경로로 정적화된다.
- 파이프라인 절이 없는 옛 계획서는 지금처럼 경고만 뜨고 문서는 만들어진다.

## Exit criteria

- TESTS.md 의 모든 항목이 통과한다.
- Graft 가 설치된 자바스크립트 계열 저장소에서 한 번 실제로 돌려, 대조 표시가 실제 코드와 맞는 것을 확인한다.
- 이 저장소에서는 견본 응답으로 검사가 통과한다 (Graft 가 셸 스크립트를 지원하지 않는다).
- 전체 계약 검사가 통과한다.
- 부하를 건 상태에서도 시간 예산을 쓰는 검사들이 통과한다 (흔들림 제거).

## Suggested path

1. 파이프라인 절 파서를 쓴다 — 표에서 단계 이름·입출력·순수여부·상태를 읽어낸다.
2. 상태 칸이 없는 옛 서식도 읽히게 한다. 상태가 없으면 "미지정" 으로 둔다.
3. 대조 함수를 쓴다 — 선언과 근거를 받아 일치·불일치·근거없음 셋 중 하나를 붙인다.
4. 파이프라인 그림 생성기를 쓴다. 상태별 색과 모양을 정하고, 삭제는 점선으로 둔다.
5. 화면 설계의 단계 태그에 상태를 얹는다.
6. 문서 생성 경로에 Graft 를 선택 입구로 붙인다. 없으면 설치 명령 한 줄을 안내한다.
7. 견본 응답으로 검사를 채운다.

## Risks / Open Questions

- Graft 의 응답 모양이 문서화돼 있지 않다. 기존 어댑터가 흔한 두 모양을 추정해 두었고, 이번에도 그 추정 위에 얹는다. 실물 확인 전까지는 추정이다.
- 단계 이름과 실제 함수 이름이 다르면 대조가 헛돈다. 이름이 어긋나면 "근거없음" 으로 떨어지고, 그것이 곧 신호다.
- 그림이 커지면 읽히지 않는다. 단계가 많을 때 어디서 끊을지는 실물을 보고 정한다.
