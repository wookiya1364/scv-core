# Test Plan — 계획서가 바뀔 함수를 먼저 말하고, 문서가 그것을 그림으로 보여준다

## Overview

두 가지를 확인한다. 첫째, 선언한 상태가 그림과 표로 정확히 나오는가. 둘째, Graft 가 없거나
이상하게 굴어도 문서 생성이 끝까지 가는가. 순수한 단계는 문자열만 넣고 문자열만 확인하고,
Graft 는 견본 응답으로 세운다.

## Test scenarios

### T1. 파이프라인 표에서 단계와 상태를 읽어낸다

- **Setup**: 상태 칸이 있는 파이프라인 표를 담은 계획서 견본을 만든다. 단계 넷을 각각 추가·변경·삭제·재사용으로 적는다.
- **Run**: 파서를 그 본문에 대고 돌린다.
- **Expected**: 단계 넷이 순서대로 나오고, 각 단계의 이름·받는 값·돌려주는 값·순수여부·상태가 적은 그대로 나온다.
- **Pass criterion**: 네 단계 모두 다섯 항목이 일치한다.

### T2. 상태 칸이 없는 옛 계획서도 읽힌다

- **Setup**: 상태 칸이 없는 기존 서식의 파이프라인 표를 담은 견본을 만든다.
- **Run**: 같은 파서를 돌린다.
- **Expected**: 단계는 전부 읽히고, 상태는 "미지정" 으로 채워진다. 오류가 나지 않는다.
- **Pass criterion**: 단계 개수가 맞고, 모든 상태가 미지정이다.

### T3. 파이프라인 절이 아예 없어도 문서가 만들어진다

- **Setup**: 파이프라인 절이 없는 계획 폴더를 만든다.
- **Run**: 문서를 만든다.
- **Expected**: 지금과 같은 경고가 뜨고, 문서 파일은 정상으로 만들어진다. 변경 표와 파이프라인 그림 절은 나타나지 않는다.
- **Pass criterion**: 종료 코드가 0 이고, 결과 파일이 존재하며, 빈 표가 들어 있지 않다.

### T4. 상태가 그림에 색으로 구분된다

- **Setup**: T1 의 견본을 쓴다.
- **Run**: 그림 생성기를 돌린다.
- **Expected**: 머메이드 글이 나오고, 추가·변경·삭제가 서로 다른 클래스로 표시된다. 삭제 단계로 가는 선은 점선이다. 재사용 단계에는 아무 클래스도 붙지 않는다.
- **Pass criterion**: 세 클래스 정의가 모두 있고, 각 단계가 자기 상태의 클래스를 달고 있다.

### T5. 만들어진 그림이 실제로 SVG 로 그려진다

- **Setup**: T4 가 만든 머메이드 글을 문서에 넣는다.
- **Run**: 문서를 만들고 정적화 단계를 돌린다.
- **Expected**: 인라인 SVG 가 심기고, 외부 로더가 제거된다.
- **Pass criterion**: 결과 파일에 SVG 가 있고 로더 표시가 없다.

### T6. Graft 가 없으면 선언만으로 전부 그려지고, 설치 명령이 안내된다

- **Setup**: Graft 실행 파일이 없는 상태로 둔다.
- **Run**: 계획 폴더로 문서를 만든다.
- **Expected**: 파이프라인 그림과 변경 표가 선언한 대로 나온다. 대조 표시만 빠진다. 터미널 출력에 설치 명령 한 줄이 나온다.
- **Pass criterion**: 종료 코드가 0 이고, 그림과 표가 있고, 대조 열이 전부 "근거없음" 이며, 출력에 설치 명령이 들어 있다.

### T7. Graft 응답이 깨졌거나 느려도 문서 생성이 끝까지 간다

- **Setup**: 깨진 응답을 돌려주는 가짜 Graft 와, 시간 제한을 넘기는 가짜 Graft 를 각각 세운다.
- **Run**: 두 경우 모두 문서를 만든다.
- **Expected**: 두 경우 모두 T6 과 같은 결과가 나온다. 예외로 끝나지 않는다.
- **Pass criterion**: 두 경우 모두 종료 코드가 0 이고 결과 파일이 만들어진다.

### T8. 선언과 코드가 어긋나면 표시된다

- **Setup**: "추가" 라고 선언한 단계가 코드에 이미 있다고 답하는 견본 응답을 세운다.
- **Run**: 대조 함수를 돌린다.
- **Expected**: 그 단계에 어긋남 표시가 붙는다. 계획서의 선언 자체는 바뀌지 않는다.
- **Pass criterion**: 대조 결과가 불일치이고, 원래 상태 값이 "추가" 그대로다.

### T9. 삭제가 적혀 있지 않으면 칸을 비운다

- **Setup**: 삭제 단계가 하나도 없는 계획서 견본을 쓴다.
- **Run**: 변경 표 생성기를 돌린다.
- **Expected**: 삭제 행이 하나도 없다. "삭제 없음" 같은 문구를 지어내지 않는다.
- **Pass criterion**: 표에 삭제 상태의 행이 0 개다.

### T10. 화면의 컴포넌트가 어떤 함수로 동작하는지, 그 함수가 새 것인지 보인다

- **Setup**: 번호 붙은 컴포넌트가 파이프라인 단계를 가리키는 화면 설계 견본을 만든다. 그 단계는 "추가" 로 선언한다.
- **Run**: 문서를 만든다.
- **Expected**: 컴포넌트 옆에 단계 이름 태그가 그려지고, 그 태그에 추가 상태가 함께 표시된다.
- **Pass criterion**: 결과 파일에서 해당 컴포넌트 항목이 단계 이름과 상태를 모두 담고 있다.

### T11. 계획 폴더가 아닌 문서에는 붙지 않는다

- **Setup**: 파이프라인 표처럼 생긴 표를 담은 평범한 마크다운 파일 하나를 만든다.
- **Run**: 그 파일 하나로 문서를 만든다.
- **Expected**: 변경 표와 파이프라인 그림이 나타나지 않는다. 문서는 정상으로 만들어진다.
- **Pass criterion**: 종료 코드가 0 이고, 결과 파일에 변경 표 절이 없다.

### T12. 순수한 단계는 파일을 만지지 않는다

- **Setup**: 순수성 검사가 보는 표시를 각 순수 단계에 붙인다.
- **Run**: 기존 순수성 검사를 돌린다.
- **Expected**: 2·3·5·6·7 번 단계가 순수로 통과한다.
- **Pass criterion**: 순수성 검사가 통과한다.

### T13. 기존 문서 기능이 그대로다

- **Setup**: 없음.
- **Run**: 기존 문서 검사 네 가지와 전체 계약 검사를 돌린다.
- **Expected**: 전부 통과한다.
- **Pass criterion**: 실패 0 건.

### T14. 시간 예산이 부하에 맞춰 늘어난다

- **Setup**: 없음.
- **Run**: 시간 예산 검사를 돌린다.
- **Expected**: 기준보다 빠른 셸에서는 예산이 그대로, 굼뜬 셸에서는 늘어나되 상한을 넘지 않는다. 같은 실행 안에서 답이 흔들리지 않는다.
- **Pass criterion**: 18건 전부 통과.

### T15. 부하를 걸어도 검사들이 통과한다

- **Setup**: 바쁜 프로세스를 여럿 띄운다.
- **Run**: 시간 예산을 쓰는 검사 셋과 이 계획의 검사를 돌린다.
- **Expected**: 전부 통과한다. 고치기 전이라면 무너졌을 조건이다.
- **Pass criterion**: 실패 0건.

## How to run

```bash
bash core/tests/test-deck-change-map.sh && bash core/tests/test-timing-budget.sh
```

## Pass criteria

- T1~T15 전부 통과.
- Graft 가 설치된 자바스크립트 계열 저장소에서 한 번 실제로 돌려, 대조 표시가 실제 코드와 맞는 것을 눈으로 확인.
- 전체 계약 검사 실패 0 건.
