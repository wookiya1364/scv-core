# 복원 요약이 끝난 대화를 싣던 것 · PR 도구가 묶음 계획 가지를 늘 main 에서 만들던 것

## Summary

2026-10-01 에 "다음 계획에서 고친다"고 미뤄 둔 둘을 고친다. 첫째, 세션을 비우거나 다시 연 뒤 싣는 복원 요약이 "진행 중" 표시가 남은 가장 최근 대화의 전문을 싣는데, 끝난 대화가 그 표시를 단 채 남아 있고 실제로 일하던 대화는 계획으로 넘어가며 표시가 바뀌어 빠진다 — 오늘도 5일 전에 끝난 무관한 대화가 실릴 차례였다. 둘째, PR 도구는 묶음 계획(에픽)의 가지가 원격에 없으면 늘 main 에서 만든다 — PR 대상을 정할 때 보는 설정과 원격의 기본 가지를 보지 않고, main 이 없는 저장소에서는 커밋한 뒤에 실패한다.

## Goals / Non-Goals

- **Goals**
  - 복원 요약은 구현 중인 계획(진행 중 · 시험 중)에 이어진 대화를 먼저 고른다 — 그 대화의 표시가 "계획으로 넘김"이어도 고른다
  - 그런 대화가 없으면 최근 3일 안에 손댄 "진행 중" 대화 가운데 가장 최근 것을 고른다
  - 3일 넘게 손대지 않은 "진행 중" 대화는 전문을 싣지 않고 경로만 알린다 — 오래됐다는 말과 함께 (사용자 선택 2026-11-13)
  - PR 도구는 묶음 계획의 가지를 만들 때 출발점을 PR 대상과 같은 순서로 정한다: 설정한 대상 → 원격의 기본 가지 → main
  - 출발점이 원격에 없으면 커밋하기 전에 멈추고 이유를 알린다
- **Non-Goals**
  - 끝난 대화의 표시를 스스로 바꾸거나 대화 파일을 옮기는 일 — 파일은 건드리지 않고 고르는 규칙만 바꾼다
  - 3일이라는 기준을 설정으로 빼는 일
  - 복원 요약의 다른 묶음(계획 요약 · 결정 기록)
  - PR 대상 가지를 정하는 순서 자체를 바꾸는 일
  - 같은 메모의 다른 절반(맥 옛 셸에서 깨지던 소문자 바꾸기) — 이미 고쳐져 있다

## Approach Overview

1. **복원 요약** — 세션 시작 훅은 대화 파일마다 "경로 · 표시 · 손댄 시각" 줄을 만들어 고르는 함수에 넘긴다. 여기에 두 가지 입력을 더한다: 구현 중인 계획들의 원자료 목록에 적힌 대화 경로들, 그리고 지금 시각. 고르는 함수는 (가) 계획에 이어진 대화 가운데 가장 최근에 손댄 것, 없으면 (나) 표시가 "진행 중"이고 3일 안에 손댄 것 가운데 가장 최근 것을 낸다. 나머지 "진행 중" 대화는 지금처럼 경로만 내되, 3일을 넘긴 것은 따로 묶어 "오래 손대지 않음"이라고 알린다. 시각은 훅이 읽어 넘기고 함수는 받기만 한다.
2. **PR 도구** — 묶음 계획 가지의 출발점은 이미 있는 대상 가지 함수에 묶음 이름을 비워 물으면 나온다(설정한 대상 → 원격의 기본 가지 → main). 묶음 계획의 가지가 원격에 없을 때, 그 출발점이 원격에 있는지를 커밋 앞에서 먼저 확인한다. 없으면 아무것도 커밋하지 않고 멈춘다. 있으면 지금 자리(올리기 앞)에서 그 출발점으로 가지를 만든다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
복원 요약: flow( 대화 줄 모으기, 계획의 대화 모으기, scv_resume_pick, scv_resume_other_active, scv_resume_stale, 싣기 )
PR 도구:   flow( scv_pr_base_branch, 출발점 확인, 커밋, 가지 만들기, 올리기 )
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | 대화 줄 모으기 | 대화 파일마다 경로 · 표시 · 손댄 시각 줄을 만든다 (지금 그대로) | 대화 폴더 → 줄들 | 부수효과 (입구) |
| 2 | 계획의 대화 모으기 | 구현 중인 계획의 원자료 목록에서 대화 경로를 모은다 | 계획 폴더 → 경로들 | 부수효과 (입구) |
| 3 | scv_resume_pick | 계획의 대화를 먼저, 없으면 3일 안에 손댄 진행 중 대화를 고른다 | 줄들 · 계획의 경로들 · 지금 시각 · 기준 초 → 경로 하나 | 순수 |
| 4 | scv_resume_other_active | 고른 것을 뺀 진행 중 대화의 경로를 낸다 — 오래된 것은 빼고 | 줄들 · 고른 경로 · 지금 시각 · 기준 초 → 경로들 | 순수 |
| 5 | scv_resume_stale | 3일 넘게 손대지 않은 진행 중 대화의 경로를 낸다 | 줄들 · 고른 경로 · 지금 시각 · 기준 초 → 경로들 | 순수 |
| 6 | 싣기 | 고른 대화의 전문(가림 필터를 거쳐)과 나머지 경로를 낸다 | 경로들 → 요약 글 | 부수효과 (출구) |
| 7 | scv_pr_base_branch | 묶음 이름을 비워 물어 가지의 출발점을 정한다 (지금 있는 함수 그대로) | 설정한 대상 · 원격의 기본 가지 → 출발점 | 순수 |
| 8 | 출발점 확인 | 묶음 계획의 가지가 원격에 없을 때 출발점이 원격에 있는지 본다 — 커밋 앞에서 | 원격 → 있음 / 없음 | 부수효과 (입구) |
| 9 | 가지 만들기 | 출발점에서 묶음 계획의 가지를 만든다 — 올리기 앞에서 | 출발점 → 원격의 새 가지 | 부수효과 (출구) |

- 부수효과 위치: 파일과 시계 읽기(1 · 2), 요약 내기(6), 원격 읽기(8) · 쓰기(9). 고르는 것(3 · 4 · 5 · 7)은 글만 받아 글만 낸다
- 재사용: 출발점은 `scv_pr_base_branch` 를 그대로 쓴다. 대화 줄 모으기는 지금 코드 그대로다. `scv_resume_pick_active` 는 `scv_resume_pick` 이 대신한다(같은 줄 모양을 받는다)

## Guardrails

- 대화 파일을 고치거나 옮기지 않는다 — 고르는 규칙과 알리는 글만 바꾼다
- 세션 시작 훅은 파일마다 프로그램을 띄우지 않는다(지금 규칙 — 파일 3천 개에서 21초가 걸린 적이 있다). 계획의 대화 모으기도 awk 한 번으로 한다
- 훅은 어떤 실패에도 오류 없이 끝난다 — 계획 폴더가 없거나 읽을 수 없으면 계획의 대화 0개로 본다
- 고른 경로가 대화 폴더의 일반 파일인지 다시 확인하는 지금 검사는 그대로 둔다(연결 파일 · 폴더 밖 경로를 싣지 않는다)
- PR 도구는 출발점이 없을 때 커밋 · 올리기 · 가지 만들기를 하나도 하지 않고 멈춘다
- 훅 틀 파일을 고치면 틀 요약값을 다시 만든다
- 맥과 리눅스, bash 3.2 와 bash 5 에서 모두 돈다. 턴 시작 · 세션 시작 길에 프로그램 호출을 늘리지 않는다(재서 확인)

## Exit criteria

- All TESTS.md scenarios pass

- 순수 검사 · 함수 사전 검사 종료 코드 0, 사전은 최신
- PR 을 올리기 전 전체 시험을 한 번 돌려 실패 0 (컴퓨터가 바빠서 넘은 시간 한도는 고치기 전 코드와 같은 조건에서 견줘 가린다)
- 코어 0.93.3 릴리스 뒤 래퍼 둘까지 릴리스된다. 코어 릴리스부터 코덱스 래퍼 릴리스까지의 시간을 재서 적는다(앞 계획의 목표 30분 안)

## Suggested path

1. 두 고침의 실패하는 시험을 먼저 쓴다 — 고치기 전에 실패하는 것을 눈으로 본다
2. 고르는 함수 셋을 만든다 — `scv_resume_pick`, `scv_resume_other_active`, `scv_resume_stale`
3. 세션 시작 훅이 계획의 대화와 지금 시각을 모아 넘기고, 오래된 대화를 따로 알린다 — `계획의 대화 모으기`, `싣기`
4. PR 도구가 출발점을 정해 커밋 앞에서 확인하고, 그 출발점으로 가지를 만든다 — `scv_pr_base_branch`, `출발점 확인`, `가지 만들기`
5. 틀 요약값과 함수 사전을 다시 만들고, 관련 시험 · 순수 검사 · 함수 사전 검사를 두 셸에서 돌린다 — 고친 둘이 실제로 통과하는지 확인한다
6. 이 저장소의 실제 기록으로 세션 시작 훅을 돌려 결과를 사용자에게 보인다 — 실제로 무엇이 실리는지 본다
7. 전체 시험을 한 번 돌리고 마무리 보고를 채운 뒤 보관 · PR 로 넘어간다 — 등록 빠짐을 올리기 전에 잡는다
8. 코어와 래퍼 둘을 릴리스하고 코덱스까지의 전체 시간을 잰다 — 앞 계획의 남은 값을 얻는다

## Risks / Open Questions

- 계획의 원자료 목록에 적힌 대화 경로가 옮겨졌거나 없을 수 있다 — 없는 경로는 고르지 않고 다음 후보로 간다
- 구현 중인 계획이 여럿이면 그 대화들 가운데 가장 최근에 손댄 것 하나만 전문으로 싣는다 — 나머지 계획은 계획 요약 묶음에 이미 나온다
- 손댄 시각은 파일의 고친 시각이다 — 저장소를 새로 받으면 모든 파일의 시각이 받은 때가 된다. 그 경우 며칠 동안은 옛 대화가 "최근"으로 보일 수 있다(지금도 같은 한계다)
- 묶음 계획은 이 저장소에서 쓰이지 않아 PR 도구의 고침은 가짜 원격으로만 확인한다
