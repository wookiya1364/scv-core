# 마무리 보고 — 복원 요약이 끝난 대화를 싣던 것 · PR 도구가 묶음 계획 가지를 늘 main 에서 만들던 것

<!-- 계획을 세울 때 아는 만큼(적어도 1번) 채우고, 일이 끝난 뒤 모든 칸을 채운다.
     고장을 고치는 계획이 아니면 2 ~ 5번은 묶음마다 "해당 없음 — 이유" 한 줄로 건너뛴다.
     1 · 6 · 7번은 모든 계획이 채운다. 빈 칸이 있으면 보관되지 않는다. -->

## 1. 문제

- 상황: 세션을 비우거나 다시 연 뒤 싣는 복원 요약이 "진행 중" 표시가 남은 가장 최근 대화의 전문을 싣는다. PR 도구는 묶음 계획(에픽)의 가지가 원격에 없으면 늘 main 에서 만든다. 둘 다 2026-10-01 에 "다음 계획에서 고친다"고 미뤘다
- 기대: 복원 요약에는 지금 하던 일의 대화가 실린다. 묶음 계획의 가지는 PR 대상을 정하는 것과 같은 순서의 출발점에서 만들어지고, 출발점이 없으면 아무것도 하기 전에 멈춘다
- 실제: 끝났는데 "진행 중" 표시가 남은 대화가 7개이고(마지막으로 손댄 날 10-09 ~ 11-09), 그 가운데 가장 최근 것(5일 전의 무관한 대화)의 전문이 실릴 차례였다. 오늘 실제로 일한 대화들은 계획으로 넘어가며 표시가 바뀌어 고르는 대상에서 빠졌다. PR 도구는 설정한 대상 · 원격의 기본 가지를 보지 않고 main 에서 만들며, main 이 없으면 커밋한 뒤에 실패한다
- 재현 조건: "진행 중" 표시의 옛 대화와 "계획으로 넘김" 표시의 오늘 대화가 함께 있는 저장소에서 세션을 비운다. main 이 없고 다른 가지가 기본인 원격에서 묶음 계획의 PR 을 올린다

## 2. 관찰

- 관찰한 사실과 측정값: 고르는 함수는 표시가 "진행 중"인 것 가운데 손댄 시각이 가장 큰 경로 하나를 낸다 — 날짜도 계획도 보지 않는다. "진행 중" 대화 7개의 마지막 손댄 날: 10-09 · 10-11 · 10-11 · 10-25 · 11-05 · 11-08 · 11-09. PR 도구의 가지 만들기는 `origin/main` 이 글자로 박혀 있다(한 곳)
- 정상일 때와 차이: 계획 없이 며칠 이어 가는 대화 하나만 있을 때는 지금 규칙으로도 맞는 대화가 실린다. 계획으로 넘긴 뒤 일이 이어지거나, 끝난 대화가 쌓이면 틀린다. main 이 기본인 저장소에서는 PR 도구도 문제가 드러나지 않는다

## 3. 가설

- H1: 틀린 대화가 실리는 것은 고르는 규칙이 표시 하나만 보기 때문이다 — 계획에 이어진 대화를 먼저 고르고 오래된 것을 빼면 맞는 대화가 실린다
- H2: PR 도구는 출발점을 대상 가지와 같은 함수로 정하면 된다 — 새 규칙을 지을 필요가 없다

## 4. 실험

- 방법과 같게 둔 것: 같은 저장소 · 같은 대화 파일로 세션 시작 훅을 고치기 전 코드(설치본 0.93.2)와 고친 코드로 돌려 무엇이 실리는지 견줬다. PR 도구는 임시 폴더의 가짜 원격 다섯 가지(설정한 대상 있음 · 기본 가지만 있음 · main 만 있음 · 출발점 없음 · 묶음 계획 가지가 이미 있음)에서 올리기까지 돌렸다. 훅의 시간은 대화 300개 · 계획 20개인 가짜 프로젝트에서 세 번씩 재서 가장 빠른 값을 견줬다
- 결과와 가설별 판정: H1 맞음 — 고치기 전에는 5일 전의 무관한 대화가 전문으로 실렸고, 고친 뒤에는 구현 중인 계획에 이어진 오늘의 대화가 실리며 옛 대화 7개는 경로만 나온다. H2 맞음 — 대상 가지 함수에 묶음 이름을 비워 물으니 출발점이 나왔고 새 규칙은 짓지 않았다. 고치기 전 코드는 가짜 원격 다섯 가운데 셋에서 틀렸다(main 에서 만듦 2건 · 커밋한 뒤 실패 1건)

## 5. 원인

- 직접 원인과 일어난 길: 고르는 함수가 표시(active)와 손댄 시각만 봤다. 계획 세우기가 대화의 표시를 promoted 로 바꾸므로 일하던 대화는 후보에서 빠지고, 계획 없이 끝난 대화는 표시가 그대로라 후보로 남았다. PR 도구는 가지 만들기 줄에 `origin/main` 이 글자로 적혀 있었고, 그 줄이 커밋 뒤에 있었다
- 근본 원인: "진행 중인 대화"를 대화 파일의 표시 하나로 정의했는데, 그 표시는 일이 끝났다고 바뀌지 않고 일이 계획으로 넘어갔을 때만 바뀐다 — 표시의 뜻과 고르는 쪽의 기대가 어긋났다. PR 대상 순서를 넣을 때(0.63.0) 대상 가지는 고쳤지만 같은 파일의 가지 만들기 줄은 범위 밖으로 남겼다

## 6. 해결과 검증

- 해결책과 고른 이유: 고르는 규칙을 바꿨다 — 구현 중인 계획의 원자료 목록에 적힌 대화 먼저, 없으면 3일 안에 손댄 active, 3일 넘은 active 는 경로만(사용자 선택: 3일). 대화 파일은 건드리지 않는다. 시각과 기준은 훅이 읽어 넘기고 함수는 받기만 한다. PR 도구는 출발점을 대상 가지와 같은 함수로 정하고, 가지와 출발점이 둘 다 없으면 커밋 앞에서 멈춘다. 길이 달라진 곳: 기존 시험 자료 다섯 곳이 2020 ~ 2022년 날짜를 써서 새 규칙에서 "오래된 대화"가 됐다 — 자료의 날짜를 지금 기준으로 바꿨고 검사하는 내용은 그대로 두었다
- 고치기 전후 값: 이 저장소의 실제 기록에서 전문으로 실리는 대화 — 5일 전에 끝난 대화 → 오늘 구현 중인 계획의 대화. "오래 손대지 않음"으로 경로만 나오는 대화 0 → 7. 가짜 원격 다섯 가운데 맞는 것 2 → 5. 출발점이 없을 때 생기는 커밋 1 → 0. 세션 시작 훅의 시간(대화 300 · 계획 20): 552 → 562ms(bash 5) · 593 → 621ms(bash 3.2). 재는 검사: 나머지 대화 고르기가 처음에 1.22배(0.64 → 0.78ms)로 한도를 넘어, 줄마다 하던 숫자 확인을 정규식에서 무늬로 바꿔 1.10배(0.62 → 0.68ms)로 통과
- 부작용과 회귀 시험: 세션 복원 시험 38 → 44줄(T16 ~ T21), PR 대상 시험에 T6(다섯 가지)을 더했고 bash 3.2 · 5 에서 실패 0. 전체 시험 한 번 115개 통과 · 실패 0. 순수 검사 · 함수 사전 검사(C 설정 포함) · 호스트 이름 검사 · 훅 일관성 검사 통과, 틀 요약값 다시 만듦. 재는 검사(계획 끝): 견준 함수 3 · 한도 넘음 0 · 새 함수 2. 남은 것: 저장소를 새로 받으면 모든 대화 파일의 시각이 받은 때가 되어 며칠 동안 옛 대화가 최근으로 보인다(전과 같은 한계). 구현 중인 계획이 여럿이면 가장 최근에 손댄 대화 하나만 전문으로 실린다. 묶음 계획은 이 저장소에서 쓰이지 않아 PR 도구의 고침은 가짜 원격으로만 확인했다. 실제 세션에서 비운 뒤의 요약은 릴리스 뒤 다시 연 세션에서 볼 수 있다

## 7. 배운 것

- 다음에 같은 문제를 만나면 진단하는 법: "엉뚱한 것이 골라진다"면 고르는 함수에 들어가는 줄을 그대로 뽑아 본다 — 이번에는 표시 · 시각 줄만 봐도 active 7개가 모두 옛것이고 오늘 대화는 promoted 라는 것이 보였다. 훅은 설치본과 작업 폴더의 것을 같은 저장소에서 차례로 돌리면 전후가 한 화면에 나온다
- 다른 곳에도 쓸 수 있는 것: 파일에 적힌 표시는 그 표시를 바꾸는 쪽이 언제 바꾸는지까지 알아야 믿을 수 있다 — 고르는 쪽은 표시 하나보다 "지금 쓰이고 있다"는 근거(구현 중인 계획이 가리킨다 · 최근에 손댔다)를 본다. 날짜가 박힌 시험 자료는 시간에 기대는 규칙이 들어오면 한꺼번에 깨진다 — 자료의 날짜는 지금 기준으로 준다. 줄마다 도는 숫자 확인은 정규식보다 무늬가 가볍다(재는 검사가 1.22배를 잡았다)
