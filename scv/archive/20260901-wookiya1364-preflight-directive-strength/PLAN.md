# 지시를 맨 앞으로, 조건문을 명령으로 — preflight 지침 강화

## Summary

0.40.0 이 배포됐는데도 앞을 보는 턴에서 대화 모드 호출이 되지 않는다. 원인은 문구의
세기 하나가 아니라 네 가지다 — **자기모순**, **묻힌 위치**, **조건문 형태**, 그리고
**같은 요구를 하는 블록이 둘**이라는 점. 네 가지를 함께 고친다.

## Goals / Non-Goals

- **Goals**
  - 지시 블록을 주입문 **맨 앞**에 둔다 (진단보다 먼저).
  - 조건문을 **세 갈래 명령**으로 바꾼다.
  - 호출을 막는 것처럼 읽히던 문장을 좁히고, 빠져나갈 구멍을 명시적으로 닫는다.
  - **왜 불러야 하는지**를 지시에 넣는다 — 볼륨보다 강한 지렛대다.
  - 같은 요구를 하는 두 블록을 하나로 합친다.

- **Non-Goals**
  - 되돌림 되살리기 — 0.40.0 의 결정을 뒤집지 않는다.
  - 세 갈래를 둘로 줄이기 — "둘 다 아님" 은 정당한 결과로 남는다.
  - help 프로토콜 본문 변경 — 세 모드의 문법은 그대로다.
  - 새 스위치 추가 — 기존 두 개로 충분하다.

## Approach Overview

**무엇이 지시를 무력화했나.** 네 가지가 겹쳤고, 첫째가 가장 크다.

1. **자기모순.** preflight 블록이 "위 진단이 이번 턴의 프로젝트 상태다. **다시
   확인하지 말고 그대로 쓰라**" 고 먼저 말한 뒤 "앞을 보는 말이면 호출하라" 고
   말한다. 앞 문장은 "필요한 건 이미 다 줬으니 더 부르지 마라" 로 읽히고, **그 읽기가
   더 단순해서 이긴다.** 진단 재조회만 막으려던 문장이 액션 호출 전반을 막는 것처럼
   작동했다. 내가 넣은 문장이고 설계 실수다.
2. **위치.** 지시가 약 40줄짜리 진단 뒤에 묻혀 있다. 읽는 쪽에서 명령은 맨 앞에
   와야 한다.
3. **형태.** "앞을 보는 말이면 …하라" 는 조건문이다. 분류를 먼저 통과해야 행동에
   닿으므로 명령문보다 약하다.
4. **중복.** 라우팅 안내 블록과 preflight 지침이 같은 요구를 한다. 둘 다 무시되고
   있고, 무시되는 지시가 쌓이면 각각이 더 약해진다.

**고치는 방향.** 하나의 블록을 맨 앞에 두고, 세 갈래를 명령으로 제시한다.

- **A** — 앞으로 할 일에 관한 말이면 help 를 이 메시지 전문을 인자로 하여 대화 모드로
  호출한다.
- **B** — 지난 일을 찾는 말이면 같은 방식으로 아카이브 검색 모드를 호출한다.
- **C** — 둘 다 아니면 아무 것도 부르지 않고 바로 답한다. **정당한 결과다.**

모순 문장은 진단 재조회로만 좁히고, 그 뒤에 구멍을 닫는 한 줄을 붙인다: "A·B 를
골랐다면 진단이 있어도 호출은 그대로 해야 한다."

**볼륨보다 강한 지렛대: 이유.** "부르라" 는 명령이고, 명령은 무시될 수 있다. 대화
모드는 주입이 **대신할 수 없는 일**을 한다 — 논의를 파일로 적어 세션이 끝나도
살아남게 하고, 그것이 계획서의 근거가 된다. "부르지 않으면 이 논의가 사라진다" 는
사실이고, 사실은 명령보다 행동에 가깝다. 그 문장을 블록에 넣는다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readSwitches,      // 설정 → 스위치 두 개
  renderDirective,   // 스위치 → 합쳐진 지시 블록 (A·B·C + 이유)
  runProbe,          // (없음) → 상태 점검 전체 출력
  trimToDiagnosis,   // 전체 출력 → 진단 부분만
  emitLines,         // (지시, 진단) → 표준출력 — 지시가 먼저
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | `readSwitches` | 설정 파일 → (라우팅, preflight) | 부수효과 (입구) |
| 2 | `renderDirective` | 스위치 → 지시 블록 문자열 | 순수 |
| 3 | `runProbe` | 없음 → 점검 전체 출력 | 부수효과 (입구) |
| 4 | `trimToDiagnosis` | 전체 출력 → 진단 부분만 | 순수 |
| 5 | `emitLines` | (지시, 진단) → 표준출력 | 부수효과 (출구) |

- 부수효과 위치: 설정 읽기와 점검 실행이 입구, 출력이 출구. 문구를 만드는 두 단계는
  문자열만 다룬다 — 그래서 블록에 A·B·C 가 다 있는지, 이유가 실렸는지를 훅 없이
  그대로 검사할 수 있다.
- 재사용: 잘라내기와 스위치 해석은 지금 것을 그대로 쓴다. 바뀌는 것은 문구 생성
  하나와, 출력 순서(지시 → 진단)다.

## Guardrails

- **지시가 진단보다 먼저 나와야 한다.** 순서가 뒤집히면 이 계획의 핵심이 사라진다.
- **셋째 갈래를 빼지 않는다.** "둘 다 아니면 그냥 답하라" 가 없으면 모든 턴이 앞뒤
  둘 중 하나로 밀리고, 짧은 맞장구에도 액션이 붙어 0.39.0 의 낭비가 이름만 바꿔
  돌아온다.
- **되돌림을 되살리지 않는다.** 문구가 안 통해도 응답 종료 훅으로 되돌아가지 않는다.
- **전체 스위치의 성질을 잃지 않는다.** 대체 선언이 옛 검사를 회귀에서 건너뛰게
  하므로, "꺼져 있으면 아무 것도 주입하지 않는다" 는 새 검사가 반드시 이어받는다.
- **세션을 막지 않는다.** 점검 실패·도구 없음·설정 없음 — 전부 조용히 넘어간다.
- **새 스위치를 만들지 않는다.** 기존 두 개로 충분하고, 늘리면 사용자가 기억할 것이
  늘어난다.
- whitespace 계약: 줄 끝 공백 금지, 파일 끝 빈 줄 금지. 호스트 이름을 핵심부에 쓰지
  않는다.

## 성공지표 (Metrics)

| 지표 | 지금 | 목표 | 어떻게 재나 |
|---|---|---|---|
| 앞을 보는 턴에서의 호출 | 안 됨 (사용자가 두 번 확인) | 대부분 호출됨 | 실제 대화에서 사람이 확인 |
| 지시 블록의 위치 | 진단 뒤 (약 40줄 아래) | 진단 앞 (첫머리) | 출력에서 두 표지의 순서 |
| 같은 요구를 하는 블록 수 | 2 | 1 | 출력의 표지 개수 |
| 모순 문장 | 있음 | 없음 (진단 재조회로 좁힘) | 문구 검사 |
| 호출 이유 제시 | 없음 | 있음 | 문구 검사 |

## 예외처리 (Edge cases)

- **전체 스위치 off** → 아무 것도 주입하지 않는다. 지시도 진단도 없다.
- **preflight 스위치 off** → 진단은 없고 지시 블록만 나간다. 라우팅은 살아 있다.
- **점검 실행 실패** → 지시 블록만 나가고 조용히 넘어간다.
- **이미 다른 SCV 액션이 실린 턴** → C 로 다룬다. 그 프로토콜을 계속한다.
- **분류가 애매한 턴** → 모델이 판단한다. 틀려도 되돌리지 않는다.
- **scv 폴더 없음** → 무출력.

## Exit criteria

- TESTS.md 시나리오가 모두 통과한다.
- 기존 검사가 계속 통과한다 (저널·가드·설정·순수성·공백·지문·호스트 중립).
- 누적 회귀가 초록이고, 대체된 옛 슬러그가 건너뛰어진다.
- **실제 대화에서 앞을 보는 턴에 호출이 되는 것을 사람이 확인한다.**
- 템플릿 지문이 갱신돼 있다.

## Suggested path

1. 문구 생성부를 다시 쓴다 — 합쳐진 블록, A·B·C 명령, 좁힌 재조회 문장, 이유.
2. 프롬프트 훅의 출력 순서를 바꾼다 — 지시 먼저, 진단 나중. 옛 라우팅 블록 제거.
3. 검사를 갱신한다 — 순서·세 갈래·이유·구멍 닫기, 그리고 옛 검사에서 이어받을 성질.
4. 기존 검사가 초록인지 확인한다.
5. 지문을 다시 계산하고 변경 이력을 남긴다.

## Risks / Open Questions

- **문구에는 천장이 있다.** 네 가지를 다 고쳐도 여전히 안 될 수 있다. 그때는 되돌림이
  아니라 다른 지렛대를 찾아야 한다 — 되돌림은 값이 이미 증명된 실패다.
- **이유를 넣는 것이 통할지는 미검증이다.** 볼륨보다 낫다는 것은 판단이지 실측이
  아니다. 실제 대화에서 확인해야 한다.
- **대체 선언으로 옛 검사가 빠진다.** 그 안의 성질을 새 검사가 빠짐없이 이어받았는지가
  이번 변경의 가장 조용한 위험이다.
