# Test Plan — 지시를 맨 앞으로, 조건문을 명령으로

## Overview

이 계획이 바꾸는 것은 **문구와 순서**다. 그래서 검사도 훅을 실행해 나온 텍스트를
직접 읽는다. 무엇이 어디에 있는지, 무엇이 빠졌는지를 본다.

검사의 절반은 대체되는 옛 계획에서 **이어받는** 것이다. 그 계획을 supersedes 로
선언하면 옛 검사가 회귀에서 빠지므로, 거기 있던 성질을 여기서 다시 세우지 않으면
조용히 사라진다. 그것이 이번 변경의 가장 큰 위험이라 T7~T9 로 따로 못 박는다.

## Test scenarios

### T1. 지시 블록이 진단보다 먼저 나온다

이 계획의 핵심이다. 순서가 뒤집히면 명령이 다시 묻힌다.

- **Setup**: scv 폴더가 있는 임시 프로젝트, 스위치 기본값.
- **Run**: 프롬프트 훅을 실행한다.
- **Expected**: 지시 표지가 진단 표지보다 앞줄에 있다.
- **Pass criterion**: 지시 표지의 줄 번호 < 진단 표지의 줄 번호.

### T2. 세 갈래가 모두 있고 명령문이다

- **Setup**: T1 과 같다.
- **Run**: 프롬프트 훅 출력을 본다.
- **Expected**: 앞으로 할 일 / 지난 일 찾기 / 둘 다 아님 세 갈래가 모두 있다.
- **Pass criterion**: 세 갈래가 각각 확인되고, 셋째 갈래에 "부르지 말고 바로
  답하라" 는 뜻이 담겨 있다.

### T3. 빠져나갈 구멍이 닫혀 있다

이번 실패의 직접 원인이었다. "진단을 이미 받았으니 안 불러도 된다" 로 읽히면 안 된다.

- **Setup**: T1 과 같다.
- **Run**: 프롬프트 훅 출력을 본다.
- **Expected**: 재조회를 막는 문장이 **진단 조회로 한정**돼 있고, 그와 별개로 A·B 를
  골랐으면 호출은 그대로 해야 한다는 문장이 있다.
- **Pass criterion**: 두 문장이 모두 확인된다.

### T4. 호출해야 하는 이유가 실려 있다

- **Setup**: T1 과 같다.
- **Run**: 프롬프트 훅 출력을 본다.
- **Expected**: 대화 모드가 논의를 파일로 남긴다는 사실이 블록에 있다.
- **Pass criterion**: 그 취지의 문장이 확인된다. 볼륨을 올리는 대신 이유를 준다는
  것이 이 계획의 설계 선택이므로, 문구가 사라지면 선택도 사라진다.

### T5. 같은 요구를 하는 블록이 하나뿐이다

- **Setup**: T1 과 같다.
- **Run**: 프롬프트 훅 출력에서 라우팅을 요구하는 표지를 센다.
- **Expected**: 하나다. 옛 라우팅 표지가 따로 나오지 않는다.
- **Pass criterion**: 옛 표지가 출력에 없다.

### T6. 진단은 여전히 실린다

순서를 바꾸다가 진단을 잃으면 안 된다.

- **Setup**: T1 과 같다.
- **Run**: 프롬프트 훅 출력을 본다.
- **Expected**: 진단 내용이 지시 블록 뒤에 있다.
- **Pass criterion**: 진단 표지가 출력에 있다.

### T7. 전체 스위치를 끄면 아무 것도 주입하지 않는다 (이어받음)

대체되는 계획의 검사에 있던 성질이다. 여기서 다시 세우지 않으면 사라진다.

- **Setup**: 설정에서 전체 라우팅 스위치를 off 로 둔다.
- **Run**: 프롬프트 훅을 실행한다.
- **Expected**: 지시도 진단도 없다.
- **Pass criterion**: 둘 다 출력에 없다.

### T8. off 만 끈다 (이어받음)

- **Setup**: 전체 스위치에 각각 `off` · `OFF` · `on` · 이상값을 넣는다.
- **Run**: 네 경우 모두 프롬프트 훅을 실행한다.
- **Expected**: `off` 와 `OFF` 만 끄고, `on` 과 이상값은 켜진 상태다.
- **Pass criterion**: 네 경우가 모두 기대대로다.

### T9. 쉬운말 스위치와 독립이다 (이어받음)

- **Setup**: 쉬운말 스위치만 off 로 둔다.
- **Run**: 프롬프트 훅을 실행한다.
- **Expected**: 쉬운말 블록은 없고 지시 블록은 있다.
- **Pass criterion**: 두 조건이 모두 만족된다.

### T10. preflight 스위치를 끄면 진단 없이 지시만 남는다

- **Setup**: preflight 스위치만 off, 전체 스위치는 on.
- **Run**: 프롬프트 훅을 실행한다.
- **Expected**: 지시 블록은 있고 진단은 없다.
- **Pass criterion**: 지시 표지 있음, 진단 표지 없음.

### T11. 되돌림은 여전히 없다

- **Setup**: 프롬프트 훅을 먼저 실행한 뒤, 영수증이 비어 있는 상태.
- **Run**: 응답 종료 훅을 5회 실행한다.
- **Expected**: 매번 차단 결정이 없다.
- **Pass criterion**: 5회 모두 차단 없음, 종료 코드 0.

### T12. scv 폴더가 없으면 아무 출력도 없다

- **Setup**: scv 폴더가 없는 임시 폴더.
- **Run**: 프롬프트 훅과 종료 훅을 실행한다.
- **Expected**: 둘 다 조용히 끝난다.
- **Pass criterion**: 표준출력이 비어 있고 종료 코드 0.

### T13. 점검을 못 돌려도 지시는 나간다

- **Setup**: 상태 점검을 실행할 수 없는 환경.
- **Run**: 프롬프트 훅을 실행한다.
- **Expected**: 지시 블록만 나가고 정상 종료한다.
- **Pass criterion**: 종료 코드 0, 지시 표지 있음.

### T14. 문구 생성부가 순수성 계약을 지킨다

- **Setup**: 없음.
- **Run**: 순수성 검사기를 문자열부에 돌린다.
- **Expected**: 위반 0건.
- **Pass criterion**: 검사기가 통과를 보고한다.

### T15. 핵심부에 호스트 이름이 새지 않는다

지난 계획에서 실제로 걸렸던 항목이라 남긴다.

- **Setup**: 없음.
- **Run**: 호스트 중립 검사를 돌린다.
- **Expected**: 누출 0건.
- **Pass criterion**: 검사가 통과한다.

### T16. 실제 대화에서 앞을 보는 턴에 호출이 된다 (사람 확인)

기계로 판정할 수 없는 유일한 항목이고, 이 계획의 진짜 목표다.

- **Setup**: 갱신된 플러그인이 적용된 새 세션.
- **Run**: "이런 걸 만들고 싶다" 류의 요청을 한 번 한다.
- **Expected**: 대화 모드가 호출된다.
- **Pass criterion**: 사람이 확인하고 보고한다. 실패하면 문구의 천장에 닿은 것이며,
  되돌림이 아니라 다른 지렛대를 찾아야 한다.

## How to run

```bash
bash core/tests/test-force-help.sh
```

## Pass criteria

- 위 시나리오 T1~T15 가 모두 통과한다.
- T16 은 사람이 확인한다.
- 아래 기존 검사가 계속 통과한다 (별도 실행): `test-journal.sh`, `test-guard.sh`,
  `test-settings.sh`, `test-purity.sh`, `test-whitespace.sh`,
  `test-template-digest.sh`, 그리고 저장소의 호스트 중립 검사.
- 어떤 시나리오에서도 훅이 0이 아닌 종료 코드로 끝나지 않는다.
