# 작은 고침 묶음 — 가장 긴 시험 나누기 · 보관한 턴 · 첨부 경로 · 흔들리는 시험

## Summary

0.92.1 에서 릴리스 검증을 여섯 조각으로 나눴지만 가장 긴 조각이 252초로, 목표 4분을 12초 넘겼다. 가장 긴 시험 하나(203 ~ 256초)가 통째라 쪼갤 수 없고, 작은 시험이 몰린 조각이 시간표보다 실제로 길었다.
사용자의 지시("가장 긴 시험은 나눠서 병렬실행시켜", 조각은 여섯 그대로)대로 그 시험을 네 파일로 나누고 시간표를 실제 릴리스의 시간으로 다시 적는다. 같은 날 실제로 걸린 셋(보관한 턴이 막힘 · 첨부 경로가 계획 기록에 적힘 · 흔들리는 시험)도 함께 고친다.

## Goals / Non-Goals

- **Goals**
  - 재는 명령 시험을 네 파일로 나눈다 — 서로 다른 조각(러너)에서 함께 돌 수 있게. 가장 긴 파일이 지금의 절반 아래다
  - 조각 시간표를 0.92.1 릴리스 실행의 실제 시간으로 다시 적는다 — 여섯 조각의 가장 긴 것이 4분 안에 든다(조각 합 1,284초 ÷ 6 = 214초)
  - 계획을 보관한 턴이 끝에서 "진행 중 계획이 없다"로 막히지 않는다 — 먼저 재현하고, 재현한 까닭을 고친다
  - 파일을 붙여 보낸 요청의 경로가 계획 기록에 적히지 않는다
  - `test-journal.sh` 의 "Broken pipe" 가 나지 않게 한다. 붐빌 때 흔들린 `test-turn-plan-check.sh` T8 · T12 는 까닭을 확인한다
- **Non-Goals**
  - 릴리스 조각 수 바꾸기 (사용자: 여섯 그대로)
  - 다른 긴 시험 나누기 (100초 안팎 — 여섯 조각에서는 줄지 않는다)
  - 경계에 걸친 함수 하나 (사용자가 고르지 않음)
  - 맥 조각의 시간 한도 · 래퍼의 맥 검사 한도 · PR 검사에서 기획서 시험 돌리기 (따로 정할 일)

## Approach Overview

사용자가 2026-11-12 선택 창에서 정한 것: 넣을 것 셋(턴 끝 검사 결함 · 첨부 경로 복사 · 흔들리는 시험), 조각은 여섯 그대로("큰 것을 나누는 게 이득"), 끝난 뒤 릴리스와 래퍼 둘까지.

1. **가장 긴 시험 나누기** — 이 맥에서 구간별로 쟀다(전체 271초): S22 97초 · S15 62초 · S17 58초 · S23 12초 · S11 11초 · 나머지 약 31초. 준비에 드는 시간은 거의 없다 — 2026-11-04 에 큰 시험을 쪼갰을 때 효과가 없던 까닭(조각마다 무거운 준비를 다시 함)이 여기에는 없다.
   - 네 파일: `a`(S1 ~ S14, 순수 함수와 가벼운 실행) · `b`(S15 ~ S16, 앞뒤 번갈아 재기) · `c`(S17 ~ S21, 턴 끝) · `d`(S22 ~ S23, 일찍 멈춤 · 4배 먼저). 함께 쓰는 준비(임시 함수 · 사전)는 파일 하나에 두고 넷이 불러 쓴다.
   - 지금 파일 이름은 넷을 차례로 부르는 묶음으로 남긴다(`# scv-test: aggregate` — 조각 실행기는 건너뛴다). 넷 모두 혼자 돈다 표시를 단다.
2. **시간표** — 리눅스 시간표를 0.92.1 릴리스 실행(43142491711)의 조각 기록에서 옮겨 적는다(기획서 시험의 실제 시간이 들어간다). 나눈 네 파일의 무게는 구간별로 잰 값의 비로 넣는다. 맥 시간표는 네 파일의 줄만 바꾼다(맥은 러너에 따라 1.5 ~ 2배 흔들려 한 번 잰 값으로 다시 적을 까닭이 없다).
3. **보관한 턴** — 턴 끝 검사는 "영수증이 있고, 계획 글에 이번 턴의 새 줄과 요청 번호 줄이 있을 때" 통과시킨다(`scv_tc_judge`). 2026-11-12 의 턴은 기록 명령을 여러 번 돌렸는데도 막혔다.
   - 찾은 까닭(2026-11-12, 그 세션의 상태 파일에서): 보관한 계획을 못 읽는 것이 아니었다. 영수증은 도구 앞 훅이 명령 글을 보고 남기는데, 첫 줄이 `bash /절대/경로/plan-link.sh <기록 종류>` 꼴(앞에 `cd … &&` 하나까지)일 때만 알아본다(`scv_tc_receipt`). 모델은 경로를 변수에 담거나, 다른 명령 뒤에 이어서, 또는 둘째 줄에서 돌린다 — 기록 명령 네 번에 영수증 0이었다. 영수증이 없으면 계획에 기록 줄이 있어도 막힌다.
   - 고침: 기록 명령(`plan-link.sh`)이 기록을 실제로 남긴 뒤 스스로 영수증을 더한다. 명령 글의 모양에 기대지 않고, 실패한 기록 명령은 영수증을 남기지 않는다. 손으로 쓴 가짜 줄 · 이름만 적은 명령은 지금처럼 막힌다(영수증이 없거나 요청 번호 줄이 없다).
4. **첨부 경로** — 턴 시작 때 요청 원문을 저장하는 곳(`turn-check.sh start`)에서, 저장하기 전에 첨부 파일 경로를 지우는 순수 함수를 거친다. 계획 줄에 붙는 "요청: …" 은 이 저장된 글에서 나온다.
5. **흔들리는 시험** — `printf … | bash 훅` 은 훅이 입력을 읽기 전에 끝나면 보내는 쪽이 끊긴다(pipefail 이라 끝 코드 1). 입력을 여기 글(here-string)로 준다 — 전에 다른 두 시험에서 같은 방법으로 고쳤다.
   - 확인한 것(2026-11-12): 프롬프트 훅은 SCV 폴더가 없으면 입력을 읽기 전에 끝난다(`on-user-prompt.sh` 24번 줄에서 끝, 입력은 92번 줄에서 읽음). 끊김이 난 줄이 바로 그 경우다. 같은 꼴 일곱 곳을 바꿨다.
   - T8 · T12 의 까닭: 둘 다 벽시계 한도를 본다(사진 0.3초 안 · 선택 답 2초 안). 겹쳐 돌면 넘는다. 한도를 늘리지 않고 그 시험에 혼자 돈다 표시를 붙였다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  scv_tc_strip_attach,  // 요청 원문 → 첨부 경로를 지운 글              (순수 · 새 함수)
  turn_start,           // 지운 글 → 턴 상태(요청 글 · 번호 · 사진)      (부수효과: 쓰기)
  plan_texts,           // 턴 상태 → 진행 중 + 이번 턴에 보관한 계획 글  (부수효과: 읽기)
  scv_tc_new_lines,     // 시작 때 줄 · 지금 줄 → 새 줄                  (순수)
  scv_tc_judge,         // 바뀐 파일 · 영수증 · 새 줄 … → 통과 | 막음     (순수)
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | scv_tc_strip_attach | 요청 글에서 첨부 파일의 경로를 지운다 | 요청 원문 → 경로 없는 글 | 순수 |
| 2 | turn_start | 턴 시작 때 요청 글 · 번호 · 작업 공간 사진을 남긴다 | 요청 글 → 턴 상태 | 부수효과 (쓰기) |
| 3 | plan_texts | 진행 중 계획과 이번 턴에 보관한 계획의 글을 읽는다 | 턴 상태 → 계획 글 | 부수효과 (읽기) |
| 4 | scv_tc_new_lines | 턴 시작 뒤에 생긴 계획 줄을 가린다 | 시작 때 줄 · 지금 줄 → 새 줄 | 순수 |
| 5 | scv_tc_judge | 기록이 있는 턴인지 가린다 | 수 여섯 · 표시 넷 → 통과 \| 막음 | 순수 |
| 6 | rf_list_tests | 시험 파일을 모으고 표시를 읽는다 — 묶음은 건너뛴다 | 폴더들 → 경로와 표시 | 부수효과 (입구) |
| 7 | rf_partition | 시간표로 시험을 조각에 고르게 나눈다 | 줄 · 시간표 · 조각 번호 → 그 조각의 줄 | 순수 |

- 부수효과 위치: 2 · 3 · 6. 지우기 · 가리기 · 판정 · 나누기(1 · 4 · 5 · 7)는 순수하다.
- 재사용: 4 · 5 · 6 · 7 은 그대로 쓴다(3단계의 까닭에 따라 3 또는 2 를 고친다). 새 함수는 1 하나다.

- TESTS.md T3 의 "가장 긴 시험이 평균의 절반 아래"는 실제 값으로는 지킬 수 없었다(127초 · 평균 211초). 지키는 시험의 기준을 3분의 2 로 바꿨다 — 절반은 어림값으로 잡은 것이었다.

## Guardrails

- 나눈 뒤에도 재는 명령 시험이 확인하는 것은 그대로다 — 확인 줄을 지우거나 느슨하게 하지 않는다. 나눈 넷의 통과 수 합이 나누기 전과 같아야 한다.
- 턴 끝 검사를 느슨하게 하지 않는다. 고치는 것은 "이번 턴에 보관한 계획의 기록을 못 읽는 것"뿐이고, 재현하지 못하면 고치지 않고 본 것을 보고한다.
- 요청 글에서 지우는 것은 첨부 파일의 경로뿐이다.
- 릴리스 조각 수 · PR 검사의 조각 수 · 필수 검사 이름은 그대로다.
- 맥(BSD) · 리눅스(GNU), bash 3.2 에서 돈다. 코어 파일에 호스트 이름을 넣지 않는다.
