# Test Plan — 검토 시점에 실제 결과 보여 주기 — 실체 보여 주기 다시 재기

## Overview

사용자가 검토 시점을 정해 둔 일에서도 그 시점에 요약 대신 실제로 돌린 결과를 보이게 안내를 고치고, 검토 시점 줄을 뺀 과제로 켬 · 끔을
다시 재서 안내만의 효과를 본다. 동시에 끄면 이전과 같고, 사용자 검토 시점은 그대로이며, 결과물이 안 바뀌는 일은 묻지 않는지 본다.
단위 검사(T1 ~ T5)는 CI 에서, 측정(T6 · T8 ~ T10)은 저장소 밖 장치(`~/scv-experiments/longbench`)로 이 맥에서 실제 Claude 세션을 돌려
확인한다 — 판정 기준 · 판정자 절차는 결과를 열기 전에 고정한다. 판정기(실사용 보고) 개선은 시도했으나 기준에 못 미쳐 이 계획에서 뺐다
(T4 · T7, 사용자 결정 2026-10-10).

## Test scenarios

### T1. 매 턴 안내에 검토 시점 문구가 있다 — 통로 셋

- **Setup**: 실체 보여 주기 켬, 통로 choice · text · none.
  (구현 전 바로잡음, 2026-10-09: 초안은 '세 언어'를 가정했으나 매 턴 세 줄은 이 기능 전부터 한국어 한 벌뿐이다 — 결과를 보기 전에 고쳤다.)
- **Run**: 매 턴 안내(`scv_show_real_rule`)를 통로마다 만든다.
- **Expected**: 세 줄 그대로이고, choice · text 통로의 안내에 '사용자가 검토 시점을 정해 두었으면 그 시점을 지키고, 그때 요약 대신 실제로
  돌린 결과를 보이고 묻는다'는 뜻이 있다. none 통로는 묻지 않고 실제 결과를 보고에 남긴다(지금과 같음).
- **Pass criterion**: 통로 셋 모두 일치, 줄 수 3.

### T2. 끄면 이전과 같다

- **Setup**: 설정 `SCV_SHOW_REAL=off`.
- **Run**: 같은 입력으로 매 턴 훅 출력을 이 기능 전(develop 기준 커밋)과 비교한다.
- **Expected**: 바이트 단위로 같다.
- **Pass criterion**: 차이 0 바이트.

### T3. 매 턴 크기 상한 · 규칙 한 곳

- **Setup**: 기존 매 턴 크기 검사 · 규칙 한 곳 검사.
- **Run**: 클로드 래퍼 설정 기준 한 턴 출력 크기를 재고, 검토 시점 규칙 본문이 계약 한 곳에만 있는지 본다.
- **Expected**: 12,000바이트 이하, 규칙 본문 중복 0(다른 파일은 가리키기만).
- **Pass criterion**: 두 검사 통과.

### T4. 판정기는 그대로 — 실사용 보고 검사가 이 기능 전과 같다

(바꿈, 2026-10-10: 순서 판정이 정답 표본에서 미달이라 판정기 변경을 뺐다 — 사용자 결정. 아래 시도한 픽스처 계획은 기록으로 남긴다.)

- **Setup**: 기존 실사용 보고 검사(`core/tests/test-show-real.sh` 의 순수 함수 표 · 고정 기록 10개의 손으로 센 값).
- **Run**: 기존 검사를 그대로 돌린다.
- **Expected**: 판정기 순수부(`scv_show_real_entries` · `split` · `classify`)가 개발 브랜치와 같고, 기존 값이 그대로 나온다.
- **Pass criterion**: 기존 검사 모두 통과, 판정기 함수 차이 0.
- (시도 기록) 고정 기록 픽스처 — (a) 편집 → 실행 → 실행 결과 한 줄을 인용한 질문 (b) 편집 → 실행 없이 질문 (c) 편집 → 실행 → 결과를
  인용하지 않은 다른 결정 질문 (d) T9 mobly 모양(첫 테스트 파일 실행 "9 passed in 0.96s" → "9개 모두 통과 … 나머지도 … 갈까요?" — 숫자
  인용) (e) 실행 → 편집 → 질문(순서 다름) (f) 결과물 변화 없음으로 끝난 턴 (g) 편집 → 살펴보기 명령(cat · git diff)만 → 그 출력을 인용한
  질문(실행이 아님).
  (구현 전 바로잡음, 2026-10-10: 숫자 인용 · 살펴보기 명령 제외를 더했다 — 판정기 정의를 사용자가 정한 대로.)
  — 순서 판정을 넣었다가 뺐다.

### T5. 결과물 변화 없음 · 사람 없는 실행은 그대로

- **Setup**: 기존 실체 보여 주기 검사(결과물 변화 없음 · 무인 · 자동 알림 턴).
- **Run**: `core/tests/test-show-real.sh` 의 기존 시나리오를 돌린다.
- **Expected**: 결과물이 안 바뀌는 일은 묻지 않고, 사람 없는 실행 · 자동 알림 턴은 묻지 않는다(이 기능 전과 같음).
- **Pass criterion**: 기존 시나리오 모두 통과.

### T6. 측정 준비 — 돌리기 전에 고정

- **Setup**: 장치 `~/scv-experiments/longbench`, 기준 문서 RUBRIC-LB.md.
- **Run**: (1) 6과제 지시에서 '커밋 뒤 검토 요청' 줄만 뺀 판을 만들고 원래 지시와의 차이를 기록한다. (2) 두 측정의 판정 기준 · 멈춤 문턱을
  기준 문서에 적는다. (3) 브랜치 플러그인 사본을 측정 세션에만 싣고, 시험 세션 대화 기록에 새 문구가 실리는지 본다.
- **Expected**: 구현 전 커밋 시각보다 앞선 날짜로 기준이 적혀 있고, 뺀 줄 외 지시 차이 0, 새 문구 실림.
- **Pass criterion**: 세 가지 모두 확인.

### T7. 판정기 정답 표본 — 시도 기록(이 계획의 통과 조건 아님)

(바꿈, 2026-10-10: 순서 판정 잘못 잡음 7/25 로 기준(2 이하) 미달 — 판정기 변경을 이 계획에서 빼고 결과를 기록으로만 남긴다. 사용자 결정.)

- **Setup**: 실제 기록에서 고른 40개(사용자 세션 + T9 기록). 정답은 판정기를 돌리기 전에 가린 판정(방식을 모르는 새 Claude)으로 정한다.
  원본은 저장소 밖에 둔다.
- **Run**: 새 판정기와 옛 판정기를 표본에 돌려 정답과 비교한다.
- **Expected**: 새 판정기가 정답이 '보여 주지 않음'인 것을 '보여 줌'으로 잡는 일이 2개 이하이고, T9 mobly 사례를 잡는다. 옛 판정기 값도 함께 기록.
- **Pass criterion**: (기록) 옛 판정기 · 순서 판정의 잡음 · 잘못 잡음 · 놓침을 측정 보고서에 남김.

### T8. 효과 측정 — 검토 시점 줄 뺀 과제, 켬 · 끔

- **Setup**: 브랜치 사본(켬) · 같은 사본에서 `SCV_SHOW_REAL=off`(끔), T6 의 뺀 지시, 관리자 Opus, 기본 모델 · 생각 깊이.
- **Run**: 6과제 × 켬 · 끔 × 1번 = 12번, 같은 과제는 하나씩. 판정자(새 Claude)가 첫 편집 뒤의 질문마다 판정하고(장치 기준 문서의 '판정자 판정 절차'), yes 질문이 하나라도 있는 과제를
  '실제 결과를 먼저 보여 줌'으로 센다.
- **Expected**: 켬에서 결과물이 바뀌는 단계마다 처음 돌아가는 순간의 실제 결과를 보이고 묻는 과제가 대부분이다.
- **Pass criterion**: 켬 4/6 이상이고 켬 − 끔 ≥ 3. 못 미치면 Exit criteria 대로 멈추고 사용자와 다시 정한다.

### T9. 문구 측정 — 원래 과제(검토 시점 있음), 켬

- **Setup**: 브랜치 사본(켬), 원래 과제 지시 그대로(검토 시점 줄 있음).
- **Run**: 6과제 × 1번 = 6번. 과제마다 검토 창 앞의 모델 글 · 질문에 실제 실행 결과(명령 출력 · 함수 호출 결과의 한 줄 이상)가 있는지,
  첫 검토 창이 과제 지시의 시점(첫 구현 커밋 뒤)보다 앞당겨졌는지 본다 — 판정은 T8 과 같은 판정자, 검토 시점은 그 단계의 첫 `git commit`.
  비교는 T9(0.66.0) 기록.
- **Expected**: 검토 시점은 그대로이고, 그 시점에 요약 대신 실제 실행 결과를 보이고 묻는다.
- **Pass criterion**: 실제 실행 결과 4/6 이상 · 첫 검토 창 앞당김 0.

### T10. 멈춤 문턱 — 나빠지지 않는다

- **Setup**: T8 의 12번 결과.
- **Run**: 숨은 테스트 통과(v2 채점), 실행당 선택 창 수, 실행 시간을 켬 · 끔으로 비교한다.
- **Expected**: 켬이 끔보다 숨은 테스트를 2과제 이상 덜 통과하지 않고, 선택 창 수 · 실행 시간 중앙값이 1.5배 미만이다.
- **Pass criterion**: 세 가지 모두 문턱 안. 하나라도 넘으면 멈추고 결과를 보이며 다시 정한다.

### T11. 맥 · 리눅스 · 순수성

- **Setup**: 맥(bash 3.2) · 리눅스 CI, 순수성 검사.
- **Run**: T1 ~ T5 검사와 순수성 검사를 두 환경에서 돌린다.
- **Expected**: 두 환경 결과가 같다.
- **Pass criterion**: 모두 통과(두 환경).

### T12. 두 래퍼 설치본

- **Setup**: 코어 릴리스 뒤 클로드 · 코덱스 래퍼 동기화 · 릴리스, 설치본.
- **Run**: 두 설치본의 매 턴 훅 출력을 본다(임시 저장소).
- **Expected**: 클로드는 선택 창 문구에, 코덱스는 글 질문 문구에 검토 시점 문구가 실린다.
- **Pass criterion**: 두 래퍼 모두 확인.

## How to run

```bash
bash core/tests/test-show-real.sh && bash core/tests/test-choice-questions.sh && bash core/tests/test-help-budget.sh && bash core/tests/test-rule-constitution.sh
```

측정(T6 · T8 ~ T10)은 실제 Claude 세션을 돌리므로 CI · 회귀 실행에 넣지 않는다 — `~/scv-experiments/longbench` 의 장치로
돌리고, 결과를 기준 문서와 측정 보고서(scv/raw)에 적는다.

## Pass criteria

- T1 ~ T5 · T11 이 맥 · 리눅스 CI 에서 통과한다.
- T8 켬 4/6 이상 · 끔보다 3 이상, T9 4/6 이상 · 앞당김 0, T10 문턱 안 — 아니면 멈추고 사용자와 다시 정한다(계획의 Exit criteria).
- T12 는 릴리스 뒤 확인한다.
