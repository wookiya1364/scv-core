# 마무리 보고 — 대시보드: 치면 맞는 기어가 뜨고, 기어 칸은 역할 먼저 한 줄씩

     고장을 고치는 계획이 아니면 2 ~ 5번은 묶음마다 "해당 없음 — 이유" 한 줄로 건너뛴다.
     1 · 6 · 7번은 모든 계획이 채운다. 빈 칸이 있으면 보관되지 않는다. -->

## 1. 문제

- 상황: 대시보드 0.3.0 을 설치해 실제 창에서 기어 칸을 본 직후(기어 1개인 프로젝트).
- 기대: 기어가 여러 개여도 한눈에 보이고, 기어를 모르는 사람도 아는 사람도 하려는 말에 맞는 기어를 쓸 수 있다.
- 실제: 기어 하나가 여섯 줄을 차지한다(이름 · 값 이름 · 역할 · 인자 · 표시 · 알림). 이름과 값 이름이 먼저 보이고, 사용자의 말과 기어를 맞춰 주는 곳이 창에도 대화에도 없다.
- 재현 조건: 기어가 있는 프로젝트에서 SCV 창을 연다. 기어 10개면 기어 칸이 60줄쯤 된다.

## 2. 관찰

- 관찰한 사실과 측정값: 실제 창 화면: 기어 1개에 여섯 줄. 기어 목록 파일의 일곱째 칸(낱말)과 기어 글의 낱말 줄을 읽는 코드는 모드 · 본체의 매 턴 훅 어디에도 없다.
- 정상일 때와 차이: 단계 흐름 칸은 단계 하나가 두 줄이고 누르면 자세히 펼쳐진다 — 기어 칸은 처음부터 다 펼쳐 놓았다.

## 3. 가설

- H1: 기어가 하나인 프로젝트의 자료로만 그려 보고 만들어서, 여러 개일 때의 모습을 보지 않았다.
- H2: 기어를 "목록에서 골라 쓰는 것"으로만 보고, 사용자가 하려는 말에서 출발하는 길을 만들지 않았다.

## 4. 실험

- 방법과 같게 둔 것: 0.3.0 을 만들 때의 확인 자료를 되짚음: 창 글자 줄은 이 프로젝트의 기어 목록(1개)으로만 뽑았다. 낱말 줄을 쓰는 곳은 코드 찾기로 확인했다.
- 결과와 가설별 판정: H1 맞음 — 여러 개일 때의 줄 수를 잰 적이 없다. H2 맞음 — 낱말 줄을 읽는 코드가 0곳.

## 5. 원인

- 직접 원인과 일어난 길: 기어 칸이 기어마다 모든 것을 펼쳐 그림 → 기어 수만큼 여섯 줄씩 늘어남. 이름을 알아야 [쓰기]를 고를 수 있음 → 모르는 사람은 쓸 수 없음.
- 근본 원인: 실제 화면을 기어 여러 개인 자료로 먼저 보지 않았고, 쓰는 사람의 출발점(하려는 말)이 아니라 저장된 것의 모양(이름 · 값)에서 화면을 짰다.

## 6. 해결과 검증

- 해결책과 고른 이유: 입력창의 글이 바뀔 때마다 기어의 낱말과 맞춰 보고, 둘 이상 겹치는 기어가 있으면 입력창 위에 그 기어가 하는 일을 한 줄로 띄운다. 그대로 보내면 글 끝에 그 기어를 쓰라는 한 줄을 붙인다. 기어 칸은 역할 문장 먼저의 한 줄씩 목록으로 바꿨다. 사용자가 고른 이유: 몰라도 쓰이고, 미리 알면 바로 부를 수 있어 같은 일을 같은 방법으로 하며 토큰을 아낀다. 목록에서 고르게 하는 안 · 찾기 칸을 두는 안은 사용자가 물리쳤다. 실제 앱에서 본 뒤 한 번 더 고쳤다(0.3.2): 버튼을 [사용함] [사용안함] 둘로 두고 — 사용함은 누르는 즉시 그 방법으로 보낸다 — 설명을 자르지 않는다.
- 고치기 전후 값: 기어 10개일 때 기어 칸: 60줄쯤(기어마다 여섯 줄) → 7줄(안내 한 줄 + 5줄 + 모두 보기), 모두 펼쳐도 12줄. 사용자의 말과 기어를 맞추는 곳: 0곳 → 입력창 위 한 줄과 보낼 때 한 줄. 모드 시험 176 → 183. 0.3.2: 입력창 위 줄의 버튼 1개 → 2개, 설명 60자에서 자름 → 전부 보임, 모드 시험 183 → 185.
- 부작용과 회귀 시험: 보낸 글 끝에 한 줄이 붙어 대화 기록에 남는다([안 씀]으로 끔). 낱말 겹침만 보므로 뜻이 같은 다른 말은 못 맞춘다. 회귀: 모드 시험 183개 통과(기어 칸을 보던 시험 다섯은 줄을 펼친 뒤 같은 글을 보게 고침), 형 검사 오류 9개 그대로. 앱에서 입력창 위 줄이 실제로 어떻게 보이는지는 릴리스 뒤 사용자가 본다 — 이 보고를 쓸 때는 보지 못했다. 실제 앱에서 본 것(사용자 화면 2026-11-24): 입력창 위 줄이 뜨고, 보낸 글 끝에 한 줄이 붙었다. 릴리스를 묻는 질문에 릴리스 검사 기어가 뜬 잘못 맞음도 한 번 있었다 — 버튼을 누르지 않고 보내면 붙는 동작은 사용자가 그대로 두기로 했다.

## 7. 배운 것

- 다음에 같은 문제를 만나면 진단하는 법: 목록을 그리는 칸은 항목 1개 · 10개 · 0개인 자료로 각각 그려 줄 수를 센다. "이 화면만 보고 처음 온 사람이 무엇을 할 수 있나"를 먼저 묻는다 — 이름과 값 이름만 보이면 쓸 수 없다.
- 다른 곳에도 쓸 수 있는 것: 저장해 둔 것을 고르게 하지 말고, 사용자가 이미 치고 있는 자리(입력창)에서 맞는 것을 먼저 내민다. 목록은 역할을 쉬운 말로 먼저 보이고 자세한 것은 누를 때 편다.
