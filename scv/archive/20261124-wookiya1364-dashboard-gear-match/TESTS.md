# Test Plan — 대시보드: 치면 맞는 기어가 뜨고, 기어 칸은 역할 먼저 한 줄씩

## Overview

두 가지를 확인한다. (1) 입력창에 친 글과 기어의 낱말이 둘 이상 겹칠 때만 입력창 위에 한 줄이 뜨고, 보낼 때 그 기어를 쓰라는 한 줄이 글 끝에 붙는지. (2) 기어 칸이 역할 문장 먼저의 한 줄씩 목록이 되고, 기어가 많아도 5줄 + 모두 보기로 줄어드는지. 모드의 시험 도구(`claude plugin test`)로 돈다.

## Test scenarios

### T1. 낱말이 둘 이상 겹치면 맞는 기어를 고른다

- **Setup**: 낱말 줄이 "릴리스 CI 시험 검사" 인 기어와 "커밋 제목 묶음" 인 기어
- **Run**: `gearMatch("릴리스 전에 시험 다 돌려줘", 기어들)`
- **Expected**: 첫 기어, 맞은 낱말 "릴리스" · "시험"
- **Pass criterion**: 돌려준 기어 이름과 맞은 낱말이 기대와 같음

### T2. 조사가 붙은 말도 맞는다

- **Setup**: T1 과 같음
- **Run**: "릴리스를 하기 전에 검사를 해줘"
- **Expected**: 첫 기어("릴리스를" = "릴리스", "검사를" = "검사")
- **Pass criterion**: 기어 이름이 기대와 같음

### T3. 낱말 하나만 겹치면 맞추지 않는다

- **Setup**: T1 과 같음
- **Run**: "시험 삼아 화면 색을 바꿔 봐", "안녕", 빈 글
- **Expected**: 셋 다 없음
- **Pass criterion**: 돌려준 값이 없음(null) 세 번

### T4. 명령과 짧은 글에는 맞추지 않는다

- **Setup**: T1 과 같음
- **Run**: "/scv:gear run release-ci 릴리스 시험", "릴리스"
- **Expected**: 둘 다 없음
- **Pass criterion**: null 두 번

### T5. 여러 기어가 맞으면 가장 많이 겹친 것 하나

- **Setup**: 낱말이 "릴리스 시험" 인 기어와 "릴리스 시험 리눅스 검사" 인 기어
- **Run**: "릴리스 전에 리눅스에서 시험하고 검사해"
- **Expected**: 둘째 기어
- **Pass criterion**: 기어 이름이 둘째

### T6. 입력창에 치면 입력창 위에 한 줄이 뜬다

- **Setup**: 기어 목록이 있는 프로젝트, 세션 시작
- **Run**: 입력창 글을 "릴리스 전에 시험 다 돌려줘" 로 바꾸고 입력창 위 자리를 그린다
- **Expected**: "저장해 둔 방법이 있음" 과 그 기어의 역할 문장, [안 씀] 버튼
- **Pass criterion**: 그린 글에 역할 문장 있음, 버튼 1개

### T7. 맞는 기어가 없으면 아무것도 뜨지 않는다

- **Setup**: T6 과 같음
- **Run**: 입력창 글을 "화면 색을 바꿔 줘" 로 바꾸고 그린다. 그다음 글을 지운다
- **Expected**: 두 경우 모두 입력창 위 줄 없음
- **Pass criterion**: 그린 글에 "저장해 둔 방법" 0번

### T8. 맞는 기어가 뜬 채로 보내면 글 끝에 한 줄이 붙는다

- **Setup**: T6 과 같음
- **Run**: "릴리스 전에 시험 다 돌려줘" 를 보낸다
- **Expected**: 넘어간 글이 원래 글로 시작하고, 끝에 그 기어 이름이 든 한 줄이 붙음. 그 기어가 최근 쓴 목록 맨 앞에 옴
- **Pass criterion**: 넘어간 글이 원래 글 + 한 줄, 한 줄에 기어 이름

### T9. [안 씀]을 누르면 붙이지 않는다

- **Setup**: T6 과 같음, 한 줄이 뜬 상태
- **Run**: [안 씀]을 누르고 같은 글을 보낸다
- **Expected**: 입력창 위 줄이 사라지고, 넘어간 글이 원래 글과 같음
- **Pass criterion**: 넘어간 글 = 원래 글

### T10. 맞는 기어가 없거나 명령이면 글이 그대로 간다

- **Setup**: T6 과 같음
- **Run**: "화면 색을 바꿔 줘" 와 "/scv:status" 를 보낸다
- **Expected**: 둘 다 그대로
- **Pass criterion**: 넘어간 글 = 원래 글 두 번

### T11. 기어 칸은 한 줄씩 — 역할 문장이 먼저

- **Setup**: 기어 3개
- **Run**: 창을 그린다
- **Expected**: 기어마다 역할 문장 한 줄과 [쓰기]. 접힌 줄에는 이름 · 값 이름 · 인자가 없다. 칸 맨 위에 "하려는 일을 그냥 말해도" 한 줄
- **Pass criterion**: 역할 문장 3개, "인자" 0번, "→" 0번

### T12. 줄을 누르면 그 기어만 펼쳐진다

- **Setup**: 기어 3개
- **Run**: 둘째 줄을 누르고, 다시 누른다
- **Expected**: 누르면 그 기어의 이름 · 정할 값 · 이럴 때 낱말이 보이고 다른 기어는 접힌 채. 다시 누르면 접힘
- **Pass criterion**: 펼친 뒤 "정할 값" 1번, 다시 누른 뒤 0번

### T13. 5개가 넘으면 5줄과 모두 보기

- **Setup**: 기어 10개
- **Run**: 창을 그리고, [10개 모두 보기]를 누른다
- **Expected**: 처음에는 5줄과 버튼, 누르면 10줄
- **Pass criterion**: [쓰기] 버튼 5개 → 10개

### T14. 최근 쓴 기어가 앞에 온다

- **Setup**: 기어 10개, 이름 순으로 여덟째 기어의 [쓰기]를 누른 적이 있음
- **Run**: 새로 그린다
- **Expected**: 그 기어가 첫 줄
- **Pass criterion**: 첫 [쓰기] 버튼이 그 기어의 것

### T15. 역할 문장이 길면 줄인다

- **Setup**: 역할이 80자인 기어
- **Run**: `gearRows`
- **Expected**: 접힌 줄은 줄임표로 끝나고, 펼친 내용에는 전문이 있다
- **Pass criterion**: 접힌 글의 길이가 정한 길이 이하, 펼친 글 = 전문

### T17. 사용함을 누르면 바로 보낸다

- **Setup**: 입력창에 맞는 글이 있고 입력창 위 줄이 뜬 상태
- **Run**: [사용함]을 누른다
- **Expected**: 입력창의 글이 그 기어의 한 줄과 함께 보내지고, 입력창이 비워지고, 줄이 사라진다. 한 줄은 한 번만 붙는다
- **Pass criterion**: 넘어간 글 1개, 그 안의 기어 줄 1번, 입력창을 비운 기록 1번

### T18. 설명을 자르지 않는다

- **Setup**: 역할이 100자가 넘는 기어
- **Run**: `hintLine`
- **Expected**: 역할 전문이 그대로 들어 있다
- **Pass criterion**: 돌려준 글 = "저장해 둔 방법이 있음: " + 전문

### T16. 기존 시험이 그대로 통과한다

- **Setup**: 없음
- **Run**: 대시보드 시험 전체
- **Expected**: 기존 176개가 모두 통과한다(기어 칸을 보던 시험은 펼친 뒤 같은 글을 본다)
- **Pass criterion**: 실패 0

## How to run

```bash
cd ../scv-mods/marketplace/mods/scv-dashboard && claude plugin test .
```

## Pass criteria

- 위 명령이 실패 0 으로 끝난다.
- 기어 10개인 창의 글자 줄을 사용자에게 보였다: 기어 칸이 10줄 안.
- 형 검사 오류 수가 9 그대로다.
