# 결정은 고르는 선택지로 — 클로드에서 SCV 가 묻는 결정을 객관식으로 되돌린다

## Summary

사용자 요구(대화 Turn 1): 클로드에서 SCV 가 사용자에게 고르게 하는 결정은 예전처럼 고르는 객관식 선택지(호스트의 선택지
도구)로 떠야 한다. 지금은 줄글 표("'다 추천대로'라고 하시거나, 바꿀 번호만 알려 주세요")로 나온다(다른 컴퓨터의 계획 화면).
조사(확인): 객관식으로 물으라는 지시는 계획 · 도움말 지시문 본문에 처음부터 없었다 — 설치본 0.31.1~0.63.0 열 개 버전 모두
래퍼 허용 도구 목록에만 있고, 모델이 스스로 고르던 습관이었다. 이 컴퓨터의 세션 기록에서 선택지 도구는 9/21 · 9/26 계획 때
("계획 폴더 이름과 제목은 이대로 갈까요?" 등) 쓰였고, 9/27 18:36 이후로는 한 번도 불리지 않았다. 도움말 답 모양은 0.44.0 부터
결정을 "번호로 답하는 표"로 묻게 하고(`core/protocols/help.md:75` · `:92-94` · `:158`), 회귀 삭감은 0.54.0 부터 결정 표 하나로
묻는다(`core/protocols/regression.md:21` · `:74-76`). 0.60.0~0.63.0 에 매 턴 등록 · 인용 · "두 표로 답하라" 원칙이 더해지면서
질문까지 글 속 표로 쓰게 된 것으로 본다(추정 — 고친 뒤 실측이 확인한다). 막는 장치는 없었다 — 가드 · 훅이 가로채는 것은
스킬 · 셸 · 파일 쓰기뿐이다(확인). 강제 수준은 사용자 결정: 글로 묻고 끝내면 같은 턴에 막아 선택지 도구로 다시 묻게 한다.

두 번째 결함(이 계획을 만든 턴에서 확인, 사용자 결정으로 포함): 종료 훅의 턴 자르기(`core/template/hooks/on-stop.sh:83-92`
`_scv_turn_stream`)가 호스트의 내부 메시지 — 스킬을 불러올 때 기록되는 사용자 몫 메시지(내부 표시가 붙은 글) — 를 사람이 보낸
프롬프트로 센다. 그래서 같은 턴에서 그보다 앞서 보인 다시 쓴 요청 인용을 보지 못하고 끝내기를 막았다(기록 597번째 줄의 인용,
620번째 줄의 계획 단계 불러오기 — 확인). 도움말에서 계획으로 넘어가는 흔한 흐름에서 생기고, 선택지 질문으로 턴이 길어지면 원본을
읽는 창(마지막 400줄)이 사람 프롬프트에 닿지 못해 같은 증상이 날 수 있다(추정).

세 번째 요구(사용자 추가, 같은 릴리스): 답의 문제 표('번호 | 위치 | 조건 | 깨지는 것 | 확인')와 단위 표의 '생길 수 있는 문제'
칸은 정보만 과다하다 — 해결책을 낼 때 예상되는 문제도 함께 해결하면 된다. 그래서 SCV 원칙(`core/contracts/rewrite-principle.md`,
0.63.0)에서 문제 표 · 문제 칸 · 위치 표시 문장을 없애고, 해결책은 각 방법이 부를 문제를 막는 길까지 담아 제시한다. 막을 수 없는 것
중 사용자가 정할 것은 선택지로 묻고, 남는 한계(확인하지 못한 것)는 추천 칸 이유에 한 줄로 적는다(사용자 답). 선택지의 보기도
같다 — 보기를 고르면 생길 문제를 막는 방법까지 보기 설명에 담는다("문제가 있으면, 선택지를 줬을 때 그걸 해결할 수 있는 방법을
포함해서 제시하면 되잖아").

네 번째 결정(사용자, 같은 릴리스 — 선택지로 고름): (a) 도움말 답 모양 절은 내용 고정(절마다 지문)과 도움말 전체 7,200B 상한
(당시 7,199B)이 함께 걸려 있어 규칙을 직접 못 쓰고 있었다 — 잠금을 풀고 결정 자리에 선택지 규칙을 직접 적은 뒤 새 문구로 다시
잠근다. 상한은 도움말 7,200→7,600B(래퍼 사본 7,500→8,000B — 클로드 사본은 펼침으로 약 400B 크다), 규약 합계 32,000→33,000B.
(b) 매 턴 상한 11,000→12,000B — 클로드 설정 실측 약 10.7KB 에 선택지 안내 한 줄(324B)과 도움말 문구가 더해진다. (c) 답의 끝
메시지에 문제 표 · '생길 수 있는 문제' 칸이 있으면 종료 훅이 같은 턴에 한 번 막는다 — "막는건 쉽잖아. 그걸 애초에 자동으로
해결되도록 할건데, 그게 왜 사용자에게 보여져야해?"

다섯 번째 요구(사용자, 같은 릴리스): 추정으로 적은 문제도 해결한다 — "그럼 추정으로 적은 문제도 해결할 수 있도록 이번에 같이
포함해". 계기: 추정으로 적은 '긴 턴' 위험이 이 릴리스를 마무리하던 세션에서 실제로 일어났다 — 설치본(0.63.0) 종료 훅이 사람

## Approach Overview

도구 이름은 호스트 설정이 준다 — 코어는 이름을 모르고 값만 옮긴다(0.63.0 자동 알림 태그와 같은 방식). 규칙은 한 자리에 쓰고,
도움말 결정 자리 · 회귀 삭감 · 각 단계 질문 블록은 그곳을 가리킨다. 도구가 없으면 지금의 번호 표가 그대로 대체 경로다.
모델에게는 도구가 있을 때만 한 줄을 앞쪽에 싣는다. 마지막 그물은 종료 훅이다: 마지막 답에서 코드 블록과 인용 줄을 뺀 본문이
사용자에게 묻거나 번호로 고르게 하면서 끝나면 같은 턴에 한 번 막는다. 판정은 순수 함수 하나(본문 → 묻나)로 두고 픽스처로
잠근다 — 화면 문구 "'다 추천대로'라고 하시거나, 바꿀 번호만 알려 주세요.", "…할까요? (추천: 예)", "번호로 답해 주세요",
영어 "answer by number" 는 잡고, 정보 표 · 인용 줄 · 코드 블록 안의 물음표는 잡지 않는다. 막는 이유 문장에 도구 이름과 나누는
규칙을 싣는다 — 모델이 이유만 읽고 바로 다시 물을 수 있게.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
# 묻는 쪽 — 앞쪽 안내 (함수 이름은 제안)
flow(
  scv_choice_line,      // (도구 이름) → 안내 한 줄 | 빈 값
)
# 지키는 쪽 — 종료 훅
flow(
  scv_answer_body,      // (마지막 답) → 코드 블록 · 인용 줄을 뺀 본문
  scv_asks_in_text,     // (본문) → 1(글로 묻거나 번호로 고르게 하고 끝남) | 0
  scv_choice_gate,      // (묻나, 도구 이름, 계속 중) → ok | block | warn
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | 호스트 설정 읽기 | 호스트 설정 파일 → 도구 이름 | 부수효과 (입구) |
| 2 | scv_choice_line | 도구 이름 → 한 줄 / 빈 값 | 순수 |
| 3 | 안내 싣기 | 한 줄 → 도움말 출력 · 매 턴 블록 | 부수효과 (출구) |
| 4 | 종료 훅: 마지막 답 읽기 | 훅 입력 → 답 텍스트 | 부수효과 (입구) |
| 5 | scv_answer_body | 답 → 본문 | 순수 |
| 6 | scv_asks_in_text | 본문 → 1 / 0 | 순수 |
| 7 | scv_choice_gate | 묻나, 도구, 계속 중 → ok / block / warn | 순수 |
| 8 | 막기 · 경고 | 판정 → 막는 출력 / 다음 턴 경고 | 부수효과 (출구) |

- 부수효과 위치: 호스트 설정 읽기, 훅 입력 읽기, 안내 출력, 막는 출력 · 경고 파일 쓰기 — 입구 · 출구뿐.
- 재사용: 호스트 설정 읽기(`core/scripts/lib/host-profile.sh`), 종료 훅의 답 고르기와 같은 턴 한 번 규칙(`scv_mp_stop_gate`
  의 계속 중 처리, `core/scripts/lib/model-prompting.sh:553`), 인용 줄 · 코드 블록 판별 방식(`scv_mp_answer_has_quote`, `:256`),
  다음 턴 경고 통로.

## Guardrails

- 호스트 설정에 도구 이름이 없으면(코덱스 · 기본) 안내 · 판정 출력이 이 계획 전과 바이트 단위로 같다.
- 같은 턴 차단은 한 번 — 호스트가 이미 계속 중이면 막지 않고 다음 턴 경고(무한 반복 금지). 등록 차단과 겹치면 한 번에 한 이유씩.
- 0.62.0 등록 · 인용 판정과 0.63.0 자동 알림 판별은 그대로 — 기존 모델별 프롬프팅 검사가 그대로 통과해야 한다.
- 코어 소스 · 검사에 클로드 도구 이름을 적지 않는다 — 픽스처는 중립 이름(예: `PickTool`)을 쓴다.
- 매 턴 · 도움말 · 합계 상한(사용자 결정 2026-10-01: 12,000B · 7,600B · 33,000B) 안 — 더 넘으면 상한을 올리지 말고 사용자에게
  묻는다.
- 도움말 답 모양 절은 결정 자리 문구만 바꾸고 새 문구로 다시 잠근다 — 결론 자리 · 쉬운 말 규칙 · 언어 절은 바이트 그대로.
- 회귀 검사의 CI 모드는 묻지 않는다(`regression.md:20` 그대로).
- 엄격 모드 훅의 새 변수에는 기본값을 붙이고, 비운 채로도 검사한다(교훈 2026-09-28). 순수부에 꺾쇠를 글자로 쓰지 않는다
  (교훈 2026-09-30). 맥 기본 bash 3.2 · 리눅스에서 같게 동작한다.
- 취소 · 무응답을 추천값으로 바꿔 진행하지 않는다.
- 종료 훅은 긴 턴(수만 줄 원본)에서도 빨라야 한다 — 원본을 읽는 일은 jq 한 번씩, bash 반복은 이번 턴의 작은 조각에만.
- 원칙 문구는 한 자리(`core/contracts/rewrite-principle.md`)에서만 고친다. 원칙 준수는 문제 표 · 문제 칸만 기계로 막고(사용자
  결정 2026-10-01), 그 밖은 판정하지 않는다(2026-09-30 결정 유지). 원칙 스위치를 끄면 등록 출력과 종료 훅이 원칙이 없던 때와 같다.
- 턴 자르기 수정은 내부 메시지만 뺀다 — 사람 프롬프트 · 도구 결과 구분, 답 모양 검사 · 규약 지문 검사의 동작은 그대로다. 내부
  표시가 없는 호스트(코덱스)의 판정은 이 계획 전과 같다.
- `SCV_CHOICE_OFF_WHEN` 이 비면(코덱스 · 기본) 안내 · 판정이 이 요구 전과 같다. 조건은 값이 같을 때만 맞는다 — 환경 변수가 없는
  실행은 도구가 있다고 본다(지금처럼).
- 코덱스 모양 원본의 판정(끝 메시지만 봄)은 이 계획 전과 같다 — 넓혀 찾지 않는 것과 '경계 없음' 기록을 남기지 않는 것만 바뀐다.

## Exit criteria

- TESTS.md 전 시나리오 통과, 맥 · 리눅스 CI 로그에서 새 검사 줄을 각각 확인, 코덱스 사본의 코어 검사 전부 통과.
- 코어 릴리스, 두 래퍼 동기화 PR 병합, 클로드 어댑터 설정에 선택지 도구 이름, 클로드 래퍼의 회귀 설명 정리 · 모델 정책 두 단계,
  두 래퍼 릴리스.
- 설치본 실측(클로드): 대화형(tmux 로 띄운 세션 — 헤드리스에는 선택지 도구가 없다)으로 (a) 서로 독립인 결정 여러 개 → 선택지 도구
  호출이 기록되고 첫 보기가 추천 (b) 글로 묻고 끝내는 답 → 같은 턴에 막히고 선택지 도구로 다시 묻는다. 헤드리스로 (c) 인용을 보인
  뒤 계획 단계를 불러오는 턴 → 인용 때문에 막히지 않는다 (d) 사람 턴의 등록 결과에 새 원칙(세 칸 단위 표, 문제 표 없음)과 새
  표식이 실린다 (e) 끝 메시지에 문제 표를 넣으면 같은 턴에 막힌다 (f) 글로 묻고 끝내도 막히지 않고 안내 줄도 없다(사람 없는 실행)
  — 실행 기록으로 확인. 그리고 사용자가 대화형 화면에서 한 번 직접 확인하고, 화면이 나왔던 다른 컴퓨터에서도 새 버전 설치 뒤
  결정이 나오는 턴을 한 번 본다(사용자만 할 수 있다).

## Suggested path

1. 호스트 설정 키(기본 빈 값 · 계약 · 예시) + 순수 함수(도구 이름 → 안내 한 줄).
2. "고르게 할 때" 규칙 한 자리 + 도움말 결정 자리 · 회귀 삭감 · 질문 블록이 그곳을 가리키게(호스트 중립 문구, 없으면 번호 표).
3. 앞쪽 안내 한 줄 — 도움말 출력과 매 턴 블록 중 비용을 재고 고른다.
4. 종료 훅: 본문 추리기 · 묻나 판정 · 같은 턴 한 번 차단(계속 중이면 경고), 자동 알림 턴 포함.
4a. 종료 훅의 턴 자르기: 내부 메시지를 사람 프롬프트에서 빼고, 긴 턴에서도 이번 사람 턴의 경계를 찾는다.
4b. SCV 원칙 문구(세 언어) · 표식 · 설정 예시 설명 · 템플릿 지문, 그리고 "고르게 할 때" 규칙에 보기 설명의 해결 방법.
4c. 네 번째 결정: 도움말 답 모양 결정 자리에 직접 적기 + 다시 잠금, 상한 셋, 종료 훅의 문제 표 막기.
4d. 다섯 번째 요구: 사람 없는 실행 조건 키, 턴 자르기 둘(출처 표시 · 다른 형식), 실제 긴 턴 모양 잠금, 판정 정확도 실측 ·
    고침, 원인 실측(tmux), 맥 기본 bash 3.2 의 속도 · 출력.
5. 검사: 판정 픽스처(잡을 것 · 잡지 않을 것), 도구 없음이면 그대로, 기존 검사(답 모양 · 규칙 헌법) 갱신, 비용 상한.
6. 코덱스 사본 · 두 bash · 전체 검사 → VERSION · CHANGELOG → PR → 병합 → 코어 릴리스.
7. 래퍼: 동기화 PR → 클로드 어댑터 설정(선택지 도구 · 사람 없는 실행 조건) · 회귀 설명 · 모델 정책 두 단계 → 래퍼 릴리스 →
   설치본 실측(대화형 tmux + 헤드리스 + 사용자 직접 한 번).

## Risks / Open Questions

다섯 번째 요구로 추정 · 미확인을 모두 확인했다 — 남은 것은 실측 두 가지(T31 · T32)와 사용자만 할 수 있는 확인 하나다.

- 원인(매 턴 "표로" 규칙의 누적) — 대화형 실측(T32, tmux): 설치본 0.63.0 그대로 · 매 턴 규칙 7개를 끈 상태, 같은 계획 요청 각 2회.
  네 번 모두 첫 결정을 선택지 도구로 물었다(질문 4개, 첫 보기 추천 — 확인). 이 컴퓨터의 새 세션(Opus 5.5 · 클로드 코드 2.1.286)에서는
  증상이 재현되지 않아 원인 추정은 지지되지 않는다. 증상은 다른 조건(화면이 나온 컴퓨터의 모델 · 버전, 긴 세션에 쌓인 글 표 답 등)에
  달린 것으로 본다(추정 — 그 컴퓨터에서만 확인할 수 있다). 고친 동작은 원인과 무관하다 — 글로 묻고 끝내면 종료 훅이 막는다.
- 판정은 문장 모양을 본다 — 로컬 실제 답 모음으로 잘못 잡은 것 · 놓친 것을 세고 고쳐 픽스처로 잠근다(T31). 남는 한계는 잰 비율로
  적는다.
- 헤드리스에는 선택지 도구가 없다(확인 — 실험) → 사람 없는 실행 조건 키로 안내 · 막기를 끄고(T27), 설치본 실측의 선택지 확인은
  대화형 tmux 로 한다.
- 매 턴 비용 — 상한 12,000B 안(확인 — 검사 T12). 사람 없는 실행에서는 안내 줄도 빠진다.
- 도구 호출을 직접 시키는 장치 — 없다(확인 — 클로드 코드 훅 문서: 훅은 도구 호출을 일으킬 수 없다).
- 선택지 창 한도 4 · 4 — 도구 정의의 최댓값(확인). 규칙은 "지금 4개"로 적어 두어, 바뀌면 그 숫자만 고친다.
- 다른 컴퓨터의 화면 — 사용자만 확인할 수 있다: 새 버전 설치 뒤 결정이 나오는 턴 한 번.
- 내부 표시 이름이 바뀌는 경우 — 도구 출처 표시도 함께 봐서 한쪽이 바뀌어도 남는다(T29). 둘 다 바뀌면 이전과 같은 쪽(한 번 막고
  계속)으로 실패하고, 릴리스마다 설치본 실측 (c)가 잡는다. 코덱스 원본은 모양이 달라 이 판정을 쓰지 않는다(확인) — 넓혀 찾지
  않는다(T28).
- 긴 턴의 경계 찾기 — 실제 원본으로 확인했다(설치본 0.63.0 은 막고, 고친 훅은 통과). 그 모양을 검사로 잠근다(T30).
- 맥 기본 bash 3.2 의 종료 훅 속도 — 검증 중 찾은 이전부터의 결함(답 하나 10만 바이트 158초 · 4,500줄 턴 79초). 고친 뒤 둘 다 1초,
  시스템 bash 로 도는 검사(T33)가 맥 CI 에서 지킨다.

# 결정은 고르는 선택지로 — 클로드에서 SCV 가 묻는 결정을 객관식으로 되돌린다

## Summary

사용자 요구(대화 Turn 1): 클로드에서 SCV 가 사용자에게 고르게 하는 결정은 예전처럼 고르는 객관식 선택지(호스트의 선택지
도구)로 떠야 한다. 지금은 줄글 표("'다 추천대로'라고 하시거나, 바꿀 번호만 알려 주세요")로 나온다(다른 컴퓨터의 계획 화면).
조사(확인): 객관식으로 물으라는 지시는 계획 · 도움말 지시문 본문에 처음부터 없었다 — 설치본 0.31.1~0.63.0 열 개 버전 모두
래퍼 허용 도구 목록에만 있고, 모델이 스스로 고르던 습관이었다. 이 컴퓨터의 세션 기록에서 선택지 도구는 9/21 · 9/26 계획 때
("계획 폴더 이름과 제목은 이대로 갈까요?" 등) 쓰였고, 9/27 18:36 이후로는 한 번도 불리지 않았다. 도움말 답 모양은 0.44.0 부터
결정을 "번호로 답하는 표"로 묻게 하고(`core/protocols/help.md:75` · `:92-94` · `:158`), 회귀 삭감은 0.54.0 부터 결정 표 하나로
묻는다(`core/protocols/regression.md:21` · `:74-76`). 0.60.0~0.63.0 에 매 턴 등록 · 인용 · "두 표로 답하라" 원칙이 더해지면서
질문까지 글 속 표로 쓰게 된 것으로 본다(추정 — 고친 뒤 실측이 확인한다). 막는 장치는 없었다 — 가드 · 훅이 가로채는 것은
스킬 · 셸 · 파일 쓰기뿐이다(확인). 강제 수준은 사용자 결정: 글로 묻고 끝내면 같은 턴에 막아 선택지 도구로 다시 묻게 한다.

두 번째 결함(이 계획을 만든 턴에서 확인, 사용자 결정으로 포함): 종료 훅의 턴 자르기(`core/template/hooks/on-stop.sh:83-92`
`_scv_turn_stream`)가 호스트의 내부 메시지 — 스킬을 불러올 때 기록되는 사용자 몫 메시지(내부 표시가 붙은 글) — 를 사람이 보낸
프롬프트로 센다. 그래서 같은 턴에서 그보다 앞서 보인 다시 쓴 요청 인용을 보지 못하고 끝내기를 막았다(기록 597번째 줄의 인용,
620번째 줄의 계획 단계 불러오기 — 확인). 도움말에서 계획으로 넘어가는 흔한 흐름에서 생기고, 선택지 질문으로 턴이 길어지면 원본을
읽는 창(마지막 400줄)이 사람 프롬프트에 닿지 못해 같은 증상이 날 수 있다(추정).

세 번째 요구(사용자 추가, 같은 릴리스): 답의 문제 표('번호 | 위치 | 조건 | 깨지는 것 | 확인')와 단위 표의 '생길 수 있는 문제'
칸은 정보만 과다하다 — 해결책을 낼 때 예상되는 문제도 함께 해결하면 된다. 그래서 SCV 원칙(`core/contracts/rewrite-principle.md`,
0.63.0)에서 문제 표 · 문제 칸 · 위치 표시 문장을 없애고, 해결책은 각 방법이 부를 문제를 막는 길까지 담아 제시한다. 막을 수 없는 것
중 사용자가 정할 것은 선택지로 묻고, 남는 한계(확인하지 못한 것)는 추천 칸 이유에 한 줄로 적는다(사용자 답). 선택지의 보기도
같다 — 보기를 고르면 생길 문제를 막는 방법까지 보기 설명에 담는다("문제가 있으면, 선택지를 줬을 때 그걸 해결할 수 있는 방법을
포함해서 제시하면 되잖아").

네 번째 결정(사용자, 같은 릴리스 — 선택지로 고름): (a) 도움말 답 모양 절은 내용 고정(절마다 지문)과 도움말 전체 7,200B 상한
(당시 7,199B)이 함께 걸려 있어 규칙을 직접 못 쓰고 있었다 — 잠금을 풀고 결정 자리에 선택지 규칙을 직접 적은 뒤 새 문구로 다시
잠근다. 상한은 도움말 7,200→7,600B(래퍼 사본 7,500→8,000B — 클로드 사본은 펼침으로 약 400B 크다), 규약 합계 32,000→33,000B.
(b) 매 턴 상한 11,000→12,000B — 클로드 설정 실측 약 10.7KB 에 선택지 안내 한 줄(324B)과 도움말 문구가 더해진다. (c) 답의 끝
메시지에 문제 표 · '생길 수 있는 문제' 칸이 있으면 종료 훅이 같은 턴에 한 번 막는다 — "막는건 쉽잖아. 그걸 애초에 자동으로
해결되도록 할건데, 그게 왜 사용자에게 보여져야해?"

다섯 번째 요구(사용자, 같은 릴리스): 추정으로 적은 문제도 해결한다 — "그럼 추정으로 적은 문제도 해결할 수 있도록 이번에 같이
포함해". 계기: 추정으로 적은 '긴 턴' 위험이 이 릴리스를 마무리하던 세션에서 실제로 일어났다 — 설치본(0.63.0) 종료 훅이 사람
프롬프트가 원본 끝 400줄 밖에 있는 턴을 빈 턴으로 보고 인용을 못 찾아 막았다(확인 — 막힌 시점의 원본 467줄을 두 방식으로 재현).
추정 · 미확인 9개를 확인한 결과(모두 확인): 헤드리스(`claude -p`)에는 선택지 도구가 없다 — 권한을 건너뛰어도, 기본 권한이어도 도구
목록에 없다(실험). 훅 환경의 '사람이 보고 있음' 값(`CLAUDE_CODE_SESSION_ATTENDED`)은 대화형 1 · 헤드리스 0(클로드 코드 2.1.281 ·
2.1.286, tmux 로 띄운 일반 대화형 세션 포함). 클로드 코드 훅은 도구 호출을 일으킬 수 없다(공식 훅 문서 — 종료 훅 차단이 문서상
유일한 길). 코덱스 세션 원본은 줄 모양이 달라(최상위 type 이 response_item 등) 턴 자르기가 사람 프롬프트를 찾지 못한다 — 0.64.0 의
넓혀 찾기가 매 종료마다 끝까지 넓히고 '경계 없음' 기록을 한 줄씩 남긴다(판정은 이전과 같고, 4만 5천 줄에서도 10초 안). 로컬 원본
25개에서 사람 프롬프트에 도구 출처 표시(`sourceToolUseID`)가 붙은 일은 0건이고 스킬 불러오기는 내부 표시 · 출처 표시를 함께 단다.
턴 중간에 온 배경 작업 알림은 사용자 글로 기록되지 않는다(이 세션 원본). 선택지 한도 4 · 4 는 도구 정의의 최댓값, 매 턴 비용은
상한 안(검사 T12). 판정 정확도(실측, 로컬 원본 230턴): 실제로 묻는 답 60개 중 35개(58%)만 잡았다 — 놓친 모양은 질문 뒤 추천 문장
("…할까요? 추천은 …입니다." 10건), 목록에 없던 요청 말투("번호로 답해 주시면 됩니다" · "…할지 알려 주세요" 등 9건), 한 줄 보기 목록

10만 바이트에 158초, 4,500줄 턴에 79초 걸린다 — 0.64.0 커밋 상태도 같다(이전부터의 결함, 훅 시간 제한을 넘을 수 있음). 매 턴 등록

## Approach Overview

도구 이름은 호스트 설정이 준다 — 코어는 이름을 모르고 값만 옮긴다(0.63.0 자동 알림 태그와 같은 방식). 규칙은 한 자리에 쓰고,
도움말 결정 자리 · 회귀 삭감 · 각 단계 질문 블록은 그곳을 가리킨다. 도구가 없으면 지금의 번호 표가 그대로 대체 경로다.
모델에게는 도구가 있을 때만 한 줄을 앞쪽에 싣는다. 마지막 그물은 종료 훅이다: 마지막 답에서 코드 블록과 인용 줄을 뺀 본문이
사용자에게 묻거나 번호로 고르게 하면서 끝나면 같은 턴에 한 번 막는다. 판정은 순수 함수 하나(본문 → 묻나)로 두고 픽스처로
잠근다 — 화면 문구 "'다 추천대로'라고 하시거나, 바꿀 번호만 알려 주세요.", "…할까요? (추천: 예)", "번호로 답해 주세요",
영어 "answer by number" 는 잡고, 정보 표 · 인용 줄 · 코드 블록 안의 물음표는 잡지 않는다. 막는 이유 문장에 도구 이름과 나누는
규칙을 싣는다 — 모델이 이유만 읽고 바로 다시 물을 수 있게.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
# 묻는 쪽 — 앞쪽 안내 (함수 이름은 제안)
flow(
  scv_choice_line,      // (도구 이름) → 안내 한 줄 | 빈 값
)
# 지키는 쪽 — 종료 훅
flow(
  scv_answer_body,      // (마지막 답) → 코드 블록 · 인용 줄을 뺀 본문
  scv_asks_in_text,     // (본문) → 1(글로 묻거나 번호로 고르게 하고 끝남) | 0
  scv_choice_gate,      // (묻나, 도구 이름, 계속 중) → ok | block | warn
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | 호스트 설정 읽기 | 호스트 설정 파일 → 도구 이름 | 부수효과 (입구) |
| 2 | scv_choice_line | 도구 이름 → 한 줄 / 빈 값 | 순수 |
| 3 | 안내 싣기 | 한 줄 → 도움말 출력 · 매 턴 블록 | 부수효과 (출구) |
| 4 | 종료 훅: 마지막 답 읽기 | 훅 입력 → 답 텍스트 | 부수효과 (입구) |
| 5 | scv_answer_body | 답 → 본문 | 순수 |
| 6 | scv_asks_in_text | 본문 → 1 / 0 | 순수 |
| 7 | scv_choice_gate | 묻나, 도구, 계속 중 → ok / block / warn | 순수 |
| 8 | 막기 · 경고 | 판정 → 막는 출력 / 다음 턴 경고 | 부수효과 (출구) |

- 부수효과 위치: 호스트 설정 읽기, 훅 입력 읽기, 안내 출력, 막는 출력 · 경고 파일 쓰기 — 입구 · 출구뿐.
- 재사용: 호스트 설정 읽기(`core/scripts/lib/host-profile.sh`), 종료 훅의 답 고르기와 같은 턴 한 번 규칙(`scv_mp_stop_gate`
  의 계속 중 처리, `core/scripts/lib/model-prompting.sh:553`), 인용 줄 · 코드 블록 판별 방식(`scv_mp_answer_has_quote`, `:256`),
  다음 턴 경고 통로.

## Guardrails

- 호스트 설정에 도구 이름이 없으면(코덱스 · 기본) 안내 · 판정 출력이 이 계획 전과 바이트 단위로 같다.
- 같은 턴 차단은 한 번 — 호스트가 이미 계속 중이면 막지 않고 다음 턴 경고(무한 반복 금지). 등록 차단과 겹치면 한 번에 한 이유씩.
- 0.62.0 등록 · 인용 판정과 0.63.0 자동 알림 판별은 그대로 — 기존 모델별 프롬프팅 검사가 그대로 통과해야 한다.
- 코어 소스 · 검사에 클로드 도구 이름을 적지 않는다 — 픽스처는 중립 이름(예: `PickTool`)을 쓴다.
- 매 턴 · 도움말 · 합계 상한(사용자 결정 2026-10-01: 12,000B · 7,600B · 33,000B) 안 — 더 넘으면 상한을 올리지 말고 사용자에게
  묻는다.
- 도움말 답 모양 절은 결정 자리 문구만 바꾸고 새 문구로 다시 잠근다 — 결론 자리 · 쉬운 말 규칙 · 언어 절은 바이트 그대로.
- 회귀 검사의 CI 모드는 묻지 않는다(`regression.md:20` 그대로).
- 엄격 모드 훅의 새 변수에는 기본값을 붙이고, 비운 채로도 검사한다(교훈 2026-09-28). 순수부에 꺾쇠를 글자로 쓰지 않는다
  (교훈 2026-09-30). 맥 기본 bash 3.2 · 리눅스에서 같게 동작한다.
- 취소 · 무응답을 추천값으로 바꿔 진행하지 않는다.
- 종료 훅은 긴 턴(수만 줄 원본)에서도 빨라야 한다 — 원본을 읽는 일은 jq 한 번씩, bash 반복은 이번 턴의 작은 조각에만.
- 원칙 문구는 한 자리(`core/contracts/rewrite-principle.md`)에서만 고친다. 원칙 준수는 문제 표 · 문제 칸만 기계로 막고(사용자
  결정 2026-10-01), 그 밖은 판정하지 않는다(2026-09-30 결정 유지). 원칙 스위치를 끄면 등록 출력과 종료 훅이 원칙이 없던 때와 같다.
- 턴 자르기 수정은 내부 메시지만 뺀다 — 사람 프롬프트 · 도구 결과 구분, 답 모양 검사 · 규약 지문 검사의 동작은 그대로다. 내부
  표시가 없는 호스트(코덱스)의 판정은 이 계획 전과 같다.
- `SCV_CHOICE_OFF_WHEN` 이 비면(코덱스 · 기본) 안내 · 판정이 이 요구 전과 같다. 조건은 값이 같을 때만 맞는다 — 환경 변수가 없는
  실행은 도구가 있다고 본다(지금처럼).
- 코덱스 모양 원본의 판정(끝 메시지만 봄)은 이 계획 전과 같다 — 넓혀 찾지 않는 것과 '경계 없음' 기록을 남기지 않는 것만 바뀐다.

## Exit criteria

- TESTS.md 전 시나리오 통과, 맥 · 리눅스 CI 로그에서 새 검사 줄을 각각 확인, 코덱스 사본의 코어 검사 전부 통과.
- 코어 릴리스, 두 래퍼 동기화 PR 병합, 클로드 어댑터 설정에 선택지 도구 이름, 클로드 래퍼의 회귀 설명 정리 · 모델 정책 두 단계,
  두 래퍼 릴리스.
- 설치본 실측(클로드): 대화형(tmux 로 띄운 세션 — 헤드리스에는 선택지 도구가 없다)으로 (a) 서로 독립인 결정 여러 개 → 선택지 도구
  호출이 기록되고 첫 보기가 추천 (b) 글로 묻고 끝내는 답 → 같은 턴에 막히고 선택지 도구로 다시 묻는다. 헤드리스로 (c) 인용을 보인
  뒤 계획 단계를 불러오는 턴 → 인용 때문에 막히지 않는다 (d) 사람 턴의 등록 결과에 새 원칙(세 칸 단위 표, 문제 표 없음)과 새
  표식이 실린다 (e) 끝 메시지에 문제 표를 넣으면 같은 턴에 막힌다 (f) 글로 묻고 끝내도 막히지 않고 안내 줄도 없다(사람 없는 실행)
  — 실행 기록으로 확인. 그리고 사용자가 대화형 화면에서 한 번 직접 확인하고, 화면이 나왔던 다른 컴퓨터에서도 새 버전 설치 뒤
  결정이 나오는 턴을 한 번 본다(사용자만 할 수 있다).

## Suggested path

1. 호스트 설정 키(기본 빈 값 · 계약 · 예시) + 순수 함수(도구 이름 → 안내 한 줄).
2. "고르게 할 때" 규칙 한 자리 + 도움말 결정 자리 · 회귀 삭감 · 질문 블록이 그곳을 가리키게(호스트 중립 문구, 없으면 번호 표).
3. 앞쪽 안내 한 줄 — 도움말 출력과 매 턴 블록 중 비용을 재고 고른다.
4. 종료 훅: 본문 추리기 · 묻나 판정 · 같은 턴 한 번 차단(계속 중이면 경고), 자동 알림 턴 포함.
4a. 종료 훅의 턴 자르기: 내부 메시지를 사람 프롬프트에서 빼고, 긴 턴에서도 이번 사람 턴의 경계를 찾는다.
4b. SCV 원칙 문구(세 언어) · 표식 · 설정 예시 설명 · 템플릿 지문, 그리고 "고르게 할 때" 규칙에 보기 설명의 해결 방법.
4c. 네 번째 결정: 도움말 답 모양 결정 자리에 직접 적기 + 다시 잠금, 상한 셋, 종료 훅의 문제 표 막기.
4d. 다섯 번째 요구: 사람 없는 실행 조건 키, 턴 자르기 둘(출처 표시 · 다른 형식), 실제 긴 턴 모양 잠금, 판정 정확도 실측 ·
    고침, 원인 실측(tmux), 맥 기본 bash 3.2 의 속도 · 출력.
5. 검사: 판정 픽스처(잡을 것 · 잡지 않을 것), 도구 없음이면 그대로, 기존 검사(답 모양 · 규칙 헌법) 갱신, 비용 상한.
6. 코덱스 사본 · 두 bash · 전체 검사 → VERSION · CHANGELOG → PR → 병합 → 코어 릴리스.
7. 래퍼: 동기화 PR → 클로드 어댑터 설정(선택지 도구 · 사람 없는 실행 조건) · 회귀 설명 · 모델 정책 두 단계 → 래퍼 릴리스 →
   설치본 실측(대화형 tmux + 헤드리스 + 사용자 직접 한 번).

## Risks / Open Questions

다섯 번째 요구로 추정 · 미확인을 모두 확인했다 — 남은 것은 실측 두 가지(T31 · T32)와 사용자만 할 수 있는 확인 하나다.

- 원인(매 턴 "표로" 규칙의 누적) — 대화형 실측(T32, tmux): 설치본 0.63.0 그대로 · 매 턴 규칙 7개를 끈 상태, 같은 계획 요청 각 2회.
  네 번 모두 첫 결정을 선택지 도구로 물었다(질문 4개, 첫 보기 추천 — 확인). 이 컴퓨터의 새 세션(Opus 5.5 · 클로드 코드 2.1.286)에서는
  증상이 재현되지 않아 원인 추정은 지지되지 않는다. 증상은 다른 조건(화면이 나온 컴퓨터의 모델 · 버전, 긴 세션에 쌓인 글 표 답 등)에
  달린 것으로 본다(추정 — 그 컴퓨터에서만 확인할 수 있다). 고친 동작은 원인과 무관하다 — 글로 묻고 끝내면 종료 훅이 막는다.
- 판정은 문장 모양을 본다 — 로컬 실제 답 모음으로 잘못 잡은 것 · 놓친 것을 세고 고쳐 픽스처로 잠근다(T31). 남는 한계는 잰 비율로
  적는다.
- 헤드리스에는 선택지 도구가 없다(확인 — 실험) → 사람 없는 실행 조건 키로 안내 · 막기를 끄고(T27), 설치본 실측의 선택지 확인은
  대화형 tmux 로 한다.
- 매 턴 비용 — 상한 12,000B 안(확인 — 검사 T12). 사람 없는 실행에서는 안내 줄도 빠진다.
- 도구 호출을 직접 시키는 장치 — 없다(확인 — 클로드 코드 훅 문서: 훅은 도구 호출을 일으킬 수 없다).
- 선택지 창 한도 4 · 4 — 도구 정의의 최댓값(확인). 규칙은 "지금 4개"로 적어 두어, 바뀌면 그 숫자만 고친다.
- 다른 컴퓨터의 화면 — 사용자만 확인할 수 있다: 새 버전 설치 뒤 결정이 나오는 턴 한 번.
- 내부 표시 이름이 바뀌는 경우 — 도구 출처 표시도 함께 봐서 한쪽이 바뀌어도 남는다(T29). 둘 다 바뀌면 이전과 같은 쪽(한 번 막고
  계속)으로 실패하고, 릴리스마다 설치본 실측 (c)가 잡는다. 코덱스 원본은 모양이 달라 이 판정을 쓰지 않는다(확인) — 넓혀 찾지
  않는다(T28).
- 긴 턴의 경계 찾기 — 실제 원본으로 확인했다(설치본 0.63.0 은 막고, 고친 훅은 통과). 그 모양을 검사로 잠근다(T30).
- 맥 기본 bash 3.2 의 종료 훅 속도 — 검증 중 찾은 이전부터의 결함(답 하나 10만 바이트 158초 · 4,500줄 턴 79초). 고친 뒤 둘 다 1초,
  시스템 bash 로 도는 검사(T33)가 맥 CI 에서 지킨다.

# Test Plan — 결정은 고르는 선택지로 — 클로드에서 SCV 가 묻는 결정을 객관식으로 되돌린다

## Overview

호스트 설정에 선택지 도구가 있을 때(클로드) SCV 가 사용자에게 고르게 하는 모든 결정이 선택지 도구로 묻게 되는지 — 앞쪽 안내가
실리고, 글로 묻고 끝내면 종료 훅이 같은 턴에 한 번 막는지 — 와, 도구가 없을 때(코덱스 · 기본) 모든 출력이 지금과 같은지를 본다.
대화와 빈틈 질문에서 정한 것(범위 · 4개 초과 · 자유 입력 · 보기 5개 이상 · 취소 · 단계 밖 질문 · 강제 · 코덱스 · 확인 방법)이
하나씩 시나리오다(최소 요구 — 빼지 않는다). 검사 픽스처는 중립 도구 이름(`PickTool`)을 쓴다. 다섯 번째 요구(추정 해소)는
T27~T32 — 사람 없는 실행, 코덱스 모양 원본, 도구 출처 표시, 실제 긴 턴 모양, 판정 정확도 실측, 원인 실측이다.

## Test scenarios

### T1. 글로 묻는 답 판정 — 순수 함수 (잡을 것)

- **Setup**: 픽스처 답(독립 검토가 찾은 누락 모양 9개 — 질문 뒤 보기 목록 · 요청형 · 이모티콘 · 괄호 · 따옴표 — 를 더해 15개,
  C · UTF-8 로캘 같은 판정) — (a) 결정 표 뒤 "'다 추천대로'라고 하시거나, 바꿀 번호만 알려 주세요." (다른 컴퓨터 화면 문구)
  (b) "질문: 세 로컬 작업 폴더를 개발 브랜치 최신으로 옮겨 둘까요? (추천: 예)" 로 끝남 (c) `| # | 질문 | 추천 |` 표 + "번호로
  답해 주세요." (d) 영어 "Reply with the numbers" / "answer by number" (e) "Should I proceed?" 로 끝남.
- **Run**: 본문 추리기 → 묻나 판정.
- **Expected**: 다섯 경우 모두 1.
- **Pass criterion**: 모두 1.

### T2. 글로 묻는 답 판정 — 순수 함수 (잡지 않을 것)

- **Setup**: 픽스처 답(독립 검토가 찾은 오탐 모양 7개 — 되짚는 표 · 표 안 물음표 · 평서문 속 문구 · 정보 목록 — 를 더해 12개)
  — (a) 정보 표만(단위 표 · 결과 표, 예전 답의 문제 표 포함) (b) 물음표가 든 인용 줄 `> **다시 쓴 요청**: 다 끝난거 맞아?…`
  (c) 코드 블록 안의 물음표 (d) "고르지 않으셔서 여기서 멈춥니다." 같은 평서문 끝 (e) 본문 중간의 물음표, 끝은 평서문.
- **Run**: 본문 추리기 → 묻나 판정.
- **Expected**: 다섯 경우 모두 0.
- **Pass criterion**: 모두 0.

### T3. 막기 판정 — 순수 함수

- **Setup**: (묻나, 도구 이름, 계속 중) 조합.
- **Run**: 막기 판정.
- **Expected**: (1, PickTool, 0) → block, (1, PickTool, 1) → warn, (0, PickTool, *) → ok, (1, 빈 값, *) → ok.
- **Pass criterion**: 모든 조합이 기대값과 같다.

### T4. 종료 훅 — 글로 묻고 끝내면 같은 턴에 한 번 막는다 (강제)

- **Setup**: 호스트 설정 `PickTool`, 등록을 마친 사람 턴, 마지막 답 = T1(a).
- **Run**: 종료 훅 → 같은 입력에 `stop_hook_active: true` 로 다시 종료 훅.
- **Expected**: 첫 번째는 막는 출력(이유에 `PickTool` · "추천을 첫 보기" · "4개씩 나눠" 안내), 두 번째는 막지 않고 다음 턴 경고를
  남긴다.
- **Pass criterion**: 두 결과 모두.

### T5. 종료 훅 — 자동 알림 턴에도 적용

- **Setup**: 0.63.0 자동 알림 턴(호스트 설정 태그로 판별), 마지막 답 = T1(b).
- **Run**: 종료 훅.
- **Expected**: 등록 판정은 지금처럼 건너뛰고(`STOP_GATE: auto` 그대로), 선택지 판정은 막는다.
- **Pass criterion**: 두 조건 모두.

### T6. 종료 훅 — 선택지로 물은 턴 · 정보만 준 턴은 통과

- **Setup**: 마지막 답 = T2 의 다섯 경우, 그리고 선택지 도구로 물은 뒤 평서문으로 끝난 답.
- **Run**: 종료 훅.
- **Expected**: 막지 않는다.
- **Pass criterion**: 여섯 경우 모두 통과.

### T7. 도구가 없으면 지금과 같다 (코덱스 · 기본)

- **Setup**: 호스트 설정에 도구 이름 없음.
- **Run**: 매 턴 훅 · 도움말 출력 · 종료 훅(마지막 답 = T1 의 다섯 경우).
- **Expected**: 출력 · 판정이 이 계획 전과 바이트 단위로 같다(안내 줄 없음, 선택지 판정으로 막지 않음).
- **Pass criterion**: 이 계획 전 기대값과 같다.

### T8. 앞쪽 안내 — 도구가 있을 때만 한 줄

- **Setup**: 호스트 설정 `PickTool` / 없음.
- **Run**: 안내 한 줄 만들기(순수) + 그 줄이 실리는 자리(도움말 출력 또는 매 턴 블록) 실행.
- **Expected**: 있을 때 도구 이름과 규칙 요지(추천 첫 보기 · 4개씩 나눔 · 보기 5개 이상 두 단계 · 자유 입력은 추천값 보기 · 취소면
  멈춤)가 한 줄로 실린다. 없을 때 아무것도 없다. 자동 알림 턴에도 실린다(사용자 결정 — 단계 밖 · 자동 턴 포함).
- **Pass criterion**: 세 경우 모두.

### T9. 규칙 한 자리와 가리키기 — 도움말 결정 자리 · 회귀 삭감 · 질문 블록

- **Setup**: 코어 지시문.
- **Run**: 문장 검사.
- **Expected**: "고르게 할 때" 규칙(결정 하나 = 질문 하나, 추천 첫 보기, 질문 4개 초과는 중요한 것부터 4개씩 연달아, 보기 4개 초과는
  두 단계, 자유 입력은 추천값 보기 + 직접 입력, 보기 설명에 그 보기를 고르면 생길 문제를 막는 방법, 취소 · 무응답이면 멈춤,
  단계 밖 질문 · 자동 턴 포함, 도구가 없으면 번호 표)이
  한 곳에만 있고, 회귀 삭감 · 호스트 설정 계약 · SCV 원칙은 그곳을 가리킨다. 도움말 답 모양의 결정 자리는 규칙을 직접 적는다
  ("When the host names a choice tool, ask each decision through it instead" · 한 번에 네 질문) — 네 번째 결정, 잠금은 새 문구로
  다시. `help/full.md` 의 결정 표 · 회귀 삭감 표 · 질문 블록의 글 묻기는 규칙 문서가 대신한다고 선언한다(해소 순서 2 · 4). 도움말
  답 모양 검사(`test-help-shape.sh`) · 잠금 검사(`test-help-router-diet.sh`) · 규칙 헌법 검사(`test-rule-constitution.sh`) 통과.
- **Pass criterion**: 규칙 문장이 한 곳뿐 + 도움말 직접 적기 · 가리키기 · 대체 선언 확인 + 세 검사 통과.

### T10. 4개를 넘는 결정 — 4개씩 나눠 연달아 (설치본 실측)

- **Setup**: 설치본(클로드), 서로 독립인 결정 7개가 나오는 계획 단계 상황(다른 컴퓨터 화면과 같은 꼴).
- **Run**: 대화형 실행(tmux 로 띄운 세션 — 헤드리스에는 선택지 도구가 없다, T27) 후 실행 기록 확인.
- **Expected**: 선택지 도구 호출이 4개 + 3개로 두 번, 중요한 것부터, 각 질문의 첫 보기가 "(추천)".
- **Pass criterion**: 실행 기록에서 두 번의 호출과 보기 순서 확인.

### T11. 자유 입력 질문 — 추천값을 보기로 (설치본 실측)

- **Setup**: 계획 폴더 이름 · 제목을 묻는 단계.
- **Run**: 대화형 실행(tmux 로 띄운 세션 — 헤드리스에는 선택지 도구가 없다, T27) 후 실행 기록 확인.
- **Expected**: 추천 이름 1~2개가 보기로 나오고 첫 보기가 "(추천)". 글로 "이름을 알려 주세요"라고 묻지 않는다.
- **Pass criterion**: 실행 기록 확인.

### T12. 보기가 4개를 넘는 질문 — 두 단계로 (모델 정책)

- **Setup**: 클로드 래퍼의 모델 정책 지시문(보기 5개).
- **Run**: 지시문 검사 + 설치본에서 모델 정책 단계를 대화형(tmux)으로 실행.
- **Expected**: 지시문이 두 단계(묶음 → 그 안에서)로 묻고, 어느 단계도 보기가 4개를 넘지 않으며, 다섯 정책 모두 고를 수 있다.
- **Pass criterion**: 지시문 검사 통과 + 실행 기록에서 각 호출의 보기 수 ≤ 4.

### T13. 취소 · 무응답 — 멈추고 추천으로 진행하지 않는다

- **Setup**: 규칙 문장 + 종료 훅.
- **Run**: 문장 검사, 그리고 "고르지 않으셔서 여기서 멈춥니다." 로 끝나는 답의 종료 훅.
- **Expected**: 규칙에 "취소 · 무응답이면 추천값으로 진행하지 않고 한 줄로 알린 뒤 멈춘다(질문 문장으로 끝내지 않는다)"가 있고, 그
  답은 막히지 않는다.
- **Pass criterion**: 두 조건 모두.

### T14. 단계 밖 질문 — 작업 끝의 "다음에 무엇을 할까요?"

- **Setup**: SCV 단계 밖의 사람 턴, 마지막 답이 "다음에 무엇을 할까요?" 로 끝남.
- **Run**: 종료 훅.
- **Expected**: 막고, 이유에 선택지 도구 안내가 있다.
- **Pass criterion**: 막는 출력 확인.

### T15. 회귀 삭감 — 선택지로, CI 모드는 묻지 않음

- **Setup**: 코어 회귀 지시문 + 클로드 래퍼 회귀 지시문.
- **Run**: 문장 검사.
- **Expected**: 실패 슬러그 삼지선다(regression / obsolete / flaky)가 규칙 한 자리를 가리키고(도구 있으면 슬러그 하나 = 질문 하나,

- **Pass criterion**: 세 조건 모두.

### T16. 지킬 것 — 호스트 중립 · 정보 표 · 등록 흐름 · 매 턴 비용
