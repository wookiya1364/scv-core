# Test Plan — 결정은 고르는 선택지로 — 클로드에서 SCV 가 묻는 결정을 객관식으로 되돌린다

## Overview

호스트 설정에 선택지 도구가 있을 때(클로드) SCV 가 사용자에게 고르게 하는 모든 결정이 선택지 도구로 묻게 되는지 — 앞쪽 안내가
실리고, 글로 묻고 끝내면 종료 훅이 같은 턴에 한 번 막는지 — 와, 도구가 없을 때(코덱스 · 기본) 모든 출력이 지금과 같은지를 본다.
대화와 빈틈 질문에서 정한 것(범위 · 4개 초과 · 자유 입력 · 보기 5개 이상 · 취소 · 단계 밖 질문 · 강제 · 코덱스 · 확인 방법)이
하나씩 시나리오다(최소 요구 — 빼지 않는다). 검사 픽스처는 중립 도구 이름(`PickTool`)을 쓴다. 다섯 번째 요구(추정 해소)는
T27~T32 — 사람 없는 실행, 코덱스 모양 원본, 도구 출처 표시, 실제 긴 턴 모양, 판정 정확도 실측, 원인 실측이다.

## Test scenarios

### T1. 글로 묻는 답 판정 — 순수 함수 (잡을 것)

- **Setup**: 픽스처 답(독립 검토가 찾은 누락 모양 9개 — 질문 뒤 보기 목록 · 요청형 · 이모티콘 · 괄호 · 따옴표 — 를 더해 15개,
  C · UTF-8 로캘 같은 판정) — (a) 결정 표 뒤 "'다 추천대로'라고 하시거나, 바꿀 번호만 알려 주세요." (다른 컴퓨터 화면 문구)
  (b) "질문: 세 로컬 작업 폴더를 개발 브랜치 최신으로 옮겨 둘까요? (추천: 예)" 로 끝남 (c) `| # | 질문 | 추천 |` 표 + "번호로
  답해 주세요." (d) 영어 "Reply with the numbers" / "answer by number" (e) "Should I proceed?" 로 끝남.
- **Run**: 본문 추리기 → 묻나 판정.
- **Expected**: 다섯 경우 모두 1.
- **Pass criterion**: 모두 1.

### T2. 글로 묻는 답 판정 — 순수 함수 (잡지 않을 것)

- **Setup**: 픽스처 답(독립 검토가 찾은 오탐 모양 7개 — 되짚는 표 · 표 안 물음표 · 평서문 속 문구 · 정보 목록 — 를 더해 12개)
  — (a) 정보 표만(단위 표 · 결과 표, 예전 답의 문제 표 포함) (b) 물음표가 든 인용 줄 `> **다시 쓴 요청**: 다 끝난거 맞아?…`
  (c) 코드 블록 안의 물음표 (d) "고르지 않으셔서 여기서 멈춥니다." 같은 평서문 끝 (e) 본문 중간의 물음표, 끝은 평서문.
- **Run**: 본문 추리기 → 묻나 판정.
- **Expected**: 다섯 경우 모두 0.
- **Pass criterion**: 모두 0.

### T3. 막기 판정 — 순수 함수

- **Setup**: (묻나, 도구 이름, 계속 중) 조합.
- **Run**: 막기 판정.
- **Expected**: (1, PickTool, 0) → block, (1, PickTool, 1) → warn, (0, PickTool, *) → ok, (1, 빈 값, *) → ok.
- **Pass criterion**: 모든 조합이 기대값과 같다.

### T4. 종료 훅 — 글로 묻고 끝내면 같은 턴에 한 번 막는다 (강제)

- **Setup**: 호스트 설정 `PickTool`, 등록을 마친 사람 턴, 마지막 답 = T1(a).
- **Run**: 종료 훅 → 같은 입력에 `stop_hook_active: true` 로 다시 종료 훅.
- **Expected**: 첫 번째는 막는 출력(이유에 `PickTool` · "추천을 첫 보기" · "4개씩 나눠" 안내), 두 번째는 막지 않고 다음 턴 경고를
  남긴다.
- **Pass criterion**: 두 결과 모두.

### T5. 종료 훅 — 자동 알림 턴에도 적용

- **Setup**: 0.63.0 자동 알림 턴(호스트 설정 태그로 판별), 마지막 답 = T1(b).
- **Run**: 종료 훅.
- **Expected**: 등록 판정은 지금처럼 건너뛰고(`STOP_GATE: auto` 그대로), 선택지 판정은 막는다.
- **Pass criterion**: 두 조건 모두.

### T6. 종료 훅 — 선택지로 물은 턴 · 정보만 준 턴은 통과

- **Setup**: 마지막 답 = T2 의 다섯 경우, 그리고 선택지 도구로 물은 뒤 평서문으로 끝난 답.
- **Run**: 종료 훅.
- **Expected**: 막지 않는다.
- **Pass criterion**: 여섯 경우 모두 통과.

### T7. 도구가 없으면 지금과 같다 (코덱스 · 기본)

- **Setup**: 호스트 설정에 도구 이름 없음.
- **Run**: 매 턴 훅 · 도움말 출력 · 종료 훅(마지막 답 = T1 의 다섯 경우).
- **Expected**: 출력 · 판정이 이 계획 전과 바이트 단위로 같다(안내 줄 없음, 선택지 판정으로 막지 않음).
- **Pass criterion**: 이 계획 전 기대값과 같다.

### T8. 앞쪽 안내 — 도구가 있을 때만 한 줄

- **Setup**: 호스트 설정 `PickTool` / 없음.
- **Run**: 안내 한 줄 만들기(순수) + 그 줄이 실리는 자리(도움말 출력 또는 매 턴 블록) 실행.
- **Expected**: 있을 때 도구 이름과 규칙 요지(추천 첫 보기 · 4개씩 나눔 · 보기 5개 이상 두 단계 · 자유 입력은 추천값 보기 · 취소면
  멈춤)가 한 줄로 실린다. 없을 때 아무것도 없다. 자동 알림 턴에도 실린다(사용자 결정 — 단계 밖 · 자동 턴 포함).
- **Pass criterion**: 세 경우 모두.

### T9. 규칙 한 자리와 가리키기 — 도움말 결정 자리 · 회귀 삭감 · 질문 블록

- **Setup**: 코어 지시문.
- **Run**: 문장 검사.
- **Expected**: "고르게 할 때" 규칙(결정 하나 = 질문 하나, 추천 첫 보기, 질문 4개 초과는 중요한 것부터 4개씩 연달아, 보기 4개 초과는
  두 단계, 자유 입력은 추천값 보기 + 직접 입력, 보기 설명에 그 보기를 고르면 생길 문제를 막는 방법, 취소 · 무응답이면 멈춤,
  단계 밖 질문 · 자동 턴 포함, 도구가 없으면 번호 표)이
  한 곳에만 있고, 회귀 삭감 · 호스트 설정 계약 · SCV 원칙은 그곳을 가리킨다. 도움말 답 모양의 결정 자리는 규칙을 직접 적는다
  ("When the host names a choice tool, ask each decision through it instead" · 한 번에 네 질문) — 네 번째 결정, 잠금은 새 문구로
  다시. `help/full.md` 의 결정 표 · 회귀 삭감 표 · 질문 블록의 글 묻기는 규칙 문서가 대신한다고 선언한다(해소 순서 2 · 4). 도움말
  답 모양 검사(`test-help-shape.sh`) · 잠금 검사(`test-help-router-diet.sh`) · 규칙 헌법 검사(`test-rule-constitution.sh`) 통과.
- **Pass criterion**: 규칙 문장이 한 곳뿐 + 도움말 직접 적기 · 가리키기 · 대체 선언 확인 + 세 검사 통과.

### T10. 4개를 넘는 결정 — 4개씩 나눠 연달아 (설치본 실측)

- **Setup**: 설치본(클로드), 서로 독립인 결정 7개가 나오는 계획 단계 상황(다른 컴퓨터 화면과 같은 꼴).
- **Run**: 대화형 실행(tmux 로 띄운 세션 — 헤드리스에는 선택지 도구가 없다, T27) 후 실행 기록 확인.
- **Expected**: 선택지 도구 호출이 4개 + 3개로 두 번, 중요한 것부터, 각 질문의 첫 보기가 "(추천)".
- **Pass criterion**: 실행 기록에서 두 번의 호출과 보기 순서 확인.

### T11. 자유 입력 질문 — 추천값을 보기로 (설치본 실측)

- **Setup**: 계획 폴더 이름 · 제목을 묻는 단계.
- **Run**: 대화형 실행(tmux 로 띄운 세션 — 헤드리스에는 선택지 도구가 없다, T27) 후 실행 기록 확인.
- **Expected**: 추천 이름 1~2개가 보기로 나오고 첫 보기가 "(추천)". 글로 "이름을 알려 주세요"라고 묻지 않는다.
- **Pass criterion**: 실행 기록 확인.

### T12. 보기가 4개를 넘는 질문 — 두 단계로 (모델 정책)

- **Setup**: 클로드 래퍼의 모델 정책 지시문(보기 5개).
- **Run**: 지시문 검사 + 설치본에서 모델 정책 단계를 대화형(tmux)으로 실행.
- **Expected**: 지시문이 두 단계(묶음 → 그 안에서)로 묻고, 어느 단계도 보기가 4개를 넘지 않으며, 다섯 정책 모두 고를 수 있다.
- **Pass criterion**: 지시문 검사 통과 + 실행 기록에서 각 호출의 보기 수 ≤ 4.

### T13. 취소 · 무응답 — 멈추고 추천으로 진행하지 않는다

- **Setup**: 규칙 문장 + 종료 훅.
- **Run**: 문장 검사, 그리고 "고르지 않으셔서 여기서 멈춥니다." 로 끝나는 답의 종료 훅.
- **Expected**: 규칙에 "취소 · 무응답이면 추천값으로 진행하지 않고 한 줄로 알린 뒤 멈춘다(질문 문장으로 끝내지 않는다)"가 있고, 그
  답은 막히지 않는다.
- **Pass criterion**: 두 조건 모두.

### T14. 단계 밖 질문 — 작업 끝의 "다음에 무엇을 할까요?"

- **Setup**: SCV 단계 밖의 사람 턴, 마지막 답이 "다음에 무엇을 할까요?" 로 끝남.
- **Run**: 종료 훅.
- **Expected**: 막고, 이유에 선택지 도구 안내가 있다.
- **Pass criterion**: 막는 출력 확인.

### T15. 회귀 삭감 — 선택지로, CI 모드는 묻지 않음

- **Setup**: 코어 회귀 지시문 + 클로드 래퍼 회귀 지시문.
- **Run**: 문장 검사.
- **Expected**: 실패 슬러그 삼지선다(regression / obsolete / flaky)가 규칙 한 자리를 가리키고(도구 있으면 슬러그 하나 = 질문 하나,
  4개씩 나눠), 래퍼의 설명과 본문이 같은 말을 한다. CI 모드 "묻지 않는다" 문장은 그대로.
- **Pass criterion**: 세 조건 모두.

### T16. 지킬 것 — 호스트 중립 · 정보 표 · 등록 흐름 · 매 턴 비용

- **Setup**: 저장소 전체.
- **Run**: `tests/test-host-neutral.sh`, `core/tests/test-model-prompting.sh`, `core/tests/test-help-budget.sh`, 원칙 · 답 모양 검사.
- **Expected**: 코어에 클로드 도구 이름 없음, 원칙 문구는 T21 대로만 바뀌고 그 밖의 정보 표 문장은 그대로, 등록 · 인용 · 종료 차단 · 자동 턴 검사
  통과, 매 턴 스택이 상한(12,000B) 안 — 선택지 도구가 있는 설정으로도 잰다(넘으면 사용자에게 묻고 멈춤).
- **Pass criterion**: 모두 통과.

### T17. 두 호스트 · 두 OS · 전체 검사

- **Setup**: 코덱스 벤더 도구로 만든 임시 사본, 맥 기본 bash 3.2 · 최신 bash, CI 두 OS.
- **Run**: 사본에서 코어 검사 전부, 새 검사를 두 bash 로(새 변수를 비운 채로도 한 번), CI 와 같은 순서의 전체 검사.
- **Expected**: 모두 통과. CI 두 OS 로그에서 새 검사 줄이 각각 보인다.
- **Pass criterion**: 실패 0, 로그 두 곳 확인.

### T18. 설치본 실측 — 대화형(tmux) + 헤드리스 + 사용자 직접 한 번

- **Setup**: 릴리스한 클로드 래퍼를 설치한 임시 저장소.
- **Run**: 대화형(tmux 로 띄운 세션)으로 (a) 서로 독립인 결정 여러 개가 나오는 도움말 턴 (b) 글로 묻고 끝내도록 유도한 턴.
  헤드리스로 (c) 인용을 보인 뒤 계획 단계를 불러오는 턴(도움말 → 계획 넘김) (d) 풀 문제가 있는 사람 턴 (e) 끝 메시지에 문제 표를
  넣게 한 턴 (f) 글로 묻고 끝내게 한 턴(사람 없는 실행). 그다음 사용자가 대화형 화면에서 결정이 나오는 턴을 한 번 직접 보고, 화면이
  나왔던 다른 컴퓨터에서도 새 버전 설치 뒤 한 번 본다(사용자만 할 수 있다).
- **Expected**: (a) 선택지 도구 호출이 기록되고 첫 보기가 "(추천)" (b) 같은 턴에 막힌 뒤 선택지 도구로 다시 묻는다 (c) 인용
  때문에 막히지 않는다 (d) 등록 결과에 새 원칙(세 칸 단위 표, 문제 표 없음)과 새 표식이 실린다 (e) 같은 턴에 막힌다 (f) 매 턴
  훅에 선택지 안내 줄이 없고 막히지 않는다. 사용자 화면에 고르는 선택지가 뜬다.
- **Pass criterion**: 실행 기록 여섯 건 확인 + 사용자 확인.

### T19. 턴 자르기 — 내부 메시지는 사람 프롬프트가 아니다 (두 번째 결함)

- **Setup**: 원본 픽스처 — 사람 프롬프트 → 인용을 보인 답 → 내부 표시가 붙은 사용자 몫 메시지(스킬 불러오기) → 도구 결과 →
  인용 없는 마지막 답. 그리고 같은 모양에서 내부 메시지 대신 진짜 사람 프롬프트가 온 경우.
- **Run**: 턴 스트림 만들기 → 턴 자르기 → 종료 훅의 등록 · 인용 판정.
- **Expected**: 내부 메시지는 경계가 아니다 — 앞서 보인 인용이 인정되어 막지 않는다. 진짜 사람 프롬프트가 오면 지금처럼 그 뒤만
  이번 턴이다. 도구 결과는 지금처럼 경계가 아니다. 내부 표시가 없는 원본(코덱스 모양)의 결과는 이 계획 전과 같다.
- **Pass criterion**: 네 경우 모두 기대대로 + 답 모양 검사 출처 검사(`test-answer-lint-source.sh`) 통과.

### T20. 긴 턴 — 원본 창을 넘어도 이번 사람 턴의 인용을 인정

- **Setup**: 사람 프롬프트와 인용 뒤로 줄이 400줄을 넘게 쌓인 원본(선택지 질문 · 도구 결과가 많은 턴).
- **Run**: 종료 훅.
- **Expected**: 이번 사람 턴의 경계를 찾아, 앞서 보인 인용 때문에 막지 않는다. 경계를 끝내 못 찾으면 지금처럼 안전 쪽(마지막
  메시지만 봄)으로 동작하고, 그 사실이 판정 기록에 남는다.
- **Pass criterion**: 두 경우 모두 기대대로.

### T21. SCV 원칙 문구 — 단위 표 세 칸, 문제 표 없음 (세 번째 요구)

- **Setup**: 원칙 파일의 한국어 · 영어 · 일본어 구역.
- **Run**: 원칙 검사(모델별 프롬프팅 검사의 원칙 부분을 새 문구에 맞춰 갱신).
- **Expected**: 세 구역 모두 — 단위 표가 '단위 | 해결책 | 추천' 세 칸, 해결책은 각 방법이 부를 문제를 막는 길까지 담음, 문제를
  따로 나열하지 않음, 막을 수 없는 것 중 정할 것은 "고르게 할 때" 규칙을 가리킴, 남는 한계는 추천 칸 이유에 한 줄. 문제 표 ·
  '생길 수 있는 문제' · 위치 표시(파일:줄 · 확인 칸) 문장이 없다. 표식은 '[SCV 원칙 적용 — 단위 표]'(영어 · 일본어 대응). 원칙
  파일 머리말의 "두 표" 설명도 단위 표 하나로 맞는다.
- **Pass criterion**: 세 구역 모두 기대대로 + 갱신한 검사 통과.

### T22. 등록 결과 · 설정 예시 · 스위치

- **Setup**: 요구 항목 목록이 있는 임시 저장소, 설정 `SCV_LANG` korean / english, 원칙 스위치 on / off.
- **Run**: 등록 → 출력 확인. 설정 예시의 원칙 설명과 템플릿 지문 검사.
- **Expected**: on — 다시 쓴 요청 끝에 새 표식, `PRINCIPLE:` 아래 새 전문(해당 언어). off — 원칙이 없던 때와 같은 출력. 설정 예시
  설명에 '문제 표'가 없고 템플릿 지문 검사가 통과한다.
- **Pass criterion**: 네 경우 모두 기대대로.

### T23. 문제 표 · '생길 수 있는 문제' 칸 막기 (네 번째 결정)

- **Setup**: 판정 픽스처 — 잡을 것: 한 · 영 · 일 각각 문제 칸이 있는 단위 표 머리, 문제 표 머리('위치'+'깨지는 것' 칸). 잡지 않을
  것: 세 칸 단위 표, 코드 블록 안, 인용 줄, 문제를 말하는 줄글. 종료 훅 — 등록을 마친 사람 턴(원칙 on).
- **Run**: 판정 함수, 그리고 종료 훅(문제 칸이 있는 끝 메시지 · 계속 중 · 글 질문과 함께 · 원칙 스위치 off · 원칙이 안 실리는 호스트).
- **Expected**: 판정 10개가 기대대로. 막음(이유에 "해결책 안에서 막아") · 계속 중이면 다음 턴 경고 · 글 질문과 함께면 원칙 이유
  하나만 · off 와 안 실리는 호스트는 판정 없음.
- **Pass criterion**: 모두 기대대로.

### T24. 도움말 직접 적기 · 상한 (네 번째 결정)

- **Setup**: 도움말 규약, 잠금 지문 파일, 비용 검사.
- **Run**: `test-help-router-diet.sh`, `test-help-budget.sh`, `test-help-shape.sh`.
- **Expected**: 도움말 원본 ≤ 7,600B(사본 ≤ 8,000B), 답 모양 절 지문이 새 문구와 일치(언어 · 쉬운 말 절은 이전 지문 그대로),
  규약 합계 ≤ 33,000B, 매 턴 ≤ 12,000B(선택지 도구가 있을 때 포함), 답 모양 절에 차단 · 되돌림 문구 없음.
- **Pass criterion**: 세 검사 통과.

### T25. 프로젝트 스위치 · 끝 메시지 없음 · 실행부 인자 (독립 검토 반영)

- **Setup**: 선택지 도구가 있는 설정, 설정 `SCV_CHOICE_GATE=off` 인 저장소, 끝 메시지를 주지 않는 종료 훅 입력.
- **Run**: 매 턴 훅 · 종료 훅, 그리고 값 없는 `--active` 로 실행부.
- **Expected**: off 면 안내 줄 없음 · 글로 물어도 막지 않음. 끝 메시지가 없으면 원본의 앞선 글로 판정하지 않는다. 실행부는
  멈추지 않고 끝난다. 다음 턴 경고는 컨텍스트 초기화 뒤에도 남는다.
- **Pass criterion**: 모두 기대대로.

### T26. 긴 턴 — 종료 훅이 빠르다 (독립 검토 반영)

- **Setup**: 사람 프롬프트 하나 뒤로 답 1,500개 · 도구 호출이 쌓인 4,500줄 원본, 그리고 사람 프롬프트 없이 내부 메시지(종료 훅
  피드백)가 반복되는 4만 줄 원본(실측용).
- **Run**: 종료 훅.
- **Expected**: 앞서 보인 인용을 찾고 막지 않는다, 30초 안에 끝난다(실측: 4만 줄 원본에서 고치기 전 22 · 45초 → 약 1초).
- **Pass criterion**: 판정과 시간 모두.

### T27. 사람 없는 실행 — 안내도 막기도 없다 (다섯 번째 요구)

- **Setup**: 호스트 설정 `PickTool` + `SCV_CHOICE_OFF_WHEN=SCV_TEST_ATTENDED=0`. 그 환경 변수가 0 · 1 · 없음인 실행.
- **Run**: 조건 판정 함수(순수), 매 턴 훅, 종료 훅(마지막 답이 글 질문).
- **Expected**: 순수 판정 — 값이 같을 때만 1, 다르거나 비었거나 조건이 없거나 모양이 틀리면 0. 0 인 실행 — 안내 줄 없음 · 막지
  않음. 1 · 없음 — 지금처럼 안내 줄이 실리고 막는다. 검사기는 "이름=값" 하나만 받고 구체화에서 키가 살아남는다.
- **Pass criterion**: 모두 기대대로 + `tests/test-profile-and-export.sh` 통과.

### T28. 코덱스 모양 원본 — 넓혀 찾지 않고, 판정은 이 기능 전과 같다 (다섯 번째 요구)

- **Setup**: 최상위 type 이 response_item · event_msg 인 4만 5천 줄 원본(코덱스 세션 기록 모양), 등록을 마친 사람 턴.
- **Run**: 종료 훅 — 끝 메시지에 인용이 있을 때 / 없을 때.
- **Expected**: 있으면 통과, 없으면 이 기능 전처럼 막는다(끝 메시지로만 판정). 판정 기록에 '경계 없음' 줄을 남기지 않는다.
  10초 안에 끝난다.
- **Pass criterion**: 세 조건 모두.

### T29. 도구 출처 표시만 있는 사용자 몫 글도 경계가 아니다 (다섯 번째 요구)

- **Setup**: T19(a)와 같은 원본에서 스킬 불러오기 줄에 내부 표시 없이 도구 출처 표시만 둔다.
- **Run**: 종료 훅.
- **Expected**: 앞서 보인 인용을 인정해 막지 않는다.
- **Pass criterion**: 막지 않음.

### T30. 실제 긴 턴 모양 — 이전 종료 훅이 막은 꼴을 잠근다 (다섯 번째 요구)

- **Setup**: 이 릴리스를 마무리하던 세션의 원본 모양 — 467줄, 16번째 줄 사람 프롬프트, 43번째 줄 스킬 불러오기(내부 표시 + 도구
  출처), 231번째 줄 인용, 끝 400줄 안에는 사람 프롬프트 없음, 끝은 인용 없는 답.
- **Run**: 모양 확인 + 종료 훅.
- **Expected**: 모양이 그대로이고, 종료 훅이 넓혀 찾아 16번째 줄을 경계로 삼아 막지 않는다.
- **Pass criterion**: 두 조건 모두.

### T31. 판정 정확도 — 실제 답 모음 실측 (다섯 번째 요구)

- **Setup**: 이 컴퓨터에 남은 클로드 세션 원본(사람 턴마다 마지막 답).
- **Run**: 글 질문 판정을 모두에 돌려 잡은 것 전부와, 놓쳤을 만한 것(끝 줄 물음표 · 요청형 꼬리 등)을 하나씩 본다.
- **Expected**: 잘못 잡은 것 · 놓친 것의 수와 모양이 기록되고, 고친 모양은 T1 · T2 픽스처에 더해져 잠긴다. 남는 한계는 잰 비율로
  CHANGELOG 에 적는다.
- **Pass criterion**: 실측 기록 + 더한 픽스처 통과.

### T32. 원인 실측 — 매 턴 규칙이 질문을 글로 바꿨나 (다섯 번째 요구)

- **Setup**: 설치본 0.63.0 을 쓰는 임시 저장소, tmux 로 띄운 대화형 세션, 서로 독립인 결정이 나오는 같은 요청.
- **Run**: (1) 설정 그대로 (2) 매 턴 규칙을 끈 상태(항상 켜짐 · 쉬운 말 · 원칙 스위치 off). 각 턴의 실행 기록을 본다.
- **Expected**: 결정을 선택지 도구로 물었는지 글로 물었는지가 두 경우 각각 기록된다. 결과가 원인 추정을 지지하는지 아닌지를 대화
  기록과 CHANGELOG 에 적는다(어느 쪽이든 고친 동작은 같다 — 종료 훅이 막는다).
- **Pass criterion**: 두 실행 기록 확인.

### T33. 맥 기본 bash 3.2 — 긴 답 · 긴 턴의 종료 훅이 빠르고, 매 턴 출력이 같다 (다섯 번째 요구, 검증 중 찾음)

- **Setup**: 시스템 bash(/bin/bash — 맥은 3.2)로 도는 훅, 답 하나 10만 바이트 원본, 4,500줄 긴 턴 원본(T26), 등록을 마친 사람 턴.
- **Run**: 종료 훅 두 번, 그리고 매 턴 훅을 시스템 bash 와 지금 bash 로 한 번씩.
- **Expected**: 두 종료 훅 모두 30초 안에 끝나고 앞서 보인 인용을 인정해 막지 않는다(고치기 전 158초 · 79초). 매 턴 출력이 두 bash
  에서 바이트로 같고 모델 id 자리 표시에 역슬래시가 없다. 턴 자르기의 줄바꿈 되돌리기는 경계 경우 8가지에서 치환과 같다.
- **Pass criterion**: 셋 모두 — 맥 CI 로그에서 확인(리눅스의 /bin/bash 는 최신이라 그냥 통과).
