# 맥 검사의 시간 한도 둘

## Summary

맥 러너에서 도는 검사 둘이 시간 한도에 바짝 붙어 있다. 코어 PR 검사의 맥 조각은 가장 긴 것이 455 ~ 577초(한도 600초)이고, 클로드 래퍼의 맥 검사는 142 ~ 340초에 380초로 한 번 끊겼다(한도 360초).
코어는 맥 조각을 5개에서 7개로 늘리고 한도를 15분으로 올린다. 래퍼는 맥 검사의 한도를 10분으로 올린다.

## Goals / Non-Goals

- **Goals**
  - 코어 PR 검사의 맥 조각을 7개로 나눈다 (이름 · 조각 목록 · 명령의 조각 수가 모두 7)
  - 맥 조각 작업의 시간 한도를 10분에서 15분으로 올린다
  - 맥 조각의 수가 이름 · 목록 · 명령에서 어긋나면 잡는 시험을 더하고, 시간표 균형 검사를 7조각으로 본다
  - 클로드 래퍼의 맥 검사 한도를 6분에서 10분으로 올리고, 한도를 지키는 시험을 그에 맞춘다
  - 올린 PR 에서 맥 조각 7개의 실제 시간을 읽어 이 계획에 적는다
- **Non-Goals**
  - 시험 자체를 빠르게 고치기
  - 래퍼의 시험을 실행기로 돌리기 (사용자 선택 2026-11-12: 한도만)
  - 코덱스 래퍼의 검사
  - 리눅스 조각 수 · 릴리스 검증 조각 수 바꾸기

## Approach Overview

사용자가 2026-11-12 선택 창에서 정한 것: 코어 맥 조각 "조각 7 + 한도 15분", 래퍼 맥 검사 "한도 6분 → 10분", 릴리스 "넷을 끝낸 뒤 한 번", 그림 "넷 다 그림 없이", 마무리 "합치기까지 자동".

읽은 값 (2026-11-12):

| 어디 | 한도 | 걸린 시간 | 출처 |
|---|---|---|---|
| 코어 맥 조각(5개) | 600초 | 실행마다 가장 긴 조각 469 · 455 · 531초, 메모의 577초 | 실행 43165213608 · 43172942509 · 43188841329 |
| 클로드 래퍼 맥 검사 | 360초 | 최근 여덟 번 142 ~ 340초, 380초 · 397초로 끊긴 적 있음 | 래퍼의 검사 기록, 메모 |

- 코어 맥 조각은 시험 단계가 거의 전부다(531초 가운데 506초, 준비 17초).
- 맥 시간표의 합은 1,696초, 가장 긴 시험은 165초다. 7조각이면 조각 평균 242초로, 가장 긴 시험보다 길다(고르게 나눌 수 있다).
- 같은 시험도 러너에 따라 1.3 ~ 1.6배 걸린다(시간표 평균 339초인 조각이 실제로는 437 ~ 531초).
- 합치려면 통과해야 하는 검사는 조각을 모으는 검사뿐이다(보호 규칙 `protect-permanent-branches`) — 조각 수를 바꿔도 이름이 그대로다.
- 래퍼의 한도를 지키는 시험은 "자동으로 도는 모든 작업의 한도가 6분"을 글자로 본다(`.github/scripts/test-ci-fast-lanes.sh`). 래퍼의 맥 · 리눅스 검사는 한 작업의 두 갈래다.

하는 일:

1. **코어 설정** — 맥 조각 작업의 이름 · 조각 목록 · 명령을 7로, 한도를 15분으로.
2. **코어 시험** — 맥 조각의 수가 세 곳에서 같은지, 한도가 15분인지 보는 확인을 더한다. 시간표 균형 검사는 설정에서 읽은 조각 수로 본다.
3. **래퍼 설정** — 맥 갈래만 10분, 리눅스 갈래는 6분 그대로.
4. **래퍼 시험** — 한도를 지키는 시험이 "맥 검사는 10분, 나머지는 6분"을 보게 한다.
5. **재기** — 코어 PR 의 맥 조각 7개의 실제 시간을 읽어 적는다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

이 계획은 설정 값을 고친다. 새 파이프라인은 없고, 이미 있는 조각 실행기의 줄에서 "몇 조각으로 나누는가"라는 입력만 바뀐다. 시험에는 설정 글에서 문제를 찾아내는 함수 하나를 더한다.

```
flow(
  rf_list_tests,   // 시험 폴더들 → '경로<탭>표시' 줄              (입구, 그대로)
  rf_classify,     // → 'parallel|serial<탭>경로'                  (순수, 그대로)
  rf_partition,    // 줄 + 맥 시간표 + I + 7 → 조각 I 의 줄        (순수, 그대로 — N 이 5 에서 7 로)
  rf_run_one,      // 시험 경로 → 로그 · 결과 줄                    (부수효과, 그대로)
  rf_summarize,    // 결과 줄 → 표 줄 + 합계                        (순수, 그대로)
  rf_report,       // 표 줄 → 출력 + 끝 코드                        (출구, 그대로)
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | rf_partition | 시간표로 시험을 조각에 고르게 나눈다 — 맥은 7조각 | 줄 · 시간표 · 조각 번호 · 7 → 그 조각의 줄 | 순수 |
| 2 | mac_problems | PR 검사 설정에서 맥 조각의 어긋남(이름 · 목록 · 명령의 수, 한도)을 찾는다 | 설정 파일 → 문제 줄들 | 부수효과 (입구: 파일 읽기) |

- 부수효과 위치: 시험의 `mac_problems` 가 설정 파일을 읽는다. 실행기는 고치지 않는다.
- 재사용: 조각 실행기 전부, 시험의 `job_block`(작업 하나의 글 꺼내기) · `check_table`(시간표 균형).

| # | 물음 | 답 | 근거 |

## Guardrails

- 합치는 데 필요한 검사의 이름(`Contracts (macos-latest)` 등)을 바꾸지 않는다.
- 리눅스 조각(6)과 릴리스 검증 조각(8)은 건드리지 않는다.
- 래퍼의 리눅스 갈래 한도는 6분 그대로 둔다.
- 래퍼에서는 설정 한 줄과 그 시험만 고친다 — 가져온 코어(vendor)는 손대지 않는다.
- 저장소의 보호 규칙 · 설정은 고치지 않는다.

## Exit criteria

- TESTS.md 의 T1 ~ T6 이 통과한다
- 코어 PR 의 맥 조각 7개가 모두 통과하고, 그 시간이 이 계획에 적혀 있다
- 래퍼 PR 의 검사가 통과하고 develop 에 합쳐져 있다

## Suggested path

1. 코어 PR 검사 설정의 맥 조각을 7개 · 한도 15분으로 고친다 — `rf_partition`
2. 맥 조각의 수와 한도를 지키는 확인을 시험에 더하고, 시간표 균형을 7조각으로 본다 — `mac_problems`
3. 두 셸에서 관련 시험을 돌린다 — 통과를 확인하는 일
4. 래퍼의 맥 검사 한도를 10분으로 고치고 한도를 지키는 시험을 맞춘다 — 옆 저장소의 설정 한 줄과 시험을 고치는 일
5. 코어 PR 을 올려 맥 조각 7개의 실제 시간을 읽고 이 계획에 적는다 — 실제 러너에서 값을 재는 일
6. 래퍼 PR 을 올려 검사 결과를 읽고 합친다 — 옆 저장소에서의 통과를 확인하는 일

## Risks / Open Questions

- 맥 러너가 모자랄 때가 있다(2026-11-05, 작업이 러너를 받지 못해 취소됨). 조각이 5에서 7이 되면 한 번에 필요한 맥 러너가 2대 늘어난다. 받지 못한 작업은 이미 있는 자동 다시 돌리기가 맡는다.
- 한도 15분은 멈춘 시험을 알아채는 데 5분이 더 걸린다는 뜻이다. 조각을 늘린 뒤의 실제 시간을 적어 두면 다음에 한도를 다시 정할 근거가 된다.
- 맥 시간표의 값은 예전 실행의 것이다. 조각이 쏠리면 이 PR 의 실행 기록으로 다시 적는다.
