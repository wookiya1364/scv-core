# 고친 턴은 계획 기록이 있어야 끝남 · 선택 답은 계획에 바로 · 대시보드에 이력

## Summary

계획 없이 하는 일이 많다. 2026-11-09 실측: slay 의 계획 밖 코드 턴 11개 중 그 턴에 계획을 함께 고친 것 0개, 강의 · 공고 자동화는 고친 턴 41 · 6 개가 모두 계획 없이 진행, slay 의 오늘 선택 답 17개 중 다음 답 전에 계획에 들어간 것 5개, 대시보드에 보인 오늘 결정 0개.
턴이 끝날 때 '이번 턴에 무언가 바뀌었는데 계획 기록이 없으면 끝내지 못하게' 하고, 선택 답은 훅이 계획에 바로 적고, 대시보드가 그 이력을 보여 준다. 시제품 3판으로 잰 결과(slay 11/11 · 강의 41/41 · 공고 6/6 잡음, 턴당 0.2초 안쪽)를 그대로 옮긴다.

## Goals / Non-Goals

- **Goals**
  - 무언가를 고친 턴(코드 · scv/ 밖 문서)은 계획 기록이 남아야 끝남 — 기록 = 성공한 plan-link 명령 + 이번 턴 요청 번호가 든 구조 줄(추가 · 보류 · 연결 · 재개 · 진행)
  - 계획 안 일은 진행 한 줄(`plan-link.sh progress`)로 통과 — 명령 한 번
  - 모든 기록 줄에 이번 턴 사용자 원문이 자동으로 붙음 — 엉터리 내용도 무엇을 요청받았는지는 늘 보임
  - git 아닌 폴더 · 작업 공간의 다른 저장소(설정 목록 + 그 턴에 건드린 폴더)도 검사
  - 선택 답이 나오면 훅이 질문 · 답을 진행 중 계획의 `## 변경 이력` 에 바로 적음
  - 대시보드(scv-mods)가 변경 이력을 최근 것부터 보여 주고, `2b.` 같은 단계 번호도 단계로 보여 줌
  - 처음부터 켜 둠, 끄는 설정 하나
- **Non-Goals**
  - 기록 내용이 좋은지 판단하기 — 낱말 겹침 실측에서 진짜 기록 2/5 를 잘못 막아 버림. 원문 첨부로 드러내기만 함
  - 같은 폴더에서 동시에 도는 두 세션의 변경 구분
  - 0.86.0 plan-link 기존 명령의 동작 바꾸기 — 예외: append 의 Non-Goals 겹침 검사(2026-11-09 사용자 결정, 검증 X2)

## Approach Overview

- 턴 시작(UserPromptSubmit)에 작업 공간 사진을 찍는다: git 저장소는 `git status` 변경 파일 해시 + HEAD, git 아닌 폴더는 파일 목록 · 수정 시각 · 크기. 작업 공간 = 이 프로젝트 + 설정 목록 저장소. 그 턴에 도구가 경로로 건드린 저장소는 그 도구가 돌기 전(PreToolUse)에 사진을 더 찍는다.
- 영수증: PreToolUse(claude 는 PostToolUse 로 성공까지)에서 명령이 `bash <절대경로>/plan-link.sh (append|pause|resume|progress|exempt)` 로 시작할 때만 이번 턴 영수증을 남긴다. 이름만 적은 명령은 영수증이 없다(실측 H3).
- plan-link 에 `progress`(계획 안 진행 한 줄)와 `exempt`(릴리스 · 동기화처럼 정한 종류만, 이유와 함께) 명령을 더한다. 모든 기록 줄 끝에 `(요청 <번호>)` 와 사용자 원문 앞부분을 붙인다 — 원문은 훅이 남긴 기록 파일 경로에서 꺼낸다.
- 턴 끝(Stop): 사진 차이로 바뀐 파일을 구한다(scv/ · 호스트 설정 제외, scv/ 밖 .md 포함). 바뀐 파일이 있으면 영수증 · 요청 번호 줄 · 구조 줄이 모두 있어야 통과. 아니면 막고 무엇을 하면 되는지 한 줄로 말한다. 연속 2번 막히면 통과시키되 '계획 기록 없음' 을 저널과 계획(있으면)에 남긴다.
- 진행 중 계획이 없는데 바뀐 파일이 있으면: 계획을 만들거나(promote) 정한 예외로 `exempt` 를 쓰라고 막는다.
- 선택 답: claude 는 PostToolUse(AskUserQuestion) 훅이 질문 · 답을 `## 변경 이력` 에 바로 적는다. codex 는 PostToolUse 가 없어 턴 끝에 기록 파일에서 꺼내 적는다(확인할 것).
- 대시보드는 scv-mods 저장소에서 따로 PR — `## 변경 이력` 절 읽기 + 단계 번호 정규식에 글자 허용.
- 설정: `SCV_TURN_PLAN_CHECK=on`(기본) | `off`, `SCV_WORKSPACE_REPOS=<절대경로:…>`.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
// 턴 시작 · 도구 앞
flow(
  readTree,        // 부수효과 입구: (폴더) → 파일 목록 + 해시/시각
  snapTurn,        // (파일 목록) → 사진 줄들 "경로 지문"
  writeSnap,       // 부수효과 출구: 사진 → 턴 폴더
)
// 도구 실행 확인
flow(
  mintPlanReceipt, // (명령 글, 끝 코드) → 영수증 줄 | 없음
)
// 기록 줄 만들기 (plan-link progress · 모든 기록)
flow(
  attachRequest,   // (기록 줄, 요청 번호, 원문) → 번호 · 원문이 붙은 줄
  progressLine,    // (계획 글, 단계, 메모) → 진행 줄이 더해진 계획 글
)
// 턴 끝
flow(
  readSnaps,       // 부수효과 입구: 턴 폴더 → 시작 사진 · 지금 사진 · 영수증 · 계획 글
  diffTurn,        // (시작 사진, 지금 사진) → 바뀐 파일 목록 (제외 규칙 적용)
  judgeTurn,       // (바뀐 파일, 영수증, 새 계획 줄, 요청 번호, 막힌 횟수) → PASS | BLOCK(이유) | PASS-기록없음
  emitDecision,    // 부수효과 출구: 판정 → 호스트 응답 · 저널
)
// 선택 답
flow(
  recordChoice,    // (계획 글, 시각, 질문, 답) → 이력 줄이 더해진 계획 글
)
```

| 4 | attachRequest | 기록 줄에 요청 번호와 원문 앞부분을 붙임 | 줄 · 번호 · 원문 → 줄 | 순수 |

- 재사용: 0.86.0 `lib/plan-link.sh` 의 `scv_plan_history_add` · `scv_plan_fm_*`, `lib/model-prompting.sh` 의 턴 폴더(`scv_mp_turn_dir`), guard 의 영수증 저장소 규칙.

## Guardrails

- 0.86.0 plan-link 기존 명령의 출력 · 끝 코드를 바꾸지 않음 — 새 명령만 더함
- guard 의 기존 규칙과 영수증 저장소를 바꾸지 않음 — 계획 기록 영수증은 따로 둠
- 사진은 턴당 0.3초를 넘기지 않음(실측 0.18초) — 파일마다 프로세스를 띄우지 않음(첫판 4.7초의 원인)
- 맥 · 리눅스 둘 다: `stat` · `sed -i` · `find` 의 BSD/GNU 차이를 감싸서 씀, bash 3.2
- 막는 말은 한 줄로 무엇을 하면 되는지까지 — 예: `plan-link.sh progress <계획> --step N --note …`
- 사용자 전역 설정을 건드리지 않음

## Exit criteria

- All TESTS.md scenarios pass
- 오늘 장면(A · B · C · D · D2 · E · F · G · H · H2 · H3 · B2 · J · K · P)이 시제품과 같은 판정
- 네 세션 다시 세기(로컬 기록, 측정 단계): slay 11/11 · 강의 41/41 · 공고 6/6, 이 세션 계획 안 턴 막힘 0
- 실제 세션 하나에서 막힘 → 진행 한 줄 → 통과가 한 번 이상 일어남을 확인

## Suggested path

1. 턴 사진 — git · git 아님 · 작업 공간 저장소, 도구 앞 추가 사진 — `readTree`, `snapTurn`
2. 계획 기록 영수증 — 성공한 plan-link 명령만 — `mintPlanReceipt`
3. plan-link `progress` · `exempt` 와 요청 번호 · 원문 자동 첨부 — `attachRequest`, `progressLine`
4. 턴 끝 판정과 막는 말, 2번 막히면 기록 없음 표시 — `diffTurn`, `judgeTurn`, `emitDecision`
5. 선택 답 자동 기록 — `recordChoice`
6. 두 래퍼 훅 연결(claude · codex)과 설정 두 개 — 훅 목록에 턴 시작 · 도구 앞뒤 · 턴 끝 연결을 더함

# 고친 턴은 계획 기록이 있어야 끝남 · 선택 답은 계획에 바로 · 대시보드에 이력

## Summary

계획 없이 하는 일이 많다. 2026-11-09 실측: slay 의 계획 밖 코드 턴 11개 중 그 턴에 계획을 함께 고친 것 0개, 강의 · 공고 자동화는 고친 턴 41 · 6 개가 모두 계획 없이 진행, slay 의 오늘 선택 답 17개 중 다음 답 전에 계획에 들어간 것 5개, 대시보드에 보인 오늘 결정 0개.
턴이 끝날 때 '이번 턴에 무언가 바뀌었는데 계획 기록이 없으면 끝내지 못하게' 하고, 선택 답은 훅이 계획에 바로 적고, 대시보드가 그 이력을 보여 준다. 시제품 3판으로 잰 결과(slay 11/11 · 강의 41/41 · 공고 6/6 잡음, 턴당 0.2초 안쪽)를 그대로 옮긴다.

## Goals / Non-Goals

- **Goals**
  - 무언가를 고친 턴(코드 · scv/ 밖 문서)은 계획 기록이 남아야 끝남 — 기록 = 성공한 plan-link 명령 + 이번 턴 요청 번호가 든 구조 줄(추가 · 보류 · 연결 · 재개 · 진행)
  - 계획 안 일은 진행 한 줄(`plan-link.sh progress`)로 통과 — 명령 한 번
  - 모든 기록 줄에 이번 턴 사용자 원문이 자동으로 붙음 — 엉터리 내용도 무엇을 요청받았는지는 늘 보임
  - git 아닌 폴더 · 작업 공간의 다른 저장소(설정 목록 + 그 턴에 건드린 폴더)도 검사
  - 선택 답이 나오면 훅이 질문 · 답을 진행 중 계획의 `## 변경 이력` 에 바로 적음
  - 대시보드(scv-mods)가 변경 이력을 최근 것부터 보여 주고, `2b.` 같은 단계 번호도 단계로 보여 줌
  - 처음부터 켜 둠, 끄는 설정 하나
- **Non-Goals**
  - 기록 내용이 좋은지 판단하기 — 낱말 겹침 실측에서 진짜 기록 2/5 를 잘못 막아 버림. 원문 첨부로 드러내기만 함
  - 같은 폴더에서 동시에 도는 두 세션의 변경 구분
  - 0.86.0 plan-link 기존 명령의 동작 바꾸기 — 예외: append 의 Non-Goals 겹침 검사(2026-11-09 사용자 결정, 검증 X2)

## Approach Overview

- 턴 시작(UserPromptSubmit)에 작업 공간 사진을 찍는다: git 저장소는 `git status` 변경 파일 해시 + HEAD, git 아닌 폴더는 파일 목록 · 수정 시각 · 크기. 작업 공간 = 이 프로젝트 + 설정 목록 저장소. 그 턴에 도구가 경로로 건드린 저장소는 그 도구가 돌기 전(PreToolUse)에 사진을 더 찍는다.
- 영수증: PreToolUse(claude 는 PostToolUse 로 성공까지)에서 명령이 `bash <절대경로>/plan-link.sh (append|pause|resume|progress|exempt)` 로 시작할 때만 이번 턴 영수증을 남긴다. 이름만 적은 명령은 영수증이 없다(실측 H3).
- plan-link 에 `progress`(계획 안 진행 한 줄)와 `exempt`(릴리스 · 동기화처럼 정한 종류만, 이유와 함께) 명령을 더한다. 모든 기록 줄 끝에 `(요청 <번호>)` 와 사용자 원문 앞부분을 붙인다 — 원문은 훅이 남긴 기록 파일 경로에서 꺼낸다.
- 턴 끝(Stop): 사진 차이로 바뀐 파일을 구한다(scv/ · 호스트 설정 제외, scv/ 밖 .md 포함). 바뀐 파일이 있으면 영수증 · 요청 번호 줄 · 구조 줄이 모두 있어야 통과. 아니면 막고 무엇을 하면 되는지 한 줄로 말한다. 연속 2번 막히면 통과시키되 '계획 기록 없음' 을 저널과 계획(있으면)에 남긴다.
- 진행 중 계획이 없는데 바뀐 파일이 있으면: 계획을 만들거나(promote) 정한 예외로 `exempt` 를 쓰라고 막는다.
- 선택 답: claude 는 PostToolUse(AskUserQuestion) 훅이 질문 · 답을 `## 변경 이력` 에 바로 적는다. codex 는 PostToolUse 가 없어 턴 끝에 기록 파일에서 꺼내 적는다(확인할 것).
- 대시보드는 scv-mods 저장소에서 따로 PR — `## 변경 이력` 절 읽기 + 단계 번호 정규식에 글자 허용.
- 설정: `SCV_TURN_PLAN_CHECK=on`(기본) | `off`, `SCV_WORKSPACE_REPOS=<절대경로:…>`.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
// 턴 시작 · 도구 앞
flow(
  readTree,        // 부수효과 입구: (폴더) → 파일 목록 + 해시/시각
  snapTurn,        // (파일 목록) → 사진 줄들 "경로 지문"
  writeSnap,       // 부수효과 출구: 사진 → 턴 폴더
)
// 도구 실행 확인
flow(
  mintPlanReceipt, // (명령 글, 끝 코드) → 영수증 줄 | 없음
)
// 기록 줄 만들기 (plan-link progress · 모든 기록)
flow(
  attachRequest,   // (기록 줄, 요청 번호, 원문) → 번호 · 원문이 붙은 줄
  progressLine,    // (계획 글, 단계, 메모) → 진행 줄이 더해진 계획 글
)
// 턴 끝
flow(
  readSnaps,       // 부수효과 입구: 턴 폴더 → 시작 사진 · 지금 사진 · 영수증 · 계획 글
  diffTurn,        // (시작 사진, 지금 사진) → 바뀐 파일 목록 (제외 규칙 적용)
  judgeTurn,       // (바뀐 파일, 영수증, 새 계획 줄, 요청 번호, 막힌 횟수) → PASS | BLOCK(이유) | PASS-기록없음
  emitDecision,    // 부수효과 출구: 판정 → 호스트 응답 · 저널
)
// 선택 답
flow(
  recordChoice,    // (계획 글, 시각, 질문, 답) → 이력 줄이 더해진 계획 글
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | readTree | 폴더의 바뀐 파일 목록과 지문을 읽음 | 폴더 → 파일 목록 | 부수효과 (입구) |
| 2 | snapTurn | 파일 목록을 정렬된 사진 줄로 만듦 | 파일 목록 → 사진 줄 | 순수 |
| 3 | mintPlanReceipt | 명령이 성공한 계획 기록 명령인지 가림 | 명령 글 · 끝 코드 → 영수증 줄 / 없음 | 순수 |
| 4 | attachRequest | 기록 줄에 요청 번호와 원문 앞부분을 붙임 | 줄 · 번호 · 원문 → 줄 | 순수 |
| 5 | progressLine | 계획 변경 이력에 진행 한 줄을 더함 | 계획 글 · 단계 · 메모 → 계획 글 | 순수 |
| 6 | diffTurn | 시작 · 끝 사진 차이에서 바뀐 파일만 남김 | 사진 두 개 → 파일 목록 | 순수 |
| 7 | judgeTurn | 바뀐 파일 · 영수증 · 새 줄로 통과 여부를 정함 | 다섯 값 → 판정 | 순수 |
| 8 | recordChoice | 질문 · 답을 이력 줄로 더함 | 계획 글 · 시각 · 질문 · 답 → 계획 글 | 순수 |
| 9 | emitDecision | 판정을 호스트 응답과 저널에 씀 | 판정 → 출력 | 부수효과 (출구) |

- 부수효과 위치: 폴더 읽기(readTree · readSnaps), 턴 폴더 · 계획 파일 · 저널 쓰기(writeSnap · emitDecision · plan-link 어댑터), git 실행.
- 재사용: 0.86.0 `lib/plan-link.sh` 의 `scv_plan_history_add` · `scv_plan_fm_*`, `lib/model-prompting.sh` 의 턴 폴더(`scv_mp_turn_dir`), guard 의 영수증 저장소 규칙.

## Guardrails

- 0.86.0 plan-link 기존 명령의 출력 · 끝 코드를 바꾸지 않음 — 새 명령만 더함
- guard 의 기존 규칙과 영수증 저장소를 바꾸지 않음 — 계획 기록 영수증은 따로 둠
- 사진은 턴당 0.3초를 넘기지 않음(실측 0.18초) — 파일마다 프로세스를 띄우지 않음(첫판 4.7초의 원인)
- 맥 · 리눅스 둘 다: `stat` · `sed -i` · `find` 의 BSD/GNU 차이를 감싸서 씀, bash 3.2
- 막는 말은 한 줄로 무엇을 하면 되는지까지 — 예: `plan-link.sh progress <계획> --step N --note …`
- 사용자 전역 설정을 건드리지 않음

## Suggested path

1. 턴 사진 — git · git 아님 · 작업 공간 저장소, 도구 앞 추가 사진 — `readTree`, `snapTurn`
2. 계획 기록 영수증 — 성공한 plan-link 명령만 — `mintPlanReceipt`
3. plan-link `progress` · `exempt` 와 요청 번호 · 원문 자동 첨부 — `attachRequest`, `progressLine`

6. 두 래퍼 훅 연결(claude · codex)과 설정 두 개 — 훅 목록에 턴 시작 · 도구 앞뒤 · 턴 끝 연결을 더함
7. 대시보드 변경 이력 · `2b.` 단계 표시(scv-mods 따로 PR) — 패널이 계획의 변경 이력 절을 읽어 최근 것부터 보여 줌

9. 진행 줄에 시작 · 끝 상태를 담고, 대시보드가 빠진 단계 보고를 계획 파일의 진행 줄로 채움 — `progressLine`
10. 대시보드가 켜져 있으면 고친 턴은 단계 보고 도구 호출이 있어야 끝남 — `mintPlanReceipt`, `judgeTurn`

12. 보류시킨 계획이 끝났는데 원래 계획이 아직 보류면 턴 끝에서 막음 — `judgeTurn`
