# 마무리 보고 — 답 · 중간 보고를 설정 언어로 — 한 줄 규칙 턴에도 언어 줄 · 쓰기 전 알림 · 여러 언어 검사

## 1. 문제

- 상황: 다른 프로젝트의 긴 세션(2026-11-22, 사람 턴 107, 설정 언어 korean)에서 사용자가 "영어로 말한다"고 알림.
- 기대: 답과 도구 사이 중간 보고가 사용자가 SCV 에 정한 언어로 나옴.
- 실제: 끝 답 53턴 중 3턴이 영어, 중간 보고 약 37%가 영어(규칙 전문 턴 28/75 · 한 줄 턴 8/21). 큰 영어 답 하나는 규칙이 한 줄만 실린 턴에서 나옴.
- 재현 조건: 규칙이 한 줄로 실리는 턴(0.96.0+), 영어 도구 출력이 많은 긴 턴.

## 2. 관찰

- 빠진 줄: 한 줄 규칙 턴에는 언어 줄이 없음(사람 턴 훅이 전문 턴에만 실음).
- 쓴 뒤 교정: '방금 쓴 글이 한국어가 아니다' 경고가 그 세션에서 약 99번 나갔는데도 영어가 다시 나옴 — 쓴 뒤에 고치는 방식.
- 언어 묶임: 언어 판정 · 도구 뒤 검사가 설정 언어 korean 일 때만 돎 — 다른 설정 언어는 검사 없음.

## 3. 가설

- 가설 1: 한 줄 턴에서 언어 규칙이 빠져 영어로 흐름 — 그 세션의 큰 영어 답 하나와 맞음, 중간 보고 비율은 전문 · 한 줄 턴이 비슷해 이것만으로는 설명 안 됨.
- 가설 2: 언어 규칙이 턴 시작에만 있어 영어 도구 출력이 쌓이면 중간 보고가 끌려감 — 경고 99번에도 반복된 것과 맞음(실제 감소는 새 세션에서만 확인 가능).

## 4. 실험

- 그 세션 기록에서 턴마다 규칙 전문 · 한 줄과 답 언어를 셈(위 1번 값).
- 재현 시험 T12–T14: 고치기 전 셋 다 실패 → 고친 뒤 통과.
- 그 세션 기록 재생(판정 규칙을 옮긴 어림): 도구 결과 650번 중 459번에 알림이 붙음, 늘어나는 글 약 26KB.

## 5. 원인

- 직접 원인: 한 줄 규칙 턴에 언어 줄이 없었고, 도구 뒤에는 이미 쓴 다른 언어 글을 교정만 했음.
- 근본 원인: 언어 강제가 '턴 시작 한 번 + 쓴 뒤 교정'이라 긴 턴 중간에 다음 글을 쓰기 직전 시점을 비워 두었고, 판정이 korean 에 묶여 있었음.

## 6. 해결과 검증

- 해결책과 고른 이유: 한 줄 규칙 턴에도 설정 언어 줄. 도구 결과 뒤 짧은 알림 — 이번 턴의 마지막 글이 설정 언어면 생략(늘어나는 글을 묶음). 판정을 설정 언어의 글자(한국어 한글 · 일본어 가나와 한자 · 중국어 한자)로 넓히고, 한국어가 아닌 언어의 교정 문구는 영어 문장에 언어 이름. english 설정은 그대로(모델 기본 언어 · 기존 약속).
- 고치기 전후 값: 한 줄 규칙 턴 매 턴 글 8,222 → 8,452B(codex 사본 8,446 → 8,676B, 한도 11,000). 판정 함수 시간은 처음 4.80배 → 하위 셸을 없애 한도 안(재는 검사 한도 넘음 0).
- 부작용과 회귀 시험: test-lang-enforce T12(한 줄 턴 언어 줄) · T13(여러 언어 판정) · T14(도구 뒤 알림 · 다른 언어 요청 존중), T3 기대를 '다시 교정하지 않고 짧은 알림'으로 바꿈. 관련 시험 12개 mac · linux 통과. 실제 영어 비율 감소는 새 세션에서만 확인 가능.

## 7. 배운 것

- 다음에 같은 문제를 만나면 진단하는 법: 세션 기록에서 턴마다 훅 글(전문 · 한 줄)과 답 언어를 나란히 셈 — 끝 답과 중간 보고를 따로 셈.
- 다른 곳에도 쓸 수 있는 것: 쓴 뒤 교정은 반복을 막지 못함 — 다음 글 직전에 짧게 알리고, 이미 맞게 쓰면 생략해 비용을 묶음. 줄마다 불리는 판정 함수에는 하위 셸을 넣지 않음.
