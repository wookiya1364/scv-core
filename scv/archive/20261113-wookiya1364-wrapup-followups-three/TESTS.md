# Test Plan — 마무리 보고 뒷정리 셋 — 넘겨받은 계획 · 검색 · 조사 떼기 글자 깨짐

## Overview

세 가지를 본다. 첫째, 넘겨받은 계획에도 마무리 보고 틀이 생겨 보관할 때 보고 검사를 거친다. 둘째, 보관 기록 검색이 마무리 보고에 적은 말을 찾되 틀에만 있는 말에는 걸리지 않는다. 셋째, 조사 떼기가 언어 설정과 셸에 상관없이 같은 답을 낸다. 시험은 임시 폴더에 가짜 작업 공간 · 가짜 기록을 만들어 실제 명령을 돌린다.

## Test scenarios

### T1. 넘겨받은 계획 폴더에 마무리 보고 틀이 생긴다

- **Setup**: 가짜 작업 공간(뿌리 + 이 저장소)과 이 저장소로 온 넘겨받은 글 하나
- **Run**: 넘겨받기 명령(`handoff.sh adopt <번호>`)
- **Expected**: 종료 코드 0. 계획 폴더에 계획 문서 · 시험 문서 · 마무리 보고 세 파일. 마무리 보고는 일곱 묶음의 채울 자리만 있다. 계획 문서의 `## Links` 아래에 마무리 보고를 가리키는 줄이 있다
- **Pass criterion**: 종료 코드 0 · 파일 3개 · 묶음 제목 7개 · 가리키는 줄 1개

### T2. 넘겨받은 계획은 보고를 채워야 보관된다

- **Setup**: T1 로 만든 계획 폴더(마무리 보고는 채우지 않은 그대로)
- **Run**: 마무리 보고 검사(`wrapup.sh check <계획 폴더>`)
- **Expected**: 종료 코드 1. "옛 계획"이라는 알림이 아니라 빈 칸의 이름을 대며 막는다
- **Pass criterion**: 종료 코드 1 · 출력에 `block` · 출력에 `legacy` 없음

### T3. 넘겨받기의 지금 동작은 그대로다

- **Setup**: T1 과 같은 가짜 작업 공간
- **Run**: 넘겨받기 명령을 같은 번호로 두 번. 그리고 작업 공간 뿌리의 파일 목록을 앞뒤로 비교
- **Expected**: 두 번째는 "이미 있다"며 거절(종료 코드 0 아님)하고 첫 번째가 쓴 파일을 건드리지 않는다. 뿌리에는 새 파일이 없다
- **Pass criterion**: 두 번째 종료 코드 ≠ 0 · 계획 폴더 파일 3개 그대로 · 뿌리 파일 목록 차이 0

### T4. 마무리 보고에만 있는 말로 그 계획을 찾는다

- **Setup**: 가짜 기록 — 보관된 계획 둘. 하나의 마무리 보고 "배운 것" 칸에만 있는 낱말(다른 어떤 문서에도 없음)
- **Run**: 보관 기록 검색(`archive-search.sh <그 낱말>`)
- **Expected**: 그 계획이 결과에 나오고, 종류가 마무리 보고로 밝혀지며, 걸린 줄의 글이 함께 나온다
- **Pass criterion**: 결과 1건 · 그 계획의 폴더 이름 · 종류 이름이 마무리 보고

### T5. 틀에만 있는 말로는 걸리지 않는다

- **Setup**: T4 의 가짜 기록. 두 계획 모두 마무리 보고가 있다
- **Run**: 묶음 제목에만 있는 낱말("가설"), 칸 이름에만 있는 낱말("재현"), 안내 글에만 있는 낱말로 각각 검색
- **Expected**: 마무리 보고에서 걸린 결과가 없다. 같은 낱말이 칸의 값에 있을 때는 걸린다
- **Pass criterion**: 틀 낱말 셋 모두 마무리 보고 결과 0건 · 값에 넣은 경우 1건

### T6. 한 계획은 결과 한 칸만 차지한다

- **Setup**: 한 계획의 계획 문서와 마무리 보고 둘 다에 같은 낱말
- **Run**: 그 낱말로 검색
- **Expected**: 그 계획은 결과에 한 번만 나온다
- **Pass criterion**: 그 폴더 이름이 결과에 1번

### T7. 마무리 보고가 없는 기록에서는 결과가 지금과 같다

- **Setup**: 마무리 보고가 하나도 없는 가짜 기록(지금의 검색 시험이 쓰는 견본)
- **Run**: 지금의 검색 시험 전체
- **Expected**: 고치기 전과 같은 줄 수로 통과한다
- **Pass criterion**: 기존 검색 시험 실패 0

### T8. 조사 떼기는 언어 설정과 셸에 상관없이 같은 답을 낸다

- **Setup**: 언어 설정 셋(C · 그 기계의 UTF-8 설정 · 비어 있음) × 셸(bash 3.2 가 있으면 그것, 그리고 bash 4 이상)
- **Run**: 조사 떼기 함수에 함수 사전의 예 셋과 덧붙인 예를 넣는다 — "환불 버튼을 추가해", "결제 화면 기능", "x", 두 글자 조사가 붙은 말("서버에서 받는다"), 한 글자 한글 낱말이 섞인 글
- **Expected**: 모든 조합에서 답이 한글 UTF-8 설정 · bash 5 의 지금 답과 바이트까지 같다. 깨진 바이트가 없다
- **Pass criterion**: 기준과 다른 조합 0개 · 건너뛴 조합마다 이유 1줄

### T9. 함수 사전 검사가 C 언어 설정에서도 통과한다

- **Setup**: 고친 뒤의 저장소
- **Run**: `LC_ALL=C` 로 함수 사전 검사를 맥 기본 셸(bash 3.2)과 bash 5 에서
- **Expected**: 위반 0건
- **Pass criterion**: 종료 코드 0 · 위반 1 → 0

### T10. 겹침 검사가 조사 붙은 말을 같은 낱말로 본다

- **Setup**: 계획의 '하지 않음' 항목 "환불 버튼", 적으려는 글 "환불 버튼을 추가한다". 언어 설정 C
- **Run**: 겹침 검사 함수(`scv_tc_nongoal_hits`)
- **Expected**: 충돌 한 줄을 낸다(고치기 전에는 C 설정에서 "버튼을"이 깨져 절반만 겹친다)
- **Pass criterion**: C 설정과 UTF-8 설정에서 같은 출력

### T11. 조사 떼기가 느려지지 않는다

- **Setup**: 고치기 전 함수와 고친 함수, 같은 긴 글
- **Run**: 지금 있는 느린 함수 시험과 재는 검사
- **Expected**: 재 본 시간이 고치기 전의 2배를 넘지 않는다
- **Pass criterion**: 느린 함수 시험 종료 코드 0 · 고친 뒤 시간 ≤ 고치기 전의 2배

## How to run

```bash
bash core/tests/test-handoff-adopt.sh && bash core/tests/test-archive-search.sh && bash core/tests/test-false-rejects.sh && bash core/tests/test-slow-pure-functions.sh && LC_ALL=C bash core/scripts/pure-catalog.sh check
```

## Pass criteria

- T1 ~ T11 이 맥의 옛 셸(bash 3.2)과 새 셸(bash 5)에서 통과한다
- 순수 검사 · 함수 사전 검사 종료 코드 0 (C 언어 설정에서도 위반 0건)
- PR 을 올리기 전 전체 시험 한 번에서 실패 0
