# Test Plan — 템플릿 갱신을 내용으로 판단

## Overview

확인하는 것: 판단 함수가 지문과 번호 넷을 받아 정해진 답만 내고, 되돌림 방지가
그대로 살아 있고, 지문 없는 기존 프로젝트가 손상으로 오인되지 않고, 지문 산출이
어디서 계산해도 같고, 안 된 이유가 다섯 가지로 구분되어 보인다는 것.

**판정은 전부 문자열 비교다.** 각 시나리오는 정해진 문자열을 찍거나 못 찍거나다.
"갱신된 것 같다" 는 판정이 없다.

## Test scenarios

### T1. 판단 함수 — 전수 검사  ✅ `OK [T1] 18/18`

- **Setup**: 파일 없음. 함수에 문자열 넷을 직접 넘긴다.
  지문 상태 3가지(같음 / 다름 / 프로젝트에 없음) × 배포본 지문 2가지(있음 / 없음)
  × 번호 관계 3가지(배포본 최신 / 같음 / 배포본이 더 오래됨) = **18가지 전부**.
- **Expected**: 18행 기대표와 정확히 일치.
  - 배포본 번호가 더 오래됨 → 지문과 무관하게 항상 `skip:backward` (6행)
  - 배포본에 지문 없음(구형) → 번호로만 판단: 다르면 `refresh:version`, 같으면 `skip:same`
  - 프로젝트에 지문 없음 → `refresh:unstamped`
  - 지문 다름 → `refresh` (**번호가 같아도**)
  - 지문 같음 + 번호 다름 → `refresh:version` (**예전 경로가 살아 있는지**)
  - 지문 같음 + 번호 같음 → `skip:same`
- **핵심**: 이 표에 **두 갱신 경로가 동시에** 있어야 한다. 지문은 번호를 대체하지
  않고 더한다. 지문만 보게 만들면 번호 스탬프만 낡은 프로젝트가 영영 안 고쳐진다.
- **Pass criterion**: `OK [T1] 18/18`

### T2. 판단 함수 — 부수효과 없음 (정적 검사)  ✅

- **Setup**: 판단 함수 본문만 추출한다.
- **Expected**: 파일 읽기/쓰기, 시각, 무작위, 네트워크 호출이 **하나도 없다.**
- **Pass criterion**: `OK [T2]`

### T3. 지문 산출 — 결정적  ✅

- **Setup**: 같은 템플릿 트리로 지문을 두 번 계산한다. 그 사이에 파일의 수정 시각과
  권한을 바꾼다. 별도로 파일 순서를 뒤집은 목록으로도 계산한다.
- **Expected**: 세 번 모두 같은 지문. 파일 **내용**을 한 글자 바꾸면 지문이 달라진다.
  파일을 하나 추가하거나 지워도 달라진다.
- **Pass criterion**: `OK [T3]`

### T4. 번호가 같은데 템플릿이 바뀐 경우 (이번 수정의 본체)  ✅

- **Setup**: 프로젝트를 최신으로 맞춘다. 그다음 배포본의 템플릿 파일 하나만 고치고
  **번호는 그대로 둔다.** 지문은 다시 계산한다.
- **Expected**: 다음 SCV 명령에서 갱신이 **돈다.** 프로젝트 파일에 그 변경이 반영된다.
  갱신 뒤 지문 스탬프가 새 값으로 바뀐다.
- **왜 중요한가**: 이 시나리오가 지금은 **실패한다.** 이게 통과하면 원인이 제거된 것이다.
- **Pass criterion**: `OK [T4]`

### T5. 되돌림 방지 — 살아 있는지  ✅

- **Setup**: 프로젝트에 최신 번호가 찍혀 있고, 배포본은 더 오래된 번호다. 지문도 다르다.
- **Expected**: 갱신이 **돌지 않는다.** 프로젝트 파일이 하나도 안 바뀐다.
  이유를 말하는 문구가 나온다.
- **Pass criterion**: `OK [T5]`

### T6. 지문 없는 기존 프로젝트 — 손상으로 오인하지 않는다  ✅

- **Setup**: 번호 스탬프는 있고 지문 스탬프는 없는 인덱스. (이번 변경 이전의 모든 프로젝트)
- **Expected**:
  - 갱신이 **돈다** (`refresh:unstamped`)
  - 갱신 뒤 지문 스탬프가 찍힌다
  - **두 번째 실행은 아무것도 하지 않는다** (`skip:same`)
  - "손상" 이나 "다시 찍어라" 문구가 **나오지 않는다**
- **대조군**: 번호 스탬프까지 없는 인덱스는 지금처럼 손상으로 안내한다.
- **Pass criterion**: `OK [T6]`

### T7. 편집 중인 파일 — 덮어쓰지 않고 스탬프도 안 올린다  ✅

- **Setup**: 템플릿이 바뀐 상태에서, 프로젝트의 템플릿 파일 하나를 수정해 둔다.
- **Expected**:
  - 그 파일은 **안 바뀐다** (수정 내용 그대로)
  - 나머지는 갱신된다
  - **지문 스탬프가 안 올라간다** — 다음 명령이 다시 시도한다
  - 남은 파일 목록이 사용자에게 보인다
- **Pass criterion**: `OK [T7]`

### T8. 업데이트 직후 갱신 (2단계)  ⛔ **취소**

2단계를 하지 않기로 했다. 플러그인 payload 는 버전별로 캐시되므로 업데이트가 도는
시점의 세션은 아직 옛 payload 를 들고 있고, 거기서 갱신을 부르면 옛 템플릿을
깔아놓고 성공을 보고한다. 검사할 동작 자체가 없다. PLAN 의 해당 절 참조.

### T9. 안 된 이유가 서로 구분된다 (3단계)  ✅ `test-autosync T5s`

- **Setup**: 다음 상황을 각각 만든다 —
  자동 갱신 꺼짐 + 어긋남 / 자동 갱신 꺼짐 + 멀쩡함 / 배포본 불완전 /
  배포본 번호가 빈 값 / 배포본이 더 오래됨 / 템플릿 2.0 이전 / 번호 스탬프 없음.
- **Expected**: 문구가 **서로 다르고**, 각각 무엇이 원인인지와 무엇을 하면 되는지를
  말한다. 전부 exit 0 이고 진행 중인 명령을 막지 않는다.
- **특히**: 꺼져 있어도 **어긋나지 않았으면 아무 말도 하지 않는다.** 매 액션마다
  떠들면 금방 무시하게 되고, 그러면 정작 중요할 때도 안 읽는다.
- **한 액션에 한 번만** 찍힌다 — 한 액션이 헬퍼를 여러 개 띄우므로 재귀 가드를
  opt-out 검사보다 먼저 잡아야 한다.
- **Pass criterion**: `T5s` 4건 통과 (test-autosync 25/25)

### T10. 상태 명령의 어긋남 표시 (3단계)  ✅ (수동 확인)

- **Setup**: 멀쩡한 프로젝트 / 어긋났고 자동 갱신 꺼짐 / 어긋났고 켜짐.
- **Expected**:
  - 멀쩡함 → **한 줄도 늘지 않는다**
  - 어긋남 + 꺼짐 → 원인과 할 일 두 줄
  - 어긋남 + 켜짐 → 자동으로 닫히므로 **역시 안 보인다**
- **왜 세 번째가 중요한가**: 이 절이 보인다는 것은 곧 "자동으로는 못 닫는 상태"
  라는 뜻이어야 한다. 그래야 "왜 아직 옛날 문서지?" 의 답이 된다.
- **Pass criterion**: 세 경우 모두 위와 같음 — 확인 완료. 자동 회귀는 아직 없다.

### T11. 회귀 — 기존 스위트  ✅

- **Expected**: `core/tests/run.sh`, `core/tests/run-dry.sh` 전부 exit 0.
- **Pass criterion**: `ALL GATES OK [T11]`

### T12. 래퍼 두 곳  ⏳ **미완**

- **Expected**: 두 래퍼에서 업데이트 명령이 갱신을 부르고, 각자의 테스트가 exit 0.
- **Pass criterion**: `OK [T12]` (래퍼별로 각각)

## How to run

```bash
bash core/tests/test-template-digest.sh    # T1 T2 T3
bash core/tests/test-autosync-digest.sh    # T4 T5 T6 T7 T9 T10
bash core/tests/run.sh && bash core/tests/run-dry.sh   # T11
# T8 T12 는 각 래퍼 저장소에서
```

## 이 테스트 계획이 지키는 것

- **T1 이 판단의 전부다.** 입력 조합이 9가지뿐이라 표본이 아니라 전수를 본다.
- **T4 는 지금 실패한다.** 고쳐졌다는 증거가 바로 이 한 줄이다.
- **T5 와 T7 은 없애면 안 되는 것을 지킨다.** 되돌림 방지와 편집 보호.
- **T6 은 기존 사용자를 지킨다.** 지문 없는 상태가 정상으로 취급되는지 본다.
- **T3 은 지문 자체를 의심한다.** 기계마다 다르게 나오면 전부 무너진다.
