# Test Plan — 강제를 preflight 로

## Overview

이 계획의 핵심 단언은 **부정형**이다: 응답 종료 훅이 어떤 경우에도 되돌리지
않는다. 그래서 검사의 절반은 "무엇이 일어나지 않는가" 를 본다. 앞선 계획의 검사가
"되돌린다" 를 단언했으므로, 그 단언을 뒤집는 것이 이 문서의 일이다.

나머지 절반은 주입을 본다. 무엇이 들어가고(진단·지침·표시줄), 무엇이 빠지는가
(개요·명령 목록). 훅을 직접 실행해 표준출력과 종료 코드로 판정한다.

## Test scenarios

### T1. 응답 종료 훅이 되돌리지 않는다

이 계획이 존재하는 이유다. 앞 계획에서 되돌림이 나오던 바로 그 상황을 그대로
재현하고, 이번에는 나오지 않는 것을 본다.

- **Setup**: scv 폴더가 있는 임시 프로젝트. 스위치 기본값. 프롬프트 훅을 먼저
  실행한다. 영수증 저장소는 비어 있다 (help 를 부르지 않은 상태).
- **Run**: 종료 훅을 실행한다.
- **Expected**: 차단 결정이 없다.
- **Pass criterion**: 표준출력에 차단 결정이 없고 종료 코드가 0.

### T2. 여러 번 실행해도 되돌리지 않는다

- **Setup**: T1 과 같다.
- **Run**: 종료 훅을 연속 5회 실행한다.
- **Expected**: 매번 차단 결정이 없다.
- **Pass criterion**: 5회 모두 출력에 차단 결정이 없다. 회차가 쌓여도 달라지지
  않는다는 것이 요점이다.

### T3. 매 턴 진단이 주입된다

- **Setup**: scv 폴더가 있는 임시 프로젝트.
- **Run**: 프롬프트 훅을 실행한다.
- **Expected**: 출력에 프로젝트 진단 내용이 실린다.
- **Pass criterion**: 진단 구간을 알아볼 수 있는 표지가 출력에 있다.

### T4. 개요와 명령 목록은 주입되지 않는다

매번 같은 내용이라 뺀 것이므로, 실제로 빠졌는지 본다.

- **Setup**: T3 과 같다.
- **Run**: 프롬프트 훅 출력과 상태 점검 전체 출력을 비교한다.
- **Expected**: 점검 전체에는 있고 훅 출력에는 없는 구간이 존재한다 (개요·명령
  목록).
- **Pass criterion**: 훅 출력이 점검 전체 출력보다 짧고, 명령 목록 표지가 훅
  출력에 없다.

### T5. 분류 지침이 세 갈래를 모두 말한다

- **Setup**: T3 과 같다.
- **Run**: 프롬프트 훅 출력을 본다.
- **Expected**: 앞을 보는 턴·뒤를 보는 턴·둘 다 아닌 턴에 대한 지침이 모두 있다.
- **Pass criterion**: 세 갈래가 각각 출력에서 확인된다. 셋째 갈래가 빠지면 모델이
  모든 턴을 둘 중 하나로 밀어넣게 되므로, 그 항목이 특히 중요하다.

### T6. 표시줄이 매 턴 나온다

- **Setup**: T3 과 같다.
- **Run**: 프롬프트 훅을 두 번 실행한다.
- **Expected**: 두 번 다 표시줄이 나온다.
- **Pass criterion**: 두 실행 모두 표시줄 표지가 출력에 있다.

### T7. preflight 스위치를 끄면 주입도 표시줄도 없다

- **Setup**: 설정에서 preflight 스위치를 off 로 둔다. 라우팅 스위치는 켜 둔다.
- **Run**: 프롬프트 훅과 종료 훅을 차례로 실행한다.
- **Expected**: 진단·지침·표시줄이 모두 없다. 기존 라우팅 안내는 그대로 나온다.
  종료 훅은 되돌리지 않는다.
- **Pass criterion**: 세 가지가 출력에 없고, 라우팅 안내는 있으며, 차단 결정이 없다.

### T8. 전체 라우팅 스위치를 끄면 아무것도 없다

- **Setup**: 라우팅 스위치를 off 로 둔다.
- **Run**: 프롬프트 훅을 실행한다.
- **Expected**: 라우팅 안내·진단·지침·표시줄이 모두 없다.
- **Pass criterion**: 네 가지가 모두 출력에 없다.

### T9. scv 폴더가 없으면 아무 출력도 없다

- **Setup**: scv 폴더가 없는 임시 폴더.
- **Run**: 프롬프트 훅과 종료 훅을 차례로 실행한다.
- **Expected**: 두 훅 모두 조용히 끝난다.
- **Pass criterion**: 표준출력이 비어 있고 종료 코드 0.

### T10. 점검 실행이 실패해도 막지 않는다

- **Setup**: 상태 점검을 실행할 수 없는 환경을 만든다.
- **Run**: 프롬프트 훅을 실행한다.
- **Expected**: 진단 없이 표시줄과 지침만 나오고 정상 종료한다.
- **Pass criterion**: 종료 코드 0, 표시줄 있음, 훅이 죽지 않음.

### T11. 저널 기록이 이번 변경 이전과 같다

- **Setup**: 기존 저널 검사가 쓰는 페이로드를 그대로 쓴다.
- **Run**: 기존 저널 검사를 실행한다.
- **Expected**: 전부 통과한다.
- **Pass criterion**: 기존 저널 검사가 초록이다. 한 턴에 한 줄이라는 성질이
  되돌림 제거 뒤에도 유지되는지를 본다.

### T12. 가드가 라이브러리를 읽지 않는다

- **Setup**: 판정부 라이브러리 파일을 읽을 수 없게 만든다.
- **Run**: 가드를 발행 모드로 실행하고 영수증이 남는지 본다.
- **Expected**: 라이브러리가 없어도 평소처럼 영수증을 남긴다.
- **Pass criterion**: 영수증이 기록되고 가드가 정상 종료한다. 가드가 다시 홀로
  서는지를 보는 항목이다.

### T13. 되돌림용 함수가 남아 있지 않다

- **Setup**: 없음.
- **Run**: 판정부 라이브러리를 훑는다.
- **Expected**: 되돌림 판정·회차별 문구·턴 상태 경로 함수가 없다.
- **Pass criterion**: 해당 함수 이름이 하나도 정의돼 있지 않다. 코드가 남아 있으면
  다음 사람이 다시 켤 수 있고, 그러면 같은 비용이 돌아온다.

### T14. 판정부가 순수성 계약을 지킨다

- **Setup**: 없음.
- **Run**: 순수성 검사기를 판정부 파일에 돌린다.
- **Expected**: 위반 0건.
- **Pass criterion**: 검사기가 통과를 보고한다.

### T15. 옛 계획이 회귀에서 건너뛰어진다

- **Setup**: 이 계획이 아카이브된 뒤.
- **Run**: 누적 회귀를 실행한다.
- **Expected**: 대체된 슬러그가 건너뛰어지고 회귀가 초록이다.
- **Pass criterion**: 실패 0건. 이 선언을 빠뜨리면 옛 슬러그의 "되돌린다" 단언이
  실패하므로, 그 사실을 검사로 못 박는다.

### T16. 실제 대화에서 본문이 한 번만 나간다 (사람 확인)

기계로 판정하기 어려워 따로 둔다.

- **Setup**: 갱신된 플러그인이 적용된 세션.
- **Run**: 평범한 대화를 몇 턴 한다.
- **Expected**: 답이 한 번만 생성되고, 같은 내용이 반복되지 않는다.
- **Pass criterion**: 사람이 확인하고 보고한다.

## How to run

```bash
bash core/tests/test-force-help.sh
```

## Pass criteria

- 위 시나리오 T1~T15 가 모두 통과한다.
- T16 은 사람이 확인한다.
- 아래 기존 검사가 계속 통과한다 (별도 실행):
  `test-journal.sh`, `test-always-on.sh`, `test-guard.sh`, `test-settings.sh`,
  `test-purity.sh`, `test-whitespace.sh`, `test-template-digest.sh`.
- 어떤 시나리오에서도 훅이 0이 아닌 종료 코드로 끝나지 않는다.
