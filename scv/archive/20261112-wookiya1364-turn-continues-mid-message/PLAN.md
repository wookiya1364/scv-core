# 턴 도중에 온 말은 같은 턴으로 이어 가기

## Summary

턴 끝 검사는 사람의 말이 올 때마다 턴 상태를 통째로 새로 시작한다. 모델이 일하는 도중에 온 말도 그렇게 처리해서, 그 앞에 남긴 계획 기록과 영수증이 "앞 턴 것"이 되고 같은 일에 기록을 한 번 더 요구한다.
계획을 보관한 뒤 같은 턴에 말이 한 번 더 오면 더 나쁘다: 보관한 계획이 "턴 시작보다 옛것"이 되어 읽히지 않고, 릴리스 예외를 적어야 턴이 끝난다(2026-11-12 두 번).
앞 턴이 아직 끝나지 않았을 때 온 말은 같은 턴이 이어지는 것으로 본다.

## Goals / Non-Goals

- **Goals**
  - "턴이 끝났다"는 표시를 남긴다 — 턴 끝 검사가 통과를 낸 때, 세션을 새로 열거나 다시 열 때
  - 사람의 말이 왔을 때 앞 턴이 끝났으면 지금처럼 새로 시작하고, 끝나지 않았으면 이어 간다
  - 이어 갈 때는 요청 번호 · 영수증 · 사진 · 내가 쓴 파일 목록 · 계획 기준선 · 막힌 횟수를 그대로 두고, 새 말을 요청 글 뒤에 덧붙인다
  - 사용자가 멈춘(Esc) 턴 뒤의 말도 이어지는 턴으로 본다 — 멈추기 전에 고친 파일도 턴 끝에 기록을 요구한다 (사용자 선택 2026-11-12)
- **Non-Goals**
  - 턴 끝에서 막힐 때의 글 규칙("한 줄로 끝내라"와 끝 보고의 모양) 손보기
  - 계획을 세울 때 그림 문서를 매번 묻는 것 손보기
  - 자동 알림 턴(배경 작업 완료 등)의 처리 바꾸기 — 지금처럼 턴을 시작하지도 끝내지도 않는다
  - 턴 끝 판정의 규칙(무엇이 기록인가) 바꾸기

## Approach Overview

사용자가 2026-11-12 선택 창에서 정한 것: 개요 "개요대로 쓰기", 멈춘 턴 "이어지는 턴으로 봄", 릴리스 "넷을 끝낸 뒤 한 번", 그림 "넷 다 그림 없이", 마무리 "합치기까지 자동".

읽은 사실 (2026-11-12):

- 프롬프트 훅은 사람의 말마다 `turn-check.sh start` 를 부른다(`core/template/hooks/on-user-prompt.sh` 209 ~ 215줄). 자동 알림 턴에는 부르지 않는다.
- `start` 는 사진 · 내가 쓴 파일 목록 · 영수증 · 막힌 횟수 · 예외 · 단계 표시를 지우고, 요청 글과 요청 번호를 새로 쓰고, 계획 기준선을 새로 찍는다(`core/scripts/turn-check.sh` 의 `start)` 가지).
- 턴 끝 판정은 "기준선 뒤에 생긴 계획 줄 가운데 이 요청 번호가 붙은 것"과 "영수증"을 센다. 번호와 기준선이 새로 찍히면 앞의 기록은 세지 않는다.
- 보관한 계획은 보관 기록 파일이 요청 번호 파일보다 새것일 때만 읽는다(`plan_texts`, 132 ~ 142줄). 번호 파일이 새로 쓰이면 그 계획은 옛것이 된다.
- 턴이 끝났다는 표시는 지금 없다. 턴 끝 훅이 `end` 를 부르고 판정만 받는다.
- 세션 시작 훅은 세션별 턴 폴더를 이미 구한다(`core/template/hooks/on-session-start.sh` 56 ~ 63줄).

하는 일:

1. **끝 표시** — `end` 가 통과(`pass` · `pass-unrecorded`)를 내면 턴 폴더에 끝 표시를 남긴다. 막힘이면 남기지 않는다.
2. **시작 방식 판정** — 순수 함수가 "요청 번호가 있는가 · 끝 표시가 있는가"로 `fresh | continue` 를 가린다.
3. **이어 가기** — `continue` 이면 아무것도 지우지 않고, 새 말을 요청 글 뒤에 덧붙인다(가리개 · 첨부 경로 지우기는 지금과 같이 거친다). `fresh` 이면 지금과 같고 끝 표시를 지운다.
4. **세션 열기** — 새로 열거나 다시 연 세션은 앞 턴이 끝난 것으로 표시한다. 압축(compact)은 턴 도중에 일어나므로 표시하지 않는다.
5. **시험** — 도중 말, 보관 뒤 말, 끝난 뒤 말, 멈춘 턴 뒤 말, 세션 다시 열기, 압축.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

턴 시작은 "상태 읽기 → 방식 판정 → 요청 글 만들기 → 쓰기"의 줄이다. 판정과 글 만들기는 순수 함수이고, 읽기와 쓰기만 양 끝에 있다.

```
flow(
  read_turn_state,      // 턴 폴더 → 번호 있음 · 끝 표시 있음 · 지금 요청 글   (입구: 파일 읽기)
  scv_tc_start_mode,    // 번호 있음 · 끝 표시 있음 → fresh | continue          (순수, 새로)
  scv_tc_req_join,      // 지금 요청 글 · 새 말 → 덧붙인 요청 글                (순수, 새로)
  write_turn_state,     // 방식 · 요청 글 → 턴 폴더                             (출구: 파일 쓰기 · 사진 찍기)
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | read_turn_state | 턴 폴더에서 요청 번호 · 끝 표시 · 요청 글을 읽는다 | 턴 폴더 → 값 셋 | 부수효과 (입구) |
| 2 | scv_tc_start_mode | 새로 시작할지 이어 갈지 가린다 | 번호 있음 · 끝 표시 있음 → `fresh` \| `continue` | 순수 |
| 3 | scv_tc_req_join | 이어 갈 때 새 말을 요청 글 뒤에 덧붙인다 | 지금 요청 글 · 새 말 → 요청 글 | 순수 |
| 4 | write_turn_state | 방식에 따라 상태를 지우거나 그대로 두고, 요청 글 · 번호 · 사진을 쓴다 | 방식 · 요청 글 → 턴 폴더 | 부수효과 (출구) |
| 5 | scv_tc_session_closes | 세션 열기의 종류가 앞 턴을 끝내는지 가린다 | 종류(startup · resume · clear · compact) → 1 \| 0 | 순수 |

- 부수효과 위치: 1 · 4 는 `turn-check.sh` 의 `start)` 가지 안이다. 끝 표시 쓰기는 `end)` 가지와 새 `close)` 가지에 있다.
- 재사용: 가리개(`journal-append.sh --redact-only`), 첨부 경로 지우기(`scv_tc_strip_attach`), 사진 찍기(`take_snap`), 판정(`scv_tc_judge`)은 그대로 쓴다.

## Guardrails

- 턴 끝 판정 함수(`scv_tc_judge`)와 "무엇이 기록인가"의 규칙은 고치지 않는다.
- 끝난 턴 뒤의 말은 반드시 새로 시작한다 — 지난 턴의 기록이 이번 턴 것으로 세어지면 안 된다.
- 자동 알림 턴은 끝 표시를 건드리지 않는다(지금도 `start` · `end` 를 부르지 않는다).
- 이어 갈 때 요청 글은 4,000자를 넘기지 않는다(지금의 한도). 가리개와 첨부 경로 지우기를 새 말에도 똑같이 거친다.
- 맥과 리눅스, 옛 셸과 새 셸에서 모두 돈다.
- 호스트 이름이 든 글을 코어에 쓰지 않는다.

7. PR 을 develop 에 올리고 검사 결과를 읽는다 — 다른 운영체제에서의 통과를 확인하는 일

## Risks / Open Questions

- 턴 끝 검사는 통과했는데 다른 검사(끝 보고 등)가 턴을 막아 이어지는 사이에 말이 오면, 끝 표시가 이미 있어 새로 시작한다 — 지금과 같은 동작이고 그 사이는 짧다. 고치지 않고 적어 둔다.
- 턴 끝 훅이 돌지 못하고 세션이 죽으면 끝 표시가 없다. 그 세션을 다시 열면 세션 시작 훅이 끝난 것으로 표시한다. 다시 열지 않고 같은 세션에 말이 이어지는 경우는 "멈춘 턴"과 같아 이어 간다.
- 이어 간 턴은 요청 번호가 처음 것이다. 계획 줄에 붙는 "요청: …" 글은 처음 말로 시작한다(덧붙인 말은 뒤에 있다).
