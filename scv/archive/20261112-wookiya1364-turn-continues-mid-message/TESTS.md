# Test Plan — 턴 도중에 온 말은 같은 턴으로 이어 가기

## Overview

모델이 일하는 도중에 사람의 말이 와도 그 턴에 남긴 계획 기록이 유지되는지, 끝난 턴 뒤의 말은 지금처럼 새로 시작하는지 확인한다. 시험은 턴 끝 검사 시험 파일에 장면으로 더한다(T36 ~ T41).

## Test scenarios

### T1. 도중에 온 말 — 앞의 기록으로 통과

- **Setup**: 진행 중인 계획 하나. 턴 시작 → 파일 고침 → 진행 기록(영수증과 요청 번호가 붙은 줄).
- **Run**: 턴 끝 없이 사람의 말이 한 번 더 온다(턴 시작을 다시 부름) → 다른 파일을 고침 → 턴 끝.
- **Expected**: 통과. 요청 번호는 처음 것 그대로다. 요청 글에 두 말이 모두 있다.
- **Pass criterion**: 판정 `pass`, 번호 파일의 값이 둘째 시작 앞뒤로 같다 — 시험 줄 `ok T36`.

### T2. 고치기 전에는 T1 이 막힌다

- **Setup**: T1 과 같다. 턴 시작만 고치기 전 것으로 되돌린다.
- **Run**: T1 과 같은 장면.
- **Expected**: 막힘(`block`) — 지금의 문제 그대로.
- **Pass criterion**: 고치기 전 코드로 돌리면 `✖ T36` 이 나온다. 확인 뒤 되돌린다.

### T3. 계획을 보관한 뒤 온 말 — 예외 없이 통과

- **Setup**: 턴 시작 → 파일 고침 → 진행 기록 → 그 계획을 보관함으로 옮김(보관 기록 파일 생김).
- **Run**: 턴 끝 없이 사람의 말이 온다 → 파일을 하나 더 고침 → 턴 끝.
- **Expected**: 통과. 릴리스 예외를 적지 않았다.
- **Pass criterion**: 판정 `pass`, 예외 파일에 줄이 없다 — 시험 줄 `ok T37`.

### T4. 끝난 턴 뒤의 말 — 지금처럼 새로 시작

- **Setup**: 턴 시작 → 파일 고침 → 진행 기록 → 턴 끝(통과).
- **Run**: 사람의 말(턴 시작) → 파일 고침 → 턴 끝.
- **Expected**: 막힘 — 지난 턴의 기록은 이번 턴 것으로 세지 않는다. 요청 번호가 바뀌고 요청 글은 새 말뿐이다.
- **Pass criterion**: 판정 `block`, 번호가 다르다 — 시험 줄 `ok T38`. 기존 T6(D · D2 · E · F)과 T33 도 그대로 `ok`.

### T5. 멈춘 턴 뒤의 말 — 멈추기 전에 고친 파일도 센다

- **Setup**: 턴 시작 → 파일 고침. 기록 없음, 턴 끝도 없음(사용자가 멈춤).
- **Run**: 사람의 말(턴 시작) → 턴 끝.
- **Expected**: 막힘, 막는 말의 바뀐 파일에 멈추기 전에 고친 파일이 있다. 그 파일을 되돌린 뒤라면 통과.
- **Pass criterion**: 판정 `block` 과 `TURN_PLAN_FILES` 에 그 파일, 되돌린 장면은 `pass` — 시험 줄 `ok T39`.

### T6. 막혔다가 이어진 턴에 온 말

- **Setup**: 턴 시작 → 파일 고침 → 턴 끝(막힘 1번).
- **Run**: 사람의 말(턴 시작) → 턴 끝.
- **Expected**: 다시 막힘이고 막힌 횟수가 이어진다(2번째). 한 번 더 끝내면 `pass-unrecorded`.
- **Pass criterion**: 판정이 차례로 `block` · `block` · `pass-unrecorded` — 시험 줄 `ok T40`.

### T7. 세션을 다시 열면 새로 시작, 압축은 이어 감

- **Setup**: 턴 시작 → 파일 고침 → 진행 기록. 턴 끝 없음.
- **Run**: (가) 세션 시작 훅을 `resume` 으로 부른 뒤 사람의 말 → 파일 고침 → 턴 끝. (나) 같은 장면을 `compact` 로.
- **Expected**: (가) 막힘 — 앞 턴이 끝난 것으로 표시되어 새로 시작했다. (나) 통과 — 압축은 턴 도중이라 이어 갔다.
- **Pass criterion**: (가) `block`, (나) `pass` — 시험 줄 `ok T41`.

### T8. 순수 함수와 사전

- **Setup**: 새 순수 함수 셋.
- **Run**: 값을 직접 넣는다 — 방식 판정 네 가지(번호 없음 · 끝 표시 있음 · 둘 다 없음 등), 요청 글 덧붙이기(빈 글 · 4,000자 넘김), 세션 열기 종류 넷. 함수 사전 검사를 돌린다.
- **Expected**: 번호가 있고 끝 표시가 없을 때만 `continue`. 덧붙인 글은 4,000자를 넘지 않는다. `startup` · `resume` 만 1.
- **Pass criterion**: 시험 줄 `ok T42`, 사전 검사 `OK  catalog:` 로 시작하는 한 줄, 두 셸에서 종료 코드 0.

### T9. 실제 세션에서 보기 (릴리스 뒤)

- **Setup**: 이 변경이 든 플러그인을 설치한 실제 세션, 진행 중인 계획.
- **Run**: 모델이 파일을 고치고 진행 기록을 남긴 뒤, 일하는 도중에 말을 한 번 보낸다.
- **Expected**: 턴이 끝날 때 기록을 다시 요구하지 않는다.
- **Pass criterion**: 턴 끝에 막힘 글이 0번. 이 계획 안에서는 확인하지 못한다.

## How to run

```bash
bash core/tests/test-turn-plan-check.sh
```

## Pass criteria

- `bash core/tests/test-turn-plan-check.sh` 의 마지막 줄이 `test-turn-plan-check: all passed`, `✖` 줄 0개 — 옛 셸과 새 셸 모두 (T1 · T3 ~ T8)
- T2: 고치기 전 코드로 `✖ T36`
- 함수 사전 검사가 `OK  catalog:` 로 시작하는 줄을 낸다
- PR 검사의 모든 항목이 `success`
- T9 는 릴리스 뒤 실제 세션에서 본다
