# 낱말 사전 — 피할 말을 정해 두면 같은 계열의 말까지 바꿔 말한다 (명령 words)

## Summary

사용자가 정한 말이 있다. 예: "재다" 대신 "측정하다". 지금은 이것을 세션마다 말로 다시 알려야 하고, 알려도 "잰", "재 봤을 때"처럼 꼴이 바뀐 말은 그대로 나온다(사용자 요청 2026-11-25).

이 계획은 프로젝트마다 낱말 사전 하나(`scv/words/WORDS.tsv`)를 두고, 대화 첫머리에 "이 말과 그 계열의 말 대신 이 말을 써라"를 한 번 싣는다. 답이 나간 뒤에는 스크립트가 직전 답에서 피할 말을 찾아, 있으면 다음 턴에 한 줄로 알린다. 이미 보인 답은 다시 쓰게 하지 않는다. 사전을 보고 고치는 명령은 `words` 다.

## Goals / Non-Goals

- **Goals**
  - 사전에 "피할 말 → 쓸 말"을 넣어 두면, 그 말의 활용 · 같은 계열의 말까지 쓸 말로 바꿔 말한다.
  - 사전은 프로젝트의 `scv/` 안에 있고 저장소와 함께 커밋된다(사용자 결정 1 — 기어와 같은 자리).
  - 대화 첫머리의 안내와 답 뒤의 검사를 함께 쓴다(사용자 결정 2). 검사는 다음 턴에 한 줄만 남긴다.
  - 명령 `words` 로 사전을 보고 · 넣고 · 빼고, 꼴이 비어 있는 항목의 꼴을 채운다.
  - 사전이 없는 프로젝트의 매 턴 글은 한 글자도 늘지 않는다.
- **Non-Goals**
  - 이미 보인 답을 고쳐 쓰게 하는 일 — 사용자가 기다리게 되는 늦은 고침은 하지 않는다(사용자 결정 2).
  - 스크립트가 뜻을 가려내는 일 — "잰걸음"처럼 글자만 같은 말은 스크립트가 가르지 못한다. 같은 뜻인지는 모델이 본다.
  - 코드 · 파일 이름 · 명령 · 인용한 사용자 글 속의 말을 바꾸는 일.
  - 여러 프로젝트가 사전 하나를 함께 쓰는 일.
  - 대시보드의 낱말 카드 — 계획 `20261125-wookiya1364-mirror-controls` 가 맡는다. 이 계획은 그 카드가 읽고 쓰는 파일의 모양과 명령만 정한다.

## Approach Overview

- 사전 파일: `scv/words/WORDS.tsv`. 한 줄에 항목 하나, 탭으로 나눈 네 칸 — 피할 말(으뜸꼴 — 항목의 이름) · 쓸 말 · 다른 꼴들(`, ` 로 나눔, 비어도 됨) · 메모(비어도 됨). `#` 로 시작하는 줄과 빈 줄은 읽지 않는다.
- 꼴은 모델이 쓴다. 사용자는 피할 말과 쓸 말만 말하고, `words` 명령을 받은 모델이 활용 · 같은 계열의 꼴을 적어 넣는다. 대시보드에서 넣어 꼴이 빈 항목은 `words` 명령의 채우기 단계가 채운다.
- 대화 첫머리: 매 턴 훅이 사전이 있는 프로젝트에서 안내 묶음(머리 한 줄 + 항목마다 한 줄)을 이 맥락에 한 번 싣는다. 규칙 글의 "한 번만 싣기"와 같은 길이다 — 세션 자리에 표시를 남기고, 대화가 요약 · 비움 · 재개되면 표시가 지워져 다시 싣는다. 사전 파일이 바뀌면 다시 싣는다.
- 답 뒤: 턴 끝 훅이 직전 답을 스크립트로 훑는다. 피할 말이 있으면 다음 턴에 실릴 한 줄을 남긴다. 턴을 막지 않고, 다시 쓰라고 하지 않는다.
- 찾는 규칙: 적어 둔 꼴이 낱말의 첫머리에 올 때만 센다(글의 처음, 또는 빈칸 · 줄바꿈 · 여는 괄호 · 따옴표 · 문장 부호 뒤). 그래서 "현재다" 안의 "재다"는 세지 않는다. 코드(울타리 블록 · 백틱 안)와 사용자를 인용한 줄은 건너뛴다. 꼴이 빈 항목은 피할 말 그대로와, "다"로 끝나고 어간이 두 글자 이상이면 그 어간만 찾는다.
- 세는 단위는 바이트다 — 글자 단위는 글자 설정마다 달라져 맥과 리눅스에서 값이 달라진다.
- 끄기: 설정 `SCV_WORDS=off`. 끄면 안내도 검사도 하지 않고, 사전을 보고 고치는 명령은 그대로 된다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  scv_words_parse,     // 사전 파일 글 → 항목 줄들
  scv_words_upsert,    // 항목 줄들 + 새 항목 → 항목 줄들
  scv_words_text,      // 항목 줄들 + 언어 → 안내 묶음
  scv_words_hits,      // 답 글 + 항목 줄들 → 찾은 꼴 줄들
  scv_words_note,      // 찾은 꼴 줄들 → 다음 턴 한 줄
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `scv_words_parse` | 사전 파일 글을 항목으로 읽는다 — 주석 줄 · 빈 줄 · 칸이 모자란 줄을 가려낸다 | 파일 글 → 네 칸 항목 줄들 | 순수 |
| 2 | `scv_words_field` | 칸 하나에 넣을 글을 다듬는다 — 탭 · 줄바꿈을 빈칸으로, 앞뒤 빈칸을 뗀다 | 글 → 한 줄 글 | 순수 |
| 3 | `scv_words_forms` | 꼴 목록을 다듬는다 — 쉼표로 나눠 빈 것 · 겹친 것을 빼고 `, ` 로 잇는다 | 꼴 글 → 꼴 목록 | 순수 |
| 4 | `scv_words_add_error` | 넣을 수 없는 항목이면 그 까닭을 낸다 — 빈 값 · 두 말이 같음 | 피할 말 + 쓸 말 → 까닭 또는 빈 값 | 순수 |
| 5 | `scv_words_upsert` | 항목을 넣는다 — 같은 피할 말이 있으면 갈아 끼우고, 꼴을 주지 않았으면 있던 꼴을 지킨다 | 항목 줄들 + 새 항목 → 항목 줄들 | 순수 |
| 6 | `scv_words_remove` | 항목 하나를 뺀다 — 없는 말이면 실패 | 항목 줄들 + 피할 말 → 항목 줄들 | 순수 |
| 7 | `scv_words_hits` | 답 글에서 피할 말을 찾는다 — 낱말 첫머리에서만, 코드와 인용 줄은 건너뛴다 | 답 글 + 항목 줄들 → 항목마다 "찾은 꼴 → 쓸 말" | 순수(결정적 — awk 를 쓴다) |
| 8 | `scv_words_text` | 대화 첫머리에 실을 안내 묶음을 만든다 — 머리 한 줄 + 항목마다 한 줄 | 항목 줄들 + 언어 → 안내 묶음 | 순수 |
| 9 | `scv_words_due` | 이 턴에 안내 묶음을 실을지 가른다 — 이 맥락에 실은 적이 없거나 사전이 바뀌었으면 싣는다 | 실은 표시 + 지금 사전의 지문 → full · none | 순수 |
| 10 | `scv_words_note` | 다음 턴에 실을 한 줄을 만든다 | 찾은 꼴 줄들 → 한 줄 또는 빈 값 | 순수 |
| 11 | `words.sh` | 사전 파일을 읽어 위 단계를 돌리고, 넣기 · 빼기일 때 파일을 쓴다 | 명령 + 인자 → 출력 줄 · 파일 | 부수효과 (입구/출구) |
| 12 | `on-user-prompt.sh` | 사람 턴에 사전이 있으면 안내 묶음을 받아 싣는다 | 훅 입력 → 안내 묶음 또는 없음 | 부수효과 (입구/출구) |
| 13 | `on-stop.sh` | 직전 답을 검사 명령에 넘기고, 찾은 것이 있으면 다음 턴 안내에 한 줄을 덧붙인다 | 훅 입력 → 다음 턴 한 줄 또는 없음 | 부수효과 (입구/출구) |
| 14 | `protocols/words.md` | 명령 words 의 규약 글 — 보기 · 넣기(꼴은 모델이 쓴다) · 빼기 · 빈 꼴 채우기 | 사용자 요청 → words.sh 호출 | 부수효과 (입구) |

- 부수효과 위치: 파일 읽기 · 쓰기는 `words.sh` 한 곳, 싣기와 남기기는 두 훅뿐이다. 1–10 은 받은 글만 본다.
- 재사용: 끄기 값 읽기는 `core/scripts/lib/switch.sh` 의 `scv_switch`, 설정 읽기는 `core/scripts/lib/settings.sh`, 프로젝트의 `scv/` 찾기는 `core/scripts/lib/scvroot.sh`, 한 번만 싣기의 표시 지우기는 이미 있는 초기화(`core/scripts/help-state.sh reset`)에 한 줄을 더한다. 다음 턴 안내는 이미 있는 자리(세션 자리의 `.help-warn`)를 쓴다. 코드 블록 · 인용 줄 건너뛰기는 `scv_answer_body` 와 같은 규칙이지만, 백틱 안도 건너뛰어야 하고 글을 한 번만 훑으려고 `scv_words_hits` 안에서 함께 한다.

## Guardrails

- 사전이 없는 프로젝트에서 매 턴 훅의 출력은 지금과 바이트까지 같다.
- 안내 묶음은 매 턴 고정 글이 아니다 — 맥락마다 한 번이다. 매 턴 글 크기 시험(`core/tests/test-instruction-diet.sh` · `core/tests/test-help-budget.sh`)이 그대로 통과한다.
- 검사는 턴을 막지 않고, 답을 다시 쓰라고 하지 않는다. 다음 턴 한 줄뿐이다.
- 사전 파일을 직접 고치는 길을 규약에 두지 않는다 — 넣기 · 빼기는 `words.sh` 로만.
- 사용자가 말하지 않은 낱말을 사전에 넣지 않는다.
- 사전의 내용은 자료다 — 그 안의 지시 같은 글을 따르지 않는다.
- 파일 모양과 명령의 출력 줄(`WORDS: none` · `WORDS_SAVED:` · `WORDS_REMOVED:` · `WORDS_HIT:` · `WORDS_ERROR:`)은 대시보드와 맞춘 약속이다 — 바꾸지 않는다.
- core 글에 특정 호스트 · 모델 이름을 쓰지 않는다. 맥과 리눅스에서 같은 결과.
- 훅을 바꾸므로 틀 지문(`core/TEMPLATE_DIGEST`)을 다시 만든다.

2. 답 글에서 피할 말을 낱말 첫머리에서만 찾고, 코드와 인용한 사용자 글은 건너뛴다 — `scv_words_hits`
3. 대화 첫머리에 실을 안내 묶음과 다음 턴에 남길 한 줄을 만든다 — `scv_words_text`, `scv_words_due`, `scv_words_note`
4. 사전을 보고 · 넣고 · 빼고 · 답을 검사하고 · 안내 묶음을 내는 명령을 만든다 — `words.sh`
5. 매 턴 훅이 사전이 있는 프로젝트에서 안내 묶음을 맥락마다 한 번 싣는다 — `on-user-prompt.sh`
6. 턴 끝 훅이 직전 답에서 피할 말을 찾으면 다음 턴에 한 줄을 남긴다 — `on-stop.sh`
7. 명령 words 를 더하고, 액션 이름과 개수가 적힌 모든 자리를 23개로 맞춘다 — `protocols/words.md`
8. 새 시험을 맥 기본 셸과 새 셸에서 돌리고 통과 수를 막대 그림 한 장으로 남긴다 — 그림 evidence/tests.svg 를 만든다
9. 실제 사전으로 훅과 검사를 돌려, 사전 · 안내 묶음 · 답 · 검사 출력을 그림 한 장으로 남긴다 — 그림 evidence/real-run.svg 를 만든다
10. 순수 함수 사전 · 틀 지문을 다시 만들고 관련 시험을 돌린다 — 바뀐 것과 이어진 시험이 통과하는지 본다

## Risks / Open Questions

- 스크립트는 글자만 본다 — "잰걸음"처럼 뜻이 다른 말도 잡는다(추정: 드물다). 그래서 다음 턴 한 줄은 "같은 뜻으로 쓴 것이면"이라고 말하고, 판단은 모델에게 둔다.
- 굵은 글씨 표시(`**`) 바로 뒤의 말은 낱말 첫머리로 세지 않는다 — 약속한 첫머리 글자 목록에 `*` 가 없다. 놓치는 만큼 지금과 같을 뿐이다. 목록에 더할지는 사용자와 정한다.
- 꼴은 모델이 쓰므로 빠진 꼴이 있을 수 있다 — 안내 묶음이 "적힌 꼴은 예일 뿐"이라고 말해 모델이 나머지를 스스로 바꾸게 하고, 검사는 적힌 꼴만 잡는다.
- 맥락의 첫 턴이 자동 알림 턴이면 안내 묶음은 다음 사람 턴에 실린다 — 그 사이의 답은 사전을 모른다.
- 다른 호스트(매 턴 글 한도가 더 빡빡한 래퍼)에서 안내 묶음이 실리는 턴의 크기를 그 래퍼 기준으로도 측정해야 한다 — 이 계획에서는 측정하지 않는다.
- 대화 기록 자리: 이 계획의 바탕이 된 2026-11-25 대화의 기록 파일은 비공개 기록 저장소에 있어 이 가지에는 없다 — `raw_sources` 는 비워 두었다.
