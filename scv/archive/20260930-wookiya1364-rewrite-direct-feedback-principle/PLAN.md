# 다시 쓴 요청에 SCV 원칙을 붙인다

## Summary

사용자 요구: SCV 가 모델 · 버전별로 다시 쓴 요청을 클로드 코드 · 코덱스에 넘길 때 원칙을 함께 붙인다 — SCV 사용자는 정확한
피드백을 가장 중요하게 여기므로, 듣기 좋은 말 대신 사실을 말하고, 풀 문제는 작은 단위로 나눠 단위마다 해결책을 제시해 잇고,
생길 수 있는 문제를 뭉뚱그리지 말고 어디가 진짜 문제인지 콕 집어 말하게 한다. 결정(대화 Turn 2~4): 원칙은 붙이기만 하고 답은
검사하지 않는다, 답은 '단위 | 해결책 | 추천 | 생길 수 있는 문제' 네 칸 표와 문제 표로 쓴다, 표는 터미널에서 실제 격자로 보여야
한다(칸이 길면 줄글처럼 풀려 보인다 — 사용자 화면으로 확인), 매 답의 인용에는 짧은 표식만 보이고 전문은 모델만 받는다, 도움말의
기존 표와 겹치면 네 칸 표로 통일한다.

## Goals / Non-Goals

- **Goals**
  - **원칙 문구 한 곳**: 원칙 전문을 한 파일(한 · 영 · 일 세 벌)에 둔다. 초안(한국어):

    > [SCV 원칙] 이 사용자는 정확한 피드백을 가장 중요하게 여긴다. 듣기 좋은 말 대신 사실을 말하라. 풀 문제가 있으면 작은
    > 단위로 나눠 두 표로 답하라.
    > 1. 단위 표 — '단위 | 해결책 | 추천 | 생길 수 있는 문제' 네 칸. 해결책은 쓸 수 있는 방법에 번호를 붙여 모두 적고, 추천은
    >    그중 하나와 고른 이유를 적는다(해결책과 추천은 다를 수 있다). 생길 수 있는 문제 칸에는 문제 번호(P1, P2…)만 적는다.
    > 2. 문제 표 — '번호 | 위치 | 조건 | 깨지는 것 | 확인' 다섯 칸. 위치는 파일:줄 · 명령 · 설정 이름으로 콕 집는다. 확인 칸은
    >    "확인: 어떻게 확인했는지" 또는 "추정: 무엇을 보면 확인되는지". 뭉뚱그린 말 대신 찾아서 위치를 대고, 끝내 찾지 못했으면
    >    찾아본 범위와 방법을 적는다. 문제가 없으면 "없음(확인한 범위: …)" 한 행.
    > 두 표 모두 한 행이 터미널 한 줄(약 80칸, 한글 약 40자)에 들어가게 칸을 짧게 쓴다 — 넘치면 표가 줄글처럼 풀려 보인다.
    > 길어지는 설명은 표 아래 번호 메모로 옮긴다.

  - **등록 결과에 싣기**: 등록이 성공하면 다시 쓴 요청 줄 끝에 짧은 표식(`[SCV 원칙 적용 — 단위 표 · 문제 표]`, 언어별)을 붙이고,
    그 아래 원칙 전문을 싣는다. 모델은 다시 쓴 요청 줄을 그대로 인용하므로 표식이 매 답의 인용에 보이고, 전문은 모델만 읽는다.
  - **규약 예외 한 줄**: 다시 쓰기 규약의 "요구를 더하지 말 것"에 SCV 원칙만 예외로 적고(원칙 파일을 가리킴), 원칙대로 답하라는
    한 줄을 더한다.
  - **도움말 표 통일**: 풀 문제가 있으면 도움말 답 모양의 항목 표(항목 · 지금 · 바뀔 것 · 크기) 대신 원칙의 두 표를 쓴다 —
    "지금 상태(확인)"는 단위 칸에, "크기"는 추천 칸에 적는다. 도움말 답 모양 절은 2026-09-16 잠금(바이트 그대로)을 지켜 고치지
    않는다(사용자 결정 2026-10-01) — 원칙 파일이 "항목 표 대신"을 선언하고 다시 쓰기 규약이 "원칙대로 답하라"고 한다(Top-level
    rules 해소 순서 4: 대신한다고 밝힌 나중 규칙). 결정 표(번호 · 정할 것 · 추천)는 그대로 둔다.
  - **스위치**: 설정 `SCV_REWRITE_PRINCIPLE`(기본 `on`, `off` 면 지금과 같음). 모델별 프롬프팅이 꺼져 있으면(등록을 안 하므로)
    원칙도 붙지 않는다.
- **Non-Goals**
  - 답 검사 — 표가 있는지, 위치가 적혔는지를 SCV 가 판정하거나 막지 않는다(사용자 결정: 붙이기만).
  - 매 턴 안내문에 원칙 싣기 — 용량 상한이 있는 곳이라 넣지 않는다.
  - 모델별로 다른 원칙 문구 — 한 문구로 시작한다(필요해지면 나중에 모델별 덮어쓰기).
  - 래퍼 CI 의 README 검사 연결 — 같은 코어 릴리스 사슬에서 따로 한다(사용자 결정 2026-09-30).

## Approach Overview

다시 쓴 요청은 등록 명령이 제출에서 꺼내 그대로 출력한다(`scv_mp_register_rewrite` → `REWRITE:` 줄). 이 출력 끝에만 표식을
붙이고 원칙 전문 줄을 더한다 — 저장되는 제출(`.help-rewrite`)과 종료 훅의 인용 판정(앞 16글자)은 건드리지 않으므로 기존 등록 ·
인용 · 차단 동작이 그대로다. 원칙 문구는 파일 하나에서 읽고(언어별 구역), 규약 · 도움말은 그 파일을 가리킨다. 스위치가 꺼지면
출력은 지금과 같다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  scv_mp_register_normalize,     // 제출 텍스트 → 탭 구분 제출 (있음)
  scv_mp_register_rewrite,       // 탭 구분 제출 → 다시 쓴 요청 (있음)
  scv_mp_rewrite_tagged,         // (다시 쓴 요청, 스위치, 표식) → REWRITE 줄 값 (새)
)
scv_mp_principle_text            // (원칙 파일 본문, 언어) → 그 언어의 원칙 전문 · 표식 (새)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | 설정 · 원칙 파일 읽기 | 설정 파일 · 원칙 파일 경로 → 스위치 · 언어 · 원칙 본문 | 부수효과 (입구) |
| 2 | scv_mp_principle_text | 원칙 본문, 언어 → 전문 · 표식 (모르는 언어는 영어) | 순수 |
| 3 | scv_mp_register_normalize · scv_mp_register_rewrite | 제출 → 다시 쓴 요청 | 순수 (있음) |
| 4 | scv_mp_rewrite_tagged | 다시 쓴 요청, 스위치, 표식 → REWRITE 줄 값 (off 면 그대로) | 순수 |
| 5 | 출력 | REGISTERED · REWRITE · 원칙 전문 줄 인쇄 | 부수효과 (출구) |

- 부수효과 위치: 설정 · 원칙 파일 읽기(입구)와 등록 결과 인쇄(출구) — 둘 다 `model-prompting.sh register` 안.
- 재사용: 제출 정규화 · 다시 쓴 요청 꺼내기 · 종료 훅 판정은 그대로 쓴다.

## Guardrails

- 매 턴 안내문(`scv_mp_turn_block`)에 원칙을 넣지 않는다 — 매 턴 용량 상한 검사(`test-help-budget` T12) 수치가 그대로여야 한다.
- 도움말 답 모양 · 언어 · 쉬운 말 절은 바이트 그대로(2026-09-16 잠금, `test-help-router-diet` T2) — 사용자 결정 2026-10-01.
- 종료 훅 판정(`scv_mp_answer_shows_rewrite` · `scv_mp_stop_gate`)을 바꾸지 않는다.
- 저장되는 제출(`.help-rewrite`)에 표식 · 원칙을 넣지 않는다 — 출력에서만 붙인다.
- 답 검사(표 · 위치 유무)를 넣지 않는다 — 사용자 결정.
- 원칙 문구를 두 곳 이상에 쓰지 않는다(최상위 규칙 4조) — 규약 · 도움말 · 검사는 원칙 파일을 가리키거나 파일에서 읽는다.
- 엄격 모드 훅 · 스크립트의 새 환경 변수에는 기본값을 붙이고, 변수를 비운 채로도 검사한다(교훈 2026-09-28).
- 사용자 원문을 지우거나 바꾸지 않고, 모델 · 사고량을 건드리지 않는다.

## Exit criteria

- TESTS.md 전 시나리오 통과 — 맥 · 리눅스 CI 로그에서 새 검사 줄을 각각 확인한다(교훈 2026-09-28).
- 코덱스 벤더 도구로 만든 임시 사본에서 코어 검사 전부 통과.
- 설치본 실측 한 턴: 등록 결과에 표식 · 원칙 전문이 나오고, 답의 인용에 표식이 보이며, 원칙대로 쓴 두 표가 사용자 터미널에서
  격자로 보인다.

## Suggested path

1. 원칙 파일(한 · 영 · 일)과 그 본문에서 언어별 전문 · 표식을 꺼내는 순수함수.
2. 등록 출력: REWRITE 줄 끝 표식 + 원칙 전문 줄(스위치 on), off 면 지금과 같게.
3. 다시 쓰기 규약: "요구를 더하지 말 것"의 SCV 원칙 예외 한 줄(원칙 파일을 가리킴)과 인용 표식 안내.
4. 표 통일: 원칙 파일의 "도움말 답의 항목 표 대신" 선언과 다시 쓰기 규약의 "원칙대로 답하라"(도움말 답 모양 절은 그대로).
5. 설정 예시에 스위치(기본 on).
6. 검사 추가, 기존 검사 전부, 코덱스 사본, 맥 · 리눅스.
7. CHANGELOG — 다음 코어 릴리스 사슬에서 VERSION 과 함께(래퍼 CI README 검사 연결도 같은 사슬).

## Risks / Open Questions

- 표 폭 기준(한 행 약 80칸)은 확인됐다(2026-09-30, 대화 Turn 5) — 칸이 긴 네 칸 표는 사용자 터미널에서 줄글처럼 풀렸고(사용자
  화면), 칸을 짧게 쓴 단위 표 · 문제 표(한 행 약 80~90칸)는 격자로 보였다(사용자 확인). 더 좁은 터미널에서의 모양은 확인하지
  않았다.
- 등록 결과가 매 턴 약 1.2KB 늘어난다(추정: 한글 약 400자) — 매 턴 안내문 상한과는 별개지만 모델이 읽는 양은 는다.
- 원칙이 모델마다 다르게 먹힐 수 있다 — 한 문구로 시작하고, 설치본 실측에서 어긋나면 모델별 덮어쓰기를 검토한다.
- 모델이 원칙을 따르지 않아도 SCV 는 막지 않는다(설계) — 표식이 인용에 떠 있어 사람이 바로 알아본다.
- 코덱스 훅의 차단 출력 형식은 여전히 미확인(기존 미결) — 등록 결과는 일반 출력이라 영향이 없을 것으로 본다(추정).
