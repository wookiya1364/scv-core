# 대시보드에 "사용자 차례" 상태와 색

## Summary

모델이 말을 끝내고 사용자의 다음 말을 기다릴 때도 대시보드는 그 단계를 노랑 "진행 중"으로 보인다. 그래서 일하는 중인지 내 말을 기다리는지 알 수 없어 "지금 어디까지 했어?"를 되풀이해 묻게 된다(사용자의 말, 2026-11-12).
턴이 끝났고, 하는 중인 단계가 있고, 빨강으로 보일 멈춤이 없고, 도는 보조 작업이 없으면 그 단계를 "사용자 차례"라는 새 상태 · 새 색으로 보인다.

## Goals / Non-Goals

- **Goals**
  - 턴이 끝난 뒤 사용자의 말을 기다리는 단계가 "사용자 차례"로 보인다 — 단계 점 · 단계 글 · 윗줄 글 · 진행 막대 · "다음 할 일" 글
  - 새 색은 초록 · 노랑 · 빨강 · 회색과 겹치지 않는다. 실제 화면을 사용자에게 보인 뒤 확정한다
  - 배경 작업(보조 작업, 배경으로 띄운 명령, 스스로 맞춘 깨우기)이 끝나기를 기다리며 끝난 턴은 "사용자 차례"가 아니다 — 노랑을 유지하고 글만 "배경 작업 기다림"으로 바꾼다
  - 다른 기기에서 보는 화면(거울 세션)도 같은 상태를 그린다
  - 사용자가 다시 말하거나 모델의 턴이 다시 시작되면 노랑 "진행 중"으로 돌아간다
- **Non-Goals**
  - 빨강의 뜻 바꾸기
  - 휴대폰 알림 더하기 · 바꾸기
  - 코어의 훅 고치기 (대시보드가 이미 턴의 시작 · 끝을 받는다)
  - 계획 글의 진행 줄 형식 바꾸기 ("N단계 시작 | 끝 | 막힘" 그대로)

## Approach Overview

사용자가 2026-11-12 선택 창에서 정한 것: 개요 "개요대로 쓰기", 대시보드 릴리스 "이 계획이 끝나면 바로", 그림 "넷 다 그림 없이", 마무리 "합치기까지 자동".

읽은 사실 (2026-11-12, 대시보드 0.2.23 의 원본 — 옆 저장소 scv-mods):

- 단계 상태는 넷이다: `done` · `doing` · `blocked` · `waiting` (`types/index.d.ts` 1줄). 색은 두 곳에 있다 — 단계 점 그림의 `NODE_COLOR`(`hooks/model.ts` 858줄)와 글의 `STATE_COLOR`(`hooks/register.tsx` 116줄).
- 대시보드는 모델의 턴이 시작될 때와 끝날 때를 받는다(`turn.start` · `turn.complete`, `hooks/register.tsx` 640 ~ 684줄). 끝나면 `live.isWorking` 이 거짓이 된다. 메모에서 "턴 끝을 가리는 상태가 없다"고 적은 것은 정확히는 "턴 끝은 알지만 단계의 색과 글에 쓰지 않는다"이다.
- "진행 중" 카드의 오른쪽 글은 이미 "일하는 중"(파랑 `#4f8cff`) · "쉬는 중"(회색)을 가린다(`hooks/register.tsx` 1047줄). 그러나 단계 점은 노랑, 단계 글은 "진행 중 ◀ 지금 여기", 윗줄은 "N단계 진행 중", 다음 할 일은 "진행 중 — 기다리면 됩니다"로 남는다.
- 도는 보조 작업은 `agents` 목록으로 안다(시작 · 끝을 받는다). 메인 대화의 도구 호출은 입력과 함께 받는다(`tool.call`, 764줄) — 배경으로 띄운 명령인지 볼 수 있다.
- 거울 세션에 보내는 상태(`mirrorState`, 385줄)에 `live` 와 `agents` 가 들어 있다.
- 파랑 `#4f8cff` 은 이미 "일하는 중" 글에 쓴다. 새 상태에 파랑을 쓰면 "일하는 중"과 헷갈릴 수 있다 — 보라를 함께 만들어 실제 화면으로 견준다.

하는 일:

1. **판정** — 순수 함수 하나가 "일하는 중 | 사용자 차례 | 배경 작업 기다림"을 가린다. 받는 값: 턴이 도는 중인가, 살아 있는 멈춤(오류 · 허락 · 선택 창)이 있는가, 도는 보조 작업 수, 이번 턴에 배경 작업을 띄웠는가.
2. **단계에 입히기** — "사용자 차례"이면 하는 중인 단계 하나의 상태를 새 상태로 바꾼다. 다른 단계와 막힌 단계는 건드리지 않는다.
3. **배경 작업 알기** — 메인 대화가 배경으로 명령을 띄우거나 스스로 깨우기를 맞추면 표시를 남기고, 다음 턴이 시작되면 지운다.
4. **색과 글** — 새 상태의 색 하나를 두 색 표에 더하고, 단계 글 · 윗줄 · 다음 할 일 · 진행 막대가 새 상태를 읽게 한다.
5. **거울** — 보내는 상태에 배경 작업 표시를 더한다.
6. **실제 화면 보이기** — 네 장면을 실제 그림으로 만들어 사용자에게 보이고 색을 확정한다.
7. **릴리스** — 대시보드만 새 버전으로 낸다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

화면에 그릴 값은 지금도 순수 함수의 줄로 만든다. 그 줄에 판정과 입히기 두 단계를 끼운다. 저장된 값(턴 상태 · 보조 작업 · 배경 표시)을 읽는 것은 화면을 그리는 입구에서, 그리는 것은 출구에서 한다.

```
flow(
  deriveStages,   // 계획 → 단계들                                    (순수, 그대로)
  findBlocks,     // 단계들 · 시험 결과 · 멈춤 셋 → 멈춤 목록          (순수, 그대로)
  applyBlocks,    // 단계들 · 멈춤 목록 → 단계들                       (순수, 그대로)
  turnStateOf,    // 도는 중 · 턴 끝을 봤는가 · 멈춤 목록 · 보조 작업 수 · 배경 표시 → 일하는 중 | 사용자 차례 | 배경 작업 기다림  (순수, 새로)
  applyTurn,      // 단계들 · 턴 상태 → 단계들                         (순수, 새로)
  headline,       // 단계들 · 멈춤 목록 · 턴 상태 → 윗줄 글            (순수, 고침)
  nextAction,     // 단계들 · 멈춤 목록 · 턴 상태 → 다음 할 일         (순수, 고침)
  barColor,       // 단계들 · 멈춤 목록 → 막대 색                      (순수, 고침)
  nodeIconSvg,    // 단계 상태 → 점 그림                               (순수, 색 표만)
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | deriveStages | 계획의 진행 줄과 신호로 단계 상태를 정한다 | 계획 → 단계들 | 순수 |
| 2 | findBlocks | 살아 있는 멈춤과 시험 실패를 모은다 | 단계들 · 시험 결과 · 멈춤 셋 → 멈춤 목록 | 순수 |
| 3 | applyBlocks | 멈춤이 있으면 하는 중인 단계를 막힘으로 바꾼다 | 단계들 · 멈춤 목록 → 단계들 | 순수 |
| 4 | turnStateOf | 일하는 중인지, 사용자 차례인지, 배경 작업을 기다리는지 가린다 | 도는 중 · 턴 끝을 봤는가 · 멈춤 목록 · 보조 작업 수 · 배경 표시 → 턴 상태 | 순수 |
| 5 | applyTurn | 사용자 차례이면 하는 중인 단계 하나를 새 상태로 바꾼다 | 단계들 · 턴 상태 → 단계들 | 순수 |
| 6 | headline | 윗줄 한 줄을 만든다 | 단계들 · 멈춤 목록 · 턴 상태 → 글 | 순수 |
| 7 | nextAction | 사용자가 다음에 할 일을 말한다 | 단계들 · 멈춤 목록 · 턴 상태 → 글과 명령 | 순수 |
| 8 | barColor | 진행 막대의 색을 고른다 | 단계들 · 멈춤 목록 → 색 | 순수 |
| 9 | nodeIconSvg | 단계 점 그림을 만든다 | 단계 상태 → 그림 | 순수 |

- 부수효과 위치: 입구 — 화면을 그릴 때 저장된 값(턴 상태 · 보조 작업 · 배경 표시)을 읽는다. 사건을 받을 때(`tool.call` · `turn.start`) 배경 표시를 적고 지운다. 출구 — 화면을 그린다, 거울 세션에 상태를 보낸다.
- 재사용: 1 ~ 3 과 9 는 그대로 쓴다. 6 ~ 8 은 인자 하나를 더 받거나 새 상태를 읽게만 고친다.
- 표에 없는 도우미: `isBackgroundStart`(도구 이름 · 입력 → 배경으로 남는 일을 띄우는가, 순수) — 사건을 받는 쪽이 배경 표시를 적을지 정할 때 쓴다. 화면을 만드는 줄에는 들지 않는다.
- 거울 세션: 턴 끝 표시와 배경 표시를 이미 보내던 `live` 값에 실었다. 보내는 쪽 · 받는 쪽 코드는 고치지 않았다.

## Guardrails

- 빨강으로 보이는 경우(오류 · 거절 · 허락 · 선택 창 · 시험 실패)는 하나도 "사용자 차례"로 바꾸지 않는다 — 멈춤이 있으면 판정은 그쪽이 이긴다.
- 색 값 넷(`#3fb950` · `#e3b341` · `#f85149` · `#6e7681` / 글의 회색 `#8b949e`)을 고치지 않는다.
- 계획 글의 진행 줄, 단계 신호 도구의 입력(`doing` · `done` · `blocked`)을 바꾸지 않는다 — 새 상태는 화면에서만 생기고 어디에도 저장하지 않는다.
- 코어 저장소의 코드는 고치지 않는다. 이 저장소에는 계획 글과 기록만 쓴다.
- 대시보드 저장소에 이미 있는 커밋 안 된 변경(`scv/` 아래 셋)은 건드리지 않고 커밋에도 넣지 않는다.
- 새 색은 사용자가 실제 화면을 보고 고른 값으로 확정한다. 그 전에는 릴리스하지 않는다.

## Exit criteria

- TESTS.md 의 T1 ~ T8 이 통과한다
- 사용자가 실제 화면을 보고 색을 정했다
- 대시보드 저장소의 develop 에 합쳐지고, 새 버전이 릴리스됐다
- 남는 확인(T9): 설치된 대시보드를 새 버전으로 올린 뒤 실제 세션에서 턴이 끝났을 때 새 색으로 보이는 것 — 사용자의 앱에서 본다

## Suggested path

1. 판정 함수와 단계에 입히는 함수를 더하고, 값만 넣는 시험을 먼저 쓴다 — `turnStateOf`, `applyTurn`
2. 새 상태를 자료 모양과 두 색 표 · 글 표에 더한다 — `nodeIconSvg`
3. 윗줄 · 다음 할 일 · 진행 막대가 새 상태와 배경 작업 기다림을 읽게 한다 — `headline`, `nextAction`, `barColor`
4. 배경으로 띄운 명령과 스스로 맞춘 깨우기를 표시로 남기고, 다음 턴이 시작되면 지운다 — 사건을 받아 저장된 값을 적는 일
5. 화면 조립부가 새 두 단계를 거치게 하고, 거울 세션에 보내는 상태에 배경 표시를 더한다 — `turnStateOf`, `applyTurn`
6. 네 장면의 실제 그림을 만들어 사용자에게 보이고 색을 확정한다 — 실제 화면으로 색과 글을 확인받는 일
7. 대시보드 시험 전부를 돌리고, 대시보드 저장소에 PR 을 올려 합친다 — 관련 시험을 돌려 통과를 확인하는 일
8. 대시보드 새 버전을 릴리스한다 — 릴리스 글을 쓰고 릴리스 스크립트를 돌리는 일

## Risks / Open Questions

- 배경 작업이 아직 도는데 다른 까닭으로 턴이 한 번 더 돌고 끝나면, 그 턴에는 배경 표시가 없어 "사용자 차례"로 잘못 보일 수 있다. 배경 작업이 끝나 다음 턴이 시작되면 바로 노랑으로 돌아온다. 대시보드가 듣는 사건 목록(`hooks/register.tsx` 의 `on(…)` 18곳)에는 배경 명령이 끝나는 사건이 없다 — 릴리스 글의 "알아 둘 것"에 적었다.
- 막 연 세션은 지금처럼 "진행 중"으로 보인다. 그 세션이 턴의 끝을 본 적이 없어서, 다른 세션이 그 계획을 하고 있는지 알 수 없기 때문이다(구현하며 정함 — 처음에는 "사용자 차례"로 보이려 했으나, 그러면 다른 세션이 일하는 계획도 그렇게 보인다). 턴이 한 번 끝나면 그때부터 가려 보인다.
