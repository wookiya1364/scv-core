# Test Plan — 대시보드에 "사용자 차례" 상태와 색

## Overview

모델의 턴이 끝나 사용자의 말을 기다릴 때 대시보드가 그 단계를 노랑 "진행 중"이 아니라 "사용자 차례"(새 색)로 보이는지 확인한다. 빨강으로 보여야 하는 멈춤과 배경 작업을 기다리는 경우가 "사용자 차례"로 잘못 보이지 않는지도 함께 본다.

시험은 옆 저장소(scv-mods)의 대시보드 시험 파일에 더한다. 지금 기준은 118개 통과다.

## Test scenarios

### T1. 판정 — 사용자 차례

- **Setup**: 값만 넣는다. 턴이 돌지 않음, 하는 중인 단계 하나, 멈춤 없음, 도는 보조 작업 0, 배경 표시 없음.
- **Run**: 판정 함수.
- **Expected**: "사용자 차례".
- **Pass criterion**: 판정 함수가 `yourTurn` 을 돌려준다 — 시험 줄 `(pass) your-turn T1`.

### T2. 판정 — 사용자 차례가 아닌 경우

- **Setup**: 다음 여섯 가지를 하나씩 넣는다 — (가) 턴이 도는 중 (나) 선택 창의 답을 기다림 (다) 도구 허락을 기다림 (라) 오류로 멈춤 (마) 도는 보조 작업 1개 (바) 이번 턴에 배경 작업을 띄움.
- **Run**: 판정 함수.
- **Expected**: (가) ~ (라)는 "일하는 중"(빨강 멈춤은 지금처럼 멈춤 목록이 그린다), (마) · (바)는 "배경 작업 기다림".
- **Pass criterion**: (가) ~ (라)는 `working`, (마) · (바)는 `background` — 시험 줄 `(pass) your-turn T2`.

### T3. 단계에 입히기

- **Setup**: 단계 넷 — 끝 · 하는 중 · 아직 · 아직.
- **Run**: 입히는 함수에 "사용자 차례" · "배경 작업 기다림" · "일하는 중"을 차례로 준다.
- **Expected**: "사용자 차례"일 때만 둘째 단계가 새 상태가 된다. 나머지 단계와 나머지 두 경우는 그대로다. 막힌 단계가 있는 목록은 어느 경우에도 바뀌지 않는다.
- **Pass criterion**: 사용자 차례일 때 `done · yourTurn · waiting · waiting`, 나머지 둘은 `done · doing · waiting · waiting` — 시험 줄 `(pass) your-turn T3`.

### T4. 색

- **Setup**: 색 표 둘(단계 점 그림 · 글).
- **Run**: 새 상태의 색을 읽고, 단계 점 그림을 만든다.
- **Expected**: 새 상태의 색이 있고, 초록 `#3fb950` · 노랑 `#e3b341` · 빨강 `#f85149` · 회색 `#6e7681` · `#8b949e` 과 다르다. 점 그림이 그 색으로 채워진다. 네 색의 값은 그대로다.
- **Pass criterion**: 새 색 `#a371f7` 이 `#3fb950` · `#e3b341` · `#f85149` · `#6e7681` · `#8b949e` · `#4f8cff` 과 다르고, 점 그림에 `fill="#a371f7"` 이 있다 — 시험 줄 `(pass) your-turn T4`.

### T5. 글

- **Setup**: 2단계가 하는 중인 계획.
- **Run**: 윗줄과 다음 할 일을 "사용자 차례" · "배경 작업 기다림" · "일하는 중"으로 만든다.
- **Expected**: 사용자 차례 — 윗줄이 `2단계 사용자 차례` 로 시작하고, 다음 할 일이 `사용자 차례 — 대화창에서 이어서 하라고 말해 주세요`. 배경 작업 기다림 — 윗줄이 `2단계 진행 중` 으로 시작하고, 다음 할 일이 `배경 작업을 기다리는 중 — 끝나면 스스로 이어집니다`. 일하는 중 — 지금과 같다(`2단계 진행 중` · `진행 중 — 기다리면 됩니다`).
- **Pass criterion**: 윗줄 `2단계 사용자 차례 · 막힘 없음 · 남은 시간 추정 불가` 와 위의 다음 할 일 글 셋이 글자 그대로 — 시험 줄 `(pass) your-turn T5`.

### T6. 화면 — 턴이 끝나면 바뀌고, 다시 시작되면 돌아온다

- **Setup**: 진행 중인 계획 하나가 있는 가짜 세션.
- **Run**: 턴 시작 → 화면 → 턴 끝(답으로 끝남) → 화면 → 사람의 말과 턴 시작 → 화면.
- **Expected**: 첫 화면과 셋째 화면은 단계 글 `진행 중`, 둘째 화면은 `사용자 차례` 와 다음 할 일 글. 진행 막대의 색이 둘째 화면에서만 새 색이다.
- **Pass criterion**: 둘째 화면에만 `사용자 차례  ◀ 지금 여기` 와 막대 색 `#a371f7`, 첫째 · 셋째 화면에는 `2단계 진행 중` — 시험 줄 `(pass) your-turn T6` · `T6b`(사용자가 멈춘 차례 뒤).

### T7. 화면 — 빨강과 배경 작업은 그대로

- **Setup**: T6 과 같은 가짜 세션.
- **Run**: (가) 선택 창을 띄운 채 화면 (나) 오류로 턴이 끝난 뒤 화면 (다) 배경으로 명령을 띄우고 턴이 끝난 뒤 화면 (라) 보조 작업이 도는 채 턴이 끝난 뒤 화면.
- **Expected**: (가) · (나)는 지금처럼 막힘(빨강)과 그 글. (다) · (라)는 단계 글 `진행 중`, 다음 할 일 `배경 작업을 기다리는 중 — 끝나면 스스로 이어집니다`. 넷 모두 `사용자 차례` 글이 없다.
- **Pass criterion**: 네 화면에 `사용자 차례` 0번, (가)에 `2단계 막힘`, (나)에 `멈춤 — 오류`, (다) · (라)에 `다음: 배경 작업을 기다리는 중 — 끝나면 스스로 이어집니다` — 시험 줄 `(pass) your-turn T7`.

### T8. 거울 세션과 기존 시험

- **Setup**: 거울 세션에 보내는 상태.
- **Run**: 배경 표시가 있는 상태를 보내고 받은 쪽의 화면을 그린다. 그리고 대시보드 시험 전부를 돌린다.
- **Expected**: 받은 쪽도 배경 작업 기다림으로 그린다. 기존 118개가 모두 통과한다.
- **Pass criterion**: 시험 실행의 끝이 `127 pass` · `0 fail` (기존 118 + 새 9), 거울은 시험 줄 `(pass) your-turn T8`.

### T9. 실제 앱에서 보기 (릴리스 뒤 사용자 확인)

- **Setup**: 설치된 대시보드를 새 버전으로 올린 실제 세션, 진행 중인 계획.
- **Run**: 모델의 턴이 끝난 뒤 대시보드를 본다.
- **Expected**: 그 단계가 새 색 `사용자 차례` 로 보인다. 다시 말을 보내면 노랑 `진행 중` 으로 돌아온다.
- **Pass criterion**: 사용자의 앱에서 턴이 끝난 뒤 단계 글이 `사용자 차례` 이고 색이 보라 `#a371f7` 이다. 이 계획 안에서는 확인하지 못한다.

## How to run

```bash
cd ../scv-mods/marketplace/mods/scv-dashboard && claude plugin test .
```

## Pass criteria

- 시험 실행의 끝이 `127 pass` · `0 fail` (T1 ~ T8)
- 색 값이 사용자가 고른 보라 `#a371f7` 이다 (2026-11-12 선택 창 답 "보라로 확정")
- T9 는 릴리스 뒤 사용자의 앱에서 본다
