Summary

/scv:deck 산출물이 쓸 수 없는 상태다. 다이어그램은 자연 크기의 절반으로 찌그러져 16px 글자가 7.7px 로 나오고, 색은 프롬프트에 박혀 있어 라이트·다크 양쪽에서 다 깨진다. 이 계획은 데크를 다크 전용으로 바꾸고, 대표님 DesignSystem 의 토큰과 크롬을 이식하고, 구운 SVG 에서 색을 벗겨내 CSS 가 칠할 수 있게 만든다.

Approach Overview

다이어그램 (가장 중요)

두 가지가 겹쳐 있다. 크기와 색이다.

크기 — static-mermaid.mjs 가 width="100%" + max-width:1437px 를 그대로 둔다. 840px 칼럼(패널 열리면 694px)에 들어가면서 0.483 배로 줄어든다. viewBox 실제 크기를 width/height 로 박고, pre.mermaid 를 overflow-x:auto 로 만들고, 본문 칼럼 바깥으로 내보낸다.

색 — promote.md 가 모델에게 붙여넣게 한 %%{init:...}%% 가 렌더러를 이기고, 헤드리스 크롬이 그 색으로 SVG 를 굽는다. 해법은 구운 SVG 를 다시 칠할 수 있게 정규화하는 것:

  1. 펜스에서 %%{init:...}%% 를 렌더 직전에 떼어낸다 (데크 사본만 — 디스크의 .md 와 GitHub 렌더링은 그대로)
  2. SVG 자체 <style> 의 #mermaid-<타임스탬프> → .scv-mmd, !important 제거. 특이도가 (1,1,0) → (0,1,0) 이 되어 일반 규칙이 이긴다
  3. 인라인 style= 에서 fill/stroke/color/background 제거. classDef 가 박는 style="fill:#FFE082 !important" 는 이것 말고는 못 이긴다
  4. id 를 scv-mmd-1 로 고정 — url(#...) 참조 일관성 + 재빌드 바이트 동일
  5. 토큰으로 칠하는 <style> 블록을 페이지에 넣는다

빌드 때 크롬이 없으면 로더가 실려 나가는 대체 경로가 있다. 같은 정규화를 클라이언트 쪽에도 넣어 두 형태가 같은 DOM 으로 수렴하게 한다.

토큰

대표님 DesignSystem/src/index.css 의 .dark 블록을 oklch → sRGB 로 변환해 쓴다. 전부 무채색이다. SCV 의 파란 기 도는 회색(#171922·#1d2029·#2c3040·#9096a8)이 두 덱을 다른 시스템으로 보이게 하던 가장 큰 원인이다.

경계선은 알파로 둔다(rgba(255,255,255,.10)). 한 값이 배경 위에서도 카드 위에서도 올바르게 합성된다 — 대표님 쪽이 그렇게 한다.

장미는 두 개다. 원본 #a50036 은 칠하는 색으로 쓰고(흰 글자 7.58:1), 글자에는 같은 색상에서 밝기만 올린 #fc7184 를 쓴다(배경 위 7.39:1). 원본을 글자에 쓰면 2.50:1 이라 안 읽힌다 — 대표님 Kicker 가 지금 그렇게 하고 있다.

활성 알약은 밝은 장미 바탕 + 검은 글자다. 어두운 장미로 칠하면 배경과 2.50:1 이라 어느 게 켜졌는지 안 보인다.

크롬

grid-template-rows:auto 1fr auto 로 100svh 를 헤더/본문/푸터로 나눈다. 대표님 SlideDeck.tsx:94 의 h-svh flex-col 을 평범한 CSS 로 옮긴 것이다.

  • 헤더: 제목 + 목차 한 줄(가로 스크롤) + 패널 토글
  • 본문: 스크롤 영역 + 사이드 패널 (이미 있는 것 거의 그대로)
  • 푸터: 진행 점 + N/M + 이전/다음

목차는 nowrap 이다. 대표님 쪽은 flex-wrap 과 overflow-x-auto 를 같이 걸어서 flex-wrap 이 이기는데, SCV 라벨 19 개를 먹이면 3 줄로 늘어난다. 여기서만 원본과 다르게 가고, 그 이유를 주석에 남긴다.

Guardrails

  • 디스크의 마크다운을 건드리지 말 것. %%{init}%% 를 떼는 것은 데크가 읽어들인 사본에서만이다. .md 파일과 GitHub 렌더링은 그대로 남는다.
  • 정적 SVG 계약을 깨지 말 것. test-deck-static-mermaid.sh 가 embedded diagrams=1, data-scv-static-mermaid="true", 로더 부재를 단언한다. 전부 유지.
  • 정규화는 열린 채로 실패할 것. 헤드리스 크롬 DOM 을 정규식으로 다루므로 mermaid 마크업이 바뀌면 깨진다. try/catch 로 감싸서 오늘 동작으로 떨어지게 하고, CI 단언을 붙여 조용히 되돌아가는 것을 막는다.
  • --muted 를 글자색으로 쓰지 말 것. shadcn 규약에서 --muted 는 표면이고 글자는 --muted-foreground 다. 지금 SCV 는 반대로 쓰고 있어서 소비처 12 곳을 먼저 이름부터 정리해야 한다. 이걸 건너뛰면 회색 글자가 회색 배경이 된다.
  • 본문 4.5:1, 선·도형 경계 3:1 아래로 내려가지 말 것. 색을 제안할 때마다 그 색이 놓이는 표면 기준으로 측정한다.
  • 한글을 깨지 말 것. 폰트 스택이 한글과 라틴을 같은 문장에서 일관되게 덮어야 한다.
  • 재빌드 바이트 동일. 타임스탬프 id 를 고정 id 로 바꾸는 이유가 이것이다.
  • 슬라이드 모드·세 파일 합치기·섹션 분할기·--wf-* 와이어프레임 킷·promote.md 의 작성 지시문은 범위 밖이다. 하나라도 새어 들어오면 리뷰 가능한 diff 가 재작성이 된다.

# 데크를 다크 전용으로 재설계하고 다이어그램을 읽히게 만든다

## Summary

`/scv:deck` 산출물이 쓸 수 없는 상태다. 다이어그램은 자연 크기의 절반으로 찌그러져
16px 글자가 7.7px 로 나오고, 색은 프롬프트에 박혀 있어 라이트·다크 양쪽에서 다
깨진다. 이 계획은 데크를 **다크 전용**으로 바꾸고, 대표님 `DesignSystem` 의 토큰과
크롬을 이식하고, 구운 SVG 에서 색을 벗겨내 CSS 가 칠할 수 있게 만든다.

## Goals / Non-Goals

- **Goals**
  - 다이어그램이 자연 크기로 나오고 글자가 읽힌다 (배율 0.483 → 1.000)
  - 다이어그램 색이 페이지 테마를 따른다 — 구운 SVG 에서 박힌 색을 벗겨서
  - 화면은 다크 전용. 라이트 토큰 세트와 테마 토글을 없앤다
  - 대표님 `DesignSystem` 의 무채색 토큰·타입 스케일·크롬 배치를 이식한다
  - 브랜드 장미색을 쓰되 글자용 밝은 값을 따로 둔다
  - 크롬 높이 268px → 110px
  - 인쇄는 종이만 라이트로 (화면에서 도달 불가능한 `@media print` 하나)
- **Non-Goals**
  - `ScreenSlide` 의 주석 칸 — 마크다운에 그 데이터가 없다
  - `Flow`·`TransitionList`·`SchemaTable` — 같은 이유
  - Inter 폰트 임베드 — 한글이 없어 한 문장 안에서 글꼴이 갈린다
  - React·Tailwind 도입
  - 슬라이드 모드, 세 파일 합치는 방식, 섹션 분할기 — 손대지 않는다

## Approach Overview

### 다이어그램 (가장 중요)

두 가지가 겹쳐 있다. **크기**와 **색**이다.

**크기** — `static-mermaid.mjs` 가 `width="100%"` + `max-width:1437px` 를 그대로 둔다.
840px 칼럼(패널 열리면 694px)에 들어가면서 0.483 배로 줄어든다. viewBox 실제 크기를
`width`/`height` 로 박고, `pre.mermaid` 를 `overflow-x:auto` 로 만들고, 본문 칼럼
바깥으로 내보낸다.

**색** — `promote.md` 가 모델에게 붙여넣게 한 `%%{init:...}%%` 가 렌더러를 이기고,
헤드리스 크롬이 그 색으로 SVG 를 굽는다. 해법은 구운 SVG 를 **다시 칠할 수 있게**
정규화하는 것:

1. 펜스에서 `%%{init:...}%%` 를 렌더 직전에 떼어낸다 (데크 사본만 — 디스크의 `.md`
   와 GitHub 렌더링은 그대로)
2. SVG 자체 `<style>` 의 `#mermaid-<타임스탬프>` → `.scv-mmd`, `!important` 제거.
   특이도가 (1,1,0) → (0,1,0) 이 되어 일반 규칙이 이긴다
3. 인라인 `style=` 에서 `fill`/`stroke`/`color`/`background` 제거. `classDef` 가 박는
   `style="fill:#FFE082 !important"` 는 이것 말고는 못 이긴다
4. id 를 `scv-mmd-1` 로 고정 — `url(#...)` 참조 일관성 + 재빌드 바이트 동일
5. 토큰으로 칠하는 `<style>` 블록을 페이지에 넣는다

빌드 때 크롬이 없으면 로더가 실려 나가는 대체 경로가 있다. 같은 정규화를
클라이언트 쪽에도 넣어 두 형태가 같은 DOM 으로 수렴하게 한다.

### 토큰

대표님 `DesignSystem/src/index.css` 의 `.dark` 블록을 oklch → sRGB 로 변환해 쓴다.
전부 무채색이다. SCV 의 파란 기 도는 회색(`#171922`·`#1d2029`·`#2c3040`·`#9096a8`)이
두 덱을 다른 시스템으로 보이게 하던 가장 큰 원인이다.

경계선은 **알파**로 둔다(`rgba(255,255,255,.10)`). 한 값이 배경 위에서도 카드 위에서도
올바르게 합성된다 — 대표님 쪽이 그렇게 한다.

**장미는 두 개다.** 원본 `#a50036` 은 칠하는 색으로 쓰고(흰 글자 7.58:1), 글자에는
같은 색상에서 밝기만 올린 `#fc7184` 를 쓴다(배경 위 7.39:1). 원본을 글자에 쓰면
2.50:1 이라 안 읽힌다 — 대표님 `Kicker` 가 지금 그렇게 하고 있다.

활성 알약은 **밝은 장미 바탕 + 검은 글자**다. 어두운 장미로 칠하면 배경과 2.50:1 이라
어느 게 켜졌는지 안 보인다.

### 크롬

`grid-template-rows:auto 1fr auto` 로 `100svh` 를 헤더/본문/푸터로 나눈다. 대표님
`SlideDeck.tsx:94` 의 `h-svh flex-col` 을 평범한 CSS 로 옮긴 것이다.

- 헤더: 제목 + 목차 한 줄(가로 스크롤) + 패널 토글
- 본문: 스크롤 영역 + 사이드 패널 (이미 있는 것 거의 그대로)
- 푸터: 진행 점 + `N/M` + 이전/다음

목차는 `nowrap` 이다. 대표님 쪽은 `flex-wrap` 과 `overflow-x-auto` 를 같이 걸어서
`flex-wrap` 이 이기는데, SCV 라벨 19 개를 먹이면 3 줄로 늘어난다. 여기서만 원본과
다르게 가고, 그 이유를 주석에 남긴다.

## Guardrails

- **디스크의 마크다운을 건드리지 말 것.** `%%{init}%%` 를 떼는 것은 데크가 읽어들인
  사본에서만이다. `.md` 파일과 GitHub 렌더링은 그대로 남는다.
- **정적 SVG 계약을 깨지 말 것.** `test-deck-static-mermaid.sh` 가 `embedded
  diagrams=1`, `data-scv-static-mermaid="true"`, 로더 부재를 단언한다. 전부 유지.
- **정규화는 열린 채로 실패할 것.** 헤드리스 크롬 DOM 을 정규식으로 다루므로 mermaid
  마크업이 바뀌면 깨진다. `try/catch` 로 감싸서 오늘 동작으로 떨어지게 하고, CI 단언을
  붙여 조용히 되돌아가는 것을 막는다.
- **`--muted` 를 글자색으로 쓰지 말 것.** shadcn 규약에서 `--muted` 는 **표면**이고
  글자는 `--muted-foreground` 다. 지금 SCV 는 반대로 쓰고 있어서 소비처 12 곳을
  먼저 이름부터 정리해야 한다. 이걸 건너뛰면 회색 글자가 회색 배경이 된다.
- **본문 4.5:1, 선·도형 경계 3:1 아래로 내려가지 말 것.** 색을 제안할 때마다 그
  색이 놓이는 표면 기준으로 측정한다.
- **한글을 깨지 말 것.** 폰트 스택이 한글과 라틴을 같은 문장에서 일관되게 덮어야
  한다.
- **재빌드 바이트 동일.** 타임스탬프 id 를 고정 id 로 바꾸는 이유가 이것이다.
- 슬라이드 모드·세 파일 합치기·섹션 분할기·`--wf-*` 와이어프레임 킷·promote.md 의
  작성 지시문은 **범위 밖**이다. 하나라도 새어 들어오면 리뷰 가능한 diff 가 재작성이
  된다.

  `SCV_DECK_CACHE_DIR` 로 따뜻한 캐시를 잡아두고 작업한다.

# Test Plan — 데크를 다크 전용으로 재설계하고 다이어그램을 읽히게 만든다

## Overview

이 계획은 **보이는 것**을 바꾼다. 그래서 "문자열이 파일에 있는가" 로는 검증이 안
된다. 지금 테스트가 정확히 그 방식이라 깨진 CSS 를 통과시켰다 — `font:600 12px/1
inherit` 은 문법 오류라 버튼이 전부 Arial 로 떨어졌는데 151 개 단언이 전부 초록이었다.

그래서 여기 시나리오는 **헤드리스 크롬에서 계산된 값**을 읽는다. 색은 대비를 재고,
크기는 픽셀을 잰다. 기준선(지금 값)을 같이 적어 두어 개선이 측정으로 보이게 한다.

## Test scenarios

### T1. 다이어그램이 자연 크기로 나온다 (가장 중요)

- **Setup**: mermaid 펜스가 있는 아카이브 데크를 다시 생성한다.
- **Run**: 헤드리스 크롬으로 열어 `svg.getBoundingClientRect().width` 와 viewBox 폭,
  그리고 `.nodeLabel` 의 실효 글자 크기를 읽는다.
- **Expected**: 렌더 폭 == viewBox 폭 (1437px), 배율 1.000, 노드 글자 실효 16.00px.
- **Pass criterion**: 배율 ≥ 0.99. **기준선: 694px / 0.483 / 7.73px.** 1152·1280·
  1440·1920 네 폭에서, 패널 열고 닫고 각각 확인한다.

### T2. 다이어그램 색이 페이지 테마를 따른다

- **Setup**: T1 과 같은 산출물.
- **Run**: 계산된 스타일로 화살표 `stroke`, 화살촉 `fill`, 노드 `rect` 의 `fill`·
  `stroke`, `.nodeLabel` 색, 클러스터 `rect`, 엣지 라벨 색을 읽는다.
- **Expected**: 전부 토큰 값. 화살표/표면 ≥ 4.5:1, 노드 테두리/표면 ≥ 3:1, 노드
  글자/노드 배경 ≥ 4.5:1.
- **Pass criterion**: 하나라도 미달이면 실패하고 그 요소 이름과 실측 대비를 출력한다.

### T3. `classDef` 노드도 테마를 따른다

- **Setup**: `classDef new fill:#FFE082,...,color:#000` 을 쓰는 다이어그램.
- **Run**: 그 노드의 `rect` `fill` 과 라벨 색을 읽는다.
- **Expected**: 토큰 값이지 `#FFE082`/`#000` 이 아니다.
- **Pass criterion**: 하드코드 값이 아니고, 라벨/배경 대비 ≥ 4.5:1. **이게 인라인
  스타일 제거가 실제로 먹혔는지 보는 유일한 시나리오다** — 이것만 CSS 로는 못 이긴다.

### T4. 옛 팔레트가 산출물에서 사라졌다

- **Setup**: 다시 생성한 아카이브 데크.
- **Run**: `#e7e9f0`·`#171922`·`#1e1e1e`·`#9096a8` 을 센다.
- **Expected**: 각각 0 회.
- **Pass criterion**: 합계 0. **기준선: 7·8·3·4 회.**

### T5. 저장된 마크다운은 안 바뀐다

- **Setup**: 데크 생성 전후로 `FEATURE_ARCHITECTURE.md` 의 해시를 잰다.
- **Run**: `sha256sum` 비교.
- **Expected**: 동일. 파일 안에 `%%{init:` 이 그대로 있다.
- **Pass criterion**: 해시 동일. `%%{init:` 이 남아 있어야 GitHub 렌더링이 유지되고,
  그게 이 정규화의 회귀 픽스처가 된다.

### T6. 재빌드해도 바이트가 같다

- **Setup**: 같은 입력으로 연속 두 번 생성.
- **Run**: `cmp` 로 두 산출물 비교.
- **Expected**: 동일.
- **Pass criterion**: 차이 없음. **기준선: 지금은 SVG id 가 빌드 타임스탬프라 매번
  다르다** — promote 마다 커밋되는 파일이므로 git diff 가 출렁인다.

### T7. 정규화가 열린 채로 실패한다

- **Setup**: 정규화가 처리 못 하는 SVG 를 흉내 낸다 (기대하는 구조를 깬 입력).
- **Run**: 데크를 생성한다.
- **Expected**: 빌드가 성공하고, 다이어그램은 정규화 전 모습으로 나오고, stderr 에
  한 줄이 남는다.
- **Pass criterion**: 종료 코드 0. **빌드를 죽이면 안 된다** — mermaid 마크업이
  바뀌었을 때 데크 생성 자체가 막히는 것이 최악이다.

### T8. 대체 경로도 같은 DOM 으로 수렴한다

- **Setup**: 헤드리스 크롬을 못 쓰게 만들어 로더가 실린 형태로 생성한다.
- **Run**: 브라우저에서 열고 T2 와 같은 계산 스타일 검사를 돌린다.
- **Expected**: 정적 형태와 같은 결과.
- **Pass criterion**: 두 형태의 계산 색이 일치. 안 그러면 사용자마다 다른 걸 본다.

### T9. 라이트 세트와 테마 토글이 사라졌다

- **Setup**: 다시 생성한 데크.
- **Run**: `html[data-theme="light"]` 셀렉터, 토글 버튼, `localStorage` 테마 스크립트를
  찾는다.
- **Expected**: 셋 다 0 회.
- **Pass criterion**: 없음. 그리고 `:root` 에 선언되지 않은 `var(--*)` 소비가 0 개
  — 라이트 세트를 지우면서 참조를 남기면 조용히 무색이 된다.

### T10. 모든 토큰이 대비 기준을 넘는다

- **Setup**: 새 `:root` 블록.
- **Run**: 글자로 쓰이는 모든 토큰을 그것이 놓이는 표면 기준으로 계산한다.
- **Expected**: 본문 ≥ 4.5:1, 큰 글자·선 ≥ 3:1.
- **Pass criterion**: 미달 0. **기준선: 지금 라이트 `--warn` 3.25:1, 라이트 `--good`
  4.14:1 — 둘 다 본문으로 쓰인다.**

### T11. 장미 두 개가 여섯 역할을 다 통과한다

- **Setup**: `--primary` = `#a50036`(칠하기), `--primary-text` = `#fc7184`(글자).
- **Run**: 여섯 조합을 잰다 — 배경 위 글자, 카드 위 글자, 칠한 판 위 흰 글자, 밝은
  판 위 검은 글자, 70% 불릿 점, 활성 알약.
- **Expected**: 글자 넷 ≥ 4.5:1, 점·알약 ≥ 3:1.
- **Pass criterion**: 6/6. **활성 알약은 밝은 장미 바탕 + 검은 글자여야 한다** —
  어두운 장미로 칠하면 2.50:1 이라 어느 게 켜졌는지 안 보인다.

### T12. 크롬이 얇아졌다

- **Setup**: 다시 생성한 데크.
- **Run**: 첫 내용 픽셀까지의 높이를 잰다.
- **Expected**: ≤ 120px (1440px 화면), ≤ 140px (1152px).
- **Pass criterion**: 두 폭 다 통과. **기준선: 268.4px(36%) / 342.8px(45%).**

### T13. 목차가 한 줄이다

- **Setup**: 섹션 19 개짜리 데크.
- **Run**: 목차 영역 높이와 `flex-wrap` 계산값을 읽는다.
- **Expected**: 한 줄, ≤ 44px, `flex-wrap: nowrap`.
- **Pass criterion**: 통과. **기준선: 154px(1440) / 191px(1152).** 대표님 덱을 그대로
  베끼면 안 되는 유일한 지점이다 — 거기선 `flex-wrap` 이 이겨서 3 줄이 된다.

### T14. 하단 조작부가 동작한다

- **Setup**: 다시 생성한 데크.
- **Run**: 진행 점, `N/M` 표시, 이전/다음 버튼을 확인하고 눌러본다.
- **Expected**: 점 개수 == 섹션 수, 활성 점이 넓다, 카운터가 맞다, 버튼이 페이지를
  넘기고 양 끝에서 비활성이다.
- **Pass criterion**: 전부. 버튼은 새 핸들러를 만들지 말고 기존 키보드 경로를 쓴다.

### T15. 목차가 활성 알약을 따라 스크롤한다

- **Setup**: 1페이지에서 시작.
- **Run**: `End` 를 눌러 마지막으로 간다.
- **Expected**: 활성 알약이 목차 안에 보인다.

# 데크를 다크 전용으로 재설계하고 다이어그램을 읽히게 만든다

## Summary

`/scv:deck` 산출물이 쓸 수 없는 상태다. 다이어그램은 자연 크기의 절반으로 찌그러져
16px 글자가 7.7px 로 나오고, 색은 프롬프트에 박혀 있어 라이트·다크 양쪽에서 다
깨진다. 이 계획은 데크를 **다크 전용**으로 바꾸고, 대표님 `DesignSystem` 의 토큰과
크롬을 이식하고, 구운 SVG 에서 색을 벗겨내 CSS 가 칠할 수 있게 만든다.

## Goals / Non-Goals

- **Goals**
  - 다이어그램이 자연 크기로 나오고 글자가 읽힌다 (배율 0.483 → 1.000)
  - 다이어그램 색이 페이지 테마를 따른다 — 구운 SVG 에서 박힌 색을 벗겨서
  - 화면은 다크 전용. 라이트 토큰 세트와 테마 토글을 없앤다
  - 대표님 `DesignSystem` 의 무채색 토큰·타입 스케일·크롬 배치를 이식한다
  - 브랜드 장미색을 쓰되 글자용 밝은 값을 따로 둔다
  - 크롬 높이 268px → 110px
  - 인쇄는 종이만 라이트로 (화면에서 도달 불가능한 `@media print` 하나)
- **Non-Goals**
  - `ScreenSlide` 의 주석 칸 — 마크다운에 그 데이터가 없다
  - `Flow`·`TransitionList`·`SchemaTable` — 같은 이유
  - Inter 폰트 임베드 — 한글이 없어 한 문장 안에서 글꼴이 갈린다
  - React·Tailwind 도입
  - 슬라이드 모드, 세 파일 합치는 방식, 섹션 분할기 — 손대지 않는다

## Approach Overview

### 다이어그램 (가장 중요)

두 가지가 겹쳐 있다. **크기**와 **색**이다.

**크기** — `static-mermaid.mjs` 가 `width="100%"` + `max-width:1437px` 를 그대로 둔다.
840px 칼럼(패널 열리면 694px)에 들어가면서 0.483 배로 줄어든다. viewBox 실제 크기를
`width`/`height` 로 박고, `pre.mermaid` 를 `overflow-x:auto` 로 만들고, 본문 칼럼
바깥으로 내보낸다.

**색** — `promote.md` 가 모델에게 붙여넣게 한 `%%{init:...}%%` 가 렌더러를 이기고,
헤드리스 크롬이 그 색으로 SVG 를 굽는다. 해법은 구운 SVG 를 **다시 칠할 수 있게**
정규화하는 것:

1. 펜스에서 `%%{init:...}%%` 를 렌더 직전에 떼어낸다 (데크 사본만 — 디스크의 `.md`
   와 GitHub 렌더링은 그대로)
2. SVG 자체 `<style>` 의 `#mermaid-<타임스탬프>` → `.scv-mmd`, `!important` 제거.
   특이도가 (1,1,0) → (0,1,0) 이 되어 일반 규칙이 이긴다
3. 인라인 `style=` 에서 `fill`/`stroke`/`color`/`background` 제거. `classDef` 가 박는
   `style="fill:#FFE082 !important"` 는 이것 말고는 못 이긴다
4. id 를 `scv-mmd-1` 로 고정 — `url(#...)` 참조 일관성 + 재빌드 바이트 동일
5. 토큰으로 칠하는 `<style>` 블록을 페이지에 넣는다

빌드 때 크롬이 없으면 로더가 실려 나가는 대체 경로가 있다. 같은 정규화를
클라이언트 쪽에도 넣어 두 형태가 같은 DOM 으로 수렴하게 한다.

### 토큰

대표님 `DesignSystem/src/index.css` 의 `.dark` 블록을 oklch → sRGB 로 변환해 쓴다.
전부 무채색이다. SCV 의 파란 기 도는 회색(`#171922`·`#1d2029`·`#2c3040`·`#9096a8`)이
두 덱을 다른 시스템으로 보이게 하던 가장 큰 원인이다.

경계선은 **알파**로 둔다(`rgba(255,255,255,.10)`). 한 값이 배경 위에서도 카드 위에서도
올바르게 합성된다 — 대표님 쪽이 그렇게 한다.

**장미는 두 개다.** 원본 `#a50036` 은 칠하는 색으로 쓰고(흰 글자 7.58:1), 글자에는
같은 색상에서 밝기만 올린 `#fc7184` 를 쓴다(배경 위 7.39:1). 원본을 글자에 쓰면
2.50:1 이라 안 읽힌다 — 대표님 `Kicker` 가 지금 그렇게 하고 있다.

활성 알약은 **밝은 장미 바탕 + 검은 글자**다. 어두운 장미로 칠하면 배경과 2.50:1 이라
어느 게 켜졌는지 안 보인다.

### 크롬

`grid-template-rows:auto 1fr auto` 로 `100svh` 를 헤더/본문/푸터로 나눈다. 대표님
`SlideDeck.tsx:94` 의 `h-svh flex-col` 을 평범한 CSS 로 옮긴 것이다.

- 헤더: 제목 + 목차 한 줄(가로 스크롤) + 패널 토글
- 본문: 스크롤 영역 + 사이드 패널 (이미 있는 것 거의 그대로)
- 푸터: 진행 점 + `N/M` + 이전/다음

목차는 `nowrap` 이다. 대표님 쪽은 `flex-wrap` 과 `overflow-x-auto` 를 같이 걸어서
`flex-wrap` 이 이기는데, SCV 라벨 19 개를 먹이면 3 줄로 늘어난다. 여기서만 원본과
다르게 가고, 그 이유를 주석에 남긴다.

## Guardrails

- **디스크의 마크다운을 건드리지 말 것.** `%%{init}%%` 를 떼는 것은 데크가 읽어들인
  사본에서만이다. `.md` 파일과 GitHub 렌더링은 그대로 남는다.
- **정적 SVG 계약을 깨지 말 것.** `test-deck-static-mermaid.sh` 가 `embedded
  diagrams=1`, `data-scv-static-mermaid="true"`, 로더 부재를 단언한다. 전부 유지.
- **정규화는 열린 채로 실패할 것.** 헤드리스 크롬 DOM 을 정규식으로 다루므로 mermaid
  마크업이 바뀌면 깨진다. `try/catch` 로 감싸서 오늘 동작으로 떨어지게 하고, CI 단언을
  붙여 조용히 되돌아가는 것을 막는다.
- **`--muted` 를 글자색으로 쓰지 말 것.** shadcn 규약에서 `--muted` 는 **표면**이고
  글자는 `--muted-foreground` 다. 지금 SCV 는 반대로 쓰고 있어서 소비처 12 곳을
  먼저 이름부터 정리해야 한다. 이걸 건너뛰면 회색 글자가 회색 배경이 된다.
- **본문 4.5:1, 선·도형 경계 3:1 아래로 내려가지 말 것.** 색을 제안할 때마다 그
  색이 놓이는 표면 기준으로 측정한다.
- **한글을 깨지 말 것.** 폰트 스택이 한글과 라틴을 같은 문장에서 일관되게 덮어야
  한다.
- **재빌드 바이트 동일.** 타임스탬프 id 를 고정 id 로 바꾸는 이유가 이것이다.
- 슬라이드 모드·세 파일 합치기·섹션 분할기·`--wf-*` 와이어프레임 킷·promote.md 의
  작성 지시문은 **범위 밖**이다. 하나라도 새어 들어오면 리뷰 가능한 diff 가 재작성이
  된다.

## Exit criteria

- TESTS.md 시나리오 전부 통과.
- 실제 아카이브 데크를 다시 생성해서 **눈으로** 확인 — 다이어그램이 읽히고, 크롬이
  얇고, 색이 대표님 덱과 같은 계열이다.
- 다이어그램 배율 1.000, 노드 글자 실효 16px (기준선 0.483 / 7.73px).
- 산출물에 `#e7e9f0`·`#171922`·`#1e1e1e`·`#9096a8` 이 0 회 (지금 각각 7·8·3·4 회).

## Risks / Open Questions

- **정규식이 mermaid 11 마크업에 묶인다.** `classDef` 가 인라인 스타일을 내는 방식이
  바뀌면 색이 조용히 다시 얼어붙는다. `try/catch` + CI 단언으로 막지만 근본적으로

- **손으로 칠한 노드 색이 사라진다.** 인라인 색 제거는 `style A fill:#f9f` 도 지운다.

- **테스트가 설계상 깨진다.** 두 파일에서 문자열 고정 단언 약 35 개가 CSS 를 그대로
  박아두고 있다. 정직한 해법은 문자열 고정을 대비 측정·기하 측정으로 바꾸는 것인데,
  그건 분리 가능한 별도 작업이다.
- **`100vw` 로 칼럼 바깥으로 내보내는 게 취약하다.** 사이드 패널이 있는
  `display:flex; overflow:hidden` 안에서 `100vw` 는 패널 폭까지 센다. 1152/1280/1440/
  1920 에서 패널 열고 닫고 확인해야 한다.
- **`render.mjs` 를 고치면 DeckUI 런타임 캐시가 무효화된다.** 매 변경 후 첫 빌드가

  `SCV_DECK_CACHE_DIR` 로 따뜻한 캐시를 잡아두고 작업한다.

# Test Plan — 데크를 다크 전용으로 재설계하고 다이어그램을 읽히게 만든다

## Overview

이 계획은 **보이는 것**을 바꾼다. 그래서 "문자열이 파일에 있는가" 로는 검증이 안
된다. 지금 테스트가 정확히 그 방식이라 깨진 CSS 를 통과시켰다 — `font:600 12px/1
inherit` 은 문법 오류라 버튼이 전부 Arial 로 떨어졌는데 151 개 단언이 전부 초록이었다.

그래서 여기 시나리오는 **헤드리스 크롬에서 계산된 값**을 읽는다. 색은 대비를 재고,
크기는 픽셀을 잰다. 기준선(지금 값)을 같이 적어 두어 개선이 측정으로 보이게 한다.

## Test scenarios

### T1. 다이어그램이 자연 크기로 나온다 (가장 중요)

- **Setup**: mermaid 펜스가 있는 아카이브 데크를 다시 생성한다.
- **Run**: 헤드리스 크롬으로 열어 `svg.getBoundingClientRect().width` 와 viewBox 폭,
  그리고 `.nodeLabel` 의 실효 글자 크기를 읽는다.
- **Expected**: 렌더 폭 == viewBox 폭 (1437px), 배율 1.000, 노드 글자 실효 16.00px.
- **Pass criterion**: 배율 ≥ 0.99. **기준선: 694px / 0.483 / 7.73px.** 1152·1280·
  1440·1920 네 폭에서, 패널 열고 닫고 각각 확인한다.

### T2. 다이어그램 색이 페이지 테마를 따른다

- **Setup**: T1 과 같은 산출물.
- **Run**: 계산된 스타일로 화살표 `stroke`, 화살촉 `fill`, 노드 `rect` 의 `fill`·
  `stroke`, `.nodeLabel` 색, 클러스터 `rect`, 엣지 라벨 색을 읽는다.
- **Expected**: 전부 토큰 값. 화살표/표면 ≥ 4.5:1, 노드 테두리/표면 ≥ 3:1, 노드
  글자/노드 배경 ≥ 4.5:1.
- **Pass criterion**: 하나라도 미달이면 실패하고 그 요소 이름과 실측 대비를 출력한다.

### T3. `classDef` 노드도 테마를 따른다

- **Setup**: `classDef new fill:#FFE082,...,color:#000` 을 쓰는 다이어그램.
- **Run**: 그 노드의 `rect` `fill` 과 라벨 색을 읽는다.
- **Expected**: 토큰 값이지 `#FFE082`/`#000` 이 아니다.
- **Pass criterion**: 하드코드 값이 아니고, 라벨/배경 대비 ≥ 4.5:1. **이게 인라인
  스타일 제거가 실제로 먹혔는지 보는 유일한 시나리오다** — 이것만 CSS 로는 못 이긴다.

### T4. 옛 팔레트가 산출물에서 사라졌다

- **Setup**: 다시 생성한 아카이브 데크.
- **Run**: `#e7e9f0`·`#171922`·`#1e1e1e`·`#9096a8` 을 센다.
- **Expected**: 각각 0 회.
- **Pass criterion**: 합계 0. **기준선: 7·8·3·4 회.**

### T5. 저장된 마크다운은 안 바뀐다

- **Setup**: 데크 생성 전후로 `FEATURE_ARCHITECTURE.md` 의 해시를 잰다.
- **Run**: `sha256sum` 비교.
- **Expected**: 동일. 파일 안에 `%%{init:` 이 그대로 있다.
- **Pass criterion**: 해시 동일. `%%{init:` 이 남아 있어야 GitHub 렌더링이 유지되고,
  그게 이 정규화의 회귀 픽스처가 된다.

### T6. 재빌드해도 바이트가 같다

- **Setup**: 같은 입력으로 연속 두 번 생성.
- **Run**: `cmp` 로 두 산출물 비교.
- **Expected**: 동일.
- **Pass criterion**: 차이 없음. **기준선: 지금은 SVG id 가 빌드 타임스탬프라 매번
  다르다** — promote 마다 커밋되는 파일이므로 git diff 가 출렁인다.

### T7. 정규화가 열린 채로 실패한다

- **Setup**: 정규화가 처리 못 하는 SVG 를 흉내 낸다 (기대하는 구조를 깬 입력).
- **Run**: 데크를 생성한다.
- **Expected**: 빌드가 성공하고, 다이어그램은 정규화 전 모습으로 나오고, stderr 에
  한 줄이 남는다.
- **Pass criterion**: 종료 코드 0. **빌드를 죽이면 안 된다** — mermaid 마크업이
  바뀌었을 때 데크 생성 자체가 막히는 것이 최악이다.

### T8. 대체 경로도 같은 DOM 으로 수렴한다
