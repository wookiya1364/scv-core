# 끝내기 전 결과 견본 확인 — 대충 말해도 원하는 결과로

## Summary

대충 한 요청에서도 사람이 원하는 결과가 나오도록, 결과물이 바뀌는 일이면 끝내기 전에 **실제 결과 견본을 한 번 보여 주고 확인받는** 규칙과, 고칠 때 **같은 계열 결함까지 찾는** 규칙을 SCV 에 넣는다.
2026-10-05 실측(대화형, 숨은 의도를 확인하는 숨은 테스트로 판정)에서 이 방식은 지금 SCV 보다 매번 더 맞혔다 — 과제 6개 × 3번에서 모두 통과 12/18 → 18/18(사용자 역할을 더 정확하게 고친 판). 지금 SCV 의 매 턴 다시 쓰기는 정확도를 올리지 못했다(다시 쓰기 끔 8/8 · 켬 6/8).
대가는 질문 수다(지금 SCV 의 약 2.3배). 이 계획은 정확도를 지키면서 질문을 지금 SCV 의 1.5배 이하로 맞추는 것을 목표로 둔다.
2026-10-06 다른 모델 실측에서 Sonnet 5 · Haiku 4.5 는 지시만으로는 견본 확인을 자주 건너뛰었다(결과물이 바뀌는 과제 12번 중 3번 · 8번, Opus 0번 — 견본을 보여 준 실행은 Opus 12/12 · Sonnet 9/9 통과). 그래서 **견본 확인 없이 끝내면 한 번 막는 검사**를 함께 넣고, 효과는 세 모델로 잰다(2026-10-06 사용자 결정).

## Goals / Non-Goals

- **Goals**
  1. **끝 확인**: 사용자가 받게 될 결과물(파일 · 출력 · 화면)이 바뀌는 일이면, 끝났다고 보고하기 전에 실제 결과의 견본을 한 번 보여 주고 확인받는다. 선택 창 보기는 '이대로 좋음'(추천) 하나와 직접 입력이고, 다른 점은 직접 입력으로 한 번에 받아 고친다(글 칸이 없는 '다른 점 적기' 같은 보기는 만들지 않는다 — 실측에서 빈 답이 넘어간 함정). 확인은 두 번까지, 그래도 남는 것은 가정을 밝히고 마무리한다.
  2. **건너뛰기**: 결과물이 바뀌지 않는 일(내부 결함 수정 · 구조 정리)은 견본 확인을 하지 않고, 답에 '결과물 변화 없음' 한 줄을 적는다(목표 9의 검사가 이 줄로 통과시킨다).
  3. **바깥 조건은 미리**: 입력 파일 형식 · 바꾸면 안 되는 것 · 되돌리기 어려운 일처럼 견본으로 드러나지 않는 것은 일을 시작하기 전에 한 번에 묶어 묻는다(실측에서 견본만으로는 '빠진 입력 형식'을 못 잡음).
  4. **같은 계열 결함 찾기**: 결함을 고칠 때 같은 파일 · 같은 흐름의 같은 계열 결함(테스트에 안 걸린 것 포함)을 찾아, 요청 범위 안이면 묻지 말고 함께 고친 뒤 테스트로 확인하고 고친 것을 보고에 적는다.
  5. **긴 작업은 맨 끝에 한 번**: 계획 구현처럼 오래 도는 일은 중간에 멈추지 않고 맨 끝에 한 번 확인한다.
  6. **기본 켬 · 설정으로 끔**: 설정 키 하나(예: `SCV_SAMPLE_CONFIRM`, 기본 on)로 끈다. 끄면 지금 SCV 와 같은 동작.
  7. **두 래퍼**: 규칙 본문은 코어에 한 번. 선택 창이 있는 호스트는 선택 창으로, 없는 호스트는 글 질문 한 번으로 확인받는다(코어 릴리스 뒤 두 래퍼 동기화).
  8. **측정 장치를 저장소로**: 2026-10-05 실측 장치(과제 6개 · 숨은 테스트 · 사용자 역할 · 집계)를 저장소 도구로 옮겨 이 계획의 검사로 쓴다. 실제 Claude 를 돌리므로 CI 가 아니라 설치본 확인 단계에서 돈다. 측정은 세 모델(Opus 5.5 · Sonnet 5 · Haiku 4.5)로 한다.
  9. **건너뛰면 막는 검사**: 파일을 바꾼 사람 턴이 끝날 때, 마지막 편집(SCV 기록 편집은 세지 않음) 뒤에 견본 확인이 없고 답에 '결과물 변화 없음' 한 줄도 없으면 한 번 막고 이유를 알린다. 기존 종료 훅의 '검사마다 한 턴에 한 번'(contracts/choices.md 7항)을 따른다. 자동 알림 턴 · 설정 off 에서는 막지 않는다. 이번 턴에 견본 확인을 이미 두 번 했거나 확인 선택 창을 취소했으면 막지 않는다(목표 1의 '두 번까지' · 취소 예외와 맞춤).
- **Non-Goals**
  - 매 턴 다시 쓰기 · 가드 · 선택 창 규칙을 바꾸거나 가볍게 하는 일(별도 계획 — 하루 실사용 분석 뒤).
  - 모델마다 다른 안내 문구 — 같은 문구와 검사로 먼저 재고, 모델별 차이가 남으면 별도 계획(2026-10-06 사용자 결정).
  - 모델 · 생각 깊이 바꾸기.
  - '미리 묻지 않기'로 질문 줄이기 — 실측에서 정확도를 떨어뜨렸다(18/18 → 15/18). 이번엔 넣지 않는다.

## Approach Overview

규칙 본문은 코어 계약 한 곳에 둔다(같은 요구는 한 곳에만 — SCV Top-level rules). 매 턴 훅이 켜짐일 때 짧은 안내(세 줄 안팎)를 싣고, 자세한 본문은 계약을 가리킨다.
호스트 프로필의 선택 창 이름(있으면)에 따라 '선택 창으로 확인' 또는 '글 질문 한 번으로 확인' 문구를 고른다 — 문구를 만드는 것은 순수 함수.
긴 작업(work 액션)은 그 액션 규약의 끝 단계(보고 전)에 '견본 확인 한 번'을 넣는다.
설정 키가 off 면 매 턴 블록에 아무것도 더하지 않는다 — 지금 SCV 와 같은 출력(바이트 단위).
종료 훅에 네 번째 검사 '견본 확인'을 더한다 — 기존 등록 · 원칙 · 선택지 검사와 같은 '한 턴에 한 번' 장치(lib/stop-gates.sh)를 쓴다. 이번 턴 대화 기록에서 마지막 편집(SCV 기록 제외)의 위치와 그 뒤의 견본 확인(선택 창 — 선택 창이 없는 호스트는 답 끝의 글 질문)을 찾고, 답에 '결과물 변화 없음' 줄이 있는지 본다. 판정은 순수 함수, 기록 읽기와 막기는 훅이 한다. 자동 알림 턴 판별은 기존 종료 훅의 판별을 그대로 쓴다.
측정 장치는 과제 저장소를 만드는 스크립트, 숨은 테스트, 운전 스크립트(tmux 대화형 세션 + 사용자 역할), 판정 · 집계 스크립트로 이루어진다. 두 방식(지금 SCV · 새 SCV)을 같은 날 나란히, 세 모델(시험 모델 지정 — 2026-10-05 장치에 더한 것) 각각 돌린다. 릴리스 전에는 브랜치의 플러그인 사본을 그 세션에만 실어 잴 수 있게 한다(2026-10-05 원인 확인에서 쓴 방법).

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readSampleSwitch,    // (설정 값 원문)           → on | off
  pickConfirmChannel,  // (호스트의 선택 창 이름)   → choice | text
  buildSampleRule,     // (on|off, choice|text)    → 매 턴 블록에 덧붙일 문구(off 면 빈 값)
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | readSampleSwitch | 설정 원문 → on/off(없거나 다른 값은 on) | 순수 |
| 2 | pickConfirmChannel | 선택 창 이름(빈 값 가능) → choice/text | 순수 |
| 3 | buildSampleRule | on/off · choice/text → 문구 | 순수 |
| 4 | 매 턴 훅 출력 | 문구 → 표준 출력 | 부수효과 (출구) |

종료 훅의 견본 확인 검사:

```
flow(
  lastEditIndex,     // (이번 턴 기록 항목들)                          → 마지막 편집 위치(SCV 기록 편집 제외, 없으면 없음)
  countConfirms,     // (항목들, 위치, choice|text)                     → 그 뒤 견본 확인 수 · 이번 턴 전체 확인 수 · 취소 여부
  judgeSampleGate,   // (on|off, 사람 턴인가, 위치, 확인 수, 선언 줄 유무) → pass | block(이유)
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 5 | lastEditIndex | 이번 턴 기록 → 마지막 편집 위치 | 순수 |
| 6 | countConfirms | 기록 · 위치 · 확인 통로 → 확인 수 · 취소 여부 | 순수 |
| 7 | judgeSampleGate | 켬/끔 · 사람 턴 · 위치 · 확인 수 · 선언 줄 → pass/block | 순수 |
| 8 | 종료 훅 멈춤 | block 이유 → 멈춤 메시지(한 턴에 한 번) | 부수효과 (출구) |

- 부수효과 위치: 설정 파일 · 대화 기록 읽기(입구)와 매 턴 훅 출력 · 종료 훅 멈춤(출구)만.
- 재사용: 설정 읽기 라이브러리, 호스트 프로필(선택 창 이름), 매 턴 블록 조립.
- 측정 장치의 판정(숨은 테스트 결과 · 질문 수 집계)도 기록 파일을 받아 숫자를 돌려주는 순수 단계로 둔다.

## 예외처리 (Edge cases)

- **결과물이 큼**: 견본은 첫 몇 줄(또는 바뀐 부분)만 보이고, 전체 위치를 함께 알린다.
- **결과물이 글이 아님**(이미지 · 이진 파일): 종류 · 크기 · 여는 법을 견본으로 보인다.
- **선택 창을 취소함**: 확인 없이 마무리하고, 보고의 '확인하지 못한 것'에 적는다. 검사도 취소를 확인한 것으로 보고 막지 않는다.
- **견본에 비밀값 · 개인 정보가 들어감**: 견본에서 가린 뒤 보인다(기존 가림 필터를 쓴다).
- **사람이 없는 실행**(무인 · 자동 알림으로 이어진 턴): 견본 확인을 하지 않고, 가정을 보고에 밝힌다 — 정확한 판별은 구현 중 정하고 사용자에게 묻는다. 검사도 자동 알림 턴에서는 막지 않는다.
- **견본 확인 뒤 다시 고침**: 마지막 편집 뒤 확인이 다시 필요하지만, 이번 턴에 이미 두 번 확인했으면 막지 않는다(두 번까지 규칙).
- **'결과물 변화 없음'을 잘못 적음**: 검사는 선언을 믿으므로 잡지 못한다 — 측정에서 결과물 과제의 선언 수를 센다.
- **SCV 기록만 바뀐 턴**: 편집으로 세지 않아 막지 않는다.
- **설정 값이 엉뚱함**: on 으로 본다(다른 SCV 스위치와 같은 규칙).

## Risks / Open Questions

- 사용자 역할(시뮬레이션)은 사람보다 일관되고, 때로 묻지 않은 것까지 말한다. 실제 사람에게서도 같은 이득이 나는지는 하루 실사용 분석에서 확인해야 한다.

- 지시만으로 이득이 났지만, 모델 버전이 바뀌면 달라질 수 있다 — 측정 장치를 남겨 다시 잴 수 있게 한다.
- 모델별 차이(2026-10-06 실측, 확인): Sonnet 5 · Haiku 4.5 는 지시를 받고도 결과물이 바뀌는 과제에서 견본 확인을 건너뛴다(12번 중 3번 · 8번, Opus 0번). 견본을 보여 준 실행은 Opus 12/12 · Sonnet 9/9 · Haiku 2/4 통과. → 검사로 막기로 함(2026-10-06 사용자 결정, 목표 9).
- 검사는 '결과물 변화 없음' 선언을 믿는다 — 모델이 결과물 과제에 잘못 선언하면 잡지 못한다(측정에서 셈).

- 검사가 막을 때마다 한 턴이 더 돈다 — 막은 횟수를 측정에서 센다.
- 결과물이 바뀌지 않는 구조 정리 과제에서도 세 모델 모두 견본 확인을 했다(Opus 3 · Sonnet 3 · Haiku 2번, 지시만, 확인) — 목표 2와 어긋나 질문을 늘린다. 측정(T10)에서 구조 정리 과제까지 센다.

# Test Plan — 끝내기 전 결과 견본 확인 — 대충 말해도 원하는 결과로

## Overview

끝 확인 규칙(결과물이 바뀌는 일이면 끝내기 전 실제 결과 견본을 한 번 보여 주고 확인받기)과 같은 계열 결함 찾기가 SCV 에 들어가, 대충 한 요청에서도 숨은 의도에 맞는 결과가 나오는지 확인한다.
자동 검사(문구 · 설정 · 순수 함수 · 규약)는 맥 · 리눅스 CI 에서, 실제 효과는 저장소로 옮긴 측정 장치로 지금 SCV 와 같은 날 나란히 잰다(실제 Claude 를 돌리므로 설치본 확인 단계).
기준선(2026-10-05): 지금 SCV 모두 통과 12/18 · 질문 22개, 다듬은 판 18/18 · 질문 51개(사용자 역할 Opus + 상황 문장 대조).
종료 훅의 견본 확인 검사(건너뛰면 한 번 막음)는 단위 검사로 확인하고, 측정은 세 모델(Opus 5.5 · Sonnet 5 · Haiku 4.5)로 한다. 모델별 기준선(지시만 넣은 판, 2026-10-06): 모두 통과 Sonnet 5 13/18 → 15/18 · Haiku 4.5 5/18 → 8/18, 결과물이 바뀌는 과제의 견본 확인 건너뜀 Sonnet 3/12 · Haiku 8/12(Opus 0/12).

## Test scenarios

### T1. 켬 — 매 턴 블록에 끝 확인 안내가 실린다

- **Setup**: 하이드레이트한 임시 저장소, 설정 키 없음(기본 on), 선택 창이 있는 호스트 프로필(Claude Code).
- **Run**: 매 턴 훅에 사람 메시지 하나를 넣는다.
- **Expected**: 매 턴 블록에 끝 확인 안내(결과물이 바뀌는 일이면 끝내기 전 견본 한 번 · 선택 창 · 다른 점은 직접 입력 · 두 번까지 · 결과물 없는 일은 건너뜀 · 바깥 조건은 미리 · 같은 계열 결함)가 실린다. 안내는 세 줄 안팎이고 자세한 본문은 계약을 가리킨다.
- **Pass criterion**: 출력에 안내 문구가 있고, 계약 경로가 있다.

### T2. 끔 — 설정 off 면 지금 SCV 와 같은 출력

- **Setup**: T1 과 같되 설정 키를 off.
- **Run**: 같은 메시지로 매 턴 훅을, 편집이 있는 같은 턴 기록으로 종료 훅을 돌리고, 이 기능이 없는 코어(직전 릴리스)의 출력과 비교한다.
- **Expected**: 매 턴 훅 · 종료 훅 출력이 각각 바이트 단위로 같다.
- **Pass criterion**: diff 없음.

### T3. 선택 창이 없는 호스트 — 글 질문 한 번

- **Setup**: 선택 창 이름이 비어 있는 호스트 프로필(코덱스 모양).
- **Run**: 매 턴 훅을 돌린다.
- **Expected**: 안내가 '선택 창' 대신 '글 질문 한 번으로 확인'을 말한다.
- **Pass criterion**: 선택 창 문구 없음, 글 질문 문구 있음.

### T4. 순수 함수 단위

- **Setup**: 코어 라이브러리를 불러온다.
- **Run**: 설정 해석(없음 · on · off · OFF · 엉뚱한 값), 확인 통로 고르기(빈 값 · 선택 창 이름), 문구 만들기(켬/끔 × 선택 창/글), 검사 판정(켬/끔 · 사람 턴 · 마지막 편집 위치 · 그 뒤 확인 수 · 이번 턴 확인 수 · 취소 · 선언 줄 조합)을 표로 확인한다.
- **Expected**: 없거나 엉뚱한 값은 on, off(대소문자 무관)만 off. 끔이면 문구는 빈 값. 검사 판정은 T16 · T17 의 경우와 같은 결과.
- **Pass criterion**: 표의 모든 칸 일치, 순수성 검사기 통과(bash 5 · 3.2).

### T5. 규칙 본문은 한 곳에만

- **Run**: 규칙 일치 검사(같은 요구는 한 곳에만)를 돌린다.
- **Expected**: 끝 확인 규칙의 본문이 코어 계약 한 곳에만 있고, 다른 문서 · 훅은 가리키기만 한다.
- **Pass criterion**: 검사 통과, 본문 중복 0.

# 끝내기 전 결과 견본 확인 — 대충 말해도 원하는 결과로

## Summary

대충 한 요청에서도 사람이 원하는 결과가 나오도록, 결과물이 바뀌는 일이면 끝내기 전에 **실제 결과 견본을 한 번 보여 주고 확인받는** 규칙과, 고칠 때 **같은 계열 결함까지 찾는** 규칙을 SCV 에 넣는다.
2026-10-05 실측(대화형, 숨은 의도를 확인하는 숨은 테스트로 판정)에서 이 방식은 지금 SCV 보다 매번 더 맞혔다 — 과제 6개 × 3번에서 모두 통과 12/18 → 18/18(사용자 역할을 더 정확하게 고친 판). 지금 SCV 의 매 턴 다시 쓰기는 정확도를 올리지 못했다(다시 쓰기 끔 8/8 · 켬 6/8).
대가는 질문 수다(지금 SCV 의 약 2.3배). 이 계획은 정확도를 지키면서 질문을 지금 SCV 의 1.5배 이하로 맞추는 것을 목표로 둔다.
2026-10-06 다른 모델 실측에서 Sonnet 5 · Haiku 4.5 는 지시만으로는 견본 확인을 자주 건너뛰었다(결과물이 바뀌는 과제 12번 중 3번 · 8번, Opus 0번 — 견본을 보여 준 실행은 Opus 12/12 · Sonnet 9/9 통과). 그래서 **견본 확인 없이 끝내면 한 번 막는 검사**를 함께 넣고, 효과는 세 모델로 잰다(2026-10-06 사용자 결정).

## Goals / Non-Goals

- **Goals**
  1. **끝 확인**: 사용자가 받게 될 결과물(파일 · 출력 · 화면)이 바뀌는 일이면, 끝났다고 보고하기 전에 실제 결과의 견본을 한 번 보여 주고 확인받는다. 선택 창 보기는 '이대로 좋음'(추천) 하나와 직접 입력이고, 다른 점은 직접 입력으로 한 번에 받아 고친다(글 칸이 없는 '다른 점 적기' 같은 보기는 만들지 않는다 — 실측에서 빈 답이 넘어간 함정). 확인은 두 번까지, 그래도 남는 것은 가정을 밝히고 마무리한다.
  2. **건너뛰기**: 결과물이 바뀌지 않는 일(내부 결함 수정 · 구조 정리)은 견본 확인을 하지 않고, 답에 '결과물 변화 없음' 한 줄을 적는다(목표 9의 검사가 이 줄로 통과시킨다).
  3. **바깥 조건은 미리**: 입력 파일 형식 · 바꾸면 안 되는 것 · 되돌리기 어려운 일처럼 견본으로 드러나지 않는 것은 일을 시작하기 전에 한 번에 묶어 묻는다(실측에서 견본만으로는 '빠진 입력 형식'을 못 잡음).
  4. **같은 계열 결함 찾기**: 결함을 고칠 때 같은 파일 · 같은 흐름의 같은 계열 결함(테스트에 안 걸린 것 포함)을 찾아, 요청 범위 안이면 묻지 말고 함께 고친 뒤 테스트로 확인하고 고친 것을 보고에 적는다.
  5. **긴 작업은 맨 끝에 한 번**: 계획 구현처럼 오래 도는 일은 중간에 멈추지 않고 맨 끝에 한 번 확인한다.
  6. **기본 켬 · 설정으로 끔**: 설정 키 하나(예: `SCV_SAMPLE_CONFIRM`, 기본 on)로 끈다. 끄면 지금 SCV 와 같은 동작.
  7. **두 래퍼**: 규칙 본문은 코어에 한 번. 선택 창이 있는 호스트는 선택 창으로, 없는 호스트는 글 질문 한 번으로 확인받는다(코어 릴리스 뒤 두 래퍼 동기화).
  8. **측정 장치를 저장소로**: 2026-10-05 실측 장치(과제 6개 · 숨은 테스트 · 사용자 역할 · 집계)를 저장소 도구로 옮겨 이 계획의 검사로 쓴다. 실제 Claude 를 돌리므로 CI 가 아니라 설치본 확인 단계에서 돈다. 측정은 세 모델(Opus 5.5 · Sonnet 5 · Haiku 4.5)로 한다.
  9. **건너뛰면 막는 검사**: 파일을 바꾼 사람 턴이 끝날 때, 마지막 편집(SCV 기록 편집은 세지 않음) 뒤에 견본 확인이 없고 답에 '결과물 변화 없음' 한 줄도 없으면 한 번 막고 이유를 알린다. 기존 종료 훅의 '검사마다 한 턴에 한 번'(contracts/choices.md 7항)을 따른다. 자동 알림 턴 · 설정 off 에서는 막지 않는다. 이번 턴에 견본 확인을 이미 두 번 했거나 확인 선택 창을 취소했으면 막지 않는다(목표 1의 '두 번까지' · 취소 예외와 맞춤).
- **Non-Goals**
  - 매 턴 다시 쓰기 · 가드 · 선택 창 규칙을 바꾸거나 가볍게 하는 일(별도 계획 — 하루 실사용 분석 뒤).
  - 모델마다 다른 안내 문구 — 같은 문구와 검사로 먼저 재고, 모델별 차이가 남으면 별도 계획(2026-10-06 사용자 결정).
  - 모델 · 생각 깊이 바꾸기.
  - '미리 묻지 않기'로 질문 줄이기 — 실측에서 정확도를 떨어뜨렸다(18/18 → 15/18). 이번엔 넣지 않는다.

## Approach Overview

규칙 본문은 코어 계약 한 곳에 둔다(같은 요구는 한 곳에만 — SCV Top-level rules). 매 턴 훅이 켜짐일 때 짧은 안내(세 줄 안팎)를 싣고, 자세한 본문은 계약을 가리킨다.
호스트 프로필의 선택 창 이름(있으면)에 따라 '선택 창으로 확인' 또는 '글 질문 한 번으로 확인' 문구를 고른다 — 문구를 만드는 것은 순수 함수.
긴 작업(work 액션)은 그 액션 규약의 끝 단계(보고 전)에 '견본 확인 한 번'을 넣는다.
설정 키가 off 면 매 턴 블록에 아무것도 더하지 않는다 — 지금 SCV 와 같은 출력(바이트 단위).
종료 훅에 네 번째 검사 '견본 확인'을 더한다 — 기존 등록 · 원칙 · 선택지 검사와 같은 '한 턴에 한 번' 장치(lib/stop-gates.sh)를 쓴다. 이번 턴 대화 기록에서 마지막 편집(SCV 기록 제외)의 위치와 그 뒤의 견본 확인(선택 창 — 선택 창이 없는 호스트는 답 끝의 글 질문)을 찾고, 답에 '결과물 변화 없음' 줄이 있는지 본다. 판정은 순수 함수, 기록 읽기와 막기는 훅이 한다. 자동 알림 턴 판별은 기존 종료 훅의 판별을 그대로 쓴다.
측정 장치는 과제 저장소를 만드는 스크립트, 숨은 테스트, 운전 스크립트(tmux 대화형 세션 + 사용자 역할), 판정 · 집계 스크립트로 이루어진다. 두 방식(지금 SCV · 새 SCV)을 같은 날 나란히, 세 모델(시험 모델 지정 — 2026-10-05 장치에 더한 것) 각각 돌린다. 릴리스 전에는 브랜치의 플러그인 사본을 그 세션에만 실어 잴 수 있게 한다(2026-10-05 원인 확인에서 쓴 방법).

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readSampleSwitch,    // (설정 값 원문)           → on | off
  pickConfirmChannel,  // (호스트의 선택 창 이름)   → choice | text
  buildSampleRule,     // (on|off, choice|text)    → 매 턴 블록에 덧붙일 문구(off 면 빈 값)
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | readSampleSwitch | 설정 원문 → on/off(없거나 다른 값은 on) | 순수 |
| 2 | pickConfirmChannel | 선택 창 이름(빈 값 가능) → choice/text | 순수 |
| 3 | buildSampleRule | on/off · choice/text → 문구 | 순수 |
| 4 | 매 턴 훅 출력 | 문구 → 표준 출력 | 부수효과 (출구) |

종료 훅의 견본 확인 검사:

```
flow(
  lastEditIndex,     // (이번 턴 기록 항목들)                          → 마지막 편집 위치(SCV 기록 편집 제외, 없으면 없음)
  countConfirms,     // (항목들, 위치, choice|text)                     → 그 뒤 견본 확인 수 · 이번 턴 전체 확인 수 · 취소 여부
  judgeSampleGate,   // (on|off, 사람 턴인가, 위치, 확인 수, 선언 줄 유무) → pass | block(이유)
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 5 | lastEditIndex | 이번 턴 기록 → 마지막 편집 위치 | 순수 |
| 6 | countConfirms | 기록 · 위치 · 확인 통로 → 확인 수 · 취소 여부 | 순수 |
| 7 | judgeSampleGate | 켬/끔 · 사람 턴 · 위치 · 확인 수 · 선언 줄 → pass/block | 순수 |
| 8 | 종료 훅 멈춤 | block 이유 → 멈춤 메시지(한 턴에 한 번) | 부수효과 (출구) |

- 부수효과 위치: 설정 파일 · 대화 기록 읽기(입구)와 매 턴 훅 출력 · 종료 훅 멈춤(출구)만.
- 재사용: 설정 읽기 라이브러리, 호스트 프로필(선택 창 이름), 매 턴 블록 조립.
- 측정 장치의 판정(숨은 테스트 결과 · 질문 수 집계)도 기록 파일을 받아 숫자를 돌려주는 순수 단계로 둔다.

## Guardrails

- frontmatter `invariants:` 넷을 지킨다 — 매 턴 등록 · 인용 · 맨 위 한 줄, 선택 창 규칙과 답 뒤 재등록, 가드, 모델 · 생각 깊이 불변.
- 설정이 off 면 매 턴 훅과 종료 훅의 출력이 지금 SCV 와 바이트 단위로 같아야 한다.
- 견본 확인 검사는 기존 종료 훅의 '검사마다 한 턴에 한 번'을 따른다 — 같은 턴에 두 번 막지 않는다. 자동 알림 턴에서는 막지 않는다(사람이 답할 수 없다).
- 확인 보기를 글 칸 없는 '다른 점 적기' 식으로 만들게 하는 문구를 쓰지 않는다 — 다른 점은 직접 입력으로.
- 맥(bash 3.2 · BSD 도구)과 리눅스(GNU) 모두에서 같은 결과. 순수 함수 검사(순수성 검사기)를 통과한다.
- 측정 장치는 실제 Claude 세션을 돌린다 — CI 에 넣지 않는다. 비용 이야기 대신 돌리는 횟수와 시간으로 규모를 정한다.
- 공개 저장소다 — 측정 기록에 다른 프로젝트 내용 · 메일 주소 · 비밀값을 넣지 않는다.

## 예외처리 (Edge cases)

- **결과물이 큼**: 견본은 첫 몇 줄(또는 바뀐 부분)만 보이고, 전체 위치를 함께 알린다.
- **결과물이 글이 아님**(이미지 · 이진 파일): 종류 · 크기 · 여는 법을 견본으로 보인다.
- **선택 창을 취소함**: 확인 없이 마무리하고, 보고의 '확인하지 못한 것'에 적는다. 검사도 취소를 확인한 것으로 보고 막지 않는다.
- **견본에 비밀값 · 개인 정보가 들어감**: 견본에서 가린 뒤 보인다(기존 가림 필터를 쓴다).
- **사람이 없는 실행**(무인 · 자동 알림으로 이어진 턴): 견본 확인을 하지 않고, 가정을 보고에 밝힌다 — 정확한 판별은 구현 중 정하고 사용자에게 묻는다. 검사도 자동 알림 턴에서는 막지 않는다.
- **견본 확인 뒤 다시 고침**: 마지막 편집 뒤 확인이 다시 필요하지만, 이번 턴에 이미 두 번 확인했으면 막지 않는다(두 번까지 규칙).
- **'결과물 변화 없음'을 잘못 적음**: 검사는 선언을 믿으므로 잡지 못한다 — 측정에서 결과물 과제의 선언 수를 센다.
- **SCV 기록만 바뀐 턴**: 편집으로 세지 않아 막지 않는다.
- **설정 값이 엉뚱함**: on 으로 본다(다른 SCV 스위치와 같은 규칙).

## Risks / Open Questions

- 사용자 역할(시뮬레이션)은 사람보다 일관되고, 때로 묻지 않은 것까지 말한다. 실제 사람에게서도 같은 이득이 나는지는 하루 실사용 분석에서 확인해야 한다.
- 질문 1.5배 목표를 못 맞출 수 있다 — 오늘 줄이려는 시도(미리 묻지 않기)는 정확도를 떨어뜨렸다.
- 견본으로 드러나지 않는 성질(예: 엑셀용 한글 깨짐 방지 표시)은 사람이 놓칠 수 있다 — 바깥 조건 미리 묻기가 얼마나 막는지 미확인.
- 무인으로 도는 긴 작업에서 '맨 끝 확인'이 흐름을 멈추게 할 수 있다 — 무인 실행일 때의 동작은 구현 중 정한다(사용자에게 묻기).
- 매 턴 블록이 길어지는 만큼 매 턴 비용이 는다 — 측정으로 확인.
- 지시만으로 이득이 났지만, 모델 버전이 바뀌면 달라질 수 있다 — 측정 장치를 남겨 다시 잴 수 있게 한다.
- 모델별 차이(2026-10-06 실측, 확인): Sonnet 5 · Haiku 4.5 는 지시를 받고도 결과물이 바뀌는 과제에서 견본 확인을 건너뛴다(12번 중 3번 · 8번, Opus 0번). 견본을 보여 준 실행은 Opus 12/12 · Sonnet 9/9 · Haiku 2/4 통과. → 검사로 막기로 함(2026-10-06 사용자 결정, 목표 9).
- 검사는 '결과물 변화 없음' 선언을 믿는다 — 모델이 결과물 과제에 잘못 선언하면 잡지 못한다(측정에서 셈).
- Haiku 4.5 는 견본을 보이고 다른 점을 두 번 들은 뒤에도 최종 출력이 바뀌지 않은 실행이 있다(1번, 원인 미확인) — 검사만으로는 Opus 수준에 닿기 어려울 수 있다.
- 검사가 막을 때마다 한 턴이 더 돈다 — 막은 횟수를 측정에서 센다.
- 결과물이 바뀌지 않는 구조 정리 과제에서도 세 모델 모두 견본 확인을 했다(Opus 3 · Sonnet 3 · Haiku 2번, 지시만, 확인) — 목표 2와 어긋나 질문을 늘린다. 측정(T10)에서 구조 정리 과제까지 센다.

# Test Plan — 끝내기 전 결과 견본 확인 — 대충 말해도 원하는 결과로

## Overview

끝 확인 규칙(결과물이 바뀌는 일이면 끝내기 전 실제 결과 견본을 한 번 보여 주고 확인받기)과 같은 계열 결함 찾기가 SCV 에 들어가, 대충 한 요청에서도 숨은 의도에 맞는 결과가 나오는지 확인한다.
자동 검사(문구 · 설정 · 순수 함수 · 규약)는 맥 · 리눅스 CI 에서, 실제 효과는 저장소로 옮긴 측정 장치로 지금 SCV 와 같은 날 나란히 잰다(실제 Claude 를 돌리므로 설치본 확인 단계).
기준선(2026-10-05): 지금 SCV 모두 통과 12/18 · 질문 22개, 다듬은 판 18/18 · 질문 51개(사용자 역할 Opus + 상황 문장 대조).
종료 훅의 견본 확인 검사(건너뛰면 한 번 막음)는 단위 검사로 확인하고, 측정은 세 모델(Opus 5.5 · Sonnet 5 · Haiku 4.5)로 한다. 모델별 기준선(지시만 넣은 판, 2026-10-06): 모두 통과 Sonnet 5 13/18 → 15/18 · Haiku 4.5 5/18 → 8/18, 결과물이 바뀌는 과제의 견본 확인 건너뜀 Sonnet 3/12 · Haiku 8/12(Opus 0/12).

## Test scenarios

### T1. 켬 — 매 턴 블록에 끝 확인 안내가 실린다

- **Setup**: 하이드레이트한 임시 저장소, 설정 키 없음(기본 on), 선택 창이 있는 호스트 프로필(Claude Code).
- **Run**: 매 턴 훅에 사람 메시지 하나를 넣는다.
- **Expected**: 매 턴 블록에 끝 확인 안내(결과물이 바뀌는 일이면 끝내기 전 견본 한 번 · 선택 창 · 다른 점은 직접 입력 · 두 번까지 · 결과물 없는 일은 건너뜀 · 바깥 조건은 미리 · 같은 계열 결함)가 실린다. 안내는 세 줄 안팎이고 자세한 본문은 계약을 가리킨다.
- **Pass criterion**: 출력에 안내 문구가 있고, 계약 경로가 있다.

### T2. 끔 — 설정 off 면 지금 SCV 와 같은 출력

- **Setup**: T1 과 같되 설정 키를 off.
- **Run**: 같은 메시지로 매 턴 훅을, 편집이 있는 같은 턴 기록으로 종료 훅을 돌리고, 이 기능이 없는 코어(직전 릴리스)의 출력과 비교한다.
- **Expected**: 매 턴 훅 · 종료 훅 출력이 각각 바이트 단위로 같다.
- **Pass criterion**: diff 없음.

### T3. 선택 창이 없는 호스트 — 글 질문 한 번

- **Setup**: 선택 창 이름이 비어 있는 호스트 프로필(코덱스 모양).
- **Run**: 매 턴 훅을 돌린다.
- **Expected**: 안내가 '선택 창' 대신 '글 질문 한 번으로 확인'을 말한다.
- **Pass criterion**: 선택 창 문구 없음, 글 질문 문구 있음.

### T4. 순수 함수 단위

- **Setup**: 코어 라이브러리를 불러온다.
- **Run**: 설정 해석(없음 · on · off · OFF · 엉뚱한 값), 확인 통로 고르기(빈 값 · 선택 창 이름), 문구 만들기(켬/끔 × 선택 창/글), 검사 판정(켬/끔 · 사람 턴 · 마지막 편집 위치 · 그 뒤 확인 수 · 이번 턴 확인 수 · 취소 · 선언 줄 조합)을 표로 확인한다.
- **Expected**: 없거나 엉뚱한 값은 on, off(대소문자 무관)만 off. 끔이면 문구는 빈 값. 검사 판정은 T16 · T17 의 경우와 같은 결과.
- **Pass criterion**: 표의 모든 칸 일치, 순수성 검사기 통과(bash 5 · 3.2).

### T5. 규칙 본문은 한 곳에만

- **Setup**: 저장소.
- **Run**: 규칙 일치 검사(같은 요구는 한 곳에만)를 돌린다.
- **Expected**: 끝 확인 규칙의 본문이 코어 계약 한 곳에만 있고, 다른 문서 · 훅은 가리키기만 한다.
- **Pass criterion**: 검사 통과, 본문 중복 0.

### T6. 긴 작업은 맨 끝에 한 번

- **Setup**: work 액션 규약.
- **Run**: 규약에서 끝 확인 문구의 위치를 찾는다.
- **Expected**: 보고 직전 끝 단계에만 '견본 확인 한 번'이 있고, 구현 중간 단계에는 없다.
- **Pass criterion**: 끝 단계에 1번, 중간 단계에 0번.

### T7. 측정 장치 자기 검증

- **Setup**: 저장소로 옮긴 측정 장치, 설치본 플러그인.
- **Run**: 과제 6개 저장소를 만들고 숨은 테스트를 처음 상태와 모범 답에 돌린다.
- **Expected**: 처음 상태는 T4(구조 정리)만 통과하고 나머지는 실패, 모범 답은 6개 모두 통과.
- **Pass criterion**: 2026-10-05 검증과 같은 표.

### T8. 측정 — 정확도

- **Setup**: 측정 장치, 사용자 역할 Opus + 상황 문장 대조, 같은 날, 세 모델(Opus 5.5 · Sonnet 5 · Haiku 4.5) 각각 기본 생각 깊이.
- **Run**: 모델마다 지금 SCV(설치본)와 새 SCV(브랜치 사본 또는 새 설치본)를 과제 6개 × 3번씩(36번, 모두 108번) 나란히 돌린다. 각 실행의 실제 모델을 대화 기록으로 확인한다.
- **Expected**: Opus 5.5 는 새 SCV 의 숨은 테스트 모두 통과가 지금 SCV 보다 3번 이상 많다. Sonnet 5 · Haiku 4.5 는 3번 이상이 목표.
- **Pass criterion**: Opus 5.5 차이 ≥ 3 (18번 기준, 필수) — 못 지키면 검사를 빼고 다시 잰다. Sonnet 5 · Haiku 4.5 는 목표 — 못 미치면 잰 값 · 원인을 기록하고 보관 전에 사용자 결정. T10~T13 의 필수 판정은 Opus 5.5 기록으로 하고, 다른 두 모델은 같은 수를 기록한다.

### T9. 측정 — 질문 수 (목표)

- **Setup**: T8 의 기록.
- **Run**: 대화 기록에서 선택 창 질문 수를 방식별로 센다.
- **Expected**: 모델마다 새 SCV 질문 수 ≤ 지금 SCV × 1.5.
- **Pass criterion**: 목표를 맞추면 통과. 못 맞추면 비율 · 원인을 기록하고 보관 전에 사용자 결정을 받는다. 검사 때문에 질문이 크게 늘었는지(어디부터 '크게'인지는 미결)는 이 기록으로 사용자와 정한다.

### T10. 측정 — 결과물 없는 일은 건너뜀

- **Setup**: T8 의 기록 중 테스트 통과 과제(T3), 그리고 구조 정리 과제(T4).
- **Run**: 새 SCV 에서 견본 확인 질문을 센다(T3 · T4 각 3번, 세 모델).
- **Expected**: 0번.
- **Pass criterion**: Opus 5.5 의 T3 3번 모두 견본 확인 없음(필수). T4 와 다른 두 모델은 센 값을 기록한다(목표 2 확인 — 지시만 넣은 판은 T4 에서 Opus 3 · Sonnet 3 · Haiku 2번 확인함).

### T11. 측정 — 다른 점은 직접 입력으로

- **Setup**: T8 의 기록.
- **Run**: 새 SCV 의 견본 확인 선택 창 보기를 모두 모은다.
- **Expected**: 글 칸 없는 '다른 점 …' 식 보기가 없다(보기는 '이대로 좋음' 하나 + 직접 입력).
- **Pass criterion**: 그런 보기 0개, 빈 답이 넘어간 기록 0번.

### T12. 측정 — 바깥 조건은 미리

- **Setup**: T8 의 기록 중 가져오기 과제(T6).
- **Run**: 새 SCV 3번에서 첫 질문과 첫 편집의 순서, 첫 질문이 입력 형식을 묻는지 본다.
- **Expected**: 입력 형식을 일 시작 전에 묻는다.
- **Pass criterion**: 3번 모두 입력 형식 질문이 첫 편집보다 먼저.

### T13. 측정 — 같은 계열 결함

- **Setup**: T8 의 기록 중 테스트 통과 과제(T3, 사용자 상황: 다른 버그도 같이 고쳐 주길 원함).
- **Run**: 숨은 테스트(테스트 밖 결함)와 마지막 보고를 본다.
- **Expected**: 새 SCV 가 테스트 밖 결함까지 고치고, 고친 것을 보고에 적는다.
- **Pass criterion**: 숨은 테스트 3/3 통과, 보고 3/3 에 고친 것 목록.

### T14. 두 래퍼 설치본

- **Setup**: 코어 릴리스 뒤 두 래퍼 동기화 · 릴리스.
- **Run**: 두 설치본의 매 턴 훅 출력과 설정 예시를 확인한다.
- **Expected**: Claude Code 는 선택 창 문구, 코덱스는 글 질문 문구, 설정 키가 예시 파일에 있다.
- **Pass criterion**: 두 래퍼 모두 확인.

### T15. 회귀 — 지켜야 할 것

- **Setup**: 저장소.
- **Run**: 기존 테스트 전부를 맥 · 리눅스에서 돌린다.
- **Expected**: 매 턴 등록 · 인용 · 맨 위 한 줄, 선택 창 규칙과 답 뒤 재등록, 가드 동작이 그대로다.
- **Pass criterion**: 기존 테스트 전부 통과.

### T16. 검사 — 편집 뒤 견본 확인이 없으면 한 번 막는다

- **Setup**: 하이드레이트한 임시 저장소, 설정 키 없음(기본 on), 선택 창이 있는 호스트 프로필, 사람 메시지로 열린 턴. 이번 턴 기록 고정본: 코드 파일 편집 → 그 뒤 선택 창 없음 → 답에 '결과물 변화 없음' 줄 없음.
- **Run**: 종료 훅을 같은 턴에 두 번 돌린다.
- **Expected**: 첫 번째는 막고, 견본 확인 또는 '결과물 변화 없음' 한 줄을 요구하는 이유를 알린다. 두 번째는 막지 않는다(검사마다 한 턴에 한 번).
- **Pass criterion**: 첫 출력에 막음 + 이유, 두 번째 출력에 막음 없음.

- **Run**: 답 끝에 견본과 글 질문이 있는 기록, 없는 기록으로 종료 훅을 돌린다.
- **Expected**: 글 질문이 있으면 통과, 없으면 한 번 막는다.
- **Pass criterion**: 두 경우 모두 기대대로.
