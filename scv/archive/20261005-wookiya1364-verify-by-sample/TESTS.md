# Test Plan — 끝내기 전 결과 견본 확인 — 대충 말해도 원하는 결과로

## Overview

끝 확인 규칙(결과물이 바뀌는 일이면 끝내기 전 실제 결과 견본을 한 번 보여 주고 확인받기)과 같은 계열 결함 찾기가 SCV 에 들어가, 대충 한 요청에서도 숨은 의도에 맞는 결과가 나오는지 확인한다.
자동 검사(문구 · 설정 · 순수 함수 · 규약)는 맥 · 리눅스 CI 에서, 실제 효과는 저장소로 옮긴 측정 장치로 지금 SCV 와 같은 날 나란히 잰다(실제 Claude 를 돌리므로 설치본 확인 단계).
기준선(2026-10-05): 지금 SCV 모두 통과 12/18 · 질문 22개, 다듬은 판 18/18 · 질문 51개(사용자 역할 Opus + 상황 문장 대조).
종료 훅의 견본 확인 검사(건너뛰면 한 번 막음)는 단위 검사로 확인하고, 측정은 세 모델(Opus 5.5 · Sonnet 5 · Haiku 4.5)로 한다. 모델별 기준선(지시만 넣은 판, 2026-10-06): 모두 통과 Sonnet 5 13/18 → 15/18 · Haiku 4.5 5/18 → 8/18, 결과물이 바뀌는 과제의 견본 확인 건너뜀 Sonnet 3/12 · Haiku 8/12(Opus 0/12).

## Test scenarios

### T1. 켬 — 매 턴 블록에 끝 확인 안내가 실린다

- **Setup**: 하이드레이트한 임시 저장소, 설정 키 없음(기본 on), 선택 창이 있는 호스트 프로필(Claude Code).
- **Run**: 매 턴 훅에 사람 메시지 하나를 넣는다.
- **Expected**: 매 턴 블록에 끝 확인 안내(결과물이 바뀌는 일이면 끝내기 전 견본 한 번 · 선택 창 · 다른 점은 직접 입력 · 두 번까지 · 결과물 없는 일은 건너뜀 · 바깥 조건은 미리 · 같은 계열 결함)가 실린다. 안내는 세 줄 안팎이고 자세한 본문은 계약을 가리킨다.
- **Pass criterion**: 출력에 안내 문구가 있고, 계약 경로가 있다.

### T2. 끔 — 설정 off 면 지금 SCV 와 같은 출력

- **Setup**: T1 과 같되 설정 키를 off.
- **Run**: 같은 메시지로 매 턴 훅을, 편집이 있는 같은 턴 기록으로 종료 훅을 돌리고, 이 기능이 없는 코어(직전 릴리스)의 출력과 비교한다.
- **Expected**: 매 턴 훅 · 종료 훅 출력이 각각 바이트 단위로 같다.
- **Pass criterion**: diff 없음.

### T3. 선택 창이 없는 호스트 — 글 질문 한 번

- **Setup**: 선택 창 이름이 비어 있는 호스트 프로필(코덱스 모양).
- **Run**: 매 턴 훅을 돌린다.
- **Expected**: 안내가 '선택 창' 대신 '글 질문 한 번으로 확인'을 말한다.
- **Pass criterion**: 선택 창 문구 없음, 글 질문 문구 있음.

### T4. 순수 함수 단위

- **Setup**: 코어 라이브러리를 불러온다.
- **Run**: 설정 해석(없음 · on · off · OFF · 엉뚱한 값), 확인 통로 고르기(빈 값 · 선택 창 이름), 문구 만들기(켬/끔 × 선택 창/글), 검사 판정(켬/끔 · 사람 턴 · 마지막 편집 위치 · 그 뒤 확인 수 · 이번 턴 확인 수 · 취소 · 선언 줄 조합)을 표로 확인한다.
- **Expected**: 없거나 엉뚱한 값은 on, off(대소문자 무관)만 off. 끔이면 문구는 빈 값. 검사 판정은 T16 · T17 의 경우와 같은 결과.
- **Pass criterion**: 표의 모든 칸 일치, 순수성 검사기 통과(bash 5 · 3.2).

### T5. 규칙 본문은 한 곳에만

- **Setup**: 저장소.
- **Run**: 규칙 일치 검사(같은 요구는 한 곳에만)를 돌린다.
- **Expected**: 끝 확인 규칙의 본문이 코어 계약 한 곳에만 있고, 다른 문서 · 훅은 가리키기만 한다.
- **Pass criterion**: 검사 통과, 본문 중복 0.

### T6. 긴 작업은 맨 끝에 한 번

- **Setup**: work 액션 규약.
- **Run**: 규약에서 끝 확인 문구의 위치를 찾는다.
- **Expected**: 보고 직전 끝 단계에만 '견본 확인 한 번'이 있고, 구현 중간 단계에는 없다.
- **Pass criterion**: 끝 단계에 1번, 중간 단계에 0번.

### T7. 측정 장치 자기 검증

- **Setup**: 저장소로 옮긴 측정 장치, 설치본 플러그인.
- **Run**: 과제 6개 저장소를 만들고 숨은 테스트를 처음 상태와 모범 답에 돌린다.
- **Expected**: 처음 상태는 T4(구조 정리)만 통과하고 나머지는 실패, 모범 답은 6개 모두 통과.
- **Pass criterion**: 2026-10-05 검증과 같은 표.

### T8. 측정 — 정확도

- **Setup**: 측정 장치, 사용자 역할 Opus + 상황 문장 대조, 같은 날, 세 모델(Opus 5.5 · Sonnet 5 · Haiku 4.5) 각각 기본 생각 깊이.
- **Run**: 모델마다 지금 SCV(설치본)와 새 SCV(브랜치 사본 또는 새 설치본)를 과제 6개 × 3번씩(36번, 모두 108번) 나란히 돌린다. 각 실행의 실제 모델을 대화 기록으로 확인한다.
- **Expected**: Opus 5.5 는 새 SCV 의 숨은 테스트 모두 통과가 지금 SCV 보다 3번 이상 많다. Sonnet 5 · Haiku 4.5 는 3번 이상이 목표.
- **Pass criterion**: Opus 5.5 차이 ≥ 3 (18번 기준, 필수) — 못 지키면 검사를 빼고 다시 잰다. Sonnet 5 · Haiku 4.5 는 목표 — 못 미치면 잰 값 · 원인을 기록하고 보관 전에 사용자 결정. T10~T13 의 필수 판정은 Opus 5.5 기록으로 하고, 다른 두 모델은 같은 수를 기록한다.

### T9. 측정 — 질문 수 (목표)

- **Setup**: T8 의 기록.
- **Run**: 대화 기록에서 선택 창 질문 수를 방식별로 센다.
- **Expected**: 모델마다 새 SCV 질문 수 ≤ 지금 SCV × 1.5.
- **Pass criterion**: 목표를 맞추면 통과. 못 맞추면 비율 · 원인을 기록하고 보관 전에 사용자 결정을 받는다. 검사 때문에 질문이 크게 늘었는지(어디부터 '크게'인지는 미결)는 이 기록으로 사용자와 정한다.

### T10. 측정 — 결과물 없는 일은 건너뜀

- **Setup**: T8 의 기록 중 테스트 통과 과제(T3), 그리고 구조 정리 과제(T4).
- **Run**: 새 SCV 에서 견본 확인 질문을 센다(T3 · T4 각 3번, 세 모델).
- **Expected**: 0번.
- **Pass criterion**: Opus 5.5 의 T3 3번 모두 견본 확인 없음(필수). T4 와 다른 두 모델은 센 값을 기록한다(목표 2 확인 — 지시만 넣은 판은 T4 에서 Opus 3 · Sonnet 3 · Haiku 2번 확인함).

### T11. 측정 — 다른 점은 직접 입력으로

- **Setup**: T8 의 기록.
- **Run**: 새 SCV 의 견본 확인 선택 창 보기를 모두 모은다.
- **Expected**: 글 칸 없는 '다른 점 …' 식 보기가 없다(보기는 '이대로 좋음' 하나 + 직접 입력).
- **Pass criterion**: 그런 보기 0개, 빈 답이 넘어간 기록 0번.

### T12. 측정 — 바깥 조건은 미리

- **Setup**: T8 의 기록 중 가져오기 과제(T6).
- **Run**: 새 SCV 3번에서 첫 질문과 첫 편집의 순서, 첫 질문이 입력 형식을 묻는지 본다.
- **Expected**: 입력 형식을 일 시작 전에 묻는다.
- **Pass criterion**: 3번 모두 입력 형식 질문이 첫 편집보다 먼저.

### T13. 측정 — 같은 계열 결함

- **Setup**: T8 의 기록 중 테스트 통과 과제(T3, 사용자 상황: 다른 버그도 같이 고쳐 주길 원함).
- **Run**: 숨은 테스트(테스트 밖 결함)와 마지막 보고를 본다.
- **Expected**: 새 SCV 가 테스트 밖 결함까지 고치고, 고친 것을 보고에 적는다.
- **Pass criterion**: 숨은 테스트 3/3 통과, 보고 3/3 에 고친 것 목록.

### T14. 두 래퍼 설치본

- **Setup**: 코어 릴리스 뒤 두 래퍼 동기화 · 릴리스.
- **Run**: 두 설치본의 매 턴 훅 출력과 설정 예시를 확인한다.
- **Expected**: Claude Code 는 선택 창 문구, 코덱스는 글 질문 문구, 설정 키가 예시 파일에 있다.
- **Pass criterion**: 두 래퍼 모두 확인.

### T15. 회귀 — 지켜야 할 것

- **Setup**: 저장소.
- **Run**: 기존 테스트 전부를 맥 · 리눅스에서 돌린다.
- **Expected**: 매 턴 등록 · 인용 · 맨 위 한 줄, 선택 창 규칙과 답 뒤 재등록, 가드 동작이 그대로다.
- **Pass criterion**: 기존 테스트 전부 통과.

### T16. 검사 — 편집 뒤 견본 확인이 없으면 한 번 막는다

- **Setup**: 하이드레이트한 임시 저장소, 설정 키 없음(기본 on), 선택 창이 있는 호스트 프로필, 사람 메시지로 열린 턴. 이번 턴 기록 고정본: 코드 파일 편집 → 그 뒤 선택 창 없음 → 답에 '결과물 변화 없음' 줄 없음.
- **Run**: 종료 훅을 같은 턴에 두 번 돌린다.
- **Expected**: 첫 번째는 막고, 견본 확인 또는 '결과물 변화 없음' 한 줄을 요구하는 이유를 알린다. 두 번째는 막지 않는다(검사마다 한 턴에 한 번).
- **Pass criterion**: 첫 출력에 막음 + 이유, 두 번째 출력에 막음 없음.

### T17. 검사 — 막지 않는 경우

- **Setup**: T16 과 같은 저장소, 기록 고정본 일곱 개.
- **Run**: (a) 마지막 편집 뒤 견본 확인 선택 창이 있음 (b) 답에 '결과물 변화 없음' 줄 (c) 편집이 SCV 기록뿐 (d) 자동 알림으로 열린 턴 (e) 설정 off (f) 이번 턴에 확인 두 번 뒤 다시 편집 (g) 확인 선택 창을 취소 — 각각 종료 훅을 돌린다.
- **Expected**: 일곱 경우 모두 막지 않는다. (e) 는 종료 훅 출력이 이 기능이 없는 코어와 바이트 단위로 같다.
- **Pass criterion**: 막음 0번, (e) diff 없음.

### T18. 검사 — 선택 창이 없는 호스트

- **Setup**: 선택 창 이름이 비어 있는 호스트 프로필(코덱스 모양), 코드 파일 편집이 있는 사람 턴.
- **Run**: 답 끝에 견본과 글 질문이 있는 기록, 없는 기록으로 종료 훅을 돌린다.
- **Expected**: 글 질문이 있으면 통과, 없으면 한 번 막는다.
- **Pass criterion**: 두 경우 모두 기대대로.

### T19. 측정 — 견본 확인 건너뜀 · 검사가 막은 횟수 (세 모델)

- **Setup**: T8 의 기록.
- **Run**: 모델마다 결과물이 바뀌는 과제(T1 · T2 · T5 · T6, 12번)에서 견본 확인을 한 실행 · 건너뛴 실행, '결과물 변화 없음' 선언 수, 검사가 막은 횟수를 센다.
- **Expected**: 세 모델 모두 건너뜀 0번(목표). 막은 횟수와 선언 수는 기록한다(기준은 미결).
- **Pass criterion**: 목표를 맞추면 통과. 못 맞추면 잰 값 · 원인을 기록하고 보관 전에 사용자 결정을 받는다.

## Pass criteria

- T1~T7, T15~T18 통과(맥 · 리눅스).
- T8 의 Opus 5.5 몫 통과(모두 통과 차이 ≥ 3), T10~T13 의 필수 몫(Opus 5.5) 통과.
- Opus 5.5 가 T8 을 못 지키거나 검사 때문에 질문이 크게 늘면(어디부터인지는 미결) 검사를 빼고 다시 잰다.
- T9 · T19 와 T8 의 Sonnet 5 · Haiku 4.5 몫은 목표 — 맞추면 통과, 못 맞추면 기록과 사용자 결정으로 닫는다.
- T14 두 래퍼 설치본 확인.
