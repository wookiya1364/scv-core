# 마무리 보고 — /scv:update — gh 없이 최신 버전 확인, 앱 · 터미널 어디서든 직접 올리기

## 1. 문제

- 상황: 다른 컴퓨터에서 SCV 를 올리려던 사용자가 막혔다는 말을 2026-11-16 에 전해 들었다. 그 컴퓨터에는 `gh` 가 없었고, 프로젝트 주인은 클로드 앱에서 `/scv:update` 가 알려 주는 명령이 듣지 않는다고 알려 줬다.
- 기대: `/scv:update` 한 번으로 최신 버전이 보이고, 새 버전이 있으면 터미널이든 클로드 앱이든 올라간다.
- 실제: `gh` 가 없으면 최신 버전 자리에 "확인 불가"만 나온다. 올리는 일은 슬래시 명령 두 줄을 안내만 하는데, 그 명령은 클로드 앱에 입력하면 플러그인 화면만 뜨고 올라가지 않는다(프로젝트 주인의 보고 — 이 계획을 세울 때 직접 다시 해 보지는 않았다).
- 재현 조건: ① `gh` 가 PATH 에 없는 셸에서 `scripts/update.sh` 실행 → `LATEST_VERSION: (unavailable — gh CLI not installed …)`. ② 클로드 앱 세션에서 `/plugin marketplace update scv-claude-code` 입력.

## 2. 관찰

- 관찰한 사실과 측정값: `scripts/update.sh` 는 `gh` 가 없으면 바로 "확인 불가"를 낸다(57 ~ 59줄). `git ls-remote --tags` 로는 같은 저장소에서 0.94.0 을 1초에 읽었고 `gh release view` 의 값과 같았다. 설명서(`skills/update/SKILL.md`)는 "자동 실행 금지 — 안내만"이라고 적는다. 명령줄에는 `claude plugin marketplace update` · `claude plugin update -s <범위>` 가 있다(2.1.322).
- 정상일 때와 차이: `gh` 가 있고 터미널에서 쓰는 컴퓨터에서는 버전이 보이고 안내한 두 명령도 듣는다. `/scv:mods` 는 같은 일을 명령줄로 직접 해서 앱에서도 된다.

## 3. 가설

- H1: 최신 버전 확인이 `gh` 하나에만 기대고 있어서, 그 도구가 없는 컴퓨터에서 확인이 안 된다.
- H2: 슬래시 명령은 클로드 앱에서 듣지 않지만, 같은 일을 하는 명령줄(`claude plugin …`)은 앱 세션의 셸에서도 된다.
- H3: 모드 엔진이 올릴 때 범위를 넘기지 않아서, 같은 모드가 두 범위에 깔리면 범위별로 올리지 못한다(같은 날 보탠 요구를 확인하다 세움).

## 4. 실험

- 방법과 같게 둔 것: 같은 저장소 · 같은 시각에 `gh release view` 와 `git ls-remote --tags`(정식 태그만 골라 숫자로 견줌)의 값을 견줬다. H2 는 2026-11-15 릴리스 때 앱 세션의 셸에서 명령줄 두 줄로 설치본을 0.93.3 → 0.94.0 으로 올린 기록과, 명령줄 도움말로 봤다. 구현 뒤에는 이 컴퓨터의 앱 세션 셸에서 고친 엔진을 실제 설치본에 돌렸고(`apply`), H3 은 임시 폴더에 대시보드를 project 범위로 한 번 더 깔아 같은 상태에서 고치기 전 엔진과 고친 엔진을 차례로 돌린 뒤 지웠다(설치 기록 파일을 앞뒤로 견줘 원래대로임을 확인).
- 결과와 가설별 판정: H1 맞음 — 두 길의 값이 같았고(0.94.0), 엔진에는 `gh` 말고 다른 길이 없다. H2 는 반만 확인 — 명령줄이 앱 세션에서 되는 것은 확인(실제 `apply`: 본체 "이미 최신 0.94.0 [user]", 모드 명령 2개 성공, 11.6초), 슬래시 명령이 앱에서 안 되는 것은 보고만 받았다. H3 은 고쳐 적음 — 두 범위 상태에서 고치기 전 엔진은 범위 없는 같은 명령을 두 번 실행했고 결과 줄에 버전만 적힌 줄이 섞여 나왔다. 고친 엔진은 `-s user` · `-s project` 를 한 번씩 실행하고 범위별 결과 두 줄을 냈다. 범위 없는 명령이 어느 쪽을 올리는지는 두 쪽이 모두 최신이라 가리지 못했다. 덤으로 확인: 설치 목록에는 다른 프로젝트의 project 범위 설치본도 그 프로젝트 폴더와 함께 나온다.

## 5. 원인

- 직접 원인과 일어난 길: 엔진이 최신 버전을 `gh` 로만 읽고, 설명서가 올리는 일을 슬래시 명령 안내로만 끝낸다. 그래서 `gh` 가 없으면 확인에서, 앱에서는 올리기에서 막힌다. 모드 쪽은 설치 목록을 "이름 버전"으로만 읽어 범위를 버렸고, 그래서 두 범위의 같은 모드가 구별되지 않는 두 줄이 됐다.
- 근본 원인: 0.11.2 때 "슬래시 명령은 다른 슬래시 명령을 부를 수 없다"에서 곧바로 "그러니 안내만 한다"로 정했고, 명령줄로 직접 하는 길을 보지 않았다. 그 뒤 `/scv:mods` 가 명령줄 길을 열었는데(2026-10-22) 이 명령에는 되돌려 적용하지 않았다.

## 6. 해결과 검증

- 해결책과 고른 이유: ① 최신 버전을 `git ls-remote --tags` 로 읽고 정식 태그만 숫자로 견준다 — `git` 은 필수 도구라 길이 하나로 줄고 컴퓨터마다 결과가 같다. ② `update.sh apply` 가 `claude plugin` 명령줄로 직접 올린다(마켓 새로 받기 → 범위마다 올리기 → 앞뒤 버전 보고) — `/scv:mods` 가 이미 쓰던 길이라 틀을 그대로 썼다. ③ 본체 뒤에 모드 엔진의 올리기를 이어 부르고 두 결과를 따로 보고한다. ④ 모드 엔진이 범위를 읽어, 두 범위 이상이면 범위마다 올린다. 설치 목록 읽기(`plugin_lines`)는 두 엔진이 함께 쓴다 — 다른 프로젝트의 설치본을 빼는 규칙이 한 곳에만 있게.
- 고치기 전후 값: `gh` 없는 환경의 진단 — 전 "확인 불가", 후 `LATEST_VERSION: 0.94.0`(0.59초; `gh` 로 읽던 때 0.61초). 새 시험 80개 검사 — 고치기 전 코드에서 79개 중 55개 실패, 후 실패 0(맥 기본 셸 3.2 · 새 셸 5.3 둘 다). 두 범위 상태의 모드 올리기 — 전: 범위 없는 같은 명령 2번, 후: 범위마다 1번씩. 업데이트 안내에 남은 슬래시 명령 — 전 설명서 1곳 · README 3곳, 후 0곳.
- 부작용과 회귀 시험: 기존 검사 두 줄을 새 동작에 맞게 바꿨다 — 모드 시험의 "업데이트 설명서에 모드라는 말이 없어야 한다"와 코어 계약 시험의 "설명서에 슬래시 명령 안내가 있어야 한다"(둘 다 오늘 요구와 반대). 모드 엔진을 보는 나머지 검사는 기대값을 바꾸지 않고 통과(55개). 코어의 README 검사가 슬래시 명령 두 문구를 요구해, README 에는 터미널용 참고 한 줄로 남겼다(사용자 결정). 돌린 것: 새 시험 80개 · 모드 시험 55개(맥 기본 셸 3.2 · 새 셸 5.3 · 우분투 24.04 의 mawk), 래퍼 CI 가 돌리는 나머지 검사 24개(README · 문법 · 설명서 형식 · 코어 받아 오기 연습 포함) 가운데 21개 통과, 3개(출처 · 개인 정보 검사)는 이 컴퓨터에 견줄 기준 커밋이 없어 건너뜀으로 끝남 — PR 의 CI 에서 봐야 한다. 처음에 래퍼의 tests 폴더 전체를 한꺼번에 돌린 것은 잘못된 방법이었다 — 그 폴더의 대부분은 코어에서 옮겨 온 시험이라 그 자리에서는 돌지 않는다. 릴리스는 하지 않았고, 실제로 버전이 오르는 것은 다음 릴리스 때 본다.

## 7. 배운 것

- 다음에 같은 문제를 만나면 진단하는 법: "업데이트가 안 된다"는 말을 들으면 세 가지를 따로 본다 — ① 최신 버전이 읽히는가(인자 없는 진단의 `LATEST_VERSION` 줄) ② 올리는 명령이 그 환경에서 듣는가(슬래시 명령은 앱에서 안 될 수 있다 — 명령줄로 본다) ③ 설치가 어느 범위에 있는가(`claude plugin list --json` 의 `scope` · `projectPath`). Claude Code 설정 폴더를 옮긴 컴퓨터라면 마켓 목록 파일의 옛 경로부터 본다 — 그것은 SCV 밖의 원인이다.
- 다른 곳에도 쓸 수 있는 것: 사람에게 명령을 안내하기 전에 "그 명령이 모든 화면(터미널 · 앱)에서 듣는가"를 먼저 확인한다 — 명령줄로 할 수 있으면 엔진이 직접 한다. 설치 목록을 읽을 때는 범위를 버리지 않는다. 가짜 환경 시험이 세운 가정(목록의 모양)은 임시 폴더에서 실제로 한 번 깔아 보고 지우는 것으로 싸게 확인할 수 있다 — 설치 기록 파일을 먼저 복사해 두고 끝에 견준다.
