# 마무리 보고 — 주석 옮기기 안전 — 셸 따옴표를 바로 읽기 · 깨지는 파일은 건드리지 않기 · 실패하면 원래대로

## 1. 문제

- 상황: 0.98.0 주석 옮기기(기본 켜짐)를 SCV 코어 사본에 돌림(2026-11-22).
- 기대: 지운 코드는 뜻이 같고, 옮기기 전 사전 항목은 하나도 잃지 않으며, 실패하면 코드가 그대로.
- 실제: 셸 스크립트 1개 문법이 깨짐(pure-declare.sh 106번 줄). 실제 저장소에서는 사전 쓰기가 실패했는데 코드 283개 파일에서 주석이 지워진 채 남음. 사본에서는 사전 항목 4개가 빠짐.
- 재현 조건: 큰따옴표 안 `$( )` 속 작은따옴표에 `"` 가 든 줄 뒤에 문자열 속 `###` 가 있는 셸 파일 · 예시 글에 `@pure` · `종류:` 가 든 표식 주석.

## 2. 관찰

- 결함 증상: `x="$(… tr -d '"[:space:]' …)"` 뒤 줄의 `'…(### 이름 …'` 가 주석으로 지워짐. 앞 버전 읽기는 큰따옴표 안의 `$( )` 를 몰라 `"` 를 바깥 따옴표 끝으로 봄.
- 복원 없음: 옮기기는 코드를 먼저 쓰고 그다음 사전을 써서, 사전 쓰기가 실패하면 코드만 바뀐 채 끝남.
- 항목 손실: 빠진 4개(parse_markers · pc_extract_entries · pc_validate_entries · scv_pd_declared)는 모두 예시 글에 `@pure` · `종류:` 가 들어 있음. 개수 비교 검사는 다른 새 항목이 수를 채워 놓침.

## 3. 가설

- 가설 1: 셸 읽기가 겹친 따옴표 · 치환을 따라가지 못함 — 맞음(작은 예 3개로 재현).
- 가설 2: 예시 글 속 표식 · 칸 이름을 진짜로 읽음 — 맞음(가짜 항목 add · clamp 가 생기고 원래 칸이 빔).
- 가설 3: 실제 저장소의 사전 쓰기 실패는 같은 원인 — 확인 못 함(사본에서는 성공).

## 4. 실험

- 작은 예로 재현: 고치기 전 `echo '(### b)'` 가 `echo '(` 로 잘림.
- 사본 전체 지운 뒤 `bash -n` · `py_compile`: 고치기 전 1개 깨짐 → 고친 뒤 0(코어 296 · claude 래퍼 282 · codex 7 파일).
- 사본 옮기기 전후 사전 항목 비교: 고치기 전 4개 빠짐 → 고친 뒤 0.

## 5. 원인

- 직접 원인: 셸 읽기의 큰따옴표 처리가 `$( )` · `${ }` · 역따옴표를 몰랐음. 표식 읽기는 줄 아무 데서나 표식 · 칸 이름을 찾았음.
- 근본 원인: 옮기기가 '지운 글이 여전히 맞는지'와 '옮기기 전 항목이 다 있는지'를 확인하지 않고 개수만 봤고, 쓰기 순서가 되돌릴 수 없게 짜여 있었음.

## 6. 해결과 검증

- 해결책과 고른 이유: (1) 셸 읽기를 '지금 어디 안에 있는가'를 따라가는 재귀 읽기로 바꿈(`_sh_scan`). 이스케이프된 공백 뒤 `#` 도 글로 봄. (2) 지운 글을 문법 검사(sh: `bash -n`, py: compile) — 원래는 통과하는데 지운 뒤 깨지면 그 파일은 건드리지 않고 `skipped` 로 보고. (3) 쓰기 전 코드 파일 · 사전 폴더 복사본을 만들고, 사전 쓰기 · 멈춤 때 되돌림. (4) 표식은 줄 맨 앞에서만, `예:` 뒤는 통째로 예시. (5) 잃는 항목 검사를 개수에서 '옮길 코드 파일에 있던 항목 하나하나'로 바꿈.
- 고치기 전후 값: 코어 사본 옮기기 — 문법 깨진 파일 1 → 0, 사전 항목 손실 4 → 0(436 → 436), 사전 쓰기 실패 시 남는 바뀐 파일 283 → 0.
- 부작용과 회귀 시험: test-comments-to-catalog T9(겹친 따옴표) · T10(문법 검사로 제외) · T11(복원, 커밋 안 한 편집 포함) · T12(예시 속 표식 · 잃는 항목 멈춤). 기존 T1–T8 그대로 통과. 문서(md)에서 나온 사전 항목은 옮기기와 무관해 비교에서 뺌.

## 7. 배운 것

- 다음에 같은 문제를 만나면 진단하는 법: 사본 전체를 옮긴 뒤 바뀐 파일마다 `bash -n` · `py_compile`, 그리고 옮기기 전후 사전 항목을 이름 단위로 비교함 — 개수 비교는 손실을 숨김.
- 다른 곳에도 쓸 수 있는 것: 남의 코드를 고쳐 쓰는 도구는 '쓰기 전 복사본 → 쓰기 → 검사 실패 시 복원'을 기본으로 둠. 설명 글 속 예시는 표식처럼 생겨도 글로 읽어야 함.
