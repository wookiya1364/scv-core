# 끝 보고 세 줄 + 근거 목록 — 비판적 사고 첫 판

## Summary

- 에이전트가 일을 다 끝낸 것처럼 포장해도 사람이 알아챌 장치가 없음(사용자, 2026-11-05). 계기는 Addy Osmani 의 글 "Critical thinking when agents do the work".
- 최상위 규칙 5조('확인한 것 · 추정 · 확인 못 한 것을 섞지 말라')는 이미 있지만 지키게 하는 검사가 없음(확인 — 코드 검색).
- 실제 기록으로 시험해 봄(확인 — 시험판 2판): 이 세션에서 시험을 바꾼 턴 9개 중 4개, 맥프로_slay 2개 중 1개가 고치기 전 실패를 보지 않았음. 세 줄이 있는 끝 보고는 0개.
- 중간 과정이 블랙박스가 되지 않게: 도구 기록은 호스트 원본에 다 남으므로(이 세션 도구 호출 1288개) 기계가 '실제로 한 일' 목록을 만들 수 있음. 학습 지식에서 나온 말만 흔적이 없음.

## Goals / Non-Goals

- **Goals**
  - 도구를 쓴 모든 턴의 끝 보고에 세 줄: 확인한 것 · 확인 못 한 것 · 제가 대신 정한 것. 짧은 턴은 '확인 범위' 한 줄.
  - 기계가 이번 턴 도구 기록으로 근거 목록(읽음 · 바꿈 · 실행 · 시험 · 찾아봄 + 결과)을 만들고, '확인한 것'이 그 목록을 짚는지 대조함.
  - 시험을 바꾼 턴은 그 시험이 실패하는 것을 먼저 봤는지 기계가 판정하고, 못 봤으면 '확인 못 한 것'에 밝히게 함.
  - 빠지면 종료 훅이 한 턴에 한 번 막음(기존 막기와 묶어서). 설정으로 끌 수 있음.
  - 실험으로 넣음 — 성공 · 중단 기준을 설치 전에 정해 둠(아래 Exit criteria).
- **Non-Goals**
  - 사람의 예상 한 줄 · 병합 전 확인 문제 · 새 눈 반박 검토(다음 판).
  - 세 줄 내용이 참인지 판정하는 일 — 모양과 근거 대조만 봄.
  - 사람이 세 줄을 읽게 강제하는 일(기계로 할 수 없음 — 실험 기준 ②로 잼).

## Approach Overview

- 규칙의 본문은 새 계약 한 곳(`core/contracts/finish-report.md`). 최상위 규칙 5조에 '제가 대신 정한 것'을 더하고 근거 문서를 그 계약으로 바꿈. 매 턴 훅은 안내 한 줄만 싣고 계약을 가리킴.
- 세 줄 이름은 설정 언어로(korean: 확인한 것 · 확인 못 한 것 · 제가 대신 정한 것 / english: Verified · Not verified · Decided for you). 굵은 주제 한 줄 아래 불릿 셋 — 글 모양 계약(writing.md)과 같은 모양.
- '확인한 것'은 근거 목록 항목의 쉬운 이름(도구 호출의 설명)으로 짚음 — 코드값을 답에 강제하지 않음(writing.md 4조).
- '없음'은 이유가 붙어야 인정('없음 — 바꾼 함수의 모든 갈래를 시험으로 돌림').
- 근거 목록: 알림 · 안내로 열린 턴은 앞 사람 턴에 묶음. 시험은 실제로 돌린 명령만(grep · sed 로 읽은 것 제외). 실패는 끝 코드 + 출력 표시(✖ · FAIL · not ok)로 판정. 뒤에서 돌린 시험은 알림의 끝 코드 · 출력 파일 읽기와 이음.
- 막기는 종료 훅의 기존 묶음 막기에 이유 하나로 더함(검사마다 한 턴에 한 번 — choices.md 7항).
- 근거 목록은 가림 필터를 거쳐 비공개 기록 폴더(scv/journal)에 턴마다 남김 — 사람이 결론까지의 길을 열어 볼 수 있게.
- 도구 종류는 입력 모양으로 가림(호스트 프로필 불필요) — 코어에 호스트 이름 · 도구 이름을 박지 않음.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  scv_turn_group,            // 원본 줄들 → 이번 턴 항목들(알림 턴은 앞 턴에 묶음)
  scv_evidence_build,        // 이번 턴 항목들 → 근거 목록(종류 · 쉬운 이름 · 결과)
  scv_evidence_test_first,   // 근거 목록 → 실패를 못 본 바꾼 시험 이름들
  scv_finish_needed,         // 근거 목록 → none | short | full
  scv_finish_scan,           // 끝 답 · 언어 → 세 줄(또는 한 줄)의 내용
  scv_finish_check,          // 세 줄 · 근거 목록 · 못 본 시험 → 빠진 것 목록
  scv_finish_note,           // 빠진 것 · 언어 → 교정 문구 한 줄
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `scv_turn_group` | 알림 · 안내 턴을 앞 사람 턴에 붙여 이번 턴을 묶음 | 원본 줄들 → 이번 턴 항목들 | 순수 |
| 2 | `scv_evidence_build` | 도구 호출을 읽음 · 바꿈 · 실행 · 시험 · 찾아봄과 결과로 바꿈 | 이번 턴 사건 줄들 → 근거 목록 | 순수 |
| 3 | `scv_evidence_test_first` | 바꾼 시험이 그 뒤 실패하는 실행을 봤는지 가림 | 근거 목록 → 못 본 시험 이름들 | 순수 |
| 4 | `scv_finish_needed` | 세 줄이 필요한 턴인지 가림 | 근거 목록 → none · short · full | 순수 |
| 5 | `scv_finish_scan` | 끝 답에서 세 줄 · 한 줄을 찾음 | 끝 답 · 언어 → 줄별 내용 | 순수 |
| 6 | `scv_finish_check` | 빠진 줄 · 이유 없는 '없음' · 근거 없는 '확인한 것' · 안 밝힌 시험을 찾음 | 줄 내용 · 근거 목록 · 못 본 시험 → 빠진 것 목록 | 순수 |
| 7 | `scv_finish_note` | 빠진 것을 짚는 교정 문구를 만듦 | 빠진 것 · 언어 → 한 줄 | 순수 |
| 8 | `scv_finish_rule_line` | 매 턴 안내 한 줄을 만듦 | 언어 → 한 줄 · 빈 값 | 순수 |
| 9 | `종료 훅` | 원본을 읽고, 묶음 막기에 이유를 더하고, 근거 목록 파일을 씀 | 훅 입력 → 막기 JSON · 기록 파일 | 부수효과 (입구/출구) |

- 부수효과 위치: 9번만 — 원본 읽기(입구), 막기 출력 · 근거 목록 파일 쓰기(출구). 매 턴 안내는 기존 매 턴 훅이 8번 결과를 실음.
- 재사용: 턴 경계 · 기계 글 판별(lib/turn-stream.sh · lib/lang-enforce.sh `scv_lang_drop_machine`), 묶음 막기 · 한 번 막기 기록(`scv_gates_reason` · `scv_gates_delivered`), 가림 필터(journal-append --redact-only).

## Guardrails

- 위 invariants 네 가지를 깨지 않음.
- 한 요구 한 곳(최상위 4조): 세 줄의 본문은 새 계약에만. 해결책 표의 '남는 한계'(rewrite-principle)는 그 추천의 한계, 세 줄은 이번 턴 일의 한계 — 계약에 둘의 관계를 적고 같은 내용을 두 번 쓰지 않게 함.
- 잠긴 help 답 모양 절은 고치지 않음. 'never adds a slot to look complete' 와의 관계는 새 계약이 선언함(최상위 해소 순서 2 · 4).
- '확인한 것'에 명령 · 경로를 강제하지 않음 — 쉬운 이름으로 짚음.
- 실패 먼저는 '못 봤으면 밝혀라'만 요구 — 실패를 보라고 강제하지 않음(시간 늘리기 · 느린 시험 문제 방지).
- 근거 목록 파일은 가림 필터를 거치고 비공개 기록 폴더에만, 심볼릭 링크면 쓰지 않음.
- 공개 저장소에 사용자 세션 원본을 넣지 않음 — 실제 기록 재현 시험은 이 컴퓨터에 사본이 있을 때만 돌고 없으면 건너뜀.
- 코어에 호스트 이름 · 도구 이름을 박지 않음(test-host-neutral). 맥 · 리눅스 같은 결과.
- 종료 훅이 늘어나는 시간: 큰 원본(40MB)에서 +1초 이하.

## Exit criteria

- 구현 완료:
  - All TESTS.md scenarios pass (실험 T18 제외)
  - 시험판 숫자 재현: 2026-11-05 기록 사본에서 실패 먼저 못 본 턴 이 세션 4/9 · 맥프로_slay 1/2
  - 언어 교정 수정(같은 브랜치 커밋 4bedc69)과 한 판으로 릴리스 — 코어 · 클로드 · 코덱스
- 실험 판정(릴리스 뒤, 긴 세션 3개 — 맥프로_slay 포함, 다른 세션도 됨):
  - 성공: ① '확인 못 한 것'에 구체 항목이 붙은 턴 50% 이상 ② 사람이 그 줄이나 근거 목록을 보고 더 확인 · 수정을 요청한 사례 3건 이상 ③ 막힘이 사람 턴의 20% 이하(세션 첫 5턴 제외) ④ 실패를 못 본 시험은 모두 밝혀짐
  - 중단: ②가 0건이거나 막힘이 30%를 넘으면 세 줄은 기본으로 끄고 근거 목록 · 실패 먼저만 남김
  - 결과는 이 계획의 기록과 결정 기록에 남김

## 예외처리 (Edge cases)

- 알림 · 안내로 열린 턴: 앞 사람 턴에 묶어 한 덩어리로 봄.
- 뒤에서 돌린 시험: 알림의 끝 코드 · 출력 파일 읽기와 이음. 다른 파일로 옮겨 읽으면 못 이음 — 막지 않고 밝히기만 요구.
- 파이프로 끝 코드가 0: 출력 표시(✖ · FAIL · not ok)로도 실패를 봄. `FAIL=0` 같은 요약은 실패가 아님.
- 짧은 턴(SCV 기록 · 질문만): '확인 범위' 한 줄이면 통과.
- 사용자가 이번 턴에 다른 언어를 요청: 줄 이름은 설정 언어로 두되, 내용은 사용자 요청 언어를 따름.
- 사람이 없는 하위 세션 · 다른 세션이 보낸 메시지로 열린 턴: 기존 종료 훅 규칙대로(사람 턴만 막음).
- 원본을 못 읽음 · 너무 큼: 막지 않음(이 기능 전과 같음) — 시간 상한을 넘으면 건너뜀.
- 코덱스 원본 모양: 판정이 돌지 않으면 끄고 한 줄로 밝힘.

## Suggested path

1. 계약 문서를 쓰고 최상위 5조 · 매 턴 안내를 맞춤 — `scv_finish_rule_line`
2. 턴 묶기와 근거 목록을 만듦(시험판 2판의 판정 그대로 옮김) — `scv_turn_group`, `scv_evidence_build`
3. 실패 먼저 판정을 만듦 — `scv_evidence_test_first`
4. 세 줄 찾기 · 대조 · 교정 문구를 만듦 — `scv_finish_needed`, `scv_finish_scan`, `scv_finish_check`, `scv_finish_note`
5. 종료 훅에 묶음 막기 이유로 붙이고 근거 목록 파일을 남김 — `종료 훅`
6. 코덱스 원본 모양에서 같은 판정이 도는지 확인하고, 안 되면 끄고 밝힘 — 코덱스에서 근거 목록이 만들어지는지 확인
7. 새 시험 · 기존 시험 · 실제 기록 재현 · 속도를 돌림 — TESTS.md 전부 실행
8. 릴리스 뒤 긴 세션 3개에서 실험 기준을 잼 — 성공 · 중단 판정과 기록

## 구현에서 달라진 점 (path delta)

- 도구 종류는 호스트 프로필의 도구 이름표가 아니라 **입력 모양**으로 가림(command → 실행, file_path + 고칠 글 → 바꿈 …). 코어에 도구 이름을 박지 않으면서 래퍼 쪽 바꿈이 필요 없음.
- 실패 먼저는 시험판의 '턴 단위'(처음 시험 파일을 바꾼 뒤 아무 시험이나 실패하면 봄)가 아니라 **파일 단위**로 판정함 — 교정 문구가 파일 이름을 짚기 때문. 한 번 실패를 본 파일은 다시 고쳐도 다시 요구하지 않음. 실제 기록 재현에서 이 세션은 시험판과 같음(10턴 중 4), 맥프로_slay 는 한 턴(턴 5)이 다름 — 그 턴의 art-files.test · map-layout.test 는 한 번도 실패를 보지 않았는데 시험판은 다른 시험의 실패 때문에 '봄'으로 셈.
- 묶어 막기 시험(T10)은 등록 검사 대신 언어 검사와 묶어 확인함 — 시험 저장소에서 등록 검사를 켜려면 등록 상태까지 꾸며야 해서.
- 다른 모양 원본(T17)은 '끄고 한 줄 출력' 대신 조용히 꺼짐 — 계약 문서에 그 사실을 적음.
- SCV_LANG 이 비어 있으면 매 턴 안내는 영어 한 줄로 나감(검사는 언어와 상관없이 돌기 때문).

## Risks / Open Questions

- 형식만 맞추기: 세 줄이 상투 문구가 될 수 있음(매 턴 안내되는 다시 쓴 요청 인용도 사람 턴 46개 중 7번 빠짐). 실험 기준 ①로 잼.
- 막힘 빈도는 추정(약 15%) — 세션 초반은 더 잦을 수 있음. 기준 ③으로 잼.
- 실패 먼저 오판: 뒤 실행 결과를 다른 파일에 저장해 읽으면 못 이음(시험판 2판 한계) — 막지 않고 밝히기만 요구하므로 피해는 한 줄.
- 코덱스는 도구 이름 · 원본 모양이 다름 — 6번에서 확인.
- 사람이 세 줄을 읽지 않으면 효과 없음 — 기계로 막을 수 없음, 기준 ②로 잼.
- 제가 대신 정한 것(고칠 수 있음): 실험 숫자(50% · 3건 · 20% · 30%) · 기간(긴 세션 3개), 폴더 이름, 실패 표시(✖ · FAIL · not ok), '짧은 턴'의 정의(SCV 기록 · 질문만 쓴 턴).
