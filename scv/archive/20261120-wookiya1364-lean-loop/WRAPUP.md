## 1. 문제

- 상황: SCV 가 지켜야 할 두 가치(토큰 아끼기 · 사람은 처음과 끝만)를 사용자가 정했다(2026-11-20).
- 기대: 장부는 보이지 않게 처리되고, 사람은 요구 전달과 마지막 검증만 한다.
- 실제: 긴 실제 세션 168 사람 턴에 SCV 장부 도구 호출 759(턴당 4.5), 종료 막힘 37, 중간 선택 질문 161(개요 승인 24 · 이대로 계속 18 · 보관 2 · 중간 결정 117). 이 세션은 장부 호출 턴당 7.8.
- 재현 조건: 아무 세션에서나 사람 턴마다 help 부르기 · 등록 · 기록 · 표시 도구 호출이 생김.

## 2. 관찰

- 관찰한 사실과 측정값: 턴당 API 호출 20–22, 그중 장부 4.5–8.9. 응답 하나가 평균 약 53만 토큰을 읽음(긴 세션 3,748 응답 · 1,986M). 응답 단위로 다시 잼(2026-11-20): 장부만 한 응답이 사람 턴당 2.9–4.2번, 그 응답들이 읽은 입력이 전체의 13–22%(긴 세션 256M/1,995M · 이전 세션 160M/717M · 이 세션 97M/582M), 출력의 7–15%.
- 정상일 때와 차이: 장부를 훅이 하면 같은 기록이 모델 호출 없이 남는다 — 지금은 매번 모델이 도구로 한다.

## 3. 가설

- H1: 장부 호출을 훅으로 옮기고 중간 질문을 줄여도 같은 결과(시험 통과 · 답 모양)가 나온다.

## 4. 실험

- 방법과 같게 둔 것: (가) 기록 재계산 — 같은 실제 세션 기록 3개(긴 실제 세션 2 · 이 세션)에서 장부만 한 응답 중 훅이 대신하게 된 도구(help 부르기 · 등록 · 표시 · 대화 기록 · 규약 읽기)만 쓴 응답을 뺌. (나) 헤드리스 비교 — 같은 두 턴 과제(덧셈 버그 고치기 → 곱셈 더하기, 시험 test.sh), 같은 모델 · 같은 래퍼 사본(이 브랜치 코어), 설정 SCV_LEAN_LOOP 만 off/on.
- 결과와 가설별 판정: H1 지지(장난감 과제 기준). (가) 사라지는 장부 응답 사람 턴당 2.4–3.2, 덜 읽는 입력 전체의 5–10%. 남는 장부는 대시보드 단계 보고 · 계획 기록 · 앱의 할 일 목록/마무리 상자. (나) off 2회: 장부 10–12 · 종료 막힘 4 · 읽은 입력 1.73M–3.29M · 출력 8.5–16.4K · 60–111초/턴. on 3회(고친 뒤): 장부 0 · 막힘 0 · 입력 0.25M–0.37M · 출력 1.8–2.8K · 17–27초/턴. 두 모드 모두 시험 통과 · 두 턴 모두 답 맨 위 인용.

## 5. 원인

- 직접 원인과 일어난 길: 매 턴 지시가 모델에게 help 부르기 · 등록 명령 · 규약 읽기 · 대화 기록을 도구로 시키고, 도구 호출 하나마다 맥락 전체를 다시 읽음. 계획 기록이 없으면 종료가 막혀 답을 다시 씀.
- 근본 원인: 장부의 확인을 '모델이 직접 했다'로 정의함 — 훅이 할 수 있는 기록도 모델 호출로 했다.

## 6. 해결과 검증

- 해결책과 고른 이유: SCV_LEAN_LOOP=on(기본 off) — 사람 턴 훅이 help 몫(진단 · 규약 전문 한 번 · 읽음 표시 · 안전장치 표시 · 자리표시 등록)을 하고, 종료 훅이 답 맨 위 인용을 등록으로 적고 지문 되새김을 끄며, 계획 기록 검사는 막지 않고 기록 · 계획 이력만 남김. SCV_ASK_MODE=ends(기본 all) — 처음 · 끝 · 되돌릴 수 없는 일만 묻는 안내 줄. 인용 · 언어처럼 바로 고칠 수 있는 어김은 그대로 막음.
- 고치기 전후 값: 4번 (나)의 값. 비교 중 찾은 결함: help 를 안 부르니 쓰기 전 안전장치(이 세션에서 SCV 액션이 돌았나)가 첫 쓰기를 막음(on 2회차 시험 실패) → 훅이 같은 표시를 남기게 고친 뒤 3회 모두 통과.
- 부작용과 회귀 시험: 기본값 훅 출력이 바뀌기 전 코어와 바이트 같음(복사본의 버전 파일 없음 경고 한 줄만 다름). test-lean-loop T1–T6 · T2b, 관련 시험 19개(선택 · 실물 · help 먼저 · 안전장치 · 언어 · 등록 · 턴 검사 · 호스트 중립 등) 통과(맥). 리눅스 · 코덱스 사본 · 전체 실행은 6단계.

## 7. 배운 것

- 다음에 같은 문제를 만나면 진단하는 법: 응답 단위로 '도구가 모두 장부인 응답'을 세고 그 응답이 읽은 입력 토큰을 더한다 — 호출 수보다 읽은 입력이 비용이다.
- 다른 곳에도 쓸 수 있는 것: 모델이 한 일의 증거가 답에 있으면(인용) 훅이 그 답에서 기록을 만든다 — 기록용 도구 호출을 없애는 일반 방법. help 를 빼면 help 가 남기던 다른 표시(안전장치 영수증)도 함께 옮겨야 한다.
