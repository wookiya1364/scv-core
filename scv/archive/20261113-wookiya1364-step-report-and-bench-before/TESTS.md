# Test Plan — 단계 보고가 턴 끝 검사에 안 잡히던 것 · 재는 검사가 옆 파일에 기대는 함수를 빼던 것

## Overview

두 가지를 본다. 첫째, 단계 보고 도구를 이번 턴에 실제로 불렀으면 도구 앞 훅의 표시가 없어도 턴 끝 검사가 통과시키고, 부르지 않았거나 앞 턴에만 불렀으면 지금처럼 막는다. 둘째, 재는 검사가 같은 폴더의 다른 파일에 기대는 함수를 빼지 않고 앞뒤를 견준다. 시험은 임시 폴더에 가짜 프로젝트 · 가짜 대화 기록 · 가짜 저장소를 만들어 실제 명령을 돌린다. 도구 이름은 지어낸 것(`tool_step`)을 쓴다.

## Test scenarios

### T1. 표시 없이 대화 기록에 이번 턴의 호출이 있으면 통과한다

- **Setup**: 대시보드가 켜진 가짜 프로젝트, 구현 중인 계획 하나, 파일을 바꾸고 계획 기록을 남긴 턴. 도구 앞 훅의 표시는 없다. 대화 기록에 턴 시작 뒤 시각의 "어시스턴트가 `tool_step` 을 부른 줄" 하나
- **Run**: 턴 끝 검사(`turn-check.sh end`)에 대화 기록 파일을 넘긴다
- **Expected**: 통과
- **Pass criterion**: 출력 `TURN_PLAN: pass` · 고치기 전 코드에서는 같은 입력에 `TURN_PLAN: block`

### T2. 부르지 않은 턴은 지금처럼 막힌다

- **Setup**: T1 과 같되 대화 기록에 그 도구의 호출이 없다
- **Run**: 턴 끝 검사
- **Expected**: 막음. 이유에 단계 보고 도구의 이름
- **Pass criterion**: `TURN_PLAN: block` · 이유 줄에 `tool_step`

### T3. 앞 턴의 호출은 세지 않는다

- **Setup**: T1 과 같되 대화 기록의 호출 줄 시각이 턴 시작보다 앞이다
- **Run**: 턴 끝 검사
- **Expected**: 막음
- **Pass criterion**: `TURN_PLAN: block`

### T4. 이름이 글에 나온 것만으로는 세지 않는다

- **Setup**: 대화 기록에 그 도구 이름이 든 줄 셋 — 사람 쪽 안내 글 · 도구 목록 · 어시스턴트의 글(도구 호출 칸이 아님). 모두 턴 시작 뒤 시각
- **Run**: 턴 끝 검사
- **Expected**: 막음
- **Pass criterion**: `TURN_PLAN: block`

### T5. 도중에 온 말로 이어진 턴은 처음 시각부터 센다

- **Setup**: 턴 시작 → 그 뒤 시각의 호출 줄 → 사람의 말이 한 번 더 와서 턴이 이어짐(턴 시작 명령을 한 번 더)
- **Run**: 턴 끝 검사
- **Expected**: 통과 — 이어진 턴의 앞부분에 한 호출도 이번 턴의 것이다
- **Pass criterion**: `TURN_PLAN: pass` · 턴 폴더의 시작 시각 파일이 두 번째 시작 뒤에도 같은 값

### T6. 훅의 표시가 있으면 대화 기록을 읽지 않는다

- **Setup**: 표시 한 줄이 있는 턴. 대화 기록 자리에는 읽으면 실패가 드러나는 것(없는 파일)을 넘긴다
- **Run**: 턴 끝 검사
- **Expected**: 통과. 오류 출력 없음
- **Pass criterion**: `TURN_PLAN: pass` · 표준 오류 0줄

### T7. 대화 기록을 읽을 수 없어도 지금과 같은 판정을 낸다

- **Setup**: 표시 없는 턴에 (가) 없는 파일 (나) 빈 파일 (다) JSON 이 아닌 줄만 든 파일 (라) 대화 기록을 넘기지 않음
- **Run**: 넷 각각 턴 끝 검사
- **Expected**: 넷 다 막음(지금과 같음), 종료 코드 0, 오류 출력 없음
- **Pass criterion**: 4 / 4 `TURN_PLAN: block` · 종료 코드 0

### T8. 세는 함수의 답

- **Setup**: 줄 글을 직접 준다 — 호출 줄 2(시작 뒤) · 호출 줄 1(시작 앞) · 다른 도구 호출 1 · 이름만 든 글 1 · 깨진 줄 1
- **Run**: `scv_tc_step_calls <줄들> tool_step <시작 시각>`
- **Expected**: 2
- **Pass criterion**: 출력 `2` · 빈 입력은 `0` · 시작 시각이 비면 `0`

### T9. 막을 일이 없는 턴은 느려지지 않는다

- **Setup**: 단계 보고가 필요 없는 턴(대시보드 꺼짐)과 큰 대화 기록(수십 MB)
- **Run**: 턴 끝 검사를 대화 기록과 함께 · 없이 각각 여러 번
- **Expected**: 두 시간의 차이가 잡음 안이다 — 대화 기록을 열지 않기 때문이다
- **Pass criterion**: 대화 기록을 넘긴 쪽 ≤ 안 넘긴 쪽 × 1.5 + 0.2초 · 막을 참인 턴(기록을 읽는 턴)은 1초 안

### T10. 끝 훅이 대화 기록 자리를 넘긴다

- **Setup**: 끝 훅 틀 파일
- **Run**: 훅에 대화 기록 자리가 든 입력을 주고, 표시 없이 호출 줄만 있는 턴에서 돌린다
- **Expected**: 막는 답(JSON)이 나오지 않는다. 호출 줄이 없으면 막는 답이 나온다
- **Pass criterion**: 호출 있음 → 막는 답 0건 · 호출 없음 → 막는 답 1건(이유에 `tool_step`) · 틀 요약값 검사 종료 코드 0

### T11. 같은 폴더의 다른 파일에 기대는 함수를 견준다

- **Setup**: 가짜 저장소 — 한 폴더에 파일 둘. 파일 가의 함수가 파일 나의 함수를 부른다. 함수 사전에 둘 다 있다. 파일 가를 답이 같게 고친다(커밋 하나 뒤 작업 폴더 변경)
- **Run**: 재는 검사 견주기(`pure-bench.sh compare --before-ref HEAD --only <가의 함수>`)
- **Expected**: 표의 판정이 "답이 달라 뺌"이 아니다. 앞 · 뒤 시간이 숫자로 나온다
- **Pass criterion**: 답이 달라 뺌 0 · 견준 함수 1 · 고치기 전 코드에서는 같은 입력에 답이 달라 뺌 1

### T12. 진짜로 답이 달라진 함수는 지금처럼 뺀다

- **Setup**: T11 의 저장소에서 파일 가의 함수를 다른 답을 내게 고친다
- **Run**: 재는 검사 견주기
- **Expected**: "답이 달라 뺌"
- **Pass criterion**: 답이 달라 뺌 1

### T13. 그 커밋에 없던 파일의 함수는 지금처럼 새 함수다

- **Setup**: T11 의 저장소에 새 파일과 새 함수를 더한다(사전에도)
- **Run**: 재는 검사 견주기
- **Expected**: "새 함수"
- **Pass criterion**: 새 함수 1 · 작업 폴더에 새로 생긴 파일 0개(임시 폴더에만 푼다)

### T14. 이 저장소의 겹침 검사 함수

- **Setup**: 이 저장소, 고친 뒤
- **Run**: `pure-bench.sh compare --before-ref v0.93.0 --only scv_tc_nongoal_hits`
- **Expected**: 판정이 "통과" 또는 "한도 넘음" 가운데 하나 — 잰 값이 나온다
- **Pass criterion**: 답이 달라 뺌 0 (고치기 전 1)

## How to run

```bash
bash core/tests/test-turn-plan-check.sh && bash core/tests/test-pure-bench-b.sh && bash core/scripts/check-purity.sh && LC_ALL=C bash core/scripts/pure-catalog.sh check
```

## Pass criteria

- T1 ~ T14 가 맥의 옛 셸(bash 3.2)과 새 셸(bash 5)에서 통과한다 — 시간을 보는 T9 는 컴퓨터가 한가할 때의 값으로 판정하고, 바쁠 때 넘으면 고치기 전 코드와 같은 조건에서 견준 값을 함께 적는다
- 순수 검사 · 함수 사전 검사 종료 코드 0 (C 언어 설정에서도 위반 0건)
- PR 을 올리기 전 전체 시험 한 번에서 실패 0, PR 의 검사(리눅스 · 맥) 전부 성공
