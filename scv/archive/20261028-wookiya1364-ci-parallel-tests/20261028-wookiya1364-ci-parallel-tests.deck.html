# CI 단축 — 시험을 여러 워커로 나눠 Contracts 3분 안에, 문서 · 버전 PR 은 무거운 시험 건너뛰기

## Summary

SCV Core CI 의 Contracts 작업은 우분투 13분 · 맥 15~16분이 든다 — 계약 시험 · 공유 회귀 · 집중 시험(64개)을 한 러너에서 차례로 돌리기 때문(확인, PR #363).
첫 시도(한 러너 안에서 동시에, PR #365 1차)는 우분투 664 → 349초 · 맥 719 → 588초에 그쳤다: 러너 하나의 CPU 를 나눠 써서 시험마다 느려졌고(맥 시험 시간 합 719 → 1397초), 10초 한도 속도 검사 하나가 부하로 실패했다(확인).
그래서 시험을 **여러 워커(별도 러너)**로 나눈다. 시험별 시간 기록으로 조각 합을 고르게 하고, 조각 안에서는 차례로 돌려 속도 검사가 흔들리지 않게 한다. 사용자 목표: Contracts 작업 전체 3분 이내(우분투 · 맥).
문서 · 버전만 바뀐 PR 은 무거운 시험을 건너뛴다.

## Goals / Non-Goals

- **Goals**
  - Contracts (ubuntu-latest) · Contracts (macos-latest) 가 PR 을 연 뒤 3분 안에 끝난다(조각 대기 포함).
  - 실패가 나면 어떤 시험이 실패했는지와 그 로그 전문이 그 조각 작업에 바로 보인다.
  - 문서(docs/) · VERSION · CHANGELOG 만 바뀐 PR 은 무거운 시험 없이 통과 보고.
  - codex 래퍼 CI 도 같은 도구(0.72.0 릴리스 체인에서 래퍼 쪽 연결).
- **Non-Goals**
  - 문서 검사(머리말 · 안내와 문서 일치 · 기획서 문서 회귀) 빼기 — 사용자 결정으로 유지.
  - 느린 시험 자체를 빠르게 고치기 — 따로(시간 표만 남긴다).
  - 시험 내용 · 시간 한도 값 바꾸기 — 예외 하나: 다시 쓴 요청 T7 의 다음 턴 상한 0.5 → 1.0초(사용자 결정 2026-10-28, 맥 러너가 혼자 돌아도 +0.64초).

## Approach Overview

- 시험 실행 도구(`core/tests/run-focused.sh`)가 시험 파일 묶음(코어 집중 시험 · 계약 시험 · 공유 회귀)을 받아 **조각 i/n** 만 돌린다. 조각 나누기는 시간 기록(`core/tests/timings.tsv`)을 보고 긴 것부터 가장 덜 찬 조각에 넣는다(기록 없는 시험은 기본값). 조각 안에서는 차례로(동시 1).
- 한 러너 안에서 동시에 돌리는 방식(--jobs)은 로컬용으로 남긴다. 시간 한도 시험은 '# scv-test: serial' 표시로 끝에 혼자.
- CI: 작은 'plan' 작업이 전체 시험 여부(문서 · 버전만 바뀐 PR 인지)를 정하고, 운영체제마다 조각 작업들(우분투 6 · 맥 9 — 맥 러너가 시험마다 약 2배 느려, 맥 전용 시간 기록 timings-macos.tsv)이 돌며, 결과를 모으는 작업이 지금 필수 검사 이름(Contracts (ubuntu-latest) · Contracts (macos-latest))으로 성공/실패를 보고한다.
- 문서 · 버전 판정은 바뀐 파일 목록만 보는 순수 함수 — README · core/ 아래 .md(실행되는 규약) · 워크플로는 문서로 치지 않는다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  list_tests,     // 시험 폴더들 + 덧붙일 파일 → 시험 파일 목록
  classify,       // 목록 + 각 파일 앞부분 → { 동시에, 혼자 }
  partition,      // 목록 + 시간 기록 + 조각 i/n → 이 조각이 돌릴 목록
  run_batch,      // 목록 + 동시 수 → 시험별 결과(종료 코드 · 초 · 로그 위치)
  summarize,      // 결과 → 표 줄들 + 실패 목록 + 최종 종료 코드
  report,         // 요약 → 화면 출력(실패 로그 전문 포함)
)
lane = ci_docs_only(바뀐 파일 목록)   // CI 'plan' 작업: 전체 시험을 돌릴지
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | list_tests | 시험 파일을 모은다 | 폴더들 · 파일 → 'path<TAB>표시' 줄 | 부수효과 (입구 — 폴더 읽기) |
| 2 | classify | 혼자 돌 시험과 동시에 돌 시험을 가른다 | 'path<TAB>표시' → 'parallel/serial<TAB>path' | 순수 |
| 3 | partition | 시간 기록으로 조각을 고르게 나눠 i 번째만 고른다 | 목록 + 'key<TAB>초' + i/n → 목록 | 순수 |
| 4 | run_batch | 고른 시험을 돌리고 결과를 남긴다 | 목록 + 동시 수 → 결과 줄들 | 부수효과 (시험 실행 · 로그 쓰기) |
| 5 | summarize | 결과를 표와 실패 목록으로 만든다 | 결과 줄들 → 표 · 실패 목록 · 합계 | 순수 |
| 6 | report | 표와 실패 로그를 찍고 종료 코드로 끝낸다 | 요약 → 화면 · 종료 코드 | 부수효과 (출구) |
| 7 | ci_docs_only | 바뀐 파일이 전부 문서 · 버전인지 본다 | 파일 목록 → yes/no | 순수 |
| 8 | ci_needs_macos | 맥 조각이 필요한지(코드가 바뀌었는지) 본다 | 파일 목록 → yes/no | 순수 |

- 부수효과 위치: 1 · 4 · 6 과 CI 의 git diff(파일 목록 얻기). 2 · 3 · 5 · 7 은 문자열만 받고 돌려준다.
- 재사용: 첫 시도의 실행 도구를 그대로 키운다. 조각 안은 동시 1 이라 시간 한도 시험이 흔들리지 않는다.

## Guardrails

- 병합에 필요한 검사 이름을 바꾸지 않는다 — 저장소 규칙(ruleset)은 건드리지 않는다.
- 시험 내용 · 시간 한도 값은 바꾸지 않는다(예외: T7 다음 턴 상한 0.5 → 1.0초, 사용자 결정). 동시에 돌려서 깨지는 시험은 "혼자" 표시로 옮기거나 조각 안에서 차례로 돌릴 뿐, 고치거나 지우지 않는다.
- 문서 · 버전 판정이 애매하면 전체 시험을 돈다(건너뛰기는 확실할 때만).
- 실패를 숨기지 않는다: 하나라도 실패하면 0 이 아닌 코드로 끝나고, 실패한 시험의 로그 전문을 보인다.
- 맥 · 리눅스 · bash 3.2 에서 같은 결과(GNU 전용 옵션 금지).
- `.github/scripts/test-ci-fast-lanes.sh` 가 요구하는 작업 규칙(자동 작업 6분 제한 등)을 어기지 않는다.
- 공개 저장소에 로컬 경로 · 세션 id 를 쓰지 않는다(개인정보 검사).

## Exit criteria

- All TESTS.md scenarios pass
- PR CI 에서 Contracts (ubuntu-latest) 가 3분 안에 보고된다 — 실측으로 확인, 두 번 이상.
- Contracts (macos-latest) 는 맥 동시 한도(5대, 실측) 안에서 처음(15~16분)보다 크게 줄어든다 — 사용자 결정(2026-10-28): 맥 3분은 다음 계획(훅 속도)으로 넘긴다.
- 시험 하나를 일부러 실패시킨 실행에서 Contracts 가 실패하고, 실패한 시험 이름과 로그가 그 조각 작업에 보인다.
- 문서 · 버전만 바뀐 PR 에서 무거운 시험 없이 통과 보고 — 이 계획 병합 뒤 첫 그런 PR(0.72.0 변경 기록 PR)에서 확인한다(이 PR 은 코드를 바꾸므로 여기서는 확인할 수 없다).

## Suggested path

1. 시험 실행 도구를 만든다 — `list_tests`, `classify`, `run_batch`, `summarize`, `report`
2. 도구의 시험(가짜 시험 폴더: 통과 · 실패 · 혼자 표시)을 만든다 — `classify`, `summarize`
3. 시간 한도가 빡빡한 시험에 "혼자" 표시를 붙인다 — 실측으로 고른 두 시험에 표시
4. 조각 나누기와 시간 기록을 더한다 — `partition`
5. 문서 · 버전 판정을 더한다 — `ci_docs_only`
6. 코어 CI 를 plan · 조각 · 모으는 작업으로 바꾼다 — 워크플로 재구성, 필수 검사 이름 그대로
7. 이 컴퓨터에서 코어 · codex 사본으로 모든 조각을 돌려 전부 통과 확인 — 로컬 확인
8. PR CI 두 번 + 일부러 실패 한 번 + 문서만 PR 한 번으로 시간과 보고를 확인 — CI 실측
9. 0.72.0 릴리스 체인에서 codex 래퍼 CI 의 코어 시험을 같은 도구로 바꾼다 — 래퍼 연결
10. 맥에서 느린 곳을 줄인다(사용자 요청으로 더함): 설정 불러오기를 jq 한 번으로, 진단의 같은 셈 한 번으로, README 검사의 되풀이 찾기 기억, 중복 시험 2곳 제거 — 결과는 옛 길과 바이트까지 같게
11. 코드가 안 바뀐 PR(.md · VERSION 만)은 맥 조각을 건너뛴다 — `ci_needs_macos`

## Risks / Open Questions

- 맥 러너는 동시에 쓸 수 있는 수에 한도가 있다(문서 기준 5, 미확인) — 조각을 늘려도 줄을 서고, 래퍼 저장소의 맥 작업과도 같은 한도를 나눠 쓸 수 있다(미확인).
- 맥 러너 속도 편차가 크다(같은 계약 시험 141초 · 249초, 확인) — 3분 목표가 맥에서 넘칠 수 있다. 넘치면 숫자로 보고한다.
- 동시에 돌리면 시험끼리 같은 임시 파일 · 홈 폴더를 쓸 수 있다 — 이 컴퓨터 실험에서는 부딪힘 없음(확인), 러너에서는 미확인.
- 속도 검사가 러너에서 더 흔들릴 수 있다 — "혼자" 표시로 막지만, 맥 러너 자체의 흔들림(#364 의 T7 실패)은 이 계획으로 없어지지 않는다.

# Test Plan — CI 단축 — 시험을 여러 워커로 나눠 Contracts 3분 안에, 문서 · 버전 PR 은 무거운 시험 건너뛰기

## Overview

시험 실행 도구가 (1) 시험을 동시에 돌려 시간을 줄이고, (2) 실패를 숨기지 않으며, (3) 속도 검사를 끝에 혼자 돌리는지 확인한다.
가짜 시험 폴더로 도구 자체를 시험하고, 실제 64개 시험과 PR CI 실행 기록으로 시간을 잰다.

## Test scenarios

### T1. 모두 통과하면 0 으로 끝난다

- **Setup**: 가짜 시험 폴더 — 통과하는 시험 3개.
- **Run**: 도구를 그 폴더에 돌린다.
- **Expected**: 시험마다 통과 줄 하나와 걸린 초, 마지막 줄에 통과 3 · 실패 0.
- **Pass criterion**: 종료 코드 0, 통과 줄 3개.

### T2. 하나라도 실패하면 실패로 끝나고 이름과 로그 전문이 보인다

- **Setup**: 통과 2개 + 실패 1개(고유한 문구를 찍고 1 로 끝남).
- **Run**: 도구를 돌린다.
- **Expected**: 실패한 시험 이름이 실패 목록에 있고, 그 시험이 찍은 고유 문구가 출력에 그대로 있다.
- **Pass criterion**: 종료 코드 0 이 아님, 실패 이름 · 고유 문구 모두 출력에 있음.

### T3. 혼자 표시가 붙은 시험은 다른 시험과 겹치지 않고 끝에 돈다

- **Setup**: 동시에 돌 시험 3개(각각 시작 · 끝 시각을 파일에 남김) + 혼자 표시 시험 1개(같은 방식).
- **Run**: 동시 수 3 으로 도구를 돌린다.
- **Expected**: 혼자 시험의 시작 시각이 다른 모든 시험의 끝 시각보다 늦다.
- **Pass criterion**: 겹침 0.

### T4. 동시에 돈다(차례로가 아니다)

- **Setup**: 각각 2초 쉬는 시험 4개.
- **Run**: 동시 수 4 로 도구를 돌린다.
- **Expected**: 전체가 8초보다 훨씬 짧다.
- **Pass criterion**: 전체 5초 미만.

### T5. 동시 수를 정할 수 있고, 1 이면 차례로 돈다

- **Setup**: T4 와 같은 폴더.
- **Run**: 동시 수 1 로 돌린다.
- **Expected**: 차례로 돌아 8초 이상.
- **Pass criterion**: 전체 8초 이상, 통과 4.

### T6. 가르기(classify)와 요약(summarize)은 순수하다

- **Setup**: 파일 이름 목록과 표시 줄 문자열, 결과 줄 문자열.
- **Run**: 두 함수를 같은 입력으로 두 번 부른다.
- **Expected**: 같은 출력, 파일 · 폴더를 만들지 않음.
- **Pass criterion**: 두 출력이 같고, 임시 폴더가 비어 있음.

### T7. bash 3.2 에서도 같다

- **Setup**: 시스템 bash(맥 /bin/bash 3.2).
- **Run**: T1 · T2 · T3 을 시스템 bash 로 돌린다.
- **Expected**: 같은 결과.
- **Pass criterion**: 세 시나리오 모두 통과.

### T8. 실제 시험 64개가 도구로 모두 통과한다(코어 · codex 사본)

- **Setup**: 이 저장소, 그리고 codex 도구로 만든 코어 사본(격리 폴더 이름 `core`).
- **Run**: 두 곳에서 도구로 집중 시험 전체를 돌린다.
- **Expected**: 실패 0. 시간 표가 찍힌다.
- **Pass criterion**: 두 곳 모두 실패 0.

### T9. PR CI 에서 Contracts (ubuntu-latest) 가 3분 안에, 맥은 동시 한도 안에서 크게 줄어든다

- **Setup**: 이 계획의 PR.
- **Run**: CI 를 두 번 이상 돌리고, 운영체제마다 첫 작업 시작부터 결과 작업 끝까지를 실행 기록에서 읽는다.
- **Expected**: 우분투 180초 이하. 맥은 처음(15~16분)보다 크게 짧다(맥 동시 한도 5대).
- **Pass criterion**: 두 실행 모두 통과 + 우분투 180초 이하 + 맥 처음의 절반 이하.

### T10. 일부러 실패시킨 CI 실행에서 실패가 보인다

- **Setup**: 실패하는 시험을 하나 넣은 임시 커밋(병합하지 않는 시험용 브랜치).
- **Run**: CI 를 돌린다.
- **Expected**: Contracts 작업 실패, 로그에 그 시험 이름과 출력.
- **Pass criterion**: 작업 실패 + 로그에 시험 이름.

### T11. 병합에 필요한 검사 이름이 그대로다

- **Setup**: 이 계획의 PR.
- **Run**: PR 검사 목록과 저장소 규칙의 필수 검사 목록을 비교한다.
- **Expected**: 이름이 모두 같다(Contracts (ubuntu-latest) · Contracts (macos-latest) · DeckUI · Deterministic release artifact · check).
- **Pass criterion**: 차이 0.

### T12. 조각 나누기는 고르고, 빠짐 · 겹침이 없다(순수)

- **Setup**: 시험 이름 10개와 시간 기록(한 개는 기록 없음).
- **Run**: 조각 수 3 으로 1/3 · 2/3 · 3/3 을 각각 고르고, 같은 입력으로 한 번 더.
- **Expected**: 세 조각을 합치면 원래 목록과 같다(빠짐 0 · 겹침 0). 가장 긴 시험은 혼자 한 조각에 간다. 같은 입력 → 같은 출력.
- **Pass criterion**: 합집합 = 원래 목록, 교집합 0, 두 번의 출력이 같음, 조각 합의 최대 − 최소 ≤ 가장 긴 시험.

### T13. 문서 · 버전 판정(순수)

- **Setup**: 바뀐 파일 목록 여러 벌.
- **Run**: 판정 함수에 넣는다.
- **Expected**: `VERSION`+`CHANGELOG.md` → yes, `docs/a.md` → yes, `README.md` → no(README 검사 대상), `core/protocols/help.md` → no(실행되는 규약), `.github/workflows/x.yml` → no, 빈 목록 → no(애매하면 전체).
- **Pass criterion**: 모든 경우가 기대와 같다.

### T14. 문서 · 버전만 바뀐 PR 에서 Contracts 두 개가 무거운 시험 없이 통과 보고

- **Setup**: docs/ 한 줄만 바꾼 시험용 PR(병합하지 않음).
- **Run**: CI 를 돌린다.
- **Expected**: 조각 작업이 건너뛰어지고, Contracts (ubuntu-latest) · Contracts (macos-latest) 는 통과.
- **Pass criterion**: 두 검사 통과 + 조각 작업 skipped.

- **Run**: 키마다 settings_get(옛 길)과 env_load(새 길)를 같은 껍데기에서 비교.
- **Expected**: 값이 모두 같고, 일반 파일의 비밀 키는 알리되 값은 찍지 않는다.
- **Pass criterion**: `core/tests/test-env-load.sh` 통과(bash 5 · 3.2).

### T16. 맥 조각이 필요한지 판정(순수)

- **Run**: ci_needs_macos 에 넣는다.

# CI 단축 — 시험을 여러 워커로 나눠 Contracts 3분 안에, 문서 · 버전 PR 은 무거운 시험 건너뛰기

## Summary

SCV Core CI 의 Contracts 작업은 우분투 13분 · 맥 15~16분이 든다 — 계약 시험 · 공유 회귀 · 집중 시험(64개)을 한 러너에서 차례로 돌리기 때문(확인, PR #363).
첫 시도(한 러너 안에서 동시에, PR #365 1차)는 우분투 664 → 349초 · 맥 719 → 588초에 그쳤다: 러너 하나의 CPU 를 나눠 써서 시험마다 느려졌고(맥 시험 시간 합 719 → 1397초), 10초 한도 속도 검사 하나가 부하로 실패했다(확인).
그래서 시험을 **여러 워커(별도 러너)**로 나눈다. 시험별 시간 기록으로 조각 합을 고르게 하고, 조각 안에서는 차례로 돌려 속도 검사가 흔들리지 않게 한다. 사용자 목표: Contracts 작업 전체 3분 이내(우분투 · 맥).
문서 · 버전만 바뀐 PR 은 무거운 시험을 건너뛴다.

## Goals / Non-Goals

- **Goals**
  - Contracts (ubuntu-latest) · Contracts (macos-latest) 가 PR 을 연 뒤 3분 안에 끝난다(조각 대기 포함).
  - 실패가 나면 어떤 시험이 실패했는지와 그 로그 전문이 그 조각 작업에 바로 보인다.
  - 문서(docs/) · VERSION · CHANGELOG 만 바뀐 PR 은 무거운 시험 없이 통과 보고.
  - codex 래퍼 CI 도 같은 도구(0.72.0 릴리스 체인에서 래퍼 쪽 연결).
- **Non-Goals**
  - 문서 검사(머리말 · 안내와 문서 일치 · 기획서 문서 회귀) 빼기 — 사용자 결정으로 유지.
  - 느린 시험 자체를 빠르게 고치기 — 따로(시간 표만 남긴다).
  - 시험 내용 · 시간 한도 값 바꾸기 — 예외 하나: 다시 쓴 요청 T7 의 다음 턴 상한 0.5 → 1.0초(사용자 결정 2026-10-28, 맥 러너가 혼자 돌아도 +0.64초).

## Approach Overview

- 시험 실행 도구(`core/tests/run-focused.sh`)가 시험 파일 묶음(코어 집중 시험 · 계약 시험 · 공유 회귀)을 받아 **조각 i/n** 만 돌린다. 조각 나누기는 시간 기록(`core/tests/timings.tsv`)을 보고 긴 것부터 가장 덜 찬 조각에 넣는다(기록 없는 시험은 기본값). 조각 안에서는 차례로(동시 1).
- 한 러너 안에서 동시에 돌리는 방식(--jobs)은 로컬용으로 남긴다. 시간 한도 시험은 '# scv-test: serial' 표시로 끝에 혼자.
- CI: 작은 'plan' 작업이 전체 시험 여부(문서 · 버전만 바뀐 PR 인지)를 정하고, 운영체제마다 조각 작업들(우분투 6 · 맥 9 — 맥 러너가 시험마다 약 2배 느려, 맥 전용 시간 기록 timings-macos.tsv)이 돌며, 결과를 모으는 작업이 지금 필수 검사 이름(Contracts (ubuntu-latest) · Contracts (macos-latest))으로 성공/실패를 보고한다.
- 문서 · 버전 판정은 바뀐 파일 목록만 보는 순수 함수 — README · core/ 아래 .md(실행되는 규약) · 워크플로는 문서로 치지 않는다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  list_tests,     // 시험 폴더들 + 덧붙일 파일 → 시험 파일 목록
  classify,       // 목록 + 각 파일 앞부분 → { 동시에, 혼자 }
  partition,      // 목록 + 시간 기록 + 조각 i/n → 이 조각이 돌릴 목록
  run_batch,      // 목록 + 동시 수 → 시험별 결과(종료 코드 · 초 · 로그 위치)
  summarize,      // 결과 → 표 줄들 + 실패 목록 + 최종 종료 코드
  report,         // 요약 → 화면 출력(실패 로그 전문 포함)
)
lane = ci_docs_only(바뀐 파일 목록)   // CI 'plan' 작업: 전체 시험을 돌릴지
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | list_tests | 시험 파일을 모은다 | 폴더들 · 파일 → 'path<TAB>표시' 줄 | 부수효과 (입구 — 폴더 읽기) |
| 2 | classify | 혼자 돌 시험과 동시에 돌 시험을 가른다 | 'path<TAB>표시' → 'parallel/serial<TAB>path' | 순수 |
| 3 | partition | 시간 기록으로 조각을 고르게 나눠 i 번째만 고른다 | 목록 + 'key<TAB>초' + i/n → 목록 | 순수 |
| 4 | run_batch | 고른 시험을 돌리고 결과를 남긴다 | 목록 + 동시 수 → 결과 줄들 | 부수효과 (시험 실행 · 로그 쓰기) |
| 5 | summarize | 결과를 표와 실패 목록으로 만든다 | 결과 줄들 → 표 · 실패 목록 · 합계 | 순수 |
| 6 | report | 표와 실패 로그를 찍고 종료 코드로 끝낸다 | 요약 → 화면 · 종료 코드 | 부수효과 (출구) |
| 7 | ci_docs_only | 바뀐 파일이 전부 문서 · 버전인지 본다 | 파일 목록 → yes/no | 순수 |
| 8 | ci_needs_macos | 맥 조각이 필요한지(코드가 바뀌었는지) 본다 | 파일 목록 → yes/no | 순수 |

- 부수효과 위치: 1 · 4 · 6 과 CI 의 git diff(파일 목록 얻기). 2 · 3 · 5 · 7 은 문자열만 받고 돌려준다.
- 재사용: 첫 시도의 실행 도구를 그대로 키운다. 조각 안은 동시 1 이라 시간 한도 시험이 흔들리지 않는다.

## Guardrails

- 병합에 필요한 검사 이름을 바꾸지 않는다 — 저장소 규칙(ruleset)은 건드리지 않는다.
- 시험 내용 · 시간 한도 값은 바꾸지 않는다(예외: T7 다음 턴 상한 0.5 → 1.0초, 사용자 결정). 동시에 돌려서 깨지는 시험은 "혼자" 표시로 옮기거나 조각 안에서 차례로 돌릴 뿐, 고치거나 지우지 않는다.
- 문서 · 버전 판정이 애매하면 전체 시험을 돈다(건너뛰기는 확실할 때만).
- 실패를 숨기지 않는다: 하나라도 실패하면 0 이 아닌 코드로 끝나고, 실패한 시험의 로그 전문을 보인다.

## Exit criteria

# Test Plan — CI 단축 — 시험을 여러 워커로 나눠 Contracts 3분 안에, 문서 · 버전 PR 은 무거운 시험 건너뛰기

## Overview

시험 실행 도구가 (1) 시험을 동시에 돌려 시간을 줄이고, (2) 실패를 숨기지 않으며, (3) 속도 검사를 끝에 혼자 돌리는지 확인한다.
가짜 시험 폴더로 도구 자체를 시험하고, 실제 64개 시험과 PR CI 실행 기록으로 시간을 잰다.

## Test scenarios

### T1. 모두 통과하면 0 으로 끝난다

- **Setup**: 가짜 시험 폴더 — 통과하는 시험 3개.
- **Run**: 도구를 그 폴더에 돌린다.
- **Expected**: 시험마다 통과 줄 하나와 걸린 초, 마지막 줄에 통과 3 · 실패 0.
- **Pass criterion**: 종료 코드 0, 통과 줄 3개.

### T2. 하나라도 실패하면 실패로 끝나고 이름과 로그 전문이 보인다

- **Setup**: 통과 2개 + 실패 1개(고유한 문구를 찍고 1 로 끝남).
- **Run**: 도구를 돌린다.
- **Expected**: 실패한 시험 이름이 실패 목록에 있고, 그 시험이 찍은 고유 문구가 출력에 그대로 있다.
- **Pass criterion**: 종료 코드 0 이 아님, 실패 이름 · 고유 문구 모두 출력에 있음.

### T3. 혼자 표시가 붙은 시험은 다른 시험과 겹치지 않고 끝에 돈다

- **Setup**: 동시에 돌 시험 3개(각각 시작 · 끝 시각을 파일에 남김) + 혼자 표시 시험 1개(같은 방식).
- **Run**: 동시 수 3 으로 도구를 돌린다.
- **Expected**: 혼자 시험의 시작 시각이 다른 모든 시험의 끝 시각보다 늦다.
- **Pass criterion**: 겹침 0.

### T4. 동시에 돈다(차례로가 아니다)

- **Setup**: 각각 2초 쉬는 시험 4개.
- **Run**: 동시 수 4 로 도구를 돌린다.
- **Expected**: 전체가 8초보다 훨씬 짧다.
- **Pass criterion**: 전체 5초 미만.

### T5. 동시 수를 정할 수 있고, 1 이면 차례로 돈다

- **Setup**: T4 와 같은 폴더.
- **Run**: 동시 수 1 로 돌린다.
- **Expected**: 차례로 돌아 8초 이상.
- **Pass criterion**: 전체 8초 이상, 통과 4.

### T6. 가르기(classify)와 요약(summarize)은 순수하다

- **Setup**: 파일 이름 목록과 표시 줄 문자열, 결과 줄 문자열.
- **Run**: 두 함수를 같은 입력으로 두 번 부른다.
- **Expected**: 같은 출력, 파일 · 폴더를 만들지 않음.
- **Pass criterion**: 두 출력이 같고, 임시 폴더가 비어 있음.

### T7. bash 3.2 에서도 같다

- **Setup**: 시스템 bash(맥 /bin/bash 3.2).
- **Run**: T1 · T2 · T3 을 시스템 bash 로 돌린다.
- **Expected**: 같은 결과.
- **Pass criterion**: 세 시나리오 모두 통과.

### T8. 실제 시험 64개가 도구로 모두 통과한다(코어 · codex 사본)

- **Setup**: 이 저장소, 그리고 codex 도구로 만든 코어 사본(격리 폴더 이름 `core`).
- **Run**: 두 곳에서 도구로 집중 시험 전체를 돌린다.
- **Expected**: 실패 0. 시간 표가 찍힌다.
- **Pass criterion**: 두 곳 모두 실패 0.

### T9. PR CI 에서 Contracts (ubuntu-latest) 가 3분 안에, 맥은 동시 한도 안에서 크게 줄어든다

- **Setup**: 이 계획의 PR.
- **Run**: CI 를 두 번 이상 돌리고, 운영체제마다 첫 작업 시작부터 결과 작업 끝까지를 실행 기록에서 읽는다.
- **Expected**: 우분투 180초 이하. 맥은 처음(15~16분)보다 크게 짧다(맥 동시 한도 5대).
- **Pass criterion**: 두 실행 모두 통과 + 우분투 180초 이하 + 맥 처음의 절반 이하.

### T10. 일부러 실패시킨 CI 실행에서 실패가 보인다

- **Setup**: 실패하는 시험을 하나 넣은 임시 커밋(병합하지 않는 시험용 브랜치).
- **Run**: CI 를 돌린다.
- **Expected**: Contracts 작업 실패, 로그에 그 시험 이름과 출력.
- **Pass criterion**: 작업 실패 + 로그에 시험 이름.

### T11. 병합에 필요한 검사 이름이 그대로다

- **Setup**: 이 계획의 PR.
- **Run**: PR 검사 목록과 저장소 규칙의 필수 검사 목록을 비교한다.
- **Expected**: 이름이 모두 같다(Contracts (ubuntu-latest) · Contracts (macos-latest) · DeckUI · Deterministic release artifact · check).
- **Pass criterion**: 차이 0.

### T12. 조각 나누기는 고르고, 빠짐 · 겹침이 없다(순수)

- **Setup**: 시험 이름 10개와 시간 기록(한 개는 기록 없음).
- **Run**: 조각 수 3 으로 1/3 · 2/3 · 3/3 을 각각 고르고, 같은 입력으로 한 번 더.
- **Expected**: 세 조각을 합치면 원래 목록과 같다(빠짐 0 · 겹침 0). 가장 긴 시험은 혼자 한 조각에 간다. 같은 입력 → 같은 출력.
- **Pass criterion**: 합집합 = 원래 목록, 교집합 0, 두 번의 출력이 같음, 조각 합의 최대 − 최소 ≤ 가장 긴 시험.

### T13. 문서 · 버전 판정(순수)

- **Setup**: 바뀐 파일 목록 여러 벌.
- **Run**: 판정 함수에 넣는다.
- **Expected**: `VERSION`+`CHANGELOG.md` → yes, `docs/a.md` → yes, `README.md` → no(README 검사 대상), `core/protocols/help.md` → no(실행되는 규약), `.github/workflows/x.yml` → no, 빈 목록 → no(애매하면 전체).
- **Pass criterion**: 모든 경우가 기대와 같다.

### T14. 문서 · 버전만 바뀐 PR 에서 Contracts 두 개가 무거운 시험 없이 통과 보고

- **Setup**: docs/ 한 줄만 바꾼 시험용 PR(병합하지 않음).
- **Run**: CI 를 돌린다.
- **Expected**: 조각 작업이 건너뛰어지고, Contracts (ubuntu-latest) · Contracts (macos-latest) 는 통과.
- **Pass criterion**: 두 검사 통과 + 조각 작업 skipped.

### T15. 설정 불러오기는 한 번에 읽어도 값이 옛 길과 바이트까지 같다

- **Setup**: 공백 · $ · 따옴표 · 탭 · 줄바꿈 · 숫자 · true/false/null · 비밀 키 · 환경 우선이 섞인 설정 두 파일.
- **Run**: 키마다 settings_get(옛 길)과 env_load(새 길)를 같은 껍데기에서 비교.
- **Expected**: 값이 모두 같고, 일반 파일의 비밀 키는 알리되 값은 찍지 않는다.
- **Pass criterion**: `core/tests/test-env-load.sh` 통과(bash 5 · 3.2).

### T16. 맥 조각이 필요한지 판정(순수)

- **Setup**: 바뀐 파일 목록 여러 벌.
- **Run**: ci_needs_macos 에 넣는다.
- **Expected**: .md · VERSION 만 → no, .sh · 워크플로 · JSON 하나라도 → yes, 빈 목록 → yes.
