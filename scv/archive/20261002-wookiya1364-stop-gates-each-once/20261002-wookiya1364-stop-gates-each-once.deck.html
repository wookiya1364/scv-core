# 검사마다 한 턴에 한 번 — 선택지 검사가 다른 검사에 밀리지 않는다

## Summary

종료 훅의 세 검사(등록 · 원칙 · 선택지)는 지금 한 턴을 통틀어 한 번만 막는다. 그래서 등록 검사가 먼저 막은 턴에는
선택지 검사가 차례를 받지 못하고, 글로 된 결정 표가 화면에 그대로 남는다 — 2026-10-02 설치본 0.64.1 대화형 재현으로
확인했다. 검사마다 한 턴에 한 번씩 막을 수 있게 하고, 한 멈춤에서 여러 검사가 걸리면 이유를 한 번의 막기에 함께 싣는다.

## Goals / Non-Goals

- **Goals**
  - 다른 검사가 먼저 막은 턴에도, 끝 메시지가 글로 묻는 답이면 같은 턴 안에 선택지 이유가 한 번 전달된다.
  - 한 멈춤에서 여러 검사가 걸리면 그 이유를 모두 한 번의 막기에 싣는다(등록 → 원칙 → 선택지 순).
  - 원칙 검사(문제 표)도 같은 규칙을 따른다 — 등록 검사에 밀려 차례를 잃지 않는다(사용자 결정: 세 검사 모두).
  - 한 검사의 이유는 한 턴에 한 번만 전달한다 — 다른 검사의 막기에 함께 실린 것도 한 번으로 센다(사용자 결정: 센다).
    이미 전달한 검사가 또 걸리면 지금처럼 다음 턴 경고로 넘긴다.
- **Non-Goals**
  - 글 질문 · 문제 표 · 등록을 알아보는 판정 기준 변경.
  - 매 턴 훅의 안내 문구, 호스트 설정(선택지 도구 이름 · 사람 없는 실행 조건) 변경.
  - 다른 주제의 메모 두 건 — 훅 경로의 맥 기본 bash 점검, /clear 뒤 요약이 끝난 대화를 싣는 문제(다음 계획).

## Approach Overview

- **지금(확인)**: 세 판정 함수(`scv_mp_stop_gate` · `scv_mp_principle_gate` · `scv_choice_gate`)가 모두 같은
  "이미 계속 중"(훅 입력의 `stop_hook_active`) 값을 받아, 계속 중이면 warn 을 낸다. 종료 훅(`core/template/hooks/on-stop.sh`
  189~214줄)은 등록 검사가 막으면 끝 메시지를 읽지 않아 나머지 둘을 판정하지 않는다. → 막을 기회가 턴 전체에 하나뿐이다.
- **바꿈**: 판정 함수에 넣는 세 번째 값을 검사마다 "이 검사가 이번 턴에 이미 이유를 전달했나"로 바꾼다(함수 모양은
  그대로). 종료 훅은 끝 메시지를 늘 읽고 세 검사를 모두 판정해, block 인 검사들의 이유를 하나로 합쳐 낸다. 전달한 검사는
  이번 턴 표(매 턴 훅이 쓰는 턴 표시)와 함께 기록한다.
- **턴 표를 못 읽으면**(표 파일 없음 · 깨짐 · 턴 표를 쓰지 않는 호스트) 지금처럼 "이미 계속 중" 값으로 판단한다 — 막는
  쪽으로 실패하지 않는다.
- **상한**: 검사 셋이 각각 한 번이므로 한 턴에 최대 세 번 막힌다. 실제로는 대개 한두 번이다.
- 계약 문서(`core/contracts/choices.md` 7항, `core/contracts/rewrite-principle.md` 막기 문장, `docs/wrapper-integration.md`
  의 계속 중 설명)와 종료 훅 주석을 새 규칙으로 고친다.
- 릴리스: 코어 패치 → 두 래퍼 동기화 · 릴리스 → 설치본 화면 재현.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readStopInput,    // 훅 입력 · 턴 표 · 전달 기록 · 등록 파일 → 판정 재료
  judgeGates,       // 판정 재료 → 검사별 걸림 0|1 (등록 · 원칙 · 선택지)
  deliveredFlags,   // 턴 표 · 전달 기록 · 계속 중 → 검사별 이미 전달 0|1
  gateDecisions,    // 걸림 · 이미 전달 → 검사별 ok | block | warn
  composeReason,    // block 인 검사들의 이유 → 한 번의 막기 이유
  emitAndRecord,    // 결정 → 막기 출력 · 전달 기록 · 다음 턴 경고
)
```

## Guardrails

- 지킬 것 네 가지(frontmatter `invariants:`)를 단계마다 스스로 점검한다.
- 글 질문 · 문제 표 · 등록 판정 함수의 판정 결과를 바꾸지 않는다 — 기존 판정 픽스처가 고치지 않은 채로 통과해야 한다.
- 턴 표를 못 읽거나 전달 기록이 깨졌으면 지금 동작(계속 중이면 막지 않음)으로 돌아간다 — 막는 쪽으로 실패하지 않는다.
- 사람 없는 실행(`SCV_CHOICE_OFF_WHEN` 일치)과 스위치 off(`SCV_CHOICE_GATE=off` · `SCV_REWRITE_PRINCIPLE=off`)의 동작은 그대로다.
- 자동 알림 턴: 등록 검사는 지금처럼 판정하지 않고, 원칙 · 선택지는 새 규칙을 따른다.
- 종료 훅은 어떤 실패에도 exit 0 — 판정을 못 하면 막지 않는다(기존 계약).
- 종료 훅 시간: 이제 멈출 때마다 세 검사를 모두 보므로, 끝 메시지가 커도(10만 바이트) 맥 기본 bash 에서 지금 수준을
  크게 넘지 않는다.
- 코어 파일에 호스트 도구 이름을 적지 않는다(`core/tests/test-host-neutral.sh`).
- 매 턴 훅의 출력 크기와 문구는 바꾸지 않는다.

## Exit criteria

- TESTS.md 의 모든 자동 시나리오가 통과한다(맥 · 리눅스 CI, 맥 시스템 bash 3.2 포함).
- 오늘 재현한 순서(등록 없이 결정 표로 끝 → 등록한 뒤 같은 결정 표로 끝)를 자동 검사로 재생하면, 같은 턴 안에 선택지
  이유가 전달된다.
- 계약 문서와 종료 훅 주석이 새 규칙과 같다.
- 코어 패치 릴리스와 두 래퍼 릴리스가 끝나고, 설치본에서 오늘과 같은 화면 재현을 한 번 더 해 결과를 기록한다. 모델이
  그래도 글로 물으면 그 사실을 기록하고, 되풀이하지 않고 멈춰서 사용자에게 묻는다(사용자 결정).

## 예외 처리 (Edge cases)

- 이번 턴 표가 없거나 깨짐 → 지금 동작(계속 중이면 막지 않고 다음 턴 경고).
- 전달 기록이 다른 턴의 것 → 비어 있는 것으로 본다.
- 전달 기록 · 다음 턴 경고 자리가 심볼릭 링크 → 쓰지 않는다(지금 `.help-warn` 을 다루는 방식과 같음).
- 끝 메시지를 받지 못함(호스트가 주지 않음) → 원칙 · 선택지는 판정하지 않는다(지금과 같음).
- 자동 알림 턴 → 등록 검사는 건너뛰고, 원칙 · 선택지는 검사별 한 번.
- 사람 없는 실행 · 스위치 off → 지금과 같음.
- 종료 훅 안에서 무엇이 실패해도 → exit 0, 막지 않는다.
- (독립 검토 뒤 더함) 전달 기록을 쓰지 못함(읽기 전용 저널 · 심볼릭 링크) → 계속 중 멈춤은 다시 읽어 확인한 기록이 없으면 막지
  않고 다음 턴 경고 — 끝없이 막지 않는다.
- (독립 검토 뒤 더함) 턴 표가 그대로인 다음 턴(자동 알림 턴) → 턴의 첫 멈춤이 같은 세션의 지난 기록을 지운다.
- (독립 검토 뒤 더함) 한 저장소 · 두 세션 → 기록에 세션을 적고, 다른 세션의 기록이면 이 기능 전과 같다. 첫 멈춤은 다른 세션의
  기록을 지우지 않는다.
- (독립 검토 뒤 더함) 앞선 글을 못 보는 원본(코덱스 모양) → 계속 중 등록 검사는 이 기능 전과 같다.
- (재검토 뒤 더함) 첫 멈춤에서 막으면서 새 기록 쓰기만 실패 → 같은 세션의 지난 기록을 먼저 지웠으므로 다음 멈춤은 이 기능 전과
  같다. 지우기마저 실패하면(그때만 읽기 전용) 같은 검사가 한 번 더 막을 수 있다 — 상한 2, 끝없는 반복 없음.

## Risks / Open Questions

- 끝난 턴 표(자동 입력 판별의 근거)는 등록 검사가 막지 않을 때 쓰인다. 뒤의 검사가 막아 턴이 이어지는 경우는 0.64.0 부터
  있었지만 새 규칙에서 늘어난다 — 이어지는 동안 자동 알림이 오면 판별이 맞는지 확인한다.
- 이번 재현은 일부러 글로 쓰게 만든 상황이다. 모델이 스스로 글로 묻는 실수가 얼마나 잦은지는 모른다.
- 한 턴에 두세 번까지 막힐 수 있어 사용자가 기다리는 시간이 조금 늘 수 있다(상한 셋).
- 모델이 함께 실린 이유 중 하나만 고치고 다른 것을 놓칠 수 있다 — 이미 전달한 것으로 세므로 다음 턴 경고로 이어진다
  (사용자 결정 '센다').
- (재검토 뒤 고침) 호스트가 세션 id 를 주지 않으면 한 저장소의 두 세션을 가를 수 없어 한 검사가 여러 번 막혔다(재현 3번) —
  그런 호스트에서는 계속 중인 멈춤을 이 기능 전과 같게 둔다. 클로드 코드 · 코덱스는 세션 id 를 준다(T13 실측에서 기록으로 확인).
- (구현 중 확인) 종료 훅은 끝 메시지의 앞 64KB 만 본다(0.64.0 부터) — 64KB 를 넘는 답 끝의 질문은 선택지 판정에 들어가지
  않는다. 판정 입력을 바꾸는 일이라 이 계획 범위 밖이다 — 다음 계획 후보.

# Test Plan — 검사마다 한 턴에 한 번 — 선택지 검사가 다른 검사에 밀리지 않는다

## Overview

종료 훅의 세 검사(등록 · 원칙 · 선택지)가 검사마다 한 턴에 한 번씩 막을 수 있는지, 한 멈춤에서 걸린 이유를 함께 싣는지,
그러면서도 끝없이 반복하지 않고 기존 판정 · 꺼짐 조건 · 맥 기본 bash 동작을 그대로 지키는지 본다. 시나리오의 출발점은
2026-10-02 설치본 0.64.1 대화형 재현이다 — 등록 없이 결정 표로 끝난 답이 등록 이유로만 막히고, 등록 뒤 같은 결정 표가
화면에 남았다. 아래 "결정 표"는 그 재현에 쓴 답이다: "**정해 주실 것** (… 번호로 답하거나 …)" 줄, '# | 질문 | 내 추천' 표,
"이름과 제목이 정해지면 …" 안내 문단. 프로필은 중립 도구 이름(PickTool)과 요구 항목 데이터를 쓴다.

테스트 파일(`core/tests/test-choice-questions.sh`)의 구역 번호와의 대응: T35.1~T35.9 · T35.11 · T35.12 = T1~T9 · T11 · T12,
T35.0 = T14, T35.10 = T15, T35.13~T35.18 = T16~T21, T10 = 두 검사 파일 전체, T13 = 릴리스 뒤 설치본 실측.

## Test scenarios

### T1. 재현 순서 — 첫 멈춤에 두 이유가 함께

- **Setup**: 임시 scv 저장소, 선택지 도구 · 요구 항목이 있는 프로필, 매 턴 훅으로 이번 턴 표 생성. 등록하지 않음.
- **Run**: 끝 메시지 = 결정 표, 계속 중 아님(false)으로 종료 훅.
- **Expected**: `decision: block`. 이유에 `[SCV 프롬프트]` 와 `[SCV 선택지]` 가 모두 있고 이 순서다.
- **Pass criterion**: 한 번의 막기 이유에 두 꼬리표가 모두 있다. 0.64.1 에서는 `[SCV 선택지]` 가 없어 붉다.

### T2. 이어서 같은 결정 표 — 선택지 이유는 이미 전달됨

- **Setup**: T1 직후 같은 턴. 등록하고 다시 쓴 요청을 인용함.
- **Run**: 같은 결정 표로 끝, 계속 중(true)으로 종료 훅.
- **Expected**: 막지 않는다. `.help-warn` 에 `[SCV 가이드] 직전 턴: [SCV 선택지]` 줄이 하나 생긴다.
- **Pass criterion**: block 이 아니고 경고 한 줄이 있다(함께 실린 이유도 한 번으로 센다 — 사용자 결정).

### T3. 등록에만 막힌 뒤 이어 쓴 답이 글로 묻는다 — 같은 턴에 선택지로 막는다

- **Setup**: 등록하지 않음.
- **Run**: (1) 글 질문이 없는 끝 메시지, 계속 중 아님 → (2) 등록 · 인용을 갖추고 결정 표로 끝, 계속 중으로 종료 훅.
- **Expected**: (1) 이유는 `[SCV 프롬프트]` 뿐. (2) `decision: block`, 이유에 `[SCV 선택지]`.
- **Pass criterion**: (2)가 block 이다 — 이번 빈틈 그 자체. 0.64.1 에서는 막지 않아 붉다.

### T4. 원칙 검사도 같은 규칙

- **Setup**: 등록하지 않음.
- **Run**: (1) 문제 표가 없는 끝 메시지, 계속 중 아님 → (2) 등록 · 인용을 갖추고 '생길 수 있는 문제' 칸이 있는 표로 끝,
  계속 중으로 종료 훅.
- **Expected**: (2) `decision: block`, 이유에 `[SCV 원칙]`.
- **Pass criterion**: (2)가 block 이다. 0.64.1 에서는 막지 않아 붉다.

### T5. 상한 — 검사마다 한 번, 끝없는 반복 없음

- **Setup**: 등록하지 않음.
- **Run**: 같은 턴에 멈춤을 네 번 — (1) 등록만 걸림 → (2) 원칙만 걸림 → (3) 선택지만 걸림 → (4) 세 가지가 모두 걸림.
  (2)~(4)는 계속 중.
- **Expected**: (1)~(3)은 각자 block, (4)는 block 이 아니다(다음 턴 경고만).
- **Pass criterion**: 한 턴 block 이 최대 세 번이고, 같은 꼬리표가 두 번 전달되지 않는다.

### T6. 새 턴이면 다시 한 번씩

- **Setup**: T2 를 마친 저장소.
- **Run**: 매 턴 훅으로 새 턴 표를 만든 뒤 결정 표로 끝, 계속 중 아님으로 종료 훅.
- **Expected**: `decision: block`, 이유에 `[SCV 선택지]`.
- **Pass criterion**: 전달 기록이 턴마다 새로 시작한다.

### T7. 사람 없는 실행 · 스위치 off 는 그대로

- **Setup**: 세 가지 — (a) `SCV_CHOICE_OFF_WHEN` 이 일치하는 실행(중립 변수 이름), (b) `SCV_CHOICE_GATE=off`,
  (c) `SCV_REWRITE_PRINCIPLE=off`.
- **Run**: 각각 T3 · T4 순서.
- **Expected**: (a)(b) 선택지 이유로 막지 않고 선택지 경고도 남기지 않는다. (c) 원칙 이유로 막지 않는다.
- **Pass criterion**: 0.64.1 과 같은 출력 · 파일.

### T8. 턴 표를 못 읽으면 지금 동작

- **Setup**: 이번 턴 표 파일이 없거나 깨짐.
- **Run**: T3 (2)와 같은 입력, 계속 중.
- **Expected**: 막지 않고 다음 턴 경고를 남긴다(0.64.1 과 같음).
- **Pass criterion**: 막는 쪽으로 실패하지 않는다.

### T9. 자동 알림 턴

- **Setup**: 자동 태그가 붙은 프롬프트로 매 턴 훅을 돌려 자동 알림 턴을 만든다.
- **Run**: (1) 결정 표로 끝, 계속 중 아님 → (2) 같은 끝, 계속 중.
- **Expected**: 등록 이유는 어느 쪽에도 없다. (1) `[SCV 선택지]` block, (2) 경고만.
- **Pass criterion**: 자동 알림 턴에서도 검사별 한 번 규칙이 같다.

### T10. 판정 기준 불변

- **Setup**: 기존 판정 픽스처 — `core/tests/test-choice-questions.sh` 의 잡을 것 · 잡지 않을 것 사례(T1 · T2 · T31 · T34 등),
  `core/tests/test-model-prompting.sh` 의 문제 표 · 등록 · 인용 사례.
- **Run**: 두 검사 파일 전체.
- **Expected**: 판정 값이 0.64.1 과 같다.
- **Pass criterion**: 판정 픽스처를 고치지 않고 통과한다. 고친 것은 '한 번에 한 이유'를 확인하던 두 줄(T4 · T23)뿐이다 — 이
  계획이 일부러 바꾼 동작이고, 바뀐 이유를 PR 설명에 적는다. '계속 중이면 막지 않음' 검사는 고치지 않고 통과한다(같은 검사가
  이미 막은 뒤라 '이미 전달').

### T11. 맥 기본 bash 3.2 와 새 bash 에서 같은 결과

- **Run**: T1~T9 의 흐름(멈춤 15번 — 재현 순서 · 새 턴 · 상한 · 자동 알림 턴 · 턴 표 없음 · 사람 없는 실행)을 시스템 bash(3.2)와
  새 bash 로 각각 돌린다.
- **Expected**: 멈춤마다 훅 출력 · 전달 기록 · 다음 턴 경고가 같다(저장소마다 다른 턴 표만 TOK 로 바꿔 비교).
- **Pass criterion**: 두 bash 의 결과가 바이트로 같고, 꼬리표 순서가 기대한 15개와 같다.

### T12. 큰 끝 메시지 속도

- **Run**: 64KB 에 가까운 끝 메시지(종료 훅은 끝 메시지의 앞 64KB 만 본다 — 0.64.0 부터의 동작)로, 등록 없이 끝에 질문이 있어
  세 검사를 모두 판정하는 멈춤. 시스템 bash 3.2.
- **Expected**: 두 이유가 함께 실리고, 병적으로 느려지지 않는다. 실측(2026-10-02, 맥): 고치기 전 2.40초 → 고친 뒤 2.69초.
- **Pass criterion**: 두 이유 · 10초 안(예전 같은 꼴의 158초 같은 느려짐을 잡는 상한).

### T13. 설치본 화면 재현 (릴리스 뒤, 사람이 보는 세션)

- **Setup**: 새 래퍼를 설치한 뒤, 임시 저장소에서 tmux 대화형 세션을 띄운다(2026-10-02 재현과 같은 방법).
- **Run**: 결정 표를 답 끝에 그대로 붙이게 하는 요청을 보낸다.
- **Expected**: 그 턴의 막기 이유(대화 원본의 `hook_blocking_error`)에 `[SCV 선택지]` 가 실린다. 그 뒤 모델이 선택지 도구로
  다시 묻는지 기록한다. 글로 다시 물으면 그 사실을 기록하고 되풀이하지 않고 멈춰서 사용자에게 묻는다.
- **Pass criterion**: `[SCV 선택지]` 이유가 같은 턴에 전달된 기록이 있다.

### T14. 순수부 — 이미 전달 · 기록 · 지우기 · 이유 합치기 (독립 검토 뒤 더함)

  셋 · 부분 일치 · 새로 시작 · 이어 붙임 · 중복 · 지우기 넷 · 이유 둘).

  기록이 없으니 계속 중 멈춤은 막지 않는다 — 이 기능 전과 같다(구현 중 보수적으로 정함: 다른 훅이 이어 간 턴에서 근거 없이 막지

- **Expected**: 첫 멈춤만 막고 나머지는 막지 않는다 — 끝없이 막지 않는다.

### T17. 전달 기록 자리가 심볼릭 링크

- **Run**: 기록 자리를 다른 파일을 가리키는 링크로 바꾸고 계속 중 결정 표로 두 번 멈춘다.

# 검사마다 한 턴에 한 번 — 선택지 검사가 다른 검사에 밀리지 않는다

## Summary

종료 훅의 세 검사(등록 · 원칙 · 선택지)는 지금 한 턴을 통틀어 한 번만 막는다. 그래서 등록 검사가 먼저 막은 턴에는
선택지 검사가 차례를 받지 못하고, 글로 된 결정 표가 화면에 그대로 남는다 — 2026-10-02 설치본 0.64.1 대화형 재현으로
확인했다. 검사마다 한 턴에 한 번씩 막을 수 있게 하고, 한 멈춤에서 여러 검사가 걸리면 이유를 한 번의 막기에 함께 싣는다.

## Goals / Non-Goals

- **Goals**
  - 다른 검사가 먼저 막은 턴에도, 끝 메시지가 글로 묻는 답이면 같은 턴 안에 선택지 이유가 한 번 전달된다.
  - 한 멈춤에서 여러 검사가 걸리면 그 이유를 모두 한 번의 막기에 싣는다(등록 → 원칙 → 선택지 순).
  - 원칙 검사(문제 표)도 같은 규칙을 따른다 — 등록 검사에 밀려 차례를 잃지 않는다(사용자 결정: 세 검사 모두).
  - 한 검사의 이유는 한 턴에 한 번만 전달한다 — 다른 검사의 막기에 함께 실린 것도 한 번으로 센다(사용자 결정: 센다).
    이미 전달한 검사가 또 걸리면 지금처럼 다음 턴 경고로 넘긴다.
- **Non-Goals**
  - 글 질문 · 문제 표 · 등록을 알아보는 판정 기준 변경.
  - 매 턴 훅의 안내 문구, 호스트 설정(선택지 도구 이름 · 사람 없는 실행 조건) 변경.
  - 다른 주제의 메모 두 건 — 훅 경로의 맥 기본 bash 점검, /clear 뒤 요약이 끝난 대화를 싣는 문제(다음 계획).

## Approach Overview

- **지금(확인)**: 세 판정 함수(`scv_mp_stop_gate` · `scv_mp_principle_gate` · `scv_choice_gate`)가 모두 같은
  "이미 계속 중"(훅 입력의 `stop_hook_active`) 값을 받아, 계속 중이면 warn 을 낸다. 종료 훅(`core/template/hooks/on-stop.sh`
  189~214줄)은 등록 검사가 막으면 끝 메시지를 읽지 않아 나머지 둘을 판정하지 않는다. → 막을 기회가 턴 전체에 하나뿐이다.
- **바꿈**: 판정 함수에 넣는 세 번째 값을 검사마다 "이 검사가 이번 턴에 이미 이유를 전달했나"로 바꾼다(함수 모양은
  그대로). 종료 훅은 끝 메시지를 늘 읽고 세 검사를 모두 판정해, block 인 검사들의 이유를 하나로 합쳐 낸다. 전달한 검사는
  이번 턴 표(매 턴 훅이 쓰는 턴 표시)와 함께 기록한다.
- **턴 표를 못 읽으면**(표 파일 없음 · 깨짐 · 턴 표를 쓰지 않는 호스트) 지금처럼 "이미 계속 중" 값으로 판단한다 — 막는
  쪽으로 실패하지 않는다.
- **상한**: 검사 셋이 각각 한 번이므로 한 턴에 최대 세 번 막힌다. 실제로는 대개 한두 번이다.
- 계약 문서(`core/contracts/choices.md` 7항, `core/contracts/rewrite-principle.md` 막기 문장, `docs/wrapper-integration.md`
  의 계속 중 설명)와 종료 훅 주석을 새 규칙으로 고친다.
- 릴리스: 코어 패치 → 두 래퍼 동기화 · 릴리스 → 설치본 화면 재현.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readStopInput,    // 훅 입력 · 턴 표 · 전달 기록 · 등록 파일 → 판정 재료
  judgeGates,       // 판정 재료 → 검사별 걸림 0|1 (등록 · 원칙 · 선택지)
  deliveredFlags,   // 턴 표 · 전달 기록 · 계속 중 → 검사별 이미 전달 0|1
  gateDecisions,    // 걸림 · 이미 전달 → 검사별 ok | block | warn
  composeReason,    // block 인 검사들의 이유 → 한 번의 막기 이유
  emitAndRecord,    // 결정 → 막기 출력 · 전달 기록 · 다음 턴 경고
)
```

|---|---|---|---|---|
| 1 | readStopInput | 훅 입력 JSON · 저널 파일 → 끝 메시지 · 계속 중 · 턴 표 · 전달 기록 · 등록 상태 | 부수효과 (입구) | 변경 |
| 2 | judgeGates | 끝 메시지 · 등록 상태 · 스위치 · 도구 → 검사별 걸림 | 순수 (기존 판정 그대로) | 재사용 |
| 3 | deliveredFlags | 턴 표 · 전달 기록 · 계속 중 → 검사별 이미 전달 | 순수 (새 함수) | 추가 |
| 4 | gateDecisions | 걸림 · 이미 전달 → ok/block/warn | 순수 (기존 세 판정 함수 그대로) | 재사용 |
| 5 | composeReason | block 검사들의 이유 → 한 줄 | 순수 (새 함수) | 추가 |
| 6 | emitAndRecord | 결정 → 막기 JSON · 전달 기록 · `.help-warn` | 부수효과 (출구) | 변경 |

- 재사용: 세 판정 함수와 두 이유 함수(`scv_choice_reason` · `scv_mp_principle_reason`), 글 질문 판정(`scv_asks_in_text` ·
  `scv_answer_body`)과 문제 표 판정(`scv_mp_answer_has_problem_table`)은 그대로 쓴다.

## Guardrails

- 지킬 것 네 가지(frontmatter `invariants:`)를 단계마다 스스로 점검한다.
- 글 질문 · 문제 표 · 등록 판정 함수의 판정 결과를 바꾸지 않는다 — 기존 판정 픽스처가 고치지 않은 채로 통과해야 한다.
- 턴 표를 못 읽거나 전달 기록이 깨졌으면 지금 동작(계속 중이면 막지 않음)으로 돌아간다 — 막는 쪽으로 실패하지 않는다.
- 사람 없는 실행(`SCV_CHOICE_OFF_WHEN` 일치)과 스위치 off(`SCV_CHOICE_GATE=off` · `SCV_REWRITE_PRINCIPLE=off`)의 동작은 그대로다.
- 자동 알림 턴: 등록 검사는 지금처럼 판정하지 않고, 원칙 · 선택지는 새 규칙을 따른다.
- 종료 훅은 어떤 실패에도 exit 0 — 판정을 못 하면 막지 않는다(기존 계약).
- 종료 훅 시간: 이제 멈출 때마다 세 검사를 모두 보므로, 끝 메시지가 커도(10만 바이트) 맥 기본 bash 에서 지금 수준을
  크게 넘지 않는다.
- 코어 파일에 호스트 도구 이름을 적지 않는다(`core/tests/test-host-neutral.sh`).
- 매 턴 훅의 출력 크기와 문구는 바꾸지 않는다.

## Exit criteria

- TESTS.md 의 모든 자동 시나리오가 통과한다(맥 · 리눅스 CI, 맥 시스템 bash 3.2 포함).
- 오늘 재현한 순서(등록 없이 결정 표로 끝 → 등록한 뒤 같은 결정 표로 끝)를 자동 검사로 재생하면, 같은 턴 안에 선택지
  이유가 전달된다.
- 계약 문서와 종료 훅 주석이 새 규칙과 같다.
- 코어 패치 릴리스와 두 래퍼 릴리스가 끝나고, 설치본에서 오늘과 같은 화면 재현을 한 번 더 해 결과를 기록한다. 모델이
  그래도 글로 물으면 그 사실을 기록하고, 되풀이하지 않고 멈춰서 사용자에게 묻는다(사용자 결정).

## 예외 처리 (Edge cases)

- 이번 턴 표가 없거나 깨짐 → 지금 동작(계속 중이면 막지 않고 다음 턴 경고).
- 전달 기록이 다른 턴의 것 → 비어 있는 것으로 본다.
- 전달 기록 · 다음 턴 경고 자리가 심볼릭 링크 → 쓰지 않는다(지금 `.help-warn` 을 다루는 방식과 같음).
- 끝 메시지를 받지 못함(호스트가 주지 않음) → 원칙 · 선택지는 판정하지 않는다(지금과 같음).
- 자동 알림 턴 → 등록 검사는 건너뛰고, 원칙 · 선택지는 검사별 한 번.
- 사람 없는 실행 · 스위치 off → 지금과 같음.
- 종료 훅 안에서 무엇이 실패해도 → exit 0, 막지 않는다.
- (독립 검토 뒤 더함) 전달 기록을 쓰지 못함(읽기 전용 저널 · 심볼릭 링크) → 계속 중 멈춤은 다시 읽어 확인한 기록이 없으면 막지
  않고 다음 턴 경고 — 끝없이 막지 않는다.
- (독립 검토 뒤 더함) 턴 표가 그대로인 다음 턴(자동 알림 턴) → 턴의 첫 멈춤이 같은 세션의 지난 기록을 지운다.
- (독립 검토 뒤 더함) 한 저장소 · 두 세션 → 기록에 세션을 적고, 다른 세션의 기록이면 이 기능 전과 같다. 첫 멈춤은 다른 세션의
  기록을 지우지 않는다.
- (독립 검토 뒤 더함) 앞선 글을 못 보는 원본(코덱스 모양) → 계속 중 등록 검사는 이 기능 전과 같다.
- (재검토 뒤 더함) 첫 멈춤에서 막으면서 새 기록 쓰기만 실패 → 같은 세션의 지난 기록을 먼저 지웠으므로 다음 멈춤은 이 기능 전과
  같다. 지우기마저 실패하면(그때만 읽기 전용) 같은 검사가 한 번 더 막을 수 있다 — 상한 2, 끝없는 반복 없음.

# Test Plan — 검사마다 한 턴에 한 번 — 선택지 검사가 다른 검사에 밀리지 않는다

## Overview

종료 훅의 세 검사(등록 · 원칙 · 선택지)가 검사마다 한 턴에 한 번씩 막을 수 있는지, 한 멈춤에서 걸린 이유를 함께 싣는지,
그러면서도 끝없이 반복하지 않고 기존 판정 · 꺼짐 조건 · 맥 기본 bash 동작을 그대로 지키는지 본다. 시나리오의 출발점은
2026-10-02 설치본 0.64.1 대화형 재현이다 — 등록 없이 결정 표로 끝난 답이 등록 이유로만 막히고, 등록 뒤 같은 결정 표가
화면에 남았다. 아래 "결정 표"는 그 재현에 쓴 답이다: "**정해 주실 것** (… 번호로 답하거나 …)" 줄, '# | 질문 | 내 추천' 표,
"이름과 제목이 정해지면 …" 안내 문단. 프로필은 중립 도구 이름(PickTool)과 요구 항목 데이터를 쓴다.

테스트 파일(`core/tests/test-choice-questions.sh`)의 구역 번호와의 대응: T35.1~T35.9 · T35.11 · T35.12 = T1~T9 · T11 · T12,
T35.0 = T14, T35.10 = T15, T35.13~T35.18 = T16~T21, T10 = 두 검사 파일 전체, T13 = 릴리스 뒤 설치본 실측.

## Test scenarios

### T1. 재현 순서 — 첫 멈춤에 두 이유가 함께

- **Setup**: 임시 scv 저장소, 선택지 도구 · 요구 항목이 있는 프로필, 매 턴 훅으로 이번 턴 표 생성. 등록하지 않음.
- **Run**: 끝 메시지 = 결정 표, 계속 중 아님(false)으로 종료 훅.
- **Expected**: `decision: block`. 이유에 `[SCV 프롬프트]` 와 `[SCV 선택지]` 가 모두 있고 이 순서다.
- **Pass criterion**: 한 번의 막기 이유에 두 꼬리표가 모두 있다. 0.64.1 에서는 `[SCV 선택지]` 가 없어 붉다.

### T2. 이어서 같은 결정 표 — 선택지 이유는 이미 전달됨

- **Setup**: T1 직후 같은 턴. 등록하고 다시 쓴 요청을 인용함.
- **Run**: 같은 결정 표로 끝, 계속 중(true)으로 종료 훅.
- **Expected**: 막지 않는다. `.help-warn` 에 `[SCV 가이드] 직전 턴: [SCV 선택지]` 줄이 하나 생긴다.
- **Pass criterion**: block 이 아니고 경고 한 줄이 있다(함께 실린 이유도 한 번으로 센다 — 사용자 결정).

### T3. 등록에만 막힌 뒤 이어 쓴 답이 글로 묻는다 — 같은 턴에 선택지로 막는다

- **Setup**: 등록하지 않음.
- **Run**: (1) 글 질문이 없는 끝 메시지, 계속 중 아님 → (2) 등록 · 인용을 갖추고 결정 표로 끝, 계속 중으로 종료 훅.
- **Expected**: (1) 이유는 `[SCV 프롬프트]` 뿐. (2) `decision: block`, 이유에 `[SCV 선택지]`.
- **Pass criterion**: (2)가 block 이다 — 이번 빈틈 그 자체. 0.64.1 에서는 막지 않아 붉다.

### T4. 원칙 검사도 같은 규칙

- **Setup**: 등록하지 않음.
- **Run**: (1) 문제 표가 없는 끝 메시지, 계속 중 아님 → (2) 등록 · 인용을 갖추고 '생길 수 있는 문제' 칸이 있는 표로 끝,
  계속 중으로 종료 훅.
- **Expected**: (2) `decision: block`, 이유에 `[SCV 원칙]`.
- **Pass criterion**: (2)가 block 이다. 0.64.1 에서는 막지 않아 붉다.

### T5. 상한 — 검사마다 한 번, 끝없는 반복 없음

- **Setup**: 등록하지 않음.
- **Run**: 같은 턴에 멈춤을 네 번 — (1) 등록만 걸림 → (2) 원칙만 걸림 → (3) 선택지만 걸림 → (4) 세 가지가 모두 걸림.
  (2)~(4)는 계속 중.
- **Expected**: (1)~(3)은 각자 block, (4)는 block 이 아니다(다음 턴 경고만).
- **Pass criterion**: 한 턴 block 이 최대 세 번이고, 같은 꼬리표가 두 번 전달되지 않는다.

### T6. 새 턴이면 다시 한 번씩

- **Setup**: T2 를 마친 저장소.
- **Run**: 매 턴 훅으로 새 턴 표를 만든 뒤 결정 표로 끝, 계속 중 아님으로 종료 훅.
- **Expected**: `decision: block`, 이유에 `[SCV 선택지]`.
- **Pass criterion**: 전달 기록이 턴마다 새로 시작한다.

### T7. 사람 없는 실행 · 스위치 off 는 그대로

- **Setup**: 세 가지 — (a) `SCV_CHOICE_OFF_WHEN` 이 일치하는 실행(중립 변수 이름), (b) `SCV_CHOICE_GATE=off`,
  (c) `SCV_REWRITE_PRINCIPLE=off`.
- **Run**: 각각 T3 · T4 순서.
- **Expected**: (a)(b) 선택지 이유로 막지 않고 선택지 경고도 남기지 않는다. (c) 원칙 이유로 막지 않는다.
- **Pass criterion**: 0.64.1 과 같은 출력 · 파일.

### T8. 턴 표를 못 읽으면 지금 동작

- **Setup**: 이번 턴 표 파일이 없거나 깨짐.
- **Run**: T3 (2)와 같은 입력, 계속 중.
- **Expected**: 막지 않고 다음 턴 경고를 남긴다(0.64.1 과 같음).
- **Pass criterion**: 막는 쪽으로 실패하지 않는다.

### T9. 자동 알림 턴

- **Setup**: 자동 태그가 붙은 프롬프트로 매 턴 훅을 돌려 자동 알림 턴을 만든다.
- **Run**: (1) 결정 표로 끝, 계속 중 아님 → (2) 같은 끝, 계속 중.
- **Expected**: 등록 이유는 어느 쪽에도 없다. (1) `[SCV 선택지]` block, (2) 경고만.
- **Pass criterion**: 자동 알림 턴에서도 검사별 한 번 규칙이 같다.

### T10. 판정 기준 불변

- **Setup**: 기존 판정 픽스처 — `core/tests/test-choice-questions.sh` 의 잡을 것 · 잡지 않을 것 사례(T1 · T2 · T31 · T34 등),
  `core/tests/test-model-prompting.sh` 의 문제 표 · 등록 · 인용 사례.
- **Run**: 두 검사 파일 전체.
- **Expected**: 판정 값이 0.64.1 과 같다.
- **Pass criterion**: 판정 픽스처를 고치지 않고 통과한다. 고친 것은 '한 번에 한 이유'를 확인하던 두 줄(T4 · T23)뿐이다 — 이
  계획이 일부러 바꾼 동작이고, 바뀐 이유를 PR 설명에 적는다. '계속 중이면 막지 않음' 검사는 고치지 않고 통과한다(같은 검사가
  이미 막은 뒤라 '이미 전달').

### T11. 맥 기본 bash 3.2 와 새 bash 에서 같은 결과

- **Run**: T1~T9 의 흐름(멈춤 15번 — 재현 순서 · 새 턴 · 상한 · 자동 알림 턴 · 턴 표 없음 · 사람 없는 실행)을 시스템 bash(3.2)와
  새 bash 로 각각 돌린다.
- **Expected**: 멈춤마다 훅 출력 · 전달 기록 · 다음 턴 경고가 같다(저장소마다 다른 턴 표만 TOK 로 바꿔 비교).
- **Pass criterion**: 두 bash 의 결과가 바이트로 같고, 꼬리표 순서가 기대한 15개와 같다.

### T12. 큰 끝 메시지 속도

- **Run**: 64KB 에 가까운 끝 메시지(종료 훅은 끝 메시지의 앞 64KB 만 본다 — 0.64.0 부터의 동작)로, 등록 없이 끝에 질문이 있어
  세 검사를 모두 판정하는 멈춤. 시스템 bash 3.2.
- **Expected**: 두 이유가 함께 실리고, 병적으로 느려지지 않는다. 실측(2026-10-02, 맥): 고치기 전 2.40초 → 고친 뒤 2.69초.
- **Pass criterion**: 두 이유 · 10초 안(예전 같은 꼴의 158초 같은 느려짐을 잡는 상한).

### T13. 설치본 화면 재현 (릴리스 뒤, 사람이 보는 세션)

- **Setup**: 새 래퍼를 설치한 뒤, 임시 저장소에서 tmux 대화형 세션을 띄운다(2026-10-02 재현과 같은 방법).
- **Run**: 결정 표를 답 끝에 그대로 붙이게 하는 요청을 보낸다.
- **Expected**: 그 턴의 막기 이유(대화 원본의 `hook_blocking_error`)에 `[SCV 선택지]` 가 실린다. 그 뒤 모델이 선택지 도구로
  다시 묻는지 기록한다. 글로 다시 물으면 그 사실을 기록하고 되풀이하지 않고 멈춰서 사용자에게 묻는다.
- **Pass criterion**: `[SCV 선택지]` 이유가 같은 턴에 전달된 기록이 있다.

### T14. 순수부 — 이미 전달 · 기록 · 지우기 · 이유 합치기 (독립 검토 뒤 더함)

- **Run**: `lib/stop-gates.sh` 의 네 함수에 경계 입력 23개(첫 멈춤 · 턴 표 없음 · 기록 없음 · 다른 턴 표 · 다른 세션 · 깨진 기록
  셋 · 부분 일치 · 새로 시작 · 이어 붙임 · 중복 · 지우기 넷 · 이유 둘).
- **Pass criterion**: 23/23. 턴 표 비교를 지운 변이와 첫 멈춤 초기화를 지운 변이에서 붉다.

### T15. 턴 표가 그대로인 다음 턴 (자동 알림 턴 · 다른 훅이 먼저 이어 간 턴)

- **Run**: 사람 턴에서 선택지를 전달한 뒤 (a) 자동 알림 턴: 문제 표로 첫 멈춤 → 계속 중 결정 표 (b) 다음 자동 알림 턴: 걸리는 것
  없는 첫 멈춤 → 계속 중 결정 표(다른 훅이 이어 간 꼴).
- **Expected**: (a) 원칙 → 선택지 차례로 막음 — 지난 턴의 전달 기록을 잇지 않는다. (b) 첫 멈춤이 지난 기록을 지우고, 이번 턴
  기록이 없으니 계속 중 멈춤은 막지 않는다 — 이 기능 전과 같다(구현 중 보수적으로 정함: 다른 훅이 이어 간 턴에서 근거 없이 막지
  않는다).

### T16. 전달 기록을 쓰지 못함 (읽기 전용 저널)

- **Run**: 등록으로 첫 멈춤을 막은 뒤 저널을 읽기 전용으로 바꾸고, 계속 중 결정 표로 세 번 멈춘다(root 면 생략).
- **Expected**: 첫 멈춤만 막고 나머지는 막지 않는다 — 끝없이 막지 않는다.

### T17. 전달 기록 자리가 심볼릭 링크

- **Run**: 기록 자리를 다른 파일을 가리키는 링크로 바꾸고 계속 중 결정 표로 두 번 멈춘다.
- **Expected**: 링크 대상은 그대로, 막지 않고 다음 턴 경고.

### T18. 한 저장소 · 두 세션

- **Run**: (a) A 선택지 막힘 → B 원칙 막힘 → A 계속 중 같은 결정 표 (b) A 선택지 막힘 → B 걸리는 것 없는 첫 멈춤 → A 계속 중.
- **Expected**: 둘 다 A 의 마지막 멈춤은 막지 않는다 — 한 검사가 한 턴에 두 번 막지 않고, B 의 첫 멈춤은 A 의 기록을 지우지 않는다.

### T19. 코덱스 모양 원본 — 계속 중 등록 검사

- **Run**: 인용 + 문제 표로 끝난 첫 멈춤(원칙 막힘) → 인용 없이 표만 고친 답으로 계속 중 멈춤.
- **Expected**: 두 번째 멈춤을 등록 이유로 막지 않는다 — 앞선 인용을 볼 수 없는 원본에서는 이 기능 전과 같다.

### T20. 첫 멈춤에서 새 기록 쓰기만 실패 (재검토 뒤 더함)

- **Run**: 사람 턴에서 원칙을 전달한 뒤 자동 알림 턴(턴 표 그대로)의 첫 멈춤을 기록 쓰기가 실패하게(가짜 mktemp) 결정 표로
  멈추고, 이어서 계속 중 같은 결정 표로 멈춘다.
- **Expected**: 첫 멈춤은 선택지로 막고 지난 기록은 지워져 있다. 두 번째 멈춤은 막지 않는다 — 지우기를 쓰기 뒤로 되돌리면 붉다.

### T21. 세션 id 를 주지 않는 호스트 (재검토 뒤 더함)

- **Run**: 세션 id 없이 T3 순서(등록만 막힌 첫 멈춤 → 계속 중 결정 표).
- **Expected**: 두 번째 멈춤을 막지 않는다 — 이 기능 전과 같다(두 세션을 가를 수 없어 상한을 지킬 수 없으므로).
