# 기획서는 그림만 — 계획·테스트 문서를 본문에서 분리

## Summary

기획서를 만들면 계획서·구조 문서·테스트 문서가 한 덩어리로 붙어 스무 절이 나오는데,
그중 번호식 화면설계서는 한두 절뿐이고 나머지는 글 덩어리다. 본문을 **그림 문서만**으로
바꿔 "큰 그림, 적은 글"이 문서 전체의 성격이 되게 한다. 계획·테스트 원문은 사라지지 않고
사이드 패널 탭으로 계속 따라다닌다.

## Goals / Non-Goals

- **Goals**
  - 폴더를 넘겨 기획서를 만들 때 **본문은 구조 문서(그림 문서)만** 렌더한다.
  - 그림 문서가 없으면 **기획서를 만들지 않고** 그 사실을 한 줄로 알린다.
  - 예전처럼 셋을 전부 합치고 싶을 때를 위한 **되살리기 옵션**을 둔다.
  - 계획 문서를 본문에서 빼도 **린트 경고가 거짓으로 늘지 않게** 한다.
- **Non-Goals**
  - 번호식 화면설계서의 렌더링 규칙 자체는 손대지 않는다 (어제 만든 것 그대로).
  - 계획 작성 단계에서 각 절을 그림으로 바꾸는 일은 이번 범위가 아니다.
  - 단일 마크다운 파일 입력 경로는 건드리지 않는다 (합치기 자체가 없다).
  - 이미 만들어둔 기획서 HTML 을 일괄 재생성하지 않는다.

## Approach Overview

기획서를 만드는 파이프라인에서 **"무엇을 본문으로 삼을지 고르는 단계"** 하나를 새로
분리한다. 지금은 폴더를 읽어 세 파일을 무조건 이어 붙이는 한 덩어리 함수인데, 이를
**읽기 → 고르기 → 본문 만들기 → 린트** 네 단계로 쪼갠다.

- **읽기** — 폴더에 실제로 있는 파트를 목록으로 만든다. (지금과 동일)
- **고르기** — 새로 생기는 단계. 본문으로 쓸 파트와 원문 탭으로 쓸 파트를 나눈다.
  기본값은 본문 = 구조 문서 하나, 원문 탭 = 있는 파트 전부. 되살리기 옵션이 켜지면
  본문 = 있는 파트 전부(지금 동작).
- **본문 만들기** — 고른 파트만 이어 붙인다. 본문 파트가 하나뿐이면 구분선·라벨이
  필요 없다.
- **린트** — 지금은 본문 트리의 제목만 훑기 때문에 계획 문서를 빼면 비목표·성공지표·
  인수기준·예외처리·순수함수 경고가 전부 거짓으로 뜬다. 린트 입력을 **본문이 아니라
  읽어들인 파트 전체**로 바꾼다.

본문 파트가 하나도 없으면(구조 문서 없음, 되살리기 옵션 꺼짐) HTML 을 쓰지 않고
"만들 것 없음"을 알리는 한 줄로 끝낸다. 실패가 아니라 정상 종료다 — 호출부(계획 만들기·
구현 마무리)가 이걸 오류로 받아 멈추면 안 된다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readSlugParts,       // 폴더 경로 → 있는 파트 목록 [{파일명, 라벨, 원문}]
  selectRenderParts,   // (파트 목록, 옵션) → { 본문 파트[], 원문 탭 파트[] }
  composeBody,         // 본문 파트[] → 결합 마크다운 (없으면 빈 값)
  lintOverParts,       // (결합 마크다운, 파트 목록 전체) → 경고 목록
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | readSlugParts | 폴더 경로 → 파트 목록 | 부수효과 (입구 — 파일 읽기) |
| 2 | selectRenderParts | (파트 목록, 옵션) → 본문/원문 분리 | 순수 |
| 3 | composeBody | 본문 파트 → 결합 마크다운 | 순수 |
| 4 | lintOverParts | (본문, 파트 전체) → 경고 목록 | 순수 |
| 5 | writeDeck | (본문, 경고) → HTML 파일 | 부수효과 (출구 — 파일 쓰기) |

- 부수효과 위치: 1번(파일 읽기)과 5번(HTML 쓰기)뿐. 2~4번은 값만 다룬다.
- 재사용: 3번의 결합 규칙(첫 파트가 제목을 갖고, 나머지는 라벨 밑으로)은 지금 것을
  그대로 쓴다. 4번의 판정 규칙도 그대로고, **입력만** 본문에서 파트 전체로 바꾼다.

## Guardrails

- 이미 만들어둔 기획서 HTML 파일을 이 작업에서 다시 쓰거나 지우지 않는다.
- 원문 사이드 패널의 세 탭(계획·구조·테스트)은 그대로 둔다 — 본문에서 빠지는 것이지
  문서에서 사라지는 게 아니다.
- 번호식 화면설계서 렌더링(마커·설명 목록·상태 띠·검증 표)에 손대지 않는다.
- 단일 마크다운 파일 입력 경로는 건드리지 않는다.
- 기존 deck 계약(158건)과 번호식 계약을 하나도 약화시키지 않는다. 옛 계약이 새 계약과
  충돌하면 **약화가 아니라 대체**임을 근거로 밝히고 갱신한다.
- 린트의 판정 규칙 자체는 바꾸지 않는다. 바꾸는 건 무엇을 훑느냐(입력)뿐이다.

## Exit criteria

- TESTS.md 시나리오 전부 통과
- 어제 만든 계획 폴더로 기획서를 만들면 **그림 절만** 나온다 (구성도 2 + 화면 2)
- 그림 문서가 없는 폴더는 HTML 을 만들지 않고 이유 한 줄로 끝난다 — 오류 아님
- 되살리기 옵션을 주면 예전과 같은 전체 결합이 나온다
- 계획 문서를 본문에서 빼도 린트 경고 개수가 늘지 않는다
- 기존 아카이브의 기획서 HTML 파일이 이 작업으로 바뀌지 않는다

## Suggested path

1. 폴더 읽기 함수를 읽기·고르기·본문 만들기 세 단계로 쪼갠다 (동작은 그대로 유지).
2. 고르기 단계에 기본값(그림 문서만)과 되살리기 옵션을 넣는다.
3. 본문 파트가 없을 때 HTML 을 쓰지 않고 알림 한 줄로 끝나는 길을 만든다.
4. 린트 입력을 파트 전체로 바꾼다.
5. 되살리기 옵션을 실행 스크립트와 지침에 노출한다.
6. 호출부 세 곳(기획서 명령·계획 만들기·구현 마무리)이 "만들 것 없음"을 오류로 받지
   않는지 확인한다.

# Test Plan — 기획서는 그림만

## Overview

확인하려는 것은 하나다: **폴더로 기획서를 만들면 본문에 그림 문서만 남는가**, 그리고
그 대가로 잃으면 안 되는 것(원문 세 탭, 예전 기획서, 린트 정확도)이 그대로인가.
그림 문서가 없는 폴더에서 빈 문서가 나오지 않는 것도 같은 무게로 확인한다.

## Test scenarios

### T1. 폴더를 넘기면 본문은 그림 문서만이다

- **Setup**: 계획·구조·테스트 세 문서가 모두 있는 임시 슬러그 폴더. 계획 문서에만
  있는 고유 문구(예: `Exit criteria` 절의 문장)와 구조 문서에만 있는 고유 문구를
  각각 심어둔다.
- **Run**: 그 폴더로 기획서를 만든다 (원문 패널 없는 렌더로 — 원문 패널이 본문 대신
  잡히는 오검을 막는다).
- **Expected**: 본문에 구조 문서의 문구는 있고, 계획 문서·테스트 문서의 문구는 없다.
- **Pass criterion**: 렌더된 본문에서 계획 문서 고유 문구가 0회, 구조 문서 고유 문구가
  1회 이상.

### T2. 그림 문서가 없으면 기획서를 만들지 않는다

- **Setup**: 계획 문서와 테스트 문서만 있고 구조 문서가 없는 임시 슬러그 폴더.
- **Run**: 그 폴더로 기획서를 만든다.
- **Expected**: HTML 파일이 생기지 않는다. "만들 것 없음"과 그 이유가 출력에 한 줄로
  나온다. 종료 코드는 성공이다 (오류가 아니다).
- **Pass criterion**: 결과 HTML 경로가 존재하지 않고, 종료 코드 0, 출력에 사유 줄 1개.

### T3. 되살리기 옵션은 예전 전체 결합을 그대로 낸다

- **Setup**: T1 과 같은 폴더.
- **Run**: 되살리기 옵션을 주고 기획서를 만든다.
- **Expected**: 계획·구조·테스트 세 문서의 고유 문구가 모두 본문에 있다.
- **Pass criterion**: 세 문구 전부 1회 이상. 이 변경 이전 코드로 만든 기준선과 본문이
  같다.

### T4. 원문 사이드 패널은 세 탭을 그대로 유지한다

- **Setup**: T1 과 같은 폴더 (원문 패널을 켠 기본 렌더).
- **Run**: 기본값(그림만)으로 기획서를 만든다.
- **Expected**: 본문에서 빠진 계획 문서와 테스트 문서가 원문 패널 탭에는 그대로 있다.
- **Pass criterion**: 원문 패널에 세 파일 이름의 탭이 모두 있고, 각 탭의 원문이 파일
  내용과 일치한다.

### T5. 계획 문서를 본문에서 빼도 린트 경고가 늘지 않는다

- **Setup**: 비목표·성공지표·인수기준·예외처리·순수함수 절을 모두 갖춘 계획 문서 +
  그림이 있는 구조 문서.
- **Run**: 기본값(그림만)으로 만든 경우와, 되살리기 옵션으로 만든 경우의 경고 수를
  비교한다.
- **Expected**: 두 경우의 경고 개수와 내용이 같다.
- **Pass criterion**: 경고 개수가 동일하고, 위 다섯 항목에 대한 경고가 어느 쪽에서도
  뜨지 않는다.

### T6. 그림이 정말 없을 때의 경고는 그대로 뜬다

- **Setup**: 구조 문서는 있으나 그 안에 그림(구성도·화면)이 하나도 없는 폴더.
- **Run**: 기본값으로 기획서를 만든다.
- **Expected**: 문서는 만들어지고, 그림 없음 경고가 뜬다. T5 의 완화로 이 경고까지
  사라지면 안 된다.
- **Pass criterion**: HTML 이 생기고, 그림 없음 경고가 1건 있다.

### T7. 어제 만든 실제 계획으로 그림 절만 나온다

- **Setup**: `scv/archive/20260826-wookiya1364-numbered-spec-deck/` (실제 아카이브).
- **Run**: 기본값으로 기획서를 만든다 (임시 출력 경로로 — 아카이브 원본을 덮지 않는다).
- **Expected**: 구조 문서의 세 절만 나오고, 그림 넷(구성도 2 + 화면 2)이 모두 렌더된다.
  계획 문서의 열두 절은 본문에 없다.
- **Pass criterion**: 본문의 절 개수가 구조 문서의 절 개수와 같고, 번호식 마커가
  렌더된다.

### T8. 예전 기획서 파일은 이 작업으로 바뀌지 않는다

- **Setup**: 작업 전 아카이브의 기획서 HTML 파일들의 해시를 기록해둔다.
- **Run**: 이 변경을 적용한 뒤 테스트를 전부 돌린다.

# 기획서는 그림만 — 계획·테스트 문서를 본문에서 분리

## Summary

기획서를 만들면 계획서·구조 문서·테스트 문서가 한 덩어리로 붙어 스무 절이 나오는데,
그중 번호식 화면설계서는 한두 절뿐이고 나머지는 글 덩어리다. 본문을 **그림 문서만**으로
바꿔 "큰 그림, 적은 글"이 문서 전체의 성격이 되게 한다. 계획·테스트 원문은 사라지지 않고
사이드 패널 탭으로 계속 따라다닌다.

## Goals / Non-Goals

- **Goals**
  - 폴더를 넘겨 기획서를 만들 때 **본문은 구조 문서(그림 문서)만** 렌더한다.
  - 그림 문서가 없으면 **기획서를 만들지 않고** 그 사실을 한 줄로 알린다.
  - 예전처럼 셋을 전부 합치고 싶을 때를 위한 **되살리기 옵션**을 둔다.
  - 계획 문서를 본문에서 빼도 **린트 경고가 거짓으로 늘지 않게** 한다.
- **Non-Goals**
  - 번호식 화면설계서의 렌더링 규칙 자체는 손대지 않는다 (어제 만든 것 그대로).
  - 계획 작성 단계에서 각 절을 그림으로 바꾸는 일은 이번 범위가 아니다.
  - 단일 마크다운 파일 입력 경로는 건드리지 않는다 (합치기 자체가 없다).
  - 이미 만들어둔 기획서 HTML 을 일괄 재생성하지 않는다.

## Approach Overview

기획서를 만드는 파이프라인에서 **"무엇을 본문으로 삼을지 고르는 단계"** 하나를 새로
분리한다. 지금은 폴더를 읽어 세 파일을 무조건 이어 붙이는 한 덩어리 함수인데, 이를
**읽기 → 고르기 → 본문 만들기 → 린트** 네 단계로 쪼갠다.

- **읽기** — 폴더에 실제로 있는 파트를 목록으로 만든다. (지금과 동일)
- **고르기** — 새로 생기는 단계. 본문으로 쓸 파트와 원문 탭으로 쓸 파트를 나눈다.
  기본값은 본문 = 구조 문서 하나, 원문 탭 = 있는 파트 전부. 되살리기 옵션이 켜지면
  본문 = 있는 파트 전부(지금 동작).
- **본문 만들기** — 고른 파트만 이어 붙인다. 본문 파트가 하나뿐이면 구분선·라벨이
  필요 없다.
- **린트** — 지금은 본문 트리의 제목만 훑기 때문에 계획 문서를 빼면 비목표·성공지표·
  인수기준·예외처리·순수함수 경고가 전부 거짓으로 뜬다. 린트 입력을 **본문이 아니라
  읽어들인 파트 전체**로 바꾼다.

본문 파트가 하나도 없으면(구조 문서 없음, 되살리기 옵션 꺼짐) HTML 을 쓰지 않고
"만들 것 없음"을 알리는 한 줄로 끝낸다. 실패가 아니라 정상 종료다 — 호출부(계획 만들기·
구현 마무리)가 이걸 오류로 받아 멈추면 안 된다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readSlugParts,       // 폴더 경로 → 있는 파트 목록 [{파일명, 라벨, 원문}]
  selectRenderParts,   // (파트 목록, 옵션) → { 본문 파트[], 원문 탭 파트[] }
  composeBody,         // 본문 파트[] → 결합 마크다운 (없으면 빈 값)
  lintOverParts,       // (결합 마크다운, 파트 목록 전체) → 경고 목록
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | readSlugParts | 폴더 경로 → 파트 목록 | 부수효과 (입구 — 파일 읽기) |
| 2 | selectRenderParts | (파트 목록, 옵션) → 본문/원문 분리 | 순수 |
| 3 | composeBody | 본문 파트 → 결합 마크다운 | 순수 |
| 4 | lintOverParts | (본문, 파트 전체) → 경고 목록 | 순수 |
| 5 | writeDeck | (본문, 경고) → HTML 파일 | 부수효과 (출구 — 파일 쓰기) |

- 부수효과 위치: 1번(파일 읽기)과 5번(HTML 쓰기)뿐. 2~4번은 값만 다룬다.
- 재사용: 3번의 결합 규칙(첫 파트가 제목을 갖고, 나머지는 라벨 밑으로)은 지금 것을
  그대로 쓴다. 4번의 판정 규칙도 그대로고, **입력만** 본문에서 파트 전체로 바꾼다.

## Guardrails

- 이미 만들어둔 기획서 HTML 파일을 이 작업에서 다시 쓰거나 지우지 않는다.
- 원문 사이드 패널의 세 탭(계획·구조·테스트)은 그대로 둔다 — 본문에서 빠지는 것이지
  문서에서 사라지는 게 아니다.
- 번호식 화면설계서 렌더링(마커·설명 목록·상태 띠·검증 표)에 손대지 않는다.
- 단일 마크다운 파일 입력 경로는 건드리지 않는다.
- 기존 deck 계약(158건)과 번호식 계약을 하나도 약화시키지 않는다. 옛 계약이 새 계약과
  충돌하면 **약화가 아니라 대체**임을 근거로 밝히고 갱신한다.
- 린트의 판정 규칙 자체는 바꾸지 않는다. 바꾸는 건 무엇을 훑느냐(입력)뿐이다.

## Exit criteria

- TESTS.md 시나리오 전부 통과
- 어제 만든 계획 폴더로 기획서를 만들면 **그림 절만** 나온다 (구성도 2 + 화면 2)
- 그림 문서가 없는 폴더는 HTML 을 만들지 않고 이유 한 줄로 끝난다 — 오류 아님
- 되살리기 옵션을 주면 예전과 같은 전체 결합이 나온다
- 계획 문서를 본문에서 빼도 린트 경고 개수가 늘지 않는다
- 기존 아카이브의 기획서 HTML 파일이 이 작업으로 바뀌지 않는다

# Test Plan — 기획서는 그림만

## Overview

확인하려는 것은 하나다: **폴더로 기획서를 만들면 본문에 그림 문서만 남는가**, 그리고
그 대가로 잃으면 안 되는 것(원문 세 탭, 예전 기획서, 린트 정확도)이 그대로인가.
그림 문서가 없는 폴더에서 빈 문서가 나오지 않는 것도 같은 무게로 확인한다.

## Test scenarios

### T1. 폴더를 넘기면 본문은 그림 문서만이다

- **Setup**: 계획·구조·테스트 세 문서가 모두 있는 임시 슬러그 폴더. 계획 문서에만
  있는 고유 문구(예: `Exit criteria` 절의 문장)와 구조 문서에만 있는 고유 문구를
  각각 심어둔다.
- **Run**: 그 폴더로 기획서를 만든다 (원문 패널 없는 렌더로 — 원문 패널이 본문 대신
  잡히는 오검을 막는다).
- **Expected**: 본문에 구조 문서의 문구는 있고, 계획 문서·테스트 문서의 문구는 없다.
- **Pass criterion**: 렌더된 본문에서 계획 문서 고유 문구가 0회, 구조 문서 고유 문구가
  1회 이상.

### T2. 그림 문서가 없으면 기획서를 만들지 않는다

- **Setup**: 계획 문서와 테스트 문서만 있고 구조 문서가 없는 임시 슬러그 폴더.
- **Run**: 그 폴더로 기획서를 만든다.
- **Expected**: HTML 파일이 생기지 않는다. "만들 것 없음"과 그 이유가 출력에 한 줄로
  나온다. 종료 코드는 성공이다 (오류가 아니다).
- **Pass criterion**: 결과 HTML 경로가 존재하지 않고, 종료 코드 0, 출력에 사유 줄 1개.

### T3. 되살리기 옵션은 예전 전체 결합을 그대로 낸다

- **Setup**: T1 과 같은 폴더.
- **Run**: 되살리기 옵션을 주고 기획서를 만든다.
- **Expected**: 계획·구조·테스트 세 문서의 고유 문구가 모두 본문에 있다.
- **Pass criterion**: 세 문구 전부 1회 이상. 이 변경 이전 코드로 만든 기준선과 본문이
  같다.

### T4. 원문 사이드 패널은 세 탭을 그대로 유지한다

- **Setup**: T1 과 같은 폴더 (원문 패널을 켠 기본 렌더).
- **Run**: 기본값(그림만)으로 기획서를 만든다.
- **Expected**: 본문에서 빠진 계획 문서와 테스트 문서가 원문 패널 탭에는 그대로 있다.
- **Pass criterion**: 원문 패널에 세 파일 이름의 탭이 모두 있고, 각 탭의 원문이 파일
  내용과 일치한다.

### T5. 계획 문서를 본문에서 빼도 린트 경고가 늘지 않는다

- **Setup**: 비목표·성공지표·인수기준·예외처리·순수함수 절을 모두 갖춘 계획 문서 +
  그림이 있는 구조 문서.
- **Run**: 기본값(그림만)으로 만든 경우와, 되살리기 옵션으로 만든 경우의 경고 수를
  비교한다.
- **Expected**: 두 경우의 경고 개수와 내용이 같다.
- **Pass criterion**: 경고 개수가 동일하고, 위 다섯 항목에 대한 경고가 어느 쪽에서도
  뜨지 않는다.

### T6. 그림이 정말 없을 때의 경고는 그대로 뜬다

- **Setup**: 구조 문서는 있으나 그 안에 그림(구성도·화면)이 하나도 없는 폴더.
- **Run**: 기본값으로 기획서를 만든다.
- **Expected**: 문서는 만들어지고, 그림 없음 경고가 뜬다. T5 의 완화로 이 경고까지
  사라지면 안 된다.
- **Pass criterion**: HTML 이 생기고, 그림 없음 경고가 1건 있다.

### T7. 어제 만든 실제 계획으로 그림 절만 나온다

- **Setup**: `scv/archive/20260826-wookiya1364-numbered-spec-deck/` (실제 아카이브).
- **Run**: 기본값으로 기획서를 만든다 (임시 출력 경로로 — 아카이브 원본을 덮지 않는다).
- **Expected**: 구조 문서의 세 절만 나오고, 그림 넷(구성도 2 + 화면 2)이 모두 렌더된다.
  계획 문서의 열두 절은 본문에 없다.
- **Pass criterion**: 본문의 절 개수가 구조 문서의 절 개수와 같고, 번호식 마커가
  렌더된다.

### T8. 예전 기획서 파일은 이 작업으로 바뀌지 않는다

- **Setup**: 작업 전 아카이브의 기획서 HTML 파일들의 해시를 기록해둔다.
- **Run**: 이 변경을 적용한 뒤 테스트를 전부 돌린다.
- **Expected**: 아카이브의 기획서 HTML 파일 해시가 하나도 변하지 않는다.
- **Pass criterion**: 작업 전후 해시 목록이 완전히 동일하다.

### T9. 단일 마크다운 파일 입력은 지금 그대로다

- **Setup**: 폴더가 아닌 마크다운 파일 하나.
- **Run**: 그 파일로 기획서를 만든다.
- **Expected**: 이 변경 이전과 결과가 같다 (합치기 자체가 없는 경로).
- **Pass criterion**: 변경 전 기준선과 결과 HTML 이 바이트 단위로 같다.

### T10. 기존 deck 계약이 전부 살아 있다

- **Setup**: 기존 계약 테스트 세 벌.
- **Run**: 번호식 화면설계서 계약 / 기존 문서 계약 / 정적 다이어그램 계약을 돌린다.
- **Expected**: 전부 통과. 옛 계약이 새 계약으로 대체되어 갱신이 필요한 경우, 그것이
  약화가 아니라 대체임을 근거와 함께 밝힌다.
- **Pass criterion**: 세 벌 모두 통과.

### T11. 호출부가 "만들 것 없음"을 오류로 받지 않는다

- **Setup**: 그림 문서가 없는 폴더.
- **Run**: 계획 만들기·구현 마무리가 기획서를 만드는 지점을 그 폴더로 실행한다.
- **Expected**: 흐름이 멈추지 않고, 기획서가 없다는 사실만 보고된다.
- **Pass criterion**: 종료 코드 0, 흐름이 다음 단계로 이어진다.
