# Test Plan — 기획서는 그림만

## Overview

확인하려는 것은 하나다: **폴더로 기획서를 만들면 본문에 그림 문서만 남는가**, 그리고
그 대가로 잃으면 안 되는 것(원문 세 탭, 예전 기획서, 린트 정확도)이 그대로인가.
그림 문서가 없는 폴더에서 빈 문서가 나오지 않는 것도 같은 무게로 확인한다.

## Test scenarios

### T1. 폴더를 넘기면 본문은 그림 문서만이다

- **Setup**: 계획·구조·테스트 세 문서가 모두 있는 임시 슬러그 폴더. 계획 문서에만
  있는 고유 문구(예: `Exit criteria` 절의 문장)와 구조 문서에만 있는 고유 문구를
  각각 심어둔다.
- **Run**: 그 폴더로 기획서를 만든다 (원문 패널 없는 렌더로 — 원문 패널이 본문 대신
  잡히는 오검을 막는다).
- **Expected**: 본문에 구조 문서의 문구는 있고, 계획 문서·테스트 문서의 문구는 없다.
- **Pass criterion**: 렌더된 본문에서 계획 문서 고유 문구가 0회, 구조 문서 고유 문구가
  1회 이상.

### T2. 그림 문서가 없으면 기획서를 만들지 않는다

- **Setup**: 계획 문서와 테스트 문서만 있고 구조 문서가 없는 임시 슬러그 폴더.
- **Run**: 그 폴더로 기획서를 만든다.
- **Expected**: HTML 파일이 생기지 않는다. "만들 것 없음"과 그 이유가 출력에 한 줄로
  나온다. 종료 코드는 성공이다 (오류가 아니다).
- **Pass criterion**: 결과 HTML 경로가 존재하지 않고, 종료 코드 0, 출력에 사유 줄 1개.

### T3. 되살리기 옵션은 예전 전체 결합을 그대로 낸다

- **Setup**: T1 과 같은 폴더.
- **Run**: 되살리기 옵션을 주고 기획서를 만든다.
- **Expected**: 계획·구조·테스트 세 문서의 고유 문구가 모두 본문에 있다.
- **Pass criterion**: 세 문구 전부 1회 이상. 이 변경 이전 코드로 만든 기준선과 본문이
  같다.

### T4. 원문 사이드 패널은 세 탭을 그대로 유지한다

- **Setup**: T1 과 같은 폴더 (원문 패널을 켠 기본 렌더).
- **Run**: 기본값(그림만)으로 기획서를 만든다.
- **Expected**: 본문에서 빠진 계획 문서와 테스트 문서가 원문 패널 탭에는 그대로 있다.
- **Pass criterion**: 원문 패널에 세 파일 이름의 탭이 모두 있고, 각 탭의 원문이 파일
  내용과 일치한다.

### T5. 계획 문서를 본문에서 빼도 린트 경고가 늘지 않는다

- **Setup**: 비목표·성공지표·인수기준·예외처리·순수함수 절을 모두 갖춘 계획 문서 +
  그림이 있는 구조 문서.
- **Run**: 기본값(그림만)으로 만든 경우와, 되살리기 옵션으로 만든 경우의 경고 수를
  비교한다.
- **Expected**: 두 경우의 경고 개수와 내용이 같다.
- **Pass criterion**: 경고 개수가 동일하고, 위 다섯 항목에 대한 경고가 어느 쪽에서도
  뜨지 않는다.

### T6. 그림이 정말 없을 때의 경고는 그대로 뜬다

- **Setup**: 구조 문서는 있으나 그 안에 그림(구성도·화면)이 하나도 없는 폴더.
- **Run**: 기본값으로 기획서를 만든다.
- **Expected**: 문서는 만들어지고, 그림 없음 경고가 뜬다. T5 의 완화로 이 경고까지
  사라지면 안 된다.
- **Pass criterion**: HTML 이 생기고, 그림 없음 경고가 1건 있다.

### T7. 어제 만든 실제 계획으로 그림 절만 나온다

- **Setup**: `scv/archive/20260826-wookiya1364-numbered-spec-deck/` (실제 아카이브).
- **Run**: 기본값으로 기획서를 만든다 (임시 출력 경로로 — 아카이브 원본을 덮지 않는다).
- **Expected**: 구조 문서의 세 절만 나오고, 그림 넷(구성도 2 + 화면 2)이 모두 렌더된다.
  계획 문서의 열두 절은 본문에 없다.
- **Pass criterion**: 본문의 절 개수가 구조 문서의 절 개수와 같고, 번호식 마커가
  렌더된다.

### T8. 예전 기획서 파일은 이 작업으로 바뀌지 않는다

- **Setup**: 작업 전 아카이브의 기획서 HTML 파일들의 해시를 기록해둔다.
- **Run**: 이 변경을 적용한 뒤 테스트를 전부 돌린다.
- **Expected**: 아카이브의 기획서 HTML 파일 해시가 하나도 변하지 않는다.
- **Pass criterion**: 작업 전후 해시 목록이 완전히 동일하다.

### T9. 단일 마크다운 파일 입력은 지금 그대로다

- **Setup**: 폴더가 아닌 마크다운 파일 하나.
- **Run**: 그 파일로 기획서를 만든다.
- **Expected**: 이 변경 이전과 결과가 같다 (합치기 자체가 없는 경로).
- **Pass criterion**: 변경 전 기준선과 결과 HTML 이 바이트 단위로 같다.

### T10. 기존 deck 계약이 전부 살아 있다

- **Setup**: 기존 계약 테스트 세 벌.
- **Run**: 번호식 화면설계서 계약 / 기존 문서 계약 / 정적 다이어그램 계약을 돌린다.
- **Expected**: 전부 통과. 옛 계약이 새 계약으로 대체되어 갱신이 필요한 경우, 그것이
  약화가 아니라 대체임을 근거와 함께 밝힌다.
- **Pass criterion**: 세 벌 모두 통과.

### T11. 호출부가 "만들 것 없음"을 오류로 받지 않는다

- **Setup**: 그림 문서가 없는 폴더.
- **Run**: 계획 만들기·구현 마무리가 기획서를 만드는 지점을 그 폴더로 실행한다.
- **Expected**: 흐름이 멈추지 않고, 기획서가 없다는 사실만 보고된다.
- **Pass criterion**: 종료 코드 0, 흐름이 다음 단계로 이어진다.

## How to run

```bash
bash -euo pipefail -c '
fail() { echo "FAIL: $1"; exit 1; }
bash core/tests/test-deck-picture-only.sh >/dev/null || fail "T1-T9,T11 그림만 기획서"
bash core/tests/test-deck-numbered-spec.sh  >/dev/null || fail "T10 번호식 화면설계서 계약"
bash core/tests/test-deck-doc.sh            >/dev/null || fail "T10 기존 deck 문서 계약"
bash core/tests/test-deck-static-mermaid.sh >/dev/null || fail "T10 정적 다이어그램 계약"
echo "ALL GATES OK"
'
```

## Pass criteria

- T1~T11 전부 통과
- 기존 deck 계약 세 벌이 하나도 약화되지 않음
- 아카이브의 기획서 HTML 해시가 작업 전후 동일
