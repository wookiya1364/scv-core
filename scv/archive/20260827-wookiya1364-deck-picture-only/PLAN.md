# 기획서는 그림만 — 계획·테스트 문서를 본문에서 분리

## Summary

기획서를 만들면 계획서·구조 문서·테스트 문서가 한 덩어리로 붙어 스무 절이 나오는데,
그중 번호식 화면설계서는 한두 절뿐이고 나머지는 글 덩어리다. 본문을 **그림 문서만**으로
바꿔 "큰 그림, 적은 글"이 문서 전체의 성격이 되게 한다. 계획·테스트 원문은 사라지지 않고
사이드 패널 탭으로 계속 따라다닌다.

## Goals / Non-Goals

- **Goals**
  - 폴더를 넘겨 기획서를 만들 때 **본문은 구조 문서(그림 문서)만** 렌더한다.
  - 그림 문서가 없으면 **기획서를 만들지 않고** 그 사실을 한 줄로 알린다.
  - 예전처럼 셋을 전부 합치고 싶을 때를 위한 **되살리기 옵션**을 둔다.
  - 계획 문서를 본문에서 빼도 **린트 경고가 거짓으로 늘지 않게** 한다.
- **Non-Goals**
  - 번호식 화면설계서의 렌더링 규칙 자체는 손대지 않는다 (어제 만든 것 그대로).
  - 계획 작성 단계에서 각 절을 그림으로 바꾸는 일은 이번 범위가 아니다.
  - 단일 마크다운 파일 입력 경로는 건드리지 않는다 (합치기 자체가 없다).
  - 이미 만들어둔 기획서 HTML 을 일괄 재생성하지 않는다.

## Approach Overview

기획서를 만드는 파이프라인에서 **"무엇을 본문으로 삼을지 고르는 단계"** 하나를 새로
분리한다. 지금은 폴더를 읽어 세 파일을 무조건 이어 붙이는 한 덩어리 함수인데, 이를
**읽기 → 고르기 → 본문 만들기 → 린트** 네 단계로 쪼갠다.

- **읽기** — 폴더에 실제로 있는 파트를 목록으로 만든다. (지금과 동일)
- **고르기** — 새로 생기는 단계. 본문으로 쓸 파트와 원문 탭으로 쓸 파트를 나눈다.
  기본값은 본문 = 구조 문서 하나, 원문 탭 = 있는 파트 전부. 되살리기 옵션이 켜지면
  본문 = 있는 파트 전부(지금 동작).
- **본문 만들기** — 고른 파트만 이어 붙인다. 본문 파트가 하나뿐이면 구분선·라벨이
  필요 없다.
- **린트** — 지금은 본문 트리의 제목만 훑기 때문에 계획 문서를 빼면 비목표·성공지표·
  인수기준·예외처리·순수함수 경고가 전부 거짓으로 뜬다. 린트 입력을 **본문이 아니라
  읽어들인 파트 전체**로 바꾼다.

본문 파트가 하나도 없으면(구조 문서 없음, 되살리기 옵션 꺼짐) HTML 을 쓰지 않고
"만들 것 없음"을 알리는 한 줄로 끝낸다. 실패가 아니라 정상 종료다 — 호출부(계획 만들기·
구현 마무리)가 이걸 오류로 받아 멈추면 안 된다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readSlugParts,       // 폴더 경로 → 있는 파트 목록 [{파일명, 라벨, 원문}]
  selectRenderParts,   // (파트 목록, 옵션) → { 본문 파트[], 원문 탭 파트[] }
  composeBody,         // 본문 파트[] → 결합 마크다운 (없으면 빈 값)
  lintOverParts,       // (결합 마크다운, 파트 목록 전체) → 경고 목록
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | readSlugParts | 폴더 경로 → 파트 목록 | 부수효과 (입구 — 파일 읽기) |
| 2 | selectRenderParts | (파트 목록, 옵션) → 본문/원문 분리 | 순수 |
| 3 | composeBody | 본문 파트 → 결합 마크다운 | 순수 |
| 4 | lintOverParts | (본문, 파트 전체) → 경고 목록 | 순수 |
| 5 | writeDeck | (본문, 경고) → HTML 파일 | 부수효과 (출구 — 파일 쓰기) |

- 부수효과 위치: 1번(파일 읽기)과 5번(HTML 쓰기)뿐. 2~4번은 값만 다룬다.
- 재사용: 3번의 결합 규칙(첫 파트가 제목을 갖고, 나머지는 라벨 밑으로)은 지금 것을
  그대로 쓴다. 4번의 판정 규칙도 그대로고, **입력만** 본문에서 파트 전체로 바꾼다.

## Guardrails

- 이미 만들어둔 기획서 HTML 파일을 이 작업에서 다시 쓰거나 지우지 않는다.
- 원문 사이드 패널의 세 탭(계획·구조·테스트)은 그대로 둔다 — 본문에서 빠지는 것이지
  문서에서 사라지는 게 아니다.
- 번호식 화면설계서 렌더링(마커·설명 목록·상태 띠·검증 표)에 손대지 않는다.
- 단일 마크다운 파일 입력 경로는 건드리지 않는다.
- 기존 deck 계약(158건)과 번호식 계약을 하나도 약화시키지 않는다. 옛 계약이 새 계약과
  충돌하면 **약화가 아니라 대체**임을 근거로 밝히고 갱신한다.
- 린트의 판정 규칙 자체는 바꾸지 않는다. 바꾸는 건 무엇을 훑느냐(입력)뿐이다.

## Exit criteria

- TESTS.md 시나리오 전부 통과
- 어제 만든 계획 폴더로 기획서를 만들면 **그림 절만** 나온다 (구성도 2 + 화면 2)
- 그림 문서가 없는 폴더는 HTML 을 만들지 않고 이유 한 줄로 끝난다 — 오류 아님
- 되살리기 옵션을 주면 예전과 같은 전체 결합이 나온다
- 계획 문서를 본문에서 빼도 린트 경고 개수가 늘지 않는다
- 기존 아카이브의 기획서 HTML 파일이 이 작업으로 바뀌지 않는다

## Suggested path

1. 폴더 읽기 함수를 읽기·고르기·본문 만들기 세 단계로 쪼갠다 (동작은 그대로 유지).
2. 고르기 단계에 기본값(그림 문서만)과 되살리기 옵션을 넣는다.
3. 본문 파트가 없을 때 HTML 을 쓰지 않고 알림 한 줄로 끝나는 길을 만든다.
4. 린트 입력을 파트 전체로 바꾼다.
5. 되살리기 옵션을 실행 스크립트와 지침에 노출한다.
6. 호출부 세 곳(기획서 명령·계획 만들기·구현 마무리)이 "만들 것 없음"을 오류로 받지
   않는지 확인한다.
