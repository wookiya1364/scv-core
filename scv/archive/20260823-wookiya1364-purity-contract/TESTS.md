# Test Plan — 순수부와 효과부 계약

## Overview

확인하는 것: 검사기가 실제로 위반을 잡고 멀쩡한 것은 통과시키는지, 선언된 함수가
약속을 지키는지, 검사가 빈 상태로 통과하지 않는지, 문서와 검사가 같은 것을
말하는지.

**가장 중요한 것은 첫 항목이다.** 통과만 하고 아무것도 안 보는 검사기는 없느니만
못하다 — 지키는 척만 하게 되어 오히려 나쁘다.

## Test scenarios

### T1. 검사기 자신이 도는가  ✅
- **Setup**: 일부러 부수효과를 심은 함수와 멀쩡한 함수를 검사기에 직접 넘긴다.
- **Expected**:
  - 시각 읽기 + 파일 쓰기가 든 함수 → **2건 이상** 잡는다
  - 산술 비교와 문자열 출력만 있는 함수 → **0건**
  - 결정적 층에서 `jq` → **0건** (허용)
  - 결정적 층에서 파일 읽기 → **1건 이상** (금지)
- **Pass criterion**: `OK  self-test: ...`

### T2. 선언된 함수가 약속을 지키는가  ✅
- **Expected**: 표식이 붙은 함수 전부 위반 0건.
- **Pass criterion**: `OK  purity: 선언된 N개 함수 전부 약속을 지킨다`

### T3. 검사가 빈 상태로 통과하지 않는가  ✅
- **Setup**: 선언된 함수 수를 센다.
- **Expected**: **5개 이상.** 표식이 없으면 검사가 아무것도 안 보면서 통과한다 —
  가장 나쁜 상태다.
- **Pass criterion**: 개수 보고

### T4. 문서와 검사가 어긋나지 않는가  ✅
- **Expected**: 계약 문서에 표식 두 종류, 검사기 이름, 자체 확인 방법, 한계 절이
  전부 있다.
- **Pass criterion**: 다섯 항목 전부

### T5. 실제 위반을 잡는가 (수동 확인)  ✅
- **Setup**: 순수 선언된 함수에 시각 읽기를 넣어 본다.
- **Expected**: 그 함수 이름과 줄을 지목하며 실패. 되돌리면 통과.
- **결과**: 확인 완료 — `settings_resolve` 에 시각 읽기를 넣자 정확히 그 줄을
  지목했다. 자동 회귀는 T1 의 canary 가 대신한다.

### T6. 회귀 — 기존 스위트  ✅
- **Expected**: run-dry 977 PASS / 0 FAIL, tests/run.sh 통과, core/tests 26개 실패 0.

## How to run

```bash
bash core/scripts/check-purity.sh --self-test   # T1
bash core/scripts/check-purity.sh               # T2
bash core/scripts/check-purity.sh --list        # T3
bash core/tests/test-purity.sh                  # T1–T4 전부
```

## 이 계획이 지키는 것

- **검사기를 의심한다.** 검사기가 도는지 검사하는 항목이 첫 번째다.
- **오탐도 실패로 본다.** 멀쩡한 코드를 위반이라 하면 사람들이 규칙을 무시한다.
- **빈 검사를 실패로 본다.** 선언이 없으면 통과가 아무 의미가 없다.
- **한계를 숨기지 않는다.** 못 잡는 것을 문서에 적고, 그 문서가 있는지도 검사한다.
