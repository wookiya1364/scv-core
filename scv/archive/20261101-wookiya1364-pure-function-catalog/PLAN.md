# 순수함수 목록 — 만들기 전에 목록에서 찾아 재사용

## Summary

SCV 자체 코드에는 순수 표식이 붙은 함수가 234개 있다(확인, 2026-11-01). 역할 설명이 붙은 건 22개뿐이라, 새 코드를 쓸 때 이미 있는 함수를 찾으려면 코드 전체를 훑어야 하고, 실제로 기능마다 다듬기 · 파싱 함수를 따로 만들어 왔다(예: 두 기능에 따로 있는 다듬기 함수). 함수마다 역할 · 종류 · 예시를 코드 옆에 적고, 그걸로 **종류별 사전 + 차례**를 자동으로 만든다. 모델은 차례와 종류 파일 하나만 읽고 재사용 후보를 찾는다. 같은 입력에 같은 출력을 내는 함수가 또 생기면 검사가 잡는다.

## Goals / Non-Goals

- **Goals**
  - 순수 · 결정적 표식 함수마다 역할 한 줄 · 종류 하나 · 예시(입력 → 출력) 1개 이상을 코드 옆 주석에 적는다. 없으면 검사 실패.
  - 예시는 실제로 돌려서 맞는지 검사한다 — 틀린 예시는 실패.
  - 주석에서 사전을 자동 생성한다: 작은 차례 파일(종류명 · 한 줄 설명 · 개수) + 종류별 파일. 사전이 코드와 어긋나면(손으로 고쳤거나 다시 안 만들었으면) CI 실패.
  - 종류 파일이 크기 한도를 넘으면 세부 종류로 쪼갠다 — 어떤 파일도 한 번에 읽을 수 있는 크기로 유지.
  - 중복 검사: 같은 개수의 인자를 받는 함수들에 공통 입력 묶음(경계 입력 포함)을 넣어 출력이 전부 같으면 '중복 의심'으로 실패. 사람이 '다름'으로 판정한 짝은 예외 목록에 남긴다.
  - work · codegen 규약: 새 함수를 쓰기 전에 차례 → 해당 종류 파일만 읽고 재사용 후보를 찾는다.
  - 기존 234개 전부 채운다. 그 과정에서 나온 진짜 중복은 합친다.
- **Non-Goals**
  - 사용자 프로젝트 · 다른 언어(TS · 파이썬 등) — 다음 계획.
  - 계획서의 '재사용' 줄을 강제하는 것 — 사전 읽기 규칙과 중복 검사로 충분하다고 정함(대화 Turn 4).
  - 표식 없는 함수(효과층)의 사전화.

## Approach Overview

- **원본은 코드 옆 주석 하나뿐.** 표식 바로 위 주석에 세 줄 형식을 더한다: `# 역할: …` · `# 종류: <종류>` · `# 예: <인자…> → <출력>`. 사전은 이 주석에서 생성만 하고 손으로 쓰지 않는다 — 두 곳에 적으면 어긋난다.
- **종류**는 하는 일 기준(다듬기 · 꺼내기 · 세기 · 비교 · 판정 · 조립 · 변환 …)이고, 정해진 목록에서만 고른다. 목록은 계약 문서에 한 곳.
- **중복 판정 = 행동 지문.** 각 함수에 그 인자 개수용 공통 입력 묶음(빈 값 · 공백 · 줄바꿈 · 탭 · 한글 · 숫자 · 특수문자)과 모든 같은 개수 함수의 예시 입력을 넣고, 출력 묶음이 전부 같으면 중복 의심. 입력 몇 개가 같다고 완전히 같다는 증명은 아니므로, 사람이 '다름'으로 보면 예외 목록에 이유와 함께 적는다.
- **기존 중복 합치기**는 경계 입력까지 전부 같을 때만, 합친 뒤 전체 시험이 통과할 때만. 하나라도 다르면 합치지 않고 예외 목록에 '비슷하지만 다름'으로 남긴다.
- 기존 순수 검사기(목록 기능이 이미 234개를 찾음)를 확장하고, 생성 · 중복 검사는 같은 자리에 둔다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readSources,         // 스크립트 경로들 → 파일 내용들 (입구, 부수효과)
  extractEntries,      // 파일 내용 → 함수 항목들(이름 · 위치 · 표식 · 역할 · 종류 · 예시)
  validateEntries,     // 항목들 → 빠진 칸 · 모르는 종류 목록
  runExamples,         // 항목들 → 예시별 실제 출력 (결정적 — 함수를 불러 봄)
  checkExamples,       // 항목 + 실제 출력 → 틀린 예시 목록
  fingerprint,         // 항목들 + 공통 입력 → 함수별 출력 지문
  findDuplicates,      // 지문들 + 예외 목록 → 중복 의심 짝
  groupByKind,         // 항목들 → 종류별 묶음 (한도 넘으면 세부 종류로)
  renderCatalog,       // 묶음 → 차례 글 + 종류별 파일 글
  writeOrCompare,      // 글 → 파일 쓰기 또는 '어긋남' 판정 (출구, 부수효과)
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | readSources | 표식 있는 스크립트를 읽는다 | 경로들 → 파일 내용들 | 부수효과 (입구) |
| 2 | extractEntries | 표식 위 주석에서 역할 · 종류 · 예시를 뽑는다 | 파일 내용 → 함수 항목들 | 순수 |
| 3 | validateEntries | 빈 칸 · 목록에 없는 종류를 찾는다 | 항목들 → 위반 목록 | 순수 |
| 4 | runExamples | 예시 입력으로 함수를 실제로 불러 본다 | 항목들 → 실제 출력들 | 결정적 (함수 호출) |
| 5 | checkExamples | 적힌 출력과 실제 출력을 비교한다 | 항목 + 출력 → 틀린 예시 | 순수 |
| 6 | fingerprint | 공통 입력 묶음을 넣어 출력 지문을 만든다 | 항목들 + 입력 묶음 → 지문들 | 결정적 (함수 호출) |
| 7 | findDuplicates | 지문이 같은 짝을 찾고 예외는 뺀다 | 지문 + 예외 → 중복 의심 | 순수 |
| 8 | groupByKind | 종류별로 묶고 큰 묶음은 쪼갠다 | 항목들 → 묶음들 | 순수 |
| 9 | renderCatalog | 차례와 종류별 파일 글을 만든다 | 묶음들 → 파일 글들 | 순수 |
| 10 | writeOrCompare | 쓰거나, 있는 파일과 비교해 어긋남을 알린다 | 파일 글들 → 결과 | 부수효과 (출구) |

- 부수효과 위치: 1(읽기)과 10(쓰기 · 비교)만. 4 · 6은 표식 함수를 부르지만, 그 함수들이 순수 · 결정적이라는 건 기존 순수 검사가 보장한다.
- 재사용: 기존 순수 검사기의 표식 찾기(목록 기능)를 그대로 2의 입력 위치 찾기로 쓴다.

## Guardrails

- 사전 파일은 생성물이다 — 손으로 고치지 않는다. 고치면 CI 가 어긋남으로 잡는다.
- 합치기는 경계 입력까지 전부 같고 전체 시험이 통과할 때만. 의심만으로 합치지 않는다.
- 중복 예외 목록의 각 줄에는 '왜 다른가' 한 줄이 반드시 있다 — 이유 없는 예외는 실패.
- 순수 검사 · 사전 생성 · 중복 검사를 합친 시간이 CI 에 30초 넘게 더하지 않는다(측정해 숫자로 보고).
- 효과층 함수에 표식을 새로 달아 개수를 맞추지 않는다 — 표식은 실제로 순수 · 결정적일 때만.

## Exit criteria

- All TESTS.md scenarios pass
- 표식 함수 전부(채우기 시점 234개 ± 합친 수)에 역할 · 종류 · 예시가 있고, 예시가 전부 실제 출력과 맞는다.
- 차례 파일만 읽고 종류 파일 하나를 열어 재사용 후보를 찾는 길이 work · codegen 규약에 적혀 있다.
- 기존 중복은 합쳐졌거나, 예외 목록에 이유와 함께 남아 있다 — 이유 없는 중복 의심 0건.
- 일부러 같은 함수를 하나 더 만들면 CI 가 실패한다.

## Metrics

| 지표 | 지금 (확인) | 목표 |
|---|---|---|
| 역할 · 종류 · 예시가 갖춰진 표식 함수 | 역할 줄 22 / 234 | 전부 |
| 이유 없는 중복 의심 | 잰 적 없음 | 0 |
| 재사용 후보 찾기에 읽는 파일 | 코어 스크립트 전체 | 차례 + 종류 파일 1개 |
| 검사 추가로 늘어난 CI 시간 | 0 | 30초 이하 |

## Suggested path

1. 계약 문서에 주석 형식 · 종류 목록 · 크기 한도 · 예외 목록 형식을 적는다 — 규칙을 한 곳에 정한다
2. 주석 읽기 · 검증 · 예시 실행을 검사기에 더한다 — `readSources`, `extractEntries`, `validateEntries`, `runExamples`, `checkExamples`
3. 지문 · 중복 판정을 더한다 — `fingerprint`, `findDuplicates`
4. 종류별 사전 생성과 어긋남 검사를 더한다 — `groupByKind`, `renderCatalog`, `writeOrCompare`
5. 기존 234개에 역할 · 종류 · 예시를 파일 묶음별로 채운다 — 예시는 실제로 돌린 출력을 적는다
6. 나온 중복 의심을 경계 입력으로 확인해 합치거나 예외로 남기고, 전체 시험을 돌린다 — 진짜 중복만 합친다
7. work · codegen 규약에 '새 함수 전에 차례 → 종류 파일' 단계를 넣고, CI 에 검사를 연결해 시간을 잰다 — 강제를 켠다

## Risks / Open Questions

- 같은 개수 인자 함수끼리만 비교하므로, 인자 순서만 다른 같은 함수는 못 잡는다(추정 — 드묾). 사전 읽기 규칙이 보완.
- 환경 값(설정 · 시각)을 인자로 받는 결정적 함수는 공통 입력에 의미 있는 출력을 안 낼 수 있다 — 그런 함수는 자기 예시 입력끼리만 비교된다.
- 234개 채우기는 양이 많다 — 파일 묶음별 커밋으로 나눠 중간에 멈춰도 이어갈 수 있게.
- 종류 목록이 처음엔 맞지 않을 수 있다 — 채우다 새 종류가 필요하면 계약 문서에 더하고 결정 기록에 남긴다.
