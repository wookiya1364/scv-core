# Test Plan — 순수함수 목록 — 만들기 전에 목록에서 찾아 재사용

## Overview

대화에서 정한 기능 하나하나가 시험 하나다: 역할 · 종류 · 예시가 없으면 실패, 틀린 예시는 실패, 사전은 주석에서 생성되고 어긋나면 실패, 종류별 파일 + 차례, 크기 한도 넘으면 쪼갬, 같은 입력 → 같은 출력이면 중복 의심, 예외는 이유가 있어야 함, 기존 234개 전부 채움, 진짜 중복은 합침, 구현 규약이 차례부터 읽게 함. 모든 시험은 임시 폴더의 고정 입력으로 돌아 결정적이다.

## Test scenarios

### T1. 역할 · 종류 · 예시가 빠지면 실패

- **Setup**: 임시 폴더에 `# @pure` 함수 세 개 — 셋 다 갖춘 것, 역할 빠진 것, 예시 빠진 것.
- **Run**: 검사기를 그 폴더에 돌린다.
- **Expected**: 빠진 두 함수 이름과 빠진 칸이 출력되고 종료 코드 1. 다 갖춘 함수는 언급되지 않는다.
- **Pass criterion**: 종료 코드 1, 출력에 두 함수 이름 · 칸 이름이 정확히.

### T2. 목록에 없는 종류는 실패

- **Setup**: `# 종류: 아무거나` 를 단 함수 하나.
- **Run**: 검사기.
- **Expected**: '모르는 종류' 위반과 허용 종류 목록 안내.
- **Pass criterion**: 종료 코드 1, 출력에 그 함수 이름.

### T3. 틀린 예시는 실패, 맞는 예시는 통과

- **Setup**: 앞뒤 공백을 지우는 함수 — 예시 `# 예: "  a " → "a"` 하나와, 일부러 틀린 `→ "b"` 하나를 각각 다른 함수로.
- **Run**: 검사기.
- **Expected**: 틀린 쪽만 '적힌 출력 "b", 실제 "a"' 로 실패.
- **Pass criterion**: 맞는 함수는 통과, 틀린 함수만 위반, 종료 코드 1.

### T4. 사전은 주석에서 생성된다 — 차례 + 종류별 파일

- **Setup**: 종류가 다른 함수 세 개(다듬기 2 · 비교 1)가 든 임시 폴더.
- **Run**: 생성 모드로 돌린다.
- **Expected**: 차례 파일에 종류 두 줄(이름 · 한 줄 설명 · 개수 2와 1), 종류 파일 두 개. 각 줄에 함수 이름 · 위치 · 역할 · 예시.
- **Pass criterion**: 생성된 파일 글이 기대 파일과 바이트까지 같다.

### T5. 사전이 코드와 어긋나면 실패

- **Setup**: T4 결과에서 (a) 사전 한 줄을 손으로 고침, (b) 코드의 역할 주석을 바꾸고 다시 생성 안 함.
- **Run**: 비교 모드.
- **Expected**: 두 경우 모두 '사전이 낡음 — 다시 생성' 과 어긋난 파일 이름.
- **Pass criterion**: 두 경우 종료 코드 1. 손대지 않은 상태에선 종료 코드 0.

### T6. 크기 한도를 넘는 종류는 쪼개진다

- **Setup**: 한도를 작게(시험용 설정) 하고 한 종류에 한도보다 많은 함수.
- **Run**: 생성 모드.
- **Expected**: 그 종류가 세부 종류 파일들로 나뉘고 차례에 각각 나온다. 어떤 파일도 한도를 넘지 않는다.
- **Pass criterion**: 모든 생성 파일 크기 ≤ 한도, 함수 누락 0.

### T7. 같은 입력 → 같은 출력이면 중복 의심

- **Setup**: 이름 · 몸체 모양은 다르지만 하는 일이 같은 다듬기 함수 둘(하나는 매개변수 확장, 하나는 반복문), 그리고 줄바꿈 처리만 다른 비슷한 함수 하나.
- **Run**: 검사기.
- **Expected**: 같은 둘은 '중복 의심' 짝으로 나온다. 줄바꿈만 다른 함수는 공통 입력의 줄바꿈 값에서 달라져 짝에 들지 않는다.
- **Pass criterion**: 짝 정확히 하나, 종료 코드 1.

### T8. 예외 목록 — 이유가 있어야 통과

- **Setup**: T7 의 짝을 예외 목록에 (a) 이유와 함께, (b) 이유 없이 적는다.
- **Run**: 검사기.
- **Expected**: (a) 통과, (b) '이유 없는 예외' 실패.
- **Pass criterion**: (a) 종료 코드 0, (b) 종료 코드 1.

### T9. 기존 234개 전부 채워짐 — 실제 저장소

- **Setup**: 이 저장소 그대로.
- **Run**: 검사기를 기본 경로(코어 스크립트 전부)에.
- **Expected**: 빠진 칸 0, 틀린 예시 0, 이유 없는 중복 의심 0. 표식 함수 개수 = 234 − 합친 수 (+ 이번에 새로 만든 검사 함수).
- **Pass criterion**: 종료 코드 0, 개수 줄이 위 식과 맞는다.

### T10. 진짜 중복은 합쳐지고 동작은 그대로

- **Setup**: 채우기 중 합친 짝 목록(결정 기록에 남김).
- **Run**: 합친 함수를 쓰던 기능들의 시험을 포함한 코어 시험 전체.
- **Expected**: 전부 통과. 합친 함수 각각에 대해 경계 입력 묶음의 출력이 합치기 전 두 함수와 같다(합치기 전 출력을 기록해 두고 비교).
- **Pass criterion**: 시험 실패 0, 출력 비교 차이 0.

### T11. 구현 규약이 차례부터 읽게 한다

- **Setup**: work · codegen 규약 파일.
- **Run**: 규약에서 '새 함수 전에 차례 → 해당 종류 파일' 단계와 사전 경로를 찾는다.
- **Expected**: 두 규약 모두에 그 단계가 있고, 경로가 실제 생성 위치와 같다.
- **Pass criterion**: 두 규약에서 찾음, 경로가 존재하는 파일.

### T12. CI 에 연결 · 시간

- **Setup**: 이 계획의 PR.
- **Run**: CI.
- **Expected**: 사전 어긋남 · 중복 의심이 있으면 CI 실패(시험 PR 커밋에서 한 번 일부러 확인 후 되돌림). 검사 추가로 늘어난 시간 측정.
- **Pass criterion**: 일부러 넣은 중복에서 CI 빨강, 되돌리면 초록. 늘어난 시간 ≤ 30초(숫자로 보고).

### T13. 맥 · 리눅스 같은 결과

- **Setup**: T1–T9.
- **Run**: 맥(bash 3.2) · 리눅스 CI 양쪽.
- **Expected**: 생성 사전이 바이트까지 같고 판정이 같다.
- **Pass criterion**: 두 운영체제에서 같은 결과.

## How to run

```bash
bash core/tests/test-pure-catalog.sh
```

- T1–T13 전부 통과.
- 기존 순수 검사 시험이 그대로 통과(불변 조건 1).
