# 다시 쓰기는 가이드만 — 항목 표 · 낱말 규칙을 없애고 가이드 셋을 넣는다

## Summary

사람의 요청을 다시 쓸 때 개입하는 것을 그 모델의 공식 프롬프트 가이드 하나로 줄인다.
SCV 가 골라 만든 항목 표와의 1:1 견주기, SCV 가 지은 낱말 규칙 15개를 없애고, 다시 쓴 요청 끝에 붙던 SCV 원칙은 답(output) 쪽 안내로 옮긴다.
가이드가 없던 세 모델(Fable 5.2 · Sonnet 5.5 · Haiku 5.5)의 가이드를 래퍼에 넣는다.

근거: 실제 요청 60개로 잰 결과, 항목 표가 있든 없든 일이 사용자 뜻대로 가는 정도는 같았다(0.79 대 0.79 · 0.85 대 0.83 · 0.86 대 0.86).
결과가 같으므로 "input 에는 가이드만, SCV 는 output 만 강제"라는 원칙과 매 턴의 수고로 고른다. 측정 기록: `scv/raw/20261110-research-guide-table-measure.md`.

## Goals / Non-Goals

- **Goals**
  - G1. 등록은 "다시 쓴 요청" 한 줄과 "범위" 한 줄만 받는다. 항목 표와 견주는 단계가 없다.
  - G2. 낱말 규칙(R1–R15 · 허용 동사 · 금지 낱말 · 용어)을 없앤다 — 문서, 도움말이 싣는 `STE:` 줄, 설정, 시험.
  - G3. SCV 원칙을 다시 쓴 요청에서 뗀다(끝의 표식, 등록 때 실리던 전문). 내용 셋은 매 턴 답 모양 안내가 실리는 자리로 옮긴다. 문구는 그대로다.
  - G4. 래퍼(클로드 코드)에 Fable 5.2 · Sonnet 5.5 · Haiku 5.5 가이드 원문 사본을 넣는다. 받기 스크립트가 받을 대상을 고를 수 있게 한다.
  - G5. 래퍼의 가이드 검사가 항목 표를 요구하지 않게 하고, 항목 표 파일 7개를 지운다.
  - G6. 가이드가 없는 모델은 공통 가이드 발췌를 읽고 다시 쓴다(지금은 아무것도 읽지 않는다).
- **Non-Goals**
  - 권장 effort 를 묻는 일(따로 계획한다).
  - 답 모양 같은 output 규칙의 내용을 바꾸는 일.
  - SCV 자신의 안내문 · 절차 문서의 다른 부분(금지 규칙 · 물음 자리 · 위임 지시).
  - 코덱스 래퍼에 가이드를 넣는 일. 코어 변경(G1–G3 · G6)은 코덱스에도 함께 적용된다.
  - 공통 가이드 전문을 읽히는 일(측정에서 발췌보다 나은 점이 없었다).
  - 다시 쓰기 자체를 없애는 일(측정으로 가릴 수 없었다).
  - 순수함수 성능 계획.

## Approach Overview

지금 한 턴의 흐름은 "훅이 안내문을 붙임 → 모델이 요청을 항목 표와 견줘 다시 씀 → 등록 → 답 맨 위에 인용"이다.
이 계획은 그 가운데 "항목 표와 견줌"과 "낱말 규칙대로 씀"을 빼고, 나머지 장치(등록 · 인용 · 쓰기 문 · 종료 훅)는 그대로 둔다.

코어에서 고치는 것:
- `core/scripts/lib/model-prompting.sh` — 등록 검사(`scv_mp_register_problems`)가 다시 쓴 요청과 범위만 요구한다. 매 턴 안내문(`scv_mp_turn_block`)에서 항목 문구를 뺀다. 표식을 붙이던 자리(`scv_mp_rewrite_tagged`)를 뗀다. 안 쓰게 되는 순수함수(`scv_mp_checklist_merge` 등)는 지우고 순수함수 목록을 다시 만든다.
- `core/scripts/model-prompting.sh` — `register` 가 옛 모양(항목 줄 포함)도 받아 준다. `checklist` 명령은 옛 호출이 깨지지 않게 "항목 표 없음" 한 줄을 낸다. 가이드 없는 모델에 공통 발췌를 가리킨다.
- `core/protocols/help/prompt-refine.md` — 2 · 3단계를 "그 모델의 가이드대로 다시 쓴다"로 고친다.
- `core/contracts/rewrite-ste.md` 삭제. `core/contracts/rewrite-principle.md` 는 문구를 두고 "어디에 실리는지"만 고친다.
- `core/template/scv/scv_settings.example.json` — `SCV_REWRITE_STE` 를 빼고 `SCV_REWRITE_PRINCIPLE` · `SCV_MODEL_PROMPTING` 설명을 고친다. 옛 값이 설정에 남아 있어도 오류가 없다.
- `core/contracts/guard.md` · 훅(`on-user-prompt.sh` · `on-stop.sh`) — 문구와 원칙이 실리는 자리.
- 시험: `test-rewrite-ste.sh` 삭제, `test-model-prompting.sh` · `test-rewrite-stays-current.sh` · `test-help-first.sh` · `test-choice-questions-*.sh` · `test-rule-constitution.sh` · `test-instruction-diet.sh` 를 새 모양에 맞춘다.

래퍼(`../scv-claude-code`)에서 고치는 것:
- `prompting/INDEX.tsv` 에 세 줄, 원문 사본 셋. `prompting/refresh.sh` 가 키 목록을 받으면 그 줄만 받는다.
- `prompting/check.sh` 에서 항목 표 검사를 뺀다. `checklist-*.tsv` 7개를 지운다. `excerpt-best-practices.sections` 의 머리말(발췌 기준)을 고친다 — 구역 여섯은 그대로 둔다.
- 래퍼 시험 가운데 항목 표에 기대는 것을 맞춘다.

순서: 코어를 먼저 내고(0.88.0), 래퍼가 그 판을 받아 가이드 셋과 함께 낸다. 래퍼의 판 번호와 내보내기는 구현을 시작할 때 사용자에게 묻는다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  scv_mp_register_normalize,   // 제출 글 → 세 칸으로 맞춘 제출
  scv_mp_register_problems,    // 제출 → 문제 줄들(없으면 통과)
  scv_mp_register_rewrite,     // 제출 → 다시 쓴 요청 한 줄
  scv_mp_scope_forbid,         // 범위 값 → 변경을 막는 문구(없으면 빈 값)
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `scv_mp_turn_block` | 매 턴 안내문을 만든다. 항목 문구가 빠진다 | 스위치 · 턴 표 · 모델 · 명령 → 안내문 | 순수 (고침) |
| 2 | `scv_mp_register_normalize` | 제출한 글을 세 칸으로 맞춘다 | 제출 글 → 맞춘 제출 | 순수 (그대로) |
| 3 | `scv_mp_register_problems` | 다시 쓴 요청과 범위가 있는지 본다. 다른 줄은 무시한다 | 제출 → 문제 줄들 | 순수 (고침) |
| 4 | `scv_mp_register_rewrite` | 다시 쓴 요청을 꺼낸다 | 제출 → 다시 쓴 요청 | 순수 (그대로) |
| 5 | `scv_mp_scope_forbid` | 범위가 변경을 막는지 본다 | 범위 값 → 막는 문구 | 순수 (그대로) |
| 6 | `scv_mp_write_gate` | 파일 쓰기를 받을지 정한다 | 턴 표 · 등록 · 답 기록 → 판정 | 순수 (그대로) |
| 7 | `scv_mp_principle_text` | SCV 원칙의 글을 낸다. 실리는 자리만 output 안내로 바뀐다 | 원칙 문서 · 언어 → 원칙 글 | 순수 (그대로) |
| 8 | `scv_mp_guide_lines` | 읽을 가이드 파일을 고른다. 가이드 없는 모델에는 공통 발췌를 낸다 | 색인 · 모델 → 가이드 줄들 | 순수 (고침) |
| 9 | `rf_pick_rows` | 받을 색인 줄을 고른다 (래퍼, 새 함수 — 이름은 제안) | 색인 줄 · 키 목록 → 받을 줄 | 순수 (새로) |
| 10 | 등록 기록 쓰기 · 원문 받기 | 턴 폴더에 등록을 쓰고, 래퍼는 원문을 내려받는다 | — | 부수효과 (출구) |

- 부수효과 위치: `model-prompting.sh register` 가 턴 폴더에 쓰는 자리, 훅이 안내문을 내는 자리, 래퍼 `refresh.sh` 가 내려받아 쓰는 자리.
- 재사용: 2 · 4 · 5 · 6 · 7 은 지금 함수를 그대로 쓴다. 지우는 것: `scv_mp_checklist_merge`, 표식 관련 함수(`scv_mp_principle_tag` · `scv_mp_rewrite_tagged`)는 쓰는 곳이 없어지면 지운다.

## Guardrails

- 사용자가 친 글을 가리거나 바꾸지 않는다. 다시 쓴 요청은 지금처럼 답 맨 위에 그대로 보인다.
- 등록 · 인용 · 쓰기 문 · 종료 훅의 동작은 지금과 같다. 달라지는 것은 등록이 받는 줄 수뿐이다.
- 범위 한 줄은 남긴다. 다시 쓰기에 쓰는 값이 아니라 "이 턴에 파일을 바꾸는가"를 기계가 가리는 값이다.
- SCV 원칙의 세 내용은 문구를 그대로 옮긴다. 해로운 변경 규칙과, 끝 메시지의 문제 표를 막는 종료 훅 검사는 남는다.
- 옛 모양 등록(항목 줄이 든 제출)이 와도 실패하지 않는다. 코어가 먼저 나가고 래퍼가 뒤따르는 사이에도 세션이 깨지지 않게.
- `SCV_MODEL_PROMPTING=off` 의 동작은 지금과 같다.
- 매 턴 안내문의 분량은 지금보다 늘지 않는다. 코덱스의 턴 글은 약 100B 더 크므로 분량 한도 시험을 그쪽 기준으로도 본다.
- 맥 기본 bash 3.2 와 리눅스 양쪽에서 같게 돈다. 코어에 호스트 이름을 넣지 않는다.
- 기존 가이드 원문 사본 7개는 다시 받지 않는다.
- 래퍼 저장소에서 이상한 것(모르는 브랜치 · 추적 안 되는 파일)을 보면 작업하지 않고 묻는다.

## Exit criteria

- TESTS.md 의 시나리오가 모두 통과한다.
- 전체 시험이 bash 5 와 bash 3.2 에서 통과한다(4개씩 나눠 돌린다).
- Fable 5.2 세션에서 도움말이 그 모델의 가이드 파일을 읽으라고 가리킨다(이 저장소 세션으로 직접 확인).
- 같은 요청 3개를 바꾸기 전과 뒤에 다시 쓴 글을 나란히 사용자에게 보였다.

## Suggested path

1. 등록이 다시 쓴 요청과 범위만 요구하게 고치고 옛 모양도 받게 한다 — `scv_mp_register_problems`
2. 매 턴 안내문과 다시 쓰기 규약에서 항목 표 문구를 뺀다 — `scv_mp_turn_block`
3. 낱말 규칙을 없앤다(문서 · 도움말이 싣는 줄 · 설정 · 시험) — 낱말 규칙에 걸린 파일을 지우고 맞춘다
4. SCV 원칙을 다시 쓴 요청에서 떼고 답 모양 안내 자리로 옮긴다 — `scv_mp_principle_text`
5. 가이드가 없는 모델에 공통 발췌를 가리킨다 — `scv_mp_guide_lines`
6. 바뀐 순수함수의 예시와 목록을 다시 만들고 코어 시험을 맞춘다 — 순수성 검사 · 목록 검사 · 관련 시험 실행
7. 같은 요청 3개를 바꾸기 전 · 뒤로 다시 써서 사용자에게 보인다 — 전후 글을 나란히 보여 확인받는다
8. 코어를 낸다(0.88.0) — 전체 시험 뒤 PR 과 릴리스
9. 래퍼에 받을 대상 고르기를 더하고 가이드 셋을 받는다 — `rf_pick_rows`, `등록 기록 쓰기 · 원문 받기`
10. 래퍼의 가이드 검사에서 항목 표를 빼고 항목 표 파일 7개를 지운다 — 가이드 검사와 래퍼 시험 실행
11. 래퍼를 낸다 — 판 번호와 내보내기를 사용자에게 물은 뒤 릴리스

## Risks / Open Questions

- 항목 표 없이 다시 쓴 글도 요청에 없는 말을 보탠다. 측정에서 40번 중 33~35번이었고 표가 있을 때(34~38번)와 비슷했다.
- 일의 결과가 나아진다는 증거는 없다. 같다는 것까지만 쟀다. 실제로 코드를 고친 결과는 재지 못했다.
- 측정은 모델 하나(Opus 5.5) · 프로젝트 하나(slay)의 요청 60개다. 다른 모델에서 같은지는 모른다.
- 범위 한 줄을 남기는 것은 이 계획을 쓴 쪽이 정했다. "input 에는 가이드만"에 어긋난다고 보면 빼야 하고, 그러면 '변경 없음' 쓰기 문도 함께 사라진다.
- 낱말 규칙의 "뜻을 지키는 규칙 7개"도 함께 없어진다. 남는 것은 "요청에 없는 요구를 보태지 않는다" 한 줄과 답 맨 위 인용이다. 기계가 뜻의 차이를 가릴 수는 없다.
- 발췌의 구역 여섯은 항목 표의 인용이 든 곳으로 골랐던 것이다. 표를 없앤 뒤에는 "다시 쓰기에 쓰는 구역"이라는 설명만 남고, 고르는 기준이 기계로 확인되지 않는다.
- 가이드가 없는 모델(코덱스 쪽 일부 포함)은 공통 발췌만 읽고 다시 쓴다.
- Sonnet 5.5 · Haiku 5.5 세션이 실제로 어떤 모델 이름을 보내는지 확인하지 못했다. Fable 5.2 는 `claude-fable-5-2` 로 확인했다.
- 코덱스 래퍼의 가이드가 어디에 있는지 이 컴퓨터에서 찾지 못했다. 코어 변경이 코덱스 시험에 주는 영향은 구현 때 확인한다.
- 옛 래퍼(항목 표가 있는 판)와 새 코어가 함께 도는 동안, 래퍼의 가이드 검사는 래퍼 안에서만 돌므로 깨지지 않을 것으로 본다(추정).
- 리눅스 컴퓨터에 같은 주제의 옛 계획 파일 둘이 커밋되지 않은 채 남아 있다. 이 계획이 그것을 대신한다.
