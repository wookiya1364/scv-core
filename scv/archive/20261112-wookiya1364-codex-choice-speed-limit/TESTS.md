# Test Plan — 코덱스 쪽에서만 걸리는 선택 답 속도 한도 고치기

## Overview

턴 끝 검사 시험의 T12(선택 답 17개 적기)가 코덱스 검사 환경에서만 2초 한도에 걸친다. 재 보니 원인은 시험이 남긴 배경 프로그램이었다. 실행기가 시험이 끝날 때마다 남은 프로그램을 끝내는지, 그래도 시험의 결과는 그대로인지, 실제 검사 환경에서 T12 가 빨라지는지 확인한다.

2026-11-12 사용자 선택("실행기가 뒷정리")으로 처음의 T3 · T4(배수 판정)를 뒷정리 확인으로 바꿨다.

## Test scenarios

### T1. 코덱스 검사 환경에서 재기

- **Setup**: 코덱스 저장소의 측정용 브랜치. 가져온 코어의 선택 답 기록 명령을 그대로 쓴다.
- **Run**: 검사 환경에서 갓 띄운 러너와 모든 시험을 돌린 뒤, 두 상태에서 빈 명령 17번 · 선택 답 17번을 여섯 번씩 잰다.
- **Expected**: 실행 기록에 두 상태의 값(ms)과 그때 돌고 있던 프로그램 목록이 남는다.
- **Pass criterion**: 두 상태의 값과 결론("시험이 남긴 배경 프로그램")이 PLAN.md 의 표에 적혀 있다.

### T2. 시험이 남긴 프로그램이 0개가 된다

- **Setup**: 가짜 시험 셋이 300초짜리 프로그램을 둘씩 남긴다(하나는 바로, 하나는 한 겹 안에서). 옛 셸(3.2)과 새 셸(5).
- **Run**: 실행기로 그 폴더를 돌린다 (`--jobs 2`).
- **Expected**: 실행기가 끝난 뒤 남긴 프로그램 6개가 모두 없다.
- **Pass criterion**: 두 셸에서 `✓ T14 가짜 시험 셋이 남긴 프로그램 6개가 실행기가 끝난 뒤 0개` 줄.

### T3. 시험의 결과는 그대로다

- **Setup**: T2 의 가짜 시험 가운데 하나는 종료 코드 7로 끝나고, 하나는 혼자 도는 시험이다. 남기지 않는 시험 하나를 더 둔다.
- **Run**: T2 와 같은 실행.
- **Expected**: 실행기의 종료 코드는 0이 아니고, 마지막 줄에 `pass=3 fail=1`, 표에 실패한 시험의 이름이 있다.
- **Pass criterion**: 두 셸에서 `✓ T14 뒷정리를 해도 시험의 종료 코드는 그대로 (통과 3 · 실패 1)` 줄.

### T4. 끝낸 것이 있으면 로그에 한 줄

- **Setup**: T2 와 같다.
- **Run**: T2 와 같은 실행.
- **Expected**: 실패한 시험의 로그 끝에 `시험이 끝난 뒤 남은 프로그램 N개를 끝냈다` 줄이 있다.
- **Pass criterion**: 두 셸에서 `✓ T14 끝낸 것이 있으면 그 시험의 로그에 한 줄이 남는다` 줄.

### T5. 고치기 전 실행기로는 T2 가 실패한다

- **Setup**: 실행기만 고치기 전 것으로 되돌린다(시험 파일은 새 것).
- **Run**: `bash core/tests/test-run-focused.sh`
- **Expected**: T2 · T4 의 줄이 두 셸에서 실패한다 — `T14 남긴 것 6 개 중 6 개가 살아 있다`.
- **Pass criterion**: `PASS=35 FAIL=4`. 확인 뒤 실행기를 새 것으로 되돌린다.

### T6. 실제 시험이 남기던 것이 없어진다

- **Setup**: 이 맥. 드림 자동 실행을 8개 남기던 실제 시험(`test-rewrite-stays-current.sh`).
- **Run**: 그 시험을 실행기로 돌리고(`--also` 로 그 파일만), 끝난 직후 `dreams.sh --auto` 프로세스를 센다.
- **Expected**: 실행기가 끝난 직후 0개. 시험은 통과한다.
- **Pass criterion**: 남은 프로세스 0개, 마지막 줄 `pass=1 fail=0`.

### T7. 코덱스 검사 환경에서 T12 가 갓 띄운 러너 수준이다

- **Setup**: 코덱스 저장소의 측정용 브랜치에 새 실행기를 넣는다.
- **Run**: 검사 환경에서 새 실행기로 가져온 코어 시험을 모두 돌린 뒤, 묶음 안의 T12 값과 그 뒤에 여섯 번 잰 값을 읽는다.
- **Expected**: 묶음 안의 T12 가 통과한다. 묶음 뒤에 남은 `dreams.sh --auto` 가 없다.
- **Pass criterion**: 묶음 안의 T12 가 1,300ms 미만(갓 띄운 러너에서 830 ~ 1,062ms, 고치기 전 묶음 안에서 2,163ms), 묶음 뒤 프로세스 목록에 `dreams.sh --auto` 0줄, 실행기 마지막 줄 `fail=0`.

### T8. 코덱스 검사 3번 연속 통과 (릴리스 때 확인)

- **Setup**: 네 계획 뒤의 코어 릴리스가 코덱스 래퍼에 실린 상태.
- **Run**: 코덱스 래퍼의 검사(동기화 PR · develop · 릴리스 PR).
- **Expected**: T12 가 세 번 모두 통과한다.
- **Pass criterion**: 세 실행의 기록에 `ok T12` 줄이 있고 `✖ T12` 줄이 없다. 이 계획 안에서는 확인하지 못하므로 릴리스 기록에 값을 적는다.

## How to run

```bash
bash core/tests/test-run-focused.sh
```

## Pass criteria

- `bash core/tests/test-run-focused.sh` 의 마지막 줄이 `test-run-focused: PASS=39 FAIL=0`, 종료 코드 0 (T2 ~ T4, 두 셸이 한 번에 돈다)
- T5: 고치기 전 실행기로 `PASS=35 FAIL=4`
- T6: 남은 프로세스 0개
- T7: 묶음 안의 T12 가 1,300ms 미만, 실행기 마지막 줄 `fail=0`
- PR 검사의 모든 항목이 `success`
- T8 은 릴리스 때 읽는다 — 그때까지 이 계획의 남는 확인으로 적어 둔다
