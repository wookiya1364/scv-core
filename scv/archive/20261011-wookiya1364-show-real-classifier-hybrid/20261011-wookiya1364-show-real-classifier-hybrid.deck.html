# 실사용 보고 판정기 둘 다 — 애매한 턴만 판정자에게, 토큰을 아끼며 늘 켜기

## Summary

규칙 판 판정기(계획 `20261011-wookiya1364-show-real-classifier-rules`)는 두 측정에서 잘못 잡는 일이 거의 없었지만(97턴 중 1개)
놓침이 남았다 — 첫 측정 15/17, 두 번째 11/20. 놓친 턴은 거의 모두 '실행 결과를 인용해 보인 뒤 물음표 없는 리뷰 부탁으로 끝난
턴'이었다('리뷰 부탁드립니다', '검토해 주세요 — 고칠 점이 있으면 …'). 이런 끝은 뜻을 읽어야 '이번 결과를 계속 · 고칠지 묻기'와
'끝난 뒤 따로 할 일 안내'가 갈린다. 그래서 확실한 턴은 규칙으로 정하고, 애매한 턴만 판정자(새 Claude)에게 묻는다. 옵션 없이 늘
켜되 토큰을 아낀다 — 끝 글 발췌만, 20턴씩 묶어, 답을 저장해 다시 묻지 않고, 기준을 넘는 가장 작은 모델로. 이 저장소 열흘 기록
(10-01 이후)에서 애매한 턴은 편집 턴 35개 중 11개였다(확인).

## Goals / Non-Goals

- **Goals**
  1. **규칙 단계 그대로**: 규칙 판의 판정 — 실행 출력을 인용해 보인 뒤(또는 보이며) 묻는 확인 창이나 끝 물음표 질문이 있으면
     보여 줌, 첫 편집 뒤 실행 · 인용 · 묻기가 없으면 아님 — 을 바꾸지 않는다.
  2. **애매한 턴 고르기**: 바뀐 턴 중 첫 편집 뒤 실행의 출력을 인용해 보였고, 인용한 확인 창이 없고, 끝 글이 물음표 질문이 아닌 턴.
  3. **판정자 단계**: 애매한 턴마다 '끝 글 마지막 부분(최대 1,500자) + 인용한 출력 몇 줄'만 모아 20턴씩 묶어 한 번 부르고, 턴마다
     예 · 아니오를 받는다. 질문은 정답 매기기의 질문과 같은 뜻(실제 결과를 보인 뒤 계속 · 고칠지를 물었나).
  4. **답 저장**: 답을 (세션 · 시각 · 끝 글 해시) 열쇠로 저장소 밖 사용자 캐시에 두어 같은 턴은 다시 묻지 않는다 — 다시 돌려도
     판정자 호출 0, 숫자 같음.
  5. **모델 고르기**: 개발용 표본에서 Haiku → Sonnet → Opus 순으로 정답과 맞대 기준을 넘는 가장 작은 모델을 고른다.
  6. **못 부를 때**: 판정자 명령이 없거나 · 한도 · 오류 · 깨진 응답이면 규칙 단계 숫자로 내고 '판정 못 한 턴 n개'를 적는다.
  7. **정답 매기기 고침**: 정답용 요약이 모델 글 하나를 1,500자에서 자르지 않게 한다(지금은 요약 전체는 자르지 않지만 글 하나는
     자른다 — 긴 끝 보고의 가운데를 판정자가 못 본다).
- **Non-Goals**
  - 실사용 보고(T10) 돌리기 — 기간과 판단 기준은 따로 정한다.
  - 매 턴 안내 문구 · 실체 보여 주기 계약 · 스위치 바꾸기.
  - 규칙 단계 다시 다듬기(규칙 판 그대로).
  - 코덱스 기록에서의 정확도(표본에 없다).

## Approach Overview

보고는 지금처럼 기록 읽기 → 턴 나누기 → 턴 판정(규칙 단계)으로 판정 줄을 만든다. 그다음 애매한 턴만 골라 끝 글 발췌와 인용한 출력
몇 줄로 짧은 묶음을 만들고, 저장된 답이 있는 턴은 빼고, 남은 턴만 20턴씩 판정자에게 한 번씩 묻는다. 받은 답을 판정 줄에 합쳐
기간별로 센다. 판정자 부르기는 파이프라인 끝의 얇은 효과부(입구 · 출구) 하나에 모으고, 고르기 · 발췌 · 저장된 답 찾기 · 합치기는
순수 단계로 둔다. 판정자는 도구 없이 · SCV 를 끈 채 · 예 · 아니오 배열만 답하게 부른다. 보고 글에는 판정자가 정한 턴 수와 판정 못 한
턴 수를 숫자로 더한다.

검증은 두 겹이다. 저장소 안에서는 가짜 판정자(정해진 답을 내는 명령)로 고르기 · 발췌 · 묶음 · 저장 · 못 부를 때 · 출력 모양을
검사한다 — 실제 모델은 부르지 않는다. 저장소 밖 측정 장치에서는 정답 매기기를 먼저 고치고, 개발용에서 모델을 고른 뒤, 아직 쓰지 않은
10-06 · 10-07 측정 기록으로 새 표본을 만들어 한 번 잰다. 기준과 절차는 표본을 열기 전에 측정 기준 문서에 고정한다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  scv_show_real_entries,    // 기록 JSONL 줄 → 사건 줄 + 실행 출력 조각                     (그대로)
  scv_show_real_split,      // 사건 줄 → 사람 턴 줄 (Q · q 표시)                              (그대로)
  scv_show_real_classify,   // 턴 줄 → 판정 줄 (규칙 단계)                                    (그대로)
  (새) 애매한 턴 고르기,      // 판정 줄 + 턴 줄 → 애매한 턴의 발췌 목록 (열쇠 · 끝 글 발췌 · 인용 출력)
  (새) 저장된 답 찾기,        // 발췌 목록 + 저장된 답 → 이미 답 있는 턴 · 물을 턴
  (새) 판정자 부르기,         // 물을 턴 → 답 (20턴씩)                                        ← 부수효과
  (새) 답 합치기,            // 판정 줄 + 답 → 최종 판정 줄 + 판정 못 한 턴 수
  scv_show_real_count,      // 판정 줄 + 기간 → 기간별 수                                      (그대로)
  scv_show_real_render,     // 수 → 보고 글 (+ 판정자가 정한 턴 · 판정 못 한 턴)
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | 기록 읽기 · 턴 나누기 · 턴 판정 | 기록 줄 → 판정 줄 | 순수 (그대로) |
| 2 | 애매한 턴 고르기 | 판정 줄 + 턴 줄 → 발췌 목록 | 순수 |
| 3 | 저장된 답 찾기 | 발췌 목록 + 저장된 답 → 답 있는 턴 · 물을 턴 | 순수 (저장 파일 읽기는 입구) |
| 4 | 판정자 부르기 | 물을 턴 → 답 | 부수효과 (판정자 명령 · 저장 파일 쓰기) |
| 5 | 답 합치기 | 판정 줄 + 답 → 최종 판정 줄 | 순수 |
| 6 | 기간별 세기 · 글로 내기 | 판정 줄 → 보고 글 | 순수 · 출구 |

- 부수효과 위치: 보고 스크립트의 입구(기록 · 저장된 답 읽기)와 끝의 판정자 부르기(명령 실행 · 저장 파일 쓰기) · 화면 출력.
- 재사용: 기록 읽기 · 턴 나누기 · 턴 판정 · 출력 인용 판정 · 기간별 세기는 규칙 판 그대로.

## Guardrails

- frontmatter `invariants:` 다섯을 지킨다.
- 규칙 단계의 판정은 규칙 판과 같다 — 애매한 턴의 보여 줌만 판정자 답으로 바뀐다. 규칙 판의 검사는 그대로 통과해야 한다.
- 판정자에게는 애매한 턴의 끝 글 발췌(최대 1,500자)와 인용한 출력 몇 줄만 보낸다 — 턴 전체 · 다른 턴 · 사람 메시지는 보내지 않는다.
- 판정자는 도구 없이 · SCV 를 끈 채 부른다. 저장 파일에는 열쇠(해시)와 답만 두고 대화 내용은 두지 않으며, 저장소 밖에 둔다.
- 기준 · 절차(정답 매기기 고침 포함) · 모델 순서는 표본을 열기 전에 측정 기준 문서에 고정하고, 결과를 본 뒤 바꾸지 않는다. 새 표본은
  한 번만 잰다.
- 판정자 입력은 애매한 턴당 평균 2천 토큰 안 — 판정자 응답의 사용량 기록으로 잰다.
- 모델 비교 · 정답 매기기 · 측정에 판정자 호출이 수백 번 든다 — 시작 전 주간 사용량을 보고, 한도에 닿으면 멈춘다.

## 예외처리 (Edge cases)

- **끝 글이 1,500자보다 김**: 끝부분만 보낸다 — 묻는 말은 끝에 있다.
- **판정자 응답이 깨짐(배열이 아님 · 수가 안 맞음)**: 그 묶음의 턴은 판정 못 한 턴으로 센다.
- **판정자 명령 없음 · 한도 안내 · 오류**: 규칙 단계 숫자로 내고 판정 못 한 턴 수를 적는다 — 보고는 멈추지 않는다.
- **같은 턴의 끝 글이 바뀜**: 해시가 달라 다시 묻는다.
- **새 표본 후보에 '보이고 물음'이 20개가 안 됨**: 후보를 늘리고, 바닥나면 있는 만큼 — 기준은 그대로.

## Exit criteria

- All TESTS.md scenarios pass (맥 · 리눅스 CI).
- 새 표본(남은 10-06 · 10-07 기록)을 한 번 잰 결과가 잘못 잡음 0 · '보이고 물음'의 90% 이상 · 규칙 단계 시간 2배 미만 ·
  판정자 입력 애매한 턴당 평균 2천 토큰 안이다.
- 하나라도 못 넘으면 멈추고 보고한다 — 다음 길은 사용자와 정한다.

## Suggested path

1. 정답 매기기 고침(모델 글 1,500자 잘림 없앰)과 기준 · 절차 · 모델 순서를 측정 기준 문서에 고정한다.
2. 새 표본: 남은 10-06 · 10-07 바뀐 턴 106개에서 후보를 뽑아 고친 판정으로 정답 → '보이고 물음' 20 · '아님' 20(내용은 열지 않음).
3. 개발용(예전 표본 40턴)도 고친 판정으로 다시 매긴다 — 판정자 단계 개발과 모델 비교에 쓴다.
4. 애매한 턴 고르기 · 저장된 답 찾기 · 묶어 부르기 · 답 합치기와 보고 표시를 구현하고, 가짜 판정자로 검사를 더한다.

# Test Plan — 실사용 보고 판정기 둘 다 — 애매한 턴만 판정자에게, 토큰을 아끼며 늘 켜기

## Overview

규칙 단계는 규칙 판 그대로 두고, 결과를 보인 뒤 물음표 없이 끝난 애매한 턴만 판정자에게 묻는 실사용 보고를 확인한다. 저장소 안의
검사는 가짜 판정자(정해진 답을 내는 명령)로 고르기 · 발췌 · 묶음 · 저장된 답 · 못 부를 때 · 출력 모양 · 두 bash 의 같은 결과를 본다 —
실제 모델은 부르지 않는다. 저장소 밖에서는 정답 매기기를 고친 뒤 개발용에서 모델을 고르고, 남은 10-06 · 10-07 기록으로 만든 새
표본을 한 번 잰다. 기준과 절차는 표본을 열기 전에 고정한다.

## Test scenarios

### T1. 끄면 같음

- **Setup**: 임시 저장소, 설정 `SCV_SHOW_REAL=off`.
- **Run**: 매 턴 훅 출력을 이 계획 전 코어와 바이트로 비교한다.
- **Expected**: 같다.
- **Pass criterion**: 차이 0.

### T2. 규칙 단계 그대로

- **Setup**: 규칙 판 검사 — 경우 13개, 고정 기록 10개, 인용 판정 단위 11개.
- **Run**: 판정자 단계를 더한 판으로 돌린다(애매한 턴이 없는 경우들).
- **Expected**: 규칙 판과 같은 결과.
- **Pass criterion**: 규칙 판 검사 전부 통과.

### T3. 애매한 턴 고르기

- **Setup**: 고정 기록 넷 — (가) 결과를 인용해 보인 뒤 '리뷰 부탁드립니다'로 끝, (나) 결과를 인용한 확인 창, (다) 첫 편집 뒤 실행 없음,
  (라) 결과를 보인 뒤 물음표 질문으로 끝.
- **Run**: 고르기 단계를 돌린다.
- **Expected**: (가)만 애매한 턴. (나) · (라)는 규칙으로 보여 줌, (다)는 규칙으로 아님.
- **Pass criterion**: 고른 턴이 (가) 하나.

### T4. 발췌 — 끝 글과 인용한 출력만

- **Setup**: 애매한 턴의 끝 글을 3,000자로(앞쪽에 심은 글), 같은 세션의 다른 턴 · 사람 메시지에도 심은 글.
- **Run**: 판정자에게 보낼 묶음을 만든다.
- **Expected**: 끝 글의 마지막 1,500자와 인용한 출력 줄만 들어 있다.
- **Pass criterion**: 심은 글(끝 글 앞쪽 · 다른 턴 · 사람 메시지)이 묶음에 0번.

### T5. 20턴씩 묶어 부르기

- **Setup**: 애매한 턴 45개인 기록, 부른 횟수를 세는 가짜 판정자.
- **Run**: 보고를 돌린다.
- **Expected**: 가짜 판정자 3번(20 · 20 · 5턴).
- **Pass criterion**: 부른 횟수 3, 묶음 크기 20 · 20 · 5.

### T6. 저장된 답

- **Setup**: T5 기록과 가짜 판정자.
- **Run**: 보고를 두 번 돌리고, 한 턴의 끝 글을 바꿔 한 번 더 돌린다.
- **Expected**: 두 번째는 판정자 0번 · 숫자 같음, 세 번째는 바뀐 턴 하나만 묻는다.
- **Pass criterion**: 부른 횟수 0 → 1(턴 1개), 두 번째 보고 글이 첫 번째와 같다.

### T7. 판정자를 못 부를 때

- **Setup**: 가짜 판정자를 넷으로 — 명령 없음, 오류로 끝남, 깨진 응답(배열 아님 · 수가 안 맞음), 한도 안내.
- **Run**: 보고를 돌린다.
- **Expected**: 보고가 끝까지 나오고, 애매한 턴은 규칙 단계 값(보여 주지 않음)으로 세며 '판정 못 한 턴 n개'가 나온다.
- **Pass criterion**: 종료 코드 0, 판정 못 한 턴 수가 애매한 턴 수와 같다.

### T8. 보고 출력

- **Setup**: 애매한 턴이 있는 고정 기록, 가짜 판정자.
- **Run**: 보고를 돌린다.
- **Expected**: 숫자 · 날짜만 — 판정자가 정한 턴 수 · 판정 못 한 턴 수가 따로 보이고, 기록 문장 · 실행 출력은 나오지 않는다.
- **Pass criterion**: 심은 글이 보고 글에 0번, 두 수가 손으로 센 값과 같다.

### T9. 저장 파일

- **Setup**: T6 뒤의 저장 파일.
- **Run**: 저장 파일을 읽는다.
- **Expected**: 열쇠(해시)와 답만, 저장소 밖 사용자 캐시 위치.
- **Pass criterion**: 심은 글 0번, 파일이 저장소 안에 없다.

### T10. 맥 기본 bash 3.2 와 지금 bash 가 같은 결과

- **Setup**: T3 ~ T8 의 고정 기록, 가짜 판정자.

- **Setup**: 같은 기록 묶음(측정 장치) · 많은 턴 세션(저장소 검사).
- **Run**: 이 계획 전 코어와 새 코어로 규칙 단계까지 돌려 시간을 잰다(맥 기본 bash 3.2). 판정자 시간은 따로 잰다.
- **Expected**: 규칙 단계 시간 비 2 미만, 600턴 세션이 상한 안.

# 실사용 보고 판정기 둘 다 — 애매한 턴만 판정자에게, 토큰을 아끼며 늘 켜기

## Summary

규칙 판 판정기(계획 `20261011-wookiya1364-show-real-classifier-rules`)는 두 측정에서 잘못 잡는 일이 거의 없었지만(97턴 중 1개)
놓침이 남았다 — 첫 측정 15/17, 두 번째 11/20. 놓친 턴은 거의 모두 '실행 결과를 인용해 보인 뒤 물음표 없는 리뷰 부탁으로 끝난
턴'이었다('리뷰 부탁드립니다', '검토해 주세요 — 고칠 점이 있으면 …'). 이런 끝은 뜻을 읽어야 '이번 결과를 계속 · 고칠지 묻기'와
'끝난 뒤 따로 할 일 안내'가 갈린다. 그래서 확실한 턴은 규칙으로 정하고, 애매한 턴만 판정자(새 Claude)에게 묻는다. 옵션 없이 늘
켜되 토큰을 아낀다 — 끝 글 발췌만, 20턴씩 묶어, 답을 저장해 다시 묻지 않고, 기준을 넘는 가장 작은 모델로. 이 저장소 열흘 기록
(10-01 이후)에서 애매한 턴은 편집 턴 35개 중 11개였다(확인).

## Goals / Non-Goals

- **Goals**
  1. **규칙 단계 그대로**: 규칙 판의 판정 — 실행 출력을 인용해 보인 뒤(또는 보이며) 묻는 확인 창이나 끝 물음표 질문이 있으면
     보여 줌, 첫 편집 뒤 실행 · 인용 · 묻기가 없으면 아님 — 을 바꾸지 않는다.
  2. **애매한 턴 고르기**: 바뀐 턴 중 첫 편집 뒤 실행의 출력을 인용해 보였고, 인용한 확인 창이 없고, 끝 글이 물음표 질문이 아닌 턴.
  3. **판정자 단계**: 애매한 턴마다 '끝 글 마지막 부분(최대 1,500자) + 인용한 출력 몇 줄'만 모아 20턴씩 묶어 한 번 부르고, 턴마다
     예 · 아니오를 받는다. 질문은 정답 매기기의 질문과 같은 뜻(실제 결과를 보인 뒤 계속 · 고칠지를 물었나).
  4. **답 저장**: 답을 (세션 · 시각 · 끝 글 해시) 열쇠로 저장소 밖 사용자 캐시에 두어 같은 턴은 다시 묻지 않는다 — 다시 돌려도
     판정자 호출 0, 숫자 같음.
  5. **모델 고르기**: 개발용 표본에서 Haiku → Sonnet → Opus 순으로 정답과 맞대 기준을 넘는 가장 작은 모델을 고른다.
  6. **못 부를 때**: 판정자 명령이 없거나 · 한도 · 오류 · 깨진 응답이면 규칙 단계 숫자로 내고 '판정 못 한 턴 n개'를 적는다.
  7. **정답 매기기 고침**: 정답용 요약이 모델 글 하나를 1,500자에서 자르지 않게 한다(지금은 요약 전체는 자르지 않지만 글 하나는
     자른다 — 긴 끝 보고의 가운데를 판정자가 못 본다).
- **Non-Goals**
  - 실사용 보고(T10) 돌리기 — 기간과 판단 기준은 따로 정한다.
  - 매 턴 안내 문구 · 실체 보여 주기 계약 · 스위치 바꾸기.
  - 규칙 단계 다시 다듬기(규칙 판 그대로).
  - 코덱스 기록에서의 정확도(표본에 없다).

## Approach Overview

보고는 지금처럼 기록 읽기 → 턴 나누기 → 턴 판정(규칙 단계)으로 판정 줄을 만든다. 그다음 애매한 턴만 골라 끝 글 발췌와 인용한 출력
몇 줄로 짧은 묶음을 만들고, 저장된 답이 있는 턴은 빼고, 남은 턴만 20턴씩 판정자에게 한 번씩 묻는다. 받은 답을 판정 줄에 합쳐
기간별로 센다. 판정자 부르기는 파이프라인 끝의 얇은 효과부(입구 · 출구) 하나에 모으고, 고르기 · 발췌 · 저장된 답 찾기 · 합치기는
순수 단계로 둔다. 판정자는 도구 없이 · SCV 를 끈 채 · 예 · 아니오 배열만 답하게 부른다. 보고 글에는 판정자가 정한 턴 수와 판정 못 한
턴 수를 숫자로 더한다.

검증은 두 겹이다. 저장소 안에서는 가짜 판정자(정해진 답을 내는 명령)로 고르기 · 발췌 · 묶음 · 저장 · 못 부를 때 · 출력 모양을
검사한다 — 실제 모델은 부르지 않는다. 저장소 밖 측정 장치에서는 정답 매기기를 먼저 고치고, 개발용에서 모델을 고른 뒤, 아직 쓰지 않은
10-06 · 10-07 측정 기록으로 새 표본을 만들어 한 번 잰다. 기준과 절차는 표본을 열기 전에 측정 기준 문서에 고정한다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  scv_show_real_entries,    // 기록 JSONL 줄 → 사건 줄 + 실행 출력 조각                     (그대로)
  scv_show_real_split,      // 사건 줄 → 사람 턴 줄 (Q · q 표시)                              (그대로)
  scv_show_real_classify,   // 턴 줄 → 판정 줄 (규칙 단계)                                    (그대로)
  (새) 애매한 턴 고르기,      // 판정 줄 + 턴 줄 → 애매한 턴의 발췌 목록 (열쇠 · 끝 글 발췌 · 인용 출력)
  (새) 저장된 답 찾기,        // 발췌 목록 + 저장된 답 → 이미 답 있는 턴 · 물을 턴
  (새) 판정자 부르기,         // 물을 턴 → 답 (20턴씩)                                        ← 부수효과
  (새) 답 합치기,            // 판정 줄 + 답 → 최종 판정 줄 + 판정 못 한 턴 수
  scv_show_real_count,      // 판정 줄 + 기간 → 기간별 수                                      (그대로)
  scv_show_real_render,     // 수 → 보고 글 (+ 판정자가 정한 턴 · 판정 못 한 턴)
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | 기록 읽기 · 턴 나누기 · 턴 판정 | 기록 줄 → 판정 줄 | 순수 (그대로) |
| 2 | 애매한 턴 고르기 | 판정 줄 + 턴 줄 → 발췌 목록 | 순수 |
| 3 | 저장된 답 찾기 | 발췌 목록 + 저장된 답 → 답 있는 턴 · 물을 턴 | 순수 (저장 파일 읽기는 입구) |
| 4 | 판정자 부르기 | 물을 턴 → 답 | 부수효과 (판정자 명령 · 저장 파일 쓰기) |
| 5 | 답 합치기 | 판정 줄 + 답 → 최종 판정 줄 | 순수 |
| 6 | 기간별 세기 · 글로 내기 | 판정 줄 → 보고 글 | 순수 · 출구 |

- 부수효과 위치: 보고 스크립트의 입구(기록 · 저장된 답 읽기)와 끝의 판정자 부르기(명령 실행 · 저장 파일 쓰기) · 화면 출력.
- 재사용: 기록 읽기 · 턴 나누기 · 턴 판정 · 출력 인용 판정 · 기간별 세기는 규칙 판 그대로.

## Guardrails

- frontmatter `invariants:` 다섯을 지킨다.
- 규칙 단계의 판정은 규칙 판과 같다 — 애매한 턴의 보여 줌만 판정자 답으로 바뀐다. 규칙 판의 검사는 그대로 통과해야 한다.
- 판정자에게는 애매한 턴의 끝 글 발췌(최대 1,500자)와 인용한 출력 몇 줄만 보낸다 — 턴 전체 · 다른 턴 · 사람 메시지는 보내지 않는다.
- 판정자는 도구 없이 · SCV 를 끈 채 부른다. 저장 파일에는 열쇠(해시)와 답만 두고 대화 내용은 두지 않으며, 저장소 밖에 둔다.
- 기준 · 절차(정답 매기기 고침 포함) · 모델 순서는 표본을 열기 전에 측정 기준 문서에 고정하고, 결과를 본 뒤 바꾸지 않는다. 새 표본은
  한 번만 잰다.
- 판정자 입력은 애매한 턴당 평균 2천 토큰 안 — 판정자 응답의 사용량 기록으로 잰다.
- 모델 비교 · 정답 매기기 · 측정에 판정자 호출이 수백 번 든다 — 시작 전 주간 사용량을 보고, 한도에 닿으면 멈춘다.

## 예외처리 (Edge cases)

- **끝 글이 1,500자보다 김**: 끝부분만 보낸다 — 묻는 말은 끝에 있다.
- **판정자 응답이 깨짐(배열이 아님 · 수가 안 맞음)**: 그 묶음의 턴은 판정 못 한 턴으로 센다.
- **판정자 명령 없음 · 한도 안내 · 오류**: 규칙 단계 숫자로 내고 판정 못 한 턴 수를 적는다 — 보고는 멈추지 않는다.
- **같은 턴의 끝 글이 바뀜**: 해시가 달라 다시 묻는다.
- **새 표본 후보에 '보이고 물음'이 20개가 안 됨**: 후보를 늘리고, 바닥나면 있는 만큼 — 기준은 그대로.

# Test Plan — 실사용 보고 판정기 둘 다 — 애매한 턴만 판정자에게, 토큰을 아끼며 늘 켜기

## Overview

규칙 단계는 규칙 판 그대로 두고, 결과를 보인 뒤 물음표 없이 끝난 애매한 턴만 판정자에게 묻는 실사용 보고를 확인한다. 저장소 안의
검사는 가짜 판정자(정해진 답을 내는 명령)로 고르기 · 발췌 · 묶음 · 저장된 답 · 못 부를 때 · 출력 모양 · 두 bash 의 같은 결과를 본다 —
실제 모델은 부르지 않는다. 저장소 밖에서는 정답 매기기를 고친 뒤 개발용에서 모델을 고르고, 남은 10-06 · 10-07 기록으로 만든 새
표본을 한 번 잰다. 기준과 절차는 표본을 열기 전에 고정한다.

## Test scenarios

### T1. 끄면 같음

- **Setup**: 임시 저장소, 설정 `SCV_SHOW_REAL=off`.
- **Run**: 매 턴 훅 출력을 이 계획 전 코어와 바이트로 비교한다.
- **Expected**: 같다.
- **Pass criterion**: 차이 0.

### T2. 규칙 단계 그대로

- **Setup**: 규칙 판 검사 — 경우 13개, 고정 기록 10개, 인용 판정 단위 11개.
- **Run**: 판정자 단계를 더한 판으로 돌린다(애매한 턴이 없는 경우들).
- **Expected**: 규칙 판과 같은 결과.
- **Pass criterion**: 규칙 판 검사 전부 통과.

### T3. 애매한 턴 고르기

- **Setup**: 고정 기록 넷 — (가) 결과를 인용해 보인 뒤 '리뷰 부탁드립니다'로 끝, (나) 결과를 인용한 확인 창, (다) 첫 편집 뒤 실행 없음,
  (라) 결과를 보인 뒤 물음표 질문으로 끝.
- **Run**: 고르기 단계를 돌린다.
- **Expected**: (가)만 애매한 턴. (나) · (라)는 규칙으로 보여 줌, (다)는 규칙으로 아님.
- **Pass criterion**: 고른 턴이 (가) 하나.

### T4. 발췌 — 끝 글과 인용한 출력만

- **Setup**: 애매한 턴의 끝 글을 3,000자로(앞쪽에 심은 글), 같은 세션의 다른 턴 · 사람 메시지에도 심은 글.
- **Run**: 판정자에게 보낼 묶음을 만든다.
- **Expected**: 끝 글의 마지막 1,500자와 인용한 출력 줄만 들어 있다.
- **Pass criterion**: 심은 글(끝 글 앞쪽 · 다른 턴 · 사람 메시지)이 묶음에 0번.

### T5. 20턴씩 묶어 부르기

- **Setup**: 애매한 턴 45개인 기록, 부른 횟수를 세는 가짜 판정자.
- **Run**: 보고를 돌린다.
- **Expected**: 가짜 판정자 3번(20 · 20 · 5턴).
- **Pass criterion**: 부른 횟수 3, 묶음 크기 20 · 20 · 5.

### T6. 저장된 답

- **Setup**: T5 기록과 가짜 판정자.
- **Run**: 보고를 두 번 돌리고, 한 턴의 끝 글을 바꿔 한 번 더 돌린다.
- **Expected**: 두 번째는 판정자 0번 · 숫자 같음, 세 번째는 바뀐 턴 하나만 묻는다.
- **Pass criterion**: 부른 횟수 0 → 1(턴 1개), 두 번째 보고 글이 첫 번째와 같다.

### T7. 판정자를 못 부를 때

- **Setup**: 가짜 판정자를 넷으로 — 명령 없음, 오류로 끝남, 깨진 응답(배열 아님 · 수가 안 맞음), 한도 안내.
- **Run**: 보고를 돌린다.
- **Expected**: 보고가 끝까지 나오고, 애매한 턴은 규칙 단계 값(보여 주지 않음)으로 세며 '판정 못 한 턴 n개'가 나온다.
- **Pass criterion**: 종료 코드 0, 판정 못 한 턴 수가 애매한 턴 수와 같다.

### T8. 보고 출력

- **Setup**: 애매한 턴이 있는 고정 기록, 가짜 판정자.
- **Run**: 보고를 돌린다.
- **Expected**: 숫자 · 날짜만 — 판정자가 정한 턴 수 · 판정 못 한 턴 수가 따로 보이고, 기록 문장 · 실행 출력은 나오지 않는다.
- **Pass criterion**: 심은 글이 보고 글에 0번, 두 수가 손으로 센 값과 같다.

### T9. 저장 파일

- **Setup**: T6 뒤의 저장 파일.
- **Run**: 저장 파일을 읽는다.
- **Expected**: 열쇠(해시)와 답만, 저장소 밖 사용자 캐시 위치.
- **Pass criterion**: 심은 글 0번, 파일이 저장소 안에 없다.

- **Setup**: T3 ~ T8 의 고정 기록, 가짜 판정자.
- **Run**: 시스템 bash 3.2 와 지금 bash 로 돌린다.
