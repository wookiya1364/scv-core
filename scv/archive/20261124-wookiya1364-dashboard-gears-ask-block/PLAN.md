# 대시보드에 기어 · 묻기 방식, 글로 묻기는 선택 창으로

## Summary

Claude 앱의 SCV 창(대시보드 모드)에는 0.100.0 · 0.101.0 에 넣은 기어와 0.97.0 에 넣은 묻기 방식이 전혀 나오지 않는다. 컨텍스트와 사용량은 '진행 중' 칸 안에만 있어서, 진행 중인 계획이 없으면 보이지 않는다. 이 계획은 창 위쪽에 컨텍스트 · 사용량 · 묻기 방식 · 기어 · 단계를 항상 보이게 하고, 나머지 칸은 '더 보기' 안에 접는다. 묻기 방식은 창에서 눌러 바로 바꾸고, 기어는 목록 · 하는 일 · 인자를 보고 창에서 쓸 수 있게 한다.

둘째 부분이 함께 있다(2026-11-24 사용자 요청). 다른 프로젝트의 실제 세션에서 SCV 가 선택 창을 부르지 않고 글로 물으며 턴을 끝내, 사용자가 채팅으로 직접 답해야 했다. 끝 답이 있는 134턴 중 12턴이 그랬다(첫 조사는 9턴으로 셌고, 다시 넣어 보니 3턴이 더 있었다). 그 12턴 중 10턴은 모델이 앱의 마무리 요약 도구에 질문과 버튼을 넣은 턴이었다. 턴 끝에서 잡으면 선택 창이 10~40초 늦게 떠서(사용자 확인 2026-11-24), 이 계획은 요약 도구를 부르는 자리에서 잡는다: 질문이 실린 호출을 거절하고 선택 창부터 부르게 한다. 끝 글이 나오기 전이라 늦어지지 않는다.

셋째로, 값이 필요한 기어를 값 없이 쓰려 하면 Claude 가 선택 창으로 값을 하나씩 안내한다. 지금 기어 규약에는 이 내용이 없어, 기본값으로 돌리거나 요청 글에서 짐작한다.

## Goals / Non-Goals

- **Goals**
  - (창 구성) 창 위쪽에 항상: 컨텍스트 · 사용량(5시간 · 7일) → 묻기 방식 → 기어 → 단계 흐름. 진행 중인 계획이 없어도 컨텍스트 · 사용량 · 묻기 방식 · 기어는 나온다.
  - (창 구성) 진행률 · 시험 결과 · 드림 · 변경 이력 · 뒤에서 도는 일 · 다음 할 일은 '더 보기' 안에 접는다. 접힘 상태는 다시 그려도 남는다. 막힌 작업은 있을 때만 접지 않고 위에 보인다.
  - (묻기 방식) 지금 값(전부 묻기 | 처음 · 끝에만 묻기)과 그 뜻 한 줄이 보인다. 고르면 본체의 설정 명령이 바로 불려 다음 메시지부터 바뀐다. 턴을 쓰지 않는다.
  - (기어) 기어마다 이름 · 받는 값 → 돌려주는 값 · 하는 일 · 인자(이름=기본값)가 보인다. 확인을 기다리는 기어 실행이 있으면 그 줄이 보인다.
  - (기어 쓰기) 모든 기어에 [쓰기]: 누르면 그 기어를 돌리는 명령이 입력창에 들어간다. 보내면 Claude 가 빠진 값을 선택 창으로 안내하고 돌린다.
  - (기어 쓰기) 부작용 표시가 하나도 없는 기어에는 [바로 실행]도: 창의 입력 칸에 넣은 값으로 30초 제한 안에서 돌리고, 결과를 그 칸에 보인다.
  - (본체) 기어 목록 파일에 '펼친 흐름에서 가장 센 표시' 칸을 더한다(pure | effect | outward | judge). 창은 이 칸으로 [바로 실행]을 붙일지 정한다.
  - (본체) 값 안내: 기어의 인자 · 입력값이 요청에 없으면 선택 창으로 묻는다. 인자마다 질문 하나, 기본값이 첫 보기, 보기는 톱니 사전의 인자 설명에서 만든다. 요청에 값이 있으면 묻지 않는다.
  - (본체) 가드의 새 규칙 S: 래퍼가 알려 준 닫는 요약 도구에 질문이 실려 오면 그 호출을 거절한다. 거절 이유는 "고를 것이면 선택 도구를 먼저 부르고, 요약 도구는 질문 없이 다시 불러라"다. 선택 도구가 없는 실행(호스트에 없음 · `SCV_CHOICE_GATE=off` · 사람 없는 실행)에서는 통과시킨다.
  - (본체) 턴 끝 검사는 0.101.0 그대로 둔다 — 글로 물으며 끝나면 다음 턴 알림만 남긴다.
  - (래퍼, 릴리스 때) Claude 래퍼의 훅 설정이 요약 도구 이름과 질문 칸을 넘긴다(`SCV_SUMMARY_ASK`). 이 값이 없으면 규칙 S 는 아무것도 하지 않는다.
  - (본체) 매 턴 안내에 "물을 것은 마무리 요약 도구보다 먼저 선택 창으로" 구절을 넣는다.
- **Non-Goals**
  - 릴리스(본체 · 래퍼 · 대시보드) — 사용자가 말할 때 한다. 릴리스 전에는 `release-ci` 기어를 맥 · 리눅스로 돌린다.
  - 묻기 방식 말고 다른 설정 스위치를 창에 넣는 일.
  - 보기 전용(미러) 세션에서 묻기 방식 · 기어를 누르는 일 — 미러에서는 값만 보인다.
  - 부작용 있는 기어를 창에서 바로 돌리는 일, 창에서 밖으로 나가는 톱니를 확인하는 일.
  - 턴 끝에서 턴을 잡아 두는 일 — 만들어 시험까지 했지만 선택 창이 늦게 떠서 걷어 냈다(사용자 선택 2026-11-24). 요약 도구 없이 글로만 물은 경우(12턴 중 2턴 꼴)는 지금처럼 다음 턴 알림만 남는다.
  - codex 쪽 화면 — 대시보드는 Claude 앱 모드다. 본체 변경은 codex 에도 들어가지만 codex 에서의 확인은 이 계획 밖이다.

## Approach Overview

**요약 도구에서 잡기.** 가드는 이미 모든 도구 호출 앞에서 돈다(help 먼저 규칙). 그 자리에 규칙 S 를 더한다. 래퍼가 `SCV_SUMMARY_ASK="<도구>=<질문 칸>"` 으로 요약 도구와 그 질문 칸을 알려 주고, 지금 부르는 도구가 그 도구이고 질문 칸이 비어 있지 않으면 거절한다. 거절 이유는 순수 함수 `scv_summary_ask_reason` 이 만들고, 선택 도구가 없는 실행인지는 기존 판단(`choice-gate.sh`)을 그대로 쓴다. 본체는 도구 이름도 칸 이름도 적지 않는다. 래퍼들이 요약 도구를 help 통과 목록에 넣어 두었으므로 규칙 S 는 그 목록보다 먼저 본다. 턴 끝 검사는 건드리지 않는다.

**값 안내.** `gear.sh ask <기어>` 가 그 기어를 쓸 때 정해야 할 값을 줄로 낸다: 인자 이름 · 기본값 · 설명 · 기어가 고정했는지, 그리고 표준 입력이 필요한지. 기어 규약 글이 Claude 에게 이 출력을 읽고, 요청에 없는 값만 선택 창으로 물으라고 정한다. 사람 없는 실행에서는 묻지 않고 기본값을 쓴다.

**기어 목록의 부작용 칸.** 목록 파일(`scv/gears/INDEX.tsv`)을 만드는 곳에서 기어의 흐름을 톱니까지 펼쳐 가장 센 표시를 9번째 칸에 적는다. 판단 단계(`@`)가 있으면 `judge` 다. 8칸짜리 예전 파일을 읽는 쪽은 그대로 돈다.

**창.** 그릴 때 프로젝트 설정 파일과 기어 목록 파일을 읽어 순수 함수로 줄을 만든다. 누를 때만 명령을 돌린다. 본체가 설치된 폴더는 Claude 의 설치 기록 파일에서 찾는다. 못 찾으면 묻기 방식 바꾸기는 입력창에 명령을 넣는 것으로 물러나고, [바로 실행]은 붙이지 않는다. 기어 목록 파일은 본체 실행기가 고쳐 쓰므로, 창은 기어 폴더가 목록 파일보다 새로우면 본체의 목록 명령을 한 번 불러 맞춘다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
// 요약 도구를 부를 때 (본체 가드)
flow(
  readToolCall,            // 훅 입력 → 도구 이름 · 질문 칸의 값                 (부수효과: 읽기)
  guardRuleS,              // (도구 이름, 질문 칸 값, 래퍼가 준 값) → 볼 것 | 넘김
  scv_summary_ask_reason,  // 선택 도구 이름 → 거절 이유 한 줄
  denyCall,                // 이유 → 거절 답                                      (부수효과: 쓰기)
)

// 기어 목록을 만들 때 · 값을 물을 때 (본체)
flow(
  readGearFiles,       // 기어 폴더 → 기어 파일 글 · 톱니 사전 글         (부수효과: 읽기)
  scv_gear_flow_mark,  // 펼친 흐름의 표시들 → pure | effect | outward | judge
  scv_gear_ask_rows,   // (인자 줄들, 기어의 고정 값, 받는 값 이름) → 물을 값 줄들
  writeIndex,          // 줄들 → 목록 파일 · 표준 출력                    (부수효과: 쓰기)
)

// 창을 그릴 때 (대시보드)
flow(
  readPaneFiles,       // 프로젝트 → 설정 글 · 기어 목록 글 · 실행 상태    (부수효과: 읽기)
  parseAskMode,        // 설정 글 → all | ends
  askModeView,         // 값 → 이름 · 뜻 한 줄 · 고를 보기
  parseGears,          // 목록 글 → 기어들
  gearRows,            // (기어들, 실행 상태, 본체 폴더 있음) → 기어 줄
  paneSections,        // (계획 있음, 막힘 있음, 접힘) → 위에 둘 칸 · 접을 칸
  drawPane,            // 줄 · 칸 → 화면                                  (부수효과: 그리기)
)

// 창에서 누를 때 (대시보드)
flow(
  pluginRoot,          // 설치 기록 글 → 본체 폴더 | 없음
  gearCommand,         // (기어, 인자 값들) → 입력창에 넣을 글 · 실행 인자
  runInProject,        // 명령 → 종료 코드 · 출력                          (부수효과: 실행)
  gearResultView,      // (종료 코드, 출력) → 결과 줄들
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `readToolCall` | (기존) 가드가 받은 도구 이름과 입력 칸을 꺼냄 | 훅 입력 → 이름 · 칸 값 | 부수효과 (입구) |
| 2 | `guardRuleS` | 지금 도구가 래퍼가 알려 준 요약 도구이고 질문 칸이 차 있는지 봄 | (이름, 칸 값, 래퍼 값) → 볼 것 · 넘김 | 순수 |
| 3 | `scv_summary_ask_reason` | 거절 이유 한 줄을 만듦 — 선택 도구를 먼저 부르고 요약은 질문 없이 다시 | 도구 이름 → 글 | 순수 |
| 4 | `chooseToolForRun` | (기존) 이 실행에 쓸 선택 도구 이름 — 없으면 빈 값 | 설정 · 프로필 → 이름 | 순수 |
| 5 | `denyCall` | (기존) 거절 답을 냄 | 이유 → (없음) | 부수효과 (출구) |
| 6 | `readGearFiles` | (기존) 기어 파일과 톱니 사전을 읽음 | 기어 폴더 → 글 | 부수효과 (입구) |
| 7 | `scv_gear_flow_mark` | 펼친 흐름에서 가장 센 표시를 고름 — 판단 단계가 있으면 judge | 표시들 → 표시 하나 | 순수 |
| 8 | `scv_gear_ask_rows` | 기어를 쓸 때 정해야 할 값을 줄로 만듦 — 고정된 인자는 고정으로 표시 | (인자 줄, 고정 값, 받는 값) → 줄들 | 순수 |
| 9 | `writeIndex` | 목록 파일과 표준 출력에 씀 | 줄들 → (없음) | 부수효과 (출구) |
| 10 | `readPaneFiles` | 설정 파일 · 기어 목록 파일 · 기어 실행 상태를 읽음 | 프로젝트 → 글들 | 부수효과 (입구) |
| 11 | `parseAskMode` | 설정 글에서 묻기 방식을 꺼냄 — 없거나 다른 값이면 all | 글 → all · ends | 순수 |
| 12 | `askModeView` | 묻기 방식의 이름 · 뜻 한 줄 · 고를 보기를 만듦 | 값 → 보일 것 | 순수 |
| 13 | `parseGears` | 목록 글에서 기어만 골라 이름 · 값 · 하는 일 · 인자 · 표시로 나눔 | 글 → 기어들 | 순수 |
| 14 | `gearRows` | 기어마다 보일 줄과 쓸 수 있는 버튼을 정함 — 표시가 pure 이고 본체가 있으면 바로 실행 | (기어들, 실행 상태, 본체 있음) → 줄들 | 순수 |
| 15 | `paneSections` | 위에 둘 칸과 접을 칸을 정함 — 막힌 작업은 있을 때 위로 | (계획, 막힘, 접힘) → 칸 목록 | 순수 |
| 16 | `drawPane` | 칸과 줄을 화면에 그림 | 칸 · 줄 → 화면 | 부수효과 (출구) |
| 17 | `pluginRoot` | 설치 기록 글에서 본체가 깔린 폴더를 찾음 | 글 → 폴더 · 없음 | 순수 |
| 18 | `gearCommand` | 입력창에 넣을 글과 실행 인자를 만듦 — 잘못된 꼴의 인자 값은 뺌 | (기어, 값들) → 글 · 인자 | 순수 |

## Guardrails

- 턴 끝 검사는 바꾸지 않는다. 0.83.0 이 고친 "답이 두 번 보임"을 되살리지 않고, 선택 창을 늦게 띄우지 않는다.
- 규칙 S 는 래퍼가 알려 준 도구 하나의 칸 하나만 본다. 본체는 도구 이름 · 칸 이름을 적지 않는다. 값이 없거나 꼴이 틀리면 0.101.0 과 같다.
- 사람 없는 실행(선택 도구가 없는 호스트 · 헤드리스 조건) · `SCV_CHOICE_GATE=off` 에서는 거절하지 않고, 값 안내도 묻지 않는다.
- 질문이 없는 요약 호출은 그대로 통과한다 — 요약 상자 자체를 막지 않는다.
- 창은 설정 파일을 직접 고쳐 쓰지 않는다. 본체의 설정 명령(`ask-mode.sh`)만 부른다.
- 창은 Claude 의 플러그인 폴더에 아무것도 쓰지 않는다. 설치 기록은 읽기만 한다.
- [바로 실행]은 표시가 `pure` 인 기어만. 표시 칸이 없는 예전 목록 파일이면 붙이지 않는다. 인자 값은 실행기에 낱말 하나씩 넘긴다 — 셸 글로 이어 붙이지 않는다.
- 매 턴 안내 글은 호스트 이름 · 도구 이름을 쓰지 않는다(호스트 중립 시험). 글 한도(시험 `test-instruction-diet`) 안에 둔다.
- 공개 저장소에 다른 프로젝트의 이름 · 세션 내용을 넣지 않는다. 실제 세션으로 한 확인은 숫자만 적는다. 시험의 예문은 같은 꼴로 새로 쓴다.
- mac · linux 둘 다 돈다(bash 3.2, BSD 도구).

## Risks / Open Questions

- 규칙 S 는 래퍼가 값을 넘겨야 돈다. Claude 래퍼 릴리스 전까지는 본체만 올려도 아무것도 바뀌지 않는다.

- 실제 세션에서는 134턴 중 33턴이 요약 상자에 질문을 넣었다. 이제 그때마다 선택 창이 뜨므로 선택 창이 지금보다 자주 뜬다(사용자가 숫자를 보고 고름 2026-11-24). '처음 · 끝에만 묻기' 프로젝트에서는 거절 이유가 "묻지 않는 결정이면 추천대로 진행하고 질문을 빼라"고 말한다.
- 요약 도구 없이 글로만 물은 경우(12턴 중 2턴)는 이 계획으로 잡히지 않는다.
- codex 에는 요약 도구가 없어 규칙 S 가 돌지 않는다.
- 창의 글 입력 요소가 화면 종류(터미널 · 앱 · 휴대폰)마다 있는지는 구현 때 확인한다. 없는 화면에서는 [바로 실행]을 숨기고 [쓰기]만 둔다.
- 본체가 프로젝트 범위로 깔린 경우 설치 기록에 줄이 둘 이상일 수 있다. 이 프로젝트 폴더에 맞는 줄을 먼저 쓴다.
- 미러 세션에서 누르기는 이번에 없다. 원격에서 보는 일이 잦으면 다음 계획으로 한다.
