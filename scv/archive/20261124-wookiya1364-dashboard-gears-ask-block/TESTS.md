# Test Plan — 대시보드에 기어 · 묻기 방식, 글로 묻기는 선택 창으로

## Overview

세 가지를 확인한다. (1) 요약 도구에 질문이 실린 호출을 가드가 거절하고, 턴 끝 검사는 그대로인지. (2) 기어 목록의 부작용 칸과 값 안내 줄이 맞게 나오는지. (3) 대시보드 창이 컨텍스트 · 사용량 · 묻기 방식 · 기어 · 단계를 위에 보이고, 눌렀을 때 본체 명령이 맞게 불리는지. 본체 시험은 `core/tests/` 의 셸 시험, 대시보드 시험은 모드의 시험 도구(`claude plugin test`)로 돈다. 본체의 새 시험은 `core/` 밖 파일이 없을 때 그 부분을 건너뛴다(codex 사본).

## Test scenarios

### T1. 요약 도구에 질문이 실리면 거절한다

- **Setup**: 선택 도구가 있는 호스트 프로필, 래퍼 값 `SCV_SUMMARY_ASK="<도구>=<질문 칸>"`
- **Run**: 가드(모든 도구 방식)에 질문 칸이 찬 요약 도구 호출을 넣는다
- **Expected**: 거절 답이 나오고, 이유가 "선택 도구를 먼저 부르고 요약 도구는 질문 없이 다시"를 말한다
- **Pass criterion**: 출력에 `"permissionDecision":"deny"`, 이유에 선택 도구 이름

### T2. 질문이 없는 요약은 통과한다

- **Setup**: T1 과 같음
- **Run**: 질문 칸이 없는 호출, 공백뿐인 호출
- **Expected**: 둘 다 통과
- **Pass criterion**: 거절 0번

### T3. 이름이 다른 도구는 보지 않는다

- **Setup**: 같은 이름의 칸을 가진 다른 도구
- **Run**: 가드에 넣는다
- **Expected**: 통과
- **Pass criterion**: 거절 0번

### T4. 래퍼가 값을 주지 않으면 0.101.0 과 같다

- **Setup**: `SCV_SUMMARY_ASK` 없음
- **Run**: 질문이 실린 요약 도구 호출
- **Expected**: 통과
- **Pass criterion**: 거절 0번

### T5. 선택 도구가 없는 실행은 통과한다

- **Setup**: 선택 도구가 없는 호스트 프로필 · `SCV_CHOICE_GATE=off` · 헤드리스 조건이 맞는 실행
- **Run**: 질문이 실린 요약 도구 호출 세 번, 그리고 조건이 맞지 않는 실행 한 번
- **Expected**: 앞의 셋은 통과, 마지막은 거절
- **Pass criterion**: 거절 1번

### T6. 틀린 모양의 값은 아무것도 하지 않는다

- **Setup**: 칸 이름에 점 · 공백이 든 값, 도구 이름만 있는 값, 이름이 비슷한 다른 도구
- **Run**: 여섯 가지 값으로 가드
- **Expected**: 모두 통과
- **Pass criterion**: 거절 0번

### T7. help 통과 목록보다 먼저 본다

- **Setup**: 요약 도구가 help 통과 목록에 있고, 사람 턴이 아직 help 를 부르지 않음
- **Run**: 질문이 실린 호출과 질문이 없는 호출
- **Expected**: 앞은 거절, 뒤는 통과
- **Pass criterion**: 거절 1번

### T8. 턴 끝 검사는 그대로다

- **Setup**: 알림 방식(기본), 끝 답이 글로 물음
- **Run**: 종료 훅
- **Expected**: 막지 않고 다음 턴 알림 파일에 한 줄
- **Pass criterion**: 표준 출력에 `block` 없음, 알림 1줄

### T9. 매 턴 안내에 새 구절이 실리고 한도 안이다

- **Setup**: 선택 도구가 있는 호스트 프로필
- **Run**: 매 턴 훅을 돌려 안내 글을 본다
- **Expected**: "물을 것은 마무리 요약보다 먼저 선택 도구로" 뜻의 구절이 있고, 호스트 이름이 없으며, 글 한도를 넘지 않는다
- **Pass criterion**: 구절 1번, `test-instruction-diet` 와 호스트 중립 시험 종료 코드 0

### T10. 기어 목록의 부작용 칸

- **Setup**: 기어 네 개 — 순수 톱니만, effect 톱니 포함, outward 톱니 포함, 판단 단계 포함. 그리고 기어 안에 기어가 든 것 하나
- **Run**: 목록 명령을 돌리고 목록 파일을 읽는다
- **Expected**: 9번째 칸이 차례로 pure · effect · outward · judge, 안에 든 기어는 펼친 흐름에서 가장 센 표시
- **Pass criterion**: 다섯 줄의 9번째 칸이 기대값과 같음, 톱니 줄의 칸 수는 그대로

### T11. 값 안내 줄

- **Setup**: 인자 셋을 가진 톱니가 든 기어, 그중 하나를 기어 파일이 고정함. 받는 값이 none 인 기어와 아닌 기어
- **Run**: `gear.sh ask <기어>`
- **Expected**: 인자마다 이름 · 기본값 · 설명 줄, 고정된 인자는 고정 표시, 받는 값이 있으면 입력 필요 줄. 없는 기어는 종료 코드 2
- **Pass criterion**: 줄 수와 칸 값이 기대와 같음, 없는 기어 종료 코드 2

### T12. 기어 규약 글에 값 안내 규칙이 있다

- **Setup**: 없음
- **Run**: 기어 규약 글을 읽는다
- **Expected**: "요청에 없는 값은 선택 도구로 묻는다 · 기본값이 첫 보기 · 요청에 값이 있으면 묻지 않는다 · 사람 없는 실행은 기본값" 네 가지가 있다
- **Pass criterion**: 네 구절이 각각 1번 이상

### T13. 실제 세션 다시 넣기 (커밋하지 않는 확인)

- **Setup**: 다른 프로젝트의 실제 세션 기록에서 요약 도구 호출 121번의 입력을 뽑아 임시 폴더에 둔다
- **Run**: 고친 가드에 차례로 넣는다
- **Expected**: 질문이 실린 34번만 거절, 87번은 통과. 글로 물은 12턴 중 10턴이 거절된 호출에 들어 있다
- **Pass criterion**: 거절 34 · 통과 87

### T14. 계획이 없어도 컨텍스트 · 사용량이 나온다

- **Setup**: 진행 중인 계획이 없는 프로젝트, 사용량 · 컨텍스트 값이 있음
- **Run**: 창을 그린다
- **Expected**: 컨텍스트 · 사용량 칸이 맨 위에 있다
- **Pass criterion**: 글자 줄에 "컨텍스트" 와 "5시간" 이 있음

### T15. 칸 순서와 접기

- **Setup**: 계획 하나, 시험 결과와 드림이 있음
- **Run**: 창을 그리고, '더 보기'를 누르고, 다시 그린다
- **Expected**: 처음에는 컨텍스트 · 사용량 → 묻기 방식 → 기어 → 단계 흐름 순서이고 진행률 · 시험 결과 · 드림 · 변경 이력은 없다. 누르면 보인다. 다시 그려도 펼친 채다
- **Pass criterion**: 누르기 전 "시험 결과" 0번, 누른 뒤 1번, 다시 그린 뒤 1번

### T16. 막힌 작업은 접지 않는다

- **Setup**: 막힌 단계가 있는 계획, '더 보기'는 접힌 채
- **Run**: 창을 그린다
- **Expected**: 막힌 작업 칸이 위쪽에 보인다
- **Pass criterion**: 글자 줄에 "막힌 작업" 있음

### T17. 묻기 방식의 값과 뜻

- **Setup**: 설정 파일에 값이 없음 · `ends` · 모르는 값
- **Run**: 창을 그린다
- **Expected**: 차례로 "전부 묻기" · "처음 · 끝에만 묻기" · "전부 묻기", 그 아래 뜻 한 줄
- **Pass criterion**: 세 경우의 이름 줄이 기대와 같음

### T18. 묻기 방식 바꾸기

- **Setup**: 본체 설치 기록이 있는 경우와 없는 경우
- **Run**: 다른 값을 고른다
- **Expected**: 있는 경우 — 본체의 설정 명령이 프로젝트 폴더에서 고른 값으로 한 번 불리고 칸이 새 값이 된다. 없는 경우 — 입력창에 바꾸는 명령이 들어가고 알림 줄이 나온다
- **Pass criterion**: 불린 명령의 인자가 고른 값, 작업 폴더가 프로젝트 폴더. 없는 경우 실행 0번 · 입력창 글 1번

### T19. 기어 목록

- **Setup**: 기어 둘 · 톱니 셋이 든 목록 파일. 그리고 목록 파일이 없는 프로젝트, 기어가 0개인 프로젝트
- **Run**: 창을 그린다
- **Expected**: 기어 두 줄만(톱니는 없음), 줄마다 이름 · 받는 값 → 돌려주는 값 · 하는 일 · 인자. 없는 프로젝트는 안내 한 줄이고 창이 깨지지 않는다
- **Pass criterion**: 기어 이름 2개, 톱니 이름 0개, 빈 경우 안내 줄 1개

### T20. 쓰기 버튼

- **Setup**: 표시가 effect 인 기어(인자 셋)와 pure 인 기어
- **Run**: effect 기어의 [쓰기]를 누른다
- **Expected**: effect 기어에는 [쓰기]만, pure 기어에는 [바로 실행]도 있다. 누르면 입력창에 그 기어를 돌리는 명령이 들어간다
- **Pass criterion**: 입력창 글이 `/scv:gear run <이름>` 으로 시작, 실행 0번

### T21. 바로 실행

- **Setup**: 표시가 pure 인 기어(받는 값 없음), 본체 설치 기록 있음. 그리고 표시 칸이 `-` 인 예전 목록 파일
- **Run**: [바로 실행]을 누른다. 실패하는 경우(종료 코드 1)도 한 번
- **Expected**: 본체 기어 실행기가 그 기어 이름으로, 프로젝트 폴더에서, 30초 제한으로 불린다. 인자는 기본값 그대로다(값을 바꾸려면 [쓰기]로 Claude 의 안내를 받는다). 출력 앞 줄들이 칸에 보인다. 실패면 종료 코드와 오류 줄. 예전 목록 파일이면 [바로 실행]이 없고, 세션이 본체에 목록을 한 번 다시 쓰게 한다
- **Pass criterion**: 불린 명령 · 작업 폴더 · 제한 시간이 기대와 같음, 결과 줄 있음, 예전 파일에서 버튼 0개 · 목록 다시 쓰기 1번

### T22. 입력 칸의 글은 표준 입력으로만 간다

- **Setup**: 표시가 pure 이고 받는 값이 있는 기어. 입력 칸에 공백 · 따옴표 · `;` · `이름=값` 이 든 글
- **Run**: 입력 칸에 적고 [바로 실행]
- **Expected**: 적은 글은 표준 입력으로만 가고, 명령은 `gear.sh run <이름>` 네 낱말 그대로다
- **Pass criterion**: 불린 명령의 인자 배열이 네 낱말, 표준 입력이 적은 글과 같음

### T23. 확인을 기다리는 기어 실행 표시

- **Setup**: 기어 실행 상태 폴더에 확인을 기다리는 실행 하나
- **Run**: 창을 그린다
- **Expected**: 기어 칸에 "확인 기다림" 줄이 나온다
- **Pass criterion**: 그 줄 1번, 상태 폴더가 없으면 0번

### T24. 기존 대시보드 시험이 그대로 통과한다

- **Setup**: 없음
- **Run**: 대시보드 시험 전체
- **Expected**: 기존 154개가 모두 통과한다(접힌 칸을 보는 시험은 펼친 뒤 같은 글을 본다)
- **Pass criterion**: 실패 0

## How to run

```bash
bash core/tests/test-choice-block.sh && bash core/tests/test-choice-questions.sh && bash core/tests/test-help-first.sh && bash core/tests/test-guard.sh && bash core/tests/test-gear-run.sh && bash core/tests/test-instruction-diet.sh && (cd ../scv-mods/marketplace/mods/scv-dashboard && claude plugin test .)
```

## Pass criteria

- 위 명령이 종료 코드 0 으로 끝난다.
- T13(실제 세션 다시 넣기)은 손으로 한 번 돌려 숫자를 마무리 보고에 적는다: 거절 34 · 통과 87.
- 순수 함수 사전 · 순도 검사 · 호스트 중립 검사가 통과한다.
- 고친 창의 글자 줄을 사용자에게 보였다.
