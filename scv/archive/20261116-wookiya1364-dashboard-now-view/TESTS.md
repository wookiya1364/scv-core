# Test Plan — 대시보드 — 지금 하는 일이 늘 보이게 (지금 하는 일 · 뒤에서 도는 일 · 최근 끝난 일)

## Overview

대시보드(`../scv-mods/marketplace/mods/scv-dashboard`)가 세 가지를 늘 보이는지 본다: 지금 하는 일, 뒤에서 도는 일(일마다 한 줄),
최근 끝난 일. 그리고 뒤의 일이 도는 동안 "사용자 차례"로 잘못 바뀌지 않는지 본다. 값만 넣어 보는 시험(순수 함수)과, 대시보드에
일(도구 호출 · 턴 시작 · 끝)을 차례로 보내고 화면 글을 읽는 시험을 쓴다 — 틀은 지금 있는 `hooks/register.test.tsx` 를 따른다.
대화에서 나온 요구(① 도는 일이 있으면 "사용자 차례"가 아니다 ② 지금 하는 일과 시작 시각이 보인다 ③ 뒤에서 도는 일이 일마다
보인다 ④ 최근 끝난 일이 보인다)가 T1 · T5 · T3 · T7 이고, 나머지는 그 넷을 지키는 경계다.

## Test scenarios

### T1. 뒤의 일이 도는 중에 사용자가 말을 걸어도 "사용자 차례"가 아니다

- **Setup**: 하는 중인 단계가 하나 있는 계획. 대시보드에 차례로 보낸다 — 턴 시작 → 뒤로 보낸 명령의 도구 호출(결과 글에 이름표와 출력 위치) → 턴 끝 → **턴 시작(사용자가 말함)** → 도구 호출 없이 턴 끝.
- **Run**: 마지막 턴 끝 뒤의 화면 글을 읽는다.
- **Expected**: 상태는 "뒤의 일 기다림"이다. "사용자 차례"라는 글이 없다. 뒤에서 도는 일 줄이 1개 있다.
- **Pass criterion**: 화면 글에 `사용자 차례` 0번 · 도는 일 줄 1개 · 시험 줄 `(pass) now-view T1`. 고치기 전 코드에서는 이 시험이 실패한다(`사용자 차례` 1번 이상).
  (구현 결과: 고치기 전 화면 코드에서 `Expected: not containing "사용자 차례"` 로 실패하는 것을 봤다.)

### T2. 일이 끝나면 목록에서 빠지고, 남은 일이 없으면 "사용자 차례"다

- **Setup**: T1 의 끝 상태에서 그 일이 끝났다는 알림(종료 코드 0)을 보내고, 턴 시작 → 턴 끝.
- **Run**: 화면 글을 읽는다.
- **Expected**: 뒤에서 도는 일 줄 0개. 최근 끝난 일에 그 일의 이름이 1줄. 상태는 "사용자 차례"(2026-11-12 계획의 동작 그대로).
- **Pass criterion**: 도는 일 줄 0개 · 끝난 일 줄에 그 이름 1번 · `사용자 차례` 1번 이상.

### T3. 뒤에서 도는 일이 일마다 한 줄 — 이름 · 걸린 시간 · 마지막 진행 줄

- **Setup**: 뒤로 보낸 명령 둘(설명 글 "시험 전체 돌리기" · "측정 128판"). 첫째의 출력 끝부분은 `[4/7] 코어 받아 오기 연습 …`, 둘째는 출력이 비어 있다. 시작한 지 각각 95초 · 12초.
- **Run**: `nowBlock` 이 만든 줄들을 읽는다.
- **Expected**: 두 줄. 첫째에 이름 `시험 전체 돌리기`, 걸린 시간 `1분 35초`, 진행 줄 `[4/7] 코어 받아 오기 연습 …`. 둘째에 이름 `측정 128판`, 걸린 시간 `12초`, 진행 줄 없음(빈 출력이어도 줄은 그려진다).
- **Pass criterion**: 줄 2개 · 위 여섯 값이 그대로 있음 · 설명 글이 없는 명령은 명령의 앞 60자가 이름으로 나옴.

### T4. 진행 막대 — "한 것 / 전체" 꼴을 읽는다

- **Setup**: 끝부분 글 넷 — `끝난 판: 10 / 64` · `[4/7] 이름 … 통과 (257초)` · `Progress 45%` · `그냥 글`.
- **Run**: `progressOf` 에 하나씩 넘긴다.
- **Expected**: 차례로 한 것 10 · 전체 64 / 한 것 4 · 전체 7 / 한 것 45 · 전체 100 / 한 것 · 전체 없음.
- **Pass criterion**: 네 결과가 위와 같음 · 전체가 0 이거나 한 것이 전체보다 크면 막대 없음.

### T5. 지금 하는 일 — 앱의 할 일 목록에서 하는 중인 항목과 시작 시각

- **Setup**: 앱의 할 일 도구 호출을 차례로 보낸다 — 목록 3개(첫째가 하는 중) → `advance` → `done [2] · start 3`.
- **Run**: 호출마다 `nowLine` 의 결과를 읽는다.
- **Expected**: 차례로 첫째 · 둘째 · 셋째 항목의 글이 "지금 하는 일"이다. 시작 시각은 그 항목이 하는 중이 된 시각이다. 대시보드의 할 일 목록에도 같은 세 항목과 상태가 있다.
- **Pass criterion**: 세 번의 한 줄이 차례로 맞음 · 시각이 호출 시각과 같음 · 기존 `TodoWrite` 시험이 그대로 통과.

### T6. 지금 하는 일 — 재료를 차례로 본다

- **Setup**: 다섯 경우((가) ~ (다) · (마)는 턴이 도는 중) — (가) 할 일 목록에 하는 중인 항목 있음 (나) 목록 없음 · 계획의 하는 중인 단계 있음 (다) 둘 다 없음 · 도는 도구 있음(설명 글 있음) (라) 턴이 끝났고 뒤에서 도는 일 1개 (마) 아무것도 없고 턴이 도는 중.
- **Run**: `nowLine`.
- **Expected**: (가) 그 항목의 글 (나) `3단계 — <단계 글>` (다) 그 도구의 설명 글 (라) `뒤에서 도는 일을 기다리는 중 — <그 일의 이름>` (마) `결과를 읽거나 다음을 정하는 중`.
- **Pass criterion**: 다섯 결과의 글이 위 Expected 와 글자까지 같음((마)는 `결과를 읽거나 다음을 정하는 중`) · (가)와 (나)를 함께 넣으면 결과가 (가)의 글과 같음.

### T7. 최근 끝난 일 — 시각과 함께 최근 5개, 실패는 실패라고

- **Setup**: 끝난 일 일곱을 차례로 넣는다(여섯째는 종료 코드 1). 끝난 시각은 10:46 ~ 11:05.
- **Run**: `applyDone` 을 일곱 번, 그리고 `nowBlock`.
- **Expected**: 최근 5개만 남고 가장 최근 것이 맨 아래다. 줄마다 `HH:MM 이름 끝`. 여섯째는 `HH:MM 이름 실패`.
- **Pass criterion**: 줄 5개 · 첫 둘이 빠짐 · `실패` 1번 · 시각 꼴 `[0-9]{2}:[0-9]{2}` 5번.

### T8. 터미널 탭에서 시작한 명령도 뒤에서 도는 일이다

- **Setup**: 터미널 탭에서 명령을 시작하는 도구 호출(제목 "남은 검사 7개") → 턴 끝.
- **Run**: 화면 글을 읽는다. 이어서 그 탭을 멈추는 도구 호출을 보낸다.
- **Expected**: 턴 끝 뒤 도는 일 줄 1개(이름 `남은 검사 7개`, 꼬리표 `터미널 탭`), `사용자 차례` 0번. 멈춤 호출 뒤 도는 일 줄 0개 · 끝난 일 1줄.
- **Pass criterion**: 앞 화면에 줄 1개와 `터미널 탭` 1번 · 뒤 화면에 줄 0개.

### T9. 보조 작업(하위 에이전트)과 스스로 맞춘 깨우기는 지금처럼

- **Setup**: (가) 보조 작업 1개가 도는 채로 턴 끝 (나) 스스로 맞춘 깨우기를 걸고 턴 끝.
- **Run**: 화면 글.
- **Expected**: 둘 다 "뒤의 일 기다림"이고 `사용자 차례` 0번. (가)에는 보조 작업 줄이 지금처럼 있다.
- **Pass criterion**: 2026-11-12 계획의 시험 T2 · T7 이 기대값을 바꾸지 않고 통과.

### T10. 다른 기기에서 보는 화면에도 같은 세 가지가 보인다

- **Setup**: 도는 일 1개 · 끝난 일 2개 · 지금 하는 일이 있는 상태.
- **Run**: 거울 세션으로 보내는 글을 만들고, 받은 쪽에서 화면을 그린다.
- **Expected**: 받은 쪽 화면에 지금 하는 일 1줄 · 도는 일 1줄 · 끝난 일 2줄이 보낸 쪽과 같다. 보내는 글에 출력 파일 위치는 없다.
- **Pass criterion**: 두 화면의 세 묶음 글이 같음 · 보내는 글에 출력 파일 경로 0번.

### T11. 진행 줄은 한 줄 · 120자, 제어 문자 없음

- **Setup**: 끝부분 글 — 300자짜리 한 줄, 색 코드(이스케이프)가 섞인 줄, 줄 끝에 캐리지 리턴으로 덮어 쓰는 진행 줄(`\r 10/64\r 11/64`).
- **Run**: `progressOf`.
- **Expected**: 300자는 120자로 잘림(끝에 `…`). 색 코드는 지워짐. 덮어 쓰는 줄은 마지막 것(`11/64`)만 남음.
- **Pass criterion**: 결과 길이가 120 이하 · 이스케이프 글자 0개 · 한 것 11 · 전체 64.

### T12. 읽는 양 — 큰 출력에서도 한 번 갱신이 느려지지 않는다

- **Setup**: 도는 일 8개, 일마다 10만 줄짜리 출력 파일.
- **Run**: 3초 갱신 한 번(읽기 → `progressOf` → `applyJobEvent`)의 걸린 시간을 고치기 전(일 없음)과 견줘 잰다. 도는 일 9번째를 더해 본다.
- **Expected**: 갱신 한 번이 200ms 이내. 아홉째는 기억하지 않는다(가장 오래 끝난 것부터 버리고, 도는 일은 버리지 않는다 — 여덟이 모두 도는 중이면 아홉째의 줄은 "외 1개"로 센다).
- **Pass criterion**: 잰 값이 200ms 이하이고 그 값을 마무리 보고에 적음 · 일 목록 길이 8 · 화면에 `외 1개` 1번.
  (구현 결과: 3초 갱신 한 번의 시간은 실제 앱에서만 잴 수 있어 재지 못했다. 대신 시험이 "바뀐 파일만 읽는다 · 256KB 넘는 파일은 통째로 읽지 않고 끝만 읽는다 · 끝 4천 자만 남긴다"를 본다. 200ms 는 확인 못 한 것으로 남는다.)

### T13. 끝났는지 모르면 "끝났다"고 그리지 않는다

- **Setup**: 도는 일 1개, 끝 알림 없음, 출력 파일이 5분 동안 바뀌지 않음.
- **Run**: 화면 글.
- **Expected**: 그 줄은 `끝난 듯`(회색)으로 그려지고 "최근 끝난 일"로 옮겨지지 않는다. `사용자 차례`는 나오지 않는다.
- **Pass criterion**: `끝난 듯` 1번 · 끝난 일 줄 0개 · `사용자 차례` 0번. (1단계 실험에서 끝 알림이 늘 닿는다고 확인되면, 이 시나리오는 "알림이 유실된 경우"로 그대로 둔다.)

### T14. 순수 단계 — 같은 입력 같은 출력, 입력을 바꾸지 않는다

- **Setup**: `jobStartOf` · `jobEndOf` · `applyJobEvent` · `applyDone` · `progressOf` · `nowLine` · `nowBlock` 에 같은 입력을 두 번.
- **Run**: 결과를 견주고, 넘긴 목록이 그대로인지 본다.
- **Expected**: 두 결과가 같다. 넘긴 목록의 길이와 내용이 바뀌지 않았다.
- **Pass criterion**: 일곱 함수 모두 두 결과의 차이 0 · 넘긴 목록의 길이 변화 0 이고 내용이 호출 전과 같음 — 시험 줄 `(pass) now-view T14`.

### T15. 기존 동작 — 시험 129개가 그대로 통과한다

- **Setup**: 없음.
- **Run**: 대시보드 시험 전부.
- **Expected**: 기존 129개의 기대값을 바꾸지 않고 통과한다. (턴 시작이 표시를 지우던 것을 보는 시험이 있으면, 그 한 줄은 새 동작으로 바꾸고 무엇을 바꿨는지 마무리 보고에 적는다.)
- **Pass criterion**: 실패 0 · 기대값을 바꾼 기존 시험이 있으면 그 이름을 마무리 보고에 적음.

### T16. 실제 화면 — 뒤 명령을 돌리며 대시보드를 본다

- **Setup**: 실제 세션. 30초 동안 1초마다 `n / 30` 을 내는 명령을 뒤로 보낸다(설명 글 "진행 화면 확인용 30초 세기").
- **Run**: 턴을 끝낸다. 10초 뒤 사용자 자리에서 한마디 보낸다("지금 뭐 해?"). 그때와 30초 뒤의 대시보드 화면을 찍는다.
- **Expected**: 도는 동안 — 지금 하는 일 `뒤에서 도는 일을 기다리는 중 — 진행 화면 확인용 30초 세기`, 도는 일 줄에 `n / 30` 과 막대, `사용자 차례` 없음. 끝난 뒤 — 도는 일 줄 0개, 끝난 일에 그 이름과 시각.
- **Pass criterion**: 두 화면을 사용자에게 그대로 보임 · 사용자가 "이대로 계속"을 고름 · 말을 건 뒤 화면에 `사용자 차례` 0번.
  (구현 결과: 정해 둔 순서 — 30초 세기 명령 · 화면 두 장 — 는 하지 않았다. 구현한 세션은 새 대시보드가 나오기 전에 시작되어 옛 대시보드로 돌았기 때문이다. 대신 2026-11-16 릴리스 뒤 사용자가 실제 화면을 직접 보고 "일단 보이긴 해 — 우선은 이대로 가 보자"고 답했다. 말을 건 뒤 `사용자 차례` 가 0번인지, 진행 줄 · 막대가 실제로 그려지는지는 따로 세지 않았다.)

## How to run

```bash
cd ../scv-mods/marketplace/mods/scv-dashboard && claude plugin test .
```

## Pass criteria

- 위 명령이 종료 코드 0 — 새 시험(T1 ~ T15)과 기존 129개가 실패 0.
- T16 의 실제 화면 두 장을 사용자에게 보였고, 사용자가 "이대로 계속"을 골랐다.
- 고치기 전 코드에서 T1 의 실패 수가 1 이상이었다(그 수를 마무리 보고에 적는다).
- 구현 1단계의 두 실험(프로젝트 밖 파일 읽기, 끝 알림이 닿는 길)의 결과가 마무리 보고에 적혀 있다.
