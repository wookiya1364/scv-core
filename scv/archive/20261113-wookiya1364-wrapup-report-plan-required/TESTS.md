# Test Plan — 마무리 보고 — 계획마다 문제에서 배운 것까지 남기고, 계획 없는 변경은 없앤다

## Overview

두 가지를 본다. 첫째, 마무리 보고가 다 채워져야만 계획이 보관되고, 보관된 뒤 그 보고가 한 번 나온다. 둘째, 계획 없이 가는 빠른 길이 문서 · 명령 · 설정 · 훅 문구 어디에도 남아 있지 않고, 릴리스 · 동기화 예외는 그대로다. 시험은 임시 폴더에 가짜 계획 폴더를 만들어 실제 보관 명령을 돌린다.

## Test scenarios

### T1. 빈 칸이 있으면 보관이 막힌다

- **Setup**: 계획 문서 · 시험 문서 · 마무리 보고가 있는 가짜 계획. 마무리 보고의 "배운 것" 묶음 한 칸이 비어 있다
- **Run**: 보관 명령
- **Expected**: 종료 코드 1. 출력에 묶음 번호 7과 빈 칸의 이름. 계획 폴더는 그 자리에 그대로, 보관 폴더와 보관 기록은 생기지 않는다
- **Pass criterion**: 종료 코드 1 · 빈 칸 이름 출력 · 옮겨진 파일 0개

### T2. 다 채우면 보관되고 보고가 나온다

- **Setup**: 16칸이 모두 채워진 가짜 계획
- **Run**: 보관 명령
- **Expected**: 종료 코드 0. 지금과 같은 `ARCHIVED:` · `WROTE:` 줄. 그 뒤에 일곱 묶음의 짧은 글. 보관 폴더에 마무리 보고 파일이 함께 있다
- **Pass criterion**: 종료 코드 0 · 짧은 글의 묶음 수 7 · 보관 폴더에 파일 넷(계획 · 시험 · 마무리 보고 · 보관 기록)

### T3. 새 기능 계획은 가운데 넷을 건너뛸 수 있다

- **Setup**: 관찰 · 가설 · 실험 · 원인 묶음이 각각 `해당 없음 — <이유>` 한 줄인 가짜 계획. 문제 · 해결과 검증 · 배운 것은 채워져 있다
- **Run**: 보관 명령
- **Expected**: 종료 코드 0. 짧은 글에 건너뛴 묶음이 이유와 함께 나온다
- **Pass criterion**: 종료 코드 0 · 건너뛴 묶음 넷의 이유가 출력에 있음

### T4. 이유 없는 건너뜀은 막힌다

- **Setup**: 가설 묶음이 `해당 없음` 뿐이고 이유가 없는 가짜 계획
- **Run**: 보관 명령
- **Expected**: 종료 코드 1. 출력에 묶음 번호 3과 "이유 없음"
- **Pass criterion**: 종료 코드 1 · 옮겨진 파일 0개

### T5. 문제 · 해결과 검증 · 배운 것은 건너뛸 수 없다

- **Setup**: 가짜 계획 셋 — 각각 묶음 1 · 6 · 7 을 `해당 없음 — <이유>` 로 건너뜀
- **Run**: 셋에 보관 명령
- **Expected**: 셋 모두 종료 코드 1. 출력에 그 묶음 번호
- **Pass criterion**: 3 / 3 막힘

### T6. 마무리 보고가 없는 옛 계획은 그대로 보관된다

- **Setup**: 계획 문서 · 시험 문서만 있고, 계획 문서가 마무리 보고를 가리키지 않는 가짜 계획
- **Run**: 보관 명령
- **Expected**: 종료 코드 0. 지금과 같은 출력에 "마무리 보고 없음(옛 계획)" 알림 한 줄
- **Pass criterion**: 종료 코드 0 · 알림 1줄 · 보관됨

### T7. 계획이 가리키는데 파일이 없으면 막힌다

- **Setup**: 계획 문서가 마무리 보고를 가리키지만 그 파일이 없는 가짜 계획
- **Run**: 보관 명령
- **Expected**: 종료 코드 1. 출력에 "마무리 보고 파일 없음"
- **Pass criterion**: 종료 코드 1 · 옮겨진 파일 0개

### T8. 칸을 지워도 막힌다

- **Setup**: "해결과 검증" 묶음에서 칸 한 줄을 통째로 지운 가짜 계획(남은 칸은 채워져 있다)
- **Run**: 보관 명령
- **Expected**: 종료 코드 1. 출력에 묶음 번호 6과 "칸 2개 · 필요 3개"
- **Pass criterion**: 종료 코드 1

### T9. 영어 계획도 같은 판정을 받는다

- **Setup**: 칸 이름이 영어이고 건너뜀이 `N/A — <reason>` 인 가짜 계획 둘(다 채움 · 한 칸 빔)
- **Run**: 둘에 보관 명령
- **Expected**: 다 채운 쪽 0, 한 칸 빈 쪽 1
- **Pass criterion**: 종료 코드 0 · 1

### T10. 순수 함수 다섯의 예

- **Setup**: 없음
- **Run**: 함수마다 적어 둔 예(입력 → 출력)를 그대로 돌린다
- **Expected**: 칸 꺼내기 · 빈 칸 고르기 · 건너뜀 고르기 · 판정 · 짧은 글이 예와 같은 값을 낸다. 빈 글 · 묶음 머리만 있는 글 · 칸 줄 안에 쌍점이 여럿인 줄에서도 죽지 않는다
- **Pass criterion**: 예 실패 0개

### T11. 계획 세우기가 틀을 쓰고, 손으로는 만들 수 없다

- **Setup**: 계획 세우기 규약 · 계획 틀 문서 · 훅
- **Run**: 두 문서의 마무리 보고 틀에서 묶음과 칸을 꺼내 견준다. 영수증 없는 세션에서 계획 폴더에 마무리 보고 파일을 새로 쓰는 편집을 훅에 넣는다
- **Expected**: 두 문서의 틀이 일곱 묶음 16칸으로 같다. 틀 그대로는 새 검사에서 막힌다(채울 자리 표시가 남아 있으므로). 훅이 그 편집을 거절한다
- **Pass criterion**: 묶음 7 · 칸 16 일치 · 틀 그대로는 종료 코드 1 · 훅 거절

### T12. 일하기 규약이 채우기와 보여 주기를 말한다

- **Setup**: 일하기 규약
- **Run**: 보관 물음 앞과 보관 뒤 단락을 읽는다
- **Expected**: 보관 전에 나머지 칸을 채우라는 문장, 보관 뒤 명령이 낸 짧은 글을 끝 답에 싣으라는 문장이 있다
- **Pass criterion**: 찾은 문장 2개

### T13. 빠른 길 선언은 없어졌다고 말하고 편집을 풀지 않는다

- **Setup**: 진행 중 계획이 없는 가짜 프로젝트
- **Run**: 빠른 길 선언 명령. 이어서 계획 밖 파일을 고치는 편집을 훅에 넣고, 파일을 바꾼 턴을 턴 끝 검사에 넣는다
- **Expected**: 선언 명령은 종료 코드 2와 "없어졌다 — 계획을 세워라" 안내. 다섯 기준 출력은 나오지 않는다. 턴 끝 검사는 "진행 중 계획이 없다"로 막는다
- **Pass criterion**: 종료 코드 2 · 기준 출력 0줄 · 턴 끝 막힘

### T14. 빠른 길 안내가 어디에도 남아 있지 않다

- **Setup**: 코어 저장소
- **Run**: 계획 틀 문서 · 설정 예시 · 아는 설정 키 목록 · 훅 · 규약 문서에서 빠른 길을 가리키는 말(선언 옵션 · 줄 수 설정 이름 · "fast-path")을 찾는다
- **Expected**: 선언 명령의 "없어졌다" 안내 한 곳만 남는다. 계획 틀 문서에는 "계획 없는 변경은 없다 — 예외는 릴리스 · 동기화"가 있다
- **Pass criterion**: 남은 곳 1 · 새 문장 있음

### T15. 릴리스 · 동기화 예외는 그대로다

- **Setup**: 턴 끝 검사의 예외 판정과 그 시험
- **Run**: 지금 있는 턴 끝 검사 시험을 그대로 돌린다
- **Expected**: 통과 수가 고치기 전과 같다. 예외 종류는 릴리스 · 동기화 둘뿐이다
- **Pass criterion**: 통과 수 같음 · 실패 0

## How to run

```bash
bash core/tests/test-wrapup.sh && bash core/tests/test-turn-plan-check.sh
```

## Pass criteria

- T1 ~ T15 가 옛 셸(bash 3.2)과 새 셸(bash 5)에서 통과한다
- 순수 함수 검사 · 함수 사전 검사의 종료 코드 0
- 이 계획에 돌린 보관 명령의 종료 코드 0 (마무리 보고 16칸이 채워진 채)
- PR 을 올리기 전 전체 시험 한 번: 실패 0개
