# 검사의 빈틈 셋 고치기 — 보관한 턴 · 끊긴 값 · 긴 마지막 확인

## Summary

2026-11-11 ~ 12 에 느린 함수 고치기 계획을 하면서 검사 둘에서 빈틈 셋을 봤다.
계획을 보관한 턴은 기록을 남겼어도 턴 끝 검사에 두 번 막혔고, 재는 검사는 고치기 전 값이 한도 시간에 끊기면 빨라진 함수를 "새로 한도를 넘음"으로 멈췄으며, 마지막 번갈아 재기는 새 셸 488초 · 옛 셸 20분 넘게 걸렸다.
이 셋을 고친다. 한도 숫자는 바꾸지 않는다.

## Goals / Non-Goals

- **Goals**
  - 턴 도중 보관한 계획에 남긴 기록을 턴 끝 검사가 읽는다
  - 고치기 전 코드가 한도 시간에 끊기고 고친 코드는 끝났으면 통과로 본다 (표에는 끊김이라고 적는다)
  - 두 쌍 연속으로 고친 쪽이 2배 넘게 빠르면 남은 쌍을 재지 않는다
  - 큰 입력은 고친 쪽을 먼저 재고, 8배 안이면 고치기 전은 재지 않는다
  - 어제와 같은 마지막 확인을 다시 돌려 걸린 시간을 앞뒤로 견준다
- **Non-Goals**
  - 한도 숫자 손대기
  - 4배 배수가 경계에서 흔들리는 함수 손보기
  - 턴 끝의 빠른 검사(세 쌍 · 35초) 방식 손대기
  - PR · 릴리스 · 래퍼 저장소 작업

## Approach Overview

사용자가 2026-11-12 선택 창에서 정한 것: 끊긴 값은 "통과로 봄", 긴 확인은 "뚜렷하면 일찍 멈춤".

1. **보관한 턴** — 턴 끝 검사는 진행 중 자리(`scv/promote`)의 계획 글만 읽어 이번 턴에 새로 생긴 줄을 센다. 턴 도중 계획을 보관하면 그 글이 보관함으로 옮겨져 새 줄이 0이 된다. 턴이 시작된 뒤에 보관된 계획(보관 기록 파일이 턴 시작 표시보다 새것)의 글도 함께 읽는다.
2. **끊긴 값** — 앞뒤를 번갈아 재는 실행이 한도 시간에 끊기면 빈칸 대신 `too-slow` 를 남긴다. 판정은 "앞이 끊기고 뒤는 끝남"을 통과로, "뒤가 끊기고 앞은 끝남"을 한도 넘음으로 본다. 표와 멈춘 글에는 `끊김`이라고 적는다.
3. **긴 확인** — 되풀이 횟수는 빠른 쪽(고친 코드)에 맞춰 정해지는데, 느린 쪽도 그 횟수로 여섯 쌍을 다 쟀다. 두 쌍 연속으로 뒤가 앞의 절반 이하이면 멈춘다. 4배 입력은 뒤를 먼저 재고, 뒤 배수가 한도 안이면 앞은 재지 않는다(판정에 쓰이지 않는 값이다).

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  pb_fixed_run,      // (코드, 함수, 인자, 되풀이) → 회당 ms | too-slow     (부수효과: 실행)
  pb_pairs_enough,   // (앞 값들, 뒤 값들) → 1 | 0                           (순수 · 새 함수)
  pb_scale_over,     // (4배 배수) → 1 | 0                                    (순수 · 새 함수)
  pb_compare,        // (앞뒤 잰 줄) → 판정 줄                                (순수 · 고침)
  pb_render_compare, // (잰 줄들, 판정 줄들) → 표                             (순수 · 고침)
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | plan_texts | 진행 중 계획과 이번 턴에 보관한 계획의 글을 읽는다 | 턴 시작 표시 → 계획 글 | 부수효과 (읽기) |
| 2 | pb_fixed_run | 되풀이 수를 정한 채 한 번 재고, 끊기면 too-slow 를 낸다 | 코드 · 함수 · 인자 → 회당 ms \| too-slow | 부수효과 (실행) |
| 3 | pb_pairs_enough | 마지막 두 쌍이 모두 "뒤가 앞의 절반 이하"인지 본다 | 앞 값들, 뒤 값들 → 1 \| 0 | 순수 |
| 4 | pb_scale_over | 4배 배수가 한도를 넘거나 끊겼는지 본다 | 배수 → 1 \| 0 | 순수 |
| 5 | pb_compare_fn | 한 함수를 앞뒤로 번갈아 잰다 — 일찍 멈추고, 4배는 뒤 먼저 | 함수 → 앞뒤 잰 줄 | 부수효과 (실행) |
| 6 | pb_compare | 앞뒤 잰 줄을 한도로 가린다 — 끊긴 값의 뜻을 안다 | 잰 줄 → 판정 줄 | 순수 |
| 7 | pb_render_compare | 표를 만든다 — too-slow 를 끊김으로 적는다 | 잰 줄들 · 판정 줄들 → 표 | 순수 |
| 8 | pb_fail_lines | 멈춘 글의 한 줄을 만든다 — 끊김을 적는다 | 판정 줄들 → 사람이 읽는 줄 | 순수 |

- 부수효과 위치: 1 · 2 · 5번(파일 읽기와 실행). 판정 3 · 4 · 6과 글 만들기 7 · 8은 순수하다.
- 재사용: `pb_median` · `pb_ratio` · `pb_scale_ratio` · `pb_to_milli` 를 그대로 쓴다.

### 알아 둘 것

- 설치된 플러그인의 훅은 릴리스 전까지 옛 턴 끝 검사를 돌린다. 이 계획을 보관하는 턴도 끝에서 막힌다.
- 앞의 4배 값을 재지 않은 함수는 표의 앞 칸이 `-` 다. 어제 표에 있던 "앞 배수 → 뒤 배수"가 통과한 함수에서는 뒤 배수만 남는다.
- 새 셸의 `scv_reg_rewrite_line` 은 4쌍에서 멈췄다 — 처음 두 쌍이 뚜렷하지 않다가 뒤의 두 쌍이 뚜렷했다.

## Guardrails

- 한도 숫자는 바꾸지 않는다.
- 일찍 멈추는 것은 "두 쌍 연속으로 뒤가 앞의 절반 이하"일 때뿐이다. 그 밖에는 지금처럼 여섯 쌍을 다 잰다.
- 끊긴 값을 숨기지 않는다 — 표와 멈춘 글에 끊김이라고 적는다.
- 턴 끝 검사가 읽는 보관 계획은 이번 턴에 보관된 것뿐이다. 예전에 보관된 계획의 글로 통과시키지 않는다.
- 맥(BSD) · 리눅스(GNU), bash 3.2 에서 돈다. 코어 파일에 호스트 이름을 넣지 않는다.

2. 끊긴 값을 남기고 판정 · 표 · 멈춘 글이 그 뜻을 알게 한다 — `pb_fixed_run`, `pb_compare`, `pb_render_compare`, `pb_fail_lines`
