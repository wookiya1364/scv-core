# Test Plan — 검사의 빈틈 셋 고치기

## Overview

턴 끝 검사가 보관한 턴을 막지 않는지, 재는 검사가 끊긴 값을 바르게 읽는지, 뚜렷이 빨라진 함수에서 일찍 멈추는지를 본다. 느려진 함수를 놓치지 않는 것도 함께 본다.

## Test scenarios

### T1. 계획을 보관한 턴은 막히지 않는다

- **Setup**: 진행 중 계획이 하나 있는 임시 저장소. 턴을 시작하고, 파일을 고치고, 그 계획에 진행 기록을 남긴 뒤 계획을 보관함으로 옮긴다
- **Run**: 턴 끝 검사
- **Expected**: 통과
- **Pass criterion**: `TURN_PLAN: pass`

### T2. 예전에 보관된 계획으로는 통과하지 않는다

- **Setup**: 턴이 시작되기 전에 이미 보관된 계획만 있는 임시 저장소. 턴을 시작하고 파일을 고친다(기록 없음)
- **Run**: 턴 끝 검사
- **Expected**: 지금처럼 막힌다
- **Pass criterion**: `TURN_PLAN: block`

### T3. 끊긴 값의 판정

- **Setup**: 앞뒤 잰 줄 넷 — 앞 4배가 끊기고 뒤는 9.1배 / 뒤 4배가 끊기고 앞은 4.0배 / 둘 다 끊김 / 앞 시간이 끊기고 뒤는 잼
- **Run**: 판정 함수
- **Expected**: 통과 / 한도 넘음(이유에 끊김) / 통과 / 통과
- **Pass criterion**: 네 줄의 판정이 위와 같다

### T4. 표와 멈춘 글에 끊김이라고 적는다

- **Setup**: 끊긴 값이 든 잰 줄과 판정 줄
- **Run**: 표 만들기, 멈춘 글 만들기
- **Expected**: `too-slow` 대신 `끊김`이 보인다
- **Pass criterion**: 표와 멈춘 글에 `끊김`이 있고 `too-slow` 가 없다

### T5. 뚜렷하면 일찍 멈추고, 아니면 다 잰다

- **Setup**: 임시 폴더의 작은 함수 셋 — 뒤가 10배쯤 빠른 것, 앞뒤가 같은 것, 뒤가 느린 것
- **Run**: 여섯 쌍으로 앞뒤 견주기. 함수마다 잰 쌍의 수를 적게 한다
- **Expected**: 빠른 것은 2쌍, 같은 것과 느린 것은 6쌍. 느린 것은 한도 넘음
- **Pass criterion**: 쌍 수 2 · 6 · 6, 판정 통과 · 통과 · 한도 넘음

### T6. 4배 입력은 뒤가 한도 안이면 앞을 재지 않는다

- **Setup**: 4배 배수가 4쯤인 작은 함수(앞뒤 같음)와, 뒤만 제곱으로 느려지는 함수
- **Run**: 꼼꼼히 견주기
- **Expected**: 앞의 4배 값은 첫 함수에서 재지 않고(빈칸), 둘째 함수에서는 재서 한도 넘음이 나온다
- **Pass criterion**: 첫 함수의 앞 배수 칸 `-` · 판정 통과, 둘째 함수 판정 한도 넘음

## How to run

```bash
bash core/tests/test-pure-bench.sh && bash core/tests/test-turn-plan-check.sh
```

## Pass criteria

- 위 명령이 옛 셸(bash 3.2)과 새 셸(bash 5)에서 끝 코드 0
- 전체 시험이 두 셸에서 통과
- 어제와 같은 마지막 확인의 앞뒤 시간이 계획에 적혀 있다
