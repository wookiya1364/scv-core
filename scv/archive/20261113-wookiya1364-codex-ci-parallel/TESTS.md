# Test Plan — 코덱스 래퍼의 CI 시간 줄이기 — 시험을 여러 러너에 나눠 함께 돌린다

## Overview

두 가지를 본다. 첫째, 나눠도 보는 것이 줄지 않는다 — 코어 시험의 수와 어댑터 검사의 줄 수가 조각 · 부분의 합과 같다. 둘째, 실제로 짧아졌다 — 설정을 고친 PR 의 실행에서 작업 시간을 읽어 목표 값과 견준다. 설정의 어긋남은 코덱스 저장소에 더하는 시험 하나가 지킨다. 시간은 GitHub 실행 기록의 값으로 판정한다.

## Test scenarios

### T1. 원자성 시험은 번호 없이 돌리면 지금과 같다

- **Setup**: 고친 원자성 시험 파일
- **Run**: 부분 번호 없이 돌린다
- **Expected**: 지금과 같은 검사 줄 수, 실패 0
- **Pass criterion**: 결과 줄 `67 passed, 0 failed`

### T2. 세 부분의 합이 전부와 같다

- **Setup**: 같은 파일
- **Run**: 부분 1/3 · 2/3 · 3/3 을 각각 돌린다
- **Expected**: 세 결과의 통과 줄 수 합이 67, 실패 0. 묶음 다섯이 각각 정확히 한 부분에만 들어 있다
- **Pass criterion**: 합 67 · 실패 0 · 묶음마다 든 부분 수 1

### T3. 잘못된 부분 번호는 거절한다

- **Setup**: 같은 파일
- **Run**: 부분 0/3 · 4/3 · 글자
- **Expected**: 아무 시험도 돌지 않고 쓰는 법을 내며 실패로 끝난다 — 조용히 0개를 돌고 통과하지 않는다
- **Pass criterion**: 셋 다 종료 코드 2 · 검사 줄 0개

### T4. 조각 설정이 한 곳만 바뀌면 시험이 잡는다

- **Setup**: 조각 설정을 지키는 새 시험과 PR 검사 설정의 복사본
- **Run**: (가) 그대로 (나) 조각 목록만 일곱으로 (다) 명령의 조각 수만 일곱으로 (라) 원자성 부분 목록에서 하나를 뺌
- **Expected**: (가) 통과, (나) · (다) · (라) 실패하고 어긋난 자리를 댄다
- **Pass criterion**: 종료 코드 0 · 1 · 1 · 1

### T5. 봇은 시험 전부를 돌리지 않는다

- **Setup**: 고친 동기화 봇 설정
- **Run**: 조각 설정을 지키는 시험
- **Expected**: 봇의 검증 단계에 코어 시험 실행기 · 흐름 시험 · 어댑터 시험 호출이 없고, 체크섬 검증 · 문법 검사 · 복사본 검증은 남아 있다
- **Pass criterion**: 시험 실행 호출 0곳 · 남아야 할 검증 셋 다 있음

### T6. 코어 시험의 수가 조각의 합과 같다

- **Setup**: 설정을 고친 PR 의 실행
- **Run**: 조각 여덟의 결과 줄(`run-focused: pass=N fail=0 … shard=i/8`)을 읽는다
- **Expected**: 통과 수의 합이 고치기 전 한 러너에서 돌 때의 통과 수와 같다. 실패 0
- **Pass criterion**: 합 = 고치기 전 값(릴리스 PR #501 의 실행에서 읽은 값) · 실패 0

### T7. 원자성 검사의 줄 수가 부분의 합과 같다 (실제 러너)

- **Setup**: 같은 실행
- **Run**: 맥 · 리눅스 각각 부분 셋의 결과 줄을 읽는다
- **Expected**: 운영체제마다 합 67, 실패 0
- **Pass criterion**: 맥 67 · 리눅스 67

### T8. PR 검사가 5분 안에 끝난다

- **Setup**: 같은 실행
- **Run**: 작업마다 걸린 시간과 실행 전체의 시간을 읽는다
- **Expected**: 가장 긴 작업 300초 안. 실행 전체(첫 작업 시작부터 마지막 작업 끝까지)도 300초 안팎 — 러너를 기다린 시간은 따로 적는다
- **Pass criterion**: 가장 긴 작업 ≤ 300초 (고치기 전 695 ~ 726초)

### T9. 릴리스 흐름이 12분 안에 끝난다

- **Setup**: 설정을 main 까지 반영하는 실행(새 버전 없음)
- **Run**: 그 실행의 걸린 시간을 읽는다
- **Expected**: 720초 안
- **Pass criterion**: ≤ 720초 (고치기 전 1,541 ~ 1,593초) — 넘으면 어디서 썼는지 적고 사용자에게 알린다

### T10. 병합 규칙이 그대로다

- **Setup**: 같은 실행들
- **Run**: 필수 검사 목록과 PR 의 병합 가능 상태를 읽는다
- **Expected**: 필수 검사는 가지 규칙 검사 하나 그대로, 모든 검사가 성공한 뒤에만 병합 가능
- **Pass criterion**: 필수 검사 1개 · 병합 직전 실패한 검사 0

## How to run

```bash
(cd ../scv-codex && bash plugins/scv/tests/test-ci-shards.sh && bash plugins/scv/tests/test-vendor-core-atomicity.sh --part 1/3 && bash plugins/scv/tests/test-vendor-core-atomicity.sh --part 2/3 && bash plugins/scv/tests/test-vendor-core-atomicity.sh --part 3/3)
```

## Pass criteria

- T1 ~ T5 가 로컬(맥)과 코덱스 PR 검사(리눅스 · 맥)에서 통과한다
- T6 ~ T8 · T10 은 설정을 고친 PR 의 실행 기록으로, T9 는 main 까지 반영하는 실행 기록으로 판정한다
- 코어 → 코덱스 릴리스 30분 안은 다음 코어 릴리스 때 잰다 — 이번에는 "못 잼"으로 적는다
