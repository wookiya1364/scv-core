# release-ci

릴리스(core · 래퍼)나 PR 을 올리기 전에 저장소마다 한 번 돌린다: `repo=<core|claude|codex>`.
`RELEASE_OK` 를 낸 뒤에 올린다. 전체 검사와 리눅스 검사는 깃허브가 한 번만 한다 — 이 컴퓨터에서 다시 돌리지 않는다.

왜 이렇게 바꿨나(2026-11-25, 같은 변경으로 잰 값): 깃허브는 리눅스 약 5분 반 · 맥 약 15분, 이 컴퓨터는 리눅스 컨테이너 10~11분 · 맥 27~28분이었다.
깃허브 검사는 병합 규칙 때문에 어차피 다시 돌므로, 로컬 전체 검사는 시간을 줄이지 않고 변경마다 40분쯤을 더했다. 이 컴퓨터가 다른 일로
바쁘면 시간을 재는 시험이 매번 다르게 떨어져 믿을 신호도 아니었다.

- 본체(`core.cmds`): 문법 · 문서 머리 · README · 개인정보 검사와, 바뀐 파일과 관련된 시험만 돈다. 관련 시험은 `related.sh` 가 고른다 —
  바뀐 시험 파일과, 바뀐 파일의 이름을 글에 담은 시험. 시간을 재는 시험(serial 표시)은 뺀다.
- 래퍼(`claude.cmds` · `codex.cmds`): 그 저장소의 CI 가 맥에서 돌리는 명령.
- 명령 목록은 이 폴더의 `<repo>.cmds` 이고 첫 줄 `dir <경로>` 가 돌릴 자리다.
