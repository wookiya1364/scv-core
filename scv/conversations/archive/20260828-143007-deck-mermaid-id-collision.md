# 대화 — 기획서 머메이드 그림이 서로 겹친다

## Turn 1 — 2026-08-28T14:30:07+09:00

**User**: 기획서를 열면 머메이드 그림이 서로 겹쳐서 안 보인다 (화면 캡처로 확인). 그림마다 다른 id 를 주되 재빌드해도 값이 변하지 않게 하고, 화면설계 시트 안의 그림이 제대로 렌더되게 해달라. 두 문제를 한 계획으로 묶는다.

**Claude Code**: 확인된 사실과 추정을 나눈다.

확인된 사실:
- 정적 머메이드 단계가 모든 SVG 에 고정 id 를 붙인다. 소스 한 줄이 원인이고, 주석에 이유가 적혀 있다 — 빌드마다 달라지는 id 를 쓰면 promote 때마다 커밋되는 산출물이 매번 바뀌므로 값을 고정했다.
- 그 결과 한 문서의 그림이 전부 같은 id 를 갖는다. 방금 만든 기획서에서 그림 3장이 모두 같았다. 머메이드는 id 로 스타일 규칙과 화살촉 참조를 한정하므로, 한 그림의 스타일과 마커가 나머지 전부에 적용된다. 이것이 겹침의 직접 원인이다.
- 두 번째 결함: 화면설계 시트의 그림이 빈 그래픽으로 나온다. 내용이 없고 크기 정보도 없어 폭이 100% 로 남는다. 그래서 레이아웃이 무너지고, 클라이언트 쪽 머메이드가 다시 그리면서 다른 절 위에 덮인다.
- 그림을 담는 컨테이너에 숨김 속성은 없다.

추정 (미검증):
- 화면설계 시트의 그림은 덱 자체 변환이 만들어 넣는데, 그 시점이 머메이드 실행 이후라 렌더가 비어 있는 채로 헤드리스 스냅샷에 잡히는 것으로 보인다. 계획 단계에서 확인이 필요하다.

첫 번째 확인 필요 사항: id 를 무엇으로 만들 것인가. 순번은 간단하지만 그림을 하나 끼워 넣으면 뒤 번호가 전부 밀려 산출물 차이가 커진다. 그림 내용에서 뽑은 값이면 위치와 무관하게 그 그림에 붙는다.

## Turn 2 — 2026-08-28T14:32:47+09:00

**User**: id 는 그림 내용에서 뽑는다. 위치가 바뀌어도 같은 그림이면 같은 id 여야 하고, 중간에 한 장 끼워 넣어도 나머지 산출물이 그대로여야 한다.

**Claude Code**: 확정. 그리고 빈 그림 쪽은 조사로 가설 둘을 배제했다.

- 머메이드 코드가 뭉개져서 실패한 것이 아니다. 정적 렌더 이전 상태를 확인했더니 세 그림 모두 줄바꿈과 이스케이프가 정상이고 문법도 유효하다.
- 페이지가 숨겨져 있어 못 잰 것도 아니다. 정적 빌드는 이미 모든 페이지를 강제로 드러내며, 그렇게 하는 이유(숨겨진 채로 처리하면 크기가 0으로 잡히고 한 번 처리된 표시가 남아 고쳐지지 않는다)가 코드 주석에 적혀 있다.

남은 범위: 화면설계 시트 자체의 레이아웃. 머메이드는 컨테이너 폭을 재서 그리는데, 시트를 감싼 상자가 넘침을 숨기고 있어 그 안에서 폭이 0으로 측정되는 것으로 보인다. 일반 그림에는 최소 폭이 걸려 있고 시트 안 그림에는 그 최소 폭이 0으로 재정의돼 있다는 차이도 확인했다 — 이 차이가 유력한 지점이다.

계획의 첫 항목은 이 측정값을 실제로 찍어 확인하는 것이다. 원인이 확정되기 전에는 고치는 방법을 정하지 않는다.

받아들임 기준 초안:
- 한 문서에 그림이 여러 장이면 id 가 서로 다르다
- 같은 그림은 문서에서의 위치가 바뀌어도 같은 id 를 갖는다 (중간 삽입이 뒤 그림의 산출물을 바꾸지 않는다)
- 같은 입력으로 두 번 빌드하면 산출물이 바이트 단위로 같다 (기존 계약 유지)
- 화면설계 시트 안의 그림이 내용 있는 SVG 로 나온다 (빈 그래픽이 아니다)
- 그 그림에 크기 정보가 실린다 (폭이 100% 로 남지 않는다)
- 기존 덱 검사들이 계속 통과한다
