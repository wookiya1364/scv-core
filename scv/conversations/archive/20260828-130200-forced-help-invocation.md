# 대화 — 일반 대화에서 scv:help 호출을 실제로 보장하기

## Turn 1 — 2026-08-28T13:02:00+09:00

**User**: 일반 대화에서 scv:help 가 실제로 호출되는지 보장하고 싶다. 현재 always-on 훅은 매 턴 "help 액션으로 라우팅하라"는 글만 주입할 뿐이라, 모델이 대부분 흘려서 Skill(scv:help) 줄이 안 뜬다. 원하는 것: (A) 사용자 프롬프트 훅이 상태 점검을 직접 실행해 결과를 매 턴 주입 — 모델 판단 없이 100% 보장, (B) 눈에 보이는 SCV 표시줄로 동작 여부를 사용자가 구분 가능하게, (C) 안내 문구를 "답하기 전 첫 행동으로 이 스킬을 호출하라"는 명령형으로 강화, (D) 그래도 호출하지 않으면 응답 종료 훅이 되돌려 세워 최대 5회까지 재시도시키고, 5회 소진 시 포기하고 세션을 절대 막지 않는다. 기존 non-blocking 보장과 저널 기록은 유지해야 한다.

**Claude Code**: 호스트를 직접 조사해 확인한 사실을 먼저 정리했습니다.

- 사용자 프롬프트 훅은 프롬프트를 바꿔치기하는 필드가 없다 (updatedPrompt 부재). 컨텍스트에 글을 덧붙이는 additionalContext 만 존재한다.
- 스킬 호출을 강제하는 장치는 없다 (forceSkill / autoInvoke / forceToolUse 전부 부재).
- 그러나 응답 종료 훅은 block + 사유로 모델을 되돌려 세울 수 있고, 무한루프 방지 플래그 stop_hook_active 가 호스트에 내장돼 있다.
- 스킬 호출 직전 훅이 이미 SCV 가드로 등록돼 있어, help 가 실제로 불렸는지 표시를 남길 수 있다.
- 상태 점검 실측: 0.45초, 출력 약 6KB.

따라서 "무조건 뜨게"는 지시 강화만으로는 불가능하고, 세 훅을 엮어야 한다: 프롬프트 훅이 상태를 결정적으로 주입하고, 스킬 훅이 호출 여부를 표시로 남기고, 종료 훅이 표시가 없으면 되돌려 세운다.

첫 번째 확인 필요 사항: 상태 점검 결과를 매 턴 주입하면 턴당 약 6KB 가 컨텍스트에 쌓인다. 매 턴 그대로 갈지, 아니면 결과를 잠깐 재사용할지 정해야 한다.

1. 사용자 프롬프트 훅 — 눈에 보이는 SCV 표시줄 한 줄 + 명령형 안내("답하기 전 첫 행동으로 help 를 호출하라")를 주입한다. 전체 상태 점검은 넣지 않는다. 동시에 이번 턴의 호출 표시와 재시도 카운터를 초기화한다.
2. 스킬 호출 직전 훅 — 호출된 스킬이 help 이면 이번 세션/턴의 호출 표시를 남긴다.
3. 응답 종료 훅 — 호출 표시가 없고 재시도 여유가 있으면 block + 사유로 모델을 되돌려 세운다. 카운터를 올리고, 상한(기본 5)에 도달하면 포기하고 exit 0 한다. 세션은 어떤 경우에도 막지 않는다.

기존 규칙 유지: 스위치가 off 면 아무 것도 하지 않는다. scv 폴더가 없으면 출력 없음. 저널 기록 동작 불변. 이미 다른 SCV 액션 프로토콜이 실린 턴은 가로채지 않는다.

받아들임 기준 초안:
- 호출 표시 없음 + 카운터 여유 → 종료 훅이 block 결정을 출력한다
- 호출 표시 있음 → 종료 훅은 block 하지 않는다
- 카운터가 상한에 도달 → block 하지 않는다 (세션이 갇히지 않는다)
- 스위치 off → 라우팅 출력도 없고 block 도 없다
- scv 폴더 없는 곳 → 출력 없음, block 없음
- 저널 기록은 기존과 동일하게 남는다
