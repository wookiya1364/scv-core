# 처음 돌아가는 순간 실제 결과를 보여 주기 — 대충 말해도 원하는 결과로

## Summary

사람은 상상만으로는 감이 오지 않아, 실제로 돌아가는 것을 볼 때에야 진짜 요구를 말한다(사용자 원칙, 2026-10-06).
그래서 결과물이 바뀌는 일이면 모델이 **처음 돌아가는 순간 가장 작은 것을 실제로 실행해 그 결과를 그대로 보여 주고 짧게 묻도록** SCV 가 안내한다.
막는 검사 없이 안내만 넣고 스위치로 끌 수 있게 하며, 효과는 며칠의 실제 사용 기록으로 확인한다.
이 계획은 '끝내기 전 결과 견본 확인'(20261005-wookiya1364-verify-by-sample)을 대체한다 — 긴 공개 과제 실측에서 글로 된 견본 확인은 지금 SCV 보다 낮았고(7/18 · 12/18), 이 방식은 지금 SCV 보다 조금 높았다(12/18 · 10/18). 둘 다 미리 정한 판정으로는 가르지 못했다.

## Goals / Non-Goals

- **Goals**
  1. **실체 보여 주기 안내**: 결과물(파일 · 출력 · 화면, 라이브러리면 공개 함수를 실제로 불러 본 결과)이 바뀌는 일이면, 설명이나 글로 된 견본 대신 처음 돌아가는 순간에 가장 작은 것을 실제로 실행해 그 결과를 그대로 보여 주고 "이대로 계속할까요, 고칠 점이 있나요?"를 짧게 묻는다. 설명은 한두 줄. 문구는 2026-10-06 두 번째 실측에서 잰 그대로를 바탕으로 한다.
  2. **결과물이 안 바뀌는 일은 그대로**: 내부 결함 수정 · 구조 정리처럼 결과물이 바뀌지 않는 일은 보여 주지도 묻지도 않고 "결과물 변화 없음"이라고 적는다.
  3. **보기 2개 이상**: 확인을 선택 창으로 물을 때 보기는 2개 이상(예: 계속 · 고칠 점)이다. 선택 창이 없는 호스트는 글 질문 한 번으로 묻는다.
  4. **스위치**: 설정 키 하나(예: `SCV_SHOW_REAL`, 기본 on)로 끈다. 끄면 지금 SCV 와 같은 동작.
  5. **실사용 확인**: 켠 뒤 며칠의 실제 세션 기록에서 (a) 결과물이 바뀐 일 중 처음 돌아가는 결과를 보여 준 비율 (b) 완료 보고 뒤에 나온 사용자 수정 요구 수 (c) 확인 창 수를 세어, 켜기 전 기록과 나란히 보고한다. 계속 켤지 · 끌지 · 뺄지는 그 숫자를 보고 사용자와 정한다.
  6. **두 래퍼**: 규칙 본문은 코어에 한 번. 코어 릴리스 뒤 두 래퍼 동기화.
- **Non-Goals**
  - 견본 확인 없이 끝내면 막는 검사(옛 계획 목표 9) — 긴 과제 실측에서 근거가 나오지 않았다.
  - 글로 된 견본 확인 · '이대로 좋음'(추천) 하나짜리 확인 창 — 실측에서 낮았고, 보기 하나짜리 창은 Claude Code 가 거절했다(18개 실행 모두, 합 39번).
  - 바깥 조건 미리 묻기 · 같은 계열 결함 찾기(옛 계획 목표 3 · 4) — 이번 실측에서 따로 재지 않았다. 필요하면 별도 계획.
  - 측정 장치를 저장소 도구로 옮기기 — 긴 과제 장치는 저장소 밖에 그대로 두고 다시 잴 때 쓴다.
  - 모델마다 다른 문구, 모델 · 생각 깊이 바꾸기.

## Approach Overview

규칙 본문은 코어 계약 한 곳(예: `core/contracts/show-real.md`)에 둔다(같은 요구는 한 곳에만 — SCV Top-level rules).
매 턴 훅이 켜짐일 때 짧은 안내(두세 줄)를 싣고, 자세한 본문은 계약을 가리킨다. 안내 문구를 만드는 것은 순수 함수다.
호스트 프로필의 선택 창 이름(있으면)에 따라 '선택 창 — 보기 2개 이상' 또는 '글 질문 한 번' 문구를 고른다.
설정 키가 off 면 매 턴 블록에 아무것도 더하지 않는다 — 지금 SCV 와 같은 출력(바이트 단위). 종료 훅에는 아무것도 더하지 않는다(막는 검사 없음).
실사용 확인은 사용자의 실제 세션 기록을 읽어 세 숫자를 세는 보고 스크립트로 한다. 기록 읽기와 출력만 부수효과이고, 분류 · 집계는 순수 함수다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

매 턴 안내:

```
flow(
  readShowRealSwitch,   // (설정 값 원문)          → on | off
  pickConfirmChannel,   // (호스트의 선택 창 이름)  → choice | text
  buildShowRealRule,    // (on|off, choice|text)   → 매 턴 블록에 덧붙일 문구(off 면 빈 값)
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | readShowRealSwitch | 설정 원문 → on/off(없거나 다른 값은 on) | 순수 |
| 2 | pickConfirmChannel | 선택 창 이름(빈 값 가능) → choice/text | 순수 |
| 3 | buildShowRealRule | on/off · choice/text → 문구 | 순수 |
| 4 | 매 턴 훅 출력 | 문구 → 표준 출력 | 부수효과 (출구) |

실사용 보고:

```
flow(
  splitSessions,       // (세션 기록 항목들)            → 사람 턴 단위 묶음
  classifyTurns,       // (턴 묶음)                     → 결과물 변화 · 첫 실제 결과 표시 · 완료 보고 · 이후 수정 요구 · 확인 창 표시
  countShowReal,       // (분류된 턴들, 기간 경계)       → 기간별 세 숫자(보여 준 비율 · 완료 뒤 수정 요구 · 확인 창 수)
  renderReport,        // (기간별 숫자)                 → 표 한 장(켜기 전 · 켠 뒤)
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 5 | 세션 기록 읽기 | 기간 → 기록 항목들 | 부수효과 (입구) |
| 6 | splitSessions | 항목들 → 사람 턴 묶음 | 순수 |
| 7 | classifyTurns | 턴 묶음 → 턴마다 표시 | 순수 |
| 8 | countShowReal | 표시 · 기간 경계 → 세 숫자 | 순수 |
| 9 | renderReport | 숫자 → 표 | 순수 |
| 10 | 보고 출력 | 표 → 표준 출력 | 부수효과 (출구) |

- 부수효과 위치: 설정 파일 · 세션 기록 읽기(입구)와 매 턴 훅 출력 · 보고 출력(출구)만.
- 재사용: 설정 읽기 라이브러리, 호스트 프로필(선택 창 이름), 매 턴 블록 조립.

- 매 턴 등록 · 다시 쓴 요청 인용 · 맨 위 한 줄, 선택 창 규칙(추천 보기 먼저)과 답 뒤 재등록, 가드 동작은 그대로다.
- SCV 는 모델 · 생각 깊이를 바꾸지 않는다.
- 맥(bash 3.2 · BSD 도구)과 리눅스(GNU) 모두에서 같은 결과. 순수 함수 검사(순수성 검사기)를 통과한다.
- 실사용 보고는 사용자 자신의 기록만 읽고, 보고에 다른 프로젝트 내용 · 메일 주소 · 비밀값을 넣지 않는다(공개 저장소).
- 긴 과제 측정은 실제 Claude 세션을 돌린다 — CI 에 넣지 않는다. 비용 이야기 대신 횟수와 시간으로 규모를 정한다.

## 예외처리 (Edge cases)

- **결과물이 큼**: 실행 결과의 첫 몇 줄(또는 바뀐 부분)만 보이고 전체 위치를 함께 알린다.
- **결과물이 글이 아님**(이미지 · 이진 파일 · 화면): 실제로 띄운 화면이나 파일의 종류 · 크기 · 여는 법을 보인다.
- **아직 돌릴 수 없음**(처음 단계에 실행할 것이 없음): 돌아가는 가장 작은 것이 생기는 첫 순간까지 미루고, 억지 예시를 지어내지 않는다.
- **결과에 비밀값 · 개인 정보**: 기존 가림 필터로 가린 뒤 보인다.
- **사람이 없는 실행**(무인 · 자동 알림으로 이어진 턴): 묻지 않고, 보여 준 결과를 보고에만 남긴다.
- **설정 값이 엉뚱함**: on 으로 본다(다른 SCV 스위치와 같은 규칙).

## Exit criteria

- All TESTS.md scenarios pass (자동 검사는 맥 · 리눅스 CI).
- 설치본에서 긴 과제 과제 6개 × 1번의 짧은 확인(T9)으로, 안내가 실제로 따라지고(처음 돌아가는 결과를 보여 줌) 보기 하나짜리 창 거절이 0번임을 확인한다.
- 켠 뒤 며칠의 실사용 보고(T10)를 사용자에게 보이고, 계속 켤지 · 끌지 · 뺄지를 사용자와 정한다(기간과 판단 기준은 시작할 때 사용자와 정함).
- 설정 off 에서 매 턴 출력이 지금과 같다.
- 두 래퍼 설치본에서 안내 문구와 설정 키가 확인된다.

## Suggested path

1. 규칙 본문을 코어 계약으로 쓰고, 순수 함수 셋 · 매 턴 블록 연결 · 설정 키(기본 on)를 더한다.
2. 단위 검사: 문구(켬 · 끔 · 선택 창 유무), 끄면 그대로, 보기 2개 이상 문구, 결과물 변화 없는 일 문구, 종료 훅 출력 불변, 순수성.
3. 실사용 보고 스크립트(순수 집계 + 기록 읽기 · 출력)를 더하고, 고정 기록으로 단위 검사한다.
4. 코어 릴리스 → 두 래퍼 동기화 · 릴리스 → 설치본 확인(T9 짧은 긴 과제 확인 · T12 두 래퍼).
5. 며칠 실사용 뒤 보고(T10)를 보이고 사용자와 다음을 정한다.

## Risks / Open Questions

- 효과는 아직 증명되지 않았다 — 과제 6개로는 지금 SCV 와의 차이(+2/18)를 가를 수 없었고, 같은 지금 SCV 도 두 번 돌리니 12/18 → 10/18 로 흔들렸다.
- 긴 과제의 관리자 역할은 AI 라서, 사람이 실체를 볼 때 요구를 더 빨리 말하는지(사용자 원칙의 핵심)는 재지 못했다 — 실사용 확인이 그 몫이다.
- 확인 창이 늘어 사용자가 번거로울 수 있다(긴 과제에서 관리자 답 +33%, 글로 쓴 요구 수는 같음) — 스위치로 끈다.
- 실측은 안내를 세션 지시로 덧붙인 형태였다 — 매 턴 훅 안내로 넣은 형태가 같은 행동을 끌어내는지 T9 로 확인한다.
- 실사용 비교는 기간이 달라 일의 종류도 다르다 — 숫자는 방향을 보는 용도이고, 해석을 사용자와 함께 한다.
- Sonnet 5 · Haiku 4.5 는 지시를 자주 건너뛰었다(옛 계획 실측) — 이 안내도 그럴 수 있다. 막는 검사 없이 두므로 모델별 차이는 실사용 보고에서 본다.
- 실사용 기간과 판단 기준은 미결 — 시작할 때 사용자와 정한다.

# Test Plan — 처음 돌아가는 순간 실제 결과를 보여 주기 — 대충 말해도 원하는 결과로

## Overview

결과물이 바뀌는 일이면 처음 돌아가는 순간 실제 결과를 보여 주고 짧게 묻는 안내가 SCV 에 들어가고, 막는 검사 없이 · 스위치로 끌 수 있게 · 보기 2개 이상 · 결과물이 안 바뀌는 일에는 질문을 더하지 않게 동작하는지 확인한다.
자동 검사(문구 · 설정 · 순수 함수 · 규약 · 종료 훅 불변 · 실사용 보고 집계)는 맥 · 리눅스 CI 에서 돈다. 실제 효과는 설치본의 짧은 긴 과제 확인(T9)과 며칠의 실사용 보고(T10)로 본다.
기준선(긴 과제 실측, 2026-10-06 ~ 07, 과제 6개 × 3번): 지금 SCV 12/18 · 10/18(두 번), 글로 된 견본 7/18, 실체 보여 주기 12/18 — 둘 다 미리 정한 판정으로는 가르지 못함.

## Test scenarios

### T1. 켬 — 매 턴 블록에 실체 보여 주기 안내가 실린다

- **Setup**: 하이드레이트한 임시 저장소, 설정 키 없음(기본 on), 선택 창이 있는 호스트 프로필(Claude Code).
- **Run**: 매 턴 훅에 사람 메시지 하나를 넣는다.
- **Expected**: 매 턴 블록에 안내가 실린다 — 결과물이 바뀌는 일이면 처음 돌아가는 순간 가장 작은 것을 실제로 실행해 그 결과를 그대로 보여 주고 "이대로 계속할까요, 고칠 점이 있나요?"를 짧게 묻기, 설명은 한두 줄. 안내는 두세 줄이고 자세한 본문은 계약을 가리킨다.
- **Pass criterion**: 출력에 안내 문구와 계약 경로가 있다.

### T2. 끔 — 설정 off 면 지금 SCV 와 같은 출력

- **Setup**: T1 과 같되 설정 키를 off(대소문자 무관).
- **Run**: 같은 메시지로 매 턴 훅을 돌리고, 이 기능이 없는 코어(직전 릴리스)의 출력과 비교한다.
- **Expected**: 매 턴 훅 출력이 바이트 단위로 같다.
- **Pass criterion**: diff 없음.

### T3. 선택 창이 없는 호스트 — 글 질문 한 번

- **Setup**: 선택 창 이름이 비어 있는 호스트 프로필(코덱스 모양).
- **Run**: 매 턴 훅을 돌린다.
- **Expected**: 안내가 '선택 창' 대신 '글 질문 한 번으로 묻기'를 말한다.
- **Pass criterion**: 선택 창 문구 없음, 글 질문 문구 있음.

### T4. 순수 함수 단위

- **Setup**: 코어 라이브러리를 불러온다.
- **Run**: 설정 해석(없음 · on · off · OFF · 엉뚱한 값), 확인 통로 고르기(빈 값 · 선택 창 이름), 문구 만들기(켬/끔 × 선택 창/글)를 표로 확인한다.
- **Expected**: 없거나 엉뚱한 값은 on, off(대소문자 무관)만 off. 끔이면 문구는 빈 값.
- **Pass criterion**: 표의 모든 칸 일치, 순수성 검사기 통과(bash 5 · 3.2).

### T5. 규칙 본문은 한 곳에만

- **Setup**: 저장소.
- **Run**: 규칙 일치 검사(같은 요구는 한 곳에만)를 돌린다.
- **Expected**: 실체 보여 주기 규칙의 본문이 코어 계약 한 곳에만 있고, 매 턴 훅 · 다른 문서는 가리키기만 한다.
- **Pass criterion**: 검사 통과, 본문 중복 0.

### T6. 막는 검사 없음 — 종료 훅 출력이 바뀌지 않는다

- **Setup**: 설정 on, 사람 메시지로 열린 턴, 이번 턴 기록 고정본: 코드 파일 편집 → 실제 결과 표시 없음 → 확인 질문 없음.
- **Run**: 종료 훅을 돌리고, 이 기능이 없는 코어의 종료 훅 출력과 비교한다.
- **Expected**: 막지 않고, 출력이 바이트 단위로 같다.
- **Pass criterion**: 막음 0번, diff 없음.

### T7. 보기 2개 이상

- **Setup**: T1 의 출력과 코어 계약.
- **Run**: 안내 문구와 계약에서 확인 창 보기에 대한 지시를 찾는다.
- **Expected**: 선택 창으로 물을 때 보기를 2개 이상(예: 계속 · 고칠 점) 두라고 말하고, 보기 하나짜리 창을 만들게 하는 문구(예: "보기는 … 하나로")가 없다.
- **Pass criterion**: 2개 이상 지시 있음, 하나짜리 지시 0개.

### T8. 결과물이 안 바뀌는 일에는 질문을 더하지 않음

- **Setup**: T1 의 출력과 코어 계약.
- **Run**: 결과물이 바뀌지 않는 일(내부 결함 수정 · 구조 정리)에 대한 지시를 찾는다.
- **Expected**: 보여 주지도 묻지도 않고 "결과물 변화 없음"이라고 적으라고 말한다.
- **Pass criterion**: 그 지시가 있다.

### T9. 설치본 짧은 긴 과제 확인 (사람이 돌림 — 실제 Claude 세션)

- **Setup**: 새 설치본, 저장소 밖 긴 과제 장치(`~/scv-experiments/longbench`, 장치 고침 1~8 판), 관리자 역할 Opus.
- **Run**: 과제 6개 × 새 설치본 1번씩 돌린다(안내는 장치가 덧붙이지 않고 설치본의 매 턴 훅만으로).
- **Expected**: 결과물이 바뀌는 단계에서 처음 돌아가는 실제 결과를 보여 주는 실행이 있고(대화 기록), 보기 하나짜리 창 거절이 0번이다.
- **Pass criterion**: 6과제 중 실제 결과를 먼저 보여 준 과제 수를 기록하고, 거절 0번. 숨은 테스트 통과 수는 기록만 한다(효과 판정 아님).

### T10. 실사용 보고 — 세 숫자 (켠 뒤 며칠)

- **Setup**: 사용자의 실제 세션 기록, 켜기 전 며칠과 켠 뒤 며칠(기간은 시작할 때 사용자와 정함).
- **Run**: 실사용 보고 스크립트를 돌린다.
- **Expected**: 기간마다 (a) 결과물이 바뀐 일 중 처음 돌아가는 결과를 보여 준 비율 (b) 완료 보고 뒤에 나온 사용자 수정 요구 수(세션당) (c) 확인 창 수(세션당)가 표 한 장으로 나온다. 보고에 다른 프로젝트 내용 · 메일 주소 · 비밀값이 없다.
- **Pass criterion**: 표가 나오고 사용자에게 보였다. 계속 켤지 · 끌지 · 뺄지는 사용자 결정으로 닫는다.

### T11. 실사용 보고 집계 — 고정 기록 단위 검사

- **Setup**: 손으로 만든 세션 기록 고정본(결과물 변화 있음 · 없음, 실제 결과를 먼저 보여 줌 · 안 보여 줌, 완료 뒤 수정 요구 있음 · 없음, 선택 창 · 글 질문).
- **Run**: 순수 집계 단계(splitSessions · classifyTurns · countShowReal · renderReport)를 돌린다.
- **Expected**: 세 숫자가 고정본에서 손으로 센 값과 같다.
- **Pass criterion**: 모든 칸 일치, 순수성 검사기 통과.

### T12. 두 래퍼 설치본

- **Setup**: 코어 릴리스 뒤 두 래퍼 동기화 · 릴리스.
- **Run**: 두 설치본의 매 턴 훅 출력과 설정 예시를 확인한다.
- **Expected**: Claude Code 는 선택 창 문구(보기 2개 이상), 코덱스는 글 질문 문구, 설정 키가 예시 파일에 있다.

# 처음 돌아가는 순간 실제 결과를 보여 주기 — 대충 말해도 원하는 결과로

## Summary

사람은 상상만으로는 감이 오지 않아, 실제로 돌아가는 것을 볼 때에야 진짜 요구를 말한다(사용자 원칙, 2026-10-06).
그래서 결과물이 바뀌는 일이면 모델이 **처음 돌아가는 순간 가장 작은 것을 실제로 실행해 그 결과를 그대로 보여 주고 짧게 묻도록** SCV 가 안내한다.
막는 검사 없이 안내만 넣고 스위치로 끌 수 있게 하며, 효과는 며칠의 실제 사용 기록으로 확인한다.
이 계획은 '끝내기 전 결과 견본 확인'(20261005-wookiya1364-verify-by-sample)을 대체한다 — 긴 공개 과제 실측에서 글로 된 견본 확인은 지금 SCV 보다 낮았고(7/18 · 12/18), 이 방식은 지금 SCV 보다 조금 높았다(12/18 · 10/18). 둘 다 미리 정한 판정으로는 가르지 못했다.

## Goals / Non-Goals

- **Goals**
  1. **실체 보여 주기 안내**: 결과물(파일 · 출력 · 화면, 라이브러리면 공개 함수를 실제로 불러 본 결과)이 바뀌는 일이면, 설명이나 글로 된 견본 대신 처음 돌아가는 순간에 가장 작은 것을 실제로 실행해 그 결과를 그대로 보여 주고 "이대로 계속할까요, 고칠 점이 있나요?"를 짧게 묻는다. 설명은 한두 줄. 문구는 2026-10-06 두 번째 실측에서 잰 그대로를 바탕으로 한다.
  2. **결과물이 안 바뀌는 일은 그대로**: 내부 결함 수정 · 구조 정리처럼 결과물이 바뀌지 않는 일은 보여 주지도 묻지도 않고 "결과물 변화 없음"이라고 적는다.
  3. **보기 2개 이상**: 확인을 선택 창으로 물을 때 보기는 2개 이상(예: 계속 · 고칠 점)이다. 선택 창이 없는 호스트는 글 질문 한 번으로 묻는다.
  4. **스위치**: 설정 키 하나(예: `SCV_SHOW_REAL`, 기본 on)로 끈다. 끄면 지금 SCV 와 같은 동작.
  5. **실사용 확인**: 켠 뒤 며칠의 실제 세션 기록에서 (a) 결과물이 바뀐 일 중 처음 돌아가는 결과를 보여 준 비율 (b) 완료 보고 뒤에 나온 사용자 수정 요구 수 (c) 확인 창 수를 세어, 켜기 전 기록과 나란히 보고한다. 계속 켤지 · 끌지 · 뺄지는 그 숫자를 보고 사용자와 정한다.
  6. **두 래퍼**: 규칙 본문은 코어에 한 번. 코어 릴리스 뒤 두 래퍼 동기화.
- **Non-Goals**
  - 견본 확인 없이 끝내면 막는 검사(옛 계획 목표 9) — 긴 과제 실측에서 근거가 나오지 않았다.
  - 글로 된 견본 확인 · '이대로 좋음'(추천) 하나짜리 확인 창 — 실측에서 낮았고, 보기 하나짜리 창은 Claude Code 가 거절했다(18개 실행 모두, 합 39번).
  - 바깥 조건 미리 묻기 · 같은 계열 결함 찾기(옛 계획 목표 3 · 4) — 이번 실측에서 따로 재지 않았다. 필요하면 별도 계획.
  - 측정 장치를 저장소 도구로 옮기기 — 긴 과제 장치는 저장소 밖에 그대로 두고 다시 잴 때 쓴다.
  - 모델마다 다른 문구, 모델 · 생각 깊이 바꾸기.

## Approach Overview

규칙 본문은 코어 계약 한 곳(예: `core/contracts/show-real.md`)에 둔다(같은 요구는 한 곳에만 — SCV Top-level rules).
매 턴 훅이 켜짐일 때 짧은 안내(두세 줄)를 싣고, 자세한 본문은 계약을 가리킨다. 안내 문구를 만드는 것은 순수 함수다.
호스트 프로필의 선택 창 이름(있으면)에 따라 '선택 창 — 보기 2개 이상' 또는 '글 질문 한 번' 문구를 고른다.
설정 키가 off 면 매 턴 블록에 아무것도 더하지 않는다 — 지금 SCV 와 같은 출력(바이트 단위). 종료 훅에는 아무것도 더하지 않는다(막는 검사 없음).
실사용 확인은 사용자의 실제 세션 기록을 읽어 세 숫자를 세는 보고 스크립트로 한다. 기록 읽기와 출력만 부수효과이고, 분류 · 집계는 순수 함수다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

매 턴 안내:

```
flow(
  readShowRealSwitch,   // (설정 값 원문)          → on | off
  pickConfirmChannel,   // (호스트의 선택 창 이름)  → choice | text
  buildShowRealRule,    // (on|off, choice|text)   → 매 턴 블록에 덧붙일 문구(off 면 빈 값)
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | readShowRealSwitch | 설정 원문 → on/off(없거나 다른 값은 on) | 순수 |
| 2 | pickConfirmChannel | 선택 창 이름(빈 값 가능) → choice/text | 순수 |
| 3 | buildShowRealRule | on/off · choice/text → 문구 | 순수 |
| 4 | 매 턴 훅 출력 | 문구 → 표준 출력 | 부수효과 (출구) |

실사용 보고:

```
flow(
  splitSessions,       // (세션 기록 항목들)            → 사람 턴 단위 묶음
  classifyTurns,       // (턴 묶음)                     → 결과물 변화 · 첫 실제 결과 표시 · 완료 보고 · 이후 수정 요구 · 확인 창 표시
  countShowReal,       // (분류된 턴들, 기간 경계)       → 기간별 세 숫자(보여 준 비율 · 완료 뒤 수정 요구 · 확인 창 수)
  renderReport,        // (기간별 숫자)                 → 표 한 장(켜기 전 · 켠 뒤)
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 5 | 세션 기록 읽기 | 기간 → 기록 항목들 | 부수효과 (입구) |
| 6 | splitSessions | 항목들 → 사람 턴 묶음 | 순수 |
| 7 | classifyTurns | 턴 묶음 → 턴마다 표시 | 순수 |
| 8 | countShowReal | 표시 · 기간 경계 → 세 숫자 | 순수 |
| 9 | renderReport | 숫자 → 표 | 순수 |
| 10 | 보고 출력 | 표 → 표준 출력 | 부수효과 (출구) |

- 부수효과 위치: 설정 파일 · 세션 기록 읽기(입구)와 매 턴 훅 출력 · 보고 출력(출구)만.
- 재사용: 설정 읽기 라이브러리, 호스트 프로필(선택 창 이름), 매 턴 블록 조립.

## 예외처리 (Edge cases)

- **결과물이 큼**: 실행 결과의 첫 몇 줄(또는 바뀐 부분)만 보이고 전체 위치를 함께 알린다.
- **결과물이 글이 아님**(이미지 · 이진 파일 · 화면): 실제로 띄운 화면이나 파일의 종류 · 크기 · 여는 법을 보인다.
- **아직 돌릴 수 없음**(처음 단계에 실행할 것이 없음): 돌아가는 가장 작은 것이 생기는 첫 순간까지 미루고, 억지 예시를 지어내지 않는다.
- **결과에 비밀값 · 개인 정보**: 기존 가림 필터로 가린 뒤 보인다.
- **사람이 없는 실행**(무인 · 자동 알림으로 이어진 턴): 묻지 않고, 보여 준 결과를 보고에만 남긴다.
- **설정 값이 엉뚱함**: on 으로 본다(다른 SCV 스위치와 같은 규칙).

# Test Plan — 처음 돌아가는 순간 실제 결과를 보여 주기 — 대충 말해도 원하는 결과로

## Overview

결과물이 바뀌는 일이면 처음 돌아가는 순간 실제 결과를 보여 주고 짧게 묻는 안내가 SCV 에 들어가고, 막는 검사 없이 · 스위치로 끌 수 있게 · 보기 2개 이상 · 결과물이 안 바뀌는 일에는 질문을 더하지 않게 동작하는지 확인한다.
자동 검사(문구 · 설정 · 순수 함수 · 규약 · 종료 훅 불변 · 실사용 보고 집계)는 맥 · 리눅스 CI 에서 돈다. 실제 효과는 설치본의 짧은 긴 과제 확인(T9)과 며칠의 실사용 보고(T10)로 본다.
기준선(긴 과제 실측, 2026-10-06 ~ 07, 과제 6개 × 3번): 지금 SCV 12/18 · 10/18(두 번), 글로 된 견본 7/18, 실체 보여 주기 12/18 — 둘 다 미리 정한 판정으로는 가르지 못함.

## Test scenarios

### T1. 켬 — 매 턴 블록에 실체 보여 주기 안내가 실린다

- **Setup**: 하이드레이트한 임시 저장소, 설정 키 없음(기본 on), 선택 창이 있는 호스트 프로필(Claude Code).
- **Run**: 매 턴 훅에 사람 메시지 하나를 넣는다.
- **Expected**: 매 턴 블록에 안내가 실린다 — 결과물이 바뀌는 일이면 처음 돌아가는 순간 가장 작은 것을 실제로 실행해 그 결과를 그대로 보여 주고 "이대로 계속할까요, 고칠 점이 있나요?"를 짧게 묻기, 설명은 한두 줄. 안내는 두세 줄이고 자세한 본문은 계약을 가리킨다.
- **Pass criterion**: 출력에 안내 문구와 계약 경로가 있다.

### T2. 끔 — 설정 off 면 지금 SCV 와 같은 출력

- **Setup**: T1 과 같되 설정 키를 off(대소문자 무관).
- **Run**: 같은 메시지로 매 턴 훅을 돌리고, 이 기능이 없는 코어(직전 릴리스)의 출력과 비교한다.
- **Expected**: 매 턴 훅 출력이 바이트 단위로 같다.
- **Pass criterion**: diff 없음.

### T3. 선택 창이 없는 호스트 — 글 질문 한 번

- **Setup**: 선택 창 이름이 비어 있는 호스트 프로필(코덱스 모양).
- **Run**: 매 턴 훅을 돌린다.
- **Expected**: 안내가 '선택 창' 대신 '글 질문 한 번으로 묻기'를 말한다.
- **Pass criterion**: 선택 창 문구 없음, 글 질문 문구 있음.

### T4. 순수 함수 단위

- **Setup**: 코어 라이브러리를 불러온다.
- **Run**: 설정 해석(없음 · on · off · OFF · 엉뚱한 값), 확인 통로 고르기(빈 값 · 선택 창 이름), 문구 만들기(켬/끔 × 선택 창/글)를 표로 확인한다.
- **Expected**: 없거나 엉뚱한 값은 on, off(대소문자 무관)만 off. 끔이면 문구는 빈 값.
- **Pass criterion**: 표의 모든 칸 일치, 순수성 검사기 통과(bash 5 · 3.2).

### T5. 규칙 본문은 한 곳에만

- **Setup**: 저장소.
- **Run**: 규칙 일치 검사(같은 요구는 한 곳에만)를 돌린다.
- **Expected**: 실체 보여 주기 규칙의 본문이 코어 계약 한 곳에만 있고, 매 턴 훅 · 다른 문서는 가리키기만 한다.
- **Pass criterion**: 검사 통과, 본문 중복 0.

### T6. 막는 검사 없음 — 종료 훅 출력이 바뀌지 않는다

- **Setup**: 설정 on, 사람 메시지로 열린 턴, 이번 턴 기록 고정본: 코드 파일 편집 → 실제 결과 표시 없음 → 확인 질문 없음.
- **Run**: 종료 훅을 돌리고, 이 기능이 없는 코어의 종료 훅 출력과 비교한다.
- **Expected**: 막지 않고, 출력이 바이트 단위로 같다.
- **Pass criterion**: 막음 0번, diff 없음.

### T7. 보기 2개 이상

- **Setup**: T1 의 출력과 코어 계약.
- **Run**: 안내 문구와 계약에서 확인 창 보기에 대한 지시를 찾는다.
- **Expected**: 선택 창으로 물을 때 보기를 2개 이상(예: 계속 · 고칠 점) 두라고 말하고, 보기 하나짜리 창을 만들게 하는 문구(예: "보기는 … 하나로")가 없다.
- **Pass criterion**: 2개 이상 지시 있음, 하나짜리 지시 0개.

### T8. 결과물이 안 바뀌는 일에는 질문을 더하지 않음

- **Setup**: T1 의 출력과 코어 계약.
- **Run**: 결과물이 바뀌지 않는 일(내부 결함 수정 · 구조 정리)에 대한 지시를 찾는다.
- **Expected**: 보여 주지도 묻지도 않고 "결과물 변화 없음"이라고 적으라고 말한다.
- **Pass criterion**: 그 지시가 있다.

### T9. 설치본 짧은 긴 과제 확인 (사람이 돌림 — 실제 Claude 세션)

- **Setup**: 새 설치본, 저장소 밖 긴 과제 장치(`~/scv-experiments/longbench`, 장치 고침 1~8 판), 관리자 역할 Opus.
- **Run**: 과제 6개 × 새 설치본 1번씩 돌린다(안내는 장치가 덧붙이지 않고 설치본의 매 턴 훅만으로).
- **Expected**: 결과물이 바뀌는 단계에서 처음 돌아가는 실제 결과를 보여 주는 실행이 있고(대화 기록), 보기 하나짜리 창 거절이 0번이다.
- **Pass criterion**: 6과제 중 실제 결과를 먼저 보여 준 과제 수를 기록하고, 거절 0번. 숨은 테스트 통과 수는 기록만 한다(효과 판정 아님).

### T10. 실사용 보고 — 세 숫자 (켠 뒤 며칠)

- **Setup**: 사용자의 실제 세션 기록, 켜기 전 며칠과 켠 뒤 며칠(기간은 시작할 때 사용자와 정함).
- **Run**: 실사용 보고 스크립트를 돌린다.
- **Expected**: 기간마다 (a) 결과물이 바뀐 일 중 처음 돌아가는 결과를 보여 준 비율 (b) 완료 보고 뒤에 나온 사용자 수정 요구 수(세션당) (c) 확인 창 수(세션당)가 표 한 장으로 나온다. 보고에 다른 프로젝트 내용 · 메일 주소 · 비밀값이 없다.
- **Pass criterion**: 표가 나오고 사용자에게 보였다. 계속 켤지 · 끌지 · 뺄지는 사용자 결정으로 닫는다.

### T11. 실사용 보고 집계 — 고정 기록 단위 검사

- **Setup**: 손으로 만든 세션 기록 고정본(결과물 변화 있음 · 없음, 실제 결과를 먼저 보여 줌 · 안 보여 줌, 완료 뒤 수정 요구 있음 · 없음, 선택 창 · 글 질문).
- **Run**: 순수 집계 단계(splitSessions · classifyTurns · countShowReal · renderReport)를 돌린다.
- **Expected**: 세 숫자가 고정본에서 손으로 센 값과 같다.
- **Pass criterion**: 모든 칸 일치, 순수성 검사기 통과.

### T12. 두 래퍼 설치본

- **Setup**: 코어 릴리스 뒤 두 래퍼 동기화 · 릴리스.
- **Run**: 두 설치본의 매 턴 훅 출력과 설정 예시를 확인한다.
- **Expected**: Claude Code 는 선택 창 문구(보기 2개 이상), 코덱스는 글 질문 문구, 설정 키가 예시 파일에 있다.
- **Pass criterion**: 두 래퍼 모두 확인.

### T13. 회귀 — 지켜야 할 것

- **Setup**: 저장소.
- **Run**: 기존 테스트 전부를 맥 · 리눅스에서 돌린다.
- **Expected**: 매 턴 등록 · 인용 · 맨 위 한 줄, 선택 창 규칙과 답 뒤 재등록, 가드 동작이 그대로다.
- **Pass criterion**: 기존 테스트 전부 통과.
