# 마무리 보고 — 원칙 글도 맥락에 한 번만 — 판정을 지문 비교에서 맥락 표시로

<!-- 계획을 세울 때 아는 만큼(적어도 1번) 채우고, 일이 끝난 뒤 모든 칸을 채운다.
     고장을 고치는 계획이 아니면 2 ~ 5번은 묶음마다 "해당 없음 — 이유" 한 줄로 건너뛴다.

## 1. 문제

- 상황: 매 턴 규칙 글을 한 줄로 줄인 뒤(계획 rules-once-no-caps) 실제 세션으로 재니 턴 전체 글이 줄지 않았다.
- 기대: 규칙 글이 한 줄인 턴에는 원칙 글도 한 줄이다.
- 실제: 규칙 글이 한 줄인 턴 108개 중 105개에 원칙 글 전문(약 2.5 KB)이 실렸다(0.98–0.101, 다른 프로젝트의 긴 세션). 한 줄 턴의 글 크기 중간값이 4.8 KB 였다.
- 재현 조건: 같은 세션에서 훅을 한 번 돌린 뒤 규약 지문을 다른 값으로 바꾸고 다시 돌린다 — 둘째 턴에도 원칙 전문이 실린다.

## 2. 관찰

- 관찰한 사실과 측정값: 실제 세션 35개 · 사람 턴 1,530개. 원칙 글 덩어리 평균이 판별로 0.8 KB → 2.2 KB → 2.2 KB. 규칙 글 덩어리는 2.5 KB → 1.9 KB 로 줄었는데 턴 전체 평균은 6.3 KB → 6.1 KB.
- 정상일 때와 차이: 시험 환경(지문이 그대로인 세션)에서는 둘째 턴부터 원칙 글이 한 줄이다. 실제 긴 세션에서는 종료 검사가 규약을 다시 읽게 할 때마다 지문이 바뀐다.

## 3. 가설

- H1: 원칙 글의 판정이 규약 지문을 견주기 때문에, 지문이 자주 바뀌는 실제 세션에서 거의 매 턴 전문이 실린다.

## 4. 실험

- 방법과 같게 둔 것: 실제 세션 기록에서 규칙 글이 한 줄인 턴만 골라 원칙 글 덩어리의 크기를 셌다(0.98–0.101 판, 자동 알림 턴 포함). 코드에서 원칙 글과 규칙 글의 판정 근거를 나란히 읽었다.
- 결과와 가설별 판정: 한 줄 턴 108개 중 원칙 전문 105개 · 한 줄 3개. 코드: 규칙 글은 맥락 표시(.rules-seen)를 보고, 원칙 글은 지문을 본다(`scv_mp_principle_show "$pseen" "$NONCE"`). H1 맞음.

## 5. 원인

- 직접 원인과 일어난 길: `_principle_block` 이 표시 파일에 적힌 지문과 지금 지문을 견준다. 종료 검사가 답 모양 어김을 잡으면 규약을 다시 읽게 하고, 그때 지문이 새로 생겨 다음 턴에 전문이 다시 실린다.
- 근본 원인: 0.97.1 에서 규칙 글의 판정만 맥락 표시로 옮기고, 같은 턴에 실리는 원칙 글의 판정은 그대로 두었다. 대화 초기화도 원칙 표시는 지우지 않고 지문만 지웠다.

## 6. 해결과 검증

- 해결책과 고른 이유: 원칙 글의 판정을 규칙 글과 같은 맥락 표시로 옮김 — `_principle_block` 이 `.principle-seen` 이 있는지만 보고, 판정은 이미 있는 `scv_mp_rules_show` 를 그대로 씀. 직전 답에 원칙 경고가 남은 턴만 전문(새 순수 함수 `scv_mp_warn_has_principle`), 대화 초기화가 표시를 지움. 다른 경고까지 세면 경고 턴이 32% 라 줄어드는 폭이 작아져 원칙 경고만 봄. 기어 턴은 훅이 출력을 버리므로 실었다고 적지 않게 건너뜀(`--no-principle`). 끈 설정(SCV_RULES_ONCE=off)은 이전의 지문 비교 그대로.
- 고치기 전후 값: 시험 환경에서 지문이 바뀐 셋째 턴 4,492 B → 2,277 B. 실제 세션 기록 재계산(0.98–0.101 판 276턴, 대화 요약 경계에서만 다시 싣는다고 봄): 원칙 전문이 실린 턴 259 → 19, 턴 글 평균 6.2 KB → 4.3 KB(31% 줄어듦), 규칙 글이 한 줄인 108턴은 평균 4.8 KB → 2.7 KB(43% 줄어듦). 재계산은 "이렇게 했다면"의 값이고 세션 재개로 인한 다시 싣기는 세지 못함 — 릴리스 뒤 실제 세션으로 다시 재야 함.
