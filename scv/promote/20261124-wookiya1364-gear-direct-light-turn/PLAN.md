# 기어는 모델 없이 바로 돌고, 대화 턴은 가볍게 — 어긋나는 지시 정리

## Summary

기어의 목적은 같은 일을 같은 방법으로 하면서 토큰을 아끼는 것이다. 그런데 지금은 기어를 쓰게 해도 아끼지 못한다. 대시보드의 [사용함]과 [쓰기]는 기어를 돌리는 것이 아니라 채팅을 한 줄 보내는 것이라, 모델이 한 턴을 통째로 돈다. 사용자가 기어 줄을 붙여 보낸 요청 한 턴을 재 보니 3.6분 · 모델 호출 10번 · 쓴 글 13,750 토큰이었다(2026-11-24, 큰 세션 — 호출 한 번마다 약 83만 토큰을 캐시에서 다시 읽음). 아무 일 없는 턴(올리기 명령)도 호출 3번 · 1분을 넘겼다. 사용자는 "사용함을 누르거나 명령을 치면 곧바로 기어가 돌 줄 알았다"고 했다.

이 계획은 세 가지를 한다. (1) 창이 기어를 모델 없이 직접 돌린다 — 이 컴퓨터에만 영향을 주는 기어까지, 값은 창의 버튼과 입력 칸으로 정하고, 오래 도는 것은 뒤에서 돌리며 진행을 창에 보인다. (2) 대화로 기어를 시키는 턴을 가볍게 한다 — 도움말 부르기 · 요청 등록 · 긴 끝 보고를 요구하지 않아 모델 호출이 3번 안에 끝나게 한다. (3) 매 턴 글 · 규약 · 앱의 지시에서 서로 어긋나는 곳을 표로 뽑아 없애거나 다듬는다(사용자 요청: "현재 프롬프트에서 상충하는 거 있으면 이번에 같이 제거하거나 가다듬자").

## Goals / Non-Goals

- **Goals**
  - (어긋나는 지시) 매 턴 훅이 싣는 글, 도움말 · 작업 · 기어 규약, 규칙 문서, 그리고 Claude 앱이 세션에 싣는 지시를 맞대 보고 어긋나는 쌍을 표로 만든다: 항목 · 두 지시의 원문 줄 · 실제로 어떤 일이 생겼는지 · 고칠 방법. 사용자에게 보이고 확인받은 뒤 고친다. 이 세션에서 실제로 부딪힌 후보는 아래 "이미 본 후보"에 있다.
  - (어긋나는 지시) 표의 항목마다 셋 중 하나로 끝낸다: 한쪽을 없앰 · 글을 다듬어 하나로 만듦 · 어느 쪽이 이기는지 한 줄로 적음. 남는 항목 0.
  - (창이 직접 돌림) 창의 실행 버튼과 입력창 위 줄의 [사용함]이, 표시가 `pure` 또는 `effect` 인 기어를 모델을 거치지 않고 돌린다. 값이 하나도 필요 없는 기어는 누르는 즉시 돈다.
  - (값 정하기) 고를 값은 버튼으로: 톱니 사전의 인자 설명에서 보기를 만든다(`돌릴 곳: mac · linux` → 버튼 둘, 기본값이 미리 골라짐). 적어야 하는 값(숫자 · 글)과 넣을 자료(표준 입력)는 입력 칸에 적는다. 다 정하면 [이 값으로 실행].
  - (값 정하기) 창에서 못 정하는 경우만 대화로 넘긴다: 입력 칸이 없는 화면에서 적어야 하는 값이 있을 때, 그리고 사용자가 [Claude 에게 맡기기]를 눌렀을 때. 넘어간 턴은 가벼운 길로 돈다.
  - (오래 도는 기어) 30초 안에 끝나지 않는 실행은 뒤에서 계속 돌고, 창이 그 출력의 끝 줄과 걸린 시간을 보인다. 끝나면 결과(종료 코드 · 끝 줄들)가 기어 칸에 남고 알림이 간다. 사용자가 멈출 수 있다.
  - (결과를 대화로) 창에서 돌린 결과를 Claude 가 알아야 할 때만 [결과를 대화에 붙이기]로 입력창에 넣는다 — 자동으로 보내지 않는다.
  - (가벼운 대화 턴) 기어를 돌리라는 요청(`기어 액션을 친 것`, 또는 창이 붙인 기어 줄이 있는 글)인 턴은 매 턴 글이 짧은 것으로 바뀌고, 도움말 먼저 · 요청 등록 · 다시 쓴 요청 인용 · 세 줄 끝 보고를 요구하지 않는다. 기록은 한 줄만 남긴다. 목표: 값이 다 있으면 모델 호출 2번(실행 · 결과 한 줄), 물어야 하면 3번.
  - (재기) 같은 기어 요청을 새 세션에서 전 · 후로 잰다: 모델 호출 수 · 쓴 토큰 · 걸린 시간. 창 실행은 호출 0.
- **Non-Goals**
  - 밖으로 나가는 기어(`outward`)를 확인 없이 돌리는 일. 창에서의 확인 버튼은 이 계획에 넣되, 확인을 없애지는 않는다.
  - 판단 단계(`judge` — 기어 글의 `@`)가 든 기어를 창이 돌리는 일. 그 단계는 모델이 해야 하므로 대화로 간다.
  - 기어 요청이 아닌 보통 턴의 절차를 줄이는 일. 다만 지시 정리로 어긋남이 풀리면서 줄어드는 것은 한다.
  - 세션이 커서 느린 문제 자체(호출마다 다시 읽는 양). 새 세션을 여는 것이 답이고, 이 계획은 턴당 호출 수를 줄인다.
  - 낱말이 겹쳐 잘못 뜨는 맞추기를 뜻까지 보게 고치는 일.
  - 릴리스 — 사용자가 말할 때 한다. 릴리스 전에는 `release-ci` 기어를 저장소마다 맥 · 리눅스로 돌린다.

## Approach Overview

**먼저 지시를 맞대 본다.** 턴 하나에 실리는 글을 한자리에 모은다: 매 턴 훅의 출력(약 8.4KB), 도움말 스킬 글, 불려 온 규약, 턴 끝 훅의 알림 글, 그리고 앱이 싣는 지시(작업 목록 · 마무리 상자 · 세션 제안). 같은 일을 다르게 시키는 쌍을 찾아 표로 만든다. 이 세션에서 실제로 부딪힌 것부터 넣는다(아래 목록). 표를 사용자에게 보이고 항목마다 고칠 방법을 확인받는다.

**가벼운 길.** 매 턴 훅이 이번 요청이 기어 요청인지 순수 함수로 가린다(기어 액션 꼴이거나, 창이 붙인 기어 줄이 있음). 기어 요청이면 긴 안내 대신 세 줄짜리 안내를 싣는다: 값은 `gear.sh ask` 로 읽고 빠진 것만 선택 도구로, `gear.sh run` 으로 돌리고, 결과를 두세 줄로. 가드의 도움말 먼저 규칙과 등록 규칙, 턴 끝의 인용 · 끝 보고 검사는 이 턴을 '액션 턴'으로 보고 요구하지 않는다(지금도 사람이 친 SCV 액션은 도움말을 부른 것으로 친다 — 그 범위를 등록 · 끝 보고까지 넓힌다). 기록은 훅이 저널 한 줄로 남긴다.

**창이 직접 돌림.** 0.3.x 의 [바로 실행](표시 `pure`, 30초)을 넓힌다. 실행 조건을 `pure | effect` 로, 값 정하기를 창 안에서: 본체의 `gear.sh ask <이름>` 출력(인자 이름 · 지금 값 · 열림 여부 · 설명 · 받는 값)을 읽어 인자마다 버튼 묶음이나 입력 칸을 그린다. 설명에서 보기를 뽑는 일은 순수 함수가 한다(쌍점 뒤를 ` · ` 로 가름, 보기가 둘 이상이고 기본값이 그중 하나일 때만 버튼). 실행은 인자를 낱말 하나씩 넘긴다. 30초가 넘는 실행은 터미널 탭이나 뒤 실행으로 옮기고, 창이 이미 가진 '뒤에서 도는 일' 표시(출력 파일의 끝 줄 읽기)를 쓴다. `outward` 기어는 창이 확인 글(무엇이 밖으로 나가는지)을 보이고 [실행] · [취소] 버튼을 누른 뒤에만 본체의 확인 절차를 거쳐 돌린다.

**[사용함]의 뜻을 바꾼다.** 지금은 "글을 그 기어의 한 줄과 함께 보냄"이다. 새 뜻: 창이 돌릴 수 있는 기어면 창이 돌리고(값이 필요하면 값 칸을 먼저 띄움), 못 돌리는 기어(`judge`)만 지금처럼 대화로 보낸다. 누르지 않고 그대로 보낸 글은 지금처럼 한 줄이 붙어 가고, 그 턴은 가벼운 길로 돈다.

### 이미 본 후보 — 어긋나는 지시 (이 세션에서 실제로 부딪힘, 2026-11-24)

1. 앱: 마무리 상자에 질문과 버튼을 둔다 ↔ SCV: 요약 상자는 요약만, 결정은 선택 도구. (0.102.0 의 가드 규칙 S 로 막음 — 글 쪽도 한 문장으로 맞출 것)
2. 매 턴 글: "글로 묻는 것은 막힌다/거절된다" ↔ 실제: 턴 끝 검사는 알림만 남긴다(0.83.0+). 글이 사실과 다름.
3. 매 턴 글: 진행 중인 계획의 단계를 알려라(`[SCV 단계]`) ↔ 그 계획을 다루지 않는 턴에도 실리고, 보관한 계획에는 단계 도구가 받지 않는데 턴 끝 검사는 요구함(이 세션에서 한 번 막힘).
4. 매 턴 글: 첫 행동은 도움말 액션 ↔ 스킬 글: 명령 블록이 이미 있으면 그 스킬을 바로 따르라(사람이 친 `/scv:update` 턴). 지금은 그 액션이 도움말을 대신하지만 글은 여전히 도움말을 부르라고 함.
5. 끝 보고: 세 묶음(확인한 것 · 확인 못 한 것 · 제가 대신 정한 것)을 매번 ↔ 답 모양: 휴대폰 한 화면, 짧게. 짧은 턴에서 보고가 본문보다 길어짐.
6. 다시 쓴 요청 인용을 답 맨 위에 전문으로 ↔ 짧은 답은 짧게. 한 줄 답에도 긴 인용이 붙음.
7. 앱: 매 턴 마무리 도구(recap) ↔ SCV: 끝 보고. 같은 내용을 두 번 씀.
8. 계획 기록 명령은 "따로, 글자 그대로의 절대 경로로" 불러야 영수증이 남음 ↔ 규약의 예시는 변수와 이어 붙인 명령. 그대로 따르면 턴 끝에서 막힘(이 세션에서 한 번).
9. 턴 끝의 확인 범위 검사: "이번 턴에 돌린 것만 통과라고 써라" ↔ 뒤에서 돌린 실행 · 앞 턴에 시작한 실행의 결과를 읽은 경우. 읽은 결과를 적으면 알림이 뜸(이 세션에서 여러 번).
10. 사용자 전역 지시: 매 단계에 현재 상태 · 핵심 불확실성 · 다음 행동 · 검증 기준 ↔ SCV 답 모양: 결과 먼저, 짧게.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
// 턴이 시작될 때 (본체 매 턴 훅)
flow(
  readPrompt,          // 훅 입력 → 요청 글                                (부수효과: 읽기)
  scv_gear_turn,       // 요청 글 → 기어 이름 | 없음 (액션 꼴 · 창이 붙인 줄)
  scv_turn_text,       // (기어 이름, 보통 안내 글) → 실을 글(짧은 글 | 보통 글)
  emitTurnText,        // 글 → 훅 출력 · 이번 턴이 액션 턴이라는 표시       (부수효과: 쓰기)
)

// 창에서 기어를 돌릴 때 (대시보드)
flow(
  readGearAsk,         // 본체의 값 안내 출력 → 글                          (부수효과: 실행 · 읽기)
  parseAsk,            // 글 → 정할 값들(인자 · 받는 값)
  argChoices,          // 인자 설명 → 버튼 보기들 | 입력 칸
  runPlan,             // (기어 표시, 정할 값들, 고른 값, 화면에 입력 칸 있음) → 바로 실행 | 값 칸 | 확인 | 대화로
  gearRunArgv,         // (본체 폴더, 이름, 고른 값) → 실행 인자 배열
  startRun,            // 인자 배열 · 표준 입력 → 실행 중인 일                (부수효과: 실행)
  runView,             // (출력 끝 줄, 걸린 시간, 종료 코드) → 기어 칸에 보일 줄
  drawRun,             // 줄 → 화면 · 알림                                  (부수효과: 그리기)
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `readPrompt` | (기존) 매 턴 훅이 받은 요청 글을 꺼냄 | 훅 입력 → 글 | 부수효과 (입구) |
| 2 | `scv_gear_turn` | 이번 요청이 기어를 돌리라는 것인지 가림 — 기어 액션 꼴이거나 창이 붙인 줄 | 글 → 기어 이름 · 없음 | 순수 |
| 3 | `scv_turn_text` | 실을 안내 글을 고름 — 기어 턴이면 세 줄짜리, 아니면 보통 글 | (이름, 보통 글) → 글 | 순수 |
| 4 | `emitTurnText` | 글을 내고, 이번 턴이 액션 턴임을 턴 상태에 적음 | 글 → (없음) | 부수효과 (출구) |
| 5 | `readGearAsk` | 본체의 값 안내 명령을 돌려 출력을 받음 | 기어 이름 → 글 | 부수효과 (입구) |
| 6 | `parseAsk` | 값 안내 글을 정할 값들로 나눔 — 인자(이름 · 지금 값 · 열림 · 설명)와 받는 값 | 글 → 값들 | 순수 |
| 7 | `argChoices` | 인자 설명에서 버튼 보기를 뽑음 — 보기가 둘 이상이고 기본값이 그중 하나일 때만 | 설명 · 기본값 → 보기들 · 입력 칸 | 순수 |
| 8 | `runPlan` | 누른 뒤 무엇을 할지 정함 — 바로 실행 · 값 칸 띄움 · 확인 받음 · 대화로 넘김 | (표시, 값들, 고른 값, 입력 칸 있음) → 할 일 | 순수 |

## Guardrails

- `outward` 표시가 든 기어는 창에서도 확인 글과 [실행] · [취소]를 거친다. 확인을 건너뛰는 길을 만들지 않는다.
- `judge`(판단 단계)가 든 기어는 창이 돌리지 않는다.
- 창이 돌릴 때 사용자가 적은 글은 표준 입력과 `이름=값` 낱말의 값으로만 간다. 셸 글로 이어 붙이지 않고, 인자 이름은 본체의 값 안내에 나온 것만 쓴다.
- 가벼운 길은 기어 요청으로 가려진 턴에만 쓴다. 그 턴에서 모델이 파일을 고치려 하면 가드는 지금처럼 본다(가벼운 길이 쓰기 검사를 풀지 않는다).
- 지시를 없애거나 다듬을 때는 표의 항목과 사용자 확인이 근거다. 표에 없는 지시는 건드리지 않는다.
- 매 턴 글은 호스트 이름 · 도구 이름을 쓰지 않고(호스트 중립 시험), 글 한도 시험 안에 둔다. 글을 줄이는 쪽이 원칙이다.
- 뒤에서 도는 실행은 사용자가 멈출 수 있고, 세션이 끝나면 남지 않게 한다.
- mac · linux 둘 다 돈다(bash 3.2, BSD 도구). 공개 저장소에 다른 프로젝트의 이름 · 세션 내용을 넣지 않는다.

## Exit criteria

- TESTS.md 의 시나리오가 모두 통과한다.
- 어긋나는 지시 표의 모든 항목이 '없앰 · 다듬음 · 이기는 쪽을 적음' 중 하나로 끝났고, 사용자가 표를 봤다.
- 새 세션에서 잰 값: 값이 필요 없는 기어를 창에서 돌리면 모델 호출 0. 같은 기어를 대화로 시키면 전보다 호출 수가 줄어 3 이하.
- 실제 창에서 값 고르기와 실행을 사용자가 봤다 — 못 본 것은 못 본 것으로 적는다.
- 본체의 순수 함수 사전 · 순도 · 호스트 중립 검사 통과, 대시보드 형 검사 오류 수가 늘지 않음(지금 9).

## Suggested path

1. 지시 글을 맞대 보고 어긋나는 곳을 표로 만들어 보이기 — 매 턴 글 · 규약 · 앱의 지시를 모아 쌍을 찾고, 사용자에게 표를 보여 고칠 방법을 확인받음

3. 끝나지 않는 예시를 끊을 때의 경합 고치기 — 지킴이가 끊었다는 표를 먼저 남기고 그 표로 '시간 안에 끝나지 않음'을 판정함
4. 기어 턴의 가벼운 길 만들기 — `scv_gear_turn`, `scv_turn_text`, `emitTurnText`

6. 창에서 값 정하기 — `readGearAsk`, `parseAsk`, `argChoices`, `runPlan`
7. 창이 직접 돌리기 넓히기와 오래 도는 실행 — `gearRunArgv`, `startRun`, `runView`, `drawRun`
8. 사용함과 기어 칸의 실행이 창 직접 실행을 먼저 쓰게 하기 — 창이 못 돌리는 기어만 대화로 넘기고, 넘어간 턴은 가벼운 길로
9. 시험을 돌리고 실제 창 모습을 보이기 — 값 고르기 · 실행 중 · 결과의 글자 줄을 뽑아 사용자에게 보여 줌

11. 그림 도구가 있는 세션에서는 표와 화살표 줄이 그림을 갈음하지 못하게 하기 — 매 턴 글의 그림 구절을 다듬고, 그 도구를 쓴 적이 있는 세션에서 흐름을 화살표 줄로만 보인 답에 알림 한 줄

## Risks / Open Questions

- 앱이 싣는 지시는 SCV 가 고칠 수 없다. 어긋날 때 SCV 쪽 글을 맞추거나 "이쪽이 이긴다"를 적는 것까지가 할 수 있는 일이다. 앱의 지시 원문은 저장소에 없으므로, 표에는 세션에서 본 문장을 옮겨 적는다.
- 기어 요청인지 가리는 일이 틀리면 보통 요청이 가벼운 길로 가서 검사를 빠져나간다. 가리는 기준은 좁게 잡는다(기어 액션 꼴, 창이 붙인 정해진 꼴의 줄).
- 가벼운 길에서 기록이 한 줄로 줄면 나중에 "그 기어를 왜 돌렸나"를 찾기 어렵다. 저널 한 줄에 기어 이름 · 인자 · 종료 코드를 담는다.
- 창이 30초 넘는 실행을 뒤에서 돌리는 길이 모드에 있는지(터미널 탭을 여는 도구는 Claude 쪽 도구다) 구현 때 확인한다. 없으면 실행기를 `nohup` 꼴로 띄우고 출력 파일을 읽는다.
- 설명에서 보기를 뽑는 규칙(` · ` 로 가름)이 맞지 않는 설명이 있을 수 있다. 맞지 않으면 입력 칸으로 물러난다. 톱니 사전에 보기를 따로 적는 꼴을 더할지는 구현 때 정한다.
- 이 세션에서 잰 "10번 · 3.6분"은 호출마다 83만 토큰을 다시 읽는 큰 세션의 값이다. 전 · 후 비교는 새 세션에서 같은 조건으로 다시 잰다.
- 0.102.0(가드 규칙 S)과 대시보드 0.3.2 가 먼저 나가 있어야 한다. 이 계획은 그 위에서 시작한다.
