# 턴 끝 확인이 멈추지 않게 — 쓴 파일 목록 중복 · 느린 비교 · 끝나지 않는 턴

## Summary

긴 세션 하나에서 턴 끝 검사(종료 훅)가 262번 중 259번 60초 시간 초과로 취소돼, 다시 쓴 요청 인용 검사가 한 번도 돌지 않았다(실제 요청의 약 13%가 인용 없이 지나감). 복사본으로 재 보니 턴 끝 확인의 '이 세션이 쓴 파일만 남기기' 비교가 멈춘 곳이었다 — 쓴 파일 목록이 440,015줄(서로 다른 파일 4,555개)로 불어 있었고, 비교가 줄마다 목록 전체를 훑어 파일 100개에 18.2초가 걸렸다. 턴 끝이 통과를 못 내니 끝 표시가 남지 않고, 다음 요청이 모두 같은 턴의 도중으로 처리돼 목록과 시작 기준이 계속 쌓이는 악순환이었다. 이 계획은 그 확인이 어떤 세션에서도 제한 시간 안에 끝나게 한다.

## Goals / Non-Goals

- **Goals**
  - 쓴 파일 목록에 같은 파일이 두 번 쌓이지 않는다.
  - '내가 쓴 파일만' 비교와 걸러내기(설정 파일 빼기)가 목록을 한 번만 훑는다.
  - 턴 끝 확인이 느려져도 제한 시간 안에 판정을 내고 끝 표시를 남겨, 끝나지 않는 턴이 생기지 않는다.
  - 쓰기 전 확인(도구 앞 훅, 5초 한도)이 같은 세션에서 1,648번 시간 초과된 이유를 재서 고친다.
- **Non-Goals**
  - 인용 검사 · 등록 검사 규칙 자체를 바꾸지 않는다.
  - 훅의 제한 시간(60초 · 5초)을 늘리지 않는다.
  - 다른 프로젝트의 쌓인 상태를 대신 지우지 않는다(새 버전이 스스로 풀리게 한다).

## Approach Overview

턴 끝 확인(turn-check end)은 저장소마다 시작 사진과 지금 사진의 차이, 시작 뒤 커밋 차이를 모은 뒤 걸러내기 · 절대 경로 만들기 · '내 파일만' 남기기를 거친다. 지금 '내 파일만'과 걸러내기는 bash 의 줄 반복 안에서 긴 글을 통째로 훑어(줄 수 × 목록 크기) 큰 세션에서 몇 분이 걸린다. 이 둘을 정렬 · 한 번 훑기(awk 집합) 방식으로 바꾸고, 목록에 쓸 때 이미 있는 파일은 다시 쓰지 않는다. 그래도 제한을 넘을 수 있는 경우(아주 큰 커밋 차이)를 위해, 턴 끝 확인은 스스로 시간 예산을 두고 넘으면 통과와 '확인 생략' 기록을 남겨 끝 표시를 꼭 쓴다. 쓰기 전 확인은 먼저 복사본으로 어느 단계가 5초를 넘는지 잰 뒤 같은 방식으로 고친다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readState,        // 상태 폴더 → 시작 사진 · 시작 기준 · 쓴 파일 목록
  changedPaths,     // 시작/끝 사진 · 커밋 차이 → 바뀐 경로 줄들
  filterExempt,     // 바뀐 경로 · 뺄 경로 규칙 → 남은 경로
  mineOnly,         // 절대 경로 · 쓴 파일 목록 → 이 세션이 쓴 경로만
  judge,            // 개수들 → pass | block | pass-unrecorded
  writeEnd,         // 판정 → 끝 표시 · 기록 (부수효과)
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `readState` | 상태 폴더의 사진 · 기준 · 목록을 읽음 | 폴더 → 글 | 부수효과 (입구) |
| 2 | `changedPaths` | 두 사진의 차이와 커밋 차이를 합침 | 사진 2개 · 차이 → 경로 줄들 | 순수 (scv_tc_diff) |
| 3 | `filterExempt` | 설정 파일 · 기록 폴더 경로를 한 번 훑어 뺌 | 경로 줄들 · 규칙 → 경로 줄들 | 순수 (scv_tc_filter) |
| 4 | `mineOnly` | 쓴 파일 목록을 집합으로 만들어 한 번 훑어 남김 | 경로 줄들 · 목록 → 경로 줄들 | 순수 (scv_tc_mine_only) |
| 5 | `judge` | 개수로 판정 | 숫자들 → 판정 | 순수 (scv_tc_judge, 그대로) |
| 6 | `writeEnd` | 끝 표시 · 기록 쓰기, 예산 초과면 통과+생략 기록 | 판정 → 파일 | 부수효과 (출구) |

- 부수효과 위치: 1 · 6 과 git 호출(사진 · 커밋 차이)만. 2–5 는 글 → 글.
- 재사용: scv_tc_diff · scv_tc_judge 는 그대로. 쓰기 쪽 중복 막기는 touch/settle 의 목록 쓰기 자리 두 곳.

## Guardrails

- 같은 입력에서 판정(막음 · 통과 · 기록 없음 통과)은 지금과 같아야 한다 — 기존 턴 확인 시험이 그대로 통과.
- 다른 세션이 고친 파일을 '내 파일'로 세지 않는다.
- 훅 제한 시간 설정(60초 · 5초)은 바꾸지 않는다.
- 일하는 중 온 말(종료 훅이 아직 안 돈 턴)은 지금처럼 같은 턴에 이어 붙는다 — 턴을 시간 · 크기로 자르지 않는다.
- 막힌 뒤 이어지는 턴은 그대로 같은 턴이다(막을 때 '멈춤 시작' 표시를 지움).
- 맥(BSD) · 리눅스(GNU) 둘 다에서 같은 결과(awk · sort 는 LC_ALL=C).
- 다른 프로젝트 이름 · 로컬 경로를 공개 저장소(시험 · 문서 · 커밋)에 넣지 않는다 — 시험은 합성 자료로.

## Exit criteria

- TESTS.md 시나리오 모두 통과.
- 측정 복사본(긴 세션 상태)으로 턴 끝 확인: 지금 180초 넘음 → 5초 안.
- 쓰기 전 확인(touch)이 같은 복사본에서 1초 안.
- 순수성 검사 · 사전 검사 통과, 맥 · 리눅스 둘 다.

## Suggested path

1. 복사본으로 쓰기 전 확인(touch · settle)이 5초를 넘는 단계를 재서 찾는다 — 느린 단계를 재서 이름 붙임
2. '내 파일만' 비교를 집합 한 번 훑기로 바꾼다 — `mineOnly`
3. 걸러내기를 한 번 훑기로 바꾼다 — `filterExempt`
4. 쓴 파일 목록에 이미 있는 파일은 다시 쓰지 않는다(옛 목록은 읽을 때 중복 제거) — `readState`
5. 턴 끝 확인에 시간 예산을 두고, 넘으면 통과 + '확인 생략' 기록 + 끝 표시 — `writeEnd`
5a. 종료 훅이 맨 처음에 '멈춤 시작' 표시를 남기고(턴 끝 확인이 막을 때만 지움), 다음 시작이 그 표시를 보면 새 턴으로 시작한다 — 종료 훅이 돌다 시간 초과로 죽어도 다음 턴이 새로 열려 악순환이 끊김. 시간 · 크기 상한은 두지 않는다(일하는 중 온 말 이어 붙이기를 깨므로, 2026-11-19 사용자 결정)
6. 1단계에서 찾은 쓰기 전 확인의 느린 단계를 고친다 — `changedPaths`
7. 합성 큰 상태 시험 · 기존 시험 · 복사본 측정을 맥 · 리눅스에서 돌린다 — 고친 뒤 전후 시간을 재서 확인

## Risks / Open Questions

- 처음 시간 초과를 부른 계기(어떤 턴의 큰 커밋 차이였는지)는 아직 모름 — 5단계 예산이 그 경우를 막는다.
- 시간 예산을 넘겨 '확인 생략'으로 통과한 턴은 계획 기록 검사를 건너뛴다 — 기록 줄로 남겨 보이게 한다.
- 쓰기 전 확인이 느린 이유는 1단계 측정 전까지 추정.
