# 마무리 보고 — 턴 끝 확인이 멈추지 않게 — 쓴 파일 목록 중복 · 느린 비교 · 끝나지 않는 턴

## 1. 문제

- 상황: 한 긴 세션(11-17~11-19, 사람 요청 약 126건)에서 답 맨 위 '다시 쓴 요청' 인용이 자주 빠졌다.
- 기대: 인용 없이 끝나는 답은 턴 끝 검사가 막아 다시 쓰게 한다.
- 실제: 인용이 17건(약 13%) 빠진 채 지나갔다. 등록은 4건만 빠졌다.
- 재현 조건: 그 세션 상태 폴더와 대화 기록의 복사본으로 종료 훅을 돌리면 180초 넘게 걸린다.

## 2. 관찰

- 관찰한 사실과 측정값: 종료 훅 262번 중 259번이 60초 시간 초과로 취소, 도구 앞 훅 1,648번이 5초 시간 초과. 쓴 파일 목록 440,015줄(서로 다른 파일 4,555개), 시작 기준 뒤 커밋 차이 1,685개.
- 정상일 때와 차이: 같은 프로젝트 직전 세션은 막음 11번 · 취소 1번, 이 저장소 세션은 취소 0번.

## 3. 가설

- H1: 대화 기록 파일이 커서(126 MB) 종료 훅의 기록 읽기가 느리다.
- H2: 턴 끝 확인(turn-check end)의 경로 비교가 쌓인 목록 때문에 느리다.

## 4. 실험

- 방법과 같게 둔 것: 같은 SCV 0.95.0, 상태 폴더 · 기록 복사본, 저장소 잠금 없이(GIT_OPTIONAL_LOCKS=0). 종료 훅을 줄마다 시각을 찍어 돌림.
- 결과와 가설별 판정: H1 기각 — 멈춘 곳은 기록 읽기 전 턴 끝 확인. H2 채택 — scv_tc_mine_only 단독으로 파일 100개 18.2초, 목록 중복만 지워도 0.33초.

## 5. 원인

- 직접 원인과 일어난 길: '내 파일만' 비교가 바뀐 경로마다 44만 줄 목록 전체를 훑음(1,685 × 약 40 MB) → 턴 끝 확인 수 분 → 종료 훅 60초 초과로 취소 → 인용 검사 안 돎.
- 근본 원인: 목록이 쓸 때마다 중복으로 쌓이고, 끝 표시는 턴 끝이 통과할 때만 남는다. 한 번 시간 초과가 나면 끝 표시가 없어 다음 요청이 모두 같은 턴의 도중으로 처리되고, 목록과 시작 기준이 계속 커지는 악순환.

## 6. 해결과 검증

- 해결책과 고른 이유: 턴 끝 확인의 비교 여섯 함수(사진 비교 · 걸러내기 · 경로 붙이기 · 내 파일만 · 계획 줄 고르기 · 늘어난 줄)를 awk 집합 한 번 훑기로 바꿈 — 판정 규칙은 그대로 두고 속도만 바꾸는 가장 작은 수정. 쓴 파일 목록은 새 경로만 덧붙이고 읽을 때 중복 제거. 끊김 대비로 30초 시간 예산(넘으면 통과 + '확인 생략' 기록 + 끝 표시)과 '멈춤 시작' 표시(종료 훅 맨 처음, 막을 때만 지움) — 시간 · 크기로 턴을 자르는 상한은 일하는 중 온 말 이어 붙이기를 깨므로 버림(사용자 결정).
- 고치기 전후 값: 긴 세션 상태 복사본의 턴 끝 확인 180초 넘음(끊김) → 2.4–4.5초(세 번 잼, 판정 정상 출력). 사진 비교 2,000개 9.2초 → 0.02초, 4,000개 37.5초 → 0.04초. 내 파일 비교 파일 100개 18.2초 → 목록 50만 줄 · 경로 2,000개 0.3초. 계획 줄 두 함수 합 38초 → 1초 아래. 쓰기 전 정산(바뀐 2,000개) 0.27초.
- 부작용과 회귀 시험: 새 시험 9개(T1 · T1b · T2 · T3 · T4 · T4b · T5 · T5a · T7) 통과, 기존 턴 확인 · 오거절 · 마무리 보고 · 재는 검사 b/c · 느린 순수 함수 · 템플릿 지문 시험 통과(맥). 함수 여섯 개가 awk · sort 를 불러 @pure → @deterministic 으로 바뀜(사전 다시 만듦, 예시 그대로 맞음). 재는 검사가 처음엔 작은 입력에서 6–9배 느려짐 · 다른 프로그램 호출 증가를 잡음 → 8,000바이트 아래 입력은 옛 셸 방식으로 돌게 나눠 6개 모두 통과(0.62–1.00배). 리눅스(GNU) 시험 3개 + 순수성 통과.

## 7. 배운 것

- 다음에 같은 문제를 만나면 진단하는 법: 대화 기록에서 훅 취소(hook_cancelled · timedOut) 수를 먼저 센다. 그다음 상태 폴더를 복사해 훅을 PS4 에 시각을 넣은 bash -x 로 돌리고, 함수별 걸린 시간 합계로 느린 곳을 좁힌다(줄 사이 간격만 보면 반복 안에 흩어진 시간을 놓친다).
- 다른 곳에도 쓸 수 있는 것: bash 에서 '줄마다 긴 글 전체에 *패턴* 비교'는 길이의 제곱으로 느려진다 — 줄 수가 커질 수 있는 목록은 처음부터 awk 집합이나 sort/comm 으로. 상태를 '끝났을 때만' 지우는 설계는 끝 판정이 한 번 죽으면 영영 안 지워진다 — 시작 표시를 먼저 남겨 다음 시작이 알아보게.
