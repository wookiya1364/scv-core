# 단계 증거를 눈에 보이게 · 뒤에서 도는 일은 뒤에서

## Summary

사용자는 코드를 보지 않는다. 처음(요구사항 정리)과 끝(잘 도는 증거)만 확인해 에이전트 루프를 빠르게 하려 한다(2026-11-25). 그런데 지금은 단계가 끝날 때의 증거로 소스코드 파일을 열게 하고, 끝난 단계에서는 진행 중에 보이던 순수 함수 목록이 사라지며, 뒤에서 도는 일과 앞에서 하는 일이 창에서 구분되지 않는다. 또 모델이 오래 도는 일을 앞에서 기다리는 동안 사용자가 새 요청을 넣으면 하던 일이 끊겨 계획이 끝까지 가지 못한다.

이 계획은 (1) 증거를 눈에 보이는 것(이미지 · 영상 · 차트)으로만 받고, (2) 보여 줄 화면이 없는 단계는 순수 함수 목록을 끝난 뒤에도 남기며, (3) 뒤에서 도는 단계를 "진행 중(백그라운드)"로 표시하고, (4) 오래 도는 일을 뒤에서 돌리게 규약에 넣고 앞에서 오래 기다리는 호출을 거절한다.

## Goals / Non-Goals

- **Goals**
  - 단계 끝 증거에서 소스코드 · 글 파일을 받지 않는다 — 이미지 · 영상 · html · pdf 만.
  - 줄에 순수 함수가 적힌 단계는 그 목록(새로 만든 것 · 다시 쓴 것)이 증거다 — 끝난 뒤에도 창에 남는다.
  - 숫자 결과(시험 통과 수 · 전후 값)를 토큰 없이 그림으로 만드는 명령을 둔다(막대 그림 SVG).
  - 뒤에서 도는 단계는 "진행 중(백그라운드)"로 표시한다.
  - 일 규약: 오래 도는 일은 끝남 알림이 오게 뒤에서 돌리고, 앞에서 기다리지 않는다. 앞에서 오래 기다리는 호출은 가드가 거절한다.
- **Non-Goals**
  - 영상 녹화 기능 새로 만들기(이미 있는 증거 첨부 길을 쓴다).
  - 릴리스 — 다음 릴리스에 묶는다.
  - 래퍼의 훅 연결(가드가 대기 도구를 보게 하는 맞춤) — 본체 릴리스 때 함께.

## Approach Overview

- 대시보드(코드는 scv-mods): 단계 보고 도구가 증거 파일의 종류를 가려, 눈에 보이는 것이 아니면 거절한다. 줄에 함수 이름이 있는 단계는 파일 없이 통과한다. 끝난 단계에도 함수 목록을 그린다. `doing` 의 `background` 인자(또는 `log` · `url`)로 "진행 중(백그라운드)"를 표시한다.
- 본체 규약(`core/protocols/work.md` 의 단계 보고 절): 증거의 뜻을 바꾸고(눈에 보이는 것, 소스코드 아님), 뒤에서 일하기를 적는다.
- 그림 만들기: `core/scripts/evidence.sh card` 가 "이름=값" 줄들로 막대 그림 SVG 를 쓴다 — 판정과 그리기는 순수 함수, 파일 쓰기만 스크립트.
- 가드: 도구 입력에 긴 대기 값이 있거나(대기 60초 이상), 뒤로 보내지 않은 셸 명령이 잠자기로 기다리면(30초 이상) 거절하고 "뒤에서 돌리고 끝남 알림을 받아라"로 안내한다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  scv_evidence_rows,      // "이름=값" 줄들 → 이름 · 값 · 막대 길이
  scv_evidence_svg,       // 제목 + 줄들 → SVG 글
  scv_guard_wait_kind,    // 도구 입력의 대기 값 · 셸 명령 → none | wait | sleep
  scv_guard_wait_reason,  // 종류 → 거절 글
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `scv_evidence_rows` | "이름=값" 줄들을 읽어 가장 큰 값에 맞춘 막대 길이를 붙인다 | 줄들 → 이름 · 값 · 길이 줄들 | 순수 |
| 2 | `scv_evidence_svg` | 제목과 줄들로 막대 그림 SVG 글을 만든다 | 제목 + 줄들 → SVG 글 | 순수 |
| 3 | `evidence.sh card` | SVG 글을 프로젝트 안 파일로 쓴다 | 제목 · 줄들 · 경로 → 파일 | 부수효과 (출구) |
| 4 | `scv_guard_wait_kind` | 도구 입력이 앞에서 오래 기다리는 호출인지 가른다 | 대기 값 · 뒤로 보냄 여부 · 셸 명령 → none · wait · sleep | 순수 |
| 5 | `scv_guard_wait_reason` | 거절 글을 만든다 | 종류 → 글 | 순수 |
| 6 | `guard.sh` | 도구를 부르기 전에 4 · 5 를 돌려 거절하거나 통과시킨다 | 훅 입력 → 거절 또는 통과 | 부수효과 (입구/출구) |

- 부수효과 위치: 3(파일 쓰기) · 6(훅 입력 읽기 · 거절 출력).
- 재사용: 가드의 기존 규칙 틀(`core/template/hooks/guard.sh`), 설정 읽기, 대시보드의 증거 검사(`evidenceKind`).

## Guardrails

- 뒤에서 돌린 일의 결과와 실패는 답에 그대로 적는다.
- 가드의 거절은 분명한 경우만: 긴 대기 값, 잠자기로 기다리는 셸 명령. 짧은 대기(60초 미만)와 보통 명령은 건드리지 않는다.
- 사용자에게 묻는 도구, 확인이 필요한 행동은 뒤로 보내지 않는다(묻기 규칙 그대로).
- 본체 글에 특정 호스트의 도구 이름을 쓰지 않는다 — 대기 값은 입력의 칸 이름으로 본다.
- 매 턴 글은 늘리지 않는다(규약 글과 가드만).
- 맥(기본 셸 3.2 포함) · 리눅스 둘 다. 가드 템플릿을 바꾸므로 템플릿 지문을 다시 만든다.

## Exit criteria

- TESTS.md 의 모든 시나리오 통과.
- 실제 대시보드 화면 사진 세 장: 그림 증거가 붙은 끝난 단계, 함수 목록이 남은 끝난 단계, "진행 중(백그라운드)" 표시.
- 깃허브 검사 통과 뒤 develop 에 병합(릴리스 없음).

## Suggested path

1. 대시보드가 볼 수 있는 증거만 받고, 누른 단계의 상세에 함수 목록을 남기고, 뒤에서 도는 단계를 따로 표시하게 고친다 — 창 화면과 모드 시험으로 확인한다
2. 이름과 값의 줄로 막대 그림 파일을 만드는 명령을 더한다 — `scv_evidence_rows`, `scv_evidence_svg`, `evidence.sh card`
3. 앞에서 오래 기다리는 호출을 도구를 부르기 전에 거절한다 — `scv_guard_wait_kind`, `scv_guard_wait_reason`, `guard.sh`
4. 일 규약의 단계 보고 절을 고친다 — 증거는 눈에 보이는 것, 오래 도는 일은 뒤에서
5. 대시보드에서 컨텍스트를 요약하는 기준을 막대로 조절하게 한다 — 5% 씩 옮기고 다음 세션에도 남는다
6. 대시보드 맨 위에 일하는 폴더와 브랜치를 보이고, 브랜치를 누르면 골라서 바꾸게 한다 — 턴이 도는 중에는 바꾸지 않는다
7. 실제 창에서 세 장면을 사진으로 남겨 사용자에게 보인다 — 실제로 도는 것을 보여 준다
8. 순수 함수 사전 · 관련 시험을 돌리고 깃허브 검사를 받는다 — 두 환경에서 같은 결과인지 본다

## Risks / Open Questions

- 가드가 대기 도구를 보려면 래퍼의 훅 연결에 그 도구가 들어가야 한다 — 본체 릴리스 때 래퍼 맞춤에서 함께 넣는다. 그 전에는 셸 명령의 잠자기만 걸린다.
- 보여 줄 화면도 함수도 없는 단계(예: 문서만 고치는 단계)는 그림을 만들어야 한다 — 그림 만들기 명령으로 숫자 한두 개라도 그리게 한다. 억지 그림이 늘지 않는지 실제 계획 몇 개로 본다.
- 뒤에서 돌리기를 지키는지는 릴리스 뒤 실제 세션 기록으로 본다(앞에서 기다린 호출 수).
