# 비우기로 줄인다 — 대화가 길어지면 요약 대신 비우고, 기록의 끝부분으로 새로 시작한다

## Summary

지금 대시보드는 턴이 끝났을 때 컨텍스트가 기준을 넘으면 요약 명령을 문으로 써서 대화를 SCV 기록으로 바꿔 끼운다. 사용자는 이것을 비우기(clear)로 바꾸기로 정했다(2026-11-25) — 공식 문서가 여러 컨텍스트에 걸친 긴 일에 "상태를 파일에 두고 새 컨텍스트로 시작"을 권하고, 요약이 느리고 좋지 않다는 의견이 있어서다.

이 계획은 턴 끝에 비우기를 돌리고, 새 대화가 SCV 기록의 끝부분 · 진행 중인 계획 · 뒤에서 도는 일 목록으로 시작하게 한다. 비우기가 되지 않으면 지금의 길로 넘어간다.

## Goals / Non-Goals

- **Goals**
  - 턴이 끝났을 때 컨텍스트가 기준을 넘으면 대시보드가 비우기 명령을 돌린다.
  - 비운 뒤 싣는 글은 기록 전체가 아니라 끝부분(12,000자, 턴 머리에서 시작)과 전체 기록의 자리다.
  - 비운 뒤 첫 글에 뒤에서 도는 일 목록(무엇을 돌렸는지)이 실린다 — 알림이 왔을 때 새 대화가 그 일을 안다.
  - 창의 글자가 "요약"이 아니라 "비우기"로 보이고, 한 뒤의 결과 한 줄이 보인다.
  - 비우기가 거절되면 지금의 길(기록으로 바꿔 끼우기)로 넘어가고, 창이 그렇게 됐다고 알린다.
- **Non-Goals**
  - 엔진이 스스로 하는 요약(턴 도중 · 미리 써 둔 요약)을 바꾸는 일.
  - 요약 · 재개 뒤에 싣는 글을 줄이는 일.
  - 코덱스 쪽.
  - 기록이 없는 프로젝트에서 비우는 일 — 기록이 없으면 지금처럼 엔진 요약으로 간다.

## Approach Overview

- 길: 턴 끝 → 기준 넘음 → 비우기 명령 → 새 세션 시작 → 본체의 이어 하기 훅이 기록의 끝부분을 실음 + 대시보드가 뒤에서 도는 일 목록을 실음.
- 본체: 이어 하기 훅은 지금 비우기 · 요약 · 재개 뒤에 진행 중인 대화 기록 전체를 찍는다. 비운 뒤(source 가 clear)에는 끝부분만 찍고, 전체가 어디 있는지 한 줄을 붙인다. 끝부분을 자르는 일은 순수 함수 하나다.
- 대시보드: 지금의 가볍게 하기는 요약 명령을 돌리고 그 답을 기록으로 채운다. 이것을 비우기 명령으로 바꾸고, 명령이 거절되면 지금의 길을 그대로 탄다.
- 확인된 것(2026-11-25, 화면 없는 실행 1회 · SCV 없이): 비우면 세션 번호가 바뀌고, 세션 시작 훅의 글이 새 대화에 실리고, 뒤에서 돌던 셸 작업의 알림이 새 대화에 온다 — 다만 새 대화는 그 일을 왜 돌렸는지 모른다.
- 확인 못 한 것: 모드가 비우기 명령을 대신 돌릴 수 있는지(모드 문서에 허용도 금지도 없음), 데스크톱 앱에서 비운 뒤 PR 감시 · 이어진 세션이 남는지. 5단계에서 실제 앱으로 본다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

본체의 단계 이름은 함수 이름이다. 대시보드의 단계 이름은 하는 일로 적었다 — 함수 이름은 대시보드 쪽 작업에서 정해 이 표에 채운다.

```
flow(
  scv_resume_tail,          // 기록 글 + 최대 글자 수 → 끝부분 글
  비울 때인지 가르기,        // 설정 + 컨텍스트 % + 턴 상태 + 마지막 때 → 예 | 아니오
  뒤에서 도는 일을 글로,     // 남은 일 목록 → 첫 글에 실을 줄들
  비운 결과를 한 줄로,       // 방법 + 앞 % + 뒤 % + 걸린 시간 → 창의 한 줄
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `scv_resume_tail` | 기록 글이 길면 끝에서 정한 글자 수만 남기되, 턴 머리 줄에서 시작하게 자른다 | 기록 글 + 최대 글자 수 → 끝부분 글 | 순수 |
| 2 | 비울 때인지 가르기 | 켜져 있고 · 기준을 넘었고 · 턴이 도는 중이 아니고 · 방금 하지 않았을 때만 예 | 설정 + % + 턴 상태 + 마지막 때 → 예 또는 아니오 | 순수 |
| 3 | 뒤에서 도는 일을 글로 | 턴이 남기고 간 일(명령 · 감시 · 터미널)을 새 대화가 읽을 줄들로 바꾼다 | 남은 일 목록 → 줄들 | 순수 |
| 4 | 비운 결과를 한 줄로 | 비웠는지 · 넘어갔는지 · 못 했는지와 앞뒤 %, 걸린 시간을 창의 한 줄로 만든다 | 방법 + % 둘 + 시간 → 한 줄 | 순수 |
| 5 | `on-session-start.sh` | 비운 뒤에는 끝부분과 전체 기록의 자리를 찍는다 | 세션 시작 알림 → 새 대화에 실릴 글 | 부수효과 (입구/출구) |
| 6 | 비우기 돌리기 | 비우기 명령을 돌린다. 거절되면 지금의 길(기록으로 바꿔 끼우기)을 탄다 | 예 → 비운 세션 또는 바꿔 끼운 대화 | 부수효과 (출구) |
| 7 | 첫 글에 싣기 · 창 그리기 | 뒤에서 도는 일의 줄들을 비운 뒤 첫 글에 싣고, 결과 한 줄을 창에 그린다 | 줄들 + 한 줄 → 새 대화 · 화면 | 부수효과 (출구) |

- 부수효과 위치: 훅(5) · 비우기 돌리기(6) · 싣기와 그리기(7). 1–4 는 받은 값만 본다.
- 재사용: 대시보드의 기록 끝부분 자르기(`recordTail`)와 같은 규칙을 본체에 둔다. 가르기(2)는 지금의 `lightDue` 를, 결과 한 줄(4)은 지금의 `lightNote` 를 넓혀 쓴다. 본체 훅은 이미 있는 기록 고르기(`scv_resume_pick`)를 그대로 쓴다.

## Guardrails

- 비우기가 되지 않았는데 됐다고 그리지 않는다 — 넘어갔으면 넘어갔다고, 못 했으면 못 했다고 그린다.
- 턴이 도는 중에는 비우지 않는다. 한 번 한 뒤 5분 안에는 다시 하지 않는다(지금 규칙 그대로).
- 기록이 없는 프로젝트는 비우지 않는다 — 비우면 아무것도 남지 않는다.
- 요약 · 재개 뒤의 글(기록 전체)은 그대로 둔다.
- 사람이 직접 친 비우기 명령은 건드리지 않는다 — 그때도 본체 훅은 끝부분을 싣는다.
- 훅은 어떤 경우에도 세션을 막지 않는다(지금 규칙 그대로) — 자르기가 실패하면 지금처럼 전체를 찍는다.

## Exit criteria

- TESTS.md 의 모든 시나리오 통과.
- 본체의 새 시험이 맥 기본 셸과 새 셸에서 통과.
- 모드 시험(`claude plugin test marketplace/mods/scv-dashboard`) 통과.
- 실제 앱의 시험용 세션에서 비우기가 도는 장면과 비운 뒤 첫 글을 사진으로 남겨 사용자에게 보인다. 모드가 비우기를 돌리지 못하면 2단계에서 멈추고 알린다.

## Suggested path

1. 본체: 비운 뒤 싣는 글을 기록 전체에서 끝부분 12,000자와 전체 기록의 자리로 줄인다 — `scv_resume_tail`, `on-session-start.sh`
2. 대시보드: 턴 끝에 기준을 넘으면 비우기 명령을 돌리고, 거절되면 지금의 길로 넘어간다 — `비울 때인지 가르기`, `비우기 돌리기`
3. 대시보드: 비운 뒤 첫 글에 뒤에서 도는 일 목록을 싣는다 — `뒤에서 도는 일을 글로`, `첫 글에 싣기 · 창 그리기`
4. 대시보드: 창의 글자를 "요약"에서 "비우기"로 바꾸고 결과 한 줄을 보인다 — `비운 결과를 한 줄로`
5. 실제 앱의 시험용 세션에서 한 번 돌려 사진으로 남긴다 — 모드가 비우기를 돌리는지, 비운 뒤 첫 글, PR 감시와 이어진 세션이 남는지를 본다

## Risks / Open Questions

- 모드가 비우기 명령을 대신 돌릴 수 있는지 모른다(모드 문서에 허용도 금지도 없음). 안 되면 대시보드 단계는 넘어가기 길만 남아 계획의 목표를 이루지 못한다 — 2단계에서 알리고 멈춘다.
- 데스크톱 앱에서 비운 뒤 PR 감시 · 이어진 세션 · 일꾼의 알림이 남는지 확인하지 못했다. 화면 없는 실행에서는 뒤에서 돌던 셸 작업의 알림이 새 대화에 왔다(1회).
- 비우면 세션 번호가 바뀐다 — 세션마다 따로 둔 SCV 상태(등록한 요청 · 읽음 표시)는 새로 시작한다. 본체 훅은 이미 비우기 때 그 상태를 되돌리게 되어 있다.
- 지금의 길은 최근 세 턴의 글을 남긴다. 비우면 그 글은 사라지고 기록의 끝부분만 남는다 — 기록에 적히기 전의 말은 잃는다.
- 대시보드 단계는 계획 `20261125-wookiya1364-mirror-controls` 와 같은 파일을 고친다 — 그 일이 끝난 뒤에 시작한다.
- 대화 기록 자리: 이 계획의 바탕이 된 2026-11-25 대화의 기록 파일은 비공개 기록 저장소에 있다 — `raw_sources` 는 비워 두었다.
