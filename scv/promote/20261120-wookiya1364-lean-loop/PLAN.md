# 가벼운 에이전트 루프 — 장부 호출을 훅으로 · 처음과 끝만 묻기 모드

## Summary

SCV 가 지켜야 할 두 가치 — 같은 결과까지 토큰을 아낀다, 사람의 일은 처음의 요구 전달과 마지막의 검증(영상 · e2e)뿐이다 — 를 지금 기록으로 재 보면 둘 다 못 지킨다(대화 Turn 30). 긴 실제 세션 168 사람 턴에서 SCV 장부 도구 호출(help 부르기 · 요청 다시 써서 등록 · 대화 기록 · 규약 표시 등)이 759번(턴당 4.5, 이 세션은 7.8), 종료 막힘 37번, 중간 선택 질문 161번이었다. 호출 하나가 맥락 전체를 다시 읽으므로 장부 호출만으로 입력 토큰의 최대 약 20%를 쓰는 것으로 추정한다.

이 계획은 (1) 장부를 훅이 대신 하게 해 턴당 장부 호출을 0–1 로 줄이고, (2) 종료 막힘을 바로 고칠 수 있는 것만 남기며, (3) 설정 하나로 켜는 '처음과 끝만 묻기' 모드(`SCV_ASK_MODE=ends`)를 만든다 — 요구 · 계획 개요와 마지막 영상 · e2e 검증에서만 묻고, 중간 결정은 추천대로 정해 끝 보고에 남긴다.

## Goals / Non-Goals

- **Goals**
  - help 결과(진단 · 규약 안내)는 매 턴 훅이 싣는다 — 모델이 help 를 도구로 부르지 않아도 된다.
  - 다시 쓴 요청 등록은 답 맨 위 인용에서 종료 훅이 읽어 한다 — 등록 도구 호출이 없다.
  - 대화 기록 · 규약 읽음 표시는 종료 훅이 한다.
  - 종료 막힘은 그 자리에서 바로 고칠 수 있는 것(인용 · 언어 등)만 남기고, 나머지는 다음 턴 경고로.
  - `SCV_ASK_MODE=ends`(설정 파일 · 환경 변수): 처음(요구 · 개요)과 끝(영상 · e2e 검증)에만 묻고 중간 결정은 추천대로, 끝 보고의 '제가 대신 정한 것'에 남김. 되돌릴 수 없는 일은 예외로 묻는다. 기본값은 지금과 같음(all).
  - 기존 세션 기록으로 전후(턴당 장부 호출 · 막힘 · 중간 질문)를 재고, 헤드리스 비교로 같은 결과인지 본다.
- **Non-Goals**
  - 기본값을 ends 로 바꾸기(사용자가 켤 때만).
  - 끝 검증 증거를 새로 만드는 기능(영상 · e2e 는 기존 Playwright · 대시보드 증거를 쓴다).

## Approach Overview

장부를 훅으로 옮기면 모델이 '직접 했다'는 확인이 '결과가 답에 있다'는 확인으로 바뀐다. 등록은 답 첫 줄의 `> **다시 쓴 요청**:` 인용을 종료 훅이 읽어 등록 파일에 쓰는 것으로 바꾸고, help 의 진단 · 규약 읽기 표시는 매 턴 훅이 지문과 함께 처리한다. 모드는 선택 규약(choices.md) · 실물 보여 주기(show-real.md) · 작업 규약(work.md)의 묻는 자리마다 "ends 면 이 자리는 묻지 않고 추천대로" 한 줄을 두고, 매 턴 안내 글도 모드에 맞춘다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readTurn,      // 훅 입력 · 상태 → 이번 턴 신호
  askPolicy,     // 모드 · 묻는 자리 종류 · 위험 여부 → 묻기 | 추천대로
  quoteRegister, // 답 글 → 다시 쓴 요청 인용(있으면)
  stopVerdict,   // 등록 · 인용 · 언어 · 모양 → 막기 | 다음 턴 경고 | 통과
  writeRecords,  // 결정들 → 등록 · 기록 · 표시 파일 (출력)
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `readTurn` | 훅 입력과 상태 파일을 읽음 | 입력 → 신호 | 부수효과 (입구) |
| 2 | `askPolicy` | 이 자리에서 물을지 추천대로 정할지 | 모드 · 자리 · 위험 → 결정 | 순수 |
| 3 | `quoteRegister` | 답 첫 줄 인용에서 다시 쓴 요청을 꺼냄 | 답 글 → 인용 글 | 순수 |
| 4 | `stopVerdict` | 바로 고칠 수 있는 어김만 막고 나머지는 경고 | 판정값들 → 결정 | 순수 |
| 5 | `writeRecords` | 등록 · 대화 기록 · 표시를 씀 | 결정 → 파일 | 부수효과 (출구) |

- 부수효과 위치: 1 · 5.
- 재사용: 지금의 등록 검사(`scv_mp_answer_rewrite_on_top` 등), 종료 판정(`scv_mp_stop_gate`), 선택 검사(choice-gate), 원칙 · 규칙 글 한 번 싣기.

## Guardrails

- 기본값(all)에서 묻는 동작 · 출력은 지금과 같다.
- 되돌릴 수 없는 일(배포 · 삭제 · 외부로 보내기)은 어떤 모드에서도 묻는다.
- 다시 쓴 요청 인용 맨 위 규칙과 그 검사는 그대로(등록 방법만 바뀜).
- 매 턴 안내 글 예산을 늘리지 않는다.
- 코어 글에 호스트 · 도구 이름 없음, 공개 저장소에 다른 프로젝트 이름 없음.

## Exit criteria

- TESTS.md 시나리오 통과(맥 · 리눅스 · 코덱스 사본), 전체 실행 통과.
- 기존 세션 기록 재계산: 턴당 장부 호출이 0–1 로(전 4.5–7.8), 막힘 수 감소, ends 모드에서 중간 질문 감소 — 수치로.
- 헤드리스 비교에서 같은 과제의 결과(시험 통과 · 답 모양)가 그대로.

## Suggested path

1. 매 턴 훅이 help 결과(진단 · 규약 안내 · 표시)를 대신 처리 — `readTurn`, `writeRecords`
2. 답 첫 줄 인용에서 다시 쓴 요청 등록 — `quoteRegister`
3. 종료 막힘을 바로 고칠 수 있는 것만 — `stopVerdict`
4. 처음과 끝만 묻기 모드(설정 · 환경 변수) — `askPolicy`
5. 기존 세션 기록 재계산 · 헤드리스 비교 — 전후를 수치로
6. 시험 · 전체 실행(맥 · 리눅스 · 코덱스 사본) — 시험으로 확인

## Risks / Open Questions

- 모델이 help 를 부르지 않게 되면, help 가 하던 '대화 모드 판단(아이디어 정리 · 기록 찾기)'을 어디서 할지 — 1단계에서 정함.
- 등록을 인용에서 읽으면 인용을 빼먹은 턴은 등록이 없음 — 지금처럼 막기로 남김(바로 고칠 수 있는 어김).
- 장부 호출의 실제 토큰 비율은 추정 — 5단계가 잰다.
