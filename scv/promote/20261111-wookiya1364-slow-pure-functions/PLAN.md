# 느린 순수함수 고치기 — 입력이 커지면 크게 느려지는 17개

## Summary

재는 명령으로 사전의 함수 363개를 재 보니, 입력을 4배로 늘릴 때 8배 넘게 느려지는 함수가 16개 있었다(옛 셸 15개, 새 셸에서만 넘는 것 1개).
가장 심한 것은 계획 충돌 검사 둘이다: 뒤쪽 검사는 4배 입력에 23초가 걸리고, 앞쪽 검사는 60초를 넘겨 끊겼다.
이 16개와, 낱말 수만큼 다른 프로그램을 부르는 함수 1개를 심한 것부터 고친다. 답은 바꾸지 않는다.

## Goals / Non-Goals

- **Goals**
  - 17개 함수를 심한 것부터 고쳐 4배 입력 시간을 줄인다
  - 함수마다 고치기 전과 답이 같은지를 시험으로 지킨다 (옛 본문을 견줄 판으로 남겨 여러 입력에서 맞댄다)
  - 함수마다 앞뒤 시간을 재는 명령으로 재서 표로 남긴다
  - 한도 안으로 들어온 함수는 배수 기준 목록에서 뺀다
  - 빨라지지 않는 함수는 되돌리고 이유를 적는다
- **Non-Goals**
  - 답의 모양이나 뜻을 고치는 일
  - 재는 명령의 한도 숫자나 재는 방법을 고치는 일
  - 17개 밖의 함수를 손보는 일
  - PR · 릴리스 · 래퍼 저장소 작업

## Approach Overview

17개는 모두 셸 함수다(순수 16개, 다른 프로그램을 부르는 것 1개). 코드를 읽어 보니 느려지는 모양은 넷이다.

1. **큰 글 하나에 계속 덧붙이기** — 답 줄을 변수 하나에 이어 붙이면 붙일 때마다 글 전체를 다시 베낀다. 나오는 대로 바로 내보내거나 배열에 모았다가 한 번에 낸다. (충돌 검사 둘, 낱말 나누기)
2. **안쪽 고리에서 같은 일을 되풀이** — 안쪽 고리를 돌 때마다 같은 글을 다시 다듬거나 다시 줄로 나눈다. 고리 밖에서 한 번만 한다. (충돌 검사 둘, 줄마다 한글 비율 재기)
3. **글자 하나씩 돌기** — 글자를 하나씩 꺼내 견준다. 통째 바꾸기나 덩어리 단위 자르기로 바꾼다. (범위 칸 소문자 바꾸기, 명령 줄 쪼개기)
4. **긴 글 통째로 무늬 맞추기 · 통째 바꾸기** — 옛 셸은 여러 바이트 글자가 든 긴 글에서 이 일이 글 길이의 제곱으로 느려진다. 바이트 단위로 해도 답이 같은 곳은 바이트 단위로 하고, 필요한 앞부분만 본다. (인용 줄 판정, 한글 비율, 경로를 파일 이름으로 바꾸기, 따옴표 속 비우기)

2026-11-11 에 뒤쪽 충돌 검사를 임시 폴더에서 시험으로 고쳐 봤다: 4배 입력에서 옛 셸 23061ms → 132ms, 새 셸 41896ms → 155ms, 답 10000줄이 모두 같았다.

짝을 모두 내는 함수 둘(같은 지문 짝, 양방향 짝)은 답 자체가 입력의 제곱만큼 늘 수 있다. 이런 함수는 8배 한도 안으로 못 들어올 수 있다 — 그때는 시간이 준 만큼만 고치고, 한도를 넘는 이유를 적어 기준 목록에 남긴다.

### 답이 같은지 지키는 방법

고치기 전 본문 17개를 `core/tests/fixtures/slow-pure/reference.sh` 에 `ref_` 이름으로 그대로 옮겨 둔다. 시험은 함수마다 사전의 예시, 그 예시를 25번 · 100번 되풀이한 입력, 손으로 고른 모서리 입력(빈 글, 한 글자, 여러 바이트 글자, 줄 끝이 없는 글)을 두 판에 넣어 출력과 끝 코드를 맞댄다.

## 결과 (2026-11-11, 이 맥에서 재는 명령으로 잰 값)

- 17개 가운데 16개가 두 셸 모두에서 4배 입력 시간이 줄었다. 답은 옛 본문과 같다(두 셸에서 맞댐).
- 기계 글 빼기(`scv_lang_drop_machine`)는 옛 셸에서 그대로다(12.2 → 12.4ms, 흔들림 안). 새 셸에서는 20.9 → 13.9ms. 바이트 단위로 찾게 한 한 줄만 남겼다.
- 입력 4배에 8배를 넘는 함수: 옛 셸 15개 → 4개, 새 셸 11개 → 4개. 기준 목록을 재는 명령이 고쳐 썼다.
- 여전히 넘는 넷과 이유:
  - 뒤쪽 충돌 검사 · 같은 지문 짝 · 양방향 짝 — 예시를 되풀이한 입력에서는 답 줄 수 자체가 입력의 제곱만큼 는다(뒤쪽 충돌 검사: 625줄 → 10,000줄). 줄 하나를 내는 값은 더 줄이지 못했다.
  - 기계 글 빼기 — 블록 하나를 지울 때마다 남은 글 전체를 다시 훑는다. 같은 답을 내면서 이것을 없애는 방법(지운 자리의 앞 조각을 따로 넘기기)을 만들어 쟀지만 빨라지지 않아 버렸다. 실제 입력(블록 0 ~ 3개)에서는 1ms 안팎이다.
- 사전 검사의 실제 모양(지문이 거의 다 다른 363줄)에서는 같은 지문 짝이 옛 셸 397 → 38ms, 새 셸 317 → 29ms.
- 범위 밖에서 본 것: 안내문 접기(`scv_mp_guide_fold`)가 새 셸에서 경계에 있다 — 고치기 전 7.5배, 이번에 다시 세 번 재니 7.6 · 8.1 · 7.5배. 이번에 손대지 않았고 기준 목록에도 넣지 않았다.
- 표: [`RESULT-table.md`](./RESULT-table.md) (17개 앞뒤), 전체 표 [`BENCH-after-bash3.md`](./BENCH-after-bash3.md) · [`BENCH-after-bash5.md`](./BENCH-after-bash5.md).

### 계획과 달라진 길

- 계획에 없던 파일 하나를 고쳤다: 재는 명령 시험(`core/tests/test-pure-bench.sh`). 그 시험은 "낱말 나누기는 옛 셸에서 8배를 넘는다"를 가파른 쪽 본보기로 썼는데, 낱말 나누기를 고쳐 4.9배가 되면서 실패했다. 본보기를 답이 제곱으로 느는 같은 지문 짝(14배)으로 바꿨다.
- 기계 글 빼기는 "빨라지지 않으면 되돌린다"는 기준에 딱 맞지 않는다 — 옛 셸에서는 그대로, 새 셸에서는 34% 줄었다. 한 줄(바이트 단위로 찾기)만 남기고, 효과가 없던 다른 시도는 버렸다.
- 한글 비율 · 경로 이름 · 낱말 나누기는 토막 크기를 셸 큰 버전에 따라 다르게 했다. 옛 셸에 맞춘 작은 토막이 새 셸에서는 고리 값만 늘려 조금 느려졌기 때문이다(한글 비율 0.27 → 0.46ms → 맞춘 뒤 0.29ms).

- 계획 끝 검사가 진짜 문제 하나를 잡았다: 범위 칸 판정의 첫 고친 판은 옛 셸에서 부를 때마다 메모리를 조금씩 흘렸다(1,500번에 3.4 → 9.2MB). 문구를 함수 안의 배열(`local -a 이름=(…)`)에 담은 탓이었다. 배열을 없애고 다시 썼다(3.4 → 3.5MB, 시간은 15 → 0.56ms). 나머지 15개는 같은 방법으로 재서 새지 않음을 봤다.
- 계획 끝 검사는 새 셸에서 끝까지 돌렸다(견준 함수 49 · 통과 20 · 새 함수 28 · 한도 넘음 1). 옛 셸에서는 고치기 전 본문이 느려 20분을 넘겨 멈췄다 — 옛 셸 쪽은 전체 표와 함수별 다시 재기로 대신했다.
- 한도 넘음 1은 뒤쪽 충돌 검사다. 느려진 것이 아니라(한 번 175 → 11ms), 고치기 전 본문이 4배 입력에서 끊겨 앞 배수를 재지 못했고 뒤 배수(11.5배)만 남아 걸렸다. 재는 검사의 빈틈이다: 고치기 전 값을 못 잰 경우를 "원래 한도 안"으로 본다.

### 고치면서 알게 된 것

- 옛 셸(bash 3.2)은 함수 안에서 `local -a 이름=(값 …)` 로 만든 배열의 메모리를 함수가 끝나도 다 돌려주지 않는다(부를 때마다 약 4KB). `local -a 이름=()` 로 만들고 하나씩 넣는 것은 새지 않았다.

- 옛 셸(bash 3.2)은 긴 글에서 `${글//무늬/}` 로 맞는 글자를 모두 지우거나 바꾸는 일이 글 길이의 제곱보다 느리다. 새 셸도 여러 바이트 글자가 든 글에서는 제곱에 가깝다(1,100자 6ms · 4,400자 63ms). 그래서 긴 글은 짧은 토막으로 잘라 하거나 머리만 본다.
- `local LC_ALL=C 값="${글//…}"` 처럼 한 줄에 쓰면 글이 먼저 바뀌고 로캘이 나중에 바뀐다.
- 함수 안에서 `local LC_ALL="${LC_ALL-}"` 로 받아 두면 도중에 `LC_ALL=C` 로 바꿔도 함수가 끝날 때 원래대로 돌아온다(두 셸에서 확인). 줄마다 띄우던 셸을 이 방법으로 없앴다.
- 줄바꿈이 없는 긴 글에서 `${글%%$'\n'*}` 는 길이의 제곱으로 느리다(두 셸 모두, 25,000자에 0.1초). 줄바꿈이 있을 때만 자른다.
- 옛 본문이 느린 것 자체가 시험 시간을 늘린다 — 견줄 판에 넣는 긴 입력은 경계마다 하나씩만 두었다.

## Guardrails

- 답을 바꾸지 않는다. 옛 본문과 한 글자라도 다르면 그 함수는 되돌린다.
- 순수함수 안에서 다른 프로그램(awk · sed · grep 같은 것)을 부르지 않는다. 순수 검사(`check-purity.sh`)가 통과해야 한다.
- 옛 셸(bash 3.2)에서 도는 문법만 쓴다 — 이름으로 찾는 배열(연관 배열), `${var,,}` 같은 것은 쓰지 않는다.
- 빨라졌다는 말은 재는 명령으로 잰 앞뒤 숫자가 있을 때만 한다.
- 배수 기준 목록은 재는 명령이 낸 결과로만 줄인다 — 손으로 지워 통과시키지 않는다.
- 코어 파일에 호스트 이름을 넣지 않는다.
