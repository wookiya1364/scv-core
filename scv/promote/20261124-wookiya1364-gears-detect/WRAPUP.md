# 마무리 보고 — 반복 알아채기 — 비슷한 요청 2번째에 "기어로 만들까요?", 맞는 기어가 있으면 한 줄 알림

## 1. 문제

- 상황: 기어를 만들어 두어도 모델이 있는 줄 모르면 쓰이지 않고, 같은 요청이 두 번째인지 알 길이 없다(2026-11-24 대화).
- 기대: 비슷한 요청이 2번째면 선택 창으로 기어로 만들지를 묻고, 맞는 기어가 있으면 그 턴에 한 줄로 알려 모델이 그것을 돌린다. 겹치는 것이 없는 턴에는 추가 글이 없다.
- 실제: SCV 는 지난 요청을 쌓지 않는다 — '다시 쓴 요청'은 이번 턴 것만 남고 덮어써진다(2026-11-24 확인: 기록 폴더의 등록 파일 하나).
- 재현 조건: 한 세션에서 요청하고, 새 세션에서 같은 요청을 다시 하면 모델은 처음 받은 요청처럼 다룬다.

## 2. 관찰

해당 없음 — 고장을 고치는 계획이 아니라 새 기능이다

## 3. 가설

해당 없음 — 원인을 찾는 일이 아니라 가설을 세우지 않았다

## 4. 실험

해당 없음 — 원인 실험이 없다. 검증은 6번에 적는다

## 5. 원인

해당 없음 — 고장이 아니라 원인이 없다

## 6. 해결과 검증

- 해결책과 고른 이유: 매 턴 훅이 사람 요청을 비밀 가림 뒤 기록 폴더에 한 줄씩 쌓고(`gear.sh detect`), 지난 요청 200줄 · 기어 사전과 스크립트로 맞춰 본다. 겹칠 때만 알림 한 줄을 싣고, 같은 일인지는 모델이 본다. 맞춰 보기는 공백 · 문장 부호를 뺀 글의 이어진 두 바이트 조각이 겹치는 비율이다 — 글자 단위는 글자 설정마다 값이 달라져 바이트로 셌다. 기어 사전은 대시보드 창과 같은 기준(낱말 둘 이상 겹침)으로 본다. 거절은 명령 하나(`gear.sh decline`)로 적어 선택 답 훅이 없는 호스트에서도 같게 돈다.
- 고치기 전후 값: 전에는 알림이 없었다(엉뚱한 알림 0 · 놓침 100%). 실제 요청 420개(두 프로젝트, 기록의 중단 표시 줄 20개는 사람 요청이 아니라 뺌)를 시간순으로 흘린 값 — 기준 점수 55 · 최소 길이 18바이트에서 알림 19번, 엉뚱한 알림 1번(5%, 기준 10% 이하), 맞는 알림 18번, 표시해 둔 반복 124번 중 놓침 106번(85%). 기준 점수를 48 아래로 내리면 엉뚱한 알림이 12% 를 넘는다(46: 25%, 42: 44%). 기준값은 같은 기록으로 골랐으므로 다른 프로젝트에서는 다를 수 있다. 매 턴 시간: 기어 스무 개 · 기록 200줄에서 훅 다섯 번의 CPU 시간이 켬 6.5초 · 끔 6.0초(1.08배, 기준 1.5배 이내).
- 부작용과 회귀 시험: 새 시험 `core/tests/test-gear-detect.sh` 12개(T1–T11 · T14), 맥 기본 셸 · 새 셸 통과. 겹치지 않는 턴과 첫 턴의 훅 출력은 끈 것과 바이트까지 같다(T3 · T4). 놓침이 85% 인 것은 설계대로다 — 말이 다른 같은 일은 잡지 않는다(잡으려면 모델이 매 턴 사전을 읽어야 한다). 끄는 설정 SCV_GEAR_DETECT=off. 실제 새 세션 두 번(작은 프로젝트, 화면 없는 실행, 고친 본체를 얹은 설치본 사본): 같은 요청의 첫 번째는 알림 없음, 새 세션의 두 번째는 알림이 실리고 모델이 답 끝에 "이것을 별도의 기어로 만들어 재사용할 수 있게 할까요?"라고 물음 — 선택 창이 없는 실행이라 글로 물었고, 모델 호출 수와 쓴 토큰은 첫 번째와 비슷했음(14 · 13번, 3,395 · 3,548). 앱의 선택 창 모습은 사용자가 직접 보기로 함(2026-11-25). 첫 전체 실행에서 순수성 검사가 걸림 — 외부 도구를 쓰는 함수 일곱의 표식을 결정적으로 바꾸고 awk 안의 부등호를 없앰(결과는 같음: 실제 요청에서 알리는 턴 19개 그대로).

## 7. 배운 것

- 다음에 같은 문제를 만나면 진단하는 법: 정답(같은 일의 반복 묶음)을 맞추는 코드보다 먼저 고정하고, 실제 요청을 시간순으로 흘려 알림이 뜬 턴마다 정답과 견준다. 첫 측정에서 엉뚱한 알림이 50% 넘게 나왔는데, 18건이 대화 기록에만 남는 중단 표시 줄이었다 — 재는 자료가 훅이 실제로 받는 입력과 같은지부터 본다.
- 다른 곳에도 쓸 수 있는 것: 글자 수를 세는 맞춰 보기는 글자 설정에 따라 값이 달라진다 — 바이트로 세면 맥 · 리눅스 · 옛 셸에서 같은 값이 나온다. 여러 줄과 견줄 때는 줄마다 프로세스를 띄우지 말고 awk 한 번으로 돈다.
