# 매 턴 규칙 글은 한 번만 · 숫자 길이 상한 없애기

## Summary

SCV 의 답 규칙과 Fable 5.2 · Opus 5.5 공식 프롬프팅 가이드를 대조한 결과(대화 Turn 16), 두 가지를 고친다. 첫째, 문장 수 · 불릿 길이처럼 숫자로 박은 상한은 공식 문서가 "글을 뚝뚝 끊는다"고 짚는 규칙이라 없앤다 — 답 모양 자체는 그대로 둔다. 둘째, 사람 턴마다 같은 규칙 글(언어 · 확인 범위 · 답 모양 · 선택 · 실물 보여 주기 · 원칙, 약 4.8 KB)이 다시 붙어 쌓인다. 원칙 글에 이미 있는 '세션에 한 번' 방식을 나머지 규칙 글에도 넓혀, 첫 턴 · 대화 요약 뒤 · 규약을 다시 읽는 턴(기본 10턴마다)에만 전문을 싣고, 그 밖의 턴은 한 줄로 줄인다. 직전 답에 경고가 있으면 그 턴은 전문을 다시 싣는다.

측정(대화 Turn 18–19): 두 세션 기록으로 다시 계산하면 턴당 4.3–6.0 KB → 1.6–2.8 KB(54–63% 줄어듦). 헤드리스 비교 시험 8턴에서 규칙 어김은 늘지 않음(매 턴 전문 16답 어김 2 · 첫 턴만 8답 어김 1, 표본 작음).

## Goals / Non-Goals

- **Goals**
  - 답 모양 검사에서 문장 수 상한(줄글 · 결론 줄)과 불릿 길이 상한을 없앤다. 매 턴 안내 · 규약 · 글 모양 규약의 숫자 표현도 숫자 없이 고친다.
  - 규칙 글 다섯 덩어리를 원칙 글과 같은 지문(nonce) 기준으로 '세션에 한 번'만 싣고, 그 밖의 턴은 한 줄 알림으로 바꾼다.
  - 직전 답에 경고가 남은 턴은 전문을 다시 싣는다.
  - 끄는 설정(`SCV_RULES_ONCE=off`)이면 지금처럼 매 턴 전문.
  - 릴리스 뒤 다른 프로젝트의 긴 실제 세션 기록으로 어김 비율 · 턴당 크기를 전후 비교한다(마무리 보고).
- **Non-Goals**
  - 다시 쓴 요청 인용 위치 · 개조식 끝맺음 바꾸기(사용자 결정: 그대로).
  - 등록 · help 먼저 부르기 지시(이 턴의 첫 행동 · [SCV 프롬프트]) 줄이기 — 검사가 막는 지시라 이번 범위 밖.
  - 경고 문구 자체 바꾸기.

## Approach Overview

1. 숫자 상한: `scv_answer_lint` 가 문장 수(prose-long)와 불릿 길이를 더는 알리지 않는다. `SCV_PLAIN_MAX_SENTENCES` 는 읽지 않는다(설정 예시 · 문서에서 뺀다). 훅 · 규약 · SCV.md 의 "1–2 sentences" 표현은 "짧게"류의 숫자 없는 말로 바꾸고, 그 문구를 고정한 시험 앵커 · 지문을 새로 만든다.
2. 한 번만 싣기: `model-prompting.sh rules --session <id>` 가 이 세션 턴 폴더의 `.rules-seen` 과 지금 지문을 견줘 `full | short` 를 내고, full 이면 표시를 쓴다(원칙 글의 `.principle-seen` 과 같은 방식, 같은 지문 — 지문은 첫 턴 · 요약 뒤 · `SCV_HELP_RELOAD_EVERY` 턴마다 바뀐다). 훅은 입력을 맨 앞에서 읽어 세션 id 를 알고, short 이고 그 세션에 남은 경고가 없으면 다섯 덩어리 대신 한 줄을 싣는다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readTurnState,   // 세션 id → 지문 · 본 표시 · 남은 경고 여부
  rulesMode,       // 지문 · 본 표시 · 경고 · 설정 → full | short
  emitRules,       // full | short → 규칙 전문 또는 한 줄 (출력)
)
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | `readTurnState` | 이 세션의 지문 · `.rules-seen` · 경고 파일 유무를 읽음 | 세션 id → 세 값 | 부수효과 (입구) |
| 2 | `rulesMode` | 설정이 off 이거나 지문이 다르거나 경고가 있으면 full, 아니면 short | 네 값 → full · short | 순수 |
| 3 | `emitRules` | full 이면 다섯 덩어리를 싣고 표시를 씀, short 면 한 줄 | 모드 → 출력 · 표시 | 부수효과 (출구) |
| 4 | `lintNoCaps` | 답 골격 검사에서 문장 수 · 불릿 길이 항목을 뺌 | 답 글 → 어김 목록 | 순수 |

- 부수효과 위치: 1 · 3 (파일 읽기 · 쓰기, 출력).
- 재사용: `scv_mp_principle_show`(지문 비교) · 원칙 글의 `.principle-seen` 방식 · `scv_answer_lint`.

## Guardrails

- 답 모양 · 개조식 · 인용 맨 위 규칙과 그 검사는 그대로(숫자 상한만 뺌).
- 매 턴 안내 글 예산 시험(instruction-diet · help-budget)의 상한은 올리지 않는다 — 줄어드는 쪽이다.
- 다른 세션의 경고 · 표시를 섞지 않는다(세션 턴 폴더만).
- 자동 알림 턴의 동작은 지금과 같게(실리는 글이 줄어들 뿐).
- 맥(BSD) · 리눅스(GNU) 둘 다. 공개 저장소에 다른 프로젝트 이름 넣지 않기.

## Exit criteria

- TESTS.md 시나리오 모두 통과(맥 · 리눅스), 푸시 전 전체 실행 통과.
- 같은 세션 둘째 턴부터 매 턴 글이 한 줄로 줄고(바이트로 확인), 지문이 바뀌거나 경고가 있는 턴은 전문.
- `SCV_RULES_ONCE=off` 에서 출력이 이전과 바이트 단위로 같음.
- core · claude · codex 릴리스.

## Suggested path

1. 답 골격 검사에서 문장 수 · 불릿 길이 상한을 뺀다 — `lintNoCaps`
2. 훅 · 규약 · SCV.md · 설정 예시의 숫자 표현을 숫자 없는 말로 바꾸고 앵커 · 지문을 새로 만든다 — 숫자 없는 글로 바꾸고 고정 문구 시험을 맞춤
3. 규칙 글 한 번만 싣기 — `readTurnState`, `rulesMode`, `emitRules`
4. 시험을 만들고 관련 시험 · 전체 실행을 맥 · 리눅스에서 돌린다 — 시험으로 확인
5. 코어 · 래퍼 릴리스 — 릴리스
6. 릴리스 뒤 다른 프로젝트의 긴 실제 세션 기록으로 턴당 크기 · 어김 비율을 전후 비교 — 마무리 보고에 수치로
7. 규약을 다시 읽을 때 전문 턴이 두 번 생기는 것 고치기 — 전문을 실은 턴이 끝날 때 새 지문을 본 것으로 적음, 기존 세션 기록으로 전후 측정
8. 규칙 글 판단을 지문 대신 맥락 표시로 — 요약 · 비움 · 재개 때만 다시 전문, 가이드 안내만 남은 경고는 세지 않음 — `rulesMode`
