# 다시 쓴 요청이 일 내내 맞게 — 답 뒤 재등록 · 세션별 턴 상태 · 가이드 다시 읽기 줄이기

## Summary

SCV 의 '다시 쓴 요청'은 같은 Claude 가 일 전에 스스로 쓰는 메모다(별도 모델 호출은 채택하지 않았다). 2026-10-03 실측에서
헤드리스 12번은 6번 모두 진단을 마친 뒤에 등록했고, 실제 긴 세션(사람 턴 7개, 약 23시간)에서는 6턴 중 4턴이 일보다 먼저 등록했다.
진짜 빈틈은 그 뒤다. 선택 창 답으로 방향이 바뀐 3턴 모두 다시 등록 없이 편집 · 커밋이 이어졌고(세션 전체 재등록 0번),
'바꾸지 않는다'로 등록한 4턴 중 2턴에서 코드가 바뀌었다. 또 가이드 원문을 7턴 중 5턴에서 다시 읽었고(약 $2.5 더 든 것으로 추정),
턴 상태가 프로젝트 공용 파일이라 같은 프로젝트의 분석 에이전트 6개 중 5개가 리드 세션의 등록 때문에 끝내지 못했다.
이 계획은 다시 쓴 요청이 일 내내 실제 일과 맞게 하고, 그 비용과 다른 세션의 끼어듦을 줄인다.

## Goals / Non-Goals

- **Goals**
  1. **보이는 곳** — 답 맨 위에 "이렇게 이해하고 일함: …" 한 줄을 두고, 결론 바로 뒤에 다시 쓴 요청 전문을 인용한다(전문 위치는 지금과 같다).
     맨 위 한 줄도 종료 검사가 확인한다. 설정 설명(`SCV_MODEL_PROMPTING` — 지금 "답 앞에 보인다")과 규칙 · 경고 문구를 이 동작에 맞춘다.
  2. **답 뒤 재등록** — 선택 창 답이 온 뒤 첫 파일 편집 전에 다시 등록해야 편집을 허용한다. 범위가 그대로면 '그대로' 한 줄 등록으로 끝난다.
  3. **금지 대조** — 마지막 등록의 범위 칸에 변경 금지가 있으면 편집을 막고, 사유에 "범위가 바뀌었으면 다시 등록하라"를 준다.
     범위 칸 밖의 문장은 판정하지 않는다(문장 전체를 판정하면 오판이 난다).
  4. **가이드 다시 읽기** — 매 턴 대화 기록에서 "마지막 /clear · 압축 뒤에 지금 모델의 가이드 원문을 읽었는가"를 보고, 없을 때만 다시 읽게 한다.
     재접속 · 이어받기 · 턴 수만으로는 다시 읽게 하지 않는다. 모델이 바뀌면 그 모델의 가이드를 읽는다.
  5. **세션별 턴 상태** — 이번 턴 표 · 등록 · 막기 기록 · 경고를 세션마다 따로 둔다. 각 세션은 자기가 받은 사람 메시지와 자기 등록으로만 판정한다.
     사람 메시지를 받지 않은 하위 세션(팀원 · 하위 에이전트)은 등록하지 않아도 막지 않고, 리드의 등록 · 막기 횟수 · 경고에 영향을 주지 않는다.
  6. **종료 검사의 입력 창** — 검사마다 필요한 쪽을 본다. 선택지 검사는 답의 끝, 원칙 검사는 답 전체(바이트 상한 안에서 앞뒤)를 본다. 64KB 를 넘는 답도 판정한다.
- **Non-Goals**
  - 별도 모델로 다시 쓰기(방식 B) — 2026-09-28 결정대로 채택하지 않는다.
  - 다시 쓴 글의 품질 판정 — SCV 는 항목이 채워졌는지와 위 검사만 본다.
  - 하위 세션에 등록 의무 지우기.
  - /clear 뒤 복원 요약(`scv/raw/20261001-resume-recap-stale-conversation.md`) · bash 3.2 점검(`scv/raw/20261001-hook-path-bash32-audit.md`) — 다음 계획.

## Approach Overview

- 판단의 근거를 '프로젝트 공용 파일'에서 '이 세션의 기록'으로 옮긴다. 훅은 입력으로 세션 id 와 대화 기록 경로를 받는다
  (종료 훅 `core/template/hooks/on-stop.sh:33` 이 대화 기록 경로를, 세션 시작 훅 `on-session-start.sh:64-73` 이 시작 이유를 이미 읽는다 — 확인).
- 턴 상태(지금 `scv/journal/.help-turn` · `.help-rewrite` · `.help-turn-gates` · `.help-guide*`)를 세션 id 로 나눠 둔다.
- 쓰기 검사(가드의 등록 규칙, `guard.sh` Rule P → `model-prompting.sh gate`)는 "이 세션의 이번 턴 등록이 있는가"에 더해
  "마지막 등록 뒤에 선택 창 답이 있었는가"와 "마지막 등록의 범위 칸이 변경을 막는가"를 본다.
- 가이드 다시 읽기는 help 가 대화 기록의 마지막 경계(/clear · 압축) 뒤에 지금 모델의 가이드 읽기가 있는지로 정한다.
- 종료 훅은 검사마다 다른 입력 창을 넘긴다(지금은 모든 검사가 앞 64KB — `on-stop.sh:138,143,186,198,221`).
- 보이는 곳: 매 턴 블록 · 규칙 문구 · 경고 문구의 인용 위치 규칙에 '맨 위 한 줄'을 더하고, 종료 검사의 인용 판정이 그 한 줄도 본다.
- 코어는 호스트 중립을 지킨다. '선택 창 답'이라는 신호는 래퍼가 알려 준다(클로드 래퍼의 훅 설정에는 지금 그 사건이 없다 — 확인).

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readHookInput,     // (훅 stdin JSON) → { session, transcript, event }              — 부수효과(입구)
  loadSessionTurn,   // (session, 기록 폴더) → 이 세션의 턴 상태                      — 부수효과(입구)
  sliceTurnEvents,   // (대화 기록 끝부분) → 이번 턴 사건 목록(등록 · 선택 창 답 · 편집 · 경계) — 순수
  decideGuideLoad,   // (사건 목록, 모델) → load | loaded                             — 순수
  decideWriteGate,   // (턴 상태, 사건 목록, 쓰기 대상) → allow | deny(사유)           — 순수
  decideStopGates,   // (턴 상태, 검사별 답 창) → 막기 | 경고 | 통과                  — 순수
  renderReason,      // (판정) → 모델 · 사용자에게 보일 한 줄                          — 순수
  saveSessionTurn,   // (새 턴 상태) → ()                                              — 부수효과(출구)
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | readHookInput | 훅 stdin → 세션 id · 대화 기록 경로 · 사건 | 부수효과 (입구) |
| 2 | loadSessionTurn | 세션 id → 이 세션의 이번 턴 표 · 등록 · 막기 기록 | 부수효과 (입구) |
| 3 | sliceTurnEvents | 대화 기록 끝부분 → 이번 턴 사건 목록 | 순수 |
| 4 | decideGuideLoad | 사건 목록 · 모델 → 다시 읽기 필요 여부 | 순수 |
| 5 | decideWriteGate | 턴 상태 · 사건 · 대상 → 허용 / 거절(사유) | 순수 |
| 6 | decideStopGates | 턴 상태 · 검사별 답 창 → 막기 / 경고 / 통과 | 순수 |
| 7 | renderReason | 판정 → 한 줄 사유 | 순수 |
| 8 | saveSessionTurn | 새 턴 상태 → 저장 | 부수효과 (출구) |

- 부수효과 위치: 훅 입력 읽기와 세션 상태 파일 읽기/쓰기뿐이다. 판정 단계는 문자열을 받아 문자열을 돌려준다.
- 재사용: 종료 훅의 이번 턴 자르기(`scv_turn_slice`), `core/scripts/lib/stop-gates.sh` 의 검사 판정,
  `core/scripts/lib/model-prompting.sh` 의 등록 · 인용 판정. 단계 이름은 제안이며 구현에서 바꿔도 된다.

## Guardrails

- 기존 검사 동작(등록 전 편집 거절 · 인용 없는 종료 막기 · 같은 턴에 한 번만 막기 · 막지 않을 때 다음 턴 경고)은 그대로다.
  바뀌는 것은 '누구의 · 언제의 등록을 보느냐'와 검사별 입력 창뿐이다. 기존 테스트(`test-model-prompting` · `test-guard` ·
  `test-choice-questions` · `test-help-load-once` · `test-session-resume` · `test-help-budget`)가 그대로 통과한다.
- 맥(bash 3.2) · 리눅스에서 같은 결과 — bash 4 전용 문법을 쓰지 않고, 두 CI 모두 초록이어야 한다.
- 어떤 실패(기록 파일 없음 · 읽기 실패 · 형식 이상)도 세션을 멈춰 세우지 않는다. 판정할 수 없으면 '의견 없음'(지금처럼)이다.
- 사용자 원문 · 모델 · 사고량은 바꾸지 않는다(2026-09-28 계획의 약속).
- 코어에 호스트 · 모델 이름을 넣지 않는다. 선택 창 신호와 가이드 폴더는 래퍼가 준다.
- 매 턴 비용 상한 검사(`test-help-budget`)를 통과한다. 올려야 하면 새 상한과 이유를 검사 파일에 적는다.
- 대화 기록은 읽기만 하고, 상태 파일은 그 세션의 것만 쓴다. 심볼릭 링크면 쓰지 않는다(지금 규칙).

## 예외처리 (Edge cases)

- 한 턴에 선택 창 답이 여러 번 — 마지막 답 뒤 첫 편집 전에 등록 하나면 된다(목표 2).
- '그대로' 한 줄로 등록했는데 직전 등록의 범위 칸에 변경 금지가 있다 — 범위가 그대로이므로 금지도 그대로다. 편집하려면 범위를 바꿔 다시 등록한다(목표 2 · 3).
- 하위 세션이 사람 메시지를 직접 받았다 — 그 세션도 자기 등록으로 판정한다(목표 5).
- 대화 기록이 없거나 형식이 다르다 — 의견 없음(Guardrails).
- 답이 64KB 를 넘는다 — 검사마다 필요한 쪽을 본다(목표 6).

## Risks / Open Questions

- 하위 세션 구분 — 분석 에이전트의 보고로는 팀원이 리드와 같은 세션 id 로 기록됐다(에이전트가 상태 파일을 보고 한 판단, 미확인).
  훅 입력에서 하위 세션을 가를 값이 없으면 '이 세션에 사람 메시지가 왔는가'(이번 턴 표가 그 세션에 생겼는가)로 가른다.
- '대화 기록 = 모델의 맥락'이라는 전제 — 이어받기 · 재접속 뒤에도 성립하는지, 압축 경계가 기록에 어떻게 남는지 테스트로 확인한다.
- 큰 대화 기록(수십 MB)에서 매 턴 판정 속도 — 구현 전에 지금 훅 시간을 재고 기준을 정한다(64KB 메모의 기준: 10만 바이트 답 1.2초).
- 재등록이 늘리는 비용과 번거로움 — '그대로' 한 줄 등록의 실제 비용을 실측으로 확인한다.
- 헤드리스에는 선택 창이 없다 — 답 뒤 재등록은 대화형(tmux)으로만 재현할 수 있다.
- 실제 긴 세션 분석은 하루 사용을 기다려야 한다 — 끝 조건의 마지막 단계다.

# Test Plan — 다시 쓴 요청이 일 내내 맞게 — 답 뒤 재등록 · 세션별 턴 상태 · 가이드 다시 읽기 줄이기

## Overview

다시 쓴 요청이 턴의 첫 부분만이 아니라 일 내내 실제 일과 맞는지, 그 장치가 다른 세션을 막거나 가이드를 쓸데없이 다시 읽게 하지 않는지를
확인한다. T1~T11 은 픽스처로 도는 자동 검사(맥 bash 3.2 · 리눅스 CI), T12~T16 은 설치본으로 하는 실측이다.
실측의 기준선은 2026-10-03 대화(`scv/conversations/20261003-155702-other-session-history-access.md`)의 숫자다:
선택 창 답 뒤 재등록 0/3, '바꾸지 않는다'인데 편집 2/4, 가이드 다시 읽기 7턴 중 5턴, 하위 세션 막힘 5/6.

## Test scenarios

### T1. 보이는 곳 — 맨 위 한 줄 + 결론 뒤 전문

- **Setup**: 이번 턴에 등록이 있는 상태. 답 픽스처 세 개 — (a) 맨 위 "이렇게 이해하고 일함: …" 한 줄 + 결론 뒤 `> **다시 쓴 요청**: …` 전문,
  (b) 결론 뒤 전문만, (c) 맨 위 한 줄만.
- **Run**: 종료 검사의 인용 판정을 세 답에 돌린다.
- **Expected**: (a) 통과. (b) · (c) 는 같은 턴 한 번 막고, 사유가 빠진 쪽(맨 위 한 줄 / 전문)을 정확히 말한다. 이미 계속 중이면 막지 않고 다음 턴 경고.
- **Pass criterion**: 세 결과가 기대와 같고, 막기 · 경고 문구가 빠진 쪽을 이름으로 말한다.

### T2. 설정 설명 · 규칙 문구가 같은 위치를 말한다

- **Setup**: 설정 예시(`core/template/scv/scv_settings.example.json` 의 `SCV_MODEL_PROMPTING` 설명), 매 턴 블록, 경고 문구, help 규약(prompt-refine).
- **Run**: 네 곳의 인용 위치 문구를 검사로 모은다.
- **Expected**: 네 곳 모두 "맨 위 한 줄 + 결론 바로 뒤 전문"을 말하고, "답 앞에 보인다" 같은 옛 문구가 남지 않는다.
- **Pass criterion**: 옛 문구 0건, 새 위치 문구가 네 곳에 모두 있다.

### T3. 답 뒤 재등록 — 선택 창 답 뒤 첫 편집 전

- **Setup**: 대화 기록 픽스처 — 사람 메시지 → 등록 → 선택 창 답 → 편집 시도.
- **Run**: 쓰기 검사를 편집 시도에 돌리고, 다시 등록한 뒤 한 번 더 돌린다.
- **Expected**: 첫 편집은 거절되고 사유에 다시 등록하는 명령이 있다. 다시 등록한 뒤에는 허용된다. 답이 없는 턴의 편집은 지금처럼 허용된다.
- **Pass criterion**: 거절 → 재등록 → 허용 순서가 그대로 나오고, 답 없는 턴은 바뀌지 않는다.

### T4. '그대로' 한 줄 등록

- **Setup**: T3 의 기록에서 범위가 바뀌지 않은 답(예: "승인").
- **Run**: 답 뒤에 '그대로' 한 줄로 등록하고 편집을 시도한다. 답이 없는 상태에서도 '그대로' 등록을 시도한다.
- **Expected**: 답 뒤 '그대로' 등록은 받아들여져 편집이 허용되고, 인용 판정의 기준은 직전 다시 쓴 요청 그대로다. 답이 없는 '그대로' 등록은 불완전 등록으로 거절된다.
- **Pass criterion**: 두 경우의 결과가 기대와 같다.

### T5. 금지 대조 — 범위 칸의 변경 금지

- **Setup**: 범위 칸이 "파일 · 코드는 바꾸지 않는다"인 등록, 범위 칸에 금지가 없고 다른 칸에만 "바꾸지 않는다" 문장이 있는 등록.
- **Run**: 각 등록 뒤 편집을 시도하고, 첫 등록 뒤에는 금지 없는 범위로 다시 등록한 뒤 한 번 더 시도한다.
- **Expected**: 범위 칸 금지 → 거절, 사유에 "범위가 바뀌었으면 다시 등록하라". 금지 없는 재등록 뒤 → 허용. 다른 칸에만 있는 문장 → 막지 않음.
- **Pass criterion**: 세 결과가 기대와 같다(오판 0).

### T6. 가이드 다시 읽기 — 대화 기록으로 판단

- **Setup**: 대화 기록 픽스처 네 개 — (a) 가이드 읽기 뒤 이어받기 · 재접속만 있고 10턴 넘게 지남, (b) 가이드 읽기 뒤 압축 경계,
  (c) 가이드 읽기 뒤 /clear, (d) 다른 모델의 가이드만 읽음.
- **Run**: help 의 가이드 판정(GUIDE 줄)을 네 기록에 돌린다.
- **Expected**: (a) loaded, (b) · (c) · (d) load.
- **Pass criterion**: 네 결과가 기대와 같고, (a) 에서 턴 수 · 재접속만으로 load 가 나오지 않는다.

### T7. 큰 대화 기록에서의 속도

- **Setup**: 수십 MB 대화 기록 픽스처(가이드 읽기가 아주 앞쪽에 있거나 없는 경우 포함).
- **Run**: 매 턴 판정(T3 · T5 · T6 의 판정)을 맥 기본 bash 3.2 와 리눅스에서 잰다.
- **Expected**: 구현 전에 잰 지금 매 턴 훅 시간 기준 안에 끝난다(기준값은 구현 전 측정으로 정해 이 항목에 적는다).
- **Pass criterion**: 두 환경 모두 기준 안.

### T8. 세션별 턴 상태 — 두 세션이 서로 끼어들지 않는다

- **Setup**: 같은 프로젝트에서 세션 A · B 를 흉내 낸 훅 입력(세션 id 다름).
- **Run**: B 만 등록한 뒤 A 의 쓰기 · 종료 검사를 돌리고, A 만 등록한 뒤 B 의 종료 검사를 돌린다. 막기 기록 · 경고를 확인한다.
- **Expected**: B 의 등록이 A 를 통과시키지 않는다. A 의 등록이 B 를 막지 않는다. 막기 횟수 · 경고가 세션끼리 섞이지 않는다.
- **Pass criterion**: 세 조건이 모두 성립한다.

### T9. 하위 세션 — 사람 메시지를 받지 않은 세션은 막지 않는다

- **Setup**: 리드 세션이 이번 턴에 등록한 상태에서, 사람 메시지 없이 일하고 끝나는 하위 세션(팀원 · 하위 에이전트)의 종료.
- **Run**: 하위 세션의 종료 검사를 돌린다.
- **Expected**: 막지 않는다. 리드의 막기 기록 · 경고 파일에 아무것도 남기지 않는다. 리드의 이번 턴 '한 번 막기'를 쓰지 않는다.
- **Pass criterion**: 세 조건이 모두 성립한다.

# 다시 쓴 요청이 일 내내 맞게 — 답 뒤 재등록 · 세션별 턴 상태 · 가이드 다시 읽기 줄이기

## Summary

SCV 의 '다시 쓴 요청'은 같은 Claude 가 일 전에 스스로 쓰는 메모다(별도 모델 호출은 채택하지 않았다). 2026-10-03 실측에서
헤드리스 12번은 6번 모두 진단을 마친 뒤에 등록했고, 실제 긴 세션(사람 턴 7개, 약 23시간)에서는 6턴 중 4턴이 일보다 먼저 등록했다.
진짜 빈틈은 그 뒤다. 선택 창 답으로 방향이 바뀐 3턴 모두 다시 등록 없이 편집 · 커밋이 이어졌고(세션 전체 재등록 0번),
'바꾸지 않는다'로 등록한 4턴 중 2턴에서 코드가 바뀌었다. 또 가이드 원문을 7턴 중 5턴에서 다시 읽었고(약 $2.5 더 든 것으로 추정),
턴 상태가 프로젝트 공용 파일이라 같은 프로젝트의 분석 에이전트 6개 중 5개가 리드 세션의 등록 때문에 끝내지 못했다.
이 계획은 다시 쓴 요청이 일 내내 실제 일과 맞게 하고, 그 비용과 다른 세션의 끼어듦을 줄인다.

## Goals / Non-Goals

- **Goals**
  1. **보이는 곳** — 답 맨 위에 "이렇게 이해하고 일함: …" 한 줄을 두고, 결론 바로 뒤에 다시 쓴 요청 전문을 인용한다(전문 위치는 지금과 같다).
     맨 위 한 줄도 종료 검사가 확인한다. 설정 설명(`SCV_MODEL_PROMPTING` — 지금 "답 앞에 보인다")과 규칙 · 경고 문구를 이 동작에 맞춘다.
  2. **답 뒤 재등록** — 선택 창 답이 온 뒤 첫 파일 편집 전에 다시 등록해야 편집을 허용한다. 범위가 그대로면 '그대로' 한 줄 등록으로 끝난다.
  3. **금지 대조** — 마지막 등록의 범위 칸에 변경 금지가 있으면 편집을 막고, 사유에 "범위가 바뀌었으면 다시 등록하라"를 준다.
     범위 칸 밖의 문장은 판정하지 않는다(문장 전체를 판정하면 오판이 난다).
  4. **가이드 다시 읽기** — 매 턴 대화 기록에서 "마지막 /clear · 압축 뒤에 지금 모델의 가이드 원문을 읽었는가"를 보고, 없을 때만 다시 읽게 한다.
     재접속 · 이어받기 · 턴 수만으로는 다시 읽게 하지 않는다. 모델이 바뀌면 그 모델의 가이드를 읽는다.
  5. **세션별 턴 상태** — 이번 턴 표 · 등록 · 막기 기록 · 경고를 세션마다 따로 둔다. 각 세션은 자기가 받은 사람 메시지와 자기 등록으로만 판정한다.
     사람 메시지를 받지 않은 하위 세션(팀원 · 하위 에이전트)은 등록하지 않아도 막지 않고, 리드의 등록 · 막기 횟수 · 경고에 영향을 주지 않는다.
  6. **종료 검사의 입력 창** — 검사마다 필요한 쪽을 본다. 선택지 검사는 답의 끝, 원칙 검사는 답 전체(바이트 상한 안에서 앞뒤)를 본다. 64KB 를 넘는 답도 판정한다.
- **Non-Goals**
  - 별도 모델로 다시 쓰기(방식 B) — 2026-09-28 결정대로 채택하지 않는다.
  - 다시 쓴 글의 품질 판정 — SCV 는 항목이 채워졌는지와 위 검사만 본다.
  - 하위 세션에 등록 의무 지우기.
  - /clear 뒤 복원 요약(`scv/raw/20261001-resume-recap-stale-conversation.md`) · bash 3.2 점검(`scv/raw/20261001-hook-path-bash32-audit.md`) — 다음 계획.

## Approach Overview

- 판단의 근거를 '프로젝트 공용 파일'에서 '이 세션의 기록'으로 옮긴다. 훅은 입력으로 세션 id 와 대화 기록 경로를 받는다
  (종료 훅 `core/template/hooks/on-stop.sh:33` 이 대화 기록 경로를, 세션 시작 훅 `on-session-start.sh:64-73` 이 시작 이유를 이미 읽는다 — 확인).
- 턴 상태(지금 `scv/journal/.help-turn` · `.help-rewrite` · `.help-turn-gates` · `.help-guide*`)를 세션 id 로 나눠 둔다.
- 쓰기 검사(가드의 등록 규칙, `guard.sh` Rule P → `model-prompting.sh gate`)는 "이 세션의 이번 턴 등록이 있는가"에 더해
  "마지막 등록 뒤에 선택 창 답이 있었는가"와 "마지막 등록의 범위 칸이 변경을 막는가"를 본다.
- 가이드 다시 읽기는 help 가 대화 기록의 마지막 경계(/clear · 압축) 뒤에 지금 모델의 가이드 읽기가 있는지로 정한다.
- 종료 훅은 검사마다 다른 입력 창을 넘긴다(지금은 모든 검사가 앞 64KB — `on-stop.sh:138,143,186,198,221`).
- 보이는 곳: 매 턴 블록 · 규칙 문구 · 경고 문구의 인용 위치 규칙에 '맨 위 한 줄'을 더하고, 종료 검사의 인용 판정이 그 한 줄도 본다.
- 코어는 호스트 중립을 지킨다. '선택 창 답'이라는 신호는 래퍼가 알려 준다(클로드 래퍼의 훅 설정에는 지금 그 사건이 없다 — 확인).

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  readHookInput,     // (훅 stdin JSON) → { session, transcript, event }              — 부수효과(입구)
  loadSessionTurn,   // (session, 기록 폴더) → 이 세션의 턴 상태                      — 부수효과(입구)
  sliceTurnEvents,   // (대화 기록 끝부분) → 이번 턴 사건 목록(등록 · 선택 창 답 · 편집 · 경계) — 순수
  decideGuideLoad,   // (사건 목록, 모델) → load | loaded                             — 순수
  decideWriteGate,   // (턴 상태, 사건 목록, 쓰기 대상) → allow | deny(사유)           — 순수
  decideStopGates,   // (턴 상태, 검사별 답 창) → 막기 | 경고 | 통과                  — 순수
  renderReason,      // (판정) → 모델 · 사용자에게 보일 한 줄                          — 순수
  saveSessionTurn,   // (새 턴 상태) → ()                                              — 부수효과(출구)
)
```

| # | 단계 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|
| 1 | readHookInput | 훅 stdin → 세션 id · 대화 기록 경로 · 사건 | 부수효과 (입구) |
| 2 | loadSessionTurn | 세션 id → 이 세션의 이번 턴 표 · 등록 · 막기 기록 | 부수효과 (입구) |
| 3 | sliceTurnEvents | 대화 기록 끝부분 → 이번 턴 사건 목록 | 순수 |
| 4 | decideGuideLoad | 사건 목록 · 모델 → 다시 읽기 필요 여부 | 순수 |
| 5 | decideWriteGate | 턴 상태 · 사건 · 대상 → 허용 / 거절(사유) | 순수 |
| 6 | decideStopGates | 턴 상태 · 검사별 답 창 → 막기 / 경고 / 통과 | 순수 |
| 7 | renderReason | 판정 → 한 줄 사유 | 순수 |
| 8 | saveSessionTurn | 새 턴 상태 → 저장 | 부수효과 (출구) |

- 부수효과 위치: 훅 입력 읽기와 세션 상태 파일 읽기/쓰기뿐이다. 판정 단계는 문자열을 받아 문자열을 돌려준다.
- 재사용: 종료 훅의 이번 턴 자르기(`scv_turn_slice`), `core/scripts/lib/stop-gates.sh` 의 검사 판정,
  `core/scripts/lib/model-prompting.sh` 의 등록 · 인용 판정. 단계 이름은 제안이며 구현에서 바꿔도 된다.

## Guardrails

- 기존 검사 동작(등록 전 편집 거절 · 인용 없는 종료 막기 · 같은 턴에 한 번만 막기 · 막지 않을 때 다음 턴 경고)은 그대로다.
  바뀌는 것은 '누구의 · 언제의 등록을 보느냐'와 검사별 입력 창뿐이다. 기존 테스트(`test-model-prompting` · `test-guard` ·
  `test-choice-questions` · `test-help-load-once` · `test-session-resume` · `test-help-budget`)가 그대로 통과한다.
- 맥(bash 3.2) · 리눅스에서 같은 결과 — bash 4 전용 문법을 쓰지 않고, 두 CI 모두 초록이어야 한다.
- 어떤 실패(기록 파일 없음 · 읽기 실패 · 형식 이상)도 세션을 멈춰 세우지 않는다. 판정할 수 없으면 '의견 없음'(지금처럼)이다.
- 사용자 원문 · 모델 · 사고량은 바꾸지 않는다(2026-09-28 계획의 약속).
- 코어에 호스트 · 모델 이름을 넣지 않는다. 선택 창 신호와 가이드 폴더는 래퍼가 준다.
- 매 턴 비용 상한 검사(`test-help-budget`)를 통과한다. 올려야 하면 새 상한과 이유를 검사 파일에 적는다.
- 대화 기록은 읽기만 하고, 상태 파일은 그 세션의 것만 쓴다. 심볼릭 링크면 쓰지 않는다(지금 규칙).

## Exit criteria

- All TESTS.md scenarios pass
- 2026-10-03 기준선을 고친 설치본으로 다시 재서 아래가 성립한다.
  - 선택 창 답 뒤 편집이 있는 턴에서 편집 전 다시 등록: 0/3 → 모두(대화형 재현).
  - '바꾸지 않는다'로 등록한 뒤의 편집: 2/4 → 0(막히고, 다시 등록한 뒤에만 진행).
  - 같은 프로젝트 하위 세션이 리드의 등록 때문에 막힘: 5/6 → 0.
  - 재접속 · 이어받기만 있고 /clear · 압축이 없는 구간의 가이드 다시 읽기: 0번.
- 오늘의 헤드리스 12번 · 5턴 실측을 같은 기준 · 가린 판정으로 다시 돌려, 질은 같거나 낫고 비용은 같거나 적다.
- 고친 설치본으로 하루 쓴 실제 긴 세션 기록을 오늘과 같은 기준(K1~K5)으로 분석해 위 숫자를 확인한다.
- 코어 · 클로드 래퍼 · 코덱스 래퍼를 릴리스하고 설치본으로 위를 확인한다(릴리스는 단계마다 사용자 확인).

## 예외처리 (Edge cases)

- 한 턴에 선택 창 답이 여러 번 — 마지막 답 뒤 첫 편집 전에 등록 하나면 된다(목표 2).
- '그대로' 한 줄로 등록했는데 직전 등록의 범위 칸에 변경 금지가 있다 — 범위가 그대로이므로 금지도 그대로다. 편집하려면 범위를 바꿔 다시 등록한다(목표 2 · 3).
- 하위 세션이 사람 메시지를 직접 받았다 — 그 세션도 자기 등록으로 판정한다(목표 5).
- 대화 기록이 없거나 형식이 다르다 — 의견 없음(Guardrails).
- 답이 64KB 를 넘는다 — 검사마다 필요한 쪽을 본다(목표 6).

3. 답 뒤 재등록 · 금지 대조(목표 2 · 3)를 쓰기 검사에 더한다. '그대로' 한 줄 등록의 모양을 정한다.

6. 보이는 곳(목표 1) — 규칙 · 경고 문구, 설정 설명, 인용 판정.
7. 래퍼 — 클로드 래퍼가 선택 창 답 신호를 주도록 훅 설정을 더하고, 코덱스 래퍼는 해당 없음을 확인한다.

## Risks / Open Questions

- 하위 세션 구분 — 분석 에이전트의 보고로는 팀원이 리드와 같은 세션 id 로 기록됐다(에이전트가 상태 파일을 보고 한 판단, 미확인).
  훅 입력에서 하위 세션을 가를 값이 없으면 '이 세션에 사람 메시지가 왔는가'(이번 턴 표가 그 세션에 생겼는가)로 가른다.
- '대화 기록 = 모델의 맥락'이라는 전제 — 이어받기 · 재접속 뒤에도 성립하는지, 압축 경계가 기록에 어떻게 남는지 테스트로 확인한다.
- 큰 대화 기록(수십 MB)에서 매 턴 판정 속도 — 구현 전에 지금 훅 시간을 재고 기준을 정한다(64KB 메모의 기준: 10만 바이트 답 1.2초).
- 재등록이 늘리는 비용과 번거로움 — '그대로' 한 줄 등록의 실제 비용을 실측으로 확인한다.
- 헤드리스에는 선택 창이 없다 — 답 뒤 재등록은 대화형(tmux)으로만 재현할 수 있다.
- 실제 긴 세션 분석은 하루 사용을 기다려야 한다 — 끝 조건의 마지막 단계다.

# Test Plan — 다시 쓴 요청이 일 내내 맞게 — 답 뒤 재등록 · 세션별 턴 상태 · 가이드 다시 읽기 줄이기

## Overview

다시 쓴 요청이 턴의 첫 부분만이 아니라 일 내내 실제 일과 맞는지, 그 장치가 다른 세션을 막거나 가이드를 쓸데없이 다시 읽게 하지 않는지를
확인한다. T1~T11 은 픽스처로 도는 자동 검사(맥 bash 3.2 · 리눅스 CI), T12~T16 은 설치본으로 하는 실측이다.
실측의 기준선은 2026-10-03 대화(`scv/conversations/20261003-155702-other-session-history-access.md`)의 숫자다:
선택 창 답 뒤 재등록 0/3, '바꾸지 않는다'인데 편집 2/4, 가이드 다시 읽기 7턴 중 5턴, 하위 세션 막힘 5/6.

## Test scenarios

### T1. 보이는 곳 — 맨 위 한 줄 + 결론 뒤 전문

- **Setup**: 이번 턴에 등록이 있는 상태. 답 픽스처 세 개 — (a) 맨 위 "이렇게 이해하고 일함: …" 한 줄 + 결론 뒤 `> **다시 쓴 요청**: …` 전문,
  (b) 결론 뒤 전문만, (c) 맨 위 한 줄만.
- **Run**: 종료 검사의 인용 판정을 세 답에 돌린다.
- **Expected**: (a) 통과. (b) · (c) 는 같은 턴 한 번 막고, 사유가 빠진 쪽(맨 위 한 줄 / 전문)을 정확히 말한다. 이미 계속 중이면 막지 않고 다음 턴 경고.
- **Pass criterion**: 세 결과가 기대와 같고, 막기 · 경고 문구가 빠진 쪽을 이름으로 말한다.

### T2. 설정 설명 · 규칙 문구가 같은 위치를 말한다

- **Setup**: 설정 예시(`core/template/scv/scv_settings.example.json` 의 `SCV_MODEL_PROMPTING` 설명), 매 턴 블록, 경고 문구, help 규약(prompt-refine).
- **Run**: 네 곳의 인용 위치 문구를 검사로 모은다.
- **Expected**: 네 곳 모두 "맨 위 한 줄 + 결론 바로 뒤 전문"을 말하고, "답 앞에 보인다" 같은 옛 문구가 남지 않는다.
- **Pass criterion**: 옛 문구 0건, 새 위치 문구가 네 곳에 모두 있다.

### T3. 답 뒤 재등록 — 선택 창 답 뒤 첫 편집 전

- **Setup**: 대화 기록 픽스처 — 사람 메시지 → 등록 → 선택 창 답 → 편집 시도.
- **Run**: 쓰기 검사를 편집 시도에 돌리고, 다시 등록한 뒤 한 번 더 돌린다.
- **Expected**: 첫 편집은 거절되고 사유에 다시 등록하는 명령이 있다. 다시 등록한 뒤에는 허용된다. 답이 없는 턴의 편집은 지금처럼 허용된다.
- **Pass criterion**: 거절 → 재등록 → 허용 순서가 그대로 나오고, 답 없는 턴은 바뀌지 않는다.

### T4. '그대로' 한 줄 등록

- **Setup**: T3 의 기록에서 범위가 바뀌지 않은 답(예: "승인").
- **Run**: 답 뒤에 '그대로' 한 줄로 등록하고 편집을 시도한다. 답이 없는 상태에서도 '그대로' 등록을 시도한다.
- **Expected**: 답 뒤 '그대로' 등록은 받아들여져 편집이 허용되고, 인용 판정의 기준은 직전 다시 쓴 요청 그대로다. 답이 없는 '그대로' 등록은 불완전 등록으로 거절된다.
- **Pass criterion**: 두 경우의 결과가 기대와 같다.

### T5. 금지 대조 — 범위 칸의 변경 금지

- **Setup**: 범위 칸이 "파일 · 코드는 바꾸지 않는다"인 등록, 범위 칸에 금지가 없고 다른 칸에만 "바꾸지 않는다" 문장이 있는 등록.
- **Run**: 각 등록 뒤 편집을 시도하고, 첫 등록 뒤에는 금지 없는 범위로 다시 등록한 뒤 한 번 더 시도한다.
- **Expected**: 범위 칸 금지 → 거절, 사유에 "범위가 바뀌었으면 다시 등록하라". 금지 없는 재등록 뒤 → 허용. 다른 칸에만 있는 문장 → 막지 않음.
- **Pass criterion**: 세 결과가 기대와 같다(오판 0).

### T6. 가이드 다시 읽기 — 대화 기록으로 판단

- **Setup**: 대화 기록 픽스처 네 개 — (a) 가이드 읽기 뒤 이어받기 · 재접속만 있고 10턴 넘게 지남, (b) 가이드 읽기 뒤 압축 경계,
  (c) 가이드 읽기 뒤 /clear, (d) 다른 모델의 가이드만 읽음.
- **Run**: help 의 가이드 판정(GUIDE 줄)을 네 기록에 돌린다.
- **Expected**: (a) loaded, (b) · (c) · (d) load.
- **Pass criterion**: 네 결과가 기대와 같고, (a) 에서 턴 수 · 재접속만으로 load 가 나오지 않는다.

### T7. 큰 대화 기록에서의 속도

- **Setup**: 수십 MB 대화 기록 픽스처(가이드 읽기가 아주 앞쪽에 있거나 없는 경우 포함).
- **Run**: 매 턴 판정(T3 · T5 · T6 의 판정)을 맥 기본 bash 3.2 와 리눅스에서 잰다.
- **Expected**: 구현 전에 잰 지금 매 턴 훅 시간 기준 안에 끝난다(기준값은 구현 전 측정으로 정해 이 항목에 적는다).
- **Pass criterion**: 두 환경 모두 기준 안.

### T8. 세션별 턴 상태 — 두 세션이 서로 끼어들지 않는다

- **Setup**: 같은 프로젝트에서 세션 A · B 를 흉내 낸 훅 입력(세션 id 다름).
- **Run**: B 만 등록한 뒤 A 의 쓰기 · 종료 검사를 돌리고, A 만 등록한 뒤 B 의 종료 검사를 돌린다. 막기 기록 · 경고를 확인한다.
- **Expected**: B 의 등록이 A 를 통과시키지 않는다. A 의 등록이 B 를 막지 않는다. 막기 횟수 · 경고가 세션끼리 섞이지 않는다.
- **Pass criterion**: 세 조건이 모두 성립한다.

### T9. 하위 세션 — 사람 메시지를 받지 않은 세션은 막지 않는다

- **Setup**: 리드 세션이 이번 턴에 등록한 상태에서, 사람 메시지 없이 일하고 끝나는 하위 세션(팀원 · 하위 에이전트)의 종료.
- **Run**: 하위 세션의 종료 검사를 돌린다.
- **Expected**: 막지 않는다. 리드의 막기 기록 · 경고 파일에 아무것도 남기지 않는다. 리드의 이번 턴 '한 번 막기'를 쓰지 않는다.
- **Pass criterion**: 세 조건이 모두 성립한다.

### T10. 종료 검사의 입력 창 — 64KB 를 넘는 답

- **Setup**: 105KB 답 끝에 질문이 있는 픽스처, 앞 64KB 뒤쪽에 문제 표가 있는 픽스처(`scv/raw/stale/20261002-stop-hook-64kb-window.md` 의 재현).
- **Run**: 선택지 검사 · 원칙 검사를 돌린다.
- **Expected**: 선택지 검사가 끝의 질문을 잡고, 원칙 검사가 뒤쪽 문제 표를 잡는다. 10만 바이트 답의 판정 시간이 지금 수준(맥 bash 3.2 약 1.2초)이다.
- **Pass criterion**: 두 검사 모두 잡고, 시간 기준 안.

- **Pass criterion**: 두 CI 모두 초록.

### T12. 대화형 재현 — 답 뒤 재등록 · 금지 대조 (설치본, tmux)

- **Setup**: 고친 설치본, 선택 창이 있는 대화형 화면(tmux), 임시 저장소.
- **Run**: (1) 선택 창으로 방향을 바꾸는 답을 준 뒤 편집을 요청한다. (2) "보고만 해 줘"로 시작해 선택 창 답으로 수정을 승인한다.
- **Expected**: (1) 첫 편집 전에 다시 등록하고, 재등록 없이 편집하려 하면 거절이 보인다. (2) '바꾸지 않는다' 등록 뒤 편집 시도 → 거절 → 재등록 → 진행.
- **Pass criterion**: 화면 기록과 대화 기록에서 두 흐름이 확인된다.
