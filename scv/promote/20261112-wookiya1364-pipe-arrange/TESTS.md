# Test Plan — 엮음 고르기 명령

## Overview

단계마다 한 번만 재서 고른 순서가 맞는지, 벽과 선언을 지키는지, 답이 달라지는 순서를 내놓지 않는지를 본다. 계산은 순수 함수의 값으로, 명령은 임시 폴더의 작은 입력으로 실제로 돌려 본다.

## Test scenarios

### T1. 단계 글 읽기

- **Setup**: 단계 넷(바꾸기 · 고르기 · 앞의 N줄 · 모아야 하는 단계)이 든 글, 빈 줄과 `#` 줄, 종류가 틀린 줄, 이름이 겹친 줄
- **Run**: 단계 글 읽기
- **Expected**: 바른 글은 단계 줄들, 틀린 글은 오류 줄과 끝 코드 1
- **Pass criterion**: 줄 수와 오류 글이 기대와 같다

### T2. 순위 값과 순서 — 2026-11-11 의 값

- **Setup**: 잰 값 셋 — up 0.134초 · 1.00, tag 0.083초 · 1.00, keep 0.032초 · 0.41
- **Run**: 순서 계산, 예상 시간 계산
- **Expected**: 순서 keep · up · tag. 예상 시간은 처음 순서 0.249초, 고른 순서 0.121초 안팎
- **Pass criterion**: 순서가 같고 예상 시간이 ±0.002초 안

### T3. 벽을 넘지 않는다

- **Setup**: 바꾸기 → 고르기 → 앞의 N줄 → 고르기, 바꾸기 → 모아야 하는 단계 → 고르기
- **Run**: 순서 계산
- **Expected**: 벽(앞의 N줄 · 모아야 하는 단계) 뒤의 고르기는 벽 앞으로 가지 않는다
- **Pass criterion**: 벽의 자리와 벽 뒤 단계의 자리가 그대로다

### T4. 선언을 지킨다

- **Setup**: 고르기에 `after:` 로 앞의 바꾸기를 적은 단계 글
- **Run**: 순서 계산
- **Expected**: 그 고르기는 적힌 바꾸기 뒤에 놓인다. 선언이 없는 다른 고르기는 맨 앞으로 간다
- **Pass criterion**: 순서가 기대와 같다

### T5. 실제 실행 — 더 빠른 순서를 고르고 답이 같다

- **Setup**: 임시 폴더의 입력 2만 줄, 단계 셋(대문자로 바꾸기 · 앞에 글 붙이기 · 7이 든 줄만 고르기)
- **Run**: 명령
- **Expected**: 고른 순서가 고르기 → 바꾸기 둘, 답 같음, 실행 횟수 5번
- **Pass criterion**: 표에 고른 순서 · `같음` · 실행 5번이 있고 끝 코드 0

### T6. 실제 실행 — 답이 달라지는 순서는 내놓지 않는다

- **Setup**: 고르기가 앞의 바꾸기 결과에 기대는 단계 글(붙인 글이 있는 줄만 고르기), 선언 없음
- **Run**: 명령
- **Expected**: 고르기를 앞으로 당긴 순서는 답이 달라 버리고, "바꿀 수 있는 순서를 찾지 못함"과 처음 순서를 낸다
- **Pass criterion**: 표에 그 글이 있고, 고른 짜임 칸이 처음 순서와 같다

### T7. 아무 파일도 고치지 않는다

- **Setup**: 단계 목록 파일과 입력 파일의 지문을 적어 둔다
- **Run**: 명령
- **Expected**: 두 파일이 그대로이고, 작업 폴더에 새 파일이 없다
- **Pass criterion**: 지문 같음 · 새 파일 0개

### T8. 쓰임새 오류

- **Setup**: 파일이 없을 때, 단계가 하나뿐일 때, 종류가 틀렸을 때
- **Run**: 명령
- **Expected**: 무엇이 틀렸는지 한 줄과 끝 코드 2
- **Pass criterion**: 끝 코드 2 와 이유 글

## How to run

```bash
bash core/tests/test-pipe-arrange.sh
```

## Pass criteria

- 위 명령이 옛 셸(bash 3.2)과 새 셸(bash 5)에서 끝 코드 0
- 전체 시험이 두 셸에서 통과
