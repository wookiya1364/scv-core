# Test Plan — 질의에 맞는 effort 추천 · 캐시 미스를 피하는 새 세션 제안

## Overview

일의 종류 판정 · 권장값 찾기 · 추천 결정이 맞는지, 같은 조건은 다시 묻지 않는지, 근거 문장이 원문과 같은지 본다.

## Test scenarios

### T1. 일의 종류 판정
- **Run**: 짧은 인사 · "이 함수 고쳐" · 진행 중 계획 + "구현해" · "조사해서 비교해 줘" 를 판정.
- **Pass criterion**: 각각 짧은 대화 · 보통 코딩 · 긴 계획 구현 · 깊은 조사.

### T2. 권장값과 근거 문장
- **Run**: Opus 5.5 · Fable 5.2 × 종류별 권장값 찾기.
- **Pass criterion**: 값이 표와 같고, 근거 문장이 원문 파일에 그대로 있음(check.sh 통과).

### T3. 종류가 바뀔 때만 묻는다
- **Run**: 같은 종류 두 턴, 다른 종류 한 턴.
- **Pass criterion**: 안내 줄은 바뀐 턴에만, 같은 조건은 두 번째에 없음.

### T4. 큰 일 + 큰 맥락이면 새 세션 제안이 첫 보기
- **Run**: 맥락이 큰 세션에서 긴 계획 구현으로 바뀜(1단계 측정이 'effort 변경이 캐시를 깸'일 때).
- **Pass criterion**: 안내 줄이 새 세션을 먼저 권함. 작은 일이면 제안 없음.

### T5. 끄면 이전과 같다
- **Run**: 끄는 설정에서 같은 시나리오.
- **Pass criterion**: 0.89.0 의 권장 effort 묻기와 같은 출력.

## How to run

```bash
bash core/tests/test-effort-by-task.sh
```

## Pass criteria

- T1–T5 통과(맥 · 리눅스 · 코덱스 사본), check.sh 통과, 전체 실행 통과, 1단계 측정값 · 5단계 기록 측정값이 마무리 보고에 수치로.
